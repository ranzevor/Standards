# 当前记忆与控制状态的有限恢复合同

入口为`checks/ai_agent_model.py`中的`MemoryIndex.restore_rows`和`Controller.restore`。这些函数只处理合成对象与调用方提供的当前权威记录，不连接真实记忆库、计费服务、任务引擎或权限系统；进程内锁也不提供分布式事务、掉电持久性或远端权限证明。

## 记忆版本与当前删除

`Memory`以租户、owner和key确定对象，version为正整数，来源、事实类型、有效期和内容均属于具体版本。`put`同时核当前ACL、owner、预期版本及删除世代；写入版本必须严格增加。重复调用不能借同版本改写内容；调用方可回读当前版本或使用等价恢复路径，而不是降低版本。

`restore_rows`要求每批每个对象只有一个已选择版本。整批先校验和暂存，再在同一进程锁中发布数据和派生来源：

| 当前事实与输入 | 结果 |
| --- | --- |
| 输入版本低于现有更正 | 隔离为`isolated-stale-version`，保留更正和派生来源 |
| 同版本且完整内容、来源、类型及期限相同 | `equivalent-current-version`，合法重复恢复不改事实 |
| 同版本但内容或来源等不同 | 明确冲突并给当前版本；该批不部分生效 |
| 输入在当前删除世代内 | `isolated-deleted-generation`，不得活跃读取 |
| 当前已删除且无现行行，备份声称更高版本 | `isolated-current-deletion`；版本号本身不授权恢复已删除对象 |
| 现行主体明确重建该对象 | 通过当前ACL/owner核验的`put`使用高于删除世代的新版本，后续有效新版本可恢复 |
| 未删除对象的合法新版本或此前不存在对象 | 恢复准确内容及派生来源；不恢复或扩大ACL |

被隔离行的版本和摘要留在进程内`restore_audit`，不是耐久审计账。无效/冲突批次以异常报告，调用方须保留原输入和失败；函数不把冲突行悄悄当作等价行。输出前再次核当前ACL、版本与删除世代：若读取后发生更正，旧读取副本不再输出；调用方可重新查询当前对象。真实存储仍须实现其自身原子条件写、当前权利覆盖、过期、索引与备份恢复验证。

## 控制恢复与根预算

`Controller.restore(checkpoint, current)`的`current`必须是调用方已取得的**完整当前权威图像**，不能仅从旧检查点复制一个新epoch。此例不获取或认证该权威；若权威缺失、未知或与已知事实冲突，不能推测成功恢复。

两份输入须属于同一任务；当前epoch和plan不得落后，同epoch不能更换attempt，同plan不能静默改required集合。当前记录保留已知结果、审计前缀和子任务；已知终态不得被恢复为运行态或另一终态。采用当前完整的attempt、epoch、plan、状态、required、results、children和audit，不从旧记录覆盖它们。

根预算先校验每个预留的类型、状态、最终收据和已用总数，再核两个图像的延续关系：

- 已结算操作的实际支出与收据不能删除、退款或改写；最终费用超预留时仍保留超限事实。
- 新增当前预留、未知费用和已发生支出必须保留；旧`unknown`不能退成仅`reserved`。
- 已权威确认未开始而释放的操作不得重新打开；`reserved/unknown`可按当前真实结算或终局未开始事实结束。
- 当前限额可以更严格，但已有支出不因此归零；已达到/超过当前上限时不能再发起增加预算的工作。
- 不完整或相互矛盾的当前记录拒绝恢复，等待有权查询和调和，不默默取较小用量。

此例的权限和收据仍是合成权威；它不证明真实扣费、允许真实副作用或补发授权。真实引擎还须把权威读取、当前控制权CAS、目标栅栏及预算账接入同一有效接受合同，单个本地快照不能完成这些保证。

`succeed`保护failed/cancelled终态；已经成功且join事实仍成立时只允许幂等重复成功。`cancel`和`fail`也不能改写其他终态。显式新决议/新任务的真实流程不由直接修改此对象状态代替。
