# 材料权属、许可与通知记录

按[权属许可规范](../standards/project-governance/014-权属许可与第三方材料规范--v0.1.0.md) PGL-01—08 填写。自有材料使用根 LICENSE 的路径和类型分配；本记录用于实际第三方材料、不同许可条件及具体争议。对象引用使用 Git 版本与路径，发行范围使用构建生成的清单；外部原件使用其版本或摘要。

| 字段 | 必填条件与合法内容 |
| --- | --- |
| `material` | 需要单独处理的第三方或异授对象：Git 版本与路径、外部版本或摘要、用途和分发范围 |
| `origin` | `owner-confirmed` / `third-party` / `generated` / `unknown`；未知材料不能直接进入可分发集合 |
| `owner_confirmation` | 自有材料记录确认主体、准确范围和可定位决定；已有有效确认可引用，不虚构额外签署 |
| `third_party_source` | 第三方必填：真实来源、版本、原许可/通知、实际读取范围及获取的准确材料；链接资料不等于再许可其正文 |
| `root_license` | 引用根 LICENSE 的当前许可、路径规则及实际排除项；许可变更使用有权主体的决定 |
| `distribution` | 目标文件/制品、包含的材料、通知位置、必要源/修改说明、排除项；逐项验证适配许可条件 |
| `contribution` | 实际采用的贡献授权流程及未决定项；模板本身不代表贡献者同意协议 |
| `brand_font_generation` | 品牌/字体的独立条件；生成材料所用工具条款、输入材料权利及分发范围，不能推定独占或第三方免责 |
| `objection` | 私密接收入口、受影响对象、临时隔离/停止新增分发、调查和恢复条件；没有真实渠道不填写虚构邮箱/SLA |
| `review` | 检查者、准确对象、发现和处置；法律适用判断应由有权者或专业人员承担 |

## 正常实例

本仓根 [LICENSE](../LICENSE) 按路径和类型分配 CC BY 4.0 与 Apache-2.0；[权属与许可状态](../governance/LICENSING.md)和 [NOTICE](../NOTICE.md) 说明适用条件及第三方通知。自有材料按这些规则核对，实际第三方材料保留自己的许可条件。发行构建生成文件清单并核对通知是否随包提供。

## 失败与恢复实例

将第三方代码移入源码后只保留根目录自有权属声明：材料分类和必要通知不完整，分发准备应被阻断。保留原取得材料和失败记录，定位准确文件、原版本及许可条件；补齐通知/源文件或替换为权利明确的实现，再对实际制品核包含范围。权利异议涉及某图片时先隔离该图片的新增分发并保留取证所需原件，不机械删除整个项目或销毁争议证据。
