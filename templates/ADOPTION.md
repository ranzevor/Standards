# 项目采用记录模板

## 填写与权威
采用者以真实需求和有效决定选规范。按照[采用接口](../standards/L6/001-项目采用与实现验收接口规范--v0.1.0.md)和[机器示例](../examples/adoption-contracts/README.md)填写，不把合成例直接当真实采用。

| 字段 | 必须填写的实际信息 | 合成示例 |
| --- | --- | --- |
| 决定 | 有权主体、权利依据、范围、时间；已有覆盖该项目的有效决定时复用其actor/authority_reference/at；确无决定时保持未决 | `not-decided`，无批准者/日期 |
| 规范集合 | ID/版本/path/SHA-256及技术参考/试用/采用 | `technical-reference`；`STD-PG-001` / `0.1.0` / `standards/project-governance/001-项目治理领域总则与职责接口--v0.1.0.md` / `0ece949523e7f87ed006b7e4eb9c100292a85600a63ab6d37b7f55839f107700` |
| 条款 | 文档ID+局部ID、触发对象、适用及事实理由 | `STD-PG-001::PGF-01`：存在规范引用，适用单一权威与精确选择；实际项目是否符合另行验收 |
| 实施对象 | 各源/制品/配置/数据版本和真实环境 | 合成设计，无实施身份 |
| 验收 | 固定夹具、命令/工具、预期、实际、退出、证据层级 | 预期已写，actual=null，not-run |
| 依赖/例外 | 提供/消费保证、必要闭包、限定决定 | 草案参考不变为正式依赖 |
| 变更/撤回 | 旧新对象、兼容影响及恢复责任 | 保留原决定，不覆盖历史 |

## 校验
运行 `python checks/project_adoption.py` 检查仓内合成示例；真实记录调用 `validate_record`并提供其权威目录和准确条款。检查只验证记录一致性，不认证权利、真实采用或运行效果。
