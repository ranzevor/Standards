# 测试质量门禁与证据规范

**文档ID：** STD-PG-011　**版本：** 0.1.0　**状态：** adopted　**生效日期：** 2026-10-30

## 范围、术语和分层

适用于所有“已验证”声明及其工具，不要求每个项目都能运行云、硬件或真实支付。合同是初态、输入、独立预期、观察和终点；原始记录是实际输出和运行事实；摘要是对原记录的派生说明。文档结构、语义实审、有限模型、隔离实现、真实目标分别判定。开发者运行检查，验收者核判据，独审者核充分性，证据保管者控制保存和访问。依赖[PGT](003-需求设计与验收追溯规范--v0.1.0.md)与[PGC](009-变更提案审查与合并规范--v0.1.0.md)。

## PGQ-01 先定义可执行合同

**输入与前置：** 准确需求、目标行为、候选/环境及允许副作用。

**操作步骤：** 写初态、输入夹具、命令或工具步骤、时钟/随机性、预期输出/状态/副作用次数、观察点及失败终点。比较规则包含单位、排序、容差和独立依据；错误注入注明发生在提交前后哪个边界。

**输出与验收：** 另一执行者能据合同判pass/fail/unknown；命令退出0不是任意业务目标的充分判据。

**失败与恢复：** 预期未定时先修合同；缺依赖/设备时记blocked或not-run及所缺条件，不生成执行事件。

**正例：** 写输出后崩溃，允许旧文件或完整新文件，不允许截断文件，原输入摘要必须不变。

**直接失败反例：** 运行后把实际结果复制为expected，再宣称测试符合规范。

**合法邻例：** 无精确单值的科学测量可按预先依据给区间和统计方法，不强制伪确定性。

**检查入口：** 自动合同模型只判已实现的有限比较类型；专业期望和容差来源人工核。

## PGQ-02 正例、反例、合法邻例与变异

**输入与前置：** 必要规则、不变量、允许变化及失效机制。

**操作步骤：** 重要规则至少给正常输入、直接违反规则的输入和相邻但合法输入。涉及状态时覆盖重复/乱序/并发/超时/未知及恢复；变异应真正改变目标实现或数据语义，并确认失败发生在目标判据，不以导入错误、语法错误或先行整文hash拒绝冒充杀死语义变异。

**输出与验收：** 反例被目标机制拒绝或表现预定失败，合法邻例仍被接受；分别统计方法、参数化场景、实际目标及跳过，不相加作覆盖充分性。

**失败与恢复：** 变异未触及目标时修注入点；合法邻例误拒时修规则，不把合法路径改成禁止来制造绿色。

**正例：** 移除revision比较后并发旧写覆盖新值，断言精确抓住该覆盖；无冲突更新仍合法。

**直接失败反例：** 删除模块导致ImportError，就宣称幂等防线已被测试。

**合法邻例：** 不影响行为的注释变化应保持测试通过，不要求所有文件变化都被拒。

**检查入口：** 对应实现/解析器的直接测试；自然语言“重要规则”与组合充分性实审。

## PGQ-03 精确对象与真实环境

**输入与前置：** 完整源/制品/配置身份、工具版本、依赖和实际执行环境。

**操作步骤：** 执行前固定实际候选身份与环境：Git仓库使用包含待测未提交修改的工作区tree及基线commit，离线发行包使用经验证的构建清单身份；执行后重核同一源对象未漂移。保存实际argv、cwd、必要非秘密配置、版本和目标；依赖动态探测结果不能冒称锁定版本。运行中修改被测内容使该次结果不能证明最后对象。

**输出与验收：** 结果能定位准确对象与环境；目标不同或源码变更触发影响判定和复验。

**失败与恢复：** 漂移、截断、依赖改变或并发写入时保留运行结果并标明invalid-for-final-object；修复隔离或对象控制后重跑，不只更新摘要。

**正例：** 规范和检查源码所在的实际候选tree在回归前后一致，运行结果绑定该tree；候选可包含尚未提交的修改。

**直接失败反例：** 测试旧程序，却将日志里的版本手改成新版本。

**合法邻例：** 日志保存到源码目录外，不影响被测源码身份。

**检查入口：** 内容身份、环境匹配和预后快照摘要可自动核；文件摘要不证明运行过程真实或语义充分。

## PGQ-04 结果状态和假通过防线

**输入与前置：** 合同、实际执行事件、退出码、观察值、未执行原因。

**操作步骤：** 状态为not-run/pass/fail/partial/unknown/not-applicable。not-run没有实际执行；unknown表示已发起但效果未核实；not-applicable须触发条件不存在。pass要求实际观察满足合同、退出/异常符合预定规则且对象/环境一致；重要步骤未执行不能被聚合为全部通过。

**输出与验收：** 跳过、基础设施失败、预期业务拒绝及测试失败区分；自动聚合必须检查全部required子项，不能只看最后一条输出。

**失败与恢复：** 子进程超时保全已捕获输出及未知效果；先核权威状态再恢复。有意测试的非零退出可符合合同，但测试进程自身失败不自动是目标预期失败。

**正例：** 命令应以退出2拒绝非法输入且不改文件，观察两者均满足，该反例测试通过。

**直接失败反例：** 浏览器未启动、10目标跳过，却把总方法数写为全部浏览器通过。

**合法邻例：** 文档可审但真实业务实现not-run，可分别报告两种状态。

**检查入口：** `evaluate_check`和`aggregate_checks`有限模型核明确合同和required集合；实际目标能力及适用性实审。

## PGQ-05 原始证据与派生摘要

**输入与前置：** 实际运行的stdout/stderr、起止/退出、观察和对象身份。

**操作步骤：** 原始两输出流与机器结果按实际取得内容保存到独立运行目录、CI制品或授权证据存储，注明未捕获或截断。派生摘要引用必要原件的路径/大小/SHA256和对应层级，源码身份引用相应Git tree或发行清单；多层索引同时验证被引用内层当前身份，外层文件存在不证明内层摘要仍有效。敏感值先按保存边界处理，脱敏版与原件关系明确。

**输出与验收：** 摘要可回溯到原始结果；失败、修复和重跑不互相覆盖。不可替代证据按PGX保留，冗余整仓副本不是必要证据。

**失败与恢复：** 原件丢失或无法读取时把对应结论降为证据缺失，不重造日志；摘要陈旧则更正当前索引并保留原错误记录。

**正例：** 补验报告链接原失败及修复后精确新运行，两者摘要分别固定。

**直接失败反例：** 更新外层“已核”标记，却没有重查已改变的内层产物。

**合法邻例：** 可重建的临时构建目录被回收，原始不可替代运行日志和源码/锁定入口仍可取得。

**检查入口：** 递归引用/摘要/路径/重复和截断标记自动核；实际过程真实性与证据完整性人工核。

## PGQ-06 门禁、复用与工具自身

**输入与前置：** 当前候选、所需检查集合、旧结果和变更影响分析。

**操作步骤：** 门禁按准确集成对象运行必要自动检查与人工审查；旧证据只有对象、环境和证明命题仍一致才可复用，列出差异及理由。检查器自身有直接负例与合法邻例；使用assert验证外部输入时拒绝Python优化模式，或改为不会被优化移除的显式验证。

**输出与验收：** 可自动检查的声明均有可运行实现；手工项列判断方法和实际记录，不让生成器自动填语义pass。

**失败与恢复：** 门禁假通过时保存直接复现，修工具/判据和相关文档，再对受影响与完整对象复验；不能通过降低门槛、静默跳过或改统计口径结案。

**正例：** 仅翻译导航变化，原算法实验可在独立核身份/影响后复用，当前链接与源译身份重新检查。

**直接失败反例：** 沿用旧绿色徽章作为新文件集合的完整验收。

**合法邻例：** 无变化、昂贵的真实业务实验不必无理由重复，但不能由此称未测的新目标已通过。

**检查入口：** `python checks/validate_all.py`运行仓库校验，`python -m unittest discover -s tests -v`运行回归测试；项目使用自身合同和环境，自动检查能力不能外推。
