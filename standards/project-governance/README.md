# 项目治理

把项目目标、变更和交付转成可执行、可恢复、可追溯的工作。先确定项目的真实功能与承诺，再选择适用条款；没有团队、部署或持久数据的项目，不需要为了填表创造这些对象。

## A · 总则与职责

从[总则与职责接口](001-项目治理领域总则与职责接口--v0.1.0.md)开始。本领域20份规范均为v0.1.0，状态为adopted；[规范登记](../../registry/standards.json)记录稳定标识、版本、路径与摘要。项目按文档标识和版本选择具体条款。

```text
范围与成功条件 → 需求/设计/接口 → 实现、变更和审查
        ↓              ↓                 ↓
     采用记录 ← 具体配置、操作和验收 → 发行/部署
        ↓                                ↓
     例外与升级 ← 维护和兼容 → 迁移、归档与退役
```

通用规范正文只在Standards维护。项目仓库记录其准确引用、适用性、配置、项目操作与必要例外；`governance/`记录Standards自身仓库政策，不代替本领域专项正文。

## C · 执行与填写

[操作指南](../../guides/PROJECT-GOVERNANCE.md)按一次合成离线工具的正常路径和失败恢复串联上述接口。[字段说明和模板](../../templates/project-governance/README.md)定义填写条件与合法值；[填妥实例](../../examples/project-governance/README.md)给出具体记录、命令、观察及不适用依据，不充当真实项目采用。

English texts are listed in the [translation index](../../translations/en/project-governance/README.md). Chinese is the normative source; the translation index links each English text to its Chinese source and clause identifiers.

## D · 检查与人工验收

```sh
python checks/project_governance.py
python checks/project_governance.py --project examples/project-governance/project-record.json
python examples/project-governance/git_scenarios.py --scenario all
python -m unittest tests.test_governance_models tests.test_project_git_scenarios tests.test_project_readme -v
```

逐条入口、输入、预期、失败判据和人工项由`../../registry/project-governance-domain.json`登记。机器核身份、引用、状态和已实现的有限模型；自然语言必要性、真实角色/决定、README阅读和译文语义由对应人工判据核实。命令成功不自动改变采用或真实业务实现状态。

跨域接口以[总则PGF-05](001-项目治理领域总则与职责接口--v0.1.0.md#pgf-05-依赖顺序和跨域接口)为入口：L0编制架构、L1制度、L2协作、L3工程机制、L4/L5技术实现、L6项目采用验收各负其责。[来源表](../../sources/project-governance/README.md)列工具原始语义、有限引用和组织规则设计的区别。
