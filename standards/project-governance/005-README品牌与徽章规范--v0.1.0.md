# README品牌与徽章规范

**文档ID：** STD-PG-005　**版本：** 0.1.0　**状态：** adopted　**生效日期：** 2026-10-30

**权威语言：** 中文（zh-Hans）

中文为唯一权威；[英文全文](../../translations/en/project-governance/readme-branding.md)仅为对应译文。“必须/不得”仅在适用条件成立且准确版本被选定采用时构成必要要求。

## 适用与不适用

适用于项目根README、语言入口、封面与状态徽章的建立和修订。受众是首次访问的中文开发者、采用者和维护者。不适用于把README当成逐次审查日志、完整规范正文或产品认证书；无远端项目不因此需要创建远端、CI或Release。

## 术语与前置

入口是帮助读者完成下一步任务的页面；封面是品牌识别图；徽章是具有对象、状态及证据入口的短声明；本地链接是相对当前文档的路径；具名链接具有能说明目的的可见文字；成熟度描述文档状态，不等于实现验收。

开始编制或采用前，先固定本条款的对象、责任主体、必要输入和预期产物；未知不等于不适用。以下条款分别给出输入、步骤、产物、异常及恢复，不能用全局口号替代。

## 条款

### PGE-01 读者任务与入口结构

- **适用、责任与输入：** 维护者在新增或改变定位时，输入实际产品范围、目标读者、当前目录和可用渠道；读者任务不能由组织名称猜测。
- **必要步骤与输出：** 必须在首页用自然中文说明是什么、解决什么问题及不解决什么；随后给最短使用路径、按任务导航、成熟度、版本、贡献、安全与许可入口。保留可独立理解的正文，不以徽章代替定位。输出为可以从陌生读者起点顺序阅读的README。
- **失败、未知与恢复：** 任务或渠道未知时写明待提供的具体入口及当前可用替代；删除失实的操作指引而不虚构服务。定位变更后重新走最短路径。
- **正确案例：** 规范仓先解释选条款与采用，再指向本地目录和采用接口。
- **直接失败反例：** 首页只有“世界领先、全面通过”及审查轮次，读者找不到用法。
- **合法邻例：** 纯文档库不需要安装命令；三步阅读、选择、记录采用是有效最短路径。
- **验收与自动/人工边界：** 人工按新读者任务走读，确认每步有真实产物；机器只核约定章节锚点和导航目标，不以关键词数、段落长度或文件数判定可读性。

### PGE-02 封面、替代文字与窄屏

- **适用、责任与输入：** 品牌维护者输入名称、图形权利范围和目标渲染器；文档维护者负责图片替代文字与正文复述。
- **必要步骤与输出：** 必须提供本地可加载封面或品牌图标；有意义图像提供说明用途的替代文字，本地SVG封面或图标提供title/desc。关键信息必须同时在可选择的正文中出现。按320 CSS px及常规宽屏查看实际像素，检查裁切、字形、缩放与横向溢出；装饰图不承载唯一操作信息。
- **失败、未知与恢复：** 图片加载失败应仍可读定位、状态与使用步骤。缺浏览器时记录未执行的渲染器/宽度，不把SVG源码检查算视觉验收；恢复后在相同文件摘要上补验。
- **正确案例：** 横幅仅放Standards品牌，成熟度另写正文；320px仍能辨认名称。
- **直接失败反例：** 把安装命令只画在1280px图片上，窄屏缩小到不可读且alt为空。
- **合法邻例：** 标记为纯装饰且无链接的背景可用空alt；具有项目识别作用的封面不可套用该例外。
- **验收与自动/人工边界：** 机器核图片路径、非装饰alt及SVG可解析性；人工实看两宽度、图像关闭时阅读及缩放。两张截图不能证明完整WCAG符合性或所有平台表现。

### PGE-03 徽章对象、状态与证据

- **适用、责任与输入：** 发布/状态维护者输入准确文档版本、采用记录或真实运行记录；没有相应运行对象时不得编造CI、覆盖率、下载或Release徽章。
- **必要步骤与输出：** 项目徽章必须使用Shields.io官方标准端点，不自行绘制或生成替代徽章。每个徽章登记官方URL、对象、可见文字、目标和状态依据；静态徽章按官方格式编码标签、消息与颜色，链接到对应项目说明。采用与草案必须区分，草案不继承其他对象的采用或审查结论。动态徽章还需核项目、分支/工作流及状态时间。
- **失败、未知与恢复：** 状态依据过时或不可用时移除成功声明或改为有依据的未知/未运行；修正目标后重核声明与数据。图片服务暂不可达时，替代文字、正文和目标链接仍须提供同一信息，不生成自制徽章作为回退。
- **正确案例：** 使用标准Shields.io静态draft徽章并链接准确草案；发行版本徽章与项目元数据一致，采用数量和状态由当前规范登记核对。
- **直接失败反例：** 手写SVG替代标准徽章；CI并不存在却展示build passing；或把某文件采用说成整个体系通过。
- **合法邻例：** 项目没有远端CI但有静态草案状态依据，可使用灰色Shields.io静态徽章；离线阅读仍可从替代文字和正文获知草案状态。
- **验收与自动/人工边界：** 离线检查核官方URL格式、编码后的可见文字、替代文字、目标及本地状态依据，不依赖远程SVG字节摘要。人工核声明含义、服务渲染和动态数据所指的准确对象；静态徽章不表达未经观测的实时结果。

### PGE-04 具名链接与目标锚点

- **适用、责任与输入：** 文档作者输入源文档位置、目标文件/章节和平台锚点规则；本地路径按源文件目录解析。
- **必要步骤与输出：** 链接必须有可理解的名称、存在的文件及存在的目标锚点。解析内联、引用式和图片链接；代码示例与注释不算可点击导航。目录指向真实README。优先本地入口；外链记录核验范围，不将离线存在检查说成联网可用。
- **失败、未知与恢复：** 目标移动时同步调用方或保留明确迁移入口；目标未知时不生成假链接。解码后的越界路径、符号链接逃逸和不支持的协议作为失败；修复后从实际入口再点选。
- **正确案例：** “许可说明”指向LICENSE-NOTICE.md，“最快开始”指向已存在的显式锚点。
- **直接失败反例：** 只有代码块里存在许可链接，或文件存在但#不存在。
- **合法邻例：** 具名引用式链接、百分号编码中文路径和指向同文件的有效锚点都可使用。
- **验收与自动/人工边界：** 自动核实际链接结构、相对路径与显式/支持的标题锚点；外链连通、标题与目的是否相符及渲染器差异由人工核验。有限解析器必须报告支持范围。

### PGE-05 最短使用与可执行命令

- **适用、责任与输入：** 功能维护者输入运行时、工作目录、必要输入、输出位置及成功判据；文档项目与软件项目分别选择阅读或运行路径。
- **必要步骤与输出：** 步骤必须按真实先后列出；命令写清前置、输入缺失行为、输出及能力边界。可运行的有限检查与完整验收分开。纯文档至少给出从选择规范到记录适用范围的路径。
- **失败、未知与恢复：** 输入缺失、命令失败和未执行分别标记；必要测试夹具缺失时不得报告运行通过。保留错误输出，补齐同身份输入后重试受影响步骤。
- **正确案例：** 先给出本地文档入口，再给出所需Python版本、测试夹具位置、检查命令和预期退出码。
- **直接失败反例：** 声称“一条命令全部验证”，实际命令静默跳过缺失的必要测试夹具。
- **合法邻例：** 需要项目具体输入的验收可只给合同和输入格式，不假造可运行真实业务。
- **验收与自动/人工边界：** 对列出的快速命令实际执行并核对输出；机器不能从代码块存在证明可执行。人工检查新读者是否知道从哪里开始及失败后怎么办。

### PGE-06 导航、成熟度与版本

- **适用、责任与输入：** 维护者输入当前规范目录、已采用快照及发行状态；各领域负责人提供可达入口。
- **必要步骤与输出：** 必须保留面向任务的主导航和领域导航，区分当前草案、已采用版本与历史。版本/贡献/安全/许可链接保持可发现；首页只总结成熟度，不承载逐次审查日志、内部排班或任务调度。
- **失败、未知与恢复：** 中央登记尚未更新时，不把新正文称为已登记或采用；明确草案入口。导航与登记不一致需修订后复验，旧版本保留原状态。
- **正确案例：** 规范采用、文档版本与实际 Release 分别呈现，并各自链接准确对象。
- **直接失败反例：** 借旧版独审结果写“全部规范已通过”，或导航暗中指向历史副本。
- **合法邻例：** README不展示测试数量，仅链接维护与版本政策，依然完整。
- **验收与自动/人工边界：** 自动验证链接目标和两语言导航合同；人工比对状态所指的具体版本。导航覆盖不等于各领域技术充分。

### PGE-07 中英文入口的同义与回退

- **适用、责任与输入：** 中文作者与英文译者输入相同范围、步骤、状态和导航清单；中文为权威源。
- **必要步骤与输出：** 英文README必须提供真实对应的完整入口内容而非“coming soon”；保持任务、状态、命令、限制与许可含义一致，并双向链接。只有中文的目标须标明Chinese only，不用英文标题伪装英文全文。
- **失败、未知与恢复：** 源文改变而译文未跟随时登记outdated并告知回退中文；争议含义按中文核对，不由英文扩大权限或义务。修复后重算摘要并实读。
- **正确案例：** 英文领域列表明确其目标目前为中文；已翻译的草案链接真实英文正文。
- **直接失败反例：** 英文写已正式发行，中文仅为草案；或把中文目录称为English documentation。
- **合法邻例：** 法律通知暂只有中文但英文清楚说明状态和入口，不伪称有英文许可全文。
- **验收与自动/人工边界：** 自动核双方锚点、相同导航角色/目标与命令合同；译者逐段实读语义、限制和例子。摘要一致只能证明身份，不能证明翻译准确。

### PGE-08 入口变更的验收与维护

- **适用、责任与输入：** 提交入口变更的作者提供文件摘要、修改范围、真实检查结果和渲染目标；接收维护者复核，不把自评当独立审查。
- **必要步骤与输出：** 必须对修改后的准确对象执行链接/徽章/语言合同检查，核对Shields.io官方标准地址、编码文字、目标与状态依据，拒绝手工仿制徽章；删除配置不得使当前项目绕过标准徽章要求。完成最短路径与窄宽屏阅读，输出带对象身份的通过、失败、未执行和待人工项；旧审查仅属于其原对象。
- **失败、未知与恢复：** 任一关键入口断裂或状态失实则入口验收失败；修复后重跑直接坏例及合法邻例。平台不可访问时保留本地结果并列目标平台未验，不用本地截图冒充远端。
- **正确案例：** 本地Chromium两宽度截图及链接测试分别记录，远端渲染未执行。
- **直接失败反例：** 只统计“使用、安全、许可”出现次数便认定README合格。
- **合法邻例：** 仅修错别字可缩小人工复读范围，但准确文件摘要、链接与受影响译文仍复核。
- **验收与自动/人工边界：** 检查入口为checks/project_readme.py、checks/readme_badges.py及对应测试；直接坏例包括非Shields.io地址、文字或目标不一致、虚构状态和删除必需协议配置，合法邻例包括采用官方转义格式且与本地依据一致的徽章。人工判读自然语言、视觉、动态状态依据及无障碍目的。完整验收需要两者，机器通过不授权发布或采用。
