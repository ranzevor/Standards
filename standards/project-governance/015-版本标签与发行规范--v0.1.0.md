# 版本标签与发行规范

**文档ID：** STD-PG-015　**版本：** 0.1.0　**状态：** adopted　**生效日期：** 2026-10-30

## 对象和术语

适用于供使用者取得的文档/软件版本、源码标签、安装包和正式发行；本地候选不是已发布版本。文档修订号、软件版本、仓库交付集合及规范采用状态分别登记。发行者管理清单和实际发布，维护者确认支持范围，权利决定者确认许可，采用者决定规范范围。版本规则可选SemVer或其他明确方案，不把SemVer强加给不声明公共API的研究结果。依赖[PGC](009-变更提案审查与合并规范--v0.1.0.md)、[PGQ](011-测试质量门禁与证据规范--v0.1.0.md)、[PGL](014-权属许可与第三方材料规范--v0.1.0.md)。

## PGV-01 版本空间与兼容语义

**输入与前置：** 公共API/格式/协议、文档义务、支持承诺和所选版本方案。

**操作步骤：** 明确每个版本号标识哪个对象；记录新增/修正/破坏性变化及兼容消费者。采用SemVer时按其2.0.0规则定义公共API和主/次/修订语义；文档义务改变单列迁移，不由仓库版本号推导规范已采用。已发行同版本内容不静默替换。

**输出与验收：** 使用者可从版本说明判断兼容和迁移；候选/预发行标识不会被写成正式发布或真实部署。

**失败与恢复：** 错标兼容性时给更正、受影响范围和替代版本，保留旧发行身份；不覆写旧标签来掩盖版本错误。

**正例：** 删除公共参数属于兼容破坏，单独列迁移及所选版本方案下的版本变化。

**直接失败反例：** 将规范正文改为新内容却保留原同版本摘要和采用决定。

**合法邻例：** 研究数据集使用日期/内容身份版本，不冒称SemVerAPI保证。

**检查入口：** 版本/声明/文件名与差异类型的一致性可核；兼容语义实审。

## PGV-02 发行清单和准备门禁

**输入与前置：** 完整候选、必要检查、独审、许可/通知、依赖和维护安排。

**操作步骤：** 发行构建从实际交付集合生成完整文件清单、长度和摘要，并随制品交付；源码关联准确commit/tree。发行说明列工具/锁定、用户相关变更、适用/支持、已知缺陷、安装/恢复和必要决定。准备门禁核必要项、当前结果及未决事项，区分ready-for-review与ready-to-publish。

**输出与验收：** 所有拟分发对象在清单内，必要阻断未解决时不能ready-to-publish；无发行任务的文档修订可停在可审候选。

**失败与恢复：** 制品缺失/检查陈旧/许可范围未定时定位对应阻断，继续不依赖该项的工作，不编造“批准人”填空。

**正例：** 本地规范候选含完整文档和离线工具，但根许可尚待决定时不声明公开发行准备通过。

**直接失败反例：** 仅因测试退出0就发布未核权利的第三方字体。

**合法邻例：** 项目无二进制制品，只发行源码/文档集合，清单准确列这些对象。

**检查入口：** `release_ready`有限模型核完整必要集合、精确证据和分发前置，不认证真实权利或发布权限。

## PGV-03 标签、源码与制品关联

**输入与前置：** 准确发布提交、标签名、所选标签/签名策略及构建制品。

**操作步骤：** 创建前确认源码对象与门禁一致；根据策略使用附注标签，记录标签对象和peeled commit。制品记录自身摘要及构建输入，不从tag名字推导包内容。需要签名时验证签名者信任与具体对象；不需要签名的项目准确说明未建立该保证。

**输出与验收：** 标签解析到预期提交，制品摘要及清单一致；签名结果属于具体签名对象，而不是全部项目安全认证。

**失败与恢复：** 同名标签已存在时先核对象，不覆盖公开标签；错标发行通过新标识更正或撤回。创建/上传超时先查实际标签/对象再重试。

**正例：** `git tag -a v0.1.0 <commit> -m 'Version 0.1.0'`后核`git rev-parse v0.1.0^{commit}`等于预定提交。

**直接失败反例：** tag指向新提交，但安装包仍是缓存里的旧源码构建物。

**合法邻例：** 本地合成标签场景验证解析关系，不声称远端发行已发生。

**检查入口：** 本地Git实例实际验标签/提交；制品和签名按目标构建/验证工具执行。

## PGV-04 发布操作与结果核对

**输入与前置：** 准备门禁、准确目标、发布范围和实际所需权限/确认。

**操作步骤：** 发布前重新读取目标状态和版本占用；上传/登记后从目标读回版本、来源、文件集合和内容身份。发布事件、规范采用决定、生产部署分别记录，不让其中一个自动触发另外两个。

**输出与验收：** 用户可从正式入口取得预期准确内容；状态为published须有实际可访问对象及读回证据。

**失败与恢复：** 上传部分成功或响应丢失时记partial/unknown并查目标；只有已确认未执行或按目标明确幂等合同安全时才重试。不得因取消客户端就认定远端没有创建对象。

**正例：** 上传后逐制品核摘要，再更新正式下载入口。

**直接失败反例：** 工具开始上传就把CHANGELOG写为已正式发布。

**合法邻例：** 仅本地交付的项目以本地准确集合为交付对象，不制造远端Release事实。

**检查入口：** 发布状态有限模型核证据和未知分支；真实目标读回是必要独立验收。

## PGV-05 发行失败、撤回和恢复

**输入与前置：** 错误版本/制品、受影响消费者、原始失败及可用替代。

**操作步骤：** 区分源码修复、制品重建、版本撤回、下载入口更正和运行回滚；通知具体影响、替代版本和迁移。保留旧身份与撤回原因，按生态规则处理不可重发版本；不删全部历史来伪装没有发布。

**输出与验收：** 旧新对象关联明确，用户能避免或处理错误版本；恢复后重新核清单、取得路径及兼容。

**失败与恢复：** 旧程序不兼容新数据时走PGU恢复点/前向修复；消费者已取得的副本不会因撤回自动消失，需另有补救。

**正例：** 发行0.1.1修复安装脚本，并明确0.1.0错误与受影响平台。

**直接失败反例：** 用同名包替换内容，旧摘要和签名仍对外宣称有效。

**合法邻例：** 未分发的本地失败构建可重建，保留必要失败记录，不假称撤回了公开版本。

**检查入口：** 撤回/替代关系和状态记录可核；消费者影响及实际取得行为实测。

## PGV-06 发行后的采用和维护接口

**输入与前置：** 准确发行集合、支持矩阵、采用选择和维护状态。

**操作步骤：** 将版本/制品/已知限制交给维护和采用接口；采用方锁定实际选择，不因上游发新版本自动升级。文档更正/安全更新通知包含是否影响必要义务、配置和迁移，不只写“请更新”。

**输出与验收：** 从发行能追到维护范围与采用变更条件；发行存在不证明所有下游已升级或全部实现通过。

**失败与恢复：** 发现漏通知或支持信息矛盾时更正当前入口并保留原记录；已停止支持版本按PGA给替代和保留策略。

**正例：** 新版发布通知列破坏性字段和旧版支持窗口，项目自行按准确条款决定升级。

**直接失败反例：** 上游新tag出现就覆写项目锁定的规范版本。

**合法邻例：** 同一软件版本可被不同项目在不同时间采用，状态分别登记。

**检查入口：** [PGN](020-规范采用例外与升级规范--v0.1.0.md)、[PGM](017-维护响应与兼容承诺规范--v0.1.0.md)的接口记录与实际消费者核验。
