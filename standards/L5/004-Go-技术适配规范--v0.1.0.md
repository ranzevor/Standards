# L5 Go 技术适配规范

**文档ID：** STD-L5-004　**版本：** 0.1.0　**状态：** adopted　**生效日期：** 2026-10-30

## 定位、适用与非目标

本画像提供本体系对 Go 的技术适配合同：将L3/L4的状态、数据、权限、兼容与验收要求落实到真实语言/运行时/工具入口。它不是重写完整语言标准或某框架教程，也不要求全部项目采用此栈。列出的固定资料版本用于可复核技术命题和示例，不构成全组织版本推荐、所有版本支持承诺或当前安全状态保证。项目L6必须选择实际受支持版本、发行/维护政策和具体平台，不得用画像存在替代该决定。

“必须/不得”为采用且触发时必要要求；“应/建议”偏离需理由与等价保障；“可/示例”不增加功能或权限。运行时是实际执行对象，工具链包括编译/解析/构建工具，宿主/target是提供API、ABI与系统能力的环境。类型/静态检查、有限样例、隔离目标与真实业务验收分别报告。

通用依赖：[L3通用工程](../L3/001-通用工程规范--v0.1.0.md)、[L6采用接口](../L6/001-项目采用与实现验收接口规范--v0.1.0.md)。具体领域按真实组成组合采用；技术参考不自动生效。逐命题来源见[十类适配来源](../../sources/stack-adapters.md)，本画像中组织工程动作由其反例及不变量说明理由，不冒称官方规范逐字规定。

- **适用条件与主体：** Go模块维护者。 仅实际具备该对象或已承诺能力时适用，不为满足文档新增不存在的功能。
- **输入、输出与权威：** 输入是准确源码/制品、有效项目合同、实际运行版本/配置及具体数据；输出为本条所列可检查工件和结果。权威由目标实现与原始输入证明，不能由类型标签、测试名或缓存摘要自证。
- **必要机制：** 必须验证可执行文件确是Go工具链并固定版本、GOOS/GOARCH、go.mod、go.sum及实际构建依赖。go.sum是校验记录而非完整锁文件，replace、workspace、vendor与工具链选择均影响来源；离线模式不自动证明来源可信。
- **失败、并发、未知与恢复：** 同名go程序、自动下载工具链或代理缺项不得被当已构建；先核go version及go env后再执行。
- **产物与可观察验收：** 从固定模块输入解析实际构建列表，比较包路径、替换和产物身份，支持架构分别构建/运行。
- **正确案例：** 实际Go编译器输出明确版本并固定模块来源。
- **直接失败反例：** 系统有名为go的棋类程序就声称Go测试可运行。
- **合法邻例：** 纯标准库单文件可无外部go.sum，但须固定源码和工具链。
- **来源与消费接口：** GO-01,GO-02；本条消费L3相应工程机制和实际L4合同，提供具体工具/API与失败边界给L6。真实检查按本条命令/观察点记录版本、输入、退出与日志；本仓文档结构检查不认证实现。

- **必要机制：** 必须区分零值、nil接口与含typed nil的接口、切片/映射别名、错误值和缺字段；JSON数值/金额/时间按合同精确保留。接口值比较、复制结构体及共享底层数组不能按外观推独立所有权。
- **失败、并发、未知与恢复：** nil/空集合/未知字段按业务有确定行为；不把所有err转nil，外部写入失败需区分未知与未执行。
- **产物与可观察验收：** 测试typed nil、0、空切片、共享slice变更、超数值范围和合法Unicode，核返回/错误与字段保真。

- **直接失败反例：** 接口不为nil便推底层指针可解引用。
- **合法邻例：** 合同允许nil表示无结果时不强制造空对象。

## STK-03 goroutine、channel与内存顺序

- **适用条件与主体：** 并发任务和共享资源拥有者。 仅实际具备该对象或已承诺能力时适用，不为满足文档新增不存在的功能。
- **输入、输出与权威：** 输入是准确源码/制品、有效项目合同、实际运行版本/配置及具体数据；输出为本条所列可检查工件和结果。权威由目标实现与原始输入证明，不能由类型标签、测试名或缓存摘要自证。
- **必要机制：** 必须以channel、mutex或atomic建立所需同步与原子边界；goroutine退出、close和发送角色明确，防发送关闭channel及泄漏。Go无数据竞争可按其模型推顺序行为，但不能据此推业务事务或全局顺序。
- **失败、并发、未知与恢复：** 取消ctx是协作信号，不杀goroutine或回滚远端；阻塞发送/接收须有退出路径并观察清理。
- **产物与可观察验收：** 固定交错/取消/关闭场景，运行适用go test -race；未发现race不证明全部调度正确。
- **正确案例：** 单一关闭拥有者协作终止并等待子任务退出。
- **直接失败反例：** close(channel)被当作停止全部后台外部写入。
- **合法邻例：** 独立只读任务可并发，不强制一个大锁串行化。
- **来源与消费接口：** GO-02,GO-03；本条消费L3相应工程机制和实际L4合同，提供具体工具/API与失败边界给L6。真实检查按本条命令/观察点记录版本、输入、退出与日志；本仓文档结构检查不认证实现。

## STK-04 资源、错误与未知提交

- **适用条件与主体：** 文件、HTTP、SQL或流调用实现者。 仅实际具备该对象或已承诺能力时适用，不为满足文档新增不存在的功能。
- **输入、输出与权威：** 输入是准确源码/制品、有效项目合同、实际运行版本/配置及具体数据；输出为本条所列可检查工件和结果。权威由目标实现与原始输入证明，不能由类型标签、测试名或缓存摘要自证。
- **必要机制：** 必须处理Close、defer、错误包装/分类及context期限；defer执行时点按函数退出而非块结束，循环资源需要相称范围。连接错误/ctx超时不证明目标事务未提交，幂等与核对消费L4。
- **失败、并发、未知与恢复：** 清理失败保留影响；HTTP body/流关闭不等业务成功，重试不得重置根预算或创建新意图。
- **产物与可观察验收：** 注入返回/错误/取消及部分读取，观察资源数、错误类别和原意图权威状态。
- **正确案例：** 响应体受控读取并关闭，提交结果另回查。
- **直接失败反例：** err!=nil便无条件再发一次扣款。
- **合法邻例：** 只读纯函数无资源无需defer装饰。
- **来源与消费接口：** GO-03；本条消费L3相应工程机制和实际L4合同，提供具体工具/API与失败边界给L6。真实检查按本条命令/观察点记录版本、输入、退出与日志；本仓文档结构检查不认证实现。

## STK-06 验证与L4/L6接口

- **适用条件与主体：** 项目采用/验收者。 仅实际具备该对象或已承诺能力时适用，不为满足文档新增不存在的功能。
- **输入、输出与权威：** 输入是准确源码/制品、有效项目合同、实际运行版本/配置及具体数据；输出为本条所列可检查工件和结果。权威由目标实现与原始输入证明，不能由类型标签、测试名或缓存摘要自证。
- **必要机制：** 必须从Go具体函数/配置映射L4错误、并发、协议与资源合同。最小命令go test ./...、go test -race ./...（按平台支持）、go vet ./...及实际发行消费者；固定网络访问与依赖前提。
- **失败、并发、未知与恢复：** 工具链不存在或同名工具不符记not-run，不能运行未知二进制后把输出当Go证据。合成并发不等耐久分布式。
- **产物与可观察验收：** 记录真实版本/命令/退出/原始日志及未执行平台，正反例和合法无网络邻例同时保持。
- **正确案例：** 已核来源和文件身份显示PATH中的同名go不是目标Go工具链；操作者保留该观察、不执行未知程序，将Go编译与测试记not-run，取得准确工具链后另行验收。
- **直接失败反例：** 用别的语言模拟通过便标Go编译测试pass。
- **合法邻例：** 无外部依赖的项目可离线运行，存在合法不共享状态任务不被误拒。
- **来源与消费接口：** GO-01,GO-02,GO-03；本条消费L3相应工程机制和实际L4合同，提供具体工具/API与失败边界给L6。真实检查按本条命令/观察点记录版本、输入、退出与日志；本仓文档结构检查不认证实现。
