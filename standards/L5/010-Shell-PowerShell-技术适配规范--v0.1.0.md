# L5 Shell / PowerShell 技术适配规范

**文档ID：** STD-L5-010　**版本：** 0.1.0　**状态：** adopted　**生效日期：** 2026-10-30

## 定位、适用与非目标

本画像提供本体系对 Shell / PowerShell 的技术适配合同：将L3/L4的状态、数据、权限、兼容与验收要求落实到真实语言/运行时/工具入口。它不是重写完整语言标准或某框架教程，也不要求全部项目采用此栈。列出的固定资料版本用于可复核技术命题和示例，不构成全组织版本推荐、所有版本支持承诺或当前安全状态保证。项目L6必须选择实际受支持版本、发行/维护政策和具体平台，不得用画像存在替代该决定。

“必须/不得”为采用且触发时必要要求；“应/建议”偏离需理由与等价保障；“可/示例”不增加功能或权限。运行时是实际执行对象，工具链包括编译/解析/构建工具，宿主/target是提供API、ABI与系统能力的环境。类型/静态检查、有限样例、隔离目标与真实业务验收分别报告。

通用依赖：[L3通用工程](../L3/001-通用工程规范--v0.1.0.md)、[L6采用接口](../L6/001-项目采用与实现验收接口规范--v0.1.0.md)。具体领域按真实组成组合采用；技术参考不自动生效。逐命题来源见[十类适配来源](../../sources/stack-adapters.md)，本画像中组织工程动作由其反例及不变量说明理由，不冒称官方规范逐字规定。

## STK-01 解释器、模式与工具身份

- **适用条件与主体：** 脚本与集成工具维护者。 仅实际具备该对象或已承诺能力时适用，不为满足文档新增不存在的功能。
- **输入、输出与权威：** 输入是准确源码/制品、有效项目合同、实际运行版本/配置及具体数据；输出为本条所列可检查工件和结果。权威由目标实现与原始输入证明，不能由类型标签、测试名或缓存摘要自证。
- **必要机制：** 必须固定POSIX shell/Bash/PowerShell方言、完整版本、OS、编码/locale、工作目录、外部工具和配置。shebang、交互/非交互、profile加载和Windows原生参数传递均影响语义；不把Bash扩展称通用sh。
- **失败、并发、未知与恢复：** 缺工具、同名程序或不兼容参数受控失败；脚本不能依赖个人profile/别名补成功。
- **产物与可观察验收：** 在实际解释器启动无个人profile的入口并记录版本、工具路径和输入输出字节。
- **正确案例：** Bash脚本明确用bash，PowerShell明确pwsh版本。
- **直接失败反例：** 以sh运行含Bash数组脚本却声称跨shell兼容。
- **合法邻例：** 单平台维护脚本可明确只支持Bash，不强制移植PowerShell。
- **来源与消费接口：** SH-01,SH-02；本条消费L3相应工程机制和实际L4合同，提供具体工具/API与失败边界给L6。真实检查按本条命令/观察点记录版本、输入、退出与日志；本仓文档结构检查不认证实现。

## STK-02 引用、参数与不可信文本

- **适用条件与主体：** 启动子进程或处理文件名/输入时的实现者。 仅实际具备该对象或已承诺能力时适用，不为满足文档新增不存在的功能。
- **输入、输出与权威：** 输入是准确源码/制品、有效项目合同、实际运行版本/配置及具体数据；输出为本条所列可检查工件和结果。权威由目标实现与原始输入证明，不能由类型标签、测试名或缓存摘要自证。
- **必要机制：** 必须把参数作为数据而非可执行拼串；Bash保留数组边界与正确引用、固定printf格式，读行按合同使用read -r和IFS；PowerShell区分表达式/参数模式、引号与数组/原生命令传递。不得对外部文本eval或Invoke-Expression。
- **失败、并发、未知与恢复：** 空格、通配符、前导-、换行及非ASCII不能造成额外命令或错文件；合法空参数与多个参数区分，路径权威按目标真实解析。
- **产物与可观察验收：** 传入含空格、*、引号、分号及Unicode路径，观察子进程实际argv和无额外副作用。
- **正确案例：** printf %s "$value"保持值为数据。
- **直接失败反例：** 将用户文件名拼成eval命令，或把值当printf格式。
- **合法邻例：** 明确允许shell表达式的受信管理接口须独立权限与合同，不把其规则用于普通参数。
- **来源与消费接口：** SH-01,SH-02；本条消费L3相应工程机制和实际L4合同，提供具体工具/API与失败边界给L6。真实检查按本条命令/观察点记录版本、输入、退出与日志；本仓文档结构检查不认证实现。

## STK-03 退出码、管道与流

- **适用条件与主体：** CLI/自动化调用实现者。 仅实际具备该对象或已承诺能力时适用，不为满足文档新增不存在的功能。
- **输入、输出与权威：** 输入是准确源码/制品、有效项目合同、实际运行版本/配置及具体数据；输出为本条所列可检查工件和结果。权威由目标实现与原始输入证明，不能由类型标签、测试名或缓存摘要自证。
- **必要机制：** 必须定义stdout数据、stderr诊断、退出码和部分输出；Bash set -e并非完整错误处理，pipeline/条件上下文按实际版本显式检查。PowerShell非终止错误、异常及原生LASTEXITCODE分别处理，不能只看打印的success。
- **失败、并发、未知与恢复：** 管道下游关闭/磁盘满/部分写入保留失败；命令超时不证明远端动作未发生，按原意图核对。
- **产物与可观察验收：** 成功/业务拒绝/缺文件/管道中段失败/空输出各核实际exit及两个流，合法无输出不误判失败。
- **正确案例：** 固定pipefail或显式各段结果且保持合同。
- **直接失败反例：** 最后一段成功掩盖前段关键转换失败。
- **合法邻例：** 没有管道的简单脚本无需新增pipefail依赖，但仍核实际命令退出。
- **来源与消费接口：** SH-01,SH-02；本条消费L3相应工程机制和实际L4合同，提供具体工具/API与失败边界给L6。真实检查按本条命令/观察点记录版本、输入、退出与日志；本仓文档结构检查不认证实现。

## STK-04 信号、子进程与文件发布

- **适用条件与主体：** 长期脚本/作业/文件集成拥有者。 仅实际具备该对象或已承诺能力时适用，不为满足文档新增不存在的功能。
- **输入、输出与权威：** 输入是准确源码/制品、有效项目合同、实际运行版本/配置及具体数据；输出为本条所列可检查工件和结果。权威由目标实现与原始输入证明，不能由类型标签、测试名或缓存摘要自证。
- **必要机制：** 必须定义SIGINT/TERM/PowerShell取消、子进程组、清理和发布临时文件；trap只是处理机会，不保证SIGKILL/断电可清理。临时路径唯一且权限相称，替换/耐久语义依平台/文件系统核，锁与并发条件真实有效。
- **失败、并发、未知与恢复：** 退出请求后子进程或远端仍可能执行，不能立刻标撤销；错误清理不删除权威输入或原失败，旧运行不能覆盖新输出。
- **产物与可观察验收：** 在写入前/中/发布前注入终止、并发和目标已存在，观察旧/新完整对象、子进程和未知结果。
- **正确案例：** 先验证完整临时输出再按目标合同发布。
- **直接失败反例：** trap能清理就声称任何崩溃无部分输出或重复效果。
- **合法邻例：** 只读短脚本无需原子文件发布流程，但信号和退出语义仍明确。
- **来源与消费接口：** SH-01；本条消费L3相应工程机制和实际L4合同，提供具体工具/API与失败边界给L6。真实检查按本条命令/观察点记录版本、输入、退出与日志；本仓文档结构检查不认证实现。

- **必要机制：** 必须限定环境变量/工作目录/PATH与凭据注入用途；脚本、依赖下载及profile是执行边界，不能输出秘密或把不可信服务输出当命令。仓库名、包名、文件路径和命令名分别按生态合同。
- **失败、并发、未知与恢复：** 错误环境不得默默指向生产；部分分发/版本共存核真实目标脚本/工具身份。回退脚本不撤销外部交易。

- **直接失败反例：** set -x把实际令牌写进交付日志。

- **合法邻例：** 只支持Bash的离线工具可不运行PowerShell，范围必须真实明确。
