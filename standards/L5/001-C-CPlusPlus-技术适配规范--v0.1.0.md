# L5 C / C++ 技术适配规范

**文档ID：** STD-L5-001　**版本：** 0.1.0　**状态：** adopted　**生效日期：** 2026-10-30

## 定位、适用与非目标

本画像提供本体系对 C / C++ 的技术适配合同：将L3/L4的状态、数据、权限、兼容与验收要求落实到真实语言/运行时/工具入口。它不是重写完整语言标准或某框架教程，也不要求全部项目采用此栈。列出的固定资料版本用于可复核技术命题和示例，不构成全组织版本推荐、所有版本支持承诺或当前安全状态保证。项目L6必须选择实际受支持版本、发行/维护政策和具体平台，不得用画像存在替代该决定。

“必须/不得”为采用且触发时必要要求；“应/建议”偏离需理由与等价保障；“可/示例”不增加功能或权限。运行时是实际执行对象，工具链包括编译/解析/构建工具，宿主/target是提供API、ABI与系统能力的环境。类型/静态检查、有限样例、隔离目标与真实业务验收分别报告。

通用依赖：[L3通用工程](../L3/001-通用工程规范--v0.1.0.md)、[L6采用接口](../L6/001-项目采用与实现验收接口规范--v0.1.0.md)。具体领域按真实组成组合采用；技术参考不自动生效。逐命题来源见[十类适配来源](../../sources/stack-adapters.md)，本画像中组织工程动作由其反例及不变量说明理由，不冒称官方规范逐字规定。

- **适用条件与主体：** C/C++组件维护者。 仅实际具备该对象或已承诺能力时适用，不为满足文档新增不存在的功能。
- **输入、输出与权威：** 输入是准确源码/制品、有效项目合同、实际运行版本/配置及具体数据；输出为本条所列可检查工件和结果。权威由目标实现与原始输入证明，不能由类型标签、测试名或缓存摘要自证。
- **必要机制：** 必须固定C/C++语言级别、编译器/标准库、target/ABI、编译链接选项、宏/生成输入和实际依赖。C与C++不是同一语言画像；架构字长、对齐、端序、异常/RTTI及运行库关系按实际边界记录。
- **失败、并发、未知与恢复：** 隐式换编译器、扩展语法或链接库不得掩盖旧target不支持；构建成功不等运行通过。
- **产物与可观察验收：** 在声明目标用-std=实际版本构建并记录命令/警告/产物依赖；发行消费者核ABI和资源。
- **正确案例：** C17与C++20示例分开用gcc/g++构建。
- **直接失败反例：** 同头文件能编译就推任意编译器二进制兼容。
- **合法邻例：** 纯C库不强制采用C++异常或RAII，但须等价资源管理。
- **来源与消费接口：** CC-01,CC-02；本条消费L3相应工程机制和实际L4合同，提供具体工具/API与失败边界给L6。真实检查按本条命令/观察点记录版本、输入、退出与日志；本仓文档结构检查不认证实现。

## STK-02 内存、边界与未定义行为

- **适用条件与主体：** 缓冲/指针/数值/原生接口实现者。 仅实际具备该对象或已承诺能力时适用，不为满足文档新增不存在的功能。
- **输入、输出与权威：** 输入是准确源码/制品、有效项目合同、实际运行版本/配置及具体数据；输出为本条所列可检查工件和结果。权威由目标实现与原始输入证明，不能由类型标签、测试名或缓存摘要自证。
- **必要机制：** 必须在解引用、索引、长度/乘法计算、对象生存期和类型别名前验证前提；定义分配/释放和错误所有权。损坏输入不得靠越界后捕异常恢复，签名/类型并不证明外部数据合法。
- **失败、并发、未知与恢复：** 长度溢出、分配失败、部分初始化和中途错误安全退出且不发布部分权威对象；不能把测试未崩溃当无UB。
- **产物与可观察验收：** 检查零/最大合法/超界、溢出和失败点；适用sanitizer/静态分析补充，显式指出未覆盖调度/硬件。
- **正确案例：** 先验证n<=capacity及运算不会溢出再复制。
- **直接失败反例：** 先memcpy再判断长度是否过大。
- **合法邻例：** 零长度合同合法时不得要求额外有效载荷或误读空缓冲。
- **来源与消费接口：** CC-01,CC-02；本条消费L3相应工程机制和实际L4合同，提供具体工具/API与失败边界给L6。真实检查按本条命令/观察点记录版本、输入、退出与日志；本仓文档结构检查不认证实现。

## STK-03 并发、volatile与设备访问

- **适用条件与主体：** 线程、ISR/设备或共享内存实现者。 仅实际具备该对象或已承诺能力时适用，不为满足文档新增不存在的功能。
- **输入、输出与权威：** 输入是准确源码/制品、有效项目合同、实际运行版本/配置及具体数据；输出为本条所列可检查工件和结果。权威由目标实现与原始输入证明，不能由类型标签、测试名或缓存摘要自证。
- **必要机制：** 必须区分volatile设备可见访问与语言线程同步；普通非原子竞争不因volatile消失。使用对应语言原子/锁并说明内存序、对象初始化和业务原子边界；ISR/DMA/缓存一致性由实际平台合同补足。
- **失败、并发、未知与恢复：** 取消标志/时钟回绕/旧任务不能造成资源提前释放；多字段原子性、掉电持久与线程同步不同。
- **产物与可观察验收：** 受控交错验不变量，平台支持时使用race检测；设备期限与物理动作仅由真实台架证据支持。
- **正确案例：** 使用明确同步保护共享复合状态。
- **直接失败反例：** volatile余额++被当线程安全事务。
- **合法邻例：** 无多线程的设备寄存器volatile访问不被机械替换为不适用的普通原子。
- **来源与消费接口：** CC-01,CC-02；本条消费L3相应工程机制和实际L4合同，提供具体工具/API与失败边界给L6。真实检查按本条命令/观察点记录版本、输入、退出与日志；本仓文档结构检查不认证实现。

## STK-04 错误、资源与外部结果

- **适用条件与主体：** C返回码/errno或C++异常和资源拥有者。 仅实际具备该对象或已承诺能力时适用，不为满足文档新增不存在的功能。
- **输入、输出与权威：** 输入是准确源码/制品、有效项目合同、实际运行版本/配置及具体数据；输出为本条所列可检查工件和结果。权威由目标实现与原始输入证明，不能由类型标签、测试名或缓存摘要自证。
- **必要机制：** 必须定义成功/失败/部分/未知结果，检查短读写/中断/返回码；C清理路径和C++RAII覆盖异常，析构/close不自动证明fsync、事务提交或远端撤销。回调/异步IO所有权跨完成边界明确。
- **失败、并发、未知与恢复：** 清理失败保留原影响；超时后内核/设备/远端仍可能执行，按原意图核对，不能释放仍被使用缓冲或创建重复效果。
- **产物与可观察验收：** 注入读写部分完成、分配失败、异常和取消，观察句柄、缓冲生命周期与权威状态。
- **正确案例：** 异步操作明确完成后再回收其缓冲。
- **直接失败反例：** 发出取消便立即free仍在DMA使用的内存。
- **合法邻例：** 纯值计算无句柄可只定义返回错误和数值边界。
