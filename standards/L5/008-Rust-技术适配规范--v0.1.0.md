# L5 Rust 技术适配规范

**文档ID：** STD-L5-008　**版本：** 0.1.0　**状态：** adopted　**生效日期：** 2026-10-30

## 定位、适用与非目标

本画像提供本体系对 Rust 的技术适配合同：将L3/L4的状态、数据、权限、兼容与验收要求落实到真实语言/运行时/工具入口。它不是重写完整语言标准或某框架教程，也不要求全部项目采用此栈。列出的固定资料版本用于可复核技术命题和示例，不构成全组织版本推荐、所有版本支持承诺或当前安全状态保证。项目L6必须选择实际受支持版本、发行/维护政策和具体平台，不得用画像存在替代该决定。

“必须/不得”为采用且触发时必要要求；“应/建议”偏离需理由与等价保障；“可/示例”不增加功能或权限。运行时是实际执行对象，工具链包括编译/解析/构建工具，宿主/target是提供API、ABI与系统能力的环境。类型/静态检查、有限样例、隔离目标与真实业务验收分别报告。

通用依赖：[L3通用工程](../L3/001-通用工程规范--v0.1.0.md)、[L6采用接口](../L6/001-项目采用与实现验收接口规范--v0.1.0.md)。具体领域按真实组成组合采用；技术参考不自动生效。逐命题来源见[十类适配来源](../../sources/stack-adapters.md)，本画像中组织工程动作由其反例及不变量说明理由，不冒称官方规范逐字规定。

- **适用条件与主体：** Rust工程维护者。 仅实际具备该对象或已承诺能力时适用，不为满足文档新增不存在的功能。
- **输入、输出与权威：** 输入是准确源码/制品、有效项目合同、实际运行版本/配置及具体数据；输出为本条所列可检查工件和结果。权威由目标实现与原始输入证明，不能由类型标签、测试名或缓存摘要自证。
- **必要机制：** 必须固定rustc/cargo版本、edition、target、feature及Cargo.lock适用策略；build.rs/proc-macro是构建执行面。--locked锁既有解析、--offline限制联网，--frozen组合两者，不提供来源信任或字节可复现的自动证明。
- **失败、并发、未知与恢复：** 缺锁或解析改变应按合同失败，离线缓存缺依赖不悄然改版；可选feature统一核实际依赖及行为。
- **产物与可观察验收：** 比较cargo metadata/构建列表与实际target、feature，干净或声明缓存环境复现同一选择。
- **正确案例：** 已固定应用锁文件用cargo build --locked --offline。
- **直接失败反例：** 认为--locked禁止网络并保证依赖无恶意。
- **合法邻例：** 纯无依赖库可有相称锁策略，不把二进制应用习惯机械套所有库消费者。

## STK-02 所有权、unsafe与FFI

- **适用条件与主体：** 安全抽象、原生接口和数据边界实现者。 仅实际具备该对象或已承诺能力时适用，不为满足文档新增不存在的功能。
- **输入、输出与权威：** 输入是准确源码/制品、有效项目合同、实际运行版本/配置及具体数据；输出为本条所列可检查工件和结果。权威由目标实现与原始输入证明，不能由类型标签、测试名或缓存摘要自证。
- **必要机制：** 必须明确借用/别名/生命周期、初始化、布局和FFI所有权；unsafe并不允许未定义行为，安全调用者必须不能触发抽象内部UB。反序列化、路径、授权和领域数值仍需运行时校验，不因编译通过视为可信。
- **失败、并发、未知与恢复：** 跨FFI释放、未对齐/悬垂/竞态属于需审计前提；不能靠捕获panic修复UB。资源部分初始化失败按所有权安全回收。
- **产物与可观察验收：** 列unsafe不变量及每个调用者保证，正反/边界输入核运行拒绝，适用Miri/sanitizer的支持范围明确。
- **正确案例：** FFI缓冲在约定分配器和生命周期内释放。
- **直接失败反例：** unsafe块包住越界指针就声称Rust已保证内存安全。
- **合法邻例：** 完全安全Rust纯值转换无需制造unsafe审核清单，但输入语义仍校验。
- **来源与消费接口：** RS-02；本条消费L3相应工程机制和实际L4合同，提供具体工具/API与失败边界给L6。真实检查按本条命令/观察点记录版本、输入、退出与日志；本仓文档结构检查不认证实现。

## STK-03 Result、panic与取消

- **适用条件与主体：** 库/异步任务/资源拥有者。 仅实际具备该对象或已承诺能力时适用，不为满足文档新增不存在的功能。
- **输入、输出与权威：** 输入是准确源码/制品、有效项目合同、实际运行版本/配置及具体数据；输出为本条所列可检查工件和结果。权威由目标实现与原始输入证明，不能由类型标签、测试名或缓存摘要自证。
- **必要机制：** 必须区分可预期Result错误、panic策略和进程终止；Drop不是数据库提交证明。异步取消/丢弃future的行为取决于实际runtime/API，不能从await或Send推导在途外部操作已撤回。
- **失败、并发、未知与恢复：** 失败和取消后的资源/事务/锁按实际库合同恢复；跨FFI展开规则和panic=abort区别固定，旧任务效果未知回查原意图。
- **产物与可观察验收：** 注入Result Err、panic/abort边界和异步取消，核本地清理及权威外部状态而非只看任务句柄。
- **正确案例：** 超时后保留未知写并查询目标。
- **直接失败反例：** 丢弃future便认为后台spawn任务和远程写都停止。
- **合法邻例：** 同步纯函数不必引入异步runtime。

## STK-04 并发同步与能力边界

- **适用条件与主体：** 线程/共享状态/插件维护者。 仅实际具备该对象或已承诺能力时适用，不为满足文档新增不存在的功能。
- **输入、输出与权威：** 输入是准确源码/制品、有效项目合同、实际运行版本/配置及具体数据；输出为本条所列可检查工件和结果。权威由目标实现与原始输入证明，不能由类型标签、测试名或缓存摘要自证。
- **必要机制：** 必须按Send/Sync实际含义审共享访问，Arc不让内部可变对象自动线程安全，锁/原子覆盖业务不变量。依赖feature、proc-macro、build.rs及动态库按最小必要构建/运行权限验证。
- **失败、并发、未知与恢复：** 锁中panic、poison或死锁恢复按实际实现处理，不无依据继续受损状态。内存线程安全不证明跨进程耐久或授权。
- **产物与可观察验收：** 受控交错测试共享状态，核取消/失败释放与并行独立对象，审unsafe Send/Sync实现的因果依据。
- **正确案例：** Arc<Mutex<状态>>在所需范围保护复合变更。
- **直接失败反例：** Arc计数线程安全被当其内部所有业务更新自动原子。
- **合法邻例：** 无共享可变状态的独立任务可并行，无需单一全局锁。
- **来源与消费接口：** RS-02；本条消费L3相应工程机制和实际L4合同，提供具体工具/API与失败边界给L6。真实检查按本条命令/观察点记录版本、输入、退出与日志；本仓文档结构检查不认证实现。

- **必要机制：** 必须检验公开类型/trait/错误与feature组合、MSRV声明和真实消费者；Rust默认ABI不作稳定跨版本插件合同，C ABI需另定布局/所有权。交付二进制固定target、链接和资源，不仅cargo test源码。

- **正确案例：** C插件边界以明确repr和函数/释放协议验证。
- **直接失败反例：** 库编译通过便宣称任意rustc插件二进制兼容。
