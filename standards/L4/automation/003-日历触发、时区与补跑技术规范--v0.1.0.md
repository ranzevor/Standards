# 日历触发、时区与补跑技术规范

**文档ID：** STD-L4-AUTOMATION-003　**版本：** 0.1.0　**状态：** adopted　**生效日期：** 2026-10-30

## 1 目标、适用与非目标

将名义火次、实际派发、停机补跑和业务期限分开，正确处理DST与iCalendar的具体规则。

**适用：** 定时/周期任务、日历导入及计划变更；无计划任务不需新增调度器。

**非目标：** 不把某Cron实现或RFC5545强加全部调度器；不在此重编完整RRULE解析器。

本文的“必须/不得”为采用相应条款时的必要条件，“应”为需说明偏离理由的建议，“可”为允许选项。外部标准的 MUST/SHOULD 依其原有强度与适用 profile 执行，项目参数不得降低其强制要求。能力不存在可据事实不适用；已承诺但未验的能力仍适用。

## 2 术语、主体与权威状态

名义火次是计划版本在日历坐标中的一次意图，派发尝试可为零/多次；UTC时刻、带TZID当地时间、浮动时间和持续时间不同。计划版本、日历/时区规则版本和执行尝试身份分离。

**主体与所有权：** 计划维护者固定规则与生效边界；调度器计算火次集合；准入器原子映射火次至逻辑执行；操作目标核业务期限及效果。

**前置输入：** 计划定义/版本、TZID或浮动语义、时区规则快照、日历规范/profile、停机区间、起止/排除日期、补跑策略、根预算和目标期限。

**输出与权威观察：** 名义火次集合、UTC解析及歧义理由、跳过/合并/逐次补跑账、派发记录与业务结果；调度器“已创建任务”不是业务完成。

**状态与终点：** 已计划/应到期/准入/跳过或合并/派发/未知/核对完成；漏火次与无工作不同，名义时间不能被实际重试时刻覆盖。

条款 ID 在本文内稳定；全局身份为文档路径、版本与条款 ID 的组合。各条的前置输入、主体和状态继承本节，再叠加本条触发条件。诊断缺失不证明效果未发生；并发、超时、取消请求与真实业务终态分别记录。

## 3 机制、不变量及逐条验收

### AUT-TIME-01 火次身份与计划版本

- **触发/前置：** 新增/修改/恢复一个计划。
- **必要机制：** 必须给名义火次稳定身份，至少含租户/计划/定义版本及日历坐标；同一火次的多个唤醒原子归入同一逻辑执行，人工新意图另有身份。实际运行延迟不改变名义时间；旧新计划的切换边界明确，保留已准入/在途。
- **不变量：** 不能用当前时刻替代历史火次导致重复或丢失；同参数新意图不被永久吞掉。
- **并发、超时、未知与恢复：** 调度/准入并发用存储唯一约束或等价机制；crash后查询原准入，不能靠内存集合保证跨重启唯一。
- **产物与观察点：** 计划版本、名义火次、原子准入及尝试记录。
- **正例：** 同一火次被两个执行器唤醒，仍只有一逻辑执行。
- **直接失败：** 每次重试用当前时间造新火次，重复业务写入。
- **合法邻例：** 两租户同一日历坐标或人工新意图可分别执行。
- **可观察验收：** 并发/重启/计划边界下导出名义集合和实际准入，逐项核身份及派发。
- **来源与限制：** RP03。来源只支持[逐命题表](../../../sources/runtime-protocol/SOURCE-CLAIMS.md)所列命题；其余必要机制是为保持本条不变量而提出的组织综合设计，不声称由单一外部标准规定。

### AUT-TIME-02 日历坐标与DST策略

- **触发/前置：** 计划包含当地时间或规则演进。
- **必要机制：** 必须固定日历、TZID与规则版本，或明确浮动时间随何执行者解释；普通调度器给gap/fold选择及执行次数。持续时间用适用单调时钟，墙钟跳变不延长根期限；不能用固定UTC偏移代表有DST的时区。
- **不变量：** 同一计划版本与规则快照得到可解释集合；时区更新不静默重写历史。
- **并发、超时、未知与恢复：** 重复当地时间须区分实际UTC候选；不存在时间须按所选协议/产品规则处理。无法解析明确失败，不能自动改系统时区。
- **产物与观察点：** 时区快照/版本、候选UTC、选择/忽略原因及期限轨迹。
- **正例：** America/New_York折叠小时被明确选择一次或产品声明的两次。
- **直接失败：** 隐式用服务器本地时区，部署迁移后触发时间改变。
- **合法邻例：** 纯UTC计划不需DST分支，仍核停机与墙钟变化。
- **可观察验收：** 固定gap/fold、跨日/闰日/时区更新及UTC邻例，比较事先列出的完整火次集合。
- **来源与限制：** RP09；RP01。来源只支持[逐命题表](../../../sources/runtime-protocol/SOURCE-CLAIMS.md)所列命题；其余必要机制是为保持本条不变量而提出的组织综合设计，不声称由单一外部标准规定。

### AUT-TIME-03 RFC5545取值与递推不可混同

- **触发/前置：** 声称采用iCalendar RFC5545。
- **必要机制：** 必须遵从所用属性/值类型：§3.3.5带TZID的重复DATE-TIME取第一次；显式不存在DATE-TIME用gap前UTC偏移解释。§3.3.10递推生成的无效日期/不存在当地时间则忽略且不计入COUNT。DTSTART与RRULE模式不一致属规范未定义集合，不能自行选择结果后声称符合。浮动时间不因VCALENDAR有VTIMEZONE而自动变固定时区。
- **不变量：** 显式值解释不套到RRULE无效实例；忽略实例不消耗COUNT。
- **并发、超时、未知与恢复：** 库不支持某规则/profile时拒绝或明确子集，不声称全RFC实现；闰秒按规范/实现支持边界记录，不由普通datetime支持推断。
- **产物与观察点：** ICS、库版本/profile、预期递推及忽略原因。
- **正例：** 每日02:30递推跨春季gap跳过该天且继续计数直到足额。
- **直接失败：** 把gap生成火次平移03:30并计数，仍称RFC5545。
- **合法邻例：** 自定义Cron可有另行明示gap策略，但不冒充iCalendar一致。
- **可观察验收：** 同组显式gap值与递推gap实例分别核；加入fold、Feb30、COUNT和不匹配DTSTART负例。
- **来源与限制：** RP01。来源只支持[逐命题表](../../../sources/runtime-protocol/SOURCE-CLAIMS.md)所列命题；其余必要机制是为保持本条不变量而提出的组织综合设计，不声称由单一外部标准规定。

### AUT-TIME-04 包含、排除与补跑集合

- **触发/前置：** RDATE/EXDATE或停机积压。
- **必要机制：** 采用RFC5545时必须由DTSTART/RRULE/RDATE并集去重后应用EXDATE，排除优先；保留DTSTART供RECURRENCE-ID等身份关联，即使被排除。调度补跑是运行政策另算：跳过/合并/逐次、期限、积压数量/成本和处理顺序明确，不把RFC的递推集合当自动补跑许可。
- **不变量：** 同火次重复包含不双执行；补跑不越业务期限或预算。
- **并发、超时、未知与恢复：** 积压超限有明确未处理/人工决策状态；合并记录被覆盖火次集合，不能只留一个当前时间掩盖漏项。
- **产物与观察点：** 候选/排除/补跑集合、合并覆盖及预算账。
- **正例：** RRULE和RDATE同一火次仅一次，EXDATE剔除，停机后按声明补剩余。
- **直接失败：** 补跑全部历史交易而去重已过期，或COUNT把跳过无效日期算进去。
- **合法邻例：** 无副作用报告可以按明确合并窗口重算。
- **可观察验收：** 停机跨DST/期限、重复RDATE/EXDATE及超积压，逐集合核对并接入效果账未知处理。
- **来源与限制：** RP01；RP03。来源只支持[逐命题表](../../../sources/runtime-protocol/SOURCE-CLAIMS.md)所列命题；其余必要机制是为保持本条不变量而提出的组织综合设计，不声称由单一外部标准规定。

### AUT-TIME-05 控制变更、审计与升级

- **触发/前置：** 暂停/恢复、定义退役或调度器升级。
- **必要机制：** 必须记录控制世代与生效屏障，分开停止未来准入与已在途任务。恢复重核当前定义/许可/目标和未决操作；升级保留计划/日历/连接器联合版本，退役处理计时器、入口与残余义务。
- **不变量：** 暂停不改写已发生事实；恢复不从旧快照无条件重放。
- **并发、超时、未知与恢复：** 迟到旧火次按原身份归账但不越新屏障派发；取消/恢复权限由实际主体规则决定。审计缺失不证明未执行。
- **产物与观察点：** 控制版本、屏障/准入时间线及未决对账。
- **正例：** 暂停后旧结果仍归原执行，不启动下一动作。
- **直接失败：** 停用计划就把在途订单标已撤销，恢复后整链重发。
- **合法邻例：** 一次性纯函数无需耐久工作流引擎，但输入/版本/结果仍可查。
- **可观察验收：** 注入屏障前后唤醒、迟到回调和升级；核新派发、保留效果及恢复集合。
- **来源与限制：** RP03。来源只支持[逐命题表](../../../sources/runtime-protocol/SOURCE-CLAIMS.md)所列命题；其余必要机制是为保持本条不变量而提出的组织综合设计，不声称由单一外部标准规定。

## 4 兼容、迁移与退役

时区规则或计划升级明确从哪一名义火次生效，保留历史解释。UTC计划可无DST分支；iCalendar、Cron和自定义日历分别绑定实现，不用自定义gap策略声称RFC5545一致。

## 5 跨域消费接口

消费基线AUT-02/03/09/13/15；L3提供时钟/状态词义，AUT-EFFECT提供耐久准入和效果账，后端目标提供业务截止/查询；调度器计算集合但不授予补跑动作许可。

接口只定位技术职责，不自动作出规范采用决定。通用状态、测试和制品义务消费 [L3 通用工程 v0.1.0](../../L3/001-通用工程规范--v0.1.0.md)；提供方版本与摘要、应用条款、实现入口和验收责任在项目契约中绑定。提供方保证须由相应实现证据支持，消费方按该保证的实际范围验收。

## 6 真实目标验收合同

真实调度器提供离线“下N火次”导出和隔离时钟/停机回放入口；采用iCalendar时用锁版本正式日历库读取固定ICS，比较RFC夹具预期集合。Python 3.12有限日期画像可运行 `python -m unittest tests.test_runtime_examples.CalendarTests -v`，仅验证明确选取的日期/gap/fold算法，不代表完整RFC5545或真实调度器。Kubernetes画像须锁集群版本及CronJob配置，在既有获准测试集群核scheduled timestamp/Job和业务账；不以本文创建集群。

**判据：** 每个固定输入精确列出预期名义火次和UTC集合，区分DATE-TIME取值与RRULE生成；停机跨期限后的跳过/合并/补跑逐项一致，重复准入不形成双业务效果；计划更新不改写历史账。
