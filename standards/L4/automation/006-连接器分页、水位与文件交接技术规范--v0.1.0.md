# 连接器分页、水位与文件交接技术规范

**文档ID：** STD-L4-AUTOMATION-006　**版本：** 0.1.0　**状态：** adopted　**生效日期：** 2026-10-30

## 1 目标、适用与非目标

使跨系统遍历、增量同步和文件交换有可核的完整边界，避免游标丢失、限流放大和半写文件消费。

**适用：** API分页/异步任务/批处理、CDC式水位同步、文件输入输出和双向映射。

**非目标：** 不强制所有连接器实现快照、分布式事务或全文件原子；不以AIP字段推广全部API。

本文的“必须/不得”为采用相应条款时的必要条件，“应”为需说明偏离理由的建议，“可”为允许选项。外部标准的 MUST/SHOULD 依其原有强度与适用 profile 执行，项目参数不得降低其强制要求。能力不存在可据事实不适用；已承诺但未验的能力仍适用。

## 2 术语、主体与权威状态

源游标、源日志/事件水位、目标已提交进度和本地检查点不同；事件时间不必单调。原子可见性、进程重启恢复与掉电耐久是不同保证。

**主体与所有权：** 连接器遵守提供方查询协议，映射器保真转换，目标拥有逐项效果，检查点写者只在符合提交边界推进；文件生产者发布完整输入，消费者验证再消费。

**前置输入：** 租户/查询/快照、分页终止与过期合同、排序/删除/水位语义、类型单位/精度、根限流预算、文件路径/编码/清单/完成协议。

**输出与权威观察：** 已交付/已处理/未决项、游标上下文、水位与目标提交证据、文件摘要/完成标记、逐项汇总。

**状态与终点：** 遍历未开始/进行/完整/中断；异步受理/终态分开；文件暂存/发布/验证/消费，检查点不能先于目标已承诺提交。

条款 ID 在本文内稳定；全局身份为文档路径、版本与条款 ID 的组合。各条的前置输入、主体和状态继承本节，再叠加本条触发条件。诊断缺失不证明效果未发生；并发、超时、取消请求与真实业务终态分别记录。

## 3 机制、不变量及逐条验收

### AUT-SYNC-01 分页上下文与异步终态

- **触发/前置：** 连接器遍历/批处理/202受理。
- **必要机制：** 必须把token绑定租户、查询/排序和服务快照语义；空页非必然结束，循环token明确失败；仅提供方允许参数可改。202保存任务身份并查终态，批次逐项接受/拒绝/未知，不用HTTP成功汇总全成功。
- **不变量：** 已交付部分与完整集合不同；cursor不授对象权限。
- **并发、超时、未知与恢复：** 失效token报告中断，显式新遍历保留旧身份/效果；不能自动第一页重做已完成写入。异步任务超时保持目标可查身份。
- **产物与观察点：** 页序/上下文、next、任务ID、逐项结果。
- **正例：** 空页带next继续，202后failed映射业务失败。
- **直接失败：** 空页提前结束，或换租户token静默继续。
- **合法邻例：** 服务明确允许调page_size可合法变更，其余查询仍固定。
- **可观察验收：** 真实连接器逐夹具核请求/目标身份、终止、部分结果与任务终态。
- **来源与限制：** RP06；RP02。来源只支持[逐命题表](../../../sources/runtime-protocol/SOURCE-CLAIMS.md)所列命题；其余必要机制是为保持本条不变量而提出的组织综合设计，不声称由单一外部标准规定。

### AUT-SYNC-02 水位、检查点与同步冲突

- **触发/前置：** 增量/双向同步或断点接续。
- **必要机制：** 必须区分源修订/日志游标、事件时间、水位和目标提交；在目标达到承诺提交后才持久推进检查点，或采用可核等价协议。双向同步记录来源和自身回写身份，定义删除/冲突权威，防回环；窗口读取有重叠去重/快照衔接策略。
- **不变量：** 检查点不跳过未决项；重复读取可归并，不能以跳水位掩盖未知效果。
- **并发、超时、未知与恢复：** crash后从已持久边界恢复并按操作账核未决；乱序/迟到事件按修订而非任意客户端时间覆盖。源日志过期走重新快照/显式缺口。
- **产物与观察点：** 源↔目标逐项对应、提交/检查点顺序、回写来源与冲突。
- **正例：** 目标提交后crash未记水位，重读同项仍命中原操作结果。
- **直接失败：** 先推进水位再写目标导致永久漏项，或自身回写无限触发。
- **合法邻例：** 无变化同步可返回无工作，不强制新写入。
- **可观察验收：** 分别在读/目标提交/水位持久前后中断，加入迟到删除/并发修改/日志过期，核完整集合和效果次数。
- **来源与限制：** RP07；RP06。来源只支持[逐命题表](../../../sources/runtime-protocol/SOURCE-CLAIMS.md)所列命题；其余必要机制是为保持本条不变量而提出的组织综合设计，不声称由单一外部标准规定。

### AUT-SYNC-03 类型、单位与映射边界

- **触发/前置：** 跨系统编码/Schema转换。
- **必要机制：** 必须声明缺失/null、编码、时间/时区、金额/精度、单位、枚举/删除语义和源目标字段映射；无环JSON示例不代表全部业务输入。必要未知字段拒绝或保留，不强制把tuple/非字符串键静默转JSON再复用操作指纹。
- **不变量：** 不同业务值不因有损规范化共用同一操作身份；合法等价值按声明编码处理。
- **并发、超时、未知与恢复：** 映射失败只阻该项并保留原输入引用/差异，修正重驱动保留原业务意图与历史效果判定；秘密不写审计。
- **产物与观察点：** 映射版本、边界值语料、指纹及往返差异。
- **正例：** 定点金额和64位ID无损，null与缺失按合同区分。
- **直接失败：** 大整数round后绑错对象，或把未知枚举设默认成功。
- **合法邻例：** 纯字符串CSV可无JSON语义，但列/编码/空值合同仍明确。
- **可观察验收：** 固定独立边界值与单位转换已知解，核数据与指纹；畸形/非有限值受控失败。
- **来源与限制：** RP13。来源只支持[逐命题表](../../../sources/runtime-protocol/SOURCE-CLAIMS.md)所列命题；其余必要机制是为保持本条不变量而提出的组织综合设计，不声称由单一外部标准规定。

### AUT-SYNC-04 限流、分页预算与部分重驱动

- **触发/前置：** 429/退避、分页大量请求或批次部分失败。
- **必要机制：** 必须合并根期限、请求/并发/成本预算，区分临时限流、永久/权限/业务拒绝和未知效果；尊重Retry-After类提供方信号。完成项不因别项失败重复提交，死信保留原身份/原因及最小输入。
- **不变量：** 上层/连接器重试不无界相乘；撤权不以高权凭据重试。
- **并发、超时、未知与恢复：** 预算到达报告剩余/未知，等待不重置预算；重驱动重核许可/版本/期限与历史效果。
- **产物与观察点：** 各层请求数、延迟、根预算、逐项终态/死信。
- **正例：** 两项一成功一限流，仅对未决安全项受控重试。
- **直接失败：** 每页错误重头遍历并重复已写对象，持续429无限增长。
- **合法邻例：** 纯只读批次允许重算但须准确报告部分和预算。
- **可观察验收：** 持续限流/超期限/部分失败/撤权，核真实请求上限和最终对象/未知项。
- **来源与限制：** RP02。来源只支持[逐命题表](../../../sources/runtime-protocol/SOURCE-CLAIMS.md)所列命题；其余必要机制是为保持本条不变量而提出的组织综合设计，不声称由单一外部标准规定。

### AUT-SYNC-05 文件完成协议与原子交接

- **触发/前置：** 文件生产/传输到消费者。
- **必要机制：** 必须使用同文件系统原子发布、完成标记加清单，或等价完整性协议；先完成写入/所需flush并验证长度/摘要再发布可见入口，消费者核标记与身份。原子rename只是可见性，掉电耐久另需文件/目录及平台存储合同；跨文件系统不能假定原子。
- **不变量：** 未完成文件不被当完整输入；重复到达不产生重复业务效果。
- **并发、超时、未知与恢复：** 发布/消费crash保留可核暂存/旧版，扫描器不把临时文件当新工作；并发生产者名称/版本条件防覆盖。流式可逐记录提交但暴露截断及检查点。
- **产物与观察点：** 文件manifest、完成标记、发布/消费时间线和重复归账。
- **正例：** 写临时文件后验证再rename，消费者只读完整最终文件。
- **直接失败：** 生产者仍写最终路径，消费者读半文件就提交全量成功。
- **合法邻例：** 合法流式日志按完整记录处理，无需等待无限文件结束。
- **可观察验收：** 在写/flush/发布/标记/消费前后中断，损坏摘要/重复/跨FS和并发生产成对测试，核业务效果与完整性。
- **来源与限制：** RP08；RP07。来源只支持[逐命题表](../../../sources/runtime-protocol/SOURCE-CLAIMS.md)所列命题；其余必要机制是为保持本条不变量而提出的组织综合设计，不声称由单一外部标准规定。

## 4 兼容、迁移与退役

API/Schema/连接器/映射/定位器联合版本绑定；旧cursor不可带至新租户/查询。兼容迁移保留旧已处理与未知，不能把失效token自动重头视为同一完整结果。

## 5 跨域消费接口

消费基线AUT-05/06/09/10/14/15与CLI M16；数据库提供事务/CDC/水位语义，后端提供异步终态与配额；自动化负责跨源到目标的逐项归账，文件系统保证由平台画像提供。

接口只定位技术职责，不自动作出规范采用决定。通用状态、测试和制品义务消费 [L3 通用工程 v0.1.0](../../L3/001-通用工程规范--v0.1.0.md)；提供方版本与摘要、应用条款、实现入口和验收责任在项目契约中绑定。提供方保证须由相应实现证据支持，消费方按该保证的实际范围验收。

## 6 真实目标验收合同

以真实连接器指向隔离API夹具，`python -m unittest target_tests.test_connector -v` 回放空页带next、循环/过期token、换租户、202后失败、429和逐项部分成功。文件用目标平台临时同/跨文件系统与真实消费进程，逐阶段中断生产者并核最终路径/标记；`python -m unittest tests.test_runtime_examples.FileTests -v`仅是本地OS的有限演示，断电与网络文件系统另验。

**判据：** 完整结果按提供方终止条件，游标错配拒绝；限流不突破根预算；水位不越未决项、重启不丢增量；半写/错摘要文件不产生完整消费，跨文件系统失败不静默暴露半文件。

每次执行保存：正文/条款版本与摘要、目标制品/实现和工具版本、OS/设备/运行时/配置、输入及故障时间线、预期和实际、stdout/stderr/退出码或等价运行证据、权威状态回读、未覆盖范围。`not-run`、模型通过和真实目标通过是不同结果；实际无环境时保留命令和判据而不填写虚构回执。
