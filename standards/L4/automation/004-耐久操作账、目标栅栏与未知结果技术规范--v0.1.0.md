# 耐久操作账、目标栅栏与未知结果技术规范

**文档ID：** STD-L4-AUTOMATION-004　**版本：** 0.1.0　**状态：** adopted　**生效日期：** 2026-10-30

## 1 目标、适用与非目标

给外部副作用建立可恢复、可核对的意图/尝试账，并以真实目标边界拒绝过期控制和迟到重复。

**适用：** 外部写入、并发执行、可恢复工作流、多步/补偿；纯无副作用函数可不采用耐久操作账。

**非目标：** 不把本地锁、状态字段或目标查询布尔当实际分布式/耐久实现；不宣称跨任意系统恰好一次或补偿能撤销所有事实。

本文的“必须/不得”为采用相应条款时的必要条件，“应”为需说明偏离理由的建议，“可”为允许选项。外部标准的 MUST/SHOULD 依其原有强度与适用 profile 执行，项目参数不得降低其强制要求。能力不存在可据事实不适用；已承诺但未验的能力仍适用。

## 2 术语、主体与权威状态

操作身份为tenant/target/definition/intent/operation，attempt分配单次尝试；failed_known需证据未派发/未应用，unknown保留所有可能已发生尝试。租约为领取权，栅栏为目标实际拒绝旧世代机制。

**主体与所有权：** 操作账写者原子维护准入/状态，执行器只在有效许可/世代下派发，目标在提交边界验证栅栏/幂等/截止并提供查询，对账者绑定操作级范围/新鲜度，补偿者持独立权限。

**前置输入：** 确定性参数编码/指纹、真实账存储版本/事务与耐久配置、目标所有写入口、幂等/查询/接受期限、授权/控制世代和根预算。

**输出与权威观察：** 意图/attempt耐久记录、派发边界、目标安装栅栏回执、提交/查询范围、未知项与逐步补偿。权威是目标可核事实及存储提交保证，不是客户端日志。

**状态与终点：** ready→dispatching→succeeded/failed_known/unknown；cancel_requested另轴。旧未知未决集合不被当前尝试失败清除；补偿另有同样状态机。

条款 ID 在本文内稳定；全局身份为文档路径、版本与条款 ID 的组合。各条的前置输入、主体和状态继承本节，再叠加本条触发条件。诊断缺失不证明效果未发生；并发、超时、取消请求与真实业务终态分别记录。

## 3 机制、不变量及逐条验收

### AUT-EFFECT-01 身份、指纹与原子准入

- **触发/前置：** 触发/重试/重新驱动可能产生外部效果。
- **必要机制：** 必须分离触发事件、逻辑意图、操作和attempt；重试保留操作键。指纹采用声明的确定编码，区分缺失/null/类型/有意义顺序；同键异参拒绝。准入和首次操作账记录原子/等价互斥，秘密只记录引用。
- **不变量：** 同一意图不会因重复触发扩成多个副作用；合法新意图同参仍可执行。
- **并发、超时、未知与恢复：** 并发键冲突回原操作，不先派发后才补唯一约束；crash恢复依耐久账而非内存set。
- **产物与观察点：** 操作键、编码版本/指纹、准入提交和attempt序。
- **正例：** 两执行器并发重复事件只建原操作，另一租户相同局部ID独立。
- **直接失败：** JSON有损转换后不同参数共用旧成功，或重试换intent。
- **合法邻例：** 无副作用纯函数可重算，无需复杂工作流引擎。
- **可观察验收：** 并发、异参、跨租户、类型/键边界及新意图成对测试；核目标效果数。
- **来源与限制：** RP13；RP07。来源只支持[逐命题表](../../../sources/runtime-protocol/SOURCE-CLAIMS.md)所列命题；其余必要机制是为保持本条不变量而提出的组织综合设计，不声称由单一外部标准规定。

### AUT-EFFECT-02 写前账、耐久配置与派发缝隙

- **触发/前置：** 操作可跨进程死亡/重启。
- **必要机制：** 必须在不可逆派发前持久记录意图/attempt与待派发状态，按真实存储事务/WAL/flush和故障模型定义成功点。账与外部目标通常无共同事务：crash在记录后/派发后均可能未知，不把“dispatching”当已发或未发的充分证明。
- **不变量：** 已对外承诺耐久的账在所声明故障范围可恢复；内存锁/JSON字段不提供耐久性。
- **并发、超时、未知与恢复：** 账损坏/存储不可用停止不安全新派发并保留证据，恢复核权威目标；备份恢复不能遗失仍需去重的历史窗口。
- **产物与观察点：** 存储版本/配置、提交点、恢复查询、各crash闸及未知。
- **正例：** SQLite提交后结束进程再打开可读原账，派发缝隙进入unknown核对。
- **直接失败：** 内存记succeeded就显示完成；掉电前未flush却宣称永久保存。
- **合法邻例：** 一次性只读转换无需耐久账，只需准确输入输出/失败。
- **可观察验收：** 逐闸进程中断、并发事务、备份恢复对账；真实掉电/复制不由进程测试通过推断。
- **来源与限制：** RP07；RP08。来源只支持[逐命题表](../../../sources/runtime-protocol/SOURCE-CLAIMS.md)所列命题；其余必要机制是为保持本条不变量而提出的组织综合设计，不声称由单一外部标准规定。

### AUT-EFFECT-03 租约、接管与目标栅栏

- **触发/前置：** 多执行器/租约过期或需要排除旧写。
- **必要机制：** 必须明确并发键和单写范围；目标以原子安装/比较世代并在每个提交入口同事务验证，或提供可证等价排他。新领取租约不等于接管成功，目标确认新栅栏后才承诺拒旧；安装前旧写窗口仍可能提交须核对。
- **不变量：** 安装后旧世代不能覆盖目标，即使新执行器尚无业务写。
- **并发、超时、未知与恢复：** 安装回执丢失查询目标世代；不支持栅栏目标只用可证单写或明确限制，不伪装全分布式安全。并发目标副本需共同拒旧保证。
- **产物与观察点：** 领取与目标安装/确认、各写入口世代判定和业务版本。
- **正例：** epoch2安装后恢复epoch1，旧写被目标拒。
- **直接失败：** 仅本地lease表升epoch，但目标直到新业务写时才检查，旧写窗口仍开。
- **合法邻例：** 真正单机互斥无需分布式租约，仍核crash未知效果。
- **可观察验收：** 新栅栏安装后、首次业务写前释放旧进程，并测试所有写入口/副本；合法当前世代写通过。
- **来源与限制：** RP07。来源只支持[逐命题表](../../../sources/runtime-protocol/SOURCE-CLAIMS.md)所列命题；其余必要机制是为保持本条不变量而提出的组织综合设计，不声称由单一外部标准规定。

### AUT-EFFECT-04 未知尝试与操作级终局

- **触发/前置：** 超时/丢响应/解析失败/取消后核对。
- **必要机制：** 必须保留所有未决attempt及其派发/目标范围，回执绑定操作/指纹/attempt。迟到旧失败不降低新在途；当前attempt未应用不能证明旧unknown未应用。消解需要操作级权威查询覆盖相关尝试、仍在途窗口、截止及新鲜度，或确实有效的目标幂等合同。
- **不变量：** 缺记录/日志不证明无效果；unknown不会被局部新失败洗掉。
- **并发、超时、未知与恢复：** 无法证明旧请求终止/不能再提交时保留unknown，提供人工/后续权威核对入口；控制请求不改写已完成。
- **产物与观察点：** 未决集合、回执身份、查询覆盖/新鲜度和权威结果。
- **正例：** 旧成功丢响应，新尝试未应用，仍保留旧未知直到操作级查回成功。
- **直接失败：** 新attempt失败就清全部unknown并以新键重发。
- **合法邻例：** 有确证未派发/目标拒绝且无旧未决者可为failed_known。
- **可观察验收：** 交错旧未知、新未应用、迟到旧失败和真实操作级结论，核状态不回退/不重发。
- **来源与限制：** RP02。来源只支持[逐命题表](../../../sources/runtime-protocol/SOURCE-CLAIMS.md)所列命题；其余必要机制是为保持本条不变量而提出的组织综合设计，不声称由单一外部标准规定。

### AUT-EFFECT-05 有限去重与目标迟到接受

- **触发/前置：** 依赖幂等键/去重窗口重试。
- **必要机制：** 必须固定tenant/target/operation作用域、参数绑定、保存期限和处理保证。派发时在窗内不够：目标须强制接受截止、证明去重覆盖全部可能接受/处理窗口，或等价机制；考虑排队/网络/服务延迟与时钟误差。窗口过后旧请求不能被当新作用。
- **不变量：** 本地去重账不能提供远端恰好一次；同键异参永不复用旧结果。
- **并发、超时、未知与恢复：** 无目标截止/覆盖保证且旧未知仍可能迟到时不得盲重发，保持unknown核对；历史补跑也受同规则。
- **产物与观察点：** 服务合同/版本、目标接受时间、去重到期/截止、最终效果账。
- **正例：** 服务端接受截止后拒旧请求，窗内同键同参返回原结果。
- **直接失败：** 本地11:59派发、12:01到目标而12:00键过期，目标新建第二对象。
- **合法邻例：** 永久幂等业务操作可按其真实合同重试，无需虚构有限TTL。
- **可观察验收：** 真实目标延迟请求跨窗并与重试交错，核拒绝/去重与效果数；仅比较本地send_at的模型不得冒称覆盖。
- **来源与限制：** RP02。来源只支持[逐命题表](../../../sources/runtime-protocol/SOURCE-CLAIMS.md)所列命题；其余必要机制是为保持本条不变量而提出的组织综合设计，不声称由单一外部标准规定。

### AUT-EFFECT-06 多步、补偿与恢复终点

- **触发/前置：** 批次/工作流部分完成、暂停恢复或退役。
- **必要机制：** 必须记录依赖/分支/逐项状态，完成项不无依据重发；补偿为新操作，独立身份/权限/预算/未知核对，不能保证逆转已被外界观察事实。恢复重验定义/许可/目标和控制屏障；退役保留未决义务和可用核对入口。
- **不变量：** 补偿失败或未知不标整体已回滚；取消不抹去成功。
- **并发、超时、未知与恢复：** 不可逆/人工处理成为显式状态，补偿重试遵同去重/迟到规则；审计中断仍回目标事实，不从空队列推完成。
- **产物与观察点：** 步骤/补偿账、未决集合、授权/控制版本和真实对账。
- **正例：** 两项一成一败只续未决项，补偿不确定如实报告。
- **直接失败：** 第一项退款未知却把工作流标全回滚并再发原交易。
- **合法邻例：** 纯只读批次可全重算，仍准确标部分/完整。
- **可观察验收：** 逐步提交前后中断、补偿失败/未知、暂停后迟到与退役，核最终业务事实及可继续动作。
- **来源与限制：** RP02；RP07。来源只支持[逐命题表](../../../sources/runtime-protocol/SOURCE-CLAIMS.md)所列命题；其余必要机制是为保持本条不变量而提出的组织综合设计，不声称由单一外部标准规定。

## 4 兼容、迁移与退役

定义/Schema/连接器/目标和授权联合版本固定。恢复从相容记录续接，不重解释旧已完成动作；存储/目标换代需要验证去重/栅栏保留与恢复闭包。

## 5 跨域消费接口

消费基线AUT-01/02/04/08–10/12–16及CLI M12/35、游戏§29；数据库提供真实事务/锁/WAL/持久配置，后端提供目标幂等/查询/权限执行边界，安全提供当前授权；自动化承担跨系统未知与补偿闭环。

接口只定位技术职责，不自动作出规范采用决定。通用状态、测试和制品义务消费 [L3 通用工程 v0.1.0](../../L3/001-通用工程规范--v0.1.0.md)；提供方版本与摘要、应用条款、实现入口和验收责任在项目契约中绑定。提供方保证须由相应实现证据支持，消费方按该保证的实际范围验收。

## 6 真实目标验收合同

目标采用真实隔离数据库/服务时，验收驱动 `python -m unittest target_tests.test_effects -v` 启动至少两个执行器与独立目标进程，在账提交、派发、目标提交、回执/水位各闸点结束进程再恢复。目标栅栏测试必须在新epoch已安装、尚无新业务写时释放旧执行器。有限本地SQLite示例用标准库、FULL同步并记录SQLite/FS身份，只验证进程重启和所列事务交错；电源/设备故障、分布式复制和服务幂等承诺保持单独真实验收。

**判据：** 每一已确认操作可恢复到真实提交事实；不确定尝试不被错误清空；旧epoch在所有目标提交入口拒绝；去重窗外迟到不成为新效果；部分补偿准确报告，未完成不会虚报整体回滚。

每次执行保存：正文/条款版本与摘要、目标制品/实现和工具版本、OS/设备/运行时/配置、输入及故障时间线、预期和实际、stdout/stderr/退出码或等价运行证据、权威状态回读、未覆盖范围。`not-run`、模型通过和真实目标通过是不同结果；实际无环境时保留命令和判据而不填写虚构回执。
