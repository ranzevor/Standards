# Webhook验证、耐久接收与事件顺序技术规范

**文档ID：** STD-L4-AUTOMATION-002　**版本：** 0.1.0　**状态：** adopted　**生效日期：** 2026-10-30

## 1 目标、适用与非目标

把签名来源、事件准入、耐久确认和业务顺序分层，拒绝重放和旧订阅恢复权限。

**适用：** Webhook接收/订阅/重送与事件驱动连接器。

**非目标：** 不假定所有提供方都签时间戳/受众/投递头，不统一验签算法或回执秒数。

本文的“必须/不得”为采用相应条款时的必要条件，“应”为需说明偏离理由的建议，“可”为允许选项。外部标准的 MUST/SHOULD 依其原有强度与适用 profile 执行，项目参数不得降低其强制要求。能力不存在可据事实不适用；已承诺但未验的能力仍适用。

## 2 术语、主体与权威状态

投递、提供方事件、业务修订和本地意图不同；签名覆盖范围由提供方协议决定。签名有效只证明被覆盖材料的来源/完整性，不自动证明新鲜、租户授权或当前订阅仍有效。

**主体与所有权：** 接收器按原始字节验签，订阅维护者核当前主体/环境/事件种类，耐久Inbox控制准入，业务消费者按版本/查询裁决。

**前置输入：** 提供方协议/版本、原始body/签名、订阅/租户、密钥集合及轮换边界、事件身份/业务修订、耐久确认与重送合同。

**输出与权威观察：** 验签/授权拒绝或耐久接收记录、原事件/尝试关联、顺序折叠/缺口与目标结果；HTTP2xx只承诺约定接收层。

**状态与终点：** 未验证→来源有效→权限有效→耐久接收→处理/未知/完成；验签/订阅拒绝不能经重送恢复为有权。

条款 ID 在本文内稳定；全局身份为文档路径、版本与条款 ID 的组合。各条的前置输入、主体和状态继承本节，再叠加本条触发条件。诊断缺失不证明效果未发生；并发、超时、取消请求与真实业务终态分别记录。

## 3 机制、不变量及逐条验收

### AUT-HOOK-01 原始字节与真实签名覆盖

- **触发/前置：** HTTP事件到达。
- **必要机制：** 必须按提供方协议对未经重序列化原始body及实际签名字段验签，采用安全比较；仅对协议确实覆盖的时间戳/受众/头作认证结论。GitHub HMAC-SHA256覆盖body，不能声称X-GitHub-Delivery或任意时间头已被该HMAC认证。
- **不变量：** 语义等价但字节改变不能沿用原签名；来源/新鲜度/授权分别判。
- **并发、超时、未知与恢复：** 过大/坏编码先按预算受控拒绝，秘密轮换记录接受key集合和截止，不为排障落密钥。
- **产物与观察点：** 签名算法/profile、覆盖字段、body摘要与拒绝原因。
- **正例：** 原body签名可验，增空白字节后旧签名被拒。
- **直接失败：** 解析JSON再dump验签，或把攻击者提供时间头视为已签新鲜度。
- **合法邻例：** 没有签名时间戳协议可通过来源验签，但不得声称协议未提供的防迟到保证。
- **可观察验收：** 官方合成向量和改一字节/改覆盖外头对照，核结论强度与真实覆盖集合。
- **来源与限制：** RP04。来源只支持[逐命题表](../../../sources/runtime-protocol/SOURCE-CLAIMS.md)所列命题；其余必要机制是为保持本条不变量而提出的组织综合设计，不声称由单一外部标准规定。

### AUT-HOOK-02 事件身份、重放与耐久确认

- **触发/前置：** 验签后准入/确认。
- **必要机制：** 必须把事件身份绑定提供方/租户/订阅命名空间；重复准入与入Inbox原子。未被认证的delivery头不能单独成为防业务重放依据，需业务操作身份/资源修订及权威核对或实际可信投递身份合同；不可从相同payload永久吞掉合法新意图。先达到约定耐久接收边界再回确认。
- **不变量：** 接收成功只证明接收层；本地去重不保证远端恰好一次。
- **并发、超时、未知与恢复：** 确认丢失重送回原接收/业务身份；崩溃在持久前不确认，持久后可接续。期限外迟到按目标效果合同处理。
- **产物与观察点：** Inbox唯一键/提交点、投递↔事件↔意图映射与效果次数。
- **正例：** 原delivery重送命中原账，改未签头仍不能重复同一资源修订效果。
- **直接失败：** 每次随机delivery值被当新购买，或内存set后2xx掉电丢事件。
- **合法邻例：** 同内容但有真实新业务意图/修订可独立执行。
- **可观察验收：** 并发重复、改未签头、原件重送和合法新意图成对测试；进程重启核已确认接收可恢复。
- **来源与限制：** RP05；RP07。来源只支持[逐命题表](../../../sources/runtime-protocol/SOURCE-CLAIMS.md)所列命题；其余必要机制是为保持本条不变量而提出的组织综合设计，不声称由单一外部标准规定。

### AUT-HOOK-03 当前订阅、租户与密钥世代

- **触发/前置：** 事件欲触发实际动作。
- **必要机制：** 必须在处理边界核当前订阅、环境、租户/对象和action授权，签名有效不等于订阅仍可执行。轮换新旧key集合及截止由协议/政策确定；旧事件可审计但不得重建撤销权限。外部payload不能改变模板/解释器权限。
- **不变量：** 旧订阅/错租户不能因签名有效或密钥尚有效而执行。
- **并发、超时、未知与恢复：** 撤权与排队并发以有效屏障重验；迟到旧key结果只归账，必要回查用当前授权且不提权。
- **产物与观察点：** 订阅/授权世代、事件种类、拒绝及真实调用记录。
- **正例：** 当前订阅有效事件通过，撤销后同签名事件仅审计不写目标。
- **直接失败：** 保留旧密钥就默认所有旧订阅继续获权。
- **合法邻例：** 匿名公开事件可无需账号凭据，但仍遵守其输入与副作用范围。
- **可观察验收：** 轮换前后/撤销后/跨租户/未知action，核真实目标调用而非配置字段。
- **来源与限制：** RP04；RP05。来源只支持[逐命题表](../../../sources/runtime-protocol/SOURCE-CLAIMS.md)所列命题；其余必要机制是为保持本条不变量而提出的组织综合设计，不声称由单一外部标准规定。

### AUT-HOOK-04 乱序、缺口与订阅退役

- **触发/前置：** 重送/并行/失联造成事件乱序或停用。
- **必要机制：** 必须按资源修订、提供方顺序合同或回查权威状态处理，不能盲按到达顺序覆盖；缺口有重取/重建/告知路径。退役解除实际订阅/路由、处理未决接收及必要保留，不仅删模板。
- **不变量：** 旧事件不覆盖较新权威状态；无日志不推断未发生。
- **并发、超时、未知与恢复：** Schema未知隔离可诊断，重驱动先核权限/版本/历史效果；历史回放使用隔离目标或禁副作用。
- **产物与观察点：** 事件修订序、权威回读、缺口与退役入口清单。
- **正例：** v2后到v1保持v2，无法判顺序时查询当前资源。
- **直接失败：** 按到达写回把v2降成v1，退役后仍有旧入口派发。
- **合法邻例：** 可交换增量按真实交换律累计，无需全局串行。
- **可观察验收：** 投递v2/v1/重复/缺口和退役迟到，核最终状态及无新增越权派发。
- **来源与限制：** RP05。来源只支持[逐命题表](../../../sources/runtime-protocol/SOURCE-CLAIMS.md)所列命题；其余必要机制是为保持本条不变量而提出的组织综合设计，不声称由单一外部标准规定。

## 4 兼容、迁移与退役

事件Schema/订阅/密钥升级保留可验证的接受集合与到期点；旧事件解码/隔离/查询明确，不因未知action默认执行。重送与新意图分别处理。

## 5 跨域消费接口

消费基线AUT-02/07/08/12/14/15；安全提供密钥/对象授权，数据库提供Inbox事务，后端提供目标权威查询；事件接收层不承诺外部业务恰好一次。

接口只定位技术职责，不自动作出规范采用决定。通用状态、测试和制品义务消费 [L3 通用工程 v0.1.0](../../L3/001-通用工程规范--v0.1.0.md)；提供方版本与摘要、应用条款、实现入口和验收责任在项目契约中绑定。提供方保证须由相应实现证据支持，消费方按该保证的实际范围验收。

## 6 真实目标验收合同

真实接收器通过本地隔离HTTP入口发送官方协议合成签名body，保存原字节和响应；GitHub画像用HMAC-SHA256及X-Hub-Signature-256，官方无统一签名时间戳时不得伪造已验证时间窗。连接器测试脚本 `python -m unittest target_tests.test_webhook -v` 发送改body、改未签投递头、密钥轮换、旧订阅、并发重复与乱序，崩溃接收进程后核Inbox和目标。

**判据：** 字节改变验签失败；有效旧订阅/错误租户仍拒绝；确认丢失重送不重复业务效果；更换未被签名投递头不能重新制造同一业务意图；接收确认点之后进程重启可恢复接收记录。

每次执行保存：正文/条款版本与摘要、目标制品/实现和工具版本、OS/设备/运行时/配置、输入及故障时间线、预期和实际、stdout/stderr/退出码或等价运行证据、权威状态回读、未覆盖范围。`not-run`、模型通过和真实目标通过是不同结果；实际无环境时保留命令和判据而不填写虚构回执。
