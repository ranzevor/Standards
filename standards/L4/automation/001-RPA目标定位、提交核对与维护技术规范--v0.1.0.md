# RPA目标定位、提交核对与维护技术规范

**文档ID：** STD-L4-AUTOMATION-001　**版本：** 0.1.0　**状态：** adopted　**生效日期：** 2026-10-30

## 1 目标、适用与非目标

使交互自动化的点击与输入绑定真实应用/会话/对象，提交未知后先核对而不是盲目重复。

**适用：** 浏览器/桌面UI自动化，尤其跨账号、可变布局或有外部副作用的操作。

**非目标：** 不强制图像识别，不绕过验证码/MFA/逐次本人确认，不把截图按钮文字当业务权威。

本文的“必须/不得”为采用相应条款时的必要条件，“应”为需说明偏离理由的建议，“可”为允许选项。外部标准的 MUST/SHOULD 依其原有强度与适用 profile 执行，项目参数不得降低其强制要求。能力不存在可据事实不适用；已承诺但未验的能力仍适用。

## 2 术语、主体与权威状态

定位命中、可交互、输入回读、提交受理和业务成功不同；定位器版本、窗口/页面世代、账号/租户和目标对象构成动作上下文。

**主体与所有权：** 自动化器核动作上下文与稳定定位，应用提供可访问/DOM等语义，业务目标提供回执/查询，人处理必须本人完成的确认。

**前置输入：** 应用/页面/窗口身份、当前账号/对象、动作允许范围、定位器/等待条件、语言缩放/模态状态和结果核对路径。

**输出与权威观察：** 定位/动作/输入回读/提交和业务回执的最小证据、未知操作账、无秘密必要区域截图。

**状态与终点：** 目标已核→定位/等待→可交互→输入已回读→提交中→已知结果/未知；动作上下文变化即失去旧定位许可。

条款 ID 在本文内稳定；全局身份为文档路径、版本与条款 ID 的组合。各条的前置输入、主体和状态继承本节，再叠加本条触发条件。诊断缺失不证明效果未发生；并发、超时、取消请求与真实业务终态分别记录。

## 3 机制、不变量及逐条验收

### AUT-RPA-01 目标、会话与稳定定位

- **触发/前置：** 每次危险动作或页面/窗口变化。
- **必要机制：** 必须在动作前核应用/来源、当前账号/租户、窗口/页面世代、对象身份及动作语义；优先稳定语义定位和状态等待，坐标/文本匹配须有适用证据。导航、焦点、模态、语言或缩放变化后重新核验，不把旧元素句柄当授权。
- **不变量：** 同名按钮不跨窗口/对象误点击；定位命中不等于可安全提交。
- **并发、超时、未知与恢复：** 等待有总期限和失败终点，遮罩/旧页面不靠固定sleep后盲点；变更上下文使旧动作失效。
- **产物与观察点：** 上下文/定位器版本、等待条件、动作前对象和实际调用。
- **正例：** 正确合成对象确认后点击，账号变更则拒绝旧动作。
- **直接失败：** 后台错误窗口同名“删除”被点击。
- **合法邻例：** 稳定API或无障碍语义路径可用，不需额外图像识别。
- **可观察验收：** 同名/错窗口/换账号/模态/缩放负例和正确上下文邻例，核目标调用及对象不变。
- **来源与限制：** RP10。来源只支持[逐命题表](../../../sources/runtime-protocol/SOURCE-CLAIMS.md)所列命题；其余必要机制是为保持本条不变量而提出的组织综合设计，不声称由单一外部标准规定。

### AUT-RPA-02 输入回读与提交未知

- **触发/前置：** 表单填写/确认外部动作。
- **必要机制：** 必须区分输入成功、目标实际值、提交受理和业务完成；敏感或精度值按适用方式回读核对。提交绑定逻辑操作身份/对象，超时后先读业务回执/状态，不连续重复点击；按钮禁用/成功动画只作UI阶段证据。
- **不变量：** UI反馈不是目标业务权威；同一意图不因等待超时双提交。
- **并发、超时、未知与恢复：** 未知进入AUT-EFFECT账，目标查无暂不能消除旧在途；必须确认动作交人完成，不能用更高权限界面绕过。
- **产物与观察点：** 输入回读、提交时间线、操作账与权威回执。
- **正例：** 输入金额回读正确，提交后丢页面响应但查回原订单。
- **直接失败：** 点击后页面卡住重复点击产生两笔，截图success便称到账。
- **合法邻例：** 无副作用查询可刷新/重算，不要求业务去重键。
- **可观察验收：** 提交前/提交后/回执丢失与并发导航处中断，核真实对象/效果数和未知终态。
- **来源与限制：** RP02。来源只支持[逐命题表](../../../sources/runtime-protocol/SOURCE-CLAIMS.md)所列命题；其余必要机制是为保持本条不变量而提出的组织综合设计，不声称由单一外部标准规定。

### AUT-RPA-03 控制、秘密与诊断最小化

- **触发/前置：** 暂停/取消、凭据或截图诊断。
- **必要机制：** 必须将控制请求与实际在途分离，阻止新动作的屏障按世代生效；旧回调可归账但不启动新动作。秘密不进通用日志/截图，必要证据限获准区域/用途/保留；凭据可用不是动作许可。
- **不变量：** 控制不改已发生事实；诊断不扩大数据披露。
- **并发、超时、未知与恢复：** 弹出登录/MFA/验证码/本人确认交接人，不自动创建持久授权；恢复核当前账号/对象/未决。脱敏失败不外传原件。
- **产物与观察点：** 控制世代、待确认交接、必要截图清单/访问和实际外发。
- **正例：** 暂停后迟到回执归原操作，不点下一步。
- **直接失败：** 账号已切换仍执行旧页面队列，或截图全屏泄令牌。
- **合法邻例：** 无需凭据的只读公开路径无需新增登录。
- **可观察验收：** 屏障前后回调、合成秘密和本人确认流程，核新动作受阻、已发生准确及数据最小化。
- **来源与限制：** RP05。来源只支持[逐命题表](../../../sources/runtime-protocol/SOURCE-CLAIMS.md)所列命题；其余必要机制是为保持本条不变量而提出的组织综合设计，不声称由单一外部标准规定。

### AUT-RPA-04 定位器升级与消费端回归

- **触发/前置：** 应用/语言/定位器升级或退役。
- **必要机制：** 必须固定联合版本和代表任务，区分合法布局变化与对象语义变化；以真实消费者入口测试，不只Mock选择器。历史重放使用隔离目标/禁副作用；退役清除入口并保留未决核对。
- **不变量：** 旧回执不覆盖新UI/账号/制品；布局更像不代表动作仍同义。
- **并发、超时、未知与恢复：** 定位失败有回退/人工入口，不用扩大选择器范围取得“绿色”；未知提交不从头重放整任务。
- **产物与观察点：** 版本/任务矩阵、定位差异、实际结果和未执行项。
- **正例：** 新UI同一对象合同仍成立并有新回执。
- **直接失败：** 选择器找不到就取第一个同名按钮，或旧截图冒新版本验收。
- **合法邻例：** 小型单平台任务可只测承诺范围，不强制跨全部OS。
- **可观察验收：** 真实应用升级/语言缩放组合跑正反任务，故意错对象应拒；回放验证不访问真实写目标。
- **来源与限制：** RP10。来源只支持[逐命题表](../../../sources/runtime-protocol/SOURCE-CLAIMS.md)所列命题；其余必要机制是为保持本条不变量而提出的组织综合设计，不声称由单一外部标准规定。

## 4 兼容、迁移与退役

应用/定位器/语言/缩放升级重新核目标任务。优先稳定语义/无障碍/API路径但不假设跨所有版本不变；纯API连接器不套图像步骤。

## 5 跨域消费接口

消费基线AUT-11/12/13/15/16及AUT-EFFECT未知/补偿；Web/桌面/移动提供真实交互语义，安全提供账号/对象权限；RPA维护者对动作前绑定与业务核对负责。

接口只定位技术职责，不自动作出规范采用决定。通用状态、测试和制品义务消费 [L3 通用工程 v0.1.0](../../L3/001-通用工程规范--v0.1.0.md)；提供方版本与摘要、应用条款、实现入口和验收责任在项目契约中绑定。提供方保证须由相应实现证据支持，消费方按该保证的实际范围验收。

## 6 真实目标验收合同

真实隔离应用用固定浏览器/OS/自动化工具版本，项目任务入口 `python -m unittest target_tests.test_rpa -v` 或现有平台测试套件。用合成账号/对象在同名按钮、切账号、导航/模态/缩放和提交后丢回执处故障注入；记录受控DOM/可访问树/必要截图及目标查询。动作许可/本人确认由实际环境规则执行，不通过自动化工具模拟授权。

**判据：** 错误窗口/账号/对象下不提交；变化后重定位并重新核权；输入回读准确，提交丢回执保留原操作查询；合法无障碍/API路径可完成；所有必要本人确认停在正确交接点而非绕过。

每次执行保存：正文/条款版本与摘要、目标制品/实现和工具版本、OS/设备/运行时/配置、输入及故障时间线、预期和实际、stdout/stderr/退出码或等价运行证据、权威状态回读、未覆盖范围。`not-run`、模型通过和真实目标通过是不同结果；实际无环境时保留命令和判据而不填写虚构回执。
