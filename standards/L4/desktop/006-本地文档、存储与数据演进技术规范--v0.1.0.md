# L4 本地文档、存储与数据演进技术规范

**文档ID：** STD-L4-DESKTOP-006　**版本：** 0.1.0　**状态：** adopted　**生效日期：** 2026-10-30

> 项目采用范围与实现验收分别记录；符合性由相应条款的实际执行证据判定。

## 目标与非目标

目标是用户文档从打开到保存、并发、迁移和恢复保持可判定结果；非目标是重写数据库WAL/备份算法、强制云同步或跨所有文件系统承诺同一持久性。

## 术语、角色与共同验收规则

“必须/应/不得”为适用条件成立时的规范要求，“建议”为可有依据替代，“例如/示例”为非穷尽说明。每条由其适用对象的组件实现者负责，产品维护者固定支持合同，L5 固定平台/API/工具版本，验证者留准确环境与原始结果。每条输入/输出与权威细化附于条内；本地/OS/渠道/远端各只对其管辖事实确认，日志字段不认证真实权限或效果。

继承所引用的 [L3 通用工程规范 v0.1.0](../../L3/001-通用工程规范--v0.1.0.md) 的工程与证据接口，不由此推定正式采用。

所有适用条款的前置为支持组合、准确运行构建、相关账号/资源/操作身份及必要预算已可定位。并发或异步状态绑定实例、账号/工作区、文档/场景和操作代际；互不相关对象允许并行。超时/断连/取消请求不是效果未发生；有界重试及恢复应先核未知结果，已确认未提交或无副作用路径可按合同重试。时钟、预算和兼容版本由采用合同固定，不从统一毫秒阈值或 latest 页面推断。完成以条内目标与判据回读，正常/直接失败/合法邻例共同验证。

## 一、定位、适用条件与边界

本专项为第 07 领域规划 P2（局部规划号，不是正式登记 ID），深化领域基线 D05–D09、D21：从用户打开本地文档到编辑、保存、并发协调、备份、恢复、格式演进及账号切换，约束应用可观察的数据状态。适用于具备本地文档或持久应用状态的桌面软件；纯只读查看器仅适用读取、身份、隔离及相关缓存条款，没有迁移或账号功能不要求虚构它们。跨平台不要求支持所有 OS、所有文件系统、同步服务或共享盘。

“应/不得”按项目选定的适用条款执行。

L0–L3 保留治理、工程与证据权威；基线规定总体不变量，本文新增文档代次、应用生命周期、用户文件与本地引擎之间的协调契约。以下相应数据库规范按实际采用版本引用，不重订其算法：

- 《事务、隔离、MVCC 与锁竞争技术规范》：引擎事务与并发控制；本文只协调应用窗口、外部文件与写入者。
- 《物理存储、WAL 与崩溃一致性技术规范》：持久承诺、WAL、同步及引擎崩溃恢复；本文不重写日志/检查点实现。
- 《Schema 迁移、回填与兼容收缩技术规范》：数据库 DDL/回填；本文补文档格式、首次启动、旧程序与附件的整体数据状态。
- 《备份、PITR 与恢复演练技术规范》：引擎备份链及恢复；本文补文档集、账号归属、恢复入口和恢复后的应用可用性。

P1 的 IPC 身份/权限与秘密存储实现不在此复制；本文消费已核定的用户/工作区与资源能力，不以目录名代替授权。P3 负责系统生命周期入口；P5 负责安装卸载；P6 负责版本切换编排；P8 负责诊断和恢复模式入口。尚未获批的兄弟专题只能作为分工说明，不作为强制前置规范。L5 选 API/框架、文件系统与实际引擎；L6 固定支持组合、数据权利、保留期、恢复目标与验收环境。

## 二、最小对象模型及用户可见承诺

每个可写文档至少能关联：应用文档标识、OS 用户/应用账号/工作区、当前资源定位符及有效访问能力、打开时观察到的文件对象与内容版本、编辑代次、保存操作标识、目标格式及持久等级。不要求在文件里写入这些全部字段，但实现和证据必须能区分它们。路径是定位方式，不是永久身份；内容相同也不意味着同一授权对象；文件 ID 不单独证明账号归属或跨卷永久同一性。

保存状态至少区分：未修改、已修改、某代次正在写入、该代次达到本地持久承诺、失败、结果未知、外部冲突。远端同步另有未上传/同步中/远端确认/冲突/未知，不能覆盖本地保存状态。即使暂时不联网，也不将已完成本地编辑误报为失败；反之，本地落盘不冒充远端副本存在。

恢复状态至少区分：发现恢复候选、验证输入、重建到隔离目标、核对数据与权限、完成切换、仍有未恢复范围。能列出文件、校验摘要或程序启动都不是用户文档已完整恢复。所有状态迁移必须可被用户或受权维护者查明，敏感正文与密钥不因此写入普通日志。

## 三、应用数据机制与验收

### S01 数据分类、目录解析与所有权
**适用：** 具有本地状态。应区分用户作品、不可重建应用数据、偏好设置、恢复草稿、可重建索引/缓存、日志、临时与机器共享对象；逐类确定目录来源、主体、漫游/备份和清理责任。草稿不能仅因隐藏或没有正式文件名被归为缓存。Windows Known Folders 可能重定向到网络位置 [DM01](../../../sources/desktop-mobile-claims.md#dm01)；采用 XDG 0.8 时按数据/配置/状态/缓存/运行目录分类，忽略无效相对环境路径 [DM02](../../../sources/desktop-mobile-claims.md#dm02)。macOS 采用其实际标准目录和容器定位接口，不从归档资料的 iOS 目录规则推导桌面规则。
**验收：** 记录实际解析目录，覆盖非默认位置、只读安装目录、目录不存在/不可写、同机第二 OS 用户；清理清单与数据分类逐项一致。便携模式是合法方案，但必须有显式位置与权限合同，不隐式写入当前工作目录或共享安装根。

**输入、输出与权威补充：** 存储者输入数据类别/目录 API，输出位置/拥有者/备份/清理合同；草稿不按隐藏文件归缓存。

**正例：** 重定向用户目录合法保存。

**具体目标入口与完成判据：** 实际目录 API、XDG 解析和第二 OS 用户/只读安装目录。 以本条机制、失败处理及案例表的预期为通过条件；同时对照正常/直接失败/合法邻例，超时或未知不得标已确认。

**来源边界：** [DM01](../../../sources/desktop-mobile-claims.md#dm01)、[DM02](../../../sources/desktop-mobile-claims.md#dm02)；仅采用各来源所列有限事实，动作/身份栅栏、恢复和案例为组织合成契约。

### S02 账号、工作区与异步任务隔离
**适用：** 多账号/工作区或后台写入。每次打开、保存、导出、备份、恢复和后台回调绑定发起主体及工作区代次。切换账号时排空、隔离或按原主体完成已获准工作；旧回调不得通过“当前账号”变量写入新账号目录。最近文件、缩略图、搜索索引、自动恢复列表与临时输出也按权限过滤。OS 用户相同不意味着应用账号间默认共享；明确的共享工作区可按其独立授权访问。
**验收：** A 保存中切至 B，延迟 A 回调；B 无法读取或覆盖 A 私有状态，A 的合法草稿不丢。退出登录的保留/清除策略与用户合同一致，不为隔离方便删除无权删除的作品。加密密钥缺失时保留原密文并报告不可解密，不偷偷降级明文；密码学与平台秘密库实现由相邻规范/L5承担。

**输入、输出与权威补充：** 异步写者输入原主体/工作区代际，输出隔离保存/导出；当前账号全局变量不作归属。

**正例：** 授权共享工作区可共享。

**具体目标入口与完成判据：** A 保存中切 B 再回调，读最近文件/缩略图/草稿及真实目标。 以本条机制、失败处理及案例表的预期为通过条件；同时对照正常/直接失败/合法邻例，超时或未知不得标已确认。

**来源边界：** [DM34](../../../sources/desktop-mobile-claims.md#dm34)；仅采用各来源所列有限事实，动作/身份栅栏、恢复和案例为组织合成契约。

### S03 定位符、文件对象与能力期限
**适用：** 文件打开/保存、移动、重新连接。应区分文件路径、目录/卷、打开句柄对应对象、应用内容版本及平台资源能力。按实际平台选择句柄查询、安全打开或文档提供者接口；Windows 的句柄信息类具有 OS/驱动差异 [DM03](../../../sources/desktop-mobile-claims.md#dm03)。选择器、扩展名和曾经授权过的路径均不能单独证明现在的对象获准访问。
**验收：** 同一路径被替换、同文件改名、链接别名、撤权后重开、可拔盘换成另一卷时，重新核对对象/权限；不能把不同介质上的同名文件自动作为原件。合法改名可重新绑定，不强迫所有用户文件禁止符号链接，也不承诺跨卷 ID 永久不变。

**输入、输出与权威补充：** 文件者输入定位符/句柄/能力，输出当前真实对象；路径和 ID 不单独授权。

**正例：** 合法改名后重新绑定同对象。

**具体目标入口与完成判据：** GetFileInformationByHandleEx 或等效对象查询；路径替换/换卷同名/撤权重开。 以本条机制、失败处理及案例表的预期为通过条件；同时对照正常/直接失败/合法邻例，超时或未知不得标已确认。

**来源边界：** [DM03](../../../sources/desktop-mobile-claims.md#dm03)；仅采用各来源所列有限事实，动作/身份栅栏、恢复和案例为组织合成契约。

### S04 打开、导入与导出的对象边界
**适用：** 解析或生成文件/目录包。验证内容类型、格式版本、尺寸/嵌套/解压资源上限及必要结构；导入路径、包内成员和外部引用不得越过被允许目标。路径规范化检查与最终使用要组成抗替换竞态的策略，不能先检查字符串再任意重开。导出先确定目标与覆盖意图，不把用户选择父目录等同于准许覆盖其中所有文件。
**验收：** 同名异类型、截断、恶意嵌套、路径穿越、验证后替换链接及合法非 ASCII/大小写差异对照。失败无对原件的破坏性写入；文档合法外部链接依合同受控访问，而非全盘无差别拒绝。具体解析器安全和配额值归 L5/L6。

**输入、输出与权威补充：** 解析者输入内容/格式/配额/导出意图，输出有界获权对象。

**正例：** 合法外部链接按合同受控读取。

**具体目标入口与完成判据：** 真实导入/解包入口送穿越、截断、替换链接与合法中文样本；核原件未改。 以本条机制、失败处理及案例表的预期为通过条件；同时对照正常/直接失败/合法邻例，超时或未知不得标已确认。

**来源边界：** [DM03](../../../sources/desktop-mobile-claims.md#dm03)；仅采用各来源所列有限事实，动作/身份栅栏、恢复和案例为组织合成契约。

### S05 编辑代次与保存确认
**适用：** 可编辑文档。保存捕获一致内容快照与编辑代次 g；完成事件只确认 g，不自动将保存期间产生的 g+1 标成未修改。重复保存、自动保存和显式保存须有序协调；旧保存不得在新保存后覆盖目标。另存成功后文档身份/目标更新必须与实际文件一致；取消另存不能丢弃当前编辑。
**验收：** 保存 g 时继续输入，再反序返回两个保存完成回调；最终文件与 UI dirty 状态一致。检查“已保存”对应的代次、目标和承诺，不以写线程退出或进度 100% 代替提交。独立文档可并行保存，无需全应用全局串行。

**输入、输出与权威补充：** 保存者输入编辑代次 g 与快照，输出只确认 g 的结果；实际文件和最新确认代次为权威。

**正例：** g+1 已保存且无后续编辑时 clean。

**具体目标入口与完成判据：** 真实 UI 连续输入/保存反序完成，核最终文件与 dirty，不只测回调标签。 以本条机制、失败处理及案例表的预期为通过条件；同时对照正常/直接失败/合法邻例，超时或未知不得标已确认。

**来源边界：** [DM07](../../../sources/desktop-mobile-claims.md#dm07)；仅采用各来源所列有限事实，动作/身份栅栏、恢复和案例为组织合成契约。

### S06 保存流水线与失败分类
**适用：** 覆盖关键文档/配置。定义捕获内容→目标与冲突校验→准备暂存→完整写入→所需同步→受控提交/替换→确认的流程或具有等价保证的实现。检查短写、close/commit/sync 的失败；暂存目录及跨卷移动语义须验证。只能在所选介质契约允许范围内承诺原子可见或持久，不能把临时文件 rename 当作所有故障下不丢。Linux 文件 fsync 与目录项持久不是同一保证 [DM04](../../../sources/desktop-mobile-claims.md#dm04)，Windows 按实际句柄/FlushFileBuffers 契约核验 [DM05](../../../sources/desktop-mobile-claims.md#dm05)。
**验收：** 在每个转换前后受控中断并回读，区分旧版本、新版本、未知/损坏与可恢复草稿；需要跨卷导出时可采用复制校验后交付，但不得宣称它天然原子。不强制每个微型应用自建事务系统或一律调用同一 API。

**输入、输出与权威补充：** 保存流水线输入源/暂存/目标与承诺，输出提交/同步/回读结果。

**正例：** 完整写入所需同步后才提示成功。

**具体目标入口与完成判据：** 所选文件系统短写/close/sync 故障入口，逐阶段中断并回读；rename 不冒充掉电。 以本条机制、失败处理及案例表的预期为通过条件；同时对照正常/直接失败/合法邻例，超时或未知不得标已确认。

**来源边界：** [DM04](../../../sources/desktop-mobile-claims.md#dm04)、[DM05](../../../sources/desktop-mobile-claims.md#dm05)；仅采用各来源所列有限事实，动作/身份栅栏、恢复和案例为组织合成契约。

### S07 替换结果未知与元数据保留
**适用：** 使用替换文件 API 或覆盖现有文件。应保留目标、暂存及备份身份与阶段，按 API 的实际返回分类核对现状，避免失败后盲目重新覆盖。权限/ACL、扩展属性、数据流、文件类型标记及链接行为仅对项目承诺的必要项验证，不能为“保存成功”放宽原保护。Windows ReplaceFileW 的某些失败码会留下改变的文件名/属性；忽略 ACL 错误标志也有实际权限后果 [DM06](../../../sources/desktop-mobile-claims.md#dm06)。
**验收：** 复现替换阶段错误，核对原路径、替换路径、备份路径和权限；未知时展示可恢复选择而非猜测成功或删除全部临时件。另存新文档按批准权限创建是合法邻例，不要求继承与其无关的原件元数据。

**输入、输出与权威补充：** 替换者输入原/暂存/备份与保护元数据，输出实际路径/权限状态。

**正例：** 另存新文件按批准权限创建。

**具体目标入口与完成判据：** 真实 ReplaceFileW 受控错误并取 GetLastError，核1176/1177对应路径、ACL与备份。 以本条机制、失败处理及案例表的预期为通过条件；同时对照正常/直接失败/合法邻例，超时或未知不得标已确认。

**来源边界：** [DM06](../../../sources/desktop-mobile-claims.md#dm06)；仅采用各来源所列有限事实，动作/身份栅栏、恢复和案例为组织合成契约。

### S08 自动保存、草稿与退出
**适用：** 自动保存/崩溃恢复。区分自动保存原件、私有恢复草稿和用户显式提交；定义草稿刷新点、可丢失窗口、关联版本和恢复选择。恢复文件应具备适当访问限制与容量边界，不在普通临时清理中误删唯一副本；正常关闭不是唯一保存机会。退出期间等待、取消、继续后台的可见行为按产品合同实现。
**验收：** 强停前后的各编辑代次、草稿与原件对照；恢复草稿旧于原件或属于另一账号时不得直接覆盖。使用 Qt QSaveFile 的项目须核验 direct-write fallback：实际进入该模式时会失去相应原子/取消保护，不能仍宣传可无损取消 [DM07](../../../sources/desktop-mobile-claims.md#dm07)。不用该框架的项目不承担其 API 配置义务。

**输入、输出与权威补充：** 自动保存者输入草稿/原件代次，输出可恢复窗口；原件提交与私有草稿分开。

**正例：** 暂存取消保留原件。

**具体目标入口与完成判据：** 真实强停及 QSaveFile 采用者构造实际 direct-write fallback，再取消核内容。 以本条机制、失败处理及案例表的预期为通过条件；同时对照正常/直接失败/合法邻例，超时或未知不得标已确认。

**来源边界：** [DM07](../../../sources/desktop-mobile-claims.md#dm07)；仅采用各来源所列有限事实，动作/身份栅栏、恢复和案例为组织合成契约。

### S09 多实例及外部编辑冲突
**适用：** 多窗口/进程/版本、外部编辑器或同步程序可写同一对象。明确单写者、受支持锁、版本条件写入、合并或保留冲突副本的策略，覆盖打开到提交的竞争窗口。mtime/长度单独作为版本令牌须有实际保证，否则不足以可靠检测同长度、相同时间精度下的变更。进程内互斥不能证明跨进程安全；检查后再无条件 rename 不能构成原子比较并交换。
**验收：** 两写者交错、外部覆盖、保存前后路径替换、相同时间戳变更；任何无法确认安全覆盖的路径保留用户编辑并报告冲突。用户在看到差异后明确选择覆盖或另存属于合法解决，不要求全自动合并，也不将冲突副本冒称最终一致版本。

**输入、输出与权威补充：** 并发者输入打开版本/真实锁，输出条件提交/冲突副本；mtime/长度无保证不作唯一版本。

**正例：** 用户核差异后明确覆盖可合法。

**具体目标入口与完成判据：** 两个实例同 mtime/长度异内容交错保存，核无静默覆盖。 以本条机制、失败处理及案例表的预期为通过条件；同时对照正常/直接失败/合法邻例，超时或未知不得标已确认。

### S10 锁生命周期与通知局限
**适用：** 使用锁文件、OS 锁或目录监听。锁身份应能区别进程重启/PID 复用与工作区，建立释放、崩溃、陈旧判定和安全接管规则。失去锁/资源能力后不得继续原假定写入；不凭 PID 文件存在永久封锁，也不无条件删除锁。文件变化通知只是重读线索，须处理丢失、合并及自身写入事件，重连后重新扫描相关状态。
**验收：** 锁持有者崩溃、另实例仍活跃、时钟变化与通知丢失；有效写者不被抢占，失效状态有可验证恢复。macOS 采用文档协调机制时，按 NSDocument/File Coordinator/Presenter 的实际参与范围实现 [DM08](../../../sources/desktop-mobile-claims.md#dm08)，不能假设它阻止任意不参与协议的进程。

**输入、输出与权威补充：** 锁/监听者输入 owner/实例代际与事件，输出有效锁/重扫线索；通知不是完整变更日志。

**正例：** 确认失效锁按协议接管。

**具体目标入口与完成判据：** PID 复用、真实锁持有者存活、丢监听事件后重读；NSDocument 按实际参与范围。 以本条机制、失败处理及案例表的预期为通过条件；同时对照正常/直接失败/合法邻例，超时或未知不得标已确认。

### S11 同步盘、网络位置与可拔介质
**适用：** 宣称支持这些位置，或标准目录可能实际被重定向。标明本地可读、占位/未下载、离线、被外部修改、同步冲突及已远端确认的差异。保存不能仅凭文件存在即认定内容已就绪；外部代理替换、延迟上传和远端删除需要冲突处理。无法可靠识别提供者状态时，明确未知与支持限制，不虚构跨服务统一状态 API。
**验收：** 离线占位、读取中断、写后上传失败、同步冲突副本、介质拔出与同名重接；用户编辑可恢复，重试不越权覆盖。不支持网络上活跃数据库可被明确拒绝，但仍保留可导出本地成果；SQLite WAL 对网络文件系统的限制按引擎文档和既有规范处理 [DM09](../../../sources/desktop-mobile-claims.md#dm09)，不能把“普通文件能同步”推出“运行中数据库可同步”。

**输入、输出与权威补充：** 提供者适配输入本地/占位/离线/远端版本，输出各自状态；文件存在不证明内容就绪。

**正例：** 普通本地文档无需同步状态。

**具体目标入口与完成判据：** 实际同步提供者离线占位、写后上传失败、介质换卷；活跃 SQLite WAL 不作普通文件同步。 以本条机制、失败处理及案例表的预期为通过条件；同时对照正常/直接失败/合法邻例，超时或未知不得标已确认。

### S12 多文件文档与引擎生命周期
**适用：** 目录包、数据库+附件/索引或多个关键配置。确定权威成员、引用完整性和一致快照边界；一个文件 rename 不证明整个目录/附件集原子完成。可选择代次目录+有效 manifest、引擎事务及受控外部文件发布等符合实际需求的方案，记录孤立附件、未发布代次和缺失引用的恢复方式，不强制新建分布式事务。
**验收：** 数据库已提交而附件未就绪、附件完成而索引未更新、关闭窗口后后台连接仍活跃；重开不得展示不存在附件为完整内容。数据库连接、备份、迁移和应用退出协调按引擎契约，不能复制单独活跃 .db 或手删 WAL 来“清理”。可重建索引损坏可以重建，作品附件不能因此一起清空。

**输入、输出与权威补充：** 文档集者输入 DB/附件/manifest，输出一致发布代次；单文件 rename 不认证多对象提交。

**正例：** 可丢索引损坏可重建而保留附件。

**具体目标入口与完成判据：** 真实引擎提交后附件未完即终止，回读 manifest/引用和实际文档；不手删 WAL。 以本条机制、失败处理及案例表的预期为通过条件；同时对照正常/直接失败/合法邻例，超时或未知不得标已确认。

### S13 空间不足、权限变化与有限重试
**适用：** 写入、备份和迁移。考虑源、目标、暂存、备份、日志/引擎临时增长的峰值，不把空间预检查当预留成功。写满、配额、只读、访问撤销、I/O 错误、共享占用及介质失联分别报告；保留失败阶段及可恢复数据。重试有界且先核实未知结果，不靠持续生成恢复副本耗尽最后空间。
**验收：** 暂存/提交/同步各阶段注入失败，确认没有假保存成功；用户可另存有权位置，不能自动扩权限或删除用户文件腾空间。空间充足的合法大文件不因小型固定测试上限被误拒；实际限制由 L6 决定。

**输入、输出与权威补充：** 写者输入峰值空间/配额/能力，输出分阶段错误/恢复；预检查不是预留。

**正例：** 用户另存有权且有空间位置可成功。

**具体目标入口与完成判据：** 真实暂存/提交/sync 注入满盘/只读/失联，核无假保存和无限副本。 以本条机制、失败处理及案例表的预期为通过条件；同时对照正常/直接失败/合法邻例，超时或未知不得标已确认。

### S14 备份对象与一致性证明
**适用：** 产品提供备份或以备份作为迁移/恢复前提。备份集应说明文档代次、格式、账号/工作区、必要附件与恢复依赖；同步副本、旧临时文件、同盘复制不自动等于满足项目灾难恢复目标。备份完成须核对一致性和可读性，文件存在或复制函数返回成功不足以证明可恢复。密钥恢复途径与备份分开授权，不把密钥明文打包作默认便利功能。
**验收：** 从合成备份恢复到隔离目标核对数量、内容、引用和权限；缺附件、备份中断、空间不足、不可用密钥有清晰结果。引擎在线备份算法直接继承数据库专项；无关键可变数据的只读应用不必虚设备份系统。

**输入、输出与权威补充：** 备份者输入一致数据集/主体/格式和恢复依赖，输出可验证备份。

**正例：** 静态普通文档按已核合同复制可用。

**具体目标入口与完成判据：** 引擎认可备份接口到隔离目录恢复，核数量/字段/附件/权限；不只复制活跃 db。 以本条机制、失败处理及案例表的预期为通过条件；同时对照正常/直接失败/合法邻例，超时或未知不得标已确认。

### S15 恢复、导入重建与原件保留
**适用：** 备份恢复、损坏修复或恢复草稿。先判定来源身份、完整性、版本及访问权，默认在隔离目标验证；覆盖现存数据需明确目标/差异及相应授权。成功切换后核对应用真实打开、编辑、保存及必要外部引用，不只校验文件数量。保留未恢复对象和可追溯原因；恢复旧快照不得自动重放外部副作用或重新启用已撤销账号。
**验收：** 恢复后能完成既定用户任务，原坏件和未确认候选按授权保留；没有可用备份时准确标记无法恢复范围，不“新建空库成功”冒充恢复。无覆盖风险的导入为新工作区是合法路径，不要求每次均覆盖原位置。

**输入、输出与权威补充：** 恢复者输入来源身份/版本/权利，输出隔离验证后任务结果；空库启动不作恢复。

**正例：** 无覆盖导入新工作区合法。

**具体目标入口与完成判据：** 实际恢复入口打开、编辑、保存重开，核原件/未恢复与副作用不自动重放。 以本条机制、失败处理及案例表的预期为通过条件；同时对照正常/直接失败/合法邻例，超时或未知不得标已确认。

### S16 格式识别与读写兼容门槛
**适用：** 格式可演进。定义魔数/类型、格式版本、最低读写能力与必要特性；应用版本号不是数据格式号。打开前验证可读、可写或仅可导出；未知版本/关键特性不得默默按旧格式写回。可保留未知字段的读取器仍须验证语义及往返保真，不能仅凭 JSON 能解析认定前向兼容。
**验收：** 旧程序读新数据、未知可选/必需字段、降级另存、损坏头部与旧合法样本；未支持写入应阻断破坏性修改，但可提供经验证的只读/转换副本。格式未变的应用版本升级不必运行虚构迁移。

**输入、输出与权威补充：** 格式者输入魔数/版本/必需能力，输出可读/可写/只读；应用版本名不是格式号。

**正例：** 未知可选字段保真往返经证实可写。

**具体目标入口与完成判据：** 真实新旧格式夹具和旧程序打开/写回，核未知必需字段拒写与合法旧样本。 以本条机制、失败处理及案例表的预期为通过条件；同时对照正常/直接失败/合法邻例，超时或未知不得标已确认。

### S17 迁移前置与独占边界
**适用：** 改变现有持久数据。迁移计划固定源/目标格式、转换器版本、输入身份、所需空间、可恢复来源及兼容窗口。开始前协调全部相关写者/引擎连接/后台组件，不因主窗口关闭就假定无人写入。新实例不得与旧版本同时无约束写迁移目标；迁移权限限原账号/工作区，不借首启取得无关数据权。
**验收：** 两实例同时首启、后台占用、备份未完成、只读目录及错误源版本；前置不满足不修改原数据，明确恢复条件。批准的可在线兼容迁移可持续服务，但其兼容证据由数据库专项和项目提供，不被本文一律禁止。

**输入、输出与权威补充：** 迁移者输入源/目标/转换器/恢复来源和写者集合，输出获准独占或在线兼容迁移。

**正例：** 无格式变化升级无需迁移。

**具体目标入口与完成判据：** 两个版本同时首启、后台连接仍在、只读目标，核前置不满足原件未动。 以本条机制、失败处理及案例表的预期为通过条件；同时对照正常/直接失败/合法邻例，超时或未知不得标已确认。

### S18 可恢复阶段、重入与提交点
**适用：** 迁移可能中断。采用受支持事务或可恢复阶段，记录已完成/未完成/未知转换及对应数据身份；进度百分比不是正确性凭证。每阶段在崩溃后能确定继续、验证、回退或前向修复；不可只重置标志从头执行非幂等步骤。迁移状态的持久顺序必须与结果一致，不能先写“完成”再转换用户内容。
**验收：** 转换前/后、提交前/后和首次健康确认前中断，重复恢复不重复改写；验证记录数、关键字段、附件引用、未知字段及实际读写，不把摘要变化作为语义正确证明。单次受支持事务覆盖全部对象时无需额外自造迁移日志。

**输入、输出与权威补充：** 迁移者输入耐久阶段/数据身份，输出可重入转换；完成标志不得早于实际结果。

**正例：** 单事务全对象提交可直接核完成。

**具体目标入口与完成判据：** 真实转换前后/commit前后中断，核记录/引用/未知字段与实际读写。 以本条机制、失败处理及案例表的预期为通过条件；同时对照正常/直接失败/合法邻例，超时或未知不得标已确认。

### S19 程序回退、数据回退与首次启动失败
**适用：** 允许升级/降级或并排版本。维护程序读写能力×数据格式的兼容表；迁移成功而新程序首启失败时，只有数据兼容才可直接回退程序。恢复旧备份会丢失迁移后新增编辑，须识别差异及有权选择，不能以版本回退授权推定允许丢弃新工作。
**验收：** 新数据+旧程序、迁移后产生新编辑、失败恢复后的后台组件，均无静默误写。可选择经验证只读、导出或前向修复；明确没有逆向转换时不得承诺可无损回退。P6 编排引用这些实际兼容结果，本文不实施发布操作。

**输入、输出与权威补充：** 回退者输入程序×格式能力及新增编辑，输出代码/数据/前向修复选择。

**正例：** 格式兼容可回退程序且保留新编辑。

**具体目标入口与完成判据：** 实际旧程序遇新数据和失败首启恢复，核只读门禁与差异，不仅安装版本。 以本条机制、失败处理及案例表的预期为通过条件；同时对照正常/直接失败/合法邻例，超时或未知不得标已确认。

### S20 保留、清理与删除边界
**适用：** 清理缓存、过期备份、迁移暂存、工作区退出或卸载。清理仅作用于明确所有权与可删除类别；执行时重新核对目标身份/路径及引用，防止链接替换、被他方接管或仍为恢复唯一副本。保留期、用户明确删除与事故证据保留义务分开处理；不能用恢复成功标志代替删除授权。
**验收：** 缓存路径混入作品、迁移暂存仍被有效 manifest 引用、备份链存在依赖、目录被替换；安全拒绝误删。已明确可重建且无依赖的缓存可按批准策略清理，不强制永久保留所有临时字节。具体安全擦除、密钥销毁与平台卸载机制不在此重订。

**输入、输出与权威补充：** 清理者输入分类/所有权/依赖和保留规则，输出实际删除/拒绝；恢复标志不作删除授权。

**正例：** 自有可重建无依赖缓存可清。

**具体目标入口与完成判据：** 清理前替换链接/目标、有效 manifest 引用与备份链，核拒绝误删。 以本条机制、失败处理及案例表的预期为通过条件；同时对照正常/直接失败/合法邻例，超时或未知不得标已确认。

**来源边界：** [DM02](../../../sources/desktop-mobile-claims.md#dm02)、[DM09](../../../sources/desktop-mobile-claims.md#dm09)；仅采用各来源所列有限事实，动作/身份栅栏、恢复和案例为组织合成契约。

## 四、失败反例、合法邻例与检查入口

以下是基于真实机制的**待执行验收设计**，不是实际故障实验结果，也不虚构已发生的产品事故。每项应由 L5/L6 转成实际支持平台上的受控操作/脚本，并保留前后数据证据。

## 五、项目证据与执行层次

项目复用现有测试及交付记录，逐项给出适用理由、实际检查入口、预期/实际、证据路径和未覆盖项，不另建竞争台账。最小证据包括：

1. **环境与内容身份：** OS build、架构、文件系统/卷/网络或同步条件、权限、应用/引擎/驱动版本、格式版本、输入数据摘要与脱敏说明；源/暂存/目标/恢复位置可区分。
2. **故障与交错：** 操作序列及注入点、编辑代次、写入/替换/同步返回、锁/账号变化和重启位置；不记录秘密或无必要正文。
3. **数据前后对照：** 已确认、未确认、未知保存的内容与恢复结果，关键字段/引用/作品数量、权限与 UI 状态。字节相同不是所有语义正确，字节不同也不自动意味着损坏。
4. **恢复验收：** 独立目录或获准隔离环境中打开、继续编辑、保存/导出及再次重开；不可恢复范围、用户选择和原件留存可查。
5. **证明层级：静态条文审查、单元替身、真实文件系统集成、进程强停、OS 崩溃、实际断电分别列示；低层级不外推高层级。网络共享、同步提供者和设备条件只覆盖真实测试矩阵。

相关官方有限命题见来源记录。项目按实际存储和恢复机制选择文件删除、用户数据迁移、数据库恢复、断电、同步盘与多实例测试，分别记录输入、失败注入、权威状态及恢复结果。
