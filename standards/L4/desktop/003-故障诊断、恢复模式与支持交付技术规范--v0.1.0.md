# L4 故障诊断、恢复模式与支持交付技术规范

**文档ID：** STD-L4-DESKTOP-003　**版本：** 0.1.0　**状态：** adopted　**生效日期：** 2026-10-30

## 一、目标、适用与非目标

使故障定位、符号、最小诊断和安全恢复形成可验证链路，不能用删除数据或错误符号产生表面恢复。

**适用对象：** 崩溃/挂起/无进展/启动循环，符号与转储，隐私配额，安全启动、支持包和恢复后任务。 按产品真实存在的能力逐条激活；单平台、离线或无账号不因本专题新增功能。

**非目标：** 不重订事故治理、P2 数据恢复或 P6 代码回退算法；不要求联网遥测或上传完整内存。

## 二、术语、强度与角色

“必须/应/不得”表示适用条件成立时的规范要求；“建议”允许有依据替代；“例如/示例”为说明，不构成新增平台、功能或统一阈值。引用厂商指南仅在采用其机制时适用，本规范综合定义的要求在来源记录中单独标明。条款 ID 在后续版本保留。

产品维护者固定支持与任务合同；L5 适配者固定 OS/SDK/框架/工具版本与真实 API；组件实现者对输入验证、状态迁移和释放负责；验证者保存准确制品、环境、前后状态与原始观察。OS/渠道记录只对其管辖状态有权威，业务结果由相应本地持久层或受权远端确认，UI 标签和日志字段本身不认证结果。

前置输入为已声明支持画像、最终构建/组件身份、相关账号/窗口/文档或操作身份、数据格式/权限与必要预算。输出为各条产物、状态和完成/失败/未知记录。实例、账号、文档与操作代际分开；状态至少区分未接纳、已接纳/排队、执行、已确认、拒绝/失败、取消请求/确认和结果未知，仅按真实对象采用。

并发和超时预算由采用方预先固定，说明时钟与睡眠语义；超时、断连或请求取消不等于效果未发生。已知未提交/无副作用路径可按合同重试；可能已提交者先回读权威结果，无法核实时保留未知。恢复不得跨账号或把旧异步回复作用于新代际。兼容以声明矩阵及双方能力/数据合同为准，不由 latest 页面或展示版本自动改变。

## 三、稳定条款与验收契约

### DT8-01 故障分类、阶段与关联

**角色/前置/必要动作：** 诊断维护者必须区分进程崩溃、UI 无响应、后台无进展、启动循环、设备/资源错误和业务结果未知。记录构建、组件/进程实例、OS/运行时、操作阶段及最小关联 ID；用户可见错误不应只剩未知 Error。日志时间同时注明墙钟/单调序列可用边界。

**并发、超时、未知与恢复：** 多组件故障与日志乱序不得靠最近一条错误推断因果；超时不证明崩溃或无效果。缺关键观测保留未知和下一诊断入口，不反复发起可能重复的业务动作。

**产物、真实目标入口与判据：** 在隔离目标触发受控测试崩溃、主线程阻塞和后台停滞分别采样；Windows Event Viewer/WinDbg，macOS Console/Activity Monitor Sample，Linux journalctl/coredumpctl/线程采样。判据为分类和阶段可重现，不将三者统称同一 crash。

**正例：** 服务提交后回包丢失标业务结果未知而非程序崩溃。 **直接失败反例：** 进度条超时就清空数据并重做任务，失败。 **合法邻例：** 无后台进程的应用可不产生后台停滞类。

**来源有限命题：** [DM24](../../../sources/desktop-mobile-claims.md#dm24)、[DM25](../../../sources/desktop-mobile-claims.md#dm25)；来源仅支持其记录的事实，组合状态机、身份栅栏与验收结果为本规范组织合成要求。

### DT8-02 构建与符号的精确绑定

**角色/前置/必要动作：** 发行者必须保存实际二进制/模块身份与相应符号（PDB 身份、Mach-O UUID/dSYM、ELF build ID/debuglink 等实际机制）的映射。产品版本名、路径和源分支名不是匹配权威。符号化前验证每个相关模块，缺符号/错符号分别报告，不强制忽略匹配错误。

**并发、超时、未知与恢复：** 同版本重建、渠道加工、裁剪或混版组件后按实际模块选符号；缺失时保留原地址/模块/偏移及不确定性，不能把看似合理函数名当正确定位。符号保留与支持窗口一致，公开/私有符号各按权利最小化。

**产物、真实目标入口与判据：** Windows WinDbg lm/!sym noisy/.reload 与对应 PDB；macOS dwarfdump --uuid 对比二进制/dSYM 再符号化；Linux readelf -n、GDB info files/匹配 debuglink。判据为受控已知故障点正确定位，错构建符号不被当成功。

**正例：** 两个同展示版本构建按 UUID 选到正确符号。 **直接失败反例：** 拿上一构建 PDB 强制装入并报告准确调用栈，失败。 **合法邻例：** 无私有符号时可提供诚实的模块+偏移诊断。

**来源有限命题：** [DM24](../../../sources/desktop-mobile-claims.md#dm24)、[DM25](../../../sources/desktop-mobile-claims.md#dm25)；来源仅支持其记录的事实，组合状态机、身份栅栏与验收结果为本规范组织合成要求。

### DT8-03 转储、脱敏与接收边界

**角色/前置/必要动作：** 采集者必须按排障任务选择日志、线程栈、最小转储或完整内存，默认最小化用户路径、正文、秘密和精确轨迹。转储可能包含已解密数据，不能因二进制格式就当匿名。导出前校验内容和接收方范围；本地采集与外发同意分开。

**并发、超时、未知与恢复：** 脱敏失败、未知字段、上传失联和账号切换时保留受控本地诊断，不自动发送原件；导出预览不得把敏感原始包扩散到普通目录。旧账号诊断不归当前账号所有。

**产物、真实目标入口与判据：** 对合成秘密/文档故障样本执行项目真实日志/转储入口，用文本/二进制可审查方式检查令牌、路径和正文；再测拒绝上传和离线导出。判据为选定信息最小且目标有权，宣称已脱敏必须有输出检查而非仅 redacted=true。

**正例：** 只导出最小模块/栈，合成令牌未出现。 **直接失败反例：** 完整内存自动上传却标“无用户数据”，失败。 **合法邻例：** 获准的受控完整转储可按明确需要单独处理。

**来源有限命题：** [DM24](../../../sources/desktop-mobile-claims.md#dm24)、[DM34](../../../sources/desktop-mobile-claims.md#dm34)；来源仅支持其记录的事实，组合状态机、身份栅栏与验收结果为本规范组织合成要求。

### DT8-04 配额、轮转与故障中的可用性

**角色/前置/必要动作：** 诊断系统必须对单条大小、频率、总量、保留和上传队列定界，按重要性保留必要故障线索；日志失败不得递归写日志。配额应考虑与文档/迁移共卷的竞争，不能让支持工具耗尽最后空间。关闭遥测不应消除合法本地排障入口。

**并发、超时、未知与恢复：** 离线、写满、权限撤销和崩溃循环时有界降采样/轮转，保留实际丢弃计数与原因，不假装证据完整。不能为恢复诊断删用户作品；清理只限已分类可丢对象。

**产物、真实目标入口与判据：** 在隔离目标重复触发合成错误、断开上传并限制诊断目标可写空间；检查文件大小、轮转、队列及文档保存。判据为预算内收敛、核心任务按合同运行、缺失证据透明且无无限内存/磁盘积压。

**正例：** 离线轮转后保留首个关键故障及丢弃计数。 **直接失败反例：** 每次日志失败递归输出直到磁盘写满，失败。 **合法邻例：** 无需遥测的离线应用可只保存本地最小日志。

**来源有限命题：** [DM24](../../../sources/desktop-mobile-claims.md#dm24)；来源仅支持其记录的事实，组合状态机、身份栅栏与验收结果为本规范组织合成要求。

### DT8-05 安全启动与最小恢复动作

**角色/前置/必要动作：** 恢复入口必须区分禁用可疑扩展、绕过可丢缓存、重建索引、配置副本和数据恢复。每个动作绑定目标、所有权、预期效果和撤销/恢复界线；安全模式不等于禁用签名验证、沙箱或扩大权限。迁移/未知保存仍由 P2 核。

**并发、超时、未知与恢复：** 启动循环使用有界次数和可解释选择，不自动重置用户目录。禁用扩展后仍有原生代码在进程内时，明确需重启的生效条件；无法恢复范围保留原件和证据。

**产物、真实目标入口与判据：** 目标系统从真实支持入口进入 Safe mode，分别加入损坏可丢缓存、故障扩展和不可读用户数据；比较动作前后文件/权限并执行核心任务。判据为只改批准类别，恢复不依赖放宽安全，唯一数据不被重置。

**正例：** 隔离扩展重启后原文档可编辑且安全边界保持。 **直接失败反例：** 安全模式通过关闭平台保护才可启动，失败。 **合法邻例：** 无扩展产品无需新增插件禁用菜单。

**来源有限命题：** [DM21](../../../sources/desktop-mobile-claims.md#dm21)、[DM24](../../../sources/desktop-mobile-claims.md#dm24)；来源仅支持其记录的事实，组合状态机、身份栅栏与验收结果为本规范组织合成要求。

### DT8-06 支持材料与可复现最小样本

**角色/前置/必要动作：** 支持交付者必须将环境、构建/符号键、复现步骤、输入类型/摘要、预期/实际、已尝试恢复和未覆盖项关联；使用合成或最小获准数据。收集工单/包仅证明材料到达，不证明故障已定位或用户工作已恢复。

**并发、超时、未知与恢复：** 不能复现时明确已观察事实与推断，不凭用户截图认定磁盘损坏。接收方或范围变化须按既定数据权利办理，不自动把私有转储附到公开议题；旧材料与本次构建不相符须标明。

**产物、真实目标入口与判据：** 在同版本隔离目标按最小步骤复现，再用修复构建重验；核诊断包 manifest 的摘要、符号匹配及合成敏感数据检查。判据为别人可定位准确对象并重复现象，不能把包存在当结案。

**正例：** 合成文件可重现解析崩溃，构建/符号对应。 **直接失败反例：** 把旧系统截图配新构建写成已复现，失败。 **合法邻例：** 无法共享用户原文时可交元数据和可审查最小样本。

**来源有限命题：** [DM24](../../../sources/desktop-mobile-claims.md#dm24)、[DM25](../../../sources/desktop-mobile-claims.md#dm25)；来源仅支持其记录的事实，组合状态机、身份栅栏与验收结果为本规范组织合成要求。

### DT8-07 恢复完成、残余状态与复验

**角色/前置/必要动作：** 恢复确认必须回到原用户任务，检查文档打开/编辑/保存重开、必要组件及权限，并分别给出已恢复、未恢复和未知结果。程序能启动、缓存重建或符号化成功均不足以证明数据/业务恢复。代码回退消费 P6 结果，数据恢复消费 P2。

**并发、超时、未知与恢复：** 恢复后迟到回包、旧后台实例和新编辑不得重新污染状态；验证当前实例/账号/文档代际。缺恢复输入时保留诚实不可恢复范围，不生成空数据冒称恢复。修复后保留原失败与新回归。

**产物、真实目标入口与判据：** 目标系统执行已批准恢复路径，核恢复前后对象、实际用户任务及重启后回读，再尝试原反例和合法邻例。判据为明确合同结果、没有误删/越权/重复副作用。

**正例：** 重建可丢索引后作品数、内容与权限一致。 **直接失败反例：** 空数据库正常启动就报告所有作品恢复，失败。 **合法邻例：** 不存在用户数据的工具可采用较小健康任务。

**来源有限命题：** [DM24](../../../sources/desktop-mobile-claims.md#dm24)、[DM25](../../../sources/desktop-mobile-claims.md#dm25)；来源仅支持其记录的事实，组合状态机、身份栅栏与验收结果为本规范组织合成要求。

## 四、采用与证据边界

目标验收入口中的产品名/包标识、文件和设备由 L6 替换为其准确对象，不把示例工具命令的退出 0 单独当作核心任务完成。仅在获准隔离目标使用故障/篡改样本；正常输入、直接失败和合法邻例必须成对观察。静态、合成、目标 OS、真实硬件/辅助技术/自然调度各层分别留证。

离线合成示例若另有运行记录，仅证明其显式有限假设，不替代这些入口。
