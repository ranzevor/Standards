# L4 更新协调、版本共存与退役技术规范

**文档ID：** STD-L4-DESKTOP-004　**版本：** 0.1.0　**状态：** adopted　**生效日期：** 2026-10-30

## 一、目标、适用与非目标

更新必须保持组件、用户工作与数据兼容，不能把下载、切换或回退代码当作完整恢复。

**适用对象：** 更新源/有效策略，暂存/切换/首次健康，多组件与数据共存，离线旧端、撤回及结束支持。 按产品真实存在的能力逐条激活；单平台、离线或无账号不因本专题新增功能。

**非目标：** 不重写 TUF 或供应链信任算法；数据迁移机制归 P2，平台安装事务归 P5，Web 资源共存归 Web 发行专题。

## 二、术语、强度与角色

“必须/应/不得”表示适用条件成立时的规范要求；“建议”允许有依据替代；“例如/示例”为说明，不构成新增平台、功能或统一阈值。引用厂商指南仅在采用其机制时适用，本规范综合定义的要求在来源记录中单独标明。条款 ID 在后续版本保留。

产品维护者固定支持与任务合同；L5 适配者固定 OS/SDK/框架/工具版本与真实 API；组件实现者对输入验证、状态迁移和释放负责；验证者保存准确制品、环境、前后状态与原始观察。OS/渠道记录只对其管辖状态有权威，业务结果由相应本地持久层或受权远端确认，UI 标签和日志字段本身不认证结果。

前置输入为已声明支持画像、最终构建/组件身份、相关账号/窗口/文档或操作身份、数据格式/权限与必要预算。输出为各条产物、状态和完成/失败/未知记录。实例、账号、文档与操作代际分开；状态至少区分未接纳、已接纳/排队、执行、已确认、拒绝/失败、取消请求/确认和结果未知，仅按真实对象采用。

并发和超时预算由采用方预先固定，说明时钟与睡眠语义；超时、断连或请求取消不等于效果未发生。已知未提交/无副作用路径可按合同重试；可能已提交者先回读权威结果，无法核实时保留未知。恢复不得跨账号或把旧异步回复作用于新代际。兼容以声明矩阵及双方能力/数据合同为准，不由 latest 页面或展示版本自动改变。

## 三、稳定条款与验收契约

### DT6-01 更新候选、来源与有效策略

**角色/前置/必要动作：** 更新选择者必须把产品/渠道、发布身份、平台/CPU、安装范围、版本序列和元数据有效性与当前设备绑定。采用既定供应链防回滚/冻结策略；备用源执行相同验证。应用配置仅是意图，设备管理/系统实际许可与有效更新设置须目标读取。App Installer 设置按 OS/Schema 支持范围解释。

**并发、超时、未知与恢复：** 主源不可达、时钟不可信、元数据过期或管理策略禁用应保留可解释状态；不绕过企业策略或降级到任意源。普通离线不等于更新失效，更不等于已有用户数据可丢。

**产物、真实目标入口与判据：** 用项目实际更新客户端指向受控离线镜像夹具，覆盖错渠道/CPU/旧序列与有效新包；Windows 检所装 appinstaller 配置及系统实际更新行为。判据为选包理由、验证结果与有效策略一致，不只核本地配置文件。

**正例：** 正确渠道/架构候选在有效策略下被暂存。 **直接失败反例：** 主源失联后直接运行任意备用 EXE，失败。 **合法邻例：** 无自动更新产品走已核人工安装合法。

**来源有限命题：** [DM20](../../../sources/desktop-mobile-claims.md#dm20)、[DM22](../../../sources/desktop-mobile-claims.md#dm22)；来源仅支持其记录的事实，组合状态机、身份栅栏与验收结果为本规范组织合成要求。

### DT6-02 组件图与共存兼容

**角色/前置/必要动作：** 更新编排者必须登记 UI、helper、服务、插件、嵌入运行时、Web 资源、协议与数据格式的兼容图。允许混版的边和期限由提供/消费方能力确认；版本字符串相同不证明协议相同。旧实例不得在不兼容新数据上继续写，多个用户会话和后台组件都属写者集合。

**并发、超时、未知与恢复：** 启动交错、服务延迟重启和插件失败时，阻断不支持的调用/写入而保留合法只读/导出。若不支持混版，应受控停止接纳和确认旧工作阶段；不能只关闭主窗推断全部连接已退出。

**产物、真实目标入口与判据：** 在隔离 OS 保留旧 helper/第二会话，升级 UI 并执行握手/保存；记录每个进程实际映像、协议能力和数据格式。判据为不兼容组合明确拒绝无破坏，支持组合真实工作，旧组件不隐形写入。

**正例：** 允许窗口中的新 UI 与兼容旧 helper 按协商操作。 **直接失败反例：** 旧服务继续按旧格式写已迁移数据，失败。 **合法邻例：** 无格式/协议变化更新无需虚构迁移。

**来源有限命题：** [DM09](../../../sources/desktop-mobile-claims.md#dm09)、[DM22](../../../sources/desktop-mobile-claims.md#dm22)；来源仅支持其记录的事实，组合状态机、身份栅栏与验收结果为本规范组织合成要求。

### DT6-03 暂存、并发更新与切换栅栏

**角色/前置/必要动作：** 同一安装目标的更新必须串行或由等效事务协调，关联更新 ID、已核制品摘要、暂存对象与阶段。切换前确认安全点、用户未保存工作及所有必要写者；下载完成不授权无条件杀进程。新候选不得让旧更新回调覆盖较新目标。

**并发、超时、未知与恢复：** 重复检查、第二候选、文件占用、磁盘不足及切换中断时回读 OS 安装/运行身份。取消下载、取消切换请求和已提交系统安装不是同一结果；未知提交先核，未发布暂存按所有权清理。

**产物、真实目标入口与判据：** 真实更新流程同时触发两个候选，在验证、暂存、退出旧进程、系统提交各边界中断；核更新账、运行映像、文档代次和安装日志。判据为一次目标切换、草稿不丢、无陈旧回调倒退。

**正例：** 文档到安全点后单次切换且回读新映像。 **直接失败反例：** 候选 B 已切换后 A 的迟到完成回调又恢复 A，失败。 **合法邻例：** 空闲且数据兼容时可以自动切换。

**来源有限命题：** [DM20](../../../sources/desktop-mobile-claims.md#dm20)、[DM22](../../../sources/desktop-mobile-claims.md#dm22)；来源仅支持其记录的事实，组合状态机、身份栅栏与验收结果为本规范组织合成要求。

### DT6-04 首启健康与有限推进

**角色/前置/必要动作：** 切换后必须分开确认系统安装、当前运行构建、必要组件握手、数据可读写和核心任务健康；更新完成标志不得先于所承诺健康边界。健康指标和观察窗由项目固定，不只以进程存在/退出 0 为准。

**并发、超时、未知与恢复：** 首启失败、部分组件失败、超时和反复更新循环要有有界恢复；暂时网络失联不自动判本地文档损坏。未知健康保留受限入口、最小诊断和已知良好材料，不抹历史失败。

**产物、真实目标入口与判据：** 目标系统从支持的旧包升级，首启运行实际打开/编辑/保存重开任务；控制 helper 不可达或核心任务失败。判据为健康门禁拦住不合格推进，失败阶段与真实数据可对应；成功不外推长期全部性能。

**正例：** 安装成功但任务失败仍记未健康并保留原数据。 **直接失败反例：** 写入已完成更新标志后才开始未知迁移，失败。 **合法邻例：** 纯离线工具的健康不依赖无关服务。

**来源有限命题：** [DM20](../../../sources/desktop-mobile-claims.md#dm20)、[DM22](../../../sources/desktop-mobile-claims.md#dm22)；来源仅支持其记录的事实，组合状态机、身份栅栏与验收结果为本规范组织合成要求。

### DT6-05 代码回退与数据兼容决策

**角色/前置/必要动作：** 恢复者必须消费 P2 的程序读写能力×数据格式表，分别决定代码回退、数据恢复和前向修复。允许平台版本降级只解决包安装条件，不证明数据能回退。迁移后新增编辑须列差异，恢复旧快照不应自动丢弃新工作或重放远端副作用。

**并发、超时、未知与恢复：** 没有安全逆向迁移时，选择经验证只读/导出/前向修复并明确不可恢复范围，不无限重启或清空用户目录。回退与仍活跃新写者须互斥或有真实兼容协议。

**产物、真实目标入口与判据：** 给旧程序加载新格式及迁移后新增编辑，在项目真实包更新/恢复入口执行；检查格式门禁与恢复副本前后内容。判据为不支持写入被拒、无静默丢编辑；兼容格式的合法代码回退可成功。

**正例：** 格式兼容的代码回退保留全部编辑。 **直接失败反例：** 系统允许 downgrade 就旧程序直接覆盖新格式，失败。 **合法邻例：** 没有 downgrade 承诺可用前向修复满足恢复合同。

**来源有限命题：** [DM22](../../../sources/desktop-mobile-claims.md#dm22)、[DM09](../../../sources/desktop-mobile-claims.md#dm09)；来源仅支持其记录的事实，组合状态机、身份栅栏与验收结果为本规范组织合成要求。

### DT6-06 长期离线客户端与远端演进

**角色/前置/必要动作：** 连接服务的产品必须将旧二进制/协议能力与支持窗口、配置/资源版本和服务接口相配。重连前核账号、权限与原操作身份；本地保存、待同步、远端确认和未知结果分别显示。最低版本门禁不得无依据封死仍应提供的数据导出/只读路径。

**并发、超时、未知与恢复：** 离线跨服务升级、配置过期和凭据撤销时，敏感写入按当前权利拒绝，合法本地工作继续。未知副作用先依既定后端权威/去重合同核对，不因更新重放。

**产物、真实目标入口与判据：** 保留支持期内代表旧包，接入新隔离服务/固定协议夹具；离线编辑后升级服务再重连并切换账号。判据为合法数据可恢复、无串号、原副作用次数与回执一致，配置不足保持未知。

**正例：** 旧端兼容只读，本地编辑可导出。 **直接失败反例：** 强制更新提示导致唯一离线作品不可取回，失败。 **合法邻例：** 从不连接服务的桌面工具不承担远端组合测试。

**来源有限命题：** [DM22](../../../sources/desktop-mobile-claims.md#dm22)；来源仅支持其记录的事实，组合状态机、身份栅栏与验收结果为本规范组织合成要求。

### DT6-07 撤回、退役与残存安装

**角色/前置/必要动作：** 维护者必须区分停止新下载、撤回候选、吊销信任材料、停止更新源、结束支持与移除终端。记录仍受支持的离线安装、最终恢复/导出路径及必要签名/更新验证材料的可用性；下架不是终端已消失。

**并发、超时、未知与恢复：** 撤回期间已在途/已安装包按其实际身份核；不能为了退役删除用户数据、共享组件或全部诊断。支持承诺变化由既定治理决定，无法观察的终端保留未知，不伪造全量清零。

**产物、真实目标入口与判据：** 用隔离镜像/更新客户端验证撤回包不再被新选择，而旧合法安装可走规定恢复/迁移；核 inventory 与退役清单。判据为各状态准确，必要数据与验证材料可取得，残存端不被表面下架报告掩盖。

**正例：** 取消分发旧候选，已安装支持期用户仍能导出。 **直接失败反例：** 撤掉 URL 即报所有终端退役，失败。 **合法邻例：** 未曾分发且无用户数据的原型可简化归档。

**来源有限命题：** [DM20](../../../sources/desktop-mobile-claims.md#dm20)、[DM22](../../../sources/desktop-mobile-claims.md#dm22)；来源仅支持其记录的事实，组合状态机、身份栅栏与验收结果为本规范组织合成要求。

## 四、采用与证据边界

目标验收入口中的产品名/包标识、文件和设备由 L6 替换为其准确对象，不把示例工具命令的退出 0 单独当作核心任务完成。仅在获准隔离目标使用故障/篡改样本；正常输入、直接失败和合法邻例必须成对观察。静态、合成、目标 OS、真实硬件/辅助技术/自然调度各层分别留证。

离线合成示例若另有运行记录，仅证明其显式有限假设，不替代这些入口。
