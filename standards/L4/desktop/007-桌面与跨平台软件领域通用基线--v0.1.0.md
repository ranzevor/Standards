# L4 桌面与跨平台软件领域通用基线

**文档ID：** STD-L4-DESKTOP-007　**版本：** 0.1.0　**状态：** adopted　**生效日期：** 2026-10-30

> 项目采用范围与实现验收分别记录；符合性由相应条款的实际执行证据判定。

## 目标与非目标

目标是终端系统集成、本地数据、发行和运行状态均有真实确认边界；非目标是强制三平台、统一框架、统一数值门槛或替代相邻引擎/浏览器/供应链算法。

## 术语、角色与共同验收规则

“必须/应/不得”为适用条件成立时的规范要求，“建议”为可有依据替代，“例如/示例”为非穷尽说明。每条由其适用对象的组件实现者负责，产品维护者固定支持合同，L5 固定平台/API/工具版本，验证者留准确环境与原始结果。每条输入/输出与权威细化附于条内；本地/OS/渠道/远端各只对其管辖事实确认，日志字段不认证真实权限或效果。

继承所引用的 [L3 通用工程规范 v0.1.0](../../L3/001-通用工程规范--v0.1.0.md) 的工程与证据接口，不由此推定正式采用。

所有适用条款的前置为支持组合、准确运行构建、相关账号/资源/操作身份及必要预算已可定位。并发或异步状态绑定实例、账号/工作区、文档/场景和操作代际；互不相关对象允许并行。超时/断连/取消请求不是效果未发生；有界重试及恢复应先核未知结果，已确认未提交或无副作用路径可按合同重试。时钟、预算和兼容版本由采用合同固定，不从统一毫秒阈值或 latest 页面推断。完成以条内目标与判据回读，正常/直接失败/合法邻例共同验证。

## 一、定位与适用判断

本基线属于分类第 07 领域，管理运行在用户桌面会话或其配套本地进程中的软件：操作系统集成、本地权限与数据、安装与更新、兼容与性能、平台签名及故障诊断。它既适用于原生应用，也适用于跨平台框架或 WebView 宿主；“跨平台”不等于必须支持 Windows、macOS、Linux 三者，更不等于同一制品、同一权限模型或全部功能完全相同。

L6 应先固定产品声明的操作系统及版本区间、CPU/ABI、发行渠道、安装范围、桌面会话/显示系统、必要硬件、运行时及支持期限。未声明的平台不得计为失败，也不得宣传为受支持。仅有实验原型时执行与其风险相称的检查，不要求选择与产品无关的发行渠道或后台服务；已有用户承诺的必要能力不得因工具或 CI 成本被省略。

规范性强度遵循本节术语；仅对满足条款适用条件的项目激活。不适用需说明对象不存在或不在支持合同内，不能把未测试标成不适用。

## 三、领域状态模型与不可混淆的证据

应用身份至少区分产品/渠道、包标识、发布者、制品摘要、安装实例、当前运行构建、本地数据格式、用户/工作区及可选后台组件。一个产品版本可有多平台包，后台服务也可能与前台不同版本；这不是允许混用的理由。

发行链路可表达为：取得候选 → 完整性/身份/适用性验证 → 暂存 → 安装或替换 → 首次启动 → 数据迁移（如需）→ 功能健康确认。每个转换保留失败或未知结果，不能把“下载完”“安装器退出 0”“进程存在”“版本标签已变”直接提升为用户任务成功。无自动更新的应用可通过批准的人工安装流程完成这些检查，不要求实现完整更新状态机。

本地保存至少区分修改中、正在写入、已满足项目持久承诺、失败及结果未知；退出/崩溃恢复按真实存储契约回读。跨设备同步、云端提交或外部付款不是“已保存到本机”的同义词。

## 四、共性机制与项目验收契约

### D01 支持矩阵和功能能力差异
**适用：** 每个拟交付桌面产品。应以平台×架构×渠道×最低/关键版本×必要能力形成可审查矩阵，记录原生或兼容层运行、受限功能及退役条件。运行时能力检查不能只依据 OS 名称推断。**证据：** 每个声明组合的真实产物、启动及核心任务结果；抽样须有风险依据和未覆盖说明。**失败：** 未满足必要能力时明确不支持或安全降级，不静默执行替代业务。单平台产品是合法邻例。

**输入、输出与权威补充：** 产品维护者输入支持声明/实际产物，输出平台能力矩阵；真实 OS/运行时能力和用户任务结果为权威。

**正例：** 仅声明的单平台核心任务可完整通过。

**具体目标入口与完成判据：** systeminfo、sw_vers 或 uname 与真实目标包启动/任务；核矩阵每项与实际证据。 以本条机制、失败处理及案例表的预期为通过条件；同时对照正常/直接失败/合法邻例，超时或未知不得标已确认。

**来源边界：** [DM23](../../../sources/desktop-mobile-claims.md#dm23)；仅采用各来源所列有限事实，动作/身份栅栏、恢复和案例为组织合成契约。

### D02 进程边界与本地信任关系
**适用：** 存在 UI、后台服务、渲染器、插件、升级器或辅助进程。应标明谁接收不可信文件/网页、谁可访问秘密、谁能写用户数据或提升权限；绘制实际 IPC 和持久化边界。**证据：** 进程/身份/权限图与实际运行权限一致，任一低信任组件不能获得通用任意命令代理。**失败：** 非必要能力拒绝并保留可诊断错误；允许简单单进程，但不能以单进程为理由信任任意输入。

**输入、输出与权威补充：** 架构者输入进程树/端点/权限，输出信任图；实际 OS 令牌、ACL/沙箱和接收端授权决定边界。

**正例：** 低信任解析进程仅能调用限定读取代理。

**具体目标入口与完成判据：** Process Explorer/Activity Monitor/ps 加实际拒绝 IPC；核不可达资源和有权正常调用。 以本条机制、失败处理及案例表的预期为通过条件；同时对照正常/直接失败/合法邻例，超时或未知不得标已确认。

**来源边界：** [DM10](../../../sources/desktop-mobile-claims.md#dm10)、[DM11](../../../sources/desktop-mobile-claims.md#dm11)、[DM12](../../../sources/desktop-mobile-claims.md#dm12)；仅采用各来源所列有限事实，动作/身份栅栏、恢复和案例为组织合成契约。

### D03 安装范围和提权操作
**适用：** 写入机器级位置、注册服务或其他受限系统资源。应区分每用户与全机安装、安装时与运行时权限；仅为具体需要使用受约束的特权组件，不让普通任务常驻管理员/root。Windows 对象访问控制、平台沙箱和用户同意是不同机制。[DM10](../../../sources/desktop-mobile-claims.md#dm10) **证据：** 普通用户完成常规任务、拒绝提权时不破坏旧状态，特权入口校验调用者与目标。**失败：** 拒绝请求不可转成自动修改系统安全设置；确需管理工具权限的产品按明确合同实现。

**输入、输出与权威补充：** 安装/helper 实现者输入目标安装范围与受限动作，输出受控提权结果；OS 授权和目标回读而非对话框同意为权威。

**正例：** 普通用户保存文档无需管理员。

**具体目标入口与完成判据：** 普通账号运行、实际 UAC/认证拒绝及系统服务/目标前后回读。 以本条机制、失败处理及案例表的预期为通过条件；同时对照正常/直接失败/合法邻例，超时或未知不得标已确认。

**来源边界：** [DM10](../../../sources/desktop-mobile-claims.md#dm10)、[DM20](../../../sources/desktop-mobile-claims.md#dm20)；仅采用各来源所列有限事实，动作/身份栅栏、恢复和案例为组织合成契约。

### D04 资源权限、沙箱与撤销
**适用：** 文件、麦克风、摄像头、屏幕、辅助功能、通知或其他系统受控资源。应记录所需能力、请求时机、拒绝/撤销/系统策略禁止及恢复路径；应用内开关不代替 OS 权限，既往授权不保证永久有效。选择 Flatpak 时区分静态权限与 portal 的用户选择资源访问；不得默认全部 Linux 应用均受 Flatpak 沙箱。[DM14](../../../sources/desktop-mobile-claims.md#dm14)[DM14](../../../sources/desktop-mobile-claims.md#dm14) **证据：** 未授权、授权后使用、撤销后再次访问与重启逐项实测。**失败：** 核心能力缺失时说明原因与可行替代，不扩大为全盘/全总线权限来掩盖缺陷。

**输入、输出与权威补充：** 资源控制者输入有效 OS/portal 授予，输出可访问资源与失效状态；应用开关不作授权权威。

**正例：** 仅选定文件可用且拒绝权限后其他功能可用。

**具体目标入口与完成判据：** 系统隐私设置、真实选择器；Flatpak 采用者运行 flatpak info --show-permissions 并撤权重试。 以本条机制、失败处理及案例表的预期为通过条件；同时对照正常/直接失败/合法邻例，超时或未知不得标已确认。

**来源边界：** [DM14](../../../sources/desktop-mobile-claims.md#dm14)；仅采用各来源所列有限事实，动作/身份栅栏、恢复和案例为组织合成契约。

### D05 数据目录与所有权
**适用：** 具有本地持久状态。应区分用户文档、应用数据、配置、缓存、日志、临时与机器共享状态，分别定义位置、拥有者、备份/漫游与清理策略。Windows Known Folders 可重定向；XDG Base Directory 0.8 将数据、配置、状态、缓存与运行期对象分开，运行目录不能承载重启后必留的文档。[DM01](../../../sources/desktop-mobile-claims.md#dm01)[DM02](../../../sources/desktop-mobile-claims.md#dm02) **证据：** 非默认用户目录、只读安装位置、目录不可写和多个 OS 用户对照。**失败：** 不回退到共享可写安装目录、不把缓存清理等同删除用户作品；便携模式可存在，但需显式目录与权限合同。

**输入、输出与权威补充：** 存储者输入 OS 解析目录与对象类别，输出有所有权的存储/清理映射；实际目录而非硬编码 HOME 为权威。

**正例：** 重定向目录仍保存到实际文档位置。

**具体目标入口与完成判据：** SHGetKnownFolderPath/系统目录 API 或 XDG 环境解析，读实际目标并核第二用户隔离。 以本条机制、失败处理及案例表的预期为通过条件；同时对照正常/直接失败/合法邻例，超时或未知不得标已确认。

**来源边界：** [DM01](../../../sources/desktop-mobile-claims.md#dm01)、[DM02](../../../sources/desktop-mobile-claims.md#dm02)；仅采用各来源所列有限事实，动作/身份栅栏、恢复和案例为组织合成契约。

### D06 文件对象、路径与外部输入
**适用：** 打开/导入/导出/解包/拖放文件。应验证真实文件类型、大小、编码及资源上限；路径校验覆盖目录穿越、符号链接/重解析、替换竞态、大小写及 Unicode 差异，不以字符串前缀证明目标仍在授权目录内。应在使用对象时验证允许的目标与权限，按 L5 选择句柄或平台支持的安全打开机制。FileChooser 的过滤器只帮助选择，不保证文件匹配。[DM14](../../../sources/desktop-mobile-claims.md#dm14) **证据：** 同名异类型、链接跳转、合法非 ASCII 与大文件对照。**失败：** 拒绝越界或损坏输入且不覆盖原文件，合法用户所选目录按合同处理。

**输入、输出与权威补充：** 文件入口输入用户所选定位符/内容，输出验证后的有权对象；最终打开句柄和内容版本决定实际目标。

**正例：** 合法中文空格文件可导入而不扩大目录权。

**具体目标入口与完成判据：** 真实 Open/Import/Share 入口送截断/越界链接及合法样本，核文件与权限前后。 以本条机制、失败处理及案例表的预期为通过条件；同时对照正常/直接失败/合法邻例，超时或未知不得标已确认。

**来源边界：** [DM03](../../../sources/desktop-mobile-claims.md#dm03)、[DM14](../../../sources/desktop-mobile-claims.md#dm14)；仅采用各来源所列有限事实，动作/身份栅栏、恢复和案例为组织合成契约。

### D07 文档保存与持久承诺
**适用：** 编辑文档或更新关键配置。应定义覆盖、另存、冲突、取消及用户可见的保存确认点；临时文件替换和文件同步须按实际文件系统/介质契约实现，原子命名变化不能被宣传为所有故障下持久。数据库模式继承 WAL 专题，不手工复制/删除活跃日志。[DM04](../../../sources/desktop-mobile-claims.md#dm04)[DM09](../../../sources/desktop-mobile-claims.md#dm09) **证据：** 写满、拒绝访问、写中断、重启回读及旧/新内容校验。**失败：** 保存失败保留可恢复草稿或原件并明确未完成，不返回假成功。

**输入、输出与权威补充：** 保存者输入编辑快照/代次和目标，输出该代次持久结果；引擎提交/同步契约及回读为权威。

**正例：** 确认最新代次后再次重开内容相同。

**具体目标入口与完成判据：** 实际保存入口注入短写/同步失败，按目标文件系统回读；fsync/FlushFileBuffers 返回分列。 以本条机制、失败处理及案例表的预期为通过条件；同时对照正常/直接失败/合法邻例，超时或未知不得标已确认。

**来源边界：** [DM04](../../../sources/desktop-mobile-claims.md#dm04)、[DM05](../../../sources/desktop-mobile-claims.md#dm05)；仅采用各来源所列有限事实，动作/身份栅栏、恢复和案例为组织合成契约。

### D08 并发实例与文件冲突
**适用：** 多窗口、多进程、多个版本、外部编辑器或同步盘可能同时写同一对象。应选择单写者、版本条件更新、引擎事务或可验证锁，并定义锁持有者崩溃、陈旧锁和用户冲突解决。不得仅按 PID 文件存在永久拒绝，也不得无条件删除他人有效锁。**证据：** 两写者交错、崩溃后恢复及外部变更对照；不同文档可并行。**失败：** 拒绝危险覆盖或保存独立冲突副本，不无声后写覆盖。

**输入、输出与权威补充：** 写者协调者输入对象版本/锁，输出有序提交或冲突；真实排他原语/条件事务非 PID 文件存在为权威。

**正例：** 独立文档并行，相同对象冲突可选副本。

**具体目标入口与完成判据：** 两个真实应用进程交错保存，检查最终内容/锁持有者与冲突 UI。 以本条机制、失败处理及案例表的预期为通过条件；同时对照正常/直接失败/合法邻例，超时或未知不得标已确认。

**来源边界：** [DM08](../../../sources/desktop-mobile-claims.md#dm08)；仅采用各来源所列有限事实，动作/身份栅栏、恢复和案例为组织合成契约。

### D09 本地迁移、导出与恢复
**适用：** 升级持久数据格式、账号/工作区转换或提供备份。应绑定数据格式与可读写版本，迁移前确认可恢复输入，按事务或可恢复阶段推进，支持重启识别已做/未做/未知步骤。仅回滚程序不能承诺回滚数据。**证据：** 旧数据升级、中断重入、失败回读、导出再导入及实际恢复对照。**失败：** 新数据不能被旧版误写；按合同只读、前向修复或恢复可信副本，不能清空数据“修复”。引擎备份细节继承数据库规范。

**输入、输出与权威补充：** 迁移者输入格式兼容表/恢复来源，输出可恢复阶段及数据；实际字段/引用/读写结果为权威。

**正例：** 旧格式迁移重入后只转换一次且新编辑保留。

## 六、验收入口与实际采用

项目应复用已有测试/发行系统记录以下证据，不另建竞争台账：

1. **静态与构建层：** 固定源码/依赖/最终包摘要、声明矩阵、清单/权限/桥面/更新配置审查；它们只证明相应结构。
2. **目标系统层：** 从实际分发物完成安装、首启、权限拒绝/撤销、Shell 激活、保存/重开、辅助技术、设备/资源异常；每项对应实际 OS build 和架构。
3. **发行演进层：** 至少覆盖项目支持窗口内有风险的新旧组合、迁移中断、更新失败及恢复，记录更新前后程序和数据身份；不是要求任意历史版本两两全测。
4. **用户结果层：** 已批准的关键用户任务、合法差异、失败恢复、必要外部确认与数据完整性；渠道/商店后台成功不替代终端证据。
5. **不能自动证明的条件：** 实际设备体验、辅助技术、平台签名信任、用户权利与支持承诺由真实授权主体及实验确认；缺失列为待补证。
