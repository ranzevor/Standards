# L4 安装制品、平台信任与分发技术规范

**文档ID：** STD-L4-DESKTOP-002　**版本：** 0.1.0　**状态：** adopted　**生效日期：** 2026-10-30

## 一、目标、适用与非目标

把最终分发字节、目标系统信任与已安装对象绑定，避免把签名成功、安装器退出或开发机可启动误当用户安装成功。

**适用对象：** 安装范围/包身份，平台签名与公证，依赖、安装/修复/卸载和渠道实际制品。 按产品真实存在的能力逐条激活；单平台、离线或无账号不因本专题新增功能。

**非目标：** 不重订密码学、SBOM 或证明算法；不要求所有产品进商店或使用系统安装器；平台信任不等于业务授权。

## 二、术语、强度与角色

“必须/应/不得”表示适用条件成立时的规范要求；“建议”允许有依据替代；“例如/示例”为说明，不构成新增平台、功能或统一阈值。引用厂商指南仅在采用其机制时适用，本规范综合定义的要求在来源记录中单独标明。条款 ID 在后续版本保留。

产品维护者固定支持与任务合同；L5 适配者固定 OS/SDK/框架/工具版本与真实 API；组件实现者对输入验证、状态迁移和释放负责；验证者保存准确制品、环境、前后状态与原始观察。OS/渠道记录只对其管辖状态有权威，业务结果由相应本地持久层或受权远端确认，UI 标签和日志字段本身不认证结果。

前置输入为已声明支持画像、最终构建/组件身份、相关账号/窗口/文档或操作身份、数据格式/权限与必要预算。输出为各条产物、状态和完成/失败/未知记录。实例、账号、文档与操作代际分开；状态至少区分未接纳、已接纳/排队、执行、已确认、拒绝/失败、取消请求/确认和结果未知，仅按真实对象采用。

并发和超时预算由采用方预先固定，说明时钟与睡眠语义；超时、断连或请求取消不等于效果未发生。已知未提交/无副作用路径可按合同重试；可能已提交者先回读权威结果，无法核实时保留未知。恢复不得跨账号或把旧异步回复作用于新代际。兼容以声明矩阵及双方能力/数据合同为准，不由 latest 页面或展示版本自动改变。

## 三、稳定条款与验收契约

### DT5-01 包与安装对象身份

**角色/前置/必要动作：** 发行维护者必须将源码构建、平台/CPU、渠道、包标识/发布者、最终字节摘要、安装范围及组件映射。安装前确认目标适配和依赖，安装后回读实际包/文件/组件版本；展示版本字符串不能替代摘要或 OS 包身份。便携包同样说明可执行、数据目录和清理对象。

**并发、超时、未知与恢复：** 同名渠道、并排版本和相同展示版本不同字节不得静默混用；未知安装结果保留原件和系统记录后核对，不重新覆盖用户数据。

**产物、真实目标入口与判据：** Windows Get-AppxPackage 或安装器 inventory；macOS pkgutil --pkg-info 与包内 Info.plist/代码身份；Linux 所选包管理器查询或自有便携 manifest。判据为最终包→安装对象→运行映像链完整且无未登记 helper。

**正例：** 稳定 x64 包的安装对象与构建清单匹配。 **直接失败反例：** 只看 About 1.0 就接受来自预览渠道的另一字节包，失败。 **合法邻例：** 同版本多平台包分别登记合法。

**来源有限命题：** [DM20](../../../sources/desktop-mobile-claims.md#dm20)、[DM21](../../../sources/desktop-mobile-claims.md#dm21)；来源仅支持其记录的事实，组合状态机、身份栅栏与验收结果为本规范组织合成要求。

### DT5-02 消费系统信任与签后完整性

**角色/前置/必要动作：** 使用签名的发行物必须核最终消费对象、发布者策略、信任链、时间戳、适用撤销/到期和嵌套代码。MSIX 包签名需设备信任；macOS 外部分发的 Gatekeeper 评估、公证与 App Store 审核/沙箱分别记录。归档、压缩、安装后的正常转换须保留身份映射，不把所有对象要求同一摘要。

**并发、超时、未知与恢复：** 签后修改、错误发布者、系统策略拒绝须准确拒收；不得把关闭 Gatekeeper、扩大信任根或绕过安全策略作为正常通过条件。网络信任检查不可用时按渠道政策保留未知/受限，不猜测有效。

**产物、真实目标入口与判据：** Windows 对最终 MSIX 用 signtool verify /pa /v；macOS codesign --verify --strict --verbose=2 及 spctl --assess --type execute --verbose=4；相应 installer 用平台适用评估类型。正常策略干净目标首次启动并配错身份/篡改反例，判据为真实消费结果而非仅签名工具 0。

**正例：** 正常策略验证和目标首次核心任务均有分列证据。 **直接失败反例：** 公证通过后重新改包仍宣称原公证覆盖，失败。 **合法邻例：** 获准内部开发包可按其隔离路径验收，不冒称公开分发资格。

**来源有限命题：** [DM20](../../../sources/desktop-mobile-claims.md#dm20)、[DM21](../../../sources/desktop-mobile-claims.md#dm21)；来源仅支持其记录的事实，组合状态机、身份栅栏与验收结果为本规范组织合成要求。

### DT5-03 范围、依赖和最小权限

**角色/前置/必要动作：** 安装者必须区分用户安装、机器安装、运行权限和管理策略，列明服务、驱动、运行时及共享依赖的所有者/使用者。普通使用不得因安装时提权而永久常驻高权。必要外部依赖取得来源、版本和失败路径由供应链合同约束。

**并发、超时、未知与恢复：** 提权被拒、缺运行时/CPU 或设备管理禁止时，在修改关键数据前拒绝或提供已验证替代；不可偷偷下载未批准执行物或更改 ACL 掩盖错误。共享依赖不能因卸载本产品删除其他消费者仍需对象。

**产物、真实目标入口与判据：** 在声明的干净 OS/架构以普通账号安装和运行，拒绝 UAC/认证对话框并查看系统服务/依赖 inventory。Windows 可用 dumpbin /headers /dependents 结合实际加载，macOS otool -L，Linux readelf -d；判据为依赖和有效权限与清单相符。

**正例：** 用户目录安装无需全机写权即可完成常规任务。 **直接失败反例：** 缺库时自动执行用户可写目录同名 DLL，失败。 **合法邻例：** 真实系统管理工具可有明确限定提权入口。

**来源有限命题：** [DM20](../../../sources/desktop-mobile-claims.md#dm20)、[DM23](../../../sources/desktop-mobile-claims.md#dm23)；来源仅支持其记录的事实，组合状态机、身份栅栏与验收结果为本规范组织合成要求。

### DT5-04 安装事务、占用与恢复

**角色/前置/必要动作：** 安装协议必须定义已下载、已验证、暂存、系统提交、重启待定、安装完成及首次健康确认。优先使用选定平台支持的安装事务，外部自定义动作另列补偿与幂等边界；包管理器原子性不能外推自定义脚本。安装中不得让未验证半包取代可用版本。

**并发、超时、未知与恢复：** 并行安装/更新须协调同一目标；文件占用、磁盘不足、拒绝权限和中断后以 OS inventory/文件及日志核对已变对象。超时不等于未安装；可恢复阶段继续或受控回退，不盲重跑不可逆动作。

**产物、真实目标入口与判据：** 在隔离目标以真实发行安装器执行新装、占用中安装、提交前后中断、重启待定再继续；Windows 保存 msiexec /L*v 日志（仅 MSI）、macOS Installer 日志、Linux 包管理器事务日志。判据为可启动版本与组件集合一致、数据保持、恢复不会重复动作。

**正例：** 中断后系统修复完成登记且原用户文档完整。 **直接失败反例：** 自定义动作已建服务却重复执行生成第二服务，失败。 **合法邻例：** 免安装包可用安全目录切换，不必包装 MSI。

**来源有限命题：** [DM20](../../../sources/desktop-mobile-claims.md#dm20)；来源仅支持其记录的事实，组合状态机、身份栅栏与验收结果为本规范组织合成要求。

### DT5-05 首启与修复不等于数据重置

**角色/前置/必要动作：** 首启验证者必须回读运行映像/组件身份，完成最小用户任务及必要数据访问，区分安装健康、应用健康、账号和数据兼容。修复仅恢复本应用拥有的代码/配置可重建项，用户作品、密钥与迁移由 P2 契约处理。修复更新或渠道切换不自动授权丢弃新数据。

**并发、超时、未知与恢复：** 首启崩溃、秘密库不可用和迁移未知须保留精确阶段；有界重试，必要时隔离扩展或受限启动。程序回退必须消费 P2 读写兼容结果，不因修复菜单被点击而清空配置/作品。

**产物、真实目标入口与判据：** 从最终渠道安装后普通用户首启、打开合成旧数据、保存重开；注入缺失依赖/损坏可丢缓存再 Repair，比较数据和权限前后。判据为运行构建正确、任务真实可用、修复范围可审计而非安装器退出 0。

**正例：** 重装自有可执行后原草稿能继续编辑。 **直接失败反例：** Repair 删除唯一数据库后空界面启动成功，失败。 **合法邻例：** 无用户状态工具可简化数据复验。

**来源有限命题：** [DM20](../../../sources/desktop-mobile-claims.md#dm20)、[DM21](../../../sources/desktop-mobile-claims.md#dm21)；来源仅支持其记录的事实，组合状态机、身份栅栏与验收结果为本规范组织合成要求。

### DT5-06 卸载、关联接管与残留

**角色/前置/必要动作：** 卸载者必须按所有权列出代码、服务、登录项、注册、缓存、用户数据和共享组件的去向。删除前核当前目标仍属本安装实例，尊重他方接管和用户保留/导出合同；代码卸载与业务账号删除分开。

**并发、超时、未知与恢复：** 卸载中断、组件仍运行和权限拒绝分别保留状态；必要重启后核残留，不因一条 Remove 返回成功声称清理全部完成。未知唯一恢复副本不能自动作为垃圾删除。

**产物、真实目标入口与判据：** 用真实卸载入口/所选包管理器执行，重启后检查进程/服务/登录项/关联/已知目录；先让另一应用接管关联再卸载。判据为自有代码按合同移除、他方对象和用户数据无误删，残留有可解释原因。

**正例：** 移除本应用登录项并保留用户作品。 **直接失败反例：** 卸载删除已被另一软件接管的 handler，失败。 **合法邻例：** 用户明确选择且有权删除自有数据时可按合同删除。

**来源有限命题：** [DM15](../../../sources/desktop-mobile-claims.md#dm15)、[DM20](../../../sources/desktop-mobile-claims.md#dm20)；来源仅支持其记录的事实，组合状态机、身份栅栏与验收结果为本规范组织合成要求。

### DT5-07 渠道转换、证据和兼容门禁

**角色/前置/必要动作：** 渠道维护者必须标明原始包、渠道加工/重签后包、设备取得物和实际安装物的映射；每个支持组合用其真实制品验证。静态签名/容器构建、干净 VM 和必要硬件/管理策略证据分层，不能用开发机已信任环境外推正常终端。

**并发、超时、未知与恢复：** 渠道资格、政策或签名格式变化需复验受影响组合；旧回执仅绑定其原字节。下载入口已可见但终端尚失败时保持失败/未知，不改成可发行。

**产物、真实目标入口与判据：** 核渠道实际下载物摘要、系统包详情及正常策略安装/启动；带架构/OS/渠道/工具版本、正反例与首启数据记录。判据为端到端身份链可核且每项承诺有对应证据。

**正例：** 商店加工后包有明确映射且目标安装任务通过。 **直接失败反例：** 使用本地开发证书成功替代正式渠道信任验收，失败。 **合法邻例：** 只选一个合法渠道的产品按该渠道完整验收即可。

**来源有限命题：** [DM20](../../../sources/desktop-mobile-claims.md#dm20)、[DM21](../../../sources/desktop-mobile-claims.md#dm21)、[DM23](../../../sources/desktop-mobile-claims.md#dm23)；来源仅支持其记录的事实，组合状态机、身份栅栏与验收结果为本规范组织合成要求。

## 四、采用与证据边界

目标验收入口中的产品名/包标识、文件和设备由 L6 替换为其准确对象，不把示例工具命令的退出 0 单独当作核心任务完成。仅在获准隔离目标使用故障/篡改样本；正常输入、直接失败和合法邻例必须成对观察。静态、合成、目标 OS、真实硬件/辅助技术/自然调度各层分别留证。

离线合成示例若另有运行记录，仅证明其显式有限假设，不替代这些入口。
