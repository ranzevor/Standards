# L4 后台调度、检查点与可恢复操作技术规范

**文档ID：** STD-L4-MOBILE-002　**版本：** 0.1.0　**状态：** adopted　**生效日期：** 2026-10-30

## 一、目标、适用与非目标

把系统执行机会与业务操作结果分离，使到期、重入、进程死亡和前后台交接不导致假完成或重复效果。

**适用对象：** 可延后/即时/用户可见任务，系统作业身份、操作账、检查点、约束、到期与自然调度证据。 按产品真实存在的能力逐条激活；单平台、离线或无账号不因本专题新增功能。

**非目标：** 不保证后台固定时刻必达；不强制 WorkManager/BGTask 用于全部工作；不新增无实际需求的持续后台能力。

## 二、术语、强度与角色

“必须/应/不得”表示适用条件成立时的规范要求；“建议”允许有依据替代；“例如/示例”为说明，不构成新增平台、功能或统一阈值。引用厂商指南仅在采用其机制时适用，本规范综合定义的要求在来源记录中单独标明。条款 ID 在后续版本保留。

产品维护者固定支持与任务合同；L5 适配者固定 OS/SDK/框架/工具版本与真实 API；组件实现者对输入验证、状态迁移和释放负责；验证者保存准确制品、环境、前后状态与原始观察。OS/渠道记录只对其管辖状态有权威，业务结果由相应本地持久层或受权远端确认，UI 标签和日志字段本身不认证结果。

前置输入为已声明支持画像、最终构建/组件身份、相关账号/窗口/文档或操作身份、数据格式/权限与必要预算。输出为各条产物、状态和完成/失败/未知记录。实例、账号、文档与操作代际分开；状态至少区分未接纳、已接纳/排队、执行、已确认、拒绝/失败、取消请求/确认和结果未知，仅按真实对象采用。

并发和超时预算由采用方预先固定，说明时钟与睡眠语义；超时、断连或请求取消不等于效果未发生。已知未提交/无副作用路径可按合同重试；可能已提交者先回读权威结果，无法核实时保留未知。恢复不得跨账号或把旧异步回复作用于新代际。兼容以声明矩阵及双方能力/数据合同为准，不由 latest 页面或展示版本自动改变。

## 三、稳定条款与验收契约

### MB2-01 任务类型与平台执行机会

**角色/前置/必要动作：** 任务设计者必须按即时性、可延后性、可中断、外部效果、资源和用户可见性选择所选 OS 合法机制。系统调度接受、实际启动、获得执行机会和业务完成分别记账；内存线程不充当跨进程死亡的持久任务。采用方锁具体 SDK/API/target 与有效配置，不从历史演讲推导当前统一时限。

**并发、超时、未知与恢复：** 不符合调度条件或系统未授予执行时保持待办/受限状态；不借虚假音频/VoIP、忙循环或无必要 wake lock 绕限制。工作确不需跨进程存活可使用生命周期内异步任务。

**产物、真实目标入口与判据：** Android 核实际 WorkManager/JobScheduler/前台服务类型及 dumpsys jobscheduler；iOS 核所选 target capability、任务 identifier 和实际 handler 轨迹。判据为用户需求与机制一致，enqueue/submit 成功未直接显示完成。

**正例：** 可延后同步排队后显示待执行，实际回执后才完成。 **直接失败反例：** 提交 BGTask 请求即提示文件已上传，失败。 **合法邻例：** 随页面关闭可安全丢弃的预览无需耐久后台作业。

**来源有限命题：** [DM29](../../../sources/desktop-mobile-claims.md#dm29)、[DM30](../../../sources/desktop-mobile-claims.md#dm30)；来源仅支持其记录的事实，组合状态机、身份栅栏与验收结果为本规范组织合成要求。

### MB2-02 作业 ID 与业务操作身份

**角色/前置/必要动作：** 执行者必须区分系统 job/work request ID、每次运行 attempt、业务 operation ID、账号/对象和不可变参数。重启、重新入队或系统重复运行保持原业务身份；调度器 unique 名称不独立保证跨设备/后端效果恰好一次。敏感操作身份在相应持久事务后才确认为排队。

**并发、超时、未知与恢复：** 新作业承接旧操作必须核已完成/在途/未知阶段；未能核旧尝试结果时不以新 attempt 未执行作为旧效果不存在证据。参数变化形成明确新意图，不重用原去重 key 偷换内容。

**产物、真实目标入口与判据：** 目标 App 重复调度同一业务操作、杀进程重建任务，再核本地 operation 记录和隔离服务效果次数。判据为一次业务身份稳定、每次 attempt 可追，未知不盲重放；独立新操作仍可工作。

**正例：** 重启后新 job 继续同 operation ID 并取得原回执。 **直接失败反例：** 每次重排 job 都生成新支付 ID，失败。 **合法邻例：** 只读刷新可按其无副作用合同重新查询。

**来源有限命题：** [DM29](../../../sources/desktop-mobile-claims.md#dm29)、[DM30](../../../sources/desktop-mobile-claims.md#dm30)；来源仅支持其记录的事实，组合状态机、身份栅栏与验收结果为本规范组织合成要求。

### MB2-03 耐久检查点与并发执行权

**角色/前置/必要动作：** 任务实现者必须用所选引擎事务或可恢复阶段绑定检查点、输入/输出身份及提交结果；进度百分比不作权威。前台、后台、扩展等可能同时处理时，以真实跨执行者互斥/条件事务或等效协议决定执行权；内存布尔和串行队列不是耐久锁。

**并发、超时、未知与恢复：** 进程死亡或条件变化时可识别已完成/未完成/未知步骤；租约到期若不能阻止旧执行者继续产生效果，不能仅凭新租约宣布安全。关键提交需目标可执行的栅栏或原操作幂等/核对，检查点不能先记完成再写数据。

**产物、真实目标入口与判据：** 在真实持久引擎运行两个执行入口，暂停旧 worker 后启动新 worker，在转换前后终止并恢复。观察事务、写者身份和实际效果；判据为旧 writer 不越栅栏、阶段与数据一致，不只看租约字段已更新。

**正例：** 同一原子事务保存输出与完成检查点。 **直接失败反例：** 进度先 100% 后写入中断，重启跳过缺失数据，失败。 **合法邻例：** 原子引擎事务已覆盖全部对象时无需自建日志。

**来源有限命题：** [DM29](../../../sources/desktop-mobile-claims.md#dm29)；来源仅支持其记录的事实，组合状态机、身份栅栏与验收结果为本规范组织合成要求。

### MB2-04 到期、取消与完成回报

**角色/前置/必要动作：** 处理器必须将运行窗口到期、系统取消、用户取消请求、应用已停止可控工作和业务效果结果分开。收到到期/取消时停止接纳新敏感步骤，安全收敛并保留检查点；按所选 API 要求回报完成/失败，完成回调与取消回调的竞争由受同步的单一终态收敛。

**并发、超时、未知与恢复：** 到期时远端可能已提交，不能标未发生或承诺回滚。重复 completion 不产生重复业务；取消后晚到成功回执仍应归原操作核对，不能发给新账号。系统强行回收前不保证完成所有清理，关键记录应尽早持久。

**产物、真实目标入口与判据：** 用目标版本支持的 WorkManager 测试入口/系统任务诊断或 Xcode 官方文档提供的 BGTask 调试启动/到期入口；并触发实际前后台。判据为资源释放、一次 API 终态回报及诚实业务状态，调试结果只覆盖该触发路径。

**正例：** 到期保存检查点并报告本次未完成，原远端结果继续核对。 **直接失败反例：** 到期 handler 仍无限运行或直接标业务成功，失败。 **合法邻例：** 系统仍授予机会且任务已完成可正常回报成功。

**来源有限命题：** [DM30](../../../sources/desktop-mobile-claims.md#dm30)、[DM29](../../../sources/desktop-mobile-claims.md#dm29)；来源仅支持其记录的事实，组合状态机、身份栅栏与验收结果为本规范组织合成要求。

### MB2-05 约束、权限与身份重验

**角色/前置/必要动作：** 任务开始和关键受保护动作前必须重验当前账号/租户、权限、资源能力、锁屏密钥可用性和必要网络/电源条件。调度时满足条件不是执行时授权；OS 网络 connected 也非服务可达。备份恢复的旧作业不继承新设备全部权限。

**并发、超时、未知与恢复：** 账号退出、权限撤销、密钥暂不可用或网络不足时按原身份延期/隔离/取消确认；不能改用当前账号令牌或降级明文。无关本地任务不应被不需的网络/充电条件永久阻断。

**产物、真实目标入口与判据：** 让任务排队后换账号、撤权、锁屏或断服务，再通过真实调度入口执行；读实际 OS 授权、应用账和服务结果。判据为没有越权采集/串写，合法重新获权后可继续，条件/拒绝原因可见。

**正例：** A 作业在 B 会话运行时隔离待 A 重新授权。 **直接失败反例：** 排队时允许相机就后台永久采集，失败。 **合法邻例：** 不涉及秘密的本地维护无需虚构解锁依赖。

**来源有限命题：** [DM29](../../../sources/desktop-mobile-claims.md#dm29)、[DM30](../../../sources/desktop-mobile-claims.md#dm30)、[DM31](../../../sources/desktop-mobile-claims.md#dm31)、[DM34](../../../sources/desktop-mobile-claims.md#dm34)；来源仅支持其记录的事实，组合状态机、身份栅栏与验收结果为本规范组织合成要求。

### MB2-06 重试预算、前台接续与可见状态

**角色/前置/必要动作：** 任务必须定义重试分类、退避、总量/时间预算和前台查看/继续/取消入口；权限错误和参数错误不能无限退避。前台接续消费同一检查点/操作身份，后台仍活跃时须协调，UI 不以“重试”创建未知效果的新意图。

**并发、超时、未知与恢复：** 超过预算或自然长期未调度保留真实未完成，不报成功或偷偷改为常驻任务。可安全继续的工作可由用户前台触发；缺可靠防重/结果查询的已提交操作保持未知，等待受权核对。

**产物、真实目标入口与判据：** 目标任务在断网/恢复、前后台交替及预算耗尽条件运行，核 attempt 计数、队列、资源与 UI；判据为有界重试、身份不变和可行接续。合法独立任务不被全局失败锁死。

**正例：** 可重试下载退避后前台继续，已确认块不重传破坏文件。 **直接失败反例：** 401 无限重试并持续唤醒设备，失败。 **合法邻例：** 无后台承诺的在线专用操作可明确前台重试。

**来源有限命题：** [DM29](../../../sources/desktop-mobile-claims.md#dm29)、[DM30](../../../sources/desktop-mobile-claims.md#dm30)；来源仅支持其记录的事实，组合状态机、身份栅栏与验收结果为本规范组织合成要求。

### MB2-07 自然调度与测试触发分层

**角色/前置/必要动作：** 验证者必须分别记录静态配置、测试 handler、系统强制触发和真实自然调度；每项绑定最终包、设备、OS、有效设置和条件窗口。测试强行启动只能证明启动/到期处理逻辑，不能宣称自然准点或强停后必达。

**并发、超时、未知与恢复：** 自然观察窗口中未启动应保持未观察/不满足条件，不能伪造已完成；与产品合同不符须分析机制选择或恢复路径。新 SDK、OS、任务类型、账号和功耗设置变化按风险重验。

**产物、真实目标入口与判据：** Android 用 dumpsys jobscheduler 与目标 WorkManager 日志对应自然运行；iOS 用 Xcode/设备日志观察实际后台机会，并另列官方调试启动/到期试验。判据为每条结论准确限定证据层级，操作结果另由权威确认。

**正例：** 调试触发通过，报告自然调度仍待设备观察。 **直接失败反例：** 强制 run 一次后承诺每 15 分钟必达，失败。 **合法邻例：** 仅前台任务不需要自然后台调度观测。

**来源有限命题：** [DM29](../../../sources/desktop-mobile-claims.md#dm29)、[DM30](../../../sources/desktop-mobile-claims.md#dm30)；来源仅支持其记录的事实，组合状态机、身份栅栏与验收结果为本规范组织合成要求。

## 四、采用与证据边界

目标验收入口中的产品名/包标识、文件和设备由 L6 替换为其准确对象，不把示例工具命令的退出 0 单独当作核心任务完成。仅在获准隔离目标使用故障/篡改样本；正常输入、直接失败和合法邻例必须成对观察。静态、合成、目标 OS、真实硬件/辅助技术/自然调度各层分别留证。

离线合成示例若另有运行记录，仅证明其显式有限假设，不替代这些入口。
