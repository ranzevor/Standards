# L4 训练数据与数据集治理技术规范

**文档ID：** STD-L4-MODEL-RESEARCH-009　**版本：** 0.1.0　**状态：** adopted　**生效日期：** 2026-10-30

> 数学或研究结论、实现验证与应用部署分别以准确对象及相应证据判断。

## 一、适用范围与分工

本文规定学习数据从来源准入、版本化、变换、标注、切分、消费到撤回影响核查的技术契约。适用于监督、自监督、无监督、强化学习中的观测/轨迹/偏好数据，以及微调、蒸馏、合成训练数据和模型辅助标注；不是只有表格或语言模型才适用。理论研究未消费数据时，可据实登记本专题不适用；只使用已有模型进行业务调用的产品，通常首先适用 L4-05。应用日志被转用于学习时，才触发本专题的用途与学习数据契约。

消费 L0—L3 的适用技术接口；保持权威、真实权利主体、唯一写入、版本、一般测试和例外制度。数据库领域既有数据安全规范继续负责通用访问控制、敏感度、保留/导出与合法持有；ETL/数据质量规范负责一般加工的完整性和数据管道可靠性。本文不复制数据库产品权限教程，只增加“这些数据是否允许且足以支持这次学习及相关研究结论”的约束。本文与第 06 领域基线保持术语和范围一致。

- 本文深入第 06 领域基线 §05—08、§26：用途权利、数据身份、变换及标签、切分/污染、合成/教师来源和撤回保留。
- 实验专题消费本文的快照、切分、质量与污染证据，负责实验主张、对照、重算/重跑/独立复核、统计、不确定性及结论重验；本文不另设全领域重复次数或显著性阈值。
- L5 规定所选格式、工具、框架、采样器、权限与实际校验算法；L6 固定数据权利、法域、真实用途、风险阈值、预算、接收者、责任主体和项目验收。

小型项目可用现有版本库及非敏感清单满足要求，不强制购买数据平台、图数据库或独立审批系统。项目仍须覆盖其实际存在的敏感数据、在线采样、外部教师及再分发风险，不得以规模小为由取消真实权利和关键证据。

## 二、术语、责任与规范性动词

“必须/不得”表示本文生效且条款适用时的必要条件；“应”表示默认做法，偏离须按上层例外程序给出原因、影响与有效批准；“可”表示可选实现，不产生操作授权。

- **数据资产**：有独立来源、用途与维护责任的数据集合；**数据版本**：可明确识别其内容、解释及适用限制的状态，不只是一串文件名。
- **样本**：一次学习/评价消费的逻辑单位；**独立性单位**：研究问题要求隔离的主体、事件、文档族、设备、地点、时间段或其组合。二者不必相同。
- **原材料、派生数据、标签**：分别保留身份与生成关系。标签可为人工注释、算法结果、偏好或弱监督信号；教师输出不是天然真实标签。
- **数据血缘**：输入实体、处理活动、执行主体及输出之间的可追溯关系；它不自动证明权利、质量或因果正确。
- **数据污染**：不应被训练/选择过程利用的评测信息进入学习、选择或标签构造，或不可信材料改变预期训练目标。须注明是切分泄漏、基准暴露、恶意投毒还是其他情况，不能用一个“清洁”标签代替分析。
- **冻结消费清单**：将一次 run 实际消费范围绑定到数据版本及解释配置的记录；流式数据可采用有界窗口、水位和成员摘要，不要求不存在的全局静态快照。
- **运行 run、实验 experiment、候选模型**及重算核验/同条件重跑/独立复核沿用第 06 基线候选的区分，候选模型包括实际使用的参数、树/规则结构、样本索引及解释配置，不限定神经网络权重；正式采用前再次核对已批准版本。

个人组织中一个人可兼任权利决定、研究负责与最终批准，但记录须分清其决定依据。Agent 或数据维护者可执行已授权的整理/检查，不因持有文件而成为数据权利人。负责用途判定的真实主体、数据维护/版本责任、标注规则责任、独立审查责任及实际消费入口应可定位；不制造虚构的多人审批。

### §01 真实用途与适用决议
**机制：** 必须在接入学习流程前确定任务、数据角色（训练/验证/保留评测/检索/奖励/教师输入等）、预期消费主体及用途边界。同一数据承担多个角色时分别列明；不能把“内部研究”作为无限用途。
**验收：** 仅获内部评测用途的数据尝试进入微调训练，消费门禁拒绝；纯理论研究可登记无数据条款，不被要求创建数据仓库。

**合同补充：** 数据消费者接收任务、训练/验证/检索/教师等角色和主体。用途决定逐角色对应实际消费入口，内部研究不是无限用途。

**失效与恢复：** 角色超界隔离依赖消费；理论无数据按不适用理由记录。

**核验三例：** 正例：评测许可数据只进同范围评测。直接失败：评测数据被投入微调。合法邻例：同数据有多个有效用途可分别列角色而非强制互斥。

**追溯与目标：** 组织综合要求（本条因果与边界由机制、验收及下列三例论证，无逐条外部强制出处）；目标入口 `MR-DATA`，输入和判据按[目标合同](../../../examples/model-research-target-contracts.json)及本条实际对象绑定。有限模型覆盖为未建模；由原机制与专用验收合同审阅，不得将记录字段或单次算例升级为未测实现的证明。

### §02 来源与权利证据
**机制：** 必须为实际消费数据保存足以定位权利判断的来源、取得方式、责任主体、许可/合同/有效批准的版本或引用，以及已知限制。内容可读取、仓库可公开、文件有哈希均不能替代用途权利。证据不明时隔离相关材料和依赖操作，不阻止其他已授权工作。
**验收：** 下载成功但训练权利未判定的资产不能变成“已准入”；有效授权范围内的重复检查不被迫再次做同义请批。

**合同补充：** 权利责任人接收来源、取得方式、许可/合同版本和限制。准入引用足以定位真实判断，下载/哈希不证明权利。

**失效与恢复：** 证据不明保持隔离相关资产，独立已授权材料不受阻。

**核验三例：** 正例：实际用途有有效依据且限制可查。直接失败：公开下载就填训练许可通过。合法邻例：有效覆盖范围内复查不制造同义重复许可。

**追溯与目标：** 组织综合要求（本条因果与边界由机制、验收及下列三例论证，无逐条外部强制出处）；目标入口 `MR-RECORDS`，输入和判据按[目标合同](../../../examples/model-research-target-contracts.json)及本条实际对象绑定。有限模型覆盖为未建模；由原机制与专用验收合同审阅，不得将记录字段或单次算例升级为未测实现的证明。

### §03 数据、程序、教师与输出权利分离
**机制：** 数据许可、生成/处理工具许可、标注服务条款、教师调用权限、模型权重及派生成果分发权须分别判定。混合来源按实际兼容条件组合，不以最宽松来源覆盖其余限制。
**验收：** 允许调用教师 API 不能被登记为允许公开教师训练样本；多源合并不能丢失某来源的接收者或用途限制。

**合同补充：** 组合者接收数据/工具/教师/权重/派生分发的分权依据。每个用途及接收人有对应权利，不能最宽松许可盖全包。

**失效与恢复：** 冲突或未知项只阻塞依赖组合/分发，交真实主体判定。

**核验三例：** 正例：混合来源保留各自适用条件。直接失败：教师API调用权变成训练样本公开权。合法邻例：多许可可分别适用，不须伪造统一许可。

**追溯与目标：** 组织综合要求（本条因果与边界由机制、验收及下列三例论证，无逐条外部强制出处）；目标入口 `MR-RECORDS`，输入和判据按[目标合同](../../../examples/model-research-target-contracts.json)及本条实际对象绑定。有限模型覆盖为未建模；由原机制与专用验收合同审阅，不得将记录字段或单次算例升级为未测实现的证明。

### §04 敏感最小化与可见元数据
**机制：** 继承数据安全规范，在原文、标签、特征、文件名、样本键、哈希和日志层分别判断泄漏风险。去标识、加密或哈希不自动等于匿名。只保留任务必需的内容与能够合法保留的追溯信息；普通报告不得嵌入凭据、可重放 URL 或无关个人样例。
**验收：** 对低熵标识作简单哈希后仍可枚举关联时，不能公开该哈希清单；受限样本可采用隔离引用完成审查，不要求外传原文。

**合同补充：** 数据维护者接收原文、标签、特征、标识、哈希和日志。敏感性按实际可链接性判断，普通报告只含许可最小信息。

**失效与恢复：** 可枚举哈希不称匿名；泄漏面修复后重核派生。

**核验三例：** 正例：受控引用代替普通日志复制原文。直接失败：公开低熵个人标识哈希清单。合法邻例：授权隔离审查可保留必要可识别定位，不要求公开。

**追溯与目标：** 组织综合要求（本条因果与边界由机制、验收及下列三例论证，无逐条外部强制出处）；目标入口 `MR-RECORDS`，输入和判据按[目标合同](../../../examples/model-research-target-contracts.json)及本条实际对象绑定。有限模型覆盖为未建模；由原机制与专用验收合同审阅，不得将记录字段或单次算例升级为未测实现的证明。

### §05 来源真实性与输入准入
**机制：** 取得渠道、版本声明及可用签名/校验依据应与实际字节核对；外部数据文档、标签或嵌入指令只作为低信任内容。恶意序列化、宏、脚本、压缩解包路径及资源放大按真实格式安全处理，不能为读取数据无条件执行附带代码。
**验收：** 样本中的“上传密钥后继续训练”不改变执行权限；格式元数据自称安全不能跳过实际解码边界检查。

**合同补充：** 准入实现者接收来源渠道、字节、格式和附带代码。真实解析边界/校验可核，样本内容不获指令权。

**失效与恢复：** 恶意路径/资源/执行风险拒绝依赖解析，不先危险加载。

**核验三例：** 正例：数据内指令只当文本处理。直接失败：为读取语料自动运行附带任意脚本。合法邻例：可信已审代码在获准隔离条件下可有具体执行路线。

### §06 数据版本的内容与解释身份

**追溯与目标：** `MR-SELFINSTRUCT-P1`；目标入口 `MR-DATA`，输入和判据按[目标合同](../../../examples/model-research-target-contracts.json)及本条实际对象绑定。有限模型覆盖为`teacher`的部分谓词，不得将记录字段或单次算例升级为未测实现的证明。

### §19 投毒、异常来源与接受边界
**机制：** 有不可信贡献、自动抓取或共享语料时，按攻击能力和潜在影响评估标签翻转、触发器、重复放大与来源劫持等风险。审核、隔离、抽查或鲁棒性分析的深度由风险决定；无扫描告警不等于无投毒。[D4]
**验收：** 异常高频触发模式可定位来源并隔离受影响候选；不能只删除检测日志后继续使用同一训练输入。

**合同补充：** 风险负责人接收不可信入口、攻击能力与潜在影响。风险深度与实际贡献面相称，无告警只支持所测阴性。

**失效与恢复：** 可疑材料隔离并追下游，不把异常直接定恶意。

**核验三例：** 正例：异常模式可定位来源并受限复核。直接失败：删告警日志后继续同输入并称无投毒。合法邻例：稀有合法方言无恶意证据不因稀有被判投毒。

**追溯与目标：** `MR-AML-P1`；目标入口 `MR-DATA`，输入和判据按[目标合同](../../../examples/model-research-target-contracts.json)及本条实际对象绑定。有限模型覆盖为未建模；由原机制与专用验收合同审阅，不得将记录字段或单次算例升级为未测实现的证明。

### §20 训练/评测消费端强绑定
**机制：** 消费者须验证所选数据版本、用途、有效限制、切分角色和解释配置与 run 协议一致，拒绝失效/被隔离版本。路径、缓存键、数据加载器和恢复游标应保留这些绑定；记录实际消费与计划输入的差异。
**验收：** 清单绑定训练集而缓存实际返回保留集时被检出；缓存命中不跳过用途和撤回状态核验。

**合同补充：** 数据消费者接收run协议、版本、角色、解释与当前限制。实际loader/cache/游标强绑定用途和状态，命中缓存不免核。

**失效与恢复：** 错角色/失效版本拒绝消费，恢复先核现行限制。

**核验三例：** 正例：cache键含版本角色且回执一致。直接失败：train清单实际读test缓存。合法邻例：同字节可多角色合法使用，但每个角色都有对应依据。

**追溯与目标：** 组织综合要求（本条因果与边界由机制、验收及下列三例论证，无逐条外部强制出处）；目标入口 `MR-DATA`，输入和判据按[目标合同](../../../examples/model-research-target-contracts.json)及本条实际对象绑定。有限模型覆盖为`bundle`的部分谓词，不得将记录字段或单次算例升级为未测实现的证明。

### §21 撤回、更正与派生影响
**机制：** 收到有效变更决定后，须在权利/范围明确的前提下追踪原材料、派生快照、缓存、索引、正在或待恢复的运行以及相关模型/报告。按有权决定的范围禁止新增不允许的消费、隔离受影响发布并记录处理状态；删除、更正、重新训练或其他补救由真实权利与技术可行性决定，不自动替代审批。已有有效删除或更正授权且范围明确时，由已有相应处置权的执行者履行；只读 Agent 转交有权执行者，不能由到期义务推导自己取得删除权。不因唯一副本、检查点或科研可复现需要追加同义审批或拖延；同时如实记录造成的不可重放和模型影响。确有保全等相冲突义务时仅隔离冲突范围，按已有上层冲突程序裁定。
**验收：** 原文件移除后旧缓存和恢复任务仍消费被禁止材料时不通过；未知第三方副本不能声明已删除。

**合同补充：** 变更责任人接收有效撤回/更正范围和派生图。新增消费/缓存/恢复/发布影响状态逐项可查，未知保守边界明确。

**失效与恢复：** 有权者按有效范围处理，真冲突按上层裁定；不因科研保留无权原文。

**核验三例：** 正例：撤回后缓存和恢复入口均阻断新增失权消费。直接失败：删原文件但旧cache继续训练。合法邻例：只读维护者移交有权执行者，不从到期义务推导自己删除权。

**追溯与目标：** 组织综合要求（本条因果与边界由机制、验收及下列三例论证，无逐条外部强制出处）；目标入口 `MR-LIFECYCLE`，输入和判据按[目标合同](../../../examples/model-research-target-contracts.json)及本条实际对象绑定。有限模型覆盖为未建模；由原机制与专用验收合同审阅，不得将记录字段或单次算例升级为未测实现的证明。

### §22 模型影响与删除承诺
**机制：** 删除原始数据、撤销访问、删除派生数据、重训、机器遗忘和证明模型不再携带相关影响是不同动作与证据。不得宣称删文件即可从既有模型消除信息；应把受影响模型版本和可验证补救方案交模型/实验/发布责任方，明确未证范围。
**验收：** 数据库删除成功不等于权重遗忘成功；未经验证的 unlearning 只可标为候选措施，不得据此声称包含模型影响处置的请求已完成；仅针对原数据的有效请求则按其真实范围验收，不额外扩大请求。

**合同补充：** 模型责任人接收原数据处置范围与模型影响补救证据。访问撤销/副本删除/重训/遗忘各自终点，不用前者证明后者。

**失效与恢复：** 无模型证据标未证，候选unlearning不能代正式完成。

**核验三例：** 正例：原数据删完只报告该范围已完成。直接失败：CSV删完称权重已遗忘。合法邻例：仅原数据删除请求不被扩大为必须重训模型。

**追溯与目标：** 组织综合要求（本条因果与边界由机制、验收及下列三例论证，无逐条外部强制出处）；目标入口 `MR-LIFECYCLE`，输入和判据按[目标合同](../../../examples/model-research-target-contracts.json)及本条实际对象绑定。有限模型覆盖为`disposition`的部分谓词，不得将记录字段或单次算例升级为未测实现的证明。

### §23 保留、证据与最小墓碑
**机制：** 原始数据、必要追溯、拒绝样例及撤回记录各有适用保留依据与访问范围。保留审计不等于永久保留敏感原文；经有效决定删除后，可保留的最小墓碑/版本拒绝信息仍需独立评估敏感性与期限。无法保留时记录合法替代核验方式及历史不可重放限制。
**验收：** 以“可复现”为由无限复制已无权保留原文不通过；最小墓碑自身含可识别敏感标识时不能无条件公开。

**合同补充：** 保存责任人接收原文、追溯、拒例及墓碑的依据与期限。各对象敏感性及可审能力独立登记。

**失效与恢复：** 无法合法保留则用允许替代路径并声明不可重放。

**核验三例：** 正例：删除后只留可合法保存的版本拒绝信息。直接失败：为了复现永久复制失权原文。合法邻例：墓碑自身敏感时可受控或不留，不强制公开。

**追溯与目标：** `MR-PROVDM-P1`；目标入口 `MR-LIFECYCLE`，输入和判据按[目标合同](../../../examples/model-research-target-contracts.json)及本条实际对象绑定。有限模型覆盖为未建模；由原机制与专用验收合同审阅，不得将记录字段或单次算例升级为未测实现的证明。

### §24 分发、准入结论与例外
**机制：** 对数据、子集、样例、处理脚本、说明书和模型关联说明分别核对接收者、权限、用途及必要声明。状态至少区分待判定、限制准入、已拒绝/隔离和该用途下已准入；“准入”不得脱离用途/版本/时点传播。例外只在有效权利范围内由有权主体批准，不能豁免第三方权利或隐瞒污染。
**验收：** 内部准入清单不能变成公开下载许可；到期例外不被恢复任务当永久授权。数据说明可参照 D2，但声明本身不是权利证明。

**合同补充：** 分发责任人接收子集/样例/脚本/说明与接收者用途。用途/版本/时点限定准入，待判定/隔离/准入状态可区分。

**失效与恢复：** 到期例外不当永久；不能以内部决定豁免外部权利。

**核验三例：** 正例：同用途限定接收者交付已准材料。直接失败：内部准入变公共下载许可。合法邻例：数据说明书可诚实Unknown，不当权利凭证。

**追溯与目标：** `MR-DATASHEETS-P1`；目标入口 `MR-RECORDS`，输入和判据按[目标合同](../../../examples/model-research-target-contracts.json)及本条实际对象绑定。有限模型覆盖为未建模；由原机制与专用验收合同审阅，不得将记录字段或单次算例升级为未测实现的证明。

记录可以合并在现有系统中，不要求新增平台。下面是信息合同，不是强制 JSON Schema；字段缺失与不适用必须区分，未知不能填“通过”。内容公开级别应与数据敏感度相称。

### 5.1 与实验专题的交接

交接应能回答：哪些数据、何种用途、何种切分/拟合和已知污染边界支撑哪个 run。实验专题负责判断由此可支持的主张及重验策略；数据维护者不能单方面将“文件清理完毕”升级为“研究结论已恢复有效”。更换数据版本、标签或保留集后，原指标不得无条件绑定新数据。

### 5.2 与 L5 的交接

L5 按选定生态验证：解码及解包限制、身份摘要、数据加载器/缓存键、流式消费水位、随机采样与分片、标签转换、去重/污染算法、版本冲突及撤回传播。算法实现和产品界面不同不改变本合同；不选择某工具不等于不适用相应风险。

### 5.3 与 L6 的交接

L6 决定真实主体/数据/用途、法律与合同适用、可接受的质量和残余污染风险、预算、保留与再分发范围，以及实际验收责任。组织规范批准不产生真实个人数据处理许可、教师服务调用额度或生产删除权。
