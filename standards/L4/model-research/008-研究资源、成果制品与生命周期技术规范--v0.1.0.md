“必须/不得”表示适用条款的必要义务，“应”允许记录理由和有权例外，“可”不产生操作权限。实验 experiment 是逻辑研究协议，可组织多个 run；运行 run 沿用基线，指确定输入、代码、配置和环境下的一次执行，重试须有新运行标识并保留父关联。attempt/segment 用于标识实际执行尝试或恢复段，须能唯一映射对应 run 与前段，不可用聚合逻辑 ID 覆盖旧执行事实。若工具把多个重试聚合为同一平台 run，应另记规范层新 run 标识及映射；仅物理中断后按已验状态继续的恢复段可关联原 run，但仍有独立 segment/attempt 身份、原段结果及费用，不能冒充另一次独立完整运行。账务、学习连续性、数据权利三种父关系不能只用一个文件名代替。负结果是对研究问题无改善/反驳等有效结果；执行失败不是自动科学反证；未运行不是失败。证据状态不是每项研究必经的线性晋级序列。

### §01 目标与预算边界
**机制：** 研究计划绑定有权批准的目标、资源范围、期间、计量口径、可执行主体与既有控制策略。费用额度、数据用途、资源操作、外部分享分别判定；预算存在不批准获取数据、停止服务或公开模型。阈值与恢复余量由 L6 依据实际风险和计量滞后确定，不设普遍费用/次数。
**验收：** 有计算预算但无数据使用权的试验不进入执行；只读核账者不能据预算余量创建作业。

**合同补充：** 资源负责人接收目标、期间、计量口径、主体与获准控制策略。预算、数据用途、资源操作、分享各有真实决定引用。

**失效与恢复：** 有算力无数据权不执行依赖步骤；阈值由真实风险和滞后决定。

**核验三例：** 正例：目标预算与合法输入用途均覆盖。直接失败：有计算预算就获取未准数据。合法邻例：纯数学证明可只交证明依赖，无训练资源账。

**追溯与目标：** 组织综合要求（本条因果与边界由机制、验收及下列三例论证，无逐条外部强制出处）；目标入口 `MR-LEDGER`，输入和判据按[目标合同](../../../examples/model-research-target-contracts.json)及本条实际对象绑定。有限模型覆盖为未建模；由原机制与专用验收合同审阅，不得将记录字段或单次算例升级为未测实现的证明。

### §02 活跃、等待和未知账
**机制：** 每个计划项记录 experiment、run/attempt/segment 及其映射、目标父账、实际作业定位、状态事件、观察时间、证据来源及下一责任。活跃计算、排队等待、等待授权/输入、恢复核验、已终态、终态未知分别表达；研究状态与提供方资源状态并列。等待不等于不计费，断连不等于终止。事件追加或版本化更正，不覆盖失败历史。
**验收：** 命令退出但远端状态未知时，保持未决并查已有作业；不得启动副本后宣称原作业失败且零成本。

**合同补充：** 运行维护者接收experiment/run/attempt/segment与真实作业事件。研究状态和提供方资源状态并列，等待/未知不等零费用。

**失效与恢复：** 断连先查已有作业，事件追加更正不抹旧失败。

**核验三例：** 正例：恢复段单独ID关联原学习run。直接失败：断SSH即宣称作业失败零费用并双启。合法邻例：同轨迹连续恢复段可关联原run，不算独立重复。

**追溯与目标：** `MR-PROVO-P1`；目标入口 `MR-LEDGER`，输入和判据按[目标合同](../../../examples/model-research-target-contracts.json)及本条实际对象绑定。有限模型覆盖为`ledger`的部分谓词，不得将记录字段或单次算例升级为未测实现的证明。

### §03 全路径费用归集
**机制：** 按原目标累计预处理、数据取得、训练、搜索、评测/裁判、失败、恢复、存储、取回、出口及适用共享成本。保留费用记录去重键、来源更新时间、币种/单位/口径、估计或已结算状态；账单与分摊估算不双算。未知费用显式留缺口，不填零。[S1/S5]
**验收：** 同一 attempt 的用量快照与最终账单替换/对账有关系，不相加两遍；失败试验仍在总账。

**合同补充：** 计量者接收预处理、训练、搜索、评测、失败和存储明细。去重键/币种/单位/估计结算关系明确，原目标总账可核。

**失效与恢复：** 估计被账单替代而非双算；未知费用不补零。

**核验三例：** 正例：同meter的估计被最终结算值对账。直接失败：失败run与出口费用不进总成本。合法邻例：合法共享费用按声明分摊，不把整份账重复计每run。

**追溯与目标：** `MR-NEURIPS-P1`、`MR-AWSBUDGET-P1`；目标入口 `MR-LEDGER`，输入和判据按[目标合同](../../../examples/model-research-target-contracts.json)及本条实际对象绑定。有限模型覆盖为`cost`的部分谓词，不得将记录字段或单次算例升级为未测实现的证明。

### §04 预算覆盖失败与预留
**机制：** 启动/恢复前评估已发生、未入账/在途消耗和该步骤可合理约束的新增暴露，使用实际获准口径；独立预算窗口按真实批准划分但不得借更名、换设备/账号、恢复或跨日隐藏原研究累计。额度未知/不足时不新增不被覆盖的消耗，按既有有权控制处理现有作业；不得擅自停服、删数据或缩小研究目标。报告原计划未执行范围，不以较小集合冒充完整验收。
**验收：** 仪表盘只显示已入账余额、但在途足以越界时不能据旧余额放行；未获取消权的观察者转交控制责任人，不越权终止。

**合同补充：** 准入者接收已发生、滞后在途和拟新增资源暴露。按实际获准口径可判覆盖，换名/跨日不隐藏原目标累计。

**失效与恢复：** 余额旧或未知不新增未覆盖暴露；现存作业按有权策略核对。

**核验三例：** 正例：余额考虑在途估计与合理新步骤上界。直接失败：跨日新attempt清零同研究费用。合法邻例：真实独立预算窗口可分别报告，但不抹全目标累计。

**追溯与目标：** `MR-AWSBUDGET-P1`；目标入口 `MR-LEDGER`，输入和判据按[目标合同](../../../examples/model-research-target-contracts.json)及本条实际对象绑定。有限模型覆盖为`cost`的部分谓词，不得将记录字段或单次算例升级为未测实现的证明。

### §05 恢复连续性
**机制：** 恢复先核实际在途状态、唯一写入、权利/预算有效性、所需学习状态与完整性、依赖可用及当前安全限制。每个恢复段或重试记录独立实际执行身份；重试建立新 run 并关联父运行，连续恢复段按术语映射原 run，不覆盖旧段。所有 run/attempt/segment 延续目标费用账和选择账；改变算法/输入导致新 run 时仍关联研究总账。状态重建可引用并行恢复专题的等价证据；不强制不存在的优化器文件。
**验收：** 合法无状态算法可恢复；必要状态缺失则不得假称连续，重启是否获准独立判断。旧失败与新增运行均可查。

**合同补充：** 恢复者接收作业现状、唯一写入、权利预算与完整学习状态。连续段/新run及父账区别明确，选择/费用账跨恢复延续。

**失效与恢复：** 必要状态缺失不假连续；原失败和新运行均可查。

**核验三例：** 正例：完整可信切面恢复且独立segment记费用。直接失败：聚合平台run覆盖旧失败后当独立验证。合法邻例：无状态算法输入完整且等价重建可合法续作。

**追溯与目标：** 组织综合要求（本条因果与边界由机制、验收及下列三例论证，无逐条外部强制出处）；目标入口 `MR-DCP`，输入和判据按[目标合同](../../../examples/model-research-target-contracts.json)及本条实际对象绑定。有限模型覆盖为`snapshot`的部分谓词，不得将记录字段或单次算例升级为未测实现的证明。

### §06 计量可比性
**机制：** 比较资源须声明设备型号/数量或份额、软件与精度、并行策略、内存峰值定义、工作量及测量边界。墙钟、活跃时间、排队时间、累计设备时和计费时不可混称；多设备并发的累计时长不能作为单作业墙钟。不同硬件的 GPU-hour、FLOP、利用率不天然等价。估算计算量说明公式、算子覆盖和误差，实测说明采样与仪器。
**验收：** 两种设备各一小时不能直接证明同计算预算；允许按实际费用或任务条件比较，但限定主张及未匹配因素。

**合同补充：** 比较者接收设备/份额、精度、并行、工作量和仪器边界。墙钟、累计设备时、排队、计费和FLOP估算分开。

**失效与恢复：** 异设备单位不天然等价，未匹配因素限制主张。

**核验三例：** 正例：同任务同测量边界报告实际墙钟。直接失败：两型号各一GPU-hour认同计算量。合法邻例：按真实费用比较系统方案可用异构硬件但限归因。

**追溯与目标：** `MR-NEURIPS-P1`；目标入口 `MR-LEDGER`，输入和判据按[目标合同](../../../examples/model-research-target-contracts.json)及本条实际对象绑定。有限模型覆盖为未建模；由原机制与专用验收合同审阅，不得将记录字段或单次算例升级为未测实现的证明。

### §07 缓存及摊销条件
**机制：** 冷/热启动、预训练或预处理复用、共享数据缓存和公共搜索开销分别记录；同时报告本次增量与所宣称范围的总量，既不把历史全部成本重复计入每次，也不将昂贵准备当不存在。分摊方法、共享分母与不可分配项可追溯。
**验收：** 热缓存新法对冷缓存基线不称无条件加速；比较可保留为明确不同准备条件的实际系统结果。

**合同补充：** 计量者接收冷/热缓存、公共准备与本次增量。总量与增量边界及摊销分母可重建，不双算/漏算。

**失效与恢复：** 不对等准备条件不称无条件算法加速；补准备说明。

**核验三例：** 正例：共享预处理按实际分母分摊。直接失败：新法热缓存对基线冷缓存称普遍提速。合法邻例：仅研究热稳态性能可合法，但明确排除准备阶段。

### §08 选择账与负结果
**机制：** 保留候选集合、可见次序、选择/排除规则、未运行/失败/有效负结果、主张变化及资源引用。有效负结果与系统失败分开；只报告赢家不能代表研究成功率或总成本。探索无需伪造预注册，但记录当时已见信息及选择偏差，由实验专题处理推断。[S1]

**核验三例：** 正例：无改善但有效运行留作负结果。直接失败：删OOM候选只报赢家能耗。合法邻例：失败可依预定估计对象不进条件均值，但留全执行账。

### §09 最小充分组合闭包

### §10 组合兼容与派生转换

**合同补充：** 接收者接收布局/词表/适配/量化变换及误差合同。哈希相符后仍核语义兼容，派生变换形成新身份。

**失效与恢复：** 错特殊ID或超容差拒收，不能继承未转换旧分数。

**核验三例：** 正例：新量化物在预定输入/容差内核验。直接失败：Tokenizer哈希正确却语义错配仍放行。合法邻例：特定用途近似通过不等逐位同一或训练可恢复。

**追溯与目标：** `MR-PEFT-CKPT-P1`；目标入口 `MR-PEFT`，输入和判据按[目标合同](../../../examples/model-research-target-contracts.json)及本条实际对象绑定。有限模型覆盖为`bundle`的部分谓词，不得将记录字段或单次算例升级为未测实现的证明。

### §13 证据身份与可访问性

## 五、保存、撤回、清理及真实交付

### §15 按对象的保存依据
**机制：** 原件、数据派生、模型/检查点、日志、证明、报告、缓存分别登记保存目的、权利/义务、责任、期限或触发条件和访问范围。期限由真实项目决定，不虚设固定天数；需要复现不是无限保存敏感原数据的理由。最小充分审计可用获准聚合、脱敏或受控引用，明确丢失的验证能力。
**验收：** 原件到期但合法汇总仍可留时分别处置；不得把不可重跑报告伪称完整可复现，亦不为此擅自延长原件保存。

**合同补充：** 保存者接收原件/派生/模型/日志/证明的用途依据期限。逐对象期限与可保留证据明确，科研复现不是无限保留理由。

**失效与恢复：** 到期无权原件按范围处置并承认复验损失。

**核验三例：** 正例：原件到期但合法汇总另按依据留存。直接失败：无限复制敏感原件以保随时重跑。合法邻例：最小受限引用可合法支持部分审计，无须全量长期副本。

**追溯与目标：** 组织综合要求（本条因果与边界由机制、验收及下列三例论证，无逐条外部强制出处）；目标入口 `MR-LIFECYCLE`，输入和判据按[目标合同](../../../examples/model-research-target-contracts.json)及本条实际对象绑定。有限模型覆盖为`disposition`的部分谓词，不得将记录字段或单次算例升级为未测实现的证明。

### §16 撤回影响闭包
**机制：** 接收有效撤回/更正决定，按真实范围追原件、派生、缓存、模型、报告、待执行及恢复入口；数据专题负责消费隔离，本专题更新组合可用性、交付限制及保留/处置账。未知派生范围标未知并保守限制相关声明，补救由实际权利与技术证据决定；删除数据不证明模型遗忘。
**验收：** 从历史快照恢复不能重新启用当前失效数据；报告撤回不冒称所有副本与模型已被清除。

**合同补充：** 撤回责任人接收有效范围与原料/模型/报告/恢复影响图。组合可用性与消费隔离状态同步，未知范围明示。

**失效与恢复：** 删源不证明遗忘；历史快照不能复活当前失权用途。

**核验三例：** 正例：撤回后恢复入口检查当前状态。直接失败：撤报告宣称全部模型副本清除。合法邻例：无关组件证据可复用，限制按真实影响不无限扩大。

**追溯与目标：** `MR-PROVDM-P1`；目标入口 `MR-LIFECYCLE`，输入和判据按[目标合同](../../../examples/model-research-target-contracts.json)及本条实际对象绑定。有限模型覆盖为`disposition`的部分谓词，不得将记录字段或单次算例升级为未测实现的证明。

### §17 清理前依赖与处置权

**合同补充：** 处置者接收对象身份、依据、引用/在途写入和执行权限。依赖检查不制造无限留存，真实有权者承担具体处置。

**失效与恢复：** 无权不删；有效删除/到期义务依原范围执行，冲突仅隔离冲突项。

**核验三例：** 正例：合法删除唯一点并记不能恢复。直接失败：闲置扫描命中就删唯一有效checkpoint。合法邻例：只读者移交已有有权主体，不由义务自动扩权。

### §18 清理过程与实际终态
**机制：** 清单/试算只表示拟处置；实际执行按对象身份和获准范围、版本条件防止竞态误删，区分归档、隐藏、断引用、删除请求、主副本处理和真实完成。保留有权保留的处置回执、失败和未决，不把 HTTP 接受或路径消失当所有备份/复制清除；不得承诺无法观察的删除。底层重试与云退役引用既有规范。
**验收：** 删除请求成功但复制副本未确认时标部分完成；资源释放与账单尾项分别追踪，不擅自解除保护绕过拒绝。

**合同补充：** 处置实现者接收身份/版本条件、主副本和回执语义。试算/请求接受/实际完成分别记录，资源释放与账尾项分开。

**失效与恢复：** 竞态版本不符拒绝，副本未知保持部分完成而非全已删。

**核验三例：** 正例：请求接受但副本待确认准确标部分。直接失败：路径消失就认所有备份已清除。合法邻例：归档/隐藏若是原定目标可完成该目标，不冒永久删除。

### §19 恢复先核当前权利
**机制：** 恢复已归档或清理后的研究前，核实际可恢复材料、当前用途/撤回、兼容组合、预算及执行主体；备份不是绕过已生效删除的入口。可从合法冻结输入重建者给等价证明；唯一材料依法删除后承认不可恢复，提出需另行有权决定的替代，不伪造旧运行连续性。
**验收：** 旧快照字节校验通过但包含已禁用派生数据时不消费；缺失可重建配置但合法重建已验证不误判不可恢复。

**合同补充：** 恢复者接收可恢复材料、当前用途/撤回、组合和预算。备份字节可读仍须当前权利，重建等价与原轨迹分开。

**失效与恢复：** 失权数据不复活；唯一合法材料已删则承认不可恢复。

**核验三例：** 正例：合法冻结输入可重建配置且核等价。直接失败：从备份恢复已撤回样本继续消费。合法邻例：可验证重建缺配置可恢复，不因缺原文件一律拒绝。

**追溯与目标：** 组织综合要求（本条因果与边界由机制、验收及下列三例论证，无逐条外部强制出处）；目标入口 `MR-LIFECYCLE`，输入和判据按[目标合同](../../../examples/model-research-target-contracts.json)及本条实际对象绑定。有限模型覆盖为`admission`的部分谓词，不得将记录字段或单次算例升级为未测实现的证明。

### §20 成果交接与接收回执
**机制：** 正式交付按接收者目的给组合清单、实际可取路径、权利限制、必要环境/命令、已执行验证及限制、维护/撤回联系和恢复边界；既有可靠系统可引用，不造重复台账。接收者在获准环境实际核身份及所承诺的访问/加载/复核范围，无运行权限时仅记录静态接收，不自行启动付费训练。
**验收：** 文件已上传但受权接收者无法访问不称完成交接；受限审阅已完成可交付相应范围，不强迫公开全部数据。

**合同补充：** 交付者接收接收人目的、组合、可取路径和实际验证范围。接收者实际核访问及约定加载/复核，上传不等交接。

**失效与恢复：** 只作者可取视缺交付，修路径不扩受众；无运行权不启动作业。

**核验三例：** 正例：受限审查者取到准确包并静态核身份。直接失败：上传成功就称用户已接收。合法邻例：静态接收可完成静态合同，不强迫公开数据或训练。

**追溯与目标：** `MR-SLSA-P1`；目标入口 `MR-RECORDS`，输入和判据按[目标合同](../../../examples/model-research-target-contracts.json)及本条实际对象绑定。有限模型覆盖为未建模；由原机制与专用验收合同审阅，不得将记录字段或单次算例升级为未测实现的证明。

### §21 正式交付与真实部署分离
**机制：** 分别登记规范批准、源码/制品生成、完整交付、研究验证、渠道发布、模型消费集成、真实环境部署及实际应用验收。每个状态绑定对象、环境、时间、执行者和证据；渠道发布另核有效发布授权、实际渠道/命名空间及受众、固定制品身份、渠道可取证据与适用许可声明。发布申请/上传接受不等于实际渠道可取；私密交付或部署不证明已公开发布，也不产生扩大受众的权限。离线分数/静态 CI 不证明真实服务使用此组合。部署与业务验证按应用/云规则及实际授权，不以研究交付触发生产操作。
**验收：** 制品接收通过而运行环境仍用旧 tokenizer 时，交付可完成但该组合部署未证实；有权目标环境读回版本和行为证据才支持相应部署声明。渠道指向旧制品或仅作者可取时不能称目标受众发布成功；无需公开的研究可保持私密交付、渠道公开发布不适用。

**合同补充：** 发布者接收交付/研究/渠道/部署/应用的独立状态。实际渠道可取与目标环境消费身份支持各自声明。

**失效与恢复：** 上传接受/旧渠道不算新包发布，旧Tokenizer环境不算新组合部署。

**核验三例：** 正例：交付完成但部署仍未验分别记。直接失败：CI绿写生产已部署或渠道新版本可取。合法邻例：私密交付无公开目标可保持公开不适用，不扩大受众。

**追溯与目标：** `MR-SLSA-P1`；目标入口 `MR-RECORDS`，输入和判据按[目标合同](../../../examples/model-research-target-contracts.json)及本条实际对象绑定。有限模型覆盖为`delivery`的部分谓词，不得将记录字段或单次算例升级为未测实现的证明。

### §22 闭环及变化再审
**机制：** 交接和清理后的未决费用、未知作业终态、撤回传播、缺件和受限复核均保留责任及可观察完成条件；无需为本规范设置永久后台服务。正文变更、实际来源或接口变化按影响重审，独立审查与人类批准绑定确定版本；未获批准不更正式 registry 或生效状态。
**验收：** 账务尚未结算可明确“成果已交付、费用未决”；静态检查结果与真实训练、清理或部署结果分别记录。

**合同补充：** 维护者接收费用、作业未知、撤回传播和缺件未决。每个未决有责任及可观察终点，证据层保持独立。

**失效与恢复：** 未结费用不填结算；变更重审准确对象，不以自检写生效。

**核验三例：** 正例：成果已交付且费用待权威账单分别标。直接失败：来源变化后自检绿直接标规范生效。合法邻例：无需永久后台服务，可用现有系统完成有边界闭环。

**追溯与目标：** 组织综合要求（本条因果与边界由机制、验收及下列三例论证，无逐条外部强制出处）；目标入口 `MR-LIFECYCLE`，输入和判据按[目标合同](../../../examples/model-research-target-contracts.json)及本条实际对象绑定。有限模型覆盖为未建模；由原机制与专用验收合同审阅，不得将记录字段或单次算例升级为未测实现的证明。

## 七、最小实施与独立审查

可使用普通版本化文件或现有实验平台，不强制专用平台。最小对象为：目标/预算引用、run/attempt 状态事件及实际作业映射、费用明细及对账、选择/负结果账、组合 manifest、来源转换链、保留与处置记录、分层交付回执。敏感字段和权限证据留在既有受控位置，公共清单只含获准引用。

L5 核查实际计量单位、去重/并发、组合加载、摘要范围、恢复和删除回执语义；L6 明确目标、阈值、费用与具体操作权、保存依据、接收者和验收。不得为了满足静态条文重跑昂贵训练或执行清理。独立技术审查应同时检查合法正例与复合失效、依赖版本、原件/解析边界及最小化；作者自检不冒充独立审查。规范修订及采用按 L1 确定的权限与流程登记。
