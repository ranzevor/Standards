# L4 列式格式、分析表与湖仓快照技术规范

**文档ID：** STD-L4-DATABASE-007　**版本：** 0.1.0　**状态：** adopted　**生效日期：** 2026-10-30

## 一、技术范围与相邻规范

本规范是 L4「数据库与数据工程」第 12 项独立技术专题，仅对实际使用 Parquet/ORC、Arrow 内存及 IPC、Iceberg/Delta/Hudi 分析表协议的项目适用相应机制。只有普通数据库、小规模单文件或无湖仓需求的项目，不被强制增加计算集群、Catalog 或云存储支出。

相应数据库领域基线及第 1—11 项分别管理数据模型/Schema、SQL、事务/MVCC、索引、WAL、分片、HA、DDL、备份/PITR、ETL/ELT、CDC/水位；后端消息规范处理业务事件和外部副作用。本专题仅深入列式物理布局、文件元数据、Arrow Buffer/IPC、分析表事务、Manifest/Snapshot、行级 Delete 和历史可达性。第 13 项元数据与血缘、第 14 项数据安全与保留仍有独立专题。L5 决定具体 Reader/Writer/Catalog，L6 决定客户数据授权、成本及真实业务验收。

### 机制组 5：Iceberg Snapshot、Manifest 与行删除

### §25 Snapshot 原子发布
**机制：** 先生成 Data、Manifest 和元数据，只有 Catalog 原子指针提交成功才表示新的正式快照可见。

**验收：** 失败提交不出现半数文件可见

**核验合同与来源：** [lake-R04](#lake-R04)；本条对应的失败输入见下文验证矩阵。

### §26 Manifest 可达文件集合
**机制：** 对已采用的 Iceberg v1—v3，Snapshot 引用 Manifest List，Manifest Entry 决定该快照有效 Data/Delete 文件及其序列关系，不能直接列对象目录作为表内容。v4 开发稿引入 root manifest 等变化，必须隔离到其明确实验协议，不能把 v1—v3 文件树直接当作完整 v4 解析器。

**验收：** 固定 snapshot-id 后枚举实际格式引用闭包，核对新增、删除、孤儿与未提交文件；孤儿不能成为表行，仍被历史 Snapshot/Branch/Tag 引用者不得当孤儿删除。未知/草案版本由不支持读写器明确拒绝，而合法 v1/v2/v3 小型本地表不要求云 Catalog。

**核验合同与来源：** [lake-R04](#lake-R04)；本条对应的失败输入见下文验证矩阵。

### §27 Sequence Number 与删除年龄
**机制：** 区分 Snapshot ID、Data Sequence、File Sequence 与对象 mtime；重写 Manifest 不改变 Delete 适用年龄规则。

**验收：** Delete 对旧新数据的适用范围稳定

**核验合同与来源：** [lake-R04](#lake-R04)；本条对应的失败输入见下文验证矩阵。

### §28 长查询快照固定
**机制：** 同一分析查询锁定唯一 Snapshot 和相应 Data/Delete 集合，不能在读取中途拼接新旧提交。

**验收：** 并发 Commit 下单次查询仍具有一致读集

**核验合同与来源：** [lake-R04](#lake-R04)；本条对应的失败输入见下文验证矩阵。

### §29 并发 Writer 冲突重试
**机制：** Iceberg Optimistic Commit 使用实际 Catalog 原子比较与隔离条件，冲突后的 Retry 必须重新验证覆盖范围。

**验收：** 重试合法，冲突不造成部分写入或丢行

**核验合同与来源：** [lake-R05](#lake-R05)；本条对应的失败输入见下文验证矩阵。

### §30 v2/v3/v4 删除兼容
**机制：** Iceberg v2 的 Position/Equality Deletes、v3 的 Deletion Vector/Row Lineage 与开发稿 v4 分别按规范和实际读写器能力门禁。v3 新 Writer 不新增 position-delete 文件，但历史文件仍需读；同一数据文件的 DV 按规范合并成适用的单一有效集合。开发稿 v4 不新增 Equality Delete，不能由此忽略既有历史 Equality Delete，也不能据草案宣称正式部署已兼容。

**验收：** 在固定 Snapshot 中交错历史删除、重写、序列号和同一文件多份候选 DV，核对实际可见业务键集合；不支持的版本/特性拒绝写入且不发布新快照。开发稿实验成功不提升正式实现状态，旧合法删除仍生效。

**核验合同与来源：** [lake-R05](#lake-R05)；本条对应的失败输入见下文验证矩阵。

## 五、版本批准及 L5/L6 执行验收

1. 本版有 48 项连续编号的独立机制、60 项静态失败场景；前八组逐项直接关联，后两组覆盖跨格式及业务复合故障。
