# L4 数据安全、访问控制、保留与导出技术规范

**文档ID：** STD-L4-DATABASE-011　**版本：** 0.1.0　**状态：** adopted　**生效日期：** 2026-10-30

## 一、适用范围与已有技术职责

本 L4 数据库与数据工程第 14 项仅针对实际数据权利、敏感信息、行列级授权、保留、访问请求或导出的具体项目启用。普通非敏感数据项目可采用更轻量的既有能力，不默认要求额外服务或采购。相应 L1—L3 治理、L4 后端身份/业务安全及数据库第 1—13 项的实际 Schema、事务、PITR、CDC、湖仓与元数据规则继续适用，本规范只对数据的合法来源、最小化、细粒度读取、跨副本保留/删除和外部导出形成独立技术门禁。L5 负责实际产品能力与密钥/权限测试，L6 负责适用法律、合同、生产结果和唯一真实责任主体的审批。

## 三、48 项数据安全技术机制

### 机制组 1：来源权利与数据最小化

### §01 适用条件
**机制：** 依据真实数据处理目的、项目规模和所在法域激活必要条款，不因采用 SQL 强制部署新安全 SaaS。

**验收：** 对不涉及敏感数据的最小项目，允许使用既有访问与清理能力，不以购买独立治理产品作为通用门禁。

**核验合同与来源：** [security-R01](#security-R01)；本条对应的失败输入见下文验证矩阵。

### §02 数据敏感度
**机制：** 字段、记录、业务日志和元数据分别分级，保护可能揭示个人或商业机密的信息。

**验收：** 对字段、记录、日志、目录及衍生数据进行分类抽查；税号列定为敏感后，低权查询和导出无法得到原文。

**核验合同与来源：** [security-R01](#security-R01)；本条对应的失败输入见下文验证矩阵。

### §03 来源授权
**机制：** 记录采集来源、业务目的、数据主体授权及必要的合同约束，其他用途需独立判定。

**验收：** 核对数据来源、处理目的、实际合法依据和转用记录；客服数据未经有效授权改用于营销时阻断。

**核验合同与来源：** [security-R01](#security-R01)；本条对应的失败输入见下文验证矩阵。

### §04 字段最小化
**机制：** 检索、处理、计算、缓存和对外文件仅使用合法目的必需字段与范围。

**验收：** 只申请城市的请求不得从查询、缓存、导出临时文件得到姓名、门牌地址及身份字段。

**核验合同与来源：** [security-R01](#security-R01)；本条对应的失败输入见下文验证矩阵。

### §05 处理者和接收方
**机制：** 原始权利人、处理者、第三方服务、Agent 及真实客户责任边界可追踪。

**验收：** 按控制者、处理者、接收人和 Agent 绘制实际访问矩阵；向未授权服务外发被拒绝并记录主体。

**核验合同与来源：** [security-R01](#security-R01)；本条对应的失败输入见下文验证矩阵。

### §06 数据主体请求身份
**机制：** 访问、更正、删除、携带请求前核验请求者身份和法定/合同范围。

**验收：** 冒充他人发起访问、更正、删除和携带请求必须拒绝且不得影响目标数据；合法请求按例外处理。

**核验合同与来源：** [security-R01](#security-R01)；本条对应的失败输入见下文验证矩阵。

### 机制组 2：角色与数据库行列权限

### §07 读写权限分离
**机制：** 读、写、Schema、备份、管理、导出分别授权，默认服务身份不具有全部权能。

**验收：** 分别以读取、写入、DDL、备份、导出和管理身份执行正反权限矩阵；默认身份不持有无关高权。

**核验合同与来源：** [security-R02](#security-R02)；本条对应的失败输入见下文验证矩阵。

### §08 GRANT/Role 继承
**机制：** 评估对象权限、角色继承、PUBLIC 和 Grant Option；表级权限不靠撤销列级权限收紧。

**验收：** 测试表级 SELECT、列级 GRANT、角色继承、PUBLIC 和 Grant Option；表级 SELECT 仍在时不能宣称撤销列权限有效。

**核验合同与来源：** [security-R02](#security-R02)；本条对应的失败输入见下文验证矩阵。

### §09 PostgreSQL RLS 旁路
**机制：** PG18 RLS 表 Owner 默认旁路、FORCE ROW LEVEL SECURITY、BYPASSRLS/超级用户永久旁路需分别验证；TRUNCATE/REFERENCES 不受 RLS 限制，row_security=off 不是绕过权限。

**验收：** 在 PG18 分别以普通角色、Owner、启用 FORCE RLS 的 Owner、BYPASSRLS 和超级用户访问；普通租户仅见授权行，TRUNCATE/REFERENCES 单独授权，row_security=off 不应作为旁路。

**核验合同与来源：** [security-R02](#security-R02)；本条对应的失败输入见下文验证矩阵。

### §10 MySQL 8.4 权限生效
**机制：** 结合真实角色、连接、Grant 和权限生效时点验证旧新会话。

**验收：** 在 MySQL8.4 以旧新连接、激活/未激活角色和变更前后会话核验 GRANT/REVOKE；撤权后仍越权即失败。

**核验合同与来源：** [security-R02](#security-R02)；本条对应的失败输入见下文验证矩阵。

### §11 BigQuery 行策略
**机制：** 查询、授权视图、列 Policy Tag、数据复制与离线结果按服务支持范围核验。

**验收：** 以 BigQuery 原表、授权视图、行策略、列 Policy Tag、复制或导出作业及不同调用身份检查行列泄漏。

**核验合同与来源：** [security-R02](#security-R02)；本条对应的失败输入见下文验证矩阵。

### §12 Mask 与读者身份
**机制：** BigQuery/Snowflake 动态 Mask 不是静态密文；各角色和导出操作需验证真实返回值。

**验收：** 对 BigQuery/Snowflake 的不同角色和高权限批处理导出同一数据；约定应遮罩的读取和对外文件不能恢复原文。

**核验合同与来源：** [security-R02](#security-R02)；本条对应的失败输入见下文验证矩阵。

### 机制组 3：传输加密与凭据生命周期

### §13 传输端点身份
**机制：** TLS、服务端身份、调用权限、实际接收方和数据用途分别核对。

**验收：** 即使 TLS 建链成功，也要验证证书/服务端、接收方、授权目的；错误目的端点必须终止发送。

**核验合同与来源：** [security-R03](#security-R03)；本条对应的失败输入见下文验证矩阵。

### §14 静态与临时副本
**机制：** 数据库、对象、缓存、导出临时文件和备份的加密覆盖应与真实访问路径对应。

**验收：** 检查数据库、缓存、备份、临时导出和分析副本的加密、访问控制与删除期限；超期明文副本即失败。

**核验合同与来源：** [security-R03](#security-R03)；本条对应的失败输入见下文验证矩阵。

### §15 密钥粒度与恢复
**机制：** 数据密钥、封装密钥和数据分别授权；轮换记录各密文/历史备份依赖的密钥版本及解密权限。对仍处合法保留/恢复义务内的数据保留可用恢复链；依法批准的加密擦除可能使历史备份不可恢复，必须按真实密钥粒度列出连带影响，不能同时承诺已销毁密钥和永久可恢复。

**验收：** 轮换后恢复仍应保留的历史备份并拒绝跨租户调用；单租户擦除不得损害共用密钥下仍应保留的其他租户数据。明确已批准不可恢复者及恢复保留者，密钥撤销与物理密文删除分别验收。

**核验合同与来源：** [security-R03](#security-R03)；本条对应的失败输入见下文验证矩阵。

### §16 匿名化和假名化
**机制：** 可逆假名化、加密、遮罩与真正匿名化分别判断，不能忽视重识别风险。

**验收：** 使用哈希邮箱和可逆伪名化数据实施关联重识别；可复识别数据不得宣称永久匿名。

**核验合同与来源：** [security-R03](#security-R03)；本条对应的失败输入见下文验证矩阵。

### §17 日志秘密最小化
**机制：** SQL、Token、Facet、链接与错误样例限收录必要字段并设置访问/期限。

**验收：** 用含 JWT、签名下载 URL、密钥及敏感 SQL 参数的正反请求检索日志；低权人员不得取得可重放秘密。

**核验合同与来源：** [security-R03](#security-R03)；本条对应的失败输入见下文验证矩阵。

### §18 JWT 委派条件
**机制：** 验证 Token Issuer/Audience、签名和有效期，业务撤权与令牌状态需关联。

**验收：** 对 JWT Issuer/Audience、算法、签名、有效期及业务撤权状态分别投递无效令牌；均须按有效策略拒绝。

**核验合同与来源：** [security-R03](#security-R03)；本条对应的失败输入见下文验证矩阵。

### 机制组 4：派生查询与租户完整性

### §19 Join 和聚合隔离
**机制：** JOIN、View、聚合、分页及索引必须维持输入源的租户/字段授权。

**验收：** 用跨租户 JOIN、View、聚合、分页和排序数据核对行、计数及金额；不允许他租数据或统计侧漏。

**核验合同与来源：** [security-R04](#security-R04)；本条对应的失败输入见下文验证矩阵。

### §20 缓存搜索派生 ACL
**机制：** 搜索、缓存、向量和物化派生结果绑定来源对象、授权版本及撤权截止时间。逐路径设定可验证的最大撤权传播延迟和超时处置；对要求即时撤权的高风险读取，在生效时检查当前授权或暂停/隔离旧缓存，不能等一个无上限水位才停止泄露。

**验收：** 撤权前后并发访问各派生路径，测试传播正常、停滞和缓存旧授权三种情况：在声明截止前可处于受控窗口，达到截止后全部拒绝或不可公开，停滞有告警和补偿。公开无账号数据集是合法邻例，但其公开范围/撤销条件仍须明确。

**核验合同与来源：** [security-R04](#security-R04)；本条对应的失败输入见下文验证矩阵。

### §21 提升权限入口
**机制：** Security Definer、数据库 Owner、存储过程和导入 Worker 应检测权限提升边界。

**验收：** 以低权身份调用 SECURITY DEFINER、Owner 存储过程和导入 Worker；不得经搜索路径或提权入口读取额外行列。

**核验合同与来源：** [security-R04](#security-R04)；本条对应的失败输入见下文验证矩阵。

### §22 第三方共享范围
**机制：** 外部接收者、数据字段、使用目的、期限与下游责任应有真实合同授权。

**验收：** 对一次报价数据尝试额外营销、外部共享和再次分发；缺乏相应授权即停止处理并记录责任主体。

**核验合同与来源：** [security-R04](#security-R04)；本条对应的失败输入见下文验证矩阵。

### §23 查询旁路风险
**机制：** 计数、异常信息、统计、响应时延和排序可能暴露受限数据集合。

**验收：** 以受限/非受限记录样本比较统计、数量、异常和排序输出；不可间接推断其他租户资料。

**核验合同与来源：** [security-R04](#security-R04)；本条对应的失败输入见下文验证矩阵。

### §24 批量访问预算
**机制：** 高资源扫描、导出、历史重放设适当授权、限额和取消条件。

**验收：** 并发触发普通账号高资源扫描和批量导出；超授权上限需取消、限额或显式业务批准并保留成本记录。

**核验合同与来源：** [security-R04](#security-R04)；本条对应的失败输入见下文验证矩阵。

### 机制组 5：保留期限与合法持有

### §25 保留依据和例外
**机制：** 期限依实际目的、法规、合同及适用例外确定，不统一强制所有数据永久保留。

**验收：** 逐类明确保留目的、期限、例外及实际责任方；无根据的全类别永久保存不得通过。

**核验合同与来源：** [security-R05](#security-R05)；本条对应的失败输入见下文验证矩阵。

### §26 保留时钟
**机制：** 记录来源事件、到期触发、法定暂停和业务有效期的准确起点。

**验收：** 以采集/合同结束时间、法定暂停和恢复时点复算有效期限；不能将备份创建时间作为来源保留起点。

**核验合同与来源：** [security-R05](#security-R05)；本条对应的失败输入见下文验证矩阵。

### §27 S3 版本删除语义
**机制：** Versioning Delete Marker 不等于删除历史版本，期限与访问须按版本核查。

**验收：** 在 S3 Versioning 对当前对象执行 DELETE 后按 Version ID 检查；Delete Marker 不等于净化历史版本。

**核验合同与来源：** [security-R05](#security-R05)；本条对应的失败输入见下文验证矩阵。

### §28 S3 锁与 Legal Hold
**机制：** S3 Object Lock 的 Governance、Compliance、每个对象版本和 Legal Hold 分开授权；Governance 可在明确旁路权限与请求条件下绕过，Compliance 到期前不得绕过。

**验收：** 按 S3 Governance、Compliance、Legal Hold 和对象版本分别核验；Governance 需明确旁路权限与请求条件，Compliance 到期前不可绕过，Legal Hold 独立有效。

**核验合同与来源：** [security-R05](#security-R05)；本条对应的失败输入见下文验证矩阵。

### §29 GCS Bucket Lock 风险
**机制：** GCS Bucket Lock 锁定保留策略后不能缩短或移除；执行前应由有权人确认数据删除需求、保留期限、费用与冲突处理。

**验收：** 在测试环境检查 GCS 保留策略锁定前责任批准及期限；锁定后缩期/撤销不得作为合法操作。

**核验合同与来源：** [security-R05](#security-R05)；本条对应的失败输入见下文验证矩阵。

### §30 争议中的删除裁决
**机制：** 法律保全和数据主体删除请求的冲突应由有权主体明确裁决并记录。

**验收：** 对同一记录同时存在删除请求与保全限制时，禁止工程人员直接解除 Hold，需有权人作范围与理由裁决。

**核验合同与来源：** [security-R05](#security-R05)；本条对应的失败输入见下文验证矩阵。

### 机制组 6：删除传播与历史恢复

### §31 删除请求分解
**机制：** 核实身份、例外和范围，将请求映射到真实记录、衍生版本与任务。

**验收：** 通过伪造他人 ID 或跨租户身份提交删除应拒绝；合法请求须映射源记录、任务、衍生副本及例外。

**核验合同与来源：** [security-R06](#security-R06)；本条对应的失败输入见下文验证矩阵。

### §32 下游传播
**机制：** CDC、ETL、搜索、日志、分析表与导出副本依授权范围传播删除限制。

**验收：** 源库删除后重放 CDC、ETL、搜索和缓存更新；有效同步水位之后不得重新发布旧数据。

**核验合同与来源：** [security-R06](#security-R06)；本条对应的失败输入见下文验证矩阵。

### §33 PITR 恢复后重处理
**机制：** 备份保留及合法恢复与在线记录删除独立，恢复时重放获准的删除约束。

**验收：** 从删除之前的 PITR 备份隔离恢复；重新开放生产读取前必须按有效删除清单重处理。

**核验合同与来源：** [security-R06](#security-R06)；本条对应的失败输入见下文验证矩阵。

### §34 湖仓历史快照
**机制：** Iceberg、Delta、Hudi 的历史 Snapshot、Tag 和旧文件访问需跟踪删除与可见性。

**验收：** 针对采用 Iceberg/Delta/Hudi 的实际 Snapshot、Tag、旧文件和历史 Reader 测试可见性、期限与删除传播。

**核验合同与来源：** [security-R06](#security-R06)；本条对应的失败输入见下文验证矩阵。

### §35 加密擦除影响范围
**机制：** 按真实 KMS/Key 粒度验证净化与其他仍需保留对象的可恢复性。

**验收：** 模拟共用 KMS Key 的多个租户与合法财务保留；删除某主体不能破坏其他仍需保留数据可恢复性。

**核验合同与来源：** [security-R06](#security-R06)；本条对应的失败输入见下文验证矩阵。

### §36 介质净化验证
**机制：** NIST SP800-88r2 的方法需结合介质、云服务保证与实际敏感程度核实。

**验收：** 对云盘、SSD、磁盘及备份选择适当介质净化证据；仅删除目录索引而数据仍可恢复不得宣称已净化。

**核验合同与来源：** [security-R06](#security-R06)；本条对应的失败输入见下文验证矩阵。

### 机制组 7：安全导出与外部传播

### §37 身份和快照锚定
**机制：** 导出用户、租户、字段、过滤条件及数据 Snapshot/时间区间都需固定。

**验收：** 导出任务需固定请求主体、租户、字段、时间窗、过滤器和快照；不能将一天筛选变为全年管理员备份。

**核验合同与来源：** [security-R07](#security-R07)；本条对应的失败输入见下文验证矩阵。

### §38 CSV 公式解释风险
**机制：** RFC4180 的 CSV 格式合法不等于表格客户端安全；须处理公式前缀及控制字符，同时确保原始文本可恢复。

**验收：** 将 =、+、-、@ 和控制字符开头文本导出 CSV，在约定表格客户端验证不执行公式并可还原文本。

**核验合同与来源：** [security-R07](#security-R07)；本条对应的失败输入见下文验证矩阵。

### §39 类型/格式合同
**机制：** 导出对 Decimal、Timestamp、Null、字符编码和 Schema 有明确一致性要求。

**验收：** 测试 Decimal、大整数、Null、Unicode、时区时间戳往返；金额及业务类型不得被浮点、编码、时区破坏。

**核验合同与来源：** [security-R07](#security-R07)；本条对应的失败输入见下文验证矩阵。

### §40 临时对象与可撤权 URL
**机制：** 已签发下载 URL、临时对象、底层存储授权与实际接收副本分别控制；业务账号撤权并不自动撤销已签发 URL，应实测签名到期或对象侧阻断。

**验收：** 撤销账号后实际重试已签发下载链接；要独立验证签名过期、存储侧阻断或对象移除，不能假设业务撤权自动撤销。

**核验合同与来源：** [security-R07](#security-R07)；本条对应的失败输入见下文验证矩阵。

### §41 法定可携带范围
**机制：** 机器可读导出只适用于实际法律和个人数据范围，不自动包含他人资料。

**验收：** 以携带请求同时包含本人、他人及商业原件作为样本；交付字段仅限于真实适用法域和权利范围。

**核验合同与来源：** [security-R07](#security-R07)；本条对应的失败输入见下文验证矩阵。

### §42 伙伴收件/再分发
**机制：** 外部交付记录接收方、目的、合同与后续限制，证明不止于本地 Token 撤销。

**验收：** 核对下游文件接收者、目的、期限和再分发合同；不得把本地令牌失效误作第三方副本删除。

**核验合同与来源：** [security-R07](#security-R07)；本条对应的失败输入见下文验证矩阵。

### 机制组 8：审计与真实项目验收

### §43 最小审计证据
**机制：** 操作主体、批准、范围与结果可查但不保存完整个人数据/Token 原文。

**验收：** 使访问、导出、撤销、拒绝与删除产生可追踪审计，但不得存储完整密钥、可重放 Token 和无关个人原文。

**核验合同与来源：** [security-R08](#security-R08)；本条对应的失败输入见下文验证矩阵。

### §44 异常批量访问
**机制：** 大量导出或敏感访问与成本限额应具适当异常发现和业务审批。

**验收：** 触发高频敏感查询、大量导出和成本异常；按项目定义阈值生成告警、拦截或业务审批证据。

**核验合同与来源：** [security-R08](#security-R08)；本条对应的失败输入见下文验证矩阵。

### §45 Schema 政策同步
**机制：** 列新增、RLS/Mask 升级、视图和派生表应随版本重新验权限。

**验收：** 模拟新增敏感列并变更 RLS/Mask、视图、缓存及派生分析表；任何遗漏保护阻断相应发布。

**核验合同与来源：** [security-R08](#security-R08)；本条对应的失败输入见下文验证矩阵。

### §46 安全事件证据与恢复
**机制：** 未授权传播后确认对象/凭据范围、独立修复与依法通知，不能只因技术恢复就宣称业务解决。

**验收：** 模拟未授权第三方已持有文件；应分别验证副本处置、凭据范围、合法通知与业务恢复，不可仅撤销链接结案。

**核验合同与来源：** [security-R08](#security-R08)；本条对应的失败输入见下文验证矩阵。

### §47 多副本保留巡检
**机制：** 只对实际存在的数据库、缓存、备份、快照和导出平台检查权限/保留一致性。

**验收：** 针对实际使用的主库、影子分析库、缓存、日志、备份、历史快照与导出对象检查权限/保留一致性。

**核验合同与来源：** [security-R08](#security-R08)；本条对应的失败输入见下文验证矩阵。

### §48 L5/L6 业务验收
**机制：** L5 执行真实产品和隔离技术核验；L6 由真正有权主体核准客户合同、数据权利、结果和费用。

**验收：** L5 需提供对应实际版本和隔离环境技术结果；L6 另行核准适用法律、合同、真实权限与业务结果。

**核验合同与来源：** [security-R08](#security-R08)；本条对应的失败输入见下文验证矩阵。

| 共用 KMS Key 引发无关数据历史恢复风险 | §15、§34、§35 | Key 粒度与合法保留协调 |
| 导出结束后历史 S3 Version 未被跟踪 | §27、§40、§42 | 历史版本和对外传播范围核验 |
| 公开目录泄漏敏感字段，审计日志又留存原始令牌 | §17、§41、§43、§48 | 元数据、审计与数据权限同时检查 |

## 五、版本与独立验收

本版本共 48 项独立机制、60 条静态失效输入，前 48 条逐一关联 §01—§48，最后 12 条检查跨系统组合问题。静态文本和 CI 不证明已实际对真实客户数据执行测试，也不授予生产导出、密钥操作、保留锁变更、资金支出或法律决定权限。

实施与业务验收按项目分别记录。

### security-R01

**条款范围：** §01、§02、§03、§04、§05、§06

**目标工具/输入：** 法域/数据类别/来源依据、处理者/接收方、请求身份输入。可读就当有权、强制所有匿名项目造同意书、冒用主体删数据

### security-R02
