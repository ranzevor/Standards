# L4 导入、ETL/ELT 与数据质量技术规范

**文档ID：** STD-L4-DATABASE-010　**版本：** 0.1.0　**状态：** adopted　**生效日期：** 2026-10-30

## 一、适用范围、来源授权与相邻技术专题

本规范属于 L4「数据库与数据工程」领域第 10 项独立技术专题，聚焦真实导入文件/API、批处理 ETL/ELT、落地与转换、错误隔离、重复/存量增量、数据质量及项目可追溯的发布验收。**以真实业务源为前提**，不强制项目部署外部 ETL 平台、数据湖、数据质量 SaaS 或额外服务器。对于单文件一次性导入，只激活其涉及的解析/授权/质量规则。

相应数据库通用基线、数据模型/Schema、SQL 方言、事务/MVCC、索引、WAL/崩溃恢复、分区分片、复制 HA、Schema 迁移及备份/PITR 各自管理其既有职责。本文主要规定**从真实源数据到合法目标数据集的批量导入、转换和质量确认**。CDC/流批时间水位、列式格式/分析表、元数据血缘与可观测性、数据安全/保留等分别由相邻专题规定，避免提前代替。L5 确认实际文件格式、引擎与工具版本；L6 决定真实数据权利、成本、客户业务口径及有效验收。

## 三、48 项导入、ETL/ELT 与数据质量技术机制

以下每项均给出可以由合法 L5/L6 项目设计的具体断言。机制编制完成不意味着已对生产数据进行实际导入或验证。

### §01 权威源及业务用途
**机制：** 每次导入首先确定合法数据源、授权方、目标业务对象与可接受的业务输出；数据存在可读文件或第三方 API 不等于其权利、真实性和使用目的获得批准。

**验收：** 项目能为每个导入对象明确原始数据所有者、合法调用身份、受影响业务以及不可擅用的字段。

**核验合同与来源：** [import-R01](#import-R01)；本条对应的失败输入见下文验证矩阵。

### §02 来源资产与权限范围
**机制：** 按来源 URI/文件/API、环境、租户、列级权限、许可、更新节奏和保留期确定输入合同；不能用一个高权限导入 Token 绕开实际数据主体授权。

**验收：** 越权文件、跨租户输入和超期数据都被拒绝或隔离，并能追溯最小权限。

**核验合同与来源：** [import-R01](#import-R01)；本条对应的失败输入见下文验证矩阵。

### §03 不可变原件与来源指纹
**机制：** 获准保留原始输入时记录文件版本、长度、哈希、格式、编码、采集时间与任务批次 ID；对于无法合法保留的敏感数据，至少保留受控指纹及必要证明。

**验收：** 来源重传、相同文件不同内容以及证据缺失可被区分，而不公开隐私原件。

**核验合同与来源：** [import-R01](#import-R01)；本条对应的失败输入见下文验证矩阵。

### §04 完整范围、截止与交付契约
**机制：** 明确预期文件/页/分区清单、业务日期区间、抽取截止、水位、上下游依赖及是否允许部分交付；收到某批文件不代表源系统已经交齐全量数据。

**验收：** 缺一页、迟到一天、缺交易末行和上游空结果会产生可诊断的未完成状态。

**核验合同与来源：** [import-R01](#import-R01)；本条对应的失败输入见下文验证矩阵。

### §05 CSV 方言、引号及字符编码
**机制：** CSV 分隔符、引用、嵌入换行、转义、Header/BOM、换行符与字符编码应按来源约定而非盲猜；RFC 4180 为 Informational，厂商 CSV 方言并非统一 ISO SQL 语法。

**验收：** 包含引号、逗号、CR/LF、BOM、嵌套文本的测试输入无合法字段错位。

**核验合同与来源：** [import-R01](#import-R01)；本条对应的失败输入见下文验证矩阵。

### §06 表头识别与列名/位置映射
**机制：** 显式约定头部是否存在及列映射依据 NAME 或 POSITION，禁止因列顺序变化或引擎自动推断把金额/收款对象映射错列；保留版本化字段别名。

**验收：** 同名列、重排列、缺/增列的映射行为可复现并符合业务 Schema 合同。

**核验合同与来源：** [import-R01](#import-R01)；本条对应的失败输入见下文验证矩阵。

### §07 NULL、空字符串、缺失与默认值
**机制：** SQL NULL、CSV 未加引号空项、带引号空字符串、JSON null、缺失属性及目标默认值不能未经批准合并；JSON Schema 的 default 注解不会自动填充业务值。

**验收：** 缺失、显式 null、空字符串、数字零和默认字段在合法路径上按不同语义处理。

**核验合同与来源：** [import-R02](#import-R02)；本条对应的失败输入见下文验证矩阵。

### §08 数值、单位、时间及精度转换
**机制：** 对货币定点数、计量单位、时区/DST、时区缺省、日期格式和整数溢出保留源类型，避免自动 CAST、浮点数和地区 Locale 改变业务金额或有效时间窗。

**验收：** 整数前导零、超精度金额、跨 DST 时间和非法值均合法拒绝或显式可追踪转换。

**核验合同与来源：** [import-R02](#import-R02)；本条对应的失败输入见下文验证矩阵。

### §09 JSON/结构化 Schema 及数组映射
**机制：** JSON、BSON 或嵌套输入的 Required、Additional Properties、数组顺序与类型约束按实际版本定义；不得把完整 JSON Schema 验证等同业务对象已获授权。

**验收：** 嵌套字段缺失、类型漂移、未知枚举与敏感子字段有明确对应错误及版本归属。

**核验合同与来源：** [import-R02](#import-R02)；本条对应的失败输入见下文验证矩阵。

### §10 Unicode、排序规则与业务标识
**机制：** 明确 UTF-8/编码错误、Unicode 规范化、大小写及 Collation 选择，不能对不同客户业务键默默小写或丢前导零；文本清洗与业务身份需要分离。

**验收：** 含非 ASCII、相似字符和组合字符的多个 ID 不被无依据去重或错绑。

**核验合同与来源：** [import-R02](#import-R02)；本条对应的失败输入见下文验证矩阵。

### §11 压缩包、远程路径和内容安全
**机制：** 解压、远程 URL 及对象存储输入需限制解压比、总文件数、路径穿越、符号链接与危险格式；不得以 SQL COPY PROGRAM 或任意来源路径执行不可信命令。

**验收：** 恶意归档或服务器命令参数不能越权读取文件、执行 shell 或占满内存/磁盘。

**核验合同与来源：** [import-R02](#import-R02)；本条对应的失败输入见下文验证矩阵。

### §12 导入规模和资源预算
**机制：** 设置输入总字节、行数、单行长度、批次并发、超时、临时空间和出入站费用上限，大小文件并存时不得用无界读取和全量一次加载造成服务中断。

**验收：** 巨大单行、空文件、大压缩比及分布偏斜均有可复核的拒绝/限流和清理。

**核验合同与来源：** [import-R02](#import-R02)；本条对应的失败输入见下文验证矩阵。

### §13 PostgreSQL COPY 的文件与权限边界
**机制：** PG COPY FROM 文件/PROGRAM 在数据库服务端执行，COPY FROM STDIN 经客户端连接传输；服务器文件权限与 SQL 业务授权不同，客户端不可信参数不得拼入 PROGRAM。

**验收：** 远端操作者不能借 COPY 服务端文件路径或程序入口读取机密或执行越权命令。

**核验合同与来源：** [import-R03](#import-R03)；本条对应的失败输入见下文验证矩阵。

### §14 PostgreSQL COPY ON_ERROR/REJECT_LIMIT
**机制：** PG 18 ON_ERROR ignore 适用于 text/csv 输入值类型转换错误，不是忽略所有约束失败；不设置 REJECT_LIMIT 可能无界跳过出错行。必须保留完整拒绝数与拒绝类别。

**验收：** 类型转换、UNIQUE/FK、格式异常分别按真实 COPY 行为被拒绝/失败，不发生静默丢账。

**核验合同与来源：** [import-R03](#import-R03)；本条对应的失败输入见下文验证矩阵。

### §15 MySQL LOAD DATA、LOCAL 与冲突处理
**机制：** MySQL 8.4 LOAD DATA 的 LOCAL 传输、安全权限、CHARACTER SET、IGNORE/REPLACE、字段映射与 SQL_MODE 依真实引擎版本；REPLACE 可能改变已有行，不能用它替代有权幂等业务合并。

**验收：** 重复键、非法字段、LOCAL 权限、行结束符及历史业务对象写入结果可重算。

**核验合同与来源：** [import-R03](#import-R03)；本条对应的失败输入见下文验证矩阵。

### §16 SQLite CLI 导入与库 API 区别
**机制：** SQLite CLI .import 是带具体 .mode/分隔符与表结构前置的工具入口，不等于所有 SQLite API 都有相同 CLI 子命令和默认事务处理。

**验收：** 有无 Header/现存表/不同 .mode 时导入映射与目标数据不变量满足合同。

**核验合同与来源：** [import-R03](#import-R03)；本条对应的失败输入见下文验证矩阵。

### §17 DuckDB CSV 推断与拒绝行为
**机制：** DuckDB sniff_csv/sample_size 对类型/方言的识别基于输入样本，无法推定后续异常行已被完整校验；实际 ignore_errors/store_rejects 以采用版本的受支持选项审查。

**验收：** 前段为数值后段为字母/长行等样本触发受控拒绝或明确 Schema，而非静默污染。

**核验合同与来源：** [import-R03](#import-R03)；本条对应的失败输入见下文验证矩阵。

### §18 Spark CSV 损坏记录模式
**机制：** Spark 4.2 CSV 的 PERMISSIVE/DROPMALFORMED/FAILFAST 处理与 corrupt record 字段配置有关；列数过多或过少不一定被判为 corrupted，不能只看错误计数等于零。

**验收：** 多/少 token、非法类型、嵌套引号和 corrupt column 组合不会漏掉应拒绝的数据。

**核验合同与来源：** [import-R03](#import-R03)；本条对应的失败输入见下文验证矩阵。

### §19 BigQuery CSV Header 与列匹配
**机制：** BigQuery CSV schema autodetect、skip_leading_rows、NAME/POSITION 与 max_bad_records 会影响读入范围；自动探测抽样不会对整份文件的字段类型和真实用户数据作完整正确性证明。

**验收：** 全字符串 Header、列重排及第 501 行出现其他类型时数据不发生未授权错列。

**核验合同与来源：** [import-R03](#import-R03)；本条对应的失败输入见下文验证矩阵。

### §20 Snowflake COPY 错行处理与验证
**机制：** Snowflake COPY INTO 的 ON_ERROR、VALIDATION_MODE、文件格式与 COPY 历史按实际配置采用；加载返回部分成功不等于全部源记录已落地，验证模式不自动提交业务结果。

**验收：** 坏行超过阈值、部分已入库与验证结果分别可回读，不能以 Job 成功掩盖遗漏。

**核验合同与来源：** [import-R03](#import-R03)；本条对应的失败输入见下文验证矩阵。

### §21 原始落地区与 Staging 隔离
**机制：** 在具有合法数据权利的环境中隔离 Raw/Staging、已清洗候选和已发布业务表，禁止把尚未验证文件直接当权威账本；原件保留期及可删除义务由合同决定。

**验收：** 失败批次、源哈希和合法回查范围可追溯，但未经授权的用户不可访问原件。

**核验合同与来源：** [import-R04](#import-R04)；本条对应的失败输入见下文验证矩阵。

### §22 可见发布点与数据一致性
**机制：** 加载、转换、约束校验与最终发布应有明确的可见性/事务门禁；一次性覆盖目标或分批行插入可能让客户端看到只有半批的数据。

**验收：** 上游重试、业务并发读和批次失败时只暴露完成验证的业务视图。

**核验合同与来源：** [import-R04](#import-R04)；本条对应的失败输入见下文验证矩阵。

### §23 重放批次身份与幂等
**机制：** 区分文件名称、内容哈希、源版本、业务操作键及 Load Job ID：文件重命名、同名覆盖和合法重新出数均可能发生；重复执行不能插入重复资金/身份记录。

**验收：** 同一源批次重试和修正版文件补发拥有合法版本替换/保留历史的明确结果。

**核验合同与来源：** [import-R04](#import-R04)；本条对应的失败输入见下文验证矩阵。

### §24 分块检查点与续传恢复
**机制：** 大文件/多页源可按稳定业务键、分段偏移及明确事务确认点恢复，偏移推进不等于目标已提交；Chunk 恢复需保存输入版本、防止并发替换。

**验收：** 进程崩溃在 Batch Commit 前后、恢复和重复扫描均不会静默跳过或重复发布。

**核验合同与来源：** [import-R04](#import-R04)；本条对应的失败输入见下文验证矩阵。

### §25 增量范围、提取窗口与水位
**机制：** 周期性 ETL 的源提取范围必须由源端更新语义和稳定水位约定，不能把客户端本地时间或最后成功文件名当作数据库提交完整点；细粒度 CDC/事件时间另由相邻专题规定。

**验收：** 源记录在窗口边界新增、修改、删除时不因水位推进被漏取或重复当成不同对象。

**核验合同与来源：** [import-R04](#import-R04)；本条对应的失败输入见下文验证矩阵。

### §26 AWS Glue Bookmark 与目标结果分离
**机制：** Glue Job Bookmark 主要用于记录支持的来源处理进度；Rewind/Reset/Retry 不会自动清理已经写出的目标文件或目标数据库事务，应有独立目标幂等/替换处理。
