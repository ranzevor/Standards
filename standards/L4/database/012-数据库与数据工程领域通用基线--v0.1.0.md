# L4 数据库与数据工程领域通用基线

**文档ID：** STD-L4-DATABASE-012　**版本：** 0.1.0　**状态：** adopted　**生效日期：** 2026-10-30

## 一、目的、架构边界及适用范围

本基线覆盖具有真实数据库、数据集、持久业务记录、批处理/流处理、数据导入、列式文件、分析或归档需求的系统。它规定跨存储类别共同成立的数据语义、权威归属、质量、安全、生命周期和可验证性，不强制某种 SQL/NoSQL、云平台、统一数据库、数据仓库、分布式中间件或独立数据治理平台。

**分层责任：** 现行 L1—L3 的研发/组织权限、验证与交付规则继续适用；相应 L4 后端领域模型、事务与业务幂等、消息与工作流、服务流控、版本迁移、可观测性及端到端故障测试专项仍负责其应用侧协议与领域义务。本基线只补充数据资产、存储与转换系统特有的约束。数据库/数据工程的物理存储、索引/计划、事务隔离、备份/PITR、湖仓表格式及转换管道分别由[领域目录](README.md)列出的独立具体技术规范承担；L5 决定实际数据库/SDK/工具版本，L6 决定具体数据权限、恢复目标、预算和业务验收。

## 三、32 项数据工程共性机制

每个机制包含具体工程要求和可验收条件。项目只激活与真实存储结构、业务角色和风险对应的部分，不为填满领域清单而虚设技术组件。

### §01 业务数据与保存目的
**机制：** 以实际用户任务、业务权利、计算结果和合同保留要求确定数据对象及必要保存范围，分清临时计算材料、权威业务记录、审计原件与可重建副本；不要求每个项目部署统一大数据平台。

**验收：** 列明关键数据集来源、读写主体、存储目的、质量条件及真实业务完成点。

**核验合同与来源：** [baseline-R01](#baseline-R01)；本条对应的失败输入见下文验证矩阵。

### §02 权威源、派生状态与写入归属
**机制：** 区分源事务记录、缓存/索引、报表、数据湖副本、第三方镜像和实验快照。每一业务事实应明确谁能写、何处可回读、哪些衍生数据可以重建，不能把索引命中当权威提交。

**验收：** 修改、故障和回填后能按业务键重算源与副本差异，不会由派生副本反向覆盖源事实。

**核验合同与来源：** [baseline-R01](#baseline-R01)；本条对应的失败输入见下文验证矩阵。

**验收：** 每项选用存储都有实际读写任务、故障与成本理由，删除任一无用途存储不影响核心业务。

**核验合同与来源：** [baseline-R01](#baseline-R01)；本条对应的失败输入见下文验证矩阵。

### §04 主体、租户、环境与数据权利

**验收：** 跨环境、跨租户、导出、复制与备份恢复均按真实数据权利及用途拒绝越界。

**核验合同与来源：** [baseline-R01](#baseline-R01)；本条对应的失败输入见下文验证矩阵。

**机制：** 建模时区分业务自然键、技术主键、外部对象键和版本键，确定唯一性、生命周期、删除和引用行为；不把可变展示名称或无约束数组位置当长期身份。

**验收：** 并发创建、合并、重命名、导入与删除后仍能唯一判定业务对象及合法关联。

**验收：** 新旧读写者在批准兼容窗口内有确定结果，拒收未知数据时不静默截断。

**验收：** 跨区域、跨存储或导出后，合法业务计算、时序及金额不发生无授权变化。

**验收：** 非法值、并发重复和引用缺失不能悄悄进入合法结果，拒绝/修复留有证据。

**验收：** 高并发/失败场景可明确哪些修改已经提交、哪些尚不可见、哪些结果未知。

**验收：** 按固定数据量/查询负载复核计划、执行耗时、锁/IO与正确结果，反例可重现。

### §13 查询范围、分页与数据扫描预算
**机制：** 分页必须有明确业务集合、快照/变化合同及唯一稳定排序键，限制越权扫描、无限展开、跨租户查询与大结果集。Keyset 只能在定义的快照或稳定资格集合中给出对应无漏重保证；并发修改排序键、过滤条件或身份时，应选择固定快照、变更日志补偿或明确允许的变化语义，不承诺仅靠唯一 ORDER BY 对任意并发变化都无漏重。

**验收：** 在固定快照中验证重复排序值、插入/删除边界及完整集合无漏重；在实时变化模式明确并测量允许的增删/移动行为，游标绑定租户/过滤/排序/数据版本。单页小型离线数据是合法邻例，无须为分页部署分布式快照服务。

**验收：** 跨分区键变化、重平衡与冷热迁移期间查询结果及对象归属正确。

**验收：** 峰值数据规模下仍可写入、查询及恢复，合法保留/删除不被成本策略悄然破坏。

## 五、采用、专题组合与项目验收

1. 本基线的共性机制和失败场景用于界定数据权威、生命周期与验收边界；按实际数据对象选定条款，不替代具体技术专题或实际运行验收。
2. [领域目录](README.md)定位数据模型、SQL、事务、索引、WAL、分片、复制、迁移、PITR、CDC、ETL、湖仓、安全和元数据的独立规范；分别固定实际选择的版本、条款和提供/消费接口，基线批准不使这些专题自动生效。
3. SQL/存储引擎/格式规范的原始技术规格、具体 L5 实现版本、L6 项目合同和权限各自独立适用。
4. CI、文本完整性、隔离数据库的实验、真实业务恢复、生产部署及客户结果是不同验收层级。数据写入、迁移、权限调整、备份清理、外部通知和额外费用仍由真实项目的授权与环境约束控制。
