# 内容资产、媒体加载与运行身份技术规范

**文档ID：** STD-L4-GAME-001　**版本：** 0.1.0　**状态：** adopted　**生效日期：** 2026-10-30

## 1 目标、适用与非目标

把源资产、导入派生、内容引用、媒体解码与最终运行内容串联，避免编辑器成功掩盖消费端缺失或内容错配。

**适用：** 场景、模型、着色器、音视频、字体、本地化、DLC/Mod等实际资产链路。

**非目标：** 不强制glTF/OpenXR或某编解码，不对来源许可作法律裁定；不复制云供应链的签名算法。

本文的“必须/不得”为采用相应条款时的必要条件，“应”为需说明偏离理由的建议，“可”为允许选项。外部标准的 MUST/SHOULD 依其原有强度与适用 profile 执行，项目参数不得降低其强制要求。能力不存在可据事实不适用；已承诺但未验的能力仍适用。

## 2 术语、主体与权威状态

源身份、导入身份、平台变体、包身份与运行实例是不同对象；“已下载”“完整性验证”“可解码/加载”“已引用生效”是不同状态。可选装饰资源与关键玩法资源必须事先区分。

**主体与所有权：** 资产管线拥有导入配置和依赖图；加载器拥有异步请求/句柄及取消世代；场景拥有实例与订阅；发行消费者核真实包。

**前置输入：** 源文件摘要、来源/使用依据、导入器/插件与参数、平台能力、资源图、核心/可选标记。

**输出与权威观察：** 资产manifest、导入差异、运行加载轨迹、媒体实播证据和缺失资源错误。权威内容身份取实际最终包/加载对象而非编辑器路径。

**状态与终点：** 未验证→验证中→可加载→场景绑定→可交互；失败/取消请求不自动清除仍被共享所有者持有的资源。

条款 ID 在本文内稳定；全局身份为文档路径、版本与条款 ID 的组合。各条的前置输入、主体和状态继承本节，再叠加本条触发条件。诊断缺失不证明效果未发生；并发、超时、取消请求与真实业务终态分别记录。

## 3 机制、不变量及逐条验收

### G-ASSET-01 导入、派生与缓存身份

- **触发/前置：** 资产进入管线或工具/设置变化。
- **必要机制：** 必须以源摘要、导入器/插件版本、设置、依赖及目标变体组成派生身份；运行引用使用所选引擎导入契约，不把源文件在编辑器可读当导出包可读。缓存命中须校验影响输入。
- **不变量：** 同标签/路径不掩盖不同内容；缓存失效不会静默提供旧碰撞或材质。
- **并发、超时、未知与恢复：** 并行导入只发布完整派生；中断保留旧可用产物或明确失败。升级重建影响闭包，不以缓存存在免除迁移。
- **产物与观察点：** 源→派生→包→运行引用图与摘要。
- **正例：** 替换纹理/碰撞源后干净重建与增量重建符合声明结果。
- **直接失败：** 导入器升级但依然用旧缓存，或用FileAccess读仅存在于编辑器的原资源。
- **合法邻例：** 无需导入的原生文本资源可直用，但仍绑定包与运行身份。
- **可观察验收：** 清缓存/保缓存两条构建比较关键资源；删源、改参数和换导入器分别检测。
- **来源与限制：** RP21。来源只支持[逐命题表](../../../sources/runtime-protocol/SOURCE-CLAIMS.md)所列命题；其余必要机制是为保持本条不变量而提出的组织综合设计，不声称由单一外部标准规定。

### G-ASSET-02 异步加载、引用与场景准入

- **触发/前置：** 场景转换或资源异步到达。
- **必要机制：** 必须给加载请求绑定场景/玩家/版本世代，定义必需依赖集合和准入屏障；所有关键资源可加载且已初始化后才开放交互。取消释放自己持有的引用，不误释放共享资源；对象池重置上个所有者状态。
- **不变量：** 下载完成不是资源生效；旧回包不能激活已退出场景。
- **并发、超时、未知与恢复：** 加载超时/失败返回完整旧场景或明确恢复入口；重复回调按请求身份去重，资源缺失不伪装关键目标存在。
- **产物与观察点：** 各阶段时间线、资源句柄所有者、场景准入与回退事实。
- **正例：** 加载失败保留有效菜单/上一场景，重试后只激活当前场景。
- **直接失败：** 切关后迟到回包将旧NPC重新加入新关卡。
- **合法邻例：** 可选粒子缺失允许降级但不丢关键碰撞/任务实体。
- **可观察验收：** 延迟/乱序/取消完成回调及关键引用缺失，核可交互时点、句柄泄漏和恢复入口。
- **来源与限制：** RP21；RP27。来源只支持[逐命题表](../../../sources/runtime-protocol/SOURCE-CLAIMS.md)所列命题；其余必要机制是为保持本条不变量而提出的组织综合设计，不声称由单一外部标准规定。

### G-ASSET-03 媒体解码、播放与同步

- **触发/前置：** 使用视频、音轨、节奏或空间反馈。
- **必要机制：** 必须固定容器/编码profile及目标解码器，分别检查完整性、可解码、可播放、时长/音轨和场景生命周期；节奏玩法声明音画/输入允许误差。暂停、音量分组和设备切换须作用于真实播放实例。
- **不变量：** 文件摘要/下载成功不证明音画可用；音频反馈不裁决规则成功。
- **并发、超时、未知与恢复：** 损坏、解码失败、失设备及播放超时有可恢复终态；离开场景停止非共享音轨，旧回调不恢复它。
- **产物与观察点：** 解码日志、播放器事件、时长/轨道、设备/暂停轨迹和同步测量。
- **正例：** 目标播放器播完正常合成音视频，关闭音乐不关掉必需独立提示。
- **直接失败：** 损坏尾部仍显示播放完成，场景退出旧音乐无法停止。
- **合法邻例：** 纯静态图片叙事无视频轨道，不需新增编解码依赖。
- **可观察验收：** 在目标发行构建播放正常、截断、错编码和缺音轨素材；核错误/完成区别、设备切换及承诺同步误差。
- **来源与限制：** RP28。来源只支持[逐命题表](../../../sources/runtime-protocol/SOURCE-CLAIMS.md)所列命题；其余必要机制是为保持本条不变量而提出的组织综合设计，不声称由单一外部标准规定。

### G-ASSET-04 内容引用、变体与材料权利

- **触发/前置：** 分发第三方素材、多语言/地区/平台内容。
- **必要机制：** 必须核引用图及各变体所需字形、音频、文本布局和字幕时间；对实际分发材料记录来源、使用方式、权利依据和必要署名。格式合规与许可/商店发行资格分开。
- **不变量：** 每个关键引用能定位实际包内容；未知来源不因格式合法被标可发行。
- **并发、超时、未知与恢复：** 删除/替换材料重验引用影响；缺翻译按声明回退，不覆盖原件掩盖问题。新权限/用途须由对应责任接口判定。
- **产物与观察点：** 材料清单、引用扫描、语言关键流程及许可/署名定位。
- **正例：** 授权字体随包且目标语言字形完整。
- **直接失败：** 原语言截图通过就宣布全部语言可用，或根代码许可被套到异授音乐。
- **合法邻例：** 只用自有资源/单语言仍核实际范围，不要求新增第三方许可服务。
- **可观察验收：** 抽取最终包随机关键资源核来源与依赖，执行每个支持语言/变体的必要操作。
- **来源与限制：** RP29；RP30。来源只支持[逐命题表](../../../sources/runtime-protocol/SOURCE-CLAIMS.md)所列命题；其余必要机制是为保持本条不变量而提出的组织综合设计，不声称由单一外部标准规定。

### G-ASSET-05 扩展内容的兼容与信任

- **触发/前置：** 支持DLC、Mod、资源包或UGC。
- **必要机制：** 必须定义版本、依赖、优先级、卸载/缺失策略及实际能力。代码扩展与数据包分开；外来内容不得默认读取宿主账户/文件或改核心存档，未提供沙箱时不能宣称安全隔离。
- **不变量：** 可选包缺失不破坏承诺核心；来源签名不等于任意权限许可。
- **并发、超时、未知与恢复：** 扩展加载/升级中断有可回退包组合；存档引用已卸载内容需可解释错误或迁移，不静默删进度。
- **产物与观察点：** 内容组合清单、能力调用/拒绝及存档兼容结果。
- **正例：** 不可信数据包受限加载，卸载可选皮肤仍可继续核心游戏。
- **直接失败：** Mod目录自动执行脚本并获得全部账户秘密。
- **合法邻例：** 无扩展能力的游戏不必实现Mod管理器。
- **可观察验收：** 装入冲突/错版/不可信包并尝试隔离能力；真实目标验证拒绝而非只看权限字段。
- **来源与限制：** RP21。来源只支持[逐命题表](../../../sources/runtime-protocol/SOURCE-CLAIMS.md)所列命题；其余必要机制是为保持本条不变量而提出的组织综合设计，不声称由单一外部标准规定。

## 4 兼容、迁移与退役

导入器、引擎、着色器/压缩器及目标后端升级重新生成受影响派生。旧/新内容共存用独立坐标；Mod依赖和信任权限另核，不以签名代替执行能力限制。

## 5 跨域消费接口

消费基线§17–24、§31–32、§35–36及云供应链的制品/来源接口；开源/安全提供材料权利及扩展信任要求，游戏提供资产图、关键语义和实际加载结果。

接口只定位技术职责，不自动作出规范采用决定。通用状态、测试和制品义务消费 [L3 通用工程 v0.1.0](../../L3/001-通用工程规范--v0.1.0.md)；提供方版本与摘要、应用条款、实现入口和验收责任在项目契约中绑定。提供方保证须由相应实现证据支持，消费方按该保证的实际范围验收。

## 6 真实目标验收合同

Godot 4.5画像：`godot --headless --path "$PROJECT" --import`，随后 `godot --headless --path "$PROJECT" --export-release "$PRESET" "$OUT"`，由最终发行二进制运行项目的 `--asset-contract` 测试入口，记录ResourceLoader/媒体播放事件及缺失回退。录像在目标播放器从首帧到尾帧验证解码/时长/音轨与错误终态；独立离线解码工具可补证但不能替代游戏内真实播放。

**判据：** 替换源资源后最终包身份/画面/碰撞按影响变化；删关键引用拒绝进入半初始化场景，删装饰资源按合同降级；损坏尾帧/音轨必须被真实解码或播放器故障路径识别。

每次执行保存：正文/条款版本与摘要、目标制品/实现和工具版本、OS/设备/运行时/配置、输入及故障时间线、预期和实际、stdout/stderr/退出码或等价运行证据、权威状态回读、未覆盖范围。`not-run`、模型通过和真实目标通过是不同结果；实际无环境时保留命令和判据而不填写虚构回执。
