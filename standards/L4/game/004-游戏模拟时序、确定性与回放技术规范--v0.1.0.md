# 游戏模拟时序、确定性与回放技术规范

**文档ID：** STD-L4-GAME-004　**版本：** 0.1.0　**状态：** adopted　**生效日期：** 2026-10-30

## 1 目标、适用与非目标

让模拟规则、时钟和回放的承诺可检验，防止渲染帧率、浮点环境或不完整快照被误当确定性保证。

**适用：** 有规则状态和交互循环的游戏；物理、随机、回滚仅在实际采用时适用。

**非目标：** 不要求所有游戏采用固定步长、锁步、回滚或逐位确定性；不把可播放视频当模拟回放，也不规定统一帧率。

本文的“必须/不得”为采用相应条款时的必要条件，“应”为需说明偏离理由的建议，“可”为允许选项。外部标准的 MUST/SHOULD 依其原有强度与适用 profile 执行，项目参数不得降低其强制要求。能力不存在可据事实不适用；已承诺但未验的能力仍适用。

## 2 术语、主体与权威状态

tick 是规则推进序号；frame 是呈现机会；模拟时间、单调持续时间和日历时间各有坐标。确定性域是输入、初态、规则/内容、引擎/物理库、平台及构建参数共同限定的等价范围；视觉容差与影响胜负的规则相等分开。

**主体与所有权：** 规则执行器独占或按确定顺序合并权威状态；呈现层只读派生结果；回放记录器持有输入/状态记录，验收器以独立断言比较事件及状态。

**前置输入：** 玩法时钟策略、支持设备/构建、更新顺序、输入时间戳映射、初始状态、随机源及兼容承诺。

**输出与权威观察：** 逐tick状态/事件摘要、时钟轨迹、回放清单、偏差报告；录像输出另由解码/播放路径确认，不具有规则权威。

**状态与终点：** 初始化→可推进→暂停/挂起→恢复→终局；回放材料为完整/不兼容/缺项/损坏，只有完整兼容材料可支持声明范围的重建。

条款 ID 在本文内稳定；全局身份为文档路径、版本与条款 ID 的组合。各条的前置输入、主体和状态继承本节，再叠加本条触发条件。诊断缺失不证明效果未发生；并发、超时、取消请求与真实业务终态分别记录。

## 3 机制、不变量及逐条验收

### G-SIM-01 时钟分工与积压预算

- **触发/前置：** 进入实时、回合、暂停或后台恢复路径。
- **必要机制：** 必须给每类计时器指定时钟、单位、推进与暂停规则，明确输入采样、固定/可变模拟、物理、动画和呈现顺序；积压步数须受预算约束。丢弃模拟时间、降速或追赶是可选策略，但必须按玩法合同可见，不能悄悄跳过关键事件。
- **不变量：** 墙钟回拨不倒退单调期限；渲染帧率不意外倍增按时间定义的伤害或冷却。
- **并发、超时、未知与恢复：** 长帧/挂起先算实际积压再按声明处理；恢复不从墙钟差无界补算。并行更新的写冲突采用稳定合并或明确无冲突所有权。
- **产物与观察点：** 模拟/渲染/单调时间线、追赶与丢弃计数、事件序号。
- **正例：** 30与120渲染FPS下相同固定tick序列得到相同冷却事件。
- **直接失败：** 每帧减一造成低帧率冷却变慢，或挂起一小时后无限追赶卡死。
- **合法邻例：** 回合制按回合推进，无须伪造60Hz物理tick。
- **可观察验收：** 注入墙钟跳变、长帧、暂停、挂起并比较预先声明的时钟推进集合；预算超限有明确终点。
- **来源与限制：** RP17；RP09。来源只支持[逐命题表](../../../sources/runtime-protocol/SOURCE-CLAIMS.md)所列命题；其余必要机制是为保持本条不变量而提出的组织综合设计，不声称由单一外部标准规定。

### G-SIM-02 物理边界与数值域

- **触发/前置：** 采用碰撞、积分或物理后端。
- **必要机制：** 必须绑定单位、坐标、步长、子步、碰撞层、连续/离散检测及关键接触容差。确定性声明包含物理库、编译器/选项、架构、创建顺序与必要线程策略，不能从“固定步长”推出全部引擎逐位相等。
- **不变量：** 关键碰撞/胜负按玩法条件成立，表现插值不反写物理真相。
- **并发、超时、未知与恢复：** 高速穿透、NaN/无穷或迭代不收敛进入已声明纠正/失败路径；回滚必须包含求解器所需内部状态，只有位置/速度不一定足够。
- **产物与观察点：** 薄障碍/高速/堆叠/重复创建夹具、接触事件和数值环境清单。
- **正例：** 在绑定Box2D二进制及创建顺序下重复初态，核接触事件与结果。
- **直接失败：** 只用整数加法回放PASS宣称真实3D浮点物理跨平台确定。
- **合法邻例：** 允许视觉插值误差，但规则碰撞和结算事件仍满足独立断言。
- **可观察验收：** 对目标物理后端运行薄壁、高速、边界堆叠及回滚再推进；分别记录数值误差与业务事件，不凭截图认定。
- **来源与限制：** RP19；RP17。来源只支持[逐命题表](../../../sources/runtime-protocol/SOURCE-CLAIMS.md)所列命题；其余必要机制是为保持本条不变量而提出的组织综合设计，不声称由单一外部标准规定。

### G-SIM-03 随机源隔离与状态记录

- **触发/前置：** 规则使用随机性且存在复现或恢复承诺。
- **必要机制：** 必须给随机流指定算法/版本、种子来源、流作用域、调用顺序及起始/快照状态；装饰随机与规则随机分开，避免新增粒子抽样改变掉落。确定性范围声明序列化和随机实现兼容边界。
- **不变量：** 同一规则输入与声明随机状态产生相同规则抽样；无随机游戏不被要求新增种子。
- **并发、超时、未知与恢复：** 并发随机流用明确分流或稳定调度；检查点恢复重新装载状态而非重新randomize。算法升级迁移或拒绝旧承诺。
- **产物与观察点：** 随机流身份、初始/检查点状态及抽样位置。
- **正例：** 增加装饰粒子不改变战斗掉落序列。
- **直接失败：** 恢复时重新设种，续局与原抽样位置错位。
- **合法邻例：** 不承诺逐种子复现的生成游戏保留版本/错误现场，仅声称诊断证据。
- **可观察验收：** 固定输入运行、检查点接续与不中断运行比较；删除随机状态时确定性重放必须拒绝。
- **来源与限制：** RP18。来源只支持[逐命题表](../../../sources/runtime-protocol/SOURCE-CLAIMS.md)所列命题；其余必要机制是为保持本条不变量而提出的组织综合设计，不声称由单一外部标准规定。

### G-SIM-04 关键状态机与表现副作用

- **触发/前置：** 角色、任务、关卡、过场存在互斥状态或进入/退出效果。
- **必要机制：** 必须定义可用转换、事件消费边界和副作用身份。跳过动画、正常结束、重复回调统一经规则转换提交必要效果，不由多个表现监听器各发奖励；场景退出解除订阅/资源所有权。
- **不变量：** 同一规则转换最多形成一次应有奖励；互斥状态不可同时有效。
- **并发、超时、未知与恢复：** 并发死亡/关卡切换按声明优先级处理；超时允许跳过表现但不假造规则成功；失败终局保留声明退出入口。
- **产物与观察点：** 状态转换表、事件ID、订阅计数、权威奖励事实。
- **正例：** 过场跳过与自然结束均落到同一已完成任务版本。
- **直接失败：** 结束和跳过回调各奖励一次；退出场景继续收到旧伤害事件。
- **合法邻例：** 设计性失败终局可只提供重开/标题入口，不强制当前局继续。
- **可观察验收：** 对每个转换入口做重复/乱序/取消回调；核权威副作用次数及退出后订阅为零或达到声明共享所有权。
- **来源与限制：** RP17。来源只支持[逐命题表](../../../sources/runtime-protocol/SOURCE-CLAIMS.md)所列命题；其余必要机制是为保持本条不变量而提出的组织综合设计，不声称由单一外部标准规定。

### G-SIM-05 回放类型、材料与差异判定

- **触发/前置：** 交付录像、事件日志、输入回放或可重放模拟。
- **必要机制：** 必须标明交付类型；模拟重建绑定规则/内容、初态、输入顺序、时间步长、必要随机/物理状态及校验点。视频只承担解码播放和音画完整性。比较器须独立定义事件序、状态摘要或数值容差，不能以当前输出自动更新真值。
- **不变量：** 材料缺失或不兼容不升级为确定性成功；视频摘要相同不证明可播放，更不证明模拟可重建。
- **并发、超时、未知与恢复：** 截断回放报告最后完整检查点和缺口；跨版本仅走已验证解释/迁移；恢复记录不覆盖原件。
- **产物与观察点：** 回放manifest、兼容拒绝原因、逐检查点偏差、视频解码结果。
- **正例：** 相同规则初态输入重建任务事件，错误初态被拒。
- **直接失败：** 只看视频文件hash就宣称音轨完整或规则可回放。
- **合法邻例：** 纯渲染录像可无种子/初始模拟状态，只需真实播放承诺成立。
- **可观察验收：** 删除规则版本、初态或必要随机状态逐一复测；真实物理回放与整数示例分别报告，容差外/关键事件不同必失败。
- **来源与限制：** RP19；RP28。来源只支持[逐命题表](../../../sources/runtime-protocol/SOURCE-CLAIMS.md)所列命题；其余必要机制是为保持本条不变量而提出的组织综合设计，不声称由单一外部标准规定。

## 4 兼容、迁移与退役

规则/内容、物理后端、线程调度、编译浮点选项变化均重新划定确定性域。历史回放可保留旧解释器、迁移或明确拒绝，不在新版本静默以近似画面宣称精确重演。无跨平台承诺者仍需同一目标的重现与诊断证据。

## 5 跨域消费接口

消费游戏基线§03、§05–10、§30；网络提供输入交付但不提供模拟确定性，数据库提供持久快照但不保证物理内部状态可恢复。L5绑定引擎/物理API和构建；L6选择规则相等、数值容差与事件时序判据。

接口只定位技术职责，不自动作出规范采用决定。通用状态、测试和制品义务消费 [L3 通用工程 v0.1.0](../../L3/001-通用工程规范--v0.1.0.md)；提供方版本与摘要、应用条款、实现入口和验收责任在项目契约中绑定。提供方保证须由相应实现证据支持，消费方按该保证的实际范围验收。

## 6 真实目标验收合同

Godot 4.5示例画像使用固定项目和项目自带验收脚本：`godot --version`；`godot --headless --path "$PROJECT" --script res://tests/simulation_contract.gd -- --case clocks,replay,collision --seed 17`。该脚本须输出逐tick事件/状态、引擎/物理后端与显式失败分支/非零退出，不能仅打印PASS或仅依赖release会忽略的debug assert；Godot4.6的此行为来源与4.5画像分别绑定。以目标GUI构建再测渲染30/60/120档和挂起恢复；Godot为可选画像，其他引擎绑定等价真实脚本。

**判据：** 同一声明确定性域至少两次从干净初态运行相同输入，在规定事件边界相等或满足已事先设定容差；错版本/初态/随机状态必须被拒。强制改变浮点选项或创建顺序作为负控制，若系统仍宣称逐位兼容则失败。headless不验证GPU呈现、真实设备输入或音画。

每次执行保存：正文/条款版本与摘要、目标制品/实现和工具版本、OS/设备/运行时/配置、输入及故障时间线、预期和实际、stdout/stderr/退出码或等价运行证据、权威状态回读、未覆盖范围。`not-run`、模型通过和真实目标通过是不同结果；实际无环境时保留命令和判据而不填写虚构回执。
