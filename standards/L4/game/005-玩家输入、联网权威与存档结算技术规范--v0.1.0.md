# 玩家输入、联网权威与存档结算技术规范

**文档ID：** STD-L4-GAME-005　**版本：** 0.1.0　**状态：** adopted　**生效日期：** 2026-10-30

## 1 目标、适用与非目标

使玩家意图、控制权、规则结果和持久进度形成一致闭环，避免重连和恢复制造双重控制或重复结算。

**适用：** 有离散输入、共享状态或存档的游戏；联网单人云存档也属远端状态，离线同屏不被要求服务器。

**非目标：** 不选择统一客户端/服务端、P2P或锁步架构；不在游戏域重定义支付账本。

本文的“必须/不得”为采用相应条款时的必要条件，“应”为需说明偏离理由的建议，“可”为允许选项。外部标准的 MUST/SHOULD 依其原有强度与适用 profile 执行，项目参数不得降低其强制要求。能力不存在可据事实不适用；已承诺但未验的能力仍适用。

## 2 术语、主体与权威状态

输入事件、规则命令、尝试和结算意图身份分开；控制世代针对控制实例，不限制一个玩家拥有多个合法实体。存档提交点是项目承诺可恢复的状态边界，远端查询须说明强度及覆盖范围。

**主体与所有权：** 输入路由器按焦点/玩家映射分发；权威节点裁决共享规则；存档写者控制档位版本；奖励/权益提供方拥有最终结算事实。

**前置输入：** 动作映射、焦点策略、拓扑/权威节点、玩家/实体/档位身份、保存格式、迁移范围、远端去重及查询契约。

**输出与权威观察：** 输入消费账、控制世代安装回执、存档版本/校验、结算结果与未知项；HUD/音效和传输ACK不是权威。

**状态与终点：** 命令为待处理/接受/拒绝/未知；控制为旧有效/接管安装中/新世代生效；保存为暂存/持久提交/失败可恢复，不能以“请求保存”直接标已保存。

条款 ID 在本文内稳定；全局身份为文档路径、版本与条款 ID 的组合。各条的前置输入、主体和状态继承本节，再叠加本条触发条件。诊断缺失不证明效果未发生；并发、超时、取消请求与真实业务终态分别记录。

## 3 机制、不变量及逐条验收

### G-STATE-01 动作与焦点的单次消费

- **触发/前置：** 设备采样、菜单/文本输入、暂停或热插拔。
- **必要机制：** 必须为离散输入给事件身份、按下/持续/释放含义和消费时点；按玩家/设备/控制上下文路由。UI与玩法共享按键时明确唯一接收者；热拔插、焦点丢失时清理或重采样按住状态，恢复保持/清空由合同决定。
- **不变量：** 一次确认不同时提交菜单和背景攻击；同一离散事件不因多次轮询重复消费。
- **并发、超时、未知与恢复：** 异步输入回调带设备/焦点世代；旧回调不得恢复已失去的控制。超时等待设备有恢复入口而非卡键。
- **产物与观察点：** 原始事件→动作→实体的链路和消费计数。
- **正例：** 重映射后提示、保存配置和实际动作同步变化。
- **直接失败：** 文本输入“空格”同时触发背景跳跃；手柄拔出后永远前进。
- **合法邻例：** 明确保持按住状态的暂停策略可恢复移动，但焦点/设备断连仍须核验。
- **可观察验收：** 真实设备低帧率、连按、UI切换、暂停/恢复、热插拔后核动作次数、所有者与持久配置。
- **来源与限制：** RP24。来源只支持[逐命题表](../../../sources/runtime-protocol/SOURCE-CLAIMS.md)所列命题；其余必要机制是为保持本条不变量而提出的组织综合设计，不声称由单一外部标准规定。

### G-STATE-02 共享状态的权威与命令合法性

- **触发/前置：** 联网/P2P/本地同屏存在共享规则状态。
- **必要机制：** 必须说明谁裁决输入、规则、时间和冲突；命令验证玩家授权、对象归属、阶段和序号。客户端预测只为表现，回滚/锁步按所采算法保留必要输入与状态；主机迁移须有权威切换判据。
- **不变量：** 未经规则确认的客户端数值不直接成为共享奖励或其他玩家真相。
- **并发、超时、未知与恢复：** 延迟、重复、乱序和权威离线不能造成两个有效权威同时结算；不能接管时准确保持不可用/未知。
- **产物与观察点：** 拓扑、权威世代、命令接受/拒绝及状态快照。
- **正例：** P2P确定主机按明确选举和冲突规则裁决。
- **直接失败：** 改客户端经验值即获服务端持久奖励。
- **合法邻例：** 离线同屏只需输入归属及本地权威，不需虚构网络预测。
- **可观察验收：** 真实权威端注入非法/乱序命令并核最终状态；独立合法玩家/实体仍能推进。
- **来源与限制：** RP20；RP31。来源只支持[逐命题表](../../../sources/runtime-protocol/SOURCE-CLAIMS.md)所列命题；其余必要机制是为保持本条不变量而提出的组织综合设计，不声称由单一外部标准规定。

### G-STATE-03 重连接管与目标栅栏

- **触发/前置：** 旧控制实例失联后建立新实例。
- **必要机制：** 必须在权威端原子校验并安装控制世代；新连接/租约到手不等于旧实例已失效。安装前旧写窗口视为可能发生，安装确认后所有写入口拒绝较旧世代；回调归账但不驱动旧控制。
- **不变量：** 接管后不允许未经授权的双重驱动/结算；合法RTS多实体不因唯一控制检查被误拒。
- **并发、超时、未知与恢复：** 新世代安装结果未知时查询权威控制记录；不能用本地布尔锁证明分布式拒绝。恢复旧实例必须重新校验。
- **产物与观察点：** 权威安装回执、对象/玩家/世代和旧命令拒绝记录。
- **正例：** 新世代已安装但尚无业务写，旧实例恢复仍被拒。
- **直接失败：** 新实例首次业务写之前旧写仍被接受，却报告接管已完成。
- **合法邻例：** 同一玩家拥有多角色/召唤物，但每个控制通道按合同唯一授权。
- **可观察验收：** 暂停旧实例→过期→新接管安装→释放旧实例；核所有目标写入口拒旧而当前世代合法多实体通过。
- **来源与限制：** RP20。来源只支持[逐命题表](../../../sources/runtime-protocol/SOURCE-CLAIMS.md)所列命题；其余必要机制是为保持本条不变量而提出的组织综合设计，不声称由单一外部标准规定。

### G-STATE-04 一致快照与可恢复保存

- **触发/前置：** 本地保存、检查点、云同步或格式升级。
- **必要机制：** 必须将位置、物品、任务/消耗与规则版本绑定同一逻辑快照，冻结或以版本一致读取构造；暂存写完校验后才发布，持久成功点取决真实存储/同步配置。历史迁移在副本执行并验证后切换，保留损坏/未知原件。
- **不变量：** 不加载半写/混合版本；不能以rename原子可见推出断电耐久。
- **并发、超时、未知与恢复：** 并发档位写用版本条件或等价互斥；失败保留完整旧档/明确错误。云同步跨账号不得复用队列，冲突不凭客户端墙钟无条件覆盖。
- **产物与观察点：** 保存清单、提交点、完整性校验、迁移差异和回退入口。
- **正例：** 保存中断后读到完整旧档，新提交后读完整新档。
- **直接失败：** 位置来自检查点B、物品消耗来自A，或遇未知格式静默重置。
- **合法邻例：** 只读旧存档或明确前向恢复可合法替代不可行降级。
- **可观察验收：** 在写入/flush/发布/确认各边界中断；重启核全状态一致、身份、历史档迁移与错误原件保留。
- **来源与限制：** RP07；RP08；RP27。来源只支持[逐命题表](../../../sources/runtime-protocol/SOURCE-CLAIMS.md)所列命题；其余必要机制是为保持本条不变量而提出的组织综合设计，不声称由单一外部标准规定。

### G-STATE-05 远端进度与结算未知

- **触发/前置：** 奖励、赛果、云存档或其他远端写入。
- **必要机制：** 必须保留逻辑意图与尝试身份，绑定玩家/目标/参数；按目标契约重试。查无记录不足以证明旧在途已停；有限去重须覆盖目标接受/处理窗口或强制接受截止。操作级权威核对须覆盖全部未知尝试后才可消解。
- **不变量：** 同一结算不因重连重复；取消请求不改写已发生效果。
- **并发、超时、未知与恢复：** 过期去重且无终局查询保持未知并提供核对；补偿是新授权操作，不能假定逆转已被玩家消费的权益。
- **产物与观察点：** 权威结果、去重作用域/期限、未知尝试集合、对账及补偿记录。
- **正例：** 已提交丢响应后同一意图查回原赛果且不再发奖励。
- **直接失败：** 新尝试未应用就把此前未知清掉，旧请求稍后提交产生重复奖励。
- **合法邻例：** 无远端状态的离线游戏本条不适用；纯无副作用重算可以重跑。
- **可观察验收：** 隔离真实端点延迟旧请求至去重窗外并丢响应，核目标接受截止/拒绝和最终副作用数；不能由内存模型代替。
- **来源与限制：** RP02；RP31。来源只支持[逐命题表](../../../sources/runtime-protocol/SOURCE-CLAIMS.md)所列命题；其余必要机制是为保持本条不变量而提出的组织综合设计，不声称由单一外部标准规定。

## 4 兼容、迁移与退役

账号切换、旧客户端、内容包和规则版本分别验证；未知新存档不可被旧程序静默覆盖。云冲突可按玩家明确选择、版本仲裁或合并合同处理，不强制最后时间戳获胜。

## 5 跨域消费接口

消费基线§11–14、§25–29；后端/数据库提供操作级查询、去重和持久事务；网络只保证其交付层；商业交易/权益提供方判支付/奖励事实，游戏将其映射至进度但不凭success页授予权益。

接口只定位技术职责，不自动作出规范采用决定。通用状态、测试和制品义务消费 [L3 通用工程 v0.1.0](../../L3/001-通用工程规范--v0.1.0.md)；提供方版本与摘要、应用条款、实现入口和验收责任在项目契约中绑定。提供方保证须由相应实现证据支持，消费方按该保证的实际范围验收。

## 6 真实目标验收合同

目标工程提供 `godot --headless --path "$PROJECT" --script res://tests/state_contract.gd -- --case input,reconnect,save --fixture tests/fixtures/state.json` 或等价引擎入口；启动两个独立客户端和真实隔离权威进程，在安装新控制世代后再释放暂停旧实例。存档以最终发行构建在目标文件系统测试逐阶段进程中断、历史格式与账号切换；OS掉电需单列目标台架。

**判据：** 真实权威端拒绝旧世代写入，合法多实体保持；丢响应重试不重复结算，未知查询覆盖所有未决尝试；每次存档中断只加载完整旧/新状态或明确失败。进程崩溃通过不外推断电耐久。

每次执行保存：正文/条款版本与摘要、目标制品/实现和工具版本、OS/设备/运行时/配置、输入及故障时间线、预期和实际、stdout/stderr/退出码或等价运行证据、权威状态回读、未覆盖范围。`not-run`、模型通过和真实目标通过是不同结果；实际无环境时保留命令和判据而不填写虚构回执。
