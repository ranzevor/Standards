# L4 配置、秘密管理与密钥生命周期技术规范

**文档ID：** STD-L4-CLOUD-013　**版本：** 0.1.0　**状态：** adopted　**生效日期：** 2026-10-30

## 一、目标、适用与非目标

**目标：** 验证配置来源、秘密投影、真实轮换/撤权与历史密文恢复。

**适用：** 公开/敏感配置、Secret Store、Vault、KMS/HSM、容器消费者与签发材料。

**非目标：** 不由Store权限推定客户业务权，不泄露明文作证据，不把换Alias当源服务改密完成。

L4 云基础设施与 DevOps 第 7 项专门管理实际使用的运行配置来源、机密值储存与注入、秘密版本/轮换/撤销、密码密钥材料的用途、历史解密与恢复。配置、可重放凭据、加密材料、密钥引用和信任根是不同对象；环境和租户、合同与数据权利按具体项目决定。低复杂度项目可以使用已有受控服务和小型运行配置方案，不强制购买第三方 HSM、Vault、独立 Secret Manager 或企业工具。

相应云 IAM 负责 Principal/Role/资源授权，CI/Runner 负责作业执行上下文与变量访问，供应链专题负责发行制品签名和消费者可信来源，主机、网络与 IaC 分别保留宿主、传输及资源声明职责。本规范针对**敏感值实际内容和生命周期**：值在哪里、哪一版本、谁在消费、何时生效、怎样撤销与能否恢复。后续发布编排专题负责工作负载切换，而本规范仅定义 Secret/配置与应用的兼容组合。L5 实施真实云商/SDK/工具，L6 批准生产密钥、客户数据、法律许可、费用与业务结果。

### 用语、强度与权威状态

Secret值/版本、源服务凭据、消费者缓存、已发会话为不同状态；KEK/DEK、签名Key、AAD用途不同；Lease只适用相应动态对象。

OPC指单人组织/单人公司画像；真实有权自然人可兼任多个职责，不因此虚构额外审批者或由工具角色取代业务授权。

“必须/不得”为本规范适用条件成立时的强制要求；“应/优先”为需给出可复核理由方可偏离的建议；“可”为许可选项。原有机制句及其验收为规范性合同，直接失败与合法邻例约束解释范围。外部来源的MUST/SHOULD保留其原强度，本规范自行加强的门禁不得倒称外部原文要求。

**共同不变量：** 编码不加密；Store切换不撤销目标旧凭据；Key材料轮换不自动重加密数据；恢复需要合法历史Key及权限。

**状态词：** 未开始、已受理、执行中、成功、失败、取消请求、结果未知分别记录；Timeout/取消请求不自动证明目标未执行。输出至少绑定对象不可变ID/版本、实际主体、目标环境、操作ID、观察时点及所见范围，秘密值不进入共享证据。

**兼容原则：** 按所选KeyType/Origin、Secret投影方式、版本/Lease/API与软删条件验证；合法短期缓存需有风险与撤权边界而非默认失控。

## 三、技术机制与逐条可观察合同

### §01 配置分类与敏感性
<a id="CLD-SEC-01"></a>

**稳定条款：** `CLD-SEC-01`（保留 `§01`）。

**机制：** 按实际用途将可公开配置、受限内部参数、Credential、Secret、密钥材料及其引用区分；实际可重放值不因名为 config 而降级保护。

**验收：** 前端或开放接口不得导出仍有效的生产 Token、私钥和其他受限值。

**主体、前置与输入：** 本条针对“配置分类与敏感性”；执行者必须具有目标范围的实际权限，消费 `CLD-SEC-T1` 的固定输入：参数类型/范围/必填、安全默认、文件/Env/CLI/远端优先级、环境与版本。

**权威状态与输出：** 实际应用配置解析与运行实例有效值；Git文件不独自权威。输出本条验收的原始观察及 `CLD-SEC-T1` 产物：来源胜出元数据、缺安全参数拒绝、当前应用-配置-Secret组合。不能从期望配置/请求成功越级推断该输出。

**并发、超时、未知与恢复：** 并发远端覆盖/热加载需读回每实例，旧配置不得晚到覆盖新版；超时保留当前安全态。记录本条对象版本与操作身份；冲突/部分成功/未观测项不并入成功，不以新请求覆盖原请求的未知结果。

**正例及判据：** 在上述明确目标/主体/版本和有效前置下，按可重放风险分类，阻断公开与核查泄漏；本条具体可观察验收仍为“前端或开放接口不得导出仍有效的生产 Token、私钥和其他受限值。”。合法操作与应有拒绝均须由实际目标结果而非仅配置文本确认。

**直接失败：** 真实 Token 被归类为普通配置并公开到前端资源。此时必须得到上述预期检查/失败诊断，不得登记本条整体通过。

**合法邻例与兼容：** 可公开功能参数可进入前端，不能混入可重放秘密。 与本条适用条件相容；不得为拒绝该合法情形而扩大外部规范或供应商限制。不同目标平台/版本的等效实现须保留同一输出不变量。

**真实检查入口：** 消费[ `CLD-SEC-T1` ](#CLD-SEC-T1)中的命令/API/项目入口，在同一隔离画像分别运行正例、上述失败输入和合法邻例；逐项比对本条验收，不以退出0单独替代资源、权限、业务或费用读回。有限来源命题：`SECRET-K8S`、`SECRET-AWS-ROTATE`；只支持第二节所列命题，不为整条实施结果背书。

**稳定条款：** `CLD-SEC-17`（保留 `§17`）。

**机制：** CSI、Sidecar、Volume、Env 与远端 API 具有不同的读值和刷新时序，应明示消费者何时感知版本变更。

**验收：** 挂载文件轮换但进程保留旧缓存时，刷新检查应识别未收敛。

**主体、前置与输入：** 本条针对“外部 Store/Sidecar 注入语义”；执行者必须具有目标范围的实际权限，消费 `CLD-SEC-T3` 的固定输入：Env/argv/挂载/Sidecar/CSI/SDK、属主权限、etcd加密、错误/日志出口。

**权威状态与输出：** 实际进程/Pod的Secret值可见域、注入方式与内核文件权限。输出本条验收的原始观察及 `CLD-SEC-T3` 产物：合法消费者可用、其他进程/容器拒绝；投影与进程生效时刻。不能从期望配置/请求成功越级推断该输出。

**并发、超时、未知与恢复：** subPath不自动刷新；Env与进程缓存需其实际重载；异常/崩溃转储脱敏，元数据读取不替代真实值生效。记录本条对象版本与操作身份；冲突/部分成功/未观测项不并入成功，不以新请求覆盖原请求的未知结果。

**必要补充与不变量：** Secret投影卷最终一致，subPath挂载不自动更新；Env/进程缓存不因API对象改变自动重载，逐消费者确认实际版本。

**正例及判据：** 在上述明确目标/主体/版本和有效前置下，验证真实消费者刷新时序；本条具体可观察验收仍为“挂载文件轮换但进程保留旧缓存时，刷新检查应识别未收敛。”。合法操作与应有拒绝均须由实际目标结果而非仅配置文本确认。

**直接失败：** Sidecar 注入新 Secret 但长运行进程仍读旧值。此时必须得到上述预期检查/失败诊断，不得登记本条整体通过。

**合法邻例与兼容：** 需重启的Env注入可合法，不得宣称文件刷新即进程热更新。 与本条适用条件相容；不得为拒绝该合法情形而扩大外部规范或供应商限制。不同目标平台/版本的等效实现须保留同一输出不变量。
