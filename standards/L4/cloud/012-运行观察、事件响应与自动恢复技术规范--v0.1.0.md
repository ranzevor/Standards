# L4 运行观察、事件响应与自动恢复技术规范

**文档ID：** STD-L4-CLOUD-012　**版本：** 0.1.0　**状态：** adopted　**生效日期：** 2026-10-30

## 一、目标、适用与非目标

**目标：** 使信号采集、告警投递、事故诊断、自动修复与真实恢复可分别观察。

**适用：** Metrics/Logs/Trace、OTLP/Collector、Alertmanager/平台告警、Runbook与事件处理。

**非目标：** 不以遥测代业务账，不把静默/告警解除当事故结案，不授予自动化生产变更权。

本 L4 云基础设施与 DevOps 第 10 项管理实际运行的主机、容器、托管服务、Serverless、队列与外部入口的遥测产生/接收/查询、告警送达、技术事故事实、受授权的自动处置及真实恢复验证。可用既有云平台日志、独立健康探针和必要告警完成轻量需求；不强制采购 APM/SIEM、Incident SaaS、Prometheus 集群或付费第三方代理。按实际客户、权限、成本和故障风险决定采样、保留、轮值与自动化范围。

与既有 L4 体系的职责分离：后端《可观测性、性能与容量》负责应用 SLI/SLO、Counter/Histogram/采样语义和请求层度量；云《弹性调度》负责资源供给/容量与扩缩，《发布编排》负责版本和流量控制，《配置、秘密管理》负责凭据/密钥值，云 IAM/网络/容器/IaC 分别拥有权限、入口、隔离和基础设施声明。本专题专门对**运行信号是否真实可得、报警是否送达、技术事故如何有据处理、自动修复如何受权且确认实际生效**建立机制，不复写相邻规范全文。L5 验证所选监控/集群/云 API 和 Runbook 版本，L6 决定客户、生产、合同、隐私、通知、数据/资金和最终业务结果。

### 用语、强度与权威状态

事件时间与观察时间分开；每跳ACK不等永久存储；Alert状态/通知抵达/人工ACK/修复结果各自独立；Unknown为未核明事实。

OPC指单人组织/单人公司画像；真实有权自然人可兼任多个职责，不因此虚构额外审批者或由工具角色取代业务授权。

“必须/不得”为本规范适用条件成立时的强制要求；“应/优先”为需给出可复核理由方可偏离的建议；“可”为许可选项。原有机制句及其验收为规范性合同，直接失败与合法邻例约束解释范围。外部来源的MUST/SHOULD保留其原强度，本规范自行加强的门禁不得倒称外部原文要求。

**共同不变量：** 不删原失败证据；部分成功不整包重试；迟到告警执行前核当前目标；自动化取消/超时后按目标操作ID核对。

**状态词：** 未开始、已受理、执行中、成功、失败、取消请求、结果未知分别记录；Timeout/取消请求不自动证明目标未执行。输出至少绑定对象不可变ID/版本、实际主体、目标环境、操作ID、观察时点及所见范围，秘密值不进入共享证据。

**兼容原则：** 固定信号协议稳定度、采样/保留/缺数策略和通知故障域；可选择小型本地观测但不得据局部视图宣称全健康。

## 三、技术机制与逐条可观察合同

### §01 运行观察选型与成本适配
<a id="CLD-OBS-01"></a>

**稳定条款：** `CLD-OBS-01`（保留 `§01`）。

**机制：** 针对实际采用的服务器、容器、Serverless、托管服务、消息/存储依赖和生产入口选择必要观察点；单机项目可采用既有平台日志/指标与健康检查，不强制购买 APM、SIEM、Kubernetes、商业 Incident 平台。

**验收：** 所选观测组件都有实际故障判断或运维用途、责任和有界存储费用；删去无关工具不损害必须的故障检测。

**主体、前置与输入：** 本条针对“运行观察选型与成本适配”；执行者必须具有目标范围的实际权限，消费 `CLD-OBS-T1` 的固定输入：Host/Service/Region/Queue依赖、代码/配置/Resource属性、外部探针与受众权。

**权威状态与输出：** 真实服务/版本/入口与信号产生者；业务账本另有权威。输出本条验收的原始观察及 `CLD-OBS-T1` 产物：白盒/外部入口互补及租户/隐私权限矩阵。不能从期望配置/请求成功越级推断该输出。

**并发、超时、未知与恢复：** 版本重用或信号盲区保持局部/Unknown，不以PodReady或Trace存在推全部健康。记录本条对象版本与操作身份；冲突/部分成功/未观测项不并入成功，不以新请求覆盖原请求的未知结果。

**正例及判据：** 在上述明确目标/主体/版本和有效前置下，以真实入口及现有平台能力实现必要检测并避免无依据采购；本条具体可观察验收仍为“所选观测组件都有实际故障判断或运维用途、责任和有界存储费用；删去无关工具不损害必须的故障检测。”。合法操作与应有拒绝均须由实际目标结果而非仅配置文本确认。

**直接失败：** 个人单服务器服务被强制购买企业商业 APM 而没有独立观察需求。此时必须得到上述预期检查/失败诊断，不得登记本条整体通过。

**合法邻例与兼容：** 既有平台日志与独立探针可满足单机目标，不必外购APM。 与本条适用条件相容；不得为拒绝该合法情形而扩大外部规范或供应商限制。不同目标平台/版本的等效实现须保留同一输出不变量。

**真实检查入口：** 消费[ `CLD-OBS-T1` ](#CLD-OBS-T1)中的命令/API/项目入口，在同一隔离画像分别运行正例、上述失败输入和合法邻例；逐项比对本条验收，不以退出0单独替代资源、权限、业务或费用读回。有限来源命题：`K8S-PROBES`、`OTEL-METRICS`、`OTEL-LOGS`；只支持第二节所列命题，不为整条实施结果背书。

## 五、真实目标工具/API与验收产物合同

以下为按实际采用组件选择的目标入口，不是要求安装全部平台。命令中的变量必须在L5绑定为非秘密的确定对象ID与隔离测试资源，API名必须补齐所选SDK/CLI版本、完整参数及超时。项目专有入口须固定仓库路径、参数、数据夹具与预期退出/响应；缺少此绑定不得判该目标验收通过。Shell命令、HTTP/API名和故障注入动作分别标识，不将自然语言API列表当可直接复制的单条命令。

每个执行产物包括工具版本、目标账户/Region/集群/运行实例、实际Principal、输入/制品摘要、操作/请求ID、起止时点、退出/HTTP状态、资源/数据读回和覆盖边界。对每条至少保留正例/直接失败/合法邻例，不适用需给出不存在相应能力/承诺的理由。

### CLD-OBS-T1
<a id="CLD-OBS-T1"></a>

**权威与主体：** 真实服务/版本/入口与信号产生者；业务账本另有权威。

**固定输入：** Host/Service/Region/Queue依赖、代码/配置/Resource属性、外部探针与受众权。

**实际入口：** 实际外部curl有界探针、kubectl get pods -A -o json；kubectl get nodes -o json及服务版本元数据；所用OTel/平台Resource/Log/Trace查询，合成正反角色。

**故障恢复：** 版本重用或信号盲区保持局部/Unknown，不以PodReady或Trace存在推全部健康。

**通过/失败判据：** 本组中每个条款的验收逐项满足，直接失败得到拒绝/诊断/正确恢复、合法邻例不被误拒；任何Unknown、未覆盖平台/权限或关键产物缺失分别保留，不允许从组内其他成功项外推。退出0、Accepted、配置已保存只证明其各自层次。
