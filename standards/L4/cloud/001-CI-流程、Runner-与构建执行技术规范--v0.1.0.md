# L4 CI 流程、Runner 与构建执行技术规范

**文档ID：** STD-L4-CLOUD-001　**版本：** 0.1.0　**状态：** adopted　**生效日期：** 2026-10-30

## 一、目标、适用与非目标

**目标：** 使触发输入、执行环境、权限、缓存/制品和检查结论保持可信闭环。

**适用：** 实际采用的CI事件、Workflow/Pipeline、Hosted/自托管Runner、构建与部署任务。

**非目标：** 不把CI Success当真实发布/业务验收，不要求未用平台或长期Runner，不向不可信构建暴露生产Secret。

本 L4 云基础设施与 DevOps 第 5 项独立技术规范只针对真实使用的 CI 流水线、Runner/Executor、构建依赖、工作流权限、缓存与制品、验证结果、重跑、部署准入和执行成本设立技术门禁。单人项目可选择 GitHub Actions、GitLab CI、现有云平台构建能力或受控本地 CI，不强制自托管 Runner、付费执行服务或复杂编排器。

L1—L3 与 OPC 保留组织的审批和协作权威；相应云 IAM 专题负责账户/机器身份和云策略，云网络、容器宿主和 IaC 专题分别负责网络入口、运行隔离和 State/Plan。此 CI 专题只处理执行信任、触发、Runner、测试及构建输出的技术事实，不预先制定软件供应链签名/发行等级、业务支付或任何生产许可。L5 采用实际 CI 平台、Runner/OS、工具链和版本；L6 由有权主体确认生产发布、客户数据、费用、合同及业务结果。

### 用语、强度与权威状态

触发主体/Ref/事件决定信任；Run/Attempt/Job标识一次执行；Cache为非权威优化；Artifact为需绑定摘要与来源的交接物。

OPC指单人组织/单人公司画像；真实有权自然人可兼任多个职责，不因此虚构额外审批者或由工具角色取代业务授权。

“必须/不得”为本规范适用条件成立时的强制要求；“应/优先”为需给出可复核理由方可偏离的建议；“可”为许可选项。原有机制句及其验收为规范性合同，直接失败与合法邻例约束解释范围。外部来源的MUST/SHOULD保留其原强度，本规范自行加强的门禁不得倒称外部原文要求。

**共同不变量：** 不可信输入不可跨入有Secret/生产写权的执行路径；取消不证明云动作已撤销；同名Check不证明当前正确提交已检查。

**状态词：** 未开始、已受理、执行中、成功、失败、取消请求、结果未知分别记录；Timeout/取消请求不自动证明目标未执行。输出至少绑定对象不可变ID/版本、实际主体、目标环境、操作ID、观察时点及所见范围，秘密值不进入共享证据。

**兼容原则：** GitHub与GitLab事件、缓存、并发策略分别核；临时Runner注册与持久宿主清洁分开；项目构建命令由锁定工具链提供。

## 三、技术机制与逐条可观察合同

### §01 执行范围与工具成本
<a id="CLD-CI-01"></a>

**稳定条款：** `CLD-CI-01`（保留 `§01`）。

**机制：** 只对项目实际采用的仓库、构建、验证和发布流程选择 CI 平台；单人低复杂度项目可以用受控最小流水线，不强制新增 Kubernetes、付费 CI/CD 平台或专用调度集群。

**验收：** 每项 Job/服务均对应真实交付义务和费用预算，无用的依赖/新增基础设施能够去除而不影响必要验收。

**主体、前置与输入：** 本条针对“执行范围与工具成本”；执行者必须具有目标范围的实际权限，消费 `CLD-CI-T1` 的固定输入：push/PR/target/workflow_run/schedule及手动输入、Base/Head、必要Check与重复请求ID。

**权威状态与输出：** 真实事件payload、仓库/Ref/SHA和平台Run；事件类型决定信任上下文。输出本条验收的原始观察及 `CLD-CI-T1` 产物：事件到正确源码/目标的映射和低信任不能跃迁的证据。不能从期望配置/请求成功越级推断该输出。

**并发、超时、未知与恢复：** HEAD变更后旧Check失效；迟到/重跑仍核当前版本；相同业务请求不得双副作用。记录本条对象版本与操作身份；冲突/部分成功/未观测项不并入成功，不以新请求覆盖原请求的未知结果。

**正例及判据：** 在上述明确目标/主体/版本和有效前置下，允许具备可追溯证据的轻量 CI，不成立无依据采购门禁；本条具体可观察验收仍为“每项 Job/服务均对应真实交付义务和费用预算，无用的依赖/新增基础设施能够去除而不影响必要验收。”。合法操作与应有拒绝均须由实际目标结果而非仅配置文本确认。

**直接失败：** 小型静态站点被要求购买独立企业 CI 编排服务。此时必须得到上述预期检查/失败诊断，不得登记本条整体通过。

**合法邻例与兼容：** 已有本地受控流水线可满足低复杂度项目，不必购买托管分钟。 与本条适用条件相容；不得为拒绝该合法情形而扩大外部规范或供应商限制。不同目标平台/版本的等效实现须保留同一输出不变量。

**真实检查入口：** 消费[ `CLD-CI-T1` ](#CLD-CI-T1)中的命令/API/项目入口，在同一隔离画像分别运行正例、上述失败输入和合法邻例；逐项比对本条验收，不以退出0单独替代资源、权限、业务或费用读回。有限来源命题：`GH-SECURE`、`GH-OIDC`、`GH-CONCURRENCY`；只支持第二节所列命题，不为整条实施结果背书。

## 五、真实目标工具/API与验收产物合同

以下为按实际采用组件选择的目标入口，不是要求安装全部平台。命令中的变量必须在L5绑定为非秘密的确定对象ID与隔离测试资源，API名必须补齐所选SDK/CLI版本、完整参数及超时。项目专有入口须固定仓库路径、参数、数据夹具与预期退出/响应；缺少此绑定不得判该目标验收通过。Shell命令、HTTP/API名和故障注入动作分别标识，不将自然语言API列表当可直接复制的单条命令。

**通过/失败判据：** 本组中每个条款的验收逐项满足，直接失败得到拒绝/诊断/正确恢复、合法邻例不被误拒；任何Unknown、未覆盖平台/权限或关键产物缺失分别保留，不允许从组内其他成功项外推。退出0、Accepted、配置已保存只证明其各自层次。
