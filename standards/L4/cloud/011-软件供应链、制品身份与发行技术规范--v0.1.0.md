# L4 软件供应链、制品身份与发行技术规范

**文档ID：** STD-L4-CLOUD-011　**版本：** 0.1.0　**状态：** adopted　**生效日期：** 2026-10-30

## 一、目标、适用与非目标

**目标：** 把输入、构建、制品、证明、签发与最终消费者连成可验证发行链。

**适用：** 镜像/包/安装器、Registry、SBOM/VEX、SLSA/in-toto/DSSE/Sigstore或更新元数据。

**非目标：** 不宣称摘要/签名能证明软件无恶意，不强制每项目SLSAL3/TUF，不代许可/商标/再分发权审查。

本 L4 云基础设施与 DevOps 第 6 项规范管理实际发布的可执行文件、语言生态包、OCI 镜像、安装器、软件更新包及其依赖、SBOM、Provenance、签名、Registry 发行记录与下游消费验证。不将源码提交、普通 CI Artifact 或一张绿色检查徽章直接当作已获授权的发行物。项目若无对外发行需求，可保留已有受控内部制品传递方式；确需对外分发时按产品风险和实际消费路径选择适当门禁，不强制所有项目购买签名平台或满足 SLSA 固定等级。

与《CI 流程、Runner 与构建执行》边界明确：CI 专题对触发、Runner、作业权限、Cache、验证任务与产出移交负责；本专题只对构建输出的实际字节、来源证明、发行身份、完整性、发布渠道及消费者核验负责。云 IAM、网络、主机/容器、IaC 继续分别管理授权主体、流量、安全运行边界与基础设施状态；后续密钥、发布编排、事故响应专题处理各自专门机制。L5 负责选用工具、Registry/包生态、签名服务及验证器版本的真实实施；L6 负责批准生产发布、商业/许可权利、客户通知、资金和真实终端验收。

### 用语、强度与权威状态

Digest=具体字节内容定位；Signer/Builder/Publisher/Consumer为不同身份；Attestation=带Subject/类型的声明；Tag为可变指针。

OPC指单人组织/单人公司画像；真实有权自然人可兼任多个职责，不因此虚构额外审批者或由工具角色取代业务授权。

“必须/不得”为本规范适用条件成立时的强制要求；“应/优先”为需给出可复核理由方可偏离的建议；“可”为许可选项。原有机制句及其验收为规范性合同，直接失败与合法邻例约束解释范围。外部来源的MUST/SHOULD保留其原强度，本规范自行加强的门禁不得倒称外部原文要求。

**共同不变量：** 消费者核实际分发字节及允许Signer–Builder组合；签名存在不等策略允许；内容不可变与可撤销信任/读取权独立。

**状态词：** 未开始、已受理、执行中、成功、失败、取消请求、结果未知分别记录；Timeout/取消请求不自动证明目标未执行。输出至少绑定对象不可变ID/版本、实际主体、目标环境、操作ID、观察时点及所见范围，秘密值不进入共享证据。

**兼容原则：** 分清OCI Image/Distribution/Runtime、格式版本与发布包补丁版、平台ABI；可信根/历史签署时间和合法回退按实际画像保持。

## 三、技术机制与逐条可观察合同

### §01 范围与发行对象
<a id="CLD-SUP-01"></a>

**稳定条款：** `CLD-SUP-01`（保留 `§01`）。

**机制：** 以实际交付的安装包、容器镜像、语言包、固件或可下载文件为供应链对象，记录发布方、消费者、权限及目标风险；项目不因使用 CI 就必须采购商业签名服务。

**验收：** 每种启用的发行物有清楚的制品类型、消费者、发行渠道及负责主体；无需发行的内部实验输出不被错误强制公开。

**主体、前置与输入：** 本条针对“范围与发行对象”；执行者必须具有目标范围的实际权限，消费 `CLD-SUP-T1` 的固定输入：直接/传递/可选依赖锁、包源/子模块Ref、基础Manifest、下载摘要及平台条件。

**权威状态与输出：** 实际依赖解析器/受信源与构建材料清单；名称不是内容身份。输出本条验收的原始观察及 `CLD-SUP-T1` 产物：解析后输入闭包与单字节/依赖混淆替换拒绝。不能从期望配置/请求成功越级推断该输出。

**并发、超时、未知与恢复：** 上游Tag/分支/包响应变化需重绑受审输入；缓存只能加速，不把未核来源产物提升。记录本条对象版本与操作身份；冲突/部分成功/未观测项不并入成功，不以新请求覆盖原请求的未知结果。

**正例及判据：** 在上述明确目标/主体/版本和有效前置下，按实际交付对象选择低固定成本且可追溯的方案，未经需求不能强制采购；本条具体可观察验收仍为“每种启用的发行物有清楚的制品类型、消费者、发行渠道及负责主体；无需发行的内部实验输出不被错误强制公开。”。合法操作与应有拒绝均须由实际目标结果而非仅配置文本确认。

**直接失败：** 小型仅内部使用的 CLI 被要求购买外部企业发行认证服务。此时必须得到上述预期检查/失败诊断，不得登记本条整体通过。

**合法邻例与兼容：** 未对外发行的内部实验可用受控传递，不强制公开发布。 与本条适用条件相容；不得为拒绝该合法情形而扩大外部规范或供应商限制。不同目标平台/版本的等效实现须保留同一输出不变量。

**真实检查入口：** 消费[ `CLD-SUP-T1` ](#CLD-SUP-T1)中的命令/API/项目入口，在同一隔离画像分别运行正例、上述失败输入和合法邻例；逐项比对本条验收，不以退出0单独替代资源、权限、业务或费用读回。有限来源命题：`OCI-IMAGE`、`SUP-SLSA`；只支持第二节所列命题，不为整条实施结果背书。

**并发、超时、未知与恢复：** 上游Tag/分支/包响应变化需重绑受审输入；缓存只能加速，不把未核来源产物提升。记录本条对象版本与操作身份；冲突/部分成功/未观测项不并入成功，不以新请求覆盖原请求的未知结果。

**正例及判据：** 在上述明确目标/主体/版本和有效前置下，解析到的完整版本/校验和及受信来源必须可验证，变动不得静默放行；本条具体可观察验收仍为“在锁定依赖未变情况下将包源响应换成不同字节应被摘要或可信来源检查发现。”。合法操作与应有拒绝均须由实际目标结果而非仅配置文本确认。

**合法邻例与兼容：** 版本范围可表达兼容意图，正式材料仍记录解析结果和内容摘要。 与本条适用条件相容；不得为拒绝该合法情形而扩大外部规范或供应商限制。不同目标平台/版本的等效实现须保留同一输出不变量。
