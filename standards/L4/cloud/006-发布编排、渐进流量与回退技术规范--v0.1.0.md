# L4 发布编排、渐进流量与回退技术规范

**文档ID：** STD-L4-CLOUD-006　**版本：** 0.1.0　**状态：** adopted　**生效日期：** 2026-10-30

## 一、目标、适用与非目标

**目标：** 分别验证代码生效、流量推进、持久数据兼容与有权回退。

**适用：** Deployment/Revision、滚动/蓝绿/金丝雀、GitOps/FeatureFlag、长连接与消费者。

**非目标：** 不把0%流量当全部代码停止，不把代码Rollback当数据补偿，不决定客户合同/价格/通知权。

本 L4 云基础设施与 DevOps 第 8 项规定已具备可发行版本的工作负载如何经受权控制面进入真实流量、实施滚动/蓝绿/灰度、阶段性健康分析、人工暂停、功能开关、流量回退和完整交付确认。适用于实际使用的服务器、容器、边缘 Worker、Serverless、Web 静态部署与移动/桌面发布配套的服务端切换；没有渐进流量条件的低风险单实例项目可选择受控替换和适当恢复策略，不强制引入 Kubernetes、Service Mesh、Argo、Flagger、额外多环境或付费服务。

职责分界：CI/Runner 专题负责构建作业的触发、执行与检查；供应链专题负责制品来源、摘要、签名与发行准入；配置/秘密专题负责密钥内容、版本、注入和轮换；云 IAM/网络/主机/IaC 分别对账号权限、服务入口、计算隔离与基础设施真实状态负责。本专题管理**何时、向谁、以何条件让哪个已验证版本真正生效及退出**。后端跨版本与数据库专题继续负责协议/事务/Schema 语义及数据恢复，Web 发行专题负责客户端缓存及版本协调；本专题负责部署阶段依赖与互操作验收，不重写其他领域的技术条款。L5 按实际控制器及平台版本实施，L6 独立批准生产数据权利、真实发布、客户影响、费用及业务终态。

### 用语、强度与权威状态

版本=不可变代码/配置身份；路由权重=期望分配；分析=所见样本决策；恢复终态按流量/代码/配置/持久数据分别记录。

OPC指单人组织/单人公司画像；真实有权自然人可兼任多个职责，不因此虚构额外审批者或由工具角色取代业务授权。

“必须/不得”为本规范适用条件成立时的强制要求；“应/优先”为需给出可复核理由方可偏离的建议；“可”为许可选项。原有机制句及其验收为规范性合同，直接失败与合法邻例约束解释范围。外部来源的MUST/SHOULD保留其原强度，本规范自行加强的门禁不得倒称外部原文要求。

**共同不变量：** 任何放量绑定当前目标/材料/分析；缺数不伪装零错误；旧控制器/迟到批准不能覆盖新状态；持久数据不可被代码成功掩盖。

**状态词：** 未开始、已受理、执行中、成功、失败、取消请求、结果未知分别记录；Timeout/取消请求不自动证明目标未执行。输出至少绑定对象不可变ID/版本、实际主体、目标环境、操作ID、观察时点及所见范围，秘密值不进入共享证据。

**兼容原则：** 按当前/上一受支持代码、Schema、消息、缓存与客户端矩阵验；平台不支持自动回退时保持失败/暂停而不伪造成功。

## 三、技术机制与逐条可观察合同

### §01 发行对象与控制面选择
<a id="CLD-REL-01"></a>

**稳定条款：** `CLD-REL-01`（保留 `§01`）。

**机制：** 识别实际生产或预发布入口、被切换的应用、异步消费者及读写路径；按风险选择单机更新、托管 Revision 或渐进发布，不能无需求地强制部署 Kubernetes、Service Mesh 或付费发布平台。

**验收：** 每项选用的控制面对应明确服务/客户端和切换必要性；单部署目标无额外无用依赖或采购。

**主体、前置与输入：** 本条针对“发行对象与控制面选择”；执行者必须具有目标范围的实际权限，消费 `CLD-REL-T1` 的固定输入：发布模式initial/upgrade、候选Digest和Config/Secret/Schema、入口/消费者、批准/阶段/预算；upgrade固定旧稳定版本与兼容恢复材料，initial固定未部署/安全停服基线、可撤入口、新资源归属及数据/外部效果处置。

**权威状态与输出：** 目标路由/部署控制面当前版本与有效发布主体；单一目标主权。输出本条验收的原始观察及 `CLD-REL-T1` 产物：按模式记录期望/实况版本、路由/消费者、依赖就绪和批准；升级保留旧稳定恢复元组，首次上线保留无流量/安全停服及新资源范围；无权切流或缺适用恢复目标必须拒绝。不能从期望配置/请求成功越级推断该输出。

**并发、超时、未知与恢复：** 并行控制器用条件/栅栏；Unknown先核不放量；升级依兼容合同恢复旧版本或受权前向修复，首发撤路由/停新负载并核在途副作用，只回收本次新增且无共享/保留依赖的资源，取消不等于远端已撤。记录本条对象版本与操作身份；冲突/部分成功/未观测项不并入成功，不以新请求覆盖原请求的未知结果。

**正例及判据：** 在上述明确目标/主体/版本和有效前置下，以实际交付路径和成本确定必要控制面，不能新增无效采购；本条具体可观察验收仍为“每项选用的控制面对应明确服务/客户端和切换必要性；单部署目标无额外无用依赖或采购。”。合法操作与应有拒绝均须由实际目标结果而非仅配置文本确认。

**直接失败：** 一个内部单机工具被无条件要求采购企业级 Service Mesh 才能发布。此时必须得到上述预期检查/失败诊断，不得登记本条整体通过。

**合法邻例与兼容：** 低风险单实例可受控替换，不强制引入灰度控制器。 与本条适用条件相容；不得为拒绝该合法情形而扩大外部规范或供应商限制。不同目标平台/版本的等效实现须保留同一输出不变量。

**真实检查入口：** 消费[ `CLD-REL-T1` ](#CLD-REL-T1)中的命令/API/项目入口，在同一隔离画像分别运行正例、上述失败输入和合法邻例；逐项比对本条验收，不以退出0单独替代资源、权限、业务或费用读回。有限来源命题：`REL-K8S`、`REL-CLOUDRUN`、`REL-WORKERS`；只支持第二节所列命题，不为整条实施结果背书。

**验收：** Argo 控制器失联，操作者反复发送 Promote 导致发布状态未知时应保留冻结与实况核验。

**主体、前置与输入：** 本条针对“替代路径与控制面失联”；执行者必须具有目标范围的实际权限，消费 `CLD-REL-T8` 的固定输入：版本/权重/时间/群组、低频任务、旧轨GC/账单、控制器失联与有权恢复路径。

**权威状态与输出：** 分阶段真实消费者、稳定观察窗、保留/成本与替代控制路径。输出本条验收的原始观察及 `CLD-REL-T8` 产物：用户群组业务结果、观察完成条件、旧资源清理及真实L5/L6结果。不能从期望配置/请求成功越级推断该输出。

**并发、超时、未知与恢复：** 100%流量不结束低频观测；旧轨仅在恢复窗口结束后清理；失联冻结新变更不盲Promote。记录本条对象版本与操作身份；冲突/部分成功/未观测项不并入成功，不以新请求覆盖原请求的未知结果。

**正例及判据：** 在上述明确目标/主体/版本和有效前置下，冻结新写入并核对实际目标、依赖和权威状态；本条具体可观察验收仍为“Argo 控制器失联，操作者反复发送 Promote 导致发布状态未知时应保留冻结与实况核验。”。合法操作与应有拒绝均须由实际目标结果而非仅配置文本确认。

**直接失败：** 流量控制器失联仍重复执行 Promote，不知哪个版本正在接流量。此时必须得到上述预期检查/失败诊断，不得登记本条整体通过。

**合法邻例与兼容：** 控制面失联可维持已确认稳定流量，不靠重复Promote猜状态。 与本条适用条件相容；不得为拒绝该合法情形而扩大外部规范或供应商限制。不同目标平台/版本的等效实现须保留同一输出不变量。

**真实检查入口：** 消费[ `CLD-REL-T8` ](#CLD-REL-T8)中的命令/API/项目入口，在同一隔离画像分别运行正例、上述失败输入和合法邻例；逐项比对本条验收，不以退出0单独替代资源、权限、业务或费用读回。有限来源命题：`REL-K8S`、`REL-CLOUDRUN`、`COST-FOCUS`；只支持第二节所列命题，不为整条实施结果背书。

## 五、真实目标工具/API与验收产物合同

以下为按实际采用组件选择的目标入口，不是要求安装全部平台。命令中的变量必须在L5绑定为非秘密的确定对象ID与隔离测试资源，API名必须补齐所选SDK/CLI版本、完整参数及超时。项目专有入口须固定仓库路径、参数、数据夹具与预期退出/响应；缺少此绑定不得判该目标验收通过。Shell命令、HTTP/API名和故障注入动作分别标识，不将自然语言API列表当可直接复制的单条命令。

每个执行产物包括工具版本、目标账户/Region/集群/运行实例、实际Principal、输入/制品摘要、操作/请求ID、起止时点、退出/HTTP状态、资源/数据读回和覆盖边界。对每条至少保留正例/直接失败/合法邻例，不适用需给出不存在相应能力/承诺的理由。

### CLD-REL-T1
<a id="CLD-REL-T1"></a>

**权威与主体：** 目标路由/部署控制面当前版本与有效发布主体；单一目标主权。

**固定输入：** 发布模式initial/upgrade、候选Digest和Config/Secret/Schema、入口/消费者、批准/阶段/预算；upgrade固定旧稳定版本与兼容恢复材料，initial固定未部署/安全停服基线、可撤入口、新资源归属及数据/外部效果处置。

**实际入口：** kubectl get deployment,service -n "$NS" -o json；目标Cloud Run/Workers Revision与Deployment读API；当前入口版本只读请求。

**必须产物/观察：** 按模式记录期望/实况版本、路由/消费者、依赖就绪和批准；升级保留旧稳定恢复元组，首次上线保留无流量/安全停服及新资源范围；无权切流或缺适用恢复目标必须拒绝。

**故障恢复：** 并行控制器用条件/栅栏；Unknown先核不放量；升级依兼容合同恢复旧版本或受权前向修复，首发撤路由/停新负载并核在途副作用，只回收本次新增且无共享/保留依赖的资源，取消不等于远端已撤。

**通过/失败判据：** 本组中每个条款的验收逐项满足，直接失败得到拒绝/诊断/正确恢复、合法邻例不被误拒；任何Unknown、未覆盖平台/权限或关键产物缺失分别保留，不允许从组内其他成功项外推。退出0、Accepted、配置已保存只证明其各自层次。

### CLD-REL-T3
<a id="CLD-REL-T3"></a>

**逐条失败与邻例判据：**
- `CLD-REL-14`：失败条件为“Cloud Run 切回旧 Revision 后仍有新版本在途请求，平台却宣称所有新版本副作用已消失”；邻例为“切流后兼容的在途旧/新版本请求可在声明排水窗口内继续完成；分开报告路由回退、在途状态和业务副作用，不虚称全部消失。”

**权威与主体：** 实际Router权重/会话算法与所有异步/直连入口。

**故障恢复：** 传播/在途/长连接仍可运行旧或新版本；切回路由不自动取消其副作用，未知操作按业务ID核。

### CLD-REL-T4
