# L4 主机、虚拟化、容器与运行隔离技术规范

**文档ID：** STD-L4-CLOUD-002　**版本：** 0.1.0　**状态：** adopted　**生效日期：** 2026-10-30

## 一、目标、适用与非目标

**目标：** 用真实宿主、Runtime、内核及负载验证运行隔离和故障恢复。

**适用：** 自建/托管主机、VM、Linux/Windows容器、CRI/OCI、挂载、设备及调度器。

**非目标：** 不以容器代敌对租户强边界，不认证所有Hypervisor，不接管数据库事务或客户授权。

本 L4 云基础设施与 DevOps 第 3 项独立专题针对实际采用的物理宿主、虚拟机、进程/容器 Runtime、OCI 配置、容器运行用户、Namespace、cgroup、LSM/Seccomp、Pod 安全准入、Host Mount 与数据生命周期。未采用容器/VM 的托管站点不承担无关技术门禁，不强制新增 Kubernetes、MicroVM、商业安全平台或多节点资源。

相应云领域通用基线负责基础设施总体工程条件，第 1 项云 IAM 负责身份/资源授权，第 2 项云网络负责 DNS/防火墙/入口。此专题只深入主机、Guest Kernel、Runtime 和工作负载操作系统隔离，不替代 CI/Runner 构建来源、容器发行签名、云防火墙、数据库权威写入、完整灾备或商业采购流程。L5 按实际 Kernel/Windows/CRI/VM/Runtime 版本实施，L6 对真实客户资源、合同、费用及生产业务结果独立批准。

### 用语、强度与权威状态

Rootless=Daemon及容器非root；Remap=容器ID映射而Daemon可root；隔离边界=实际共享Kernel/Namespace/Hypervisor；资源约束=最终cgroup/调度条件。

OPC指单人组织/单人公司画像；真实有权自然人可兼任多个职责，不因此虚构额外审批者或由工具角色取代业务授权。

“必须/不得”为本规范适用条件成立时的强制要求；“应/优先”为需给出可复核理由方可偏离的建议；“可”为许可选项。原有机制句及其验收为规范性合同，直接失败与合法邻例约束解释范围。外部来源的MUST/SHOULD保留其原强度，本规范自行加强的门禁不得倒称外部原文要求。

**共同不变量：** 镜像Digest正确不证明Runtime安全；只读RootFS不覆盖另挂卷；重启/驱逐不回滚外部操作。

**状态词：** 未开始、已受理、执行中、成功、失败、取消请求、结果未知分别记录；Timeout/取消请求不自动证明目标未执行。输出至少绑定对象不可变ID/版本、实际主体、目标环境、操作ID、观察时点及所见范围，秘密值不进入共享证据。

**兼容原则：** 按真实OS/ABI/Kernel/Runtime/Controller与FeatureGate固定画像；未使用Windows/GPU/LSM能力不强制安装，但相关承诺不得虚报。

## 三、技术机制与逐条可观察合同

### §01 真实运行形态与成本
<a id="CLD-ISO-01"></a>

**稳定条款：** `CLD-ISO-01`（保留 `§01`）。

**机制：** 按应用风险、负载、宿主共享程度与预算选用物理主机、VM、托管容器、进程隔离容器或微虚拟机；无需容器的项目不强制部署容器平台。

**验收：** 每个运行形态与真实业务、隔离和成本对应；移除无用集群不影响合法交付。

**主体、前置与输入：** 本条针对“真实运行形态与成本”；执行者必须具有目标范围的实际权限，消费 `CLD-ISO-T1` 的固定输入：威胁模型、可信/敌对租户、Host/Image Build、节点角色和共享资源。

**权威状态与输出：** 真实Host/Guest Kernel/Hypervisor及云元数据身份，不是容器或VM标签。输出本条验收的原始观察及 `CLD-ISO-T1` 产物：选用隔离边界与跨租户/元数据访问正反结果。不能从期望配置/请求成功越级推断该输出。

**并发、超时、未知与恢复：** 宿主/Guest失联保持受影响邻接对象Unknown；不可用不改为privileged恢复；先隔离原运行实例。记录本条对象版本与操作身份；冲突/部分成功/未观测项不并入成功，不以新请求覆盖原请求的未知结果。

**正例及判据：** 在上述明确目标/主体/版本和有效前置下，保留现有托管运行路径，无依据的新增固定开支必须取消；本条具体可观察验收仍为“每个运行形态与真实业务、隔离和成本对应；移除无用集群不影响合法交付。”。合法操作与应有拒绝均须由实际目标结果而非仅配置文本确认。

**直接失败：** 简单静态网站被要求先购买专用 Hypervisor/Kubernetes 集群。此时必须得到上述预期检查/失败诊断，不得登记本条整体通过。

**合法邻例与兼容：** 托管进程运行可不引入VM/容器，只需匹配真实隔离需求。 与本条适用条件相容；不得为拒绝该合法情形而扩大外部规范或供应商限制。不同目标平台/版本的等效实现须保留同一输出不变量。

**真实检查入口：** 消费[ `CLD-ISO-T1` ](#CLD-ISO-T1)中的命令/API/项目入口，在同一隔离画像分别运行正例、上述失败输入和合法邻例；逐项比对本条验收，不以退出0单独替代资源、权限、业务或费用读回。有限来源命题：`ISO-WINDOWS`、`ISO-ROOTLESS`；只支持第二节所列命题，不为整条实施结果背书。

- `CLD-ISO-38`：失败条件为“PreStop 耗尽终止预算后被 SIGKILL，已接收的必要请求既无完成回执也无持久恢复记录，平台仍将这些请求静默丢弃”；邻例为“已接收请求均已完成或有准确持久恢复记录时，可走约定的超时强制终止；恢复中的请求保留未完成，不能把SIGKILL本身一律当失败。”
- `CLD-ISO-42`：失败条件为“在明确要求单写的存储/数据库作用域，两个节点的副本未受有效协调或旧写者隔离却同时修改同一持久状态”；邻例为“有明确产品支持并验证协调、锁及数据完整性的共享存储多实例或多主可以合法；单写协议仍须拒绝旧写者，不能以多副本配置冒充协议。”

**逐条失败与邻例判据：**
- `CLD-ISO-37`：失败条件为“Deployment 创建成功，但受 Restricted 准入影响的 Pod 全部被拒，平台仍报告交付成功”；邻例为“Deployment被接受但Pod拒绝可为正确Admission结果，交付仍未完成。”
