# L4 成本治理、资源退役与持续交付能力技术规范

**文档ID：** STD-L4-CLOUD-010　**版本：** 0.1.0　**状态：** adopted　**生效日期：** 2026-10-30

## 一、目标、适用与非目标

**目标：** 核准费用计量、限幅、持续收费残留与合法退役/退出。

**适用：** 云账单/导出、预算告警/动作/Cap、资源/合同、FinOps与交付效能度量。

**非目标：** 不把降低安全/备份当默认优化，不由标签决定费用授权，不强制付费成本产品。

本 L4 云基础设施与 DevOps 第 12 项管理已选基础设施和交付工具的实际计费使用、预算监测、异常成本、资源存废和退出、以及持续交付技术能力的可验证成本/效能边界。对于个人独立研发、小型项目或已有受控云服务，不强制部署商业 FinOps、Kubernetes/OpenCost、跨多云分析平台、企业交付看板或付费计费管道。真实采购/合同/预算/客户权益由 L6 有权主体独立决定，本规范不自行新增任何费用或持久性运营任务。

与前十一项云专题的责任分离：云 IAM/网络/主机/IaC 负责资源身份、网络、隔离及声明状态；CI/Runner 负责构建验证的可信执行，供应链负责制品发行身份，配置/密钥管理、发布编排、容量调度、事故与备份 DR 各保留具体技术准入与恢复语义。本专题只规定成本事实、费用归属/计量、技术预算限幅、资产识别与退役验证、交付通道持续可用的工程决策与证据；不会因“省钱”自行覆盖真实密钥/客户数据、灾备目标、发布授权或合同。L5 选择实际供应商、产品和工具版本测算实现；L6 独立批准财务、客户、法律和生产业务结果。

### 用语、强度与权威状态

Billed/Effective/List为不同口径；Unallocated不是零；Alert/Configured/Enforced与实际拒新工作分开；技术退役不等最终结清。

OPC指单人组织/单人公司画像；真实有权自然人可兼任多个职责，不因此虚构额外审批者或由工具角色取代业务授权。

“必须/不得”为本规范适用条件成立时的强制要求；“应/优先”为需给出可复核理由方可偏离的建议；“可”为许可选项。原有机制句及其验收为规范性合同，直接失败与合法邻例约束解释范围。外部来源的MUST/SHOULD保留其原强度，本规范自行加强的门禁不得倒称外部原文要求。

**共同不变量：** 不得双算覆盖费用或混币种/账期；未知/延迟账单仍保留负债；限幅含在途/固定承诺/残留；删除/脱管/移交分别核。

**状态词：** 未开始、已受理、执行中、成功、失败、取消请求、结果未知分别记录；Timeout/取消请求不自动证明目标未执行。输出至少绑定对象不可变ID/版本、实际主体、目标环境、操作ID、观察时点及所见范围，秘密值不进入共享证据。

**兼容原则：** 按供应商真实Schema/费用更新窗口及所选FOCUS版映射；同负载同SLO/RPO/币种口径对比，DORA五指标结合服务上下文。

## 三、技术机制与逐条可观察合同

### §01 资源成本边界与最小治理
<a id="CLD-COST-01"></a>

**稳定条款：** `CLD-COST-01`（保留 `§01`）。

**机制：** 依据业务实际需要界定需要核算的服务器、云账号、托管服务、域名、存储、CI、监控、数据出口与 SaaS；单人小项目可使用现有账单和简明资源清单，不强制采购商业 FinOps 平台。

**验收：** 被纳管资源有实际用途、计费来源和复核频次；没有跨供应商负担的项目不被要求建立无用的数据管道。

**主体、前置与输入：** 本条针对“资源成本边界与最小治理”；执行者必须具有目标范围的实际权限，消费 `CLD-COST-T1` 的固定输入：账号/Region/资源与无ID费用、SKU/Meter、共享/Idle、租户/发票主体和成功业务单位。

**权威状态与输出：** 供应商账单/实际资产与有权费用归属，不是标签自证。输出本条验收的原始观察及 `CLD-COST-T1` 产物：完整费用/Unallocated清单、隐私安全标签和可复核分母。不能从期望配置/请求成功越级推断该输出。

**并发、超时、未知与恢复：** 父Compute消失不代附属资源/合同结束；标签滞后和失败业务成本不丢失；未知归属显式保留。记录本条对象版本与操作身份；冲突/部分成功/未观测项不并入成功，不以新请求覆盖原请求的未知结果。

**正例及判据：** 在上述明确目标/主体/版本和有效前置下，以实际费用链需求选择最小核算能力，不能强制无关付费平台；本条具体可观察验收仍为“被纳管资源有实际用途、计费来源和复核频次；没有跨供应商负担的项目不被要求建立无用的数据管道。”。合法操作与应有拒绝均须由实际目标结果而非仅配置文本确认。

**直接失败：** 个体只用单服务器却被规定须购买 FinOps SaaS 才能继续开发。此时必须得到上述预期检查/失败诊断，不得登记本条整体通过。

**合法邻例与兼容：** 单供应商小项目可用简明清单，不强制FinOps数据平台。 与本条适用条件相容；不得为拒绝该合法情形而扩大外部规范或供应商限制。不同目标平台/版本的等效实现须保留同一输出不变量。

**真实检查入口：** 消费[ `CLD-COST-T1` ](#CLD-COST-T1)中的命令/API/项目入口，在同一隔离画像分别运行正例、上述失败输入和合法邻例；逐项比对本条验收，不以退出0单独替代资源、权限、业务或费用读回。有限来源命题：`COST-FOCUS`、`COST-CUR`；只支持第二节所列命题，不为整条实施结果背书。

**主体、前置与输入：** 本条针对“真实资源清单及账务映射”；执行者必须具有目标范围的实际权限，消费 `CLD-COST-T1` 的固定输入：账号/Region/资源与无ID费用、SKU/Meter、共享/Idle、租户/发票主体和成功业务单位。

**并发、超时、未知与恢复：** 父Compute消失不代附属资源/合同结束；标签滞后和失败业务成本不丢失；未知归属显式保留。记录本条对象版本与操作身份；冲突/部分成功/未观测项不并入成功，不以新请求覆盖原请求的未知结果。

**正例及判据：** 在上述明确目标/主体/版本和有效前置下，按真实资产和账单 SKU 清点残留而非只看父对象状态；本条具体可观察验收仍为“删除实例后仍有磁盘/IP/快照计费时，从账单和资源清单识别残留，不因 Compute 已停止就结案。”。合法操作与应有拒绝均须由实际目标结果而非仅配置文本确认。

**直接失败：** Compute Instance 已删除但 EBS/公网 IP 等独立计费对象持续扣费。此时必须得到上述预期检查/失败诊断，不得登记本条整体通过。

**合法邻例与兼容：** 没有Resource ID的网络/API费用可记Unallocated，不应从总额丢弃。 与本条适用条件相容；不得为拒绝该合法情形而扩大外部规范或供应商限制。不同目标平台/版本的等效实现须保留同一输出不变量。

**故障恢复：** 对象删除但账单未最终出可只记技术退役；未清持续收费不结案；迁移后仍核真实入口/协议/Key。

**通过/失败判据：** 本组中每个条款的验收逐项满足，直接失败得到拒绝/诊断/正确恢复、合法邻例不被误拒；任何Unknown、未覆盖平台/权限或关键产物缺失分别保留，不允许从组内其他成功项外推。退出0、Accepted、配置已保存只证明其各自层次。
