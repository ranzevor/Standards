# L4 订阅计量、退款争议与权益补偿技术规范

**文档ID：** STD-L4-COMMERCE-003　**版本：** 0.1.0　**状态：** adopted　**生效日期：** 2026-10-30

## 范围与状态

本专题细化[基线](001-商业交易与计费系统领域通用基线--v0.1.0.md)M11—16，面向实际订阅/计量/退款/争议/权益/多步补偿；不定义合同可退权、税法、会计处理或裁决欺诈。不要求一次性免费服务引入订阅。必须/不得、应、可分别表示必要、建议、选择；例子数字不设统一宽限期。[L3 v0.1.0](../../L3/001-通用工程规范--v0.1.0.md)提供工程接口。

`period=[start,end)`使用明确日历/时区及规则版本；usage的事件时间与入账时间不同。发票生成、付款、宽限、订阅有效与权益是独立状态。refund意图、渠道受理、已执行、客户到账不同；dispute是独立生命周期，不是普通refund。

## 逐条合同

### COM-S01 周期、变更与取消竞争

**对象与责任：** 订阅产品负责人定义周期、试用、升级降级、proration与取消生效规则，计费执行者按已批准合同/时点运行。

**输入/输出/权威：** 输入为customer/contract、plan和规则版本、周期区间/时区、变更意图及effective_at；输出为每周期账单/调整、续费决定和独立权益窗口。权威是合同/订阅事件账与真实付款事实，定时任务排队不是续费完成。

**必要机制与不变量：** 固定月末/闰日/DST和不存在/重复本地时刻策略，账期边界用明确瞬时对应，不能以固定30天代替承诺自然月。取消与续费以权威状态/版本裁决；同周期同计费意图唯一，未获准变更不得静默改变已确认条款。按比例金额的时间分母与舍入见金额专题。

**失败、并发、超时与恢复：** 并发取消、升级和扣款保留决定先后/冻结范围；旧队列执行前重核有效状态。迟到付款不能复活已按合同终止的未来权益；未知付款保持原attempt核对，不因账单任务超时新扣。

**兼容：** 到期取消可保留已付周期权益；立即取消是否退费由真实合同决定，不能从UI文字推导。旧计划/历史周期保存原解释器。

**验收与产物：** T-COM-SUB在固定可控时钟运行月末、DST、试用转正、取消/续费竞争及旧回执；每周期账单数量、金额、付款和权益分别可查，重复任务不多扣，合法保留期不误关。

**正例 / 直接失败 / 合法邻例：** 正例为到期取消阻止下一周期续费；直接失败为取消后旧任务仍扣下一期；合法邻例为已付当前周期权益按合同保留。

**来源：** 组织合成，日历和商业规则必须由项目合同固定，不将渠道默认计费规则当法律义务。

### COM-S02 用量身份、窗口与迟到更正

**对象与责任：** 计量生产者给可信来源，接收者去重/校验单位，计价者绑定窗口与价格规则；缺测责任明确，不由聚合值掩盖。

**输入/输出/权威：** 输入为客户/商户/环境、meter、event_id、事件/观察时间、单位、精确数量、来源摘要及更正关联；输出为已受理事件、聚合、估算或最终账单/补充调整。原始不可变事件和已固定计价快照是权威。

**必要机制与不变量：** 同作用域event_id同内容幂等，异内容隔离；独立真实事件即使数值/时刻相同也可计入。迟到政策固定接受截止、窗口归属与补充账单方法；负向更正有原事件/授权与下界，不覆盖已发行账单。单位转换版本明确，缺测/估算不能标最终实际用量。

**失败、并发、超时与恢复：** 事件持久接收与ACK有边界，补报/恢复重放不能重复计；聚合水位不等于源完整，采集缺口显式。并发更正按原累计可更正量检查，窗口结算后按规则追加，不写旧总额掩盖差异。

**兼容：** 可按规则先高精度累计再计价，不强制每事件舍到货币最小单位；换meter/单位不得套旧价。无计量路径排除此分支。

**验收与产物：** T-COM-METER送重复、同ID异内容、同值独立事件、跨窗口、迟到、负修订和缺测；从原事件重算聚合/账单，分母与调整关联完整。保留原输入、去重账、水位及重算差异。

**正例 / 直接失败 / 合法邻例：** 正例为迟到更正进有来源补充账单；直接失败为重放同event多收费或改旧账无痕；合法邻例为两个独立event同值同秒都有效，不按数值误去重。

**来源：** 组织合成，消费渠道/API版本的meter语义时另在L5固定，不声称本地算例覆盖真实采集丢失。

### COM-S03 权益派生、撤销与一次消费

**对象与责任：** 权益服务定义从合同、付款、宽限、取消/争议到权益的确定规则；资源服务在执行时核有权动作与有效额度。

**输入/输出/权威：** 输入为客户稳定ID、产品/期间、规则版本、来源资金/合同事实、有效窗、消费意图与epoch；输出为可用/暂限/到期/已消费/未知。权威是权益事件与资源实际效果，付款页不是权益凭证。

**必要机制与不变量：** 同一来源事实派生幂等，撤销/取消不得被迟到旧事件覆盖。一次性额度以原子扣减/预留或目标栅栏防并发双用；扣减、业务完成与失败返还分别记录，不以本地回滚追回已交付不可逆内容。退款是否撤权益由合同规则明确。

**失败、并发、超时与恢复：** 消费后丢响应按原消费意图核对，未知不重新发放新额度；旧账户/租户/epoch的离线消费同步前重核。恢复旧备份需重应用撤销/消费水位，不能重新发放已用额度。

**兼容：** 合同宽限期可允许权益而未有新付款，不把所有未付款都等于无权；合法多设备并行按真实资源/额度范围，不强加单设备限制。

**验收与产物：** T-COM-ENTITLEMENT交错重复付费事件、取消、迟到成功、并发最后额度、消费丢响应和备份恢复；核权益时间窗、额度守恒、资源效果及旧能力拒绝。

**正例 / 直接失败 / 合法邻例：** 正例为一次消费效果/一次扣减；直接失败为迟到付款恢复已撤未来权益或额度复活；合法邻例为明示宽限期有限权益不被一律拒绝。

**来源：** 组织合成，消费安全执行时授权与交易资金权威接口，不把订阅status字段视作全部权限。

### COM-S04 部分退款、争议与可用余额

**对象与责任：** 退款审批者/执行者核原交易与剩余额，争议处理者独立管理阶段和证据期限；风险决定不能代替资金权或最终裁决。

**输入/输出/权威：** 输入为原capture、币种、refund_intent/attempt、已执行/未决退款、争议敞口及授权；输出为预留、受理、执行、到账、失败/未知或争议阶段。渠道原退款/争议对象及内部预留账为权威。

**必要机制与不变量：** 可再申请额度在同币种原capture及获准调整范围内，扣除已退和仍可能执行的退款预留；原子预留防并发超退。未知退款保留占用，只有权威确认不会生效才能释放。争议冻结/败诉/胜诉独立，不能既作为普通refund又无关联再扣同一损失；退款与拒付竞态按具体渠道/业务政策核对，不强造一个通用余额式。

**失败、并发、超时与恢复：** 渠道超时按原attempt查单；新退款未应用不能关闭旧未知。争议撤销/胜诉释放对应临时限制但不恢复已消耗权益；迟到退款/争议以来源关联调整，不改旧流水。证据期限过期显式报告，不以关闭工单称胜诉。

**兼容：** 多次合法部分退款在余额内独立执行，不按同金额误合并；void授权与refund捕获款不同。舍入残差按原分摊和累计退回合同处理。

**验收与产物：** 本地退款预留模型及T-COM-REFUND并发两个部分退款、未决后重试、争议开启/撤销/胜败、迟到退款；观察总预留/已退、原渠道对象和状态，不能超原限额，未知不冒到账。

**正例 / 直接失败 / 合法邻例：** 正例为余额内两次部分退回；直接失败为并发各看到旧余额共同超退；合法邻例为同金额但各有独立意图且总额不超的两次部分退款。

**来源：** 组织合成工程不变量，不决定法定退款或会计损失确认；渠道争议规则需按精确版本在L5绑定。

### COM-S05 多步骤履约与有权补偿

**对象与责任：** 工作流负责人记录每一步外部效果，补偿执行者有独立操作权；不能用最初付款批准覆盖任意退款/物流召回。

**输入/输出/权威：** 输入为订单、步骤/意图/attempt、前置、目标效果查询及补偿条件；输出为逐步骤完成/失败/未知/不可逆和独立补偿结果。仓储、权益、通知或渠道原对象分别权威。

**必要机制与不变量：** 步骤账先于派发保存身份，重试条件按未知闭合合同；数据库事务只能保证自身状态。补偿是新动作，有原因、范围、幂等身份和结果；不能删除原发货/原扣款，使系统误认为从未发生。可补偿与已补偿分开，补偿失败保持待核。

**失败、并发、超时与恢复：** 部分履约后付款冲突/取消保留事实；同时补发/退款需规则避免双重过度补偿。不可逆动作未知时先查原效果，不重放全工作流；恢复只回放确定安全步骤。

**兼容：** 邮件、物品、数字材料可能有不同不可逆性；退款不自动收回合法交付材料。仅本地可逆步骤可用本地事务，不强制分布式编排平台。

**验收与产物：** T-COM-FAULT/HTTP让支付成功、第二步失败、第一步响应丢失和补偿超时；逐目标核效果次数与补偿账，合法恢复可完成且未知/不可逆留存。产物包含全链意图/attempt、权威查询与剩余差额。

**正例 / 直接失败 / 合法邻例：** 正例为原发货查实后不重发、独立补偿有回执；直接失败为删原发货再全量重跑；合法邻例为无需补偿的已合法交付非撤销材料准确保留。

**来源：** 组织合成，复用后端工作流与安全业务批准接口，不宣称跨外部目标原子回滚。

## 真实工具、输入与观察接口（not-run）
