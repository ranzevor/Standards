# L4 金额分摊、账本结算与渠道对账技术规范

**文档ID：** STD-L4-COMMERCE-004　**版本：** 0.1.0　**状态：** adopted　**生效日期：** 2026-10-30

## 范围与数字合同

本专题深化[基线](001-商业交易与计费系统领域通用基线--v0.1.0.md)M02、M09—12、M14—15、M18—19，规定金额表示、可追溯调整与对账工程；不决定会计准则、财税/法律适用、汇率来源合法性或实际到账。非金融业务可用相称不可变明细账，不强制建立企业总账。必须/不得为必要条件，应为建议，可为选择。[L3 v0.1.0](../../L3/001-通用工程规范--v0.1.0.md)用于一般证据。

`Money=(currency, unit/exponent, integer_amount)`；高精度计量/单价另有单位与规则，不能先冒充货币最小单位。`gross`、`fee`、`refund`、`dispute`、`reserve`、`net_settlement`、`bank_received`不同。交易、渠道可用、结算与到账有不同时间坐标/权威。

## 逐条合同

### COM-L01 精确金额、币种与舍入边界

**对象与责任：** 定价/渠道适配负责人固定支持币种、渠道实际单位/指数例外、最大值与舍入规则版本；税费适用由有权专业主体提供，工程只保留其身份。

**输入/输出/权威：** 输入为有限十进制字符串/整数、币种、单位、行项/折扣/税费、计量精度及规则；输出为客户确认总额和精确渠道整数。权威为已确认金额快照与渠道单位画像，不以locale显示或二进制float重算。

**必要机制与不变量：** 禁止NaN/Infinity/未界定溢出，跨币种禁止直接相加；固定何处量化、rounding mode、先折后税/含税等适用顺序。高精度先累计或逐行舍入只能按合同选定一种并保存输入，不可结算临时切换；各累计用受控Decimal/有界整数，显示值不得悄然成为计费输入。

**失败、并发、超时与恢复：** 未知币种/指数/汇率规则拒绝计价而非假设两位小数；恢复重算消费历史规则，当前规则改变不漂移旧金额。并发调整先定原版本与新调整身份，不能覆盖确认值。

**兼容：** 零小数/三小数币种及供应商单位例外由画像明确，不硬编码全部货币两位；合法高精度用量在计价边界前保留。零价可合法不发渠道付款。

**验收与产物：** 本地Decimal模型及T-COM-RECALC送0.005边界、负调整、极值、币种错配、未知单位与高精度合法累计；按固定规则独立重算，客户确认、账与渠道金额严格一致。保存规范化输入、量化点、模式和残差。

**正例 / 直接失败 / 合法邻例：** 正例为明确half-even的0.005按合同量化；直接失败为float总额与确认金额差最小单位或跨币种相加；合法邻例为高精度累计到末端再舍入，不能被逐事件截断。

**来源：** 组织合成数值工程合同；Python Decimal只是本地演示实现，不提供币种/税务法定规则。

### COM-L02 分摊余数与累计部分退回

**对象与责任：** 报价/账务工程负责人固定分摊对象、权重、稳定tie-break及退款回指；业务有权者决定可分摊/可退范围。

**输入/输出/权威：** 输入为有符号整数总额T、稳定line_id和非负精确权重（总权重>0）、原分摊与累计退款；输出为逐行整数和残差分配轨迹。原确认分摊快照是退款权威，不按当前目录重新分摊。

**必要机制与不变量：** 一个可采用算法是对abs(T)按权重求精确配额，先取floor，再按余数从大到小、line_id稳定次序分配剩余单位，最后恢复T符号；采用其他算法也须证明逐行整数、总和恰等T和可重现。退款逐行/累计不得超过原可退分摊，分次舍入残差在预定最后部分或累计差额算法吸收，不因多次舍入创造/丢失单位。零/重复ID或无效权重拒绝。

**失败、并发、超时与恢复：** 同一原分摊版本并发退款先原子预留剩余额；未知退款不释放预留。退款失败只释放已证不会生效部分；重算保留原分摊/tie-break，不能通过改ID改变客户间余数。

**兼容：** 负向调整可用相同符号对称规则，但业务“退款”不能任意负数形成额外扣款；无分摊对象的单金额不强制行账。允许合法多个部分退款而非全部去重。

**验收与产物：** 本地余数/退款模型及T-COM-RECALC覆盖1单位三等份、负1、权重0、重排行输入、重复ID、分次全额退和并发超退；总和守恒、tie-break稳定、最后残差闭合。保存每配额/余数、原快照与退款关联。

**正例 / 直接失败 / 合法邻例：** 正例为三等份1单位只给稳定第一行1；直接失败为各四舍五入导致总和0或3；合法邻例为负调整按明确符号对称分摊而不误当退款执行。

**来源：** 组织合成可验算法，不声称任何渠道/会计准则强制采用该算法；具体合同可选等效守恒方案。

### COM-L03 不可变分录、来源唯一与状态分离

**对象与责任：** 账记录服务核来源、账户映射与同币种平衡，核算政策所有者确定账户类别/经济含义；原始业务事实不得由账服务篡改。

**输入/输出/权威：** 输入为source_identity（商户/环境/操作/原对象）、规则版本、同币种借贷行、待定/最终状态与调整关联；输出为原子唯一过账或可判拒绝。不可变日记账与原始渠道/业务对象分别权威，余额缓存不是原始事实。

**必要机制与不变量：** 采用复式时每笔同币种借贷相等，账户类型/币种/归属匹配；平衡不证明映射正确。source同身份同内容幂等，异内容拒绝/调查；多行原子提交，不先更新部分余额。更正用关联冲正/调整，不改旧分录；待定/预留/已执行区分，不把未知当零余额。

**失败、并发、超时与恢复：** 提交丢响应查原source，不能生成新ID重记；并发同source只一笔。余额重建按固定顺序/规则复算并与检查点核对，发现损坏保留差额/原证据，不手改余额凑平。

**兼容：** 相称不可变业务明细账可替代完整总账，但仍需来源唯一、可重算、更正关联。多币种交易用分别平衡的币种子账与显式FX桥，不让金额相等掩盖币种不同。

**验收与产物：** 本地合成账本及T-COM-LEDGER测试重复、source异内容、错账户/币种、不平衡、提交中断、合法冲正与重建；核条数、金额、账户映射和原记录未改。单纯借贷和为0不能通过错账户用例。

**正例 / 直接失败 / 合法邻例：** 正例为一次capture按固定映射入账一次；直接失败为重复事件重记或直接改旧退款余额；合法邻例为新身份、有原来源关联的合法调整。

**来源：** 组织合成工程追溯要求，不就分录经济含义、收入确认或会计合规给结论。

### COM-L04 结算、费用、FX与银行对账

**对象与责任：** 对账负责人固定渠道/内部/银行数据身份、截止/时区、匹配键与差异责任；资金账户所有者核真实到账接口。

**输入/输出/权威：** 输入为交易gross、费用、退款、争议、储备/释放、FX交易与结算批次、银行流水及时间；输出为matched、合法在途、资料不足、真实差额。渠道结算报表与银行流水各证明不同事实，不把净到账当原capture。

**必要机制与不变量：** 同币种按约定符号逐笔分解gross与净额，跨币种保存源/目标金额、汇率身份、报价/执行时点、费用与舍入残差；不得用无来源汇率把差额抹平。匹配一对多/多对一需关联集合，不能复用同流水匹配两批。延迟/未结算与实差分别列。

**失败、并发、超时与恢复：** 缺报表/部分批次保持未知；重跑同版本对账不得重复入账或删除未匹配项。渠道纠正报表保留旧/新身份及差异，不能覆盖原失败。处理优先级与责任期限按实际合同，不发明统一到账天数。

**兼容：** 非资金业务可不做银行对账但保留其业务权威；有依据的跨日尚未结算是合法在途。渠道API/报表版本与时区变化触发重核，不自动把历史差异归零。

**验收与产物：** T-COM-RECON用固定含gross/fee/refund/FX/reserve、跨日/部分批次/缺流水和重复流水样本；逐笔关联与分解等式成立，合法在途保留，真实差额不得标解决。产物含原报表摘要、匹配关系、残差与待核清单。

**正例 / 直接失败 / 合法邻例：** 正例为100 gross、3 fee按合同得到97净结算并独立核银行；直接失败为将97记成客户付款额或删除3差额；合法邻例是97已结算但银行仍在合法在途窗，不冒到账。

**来源：** 组织合成对账合同；数例是合成非真实交易，不提供法定会计符号或到账保证。

### COM-L05 恢复、迁移、票据与审计闭包

**对象与责任：** 迁移/恢复负责人保留金额和来源身份，票据接口负责人管理开票/更正/拒绝；专业适用者提供地区/主体/规则版本而非开发者猜测。

**输入/输出/权威：** 输入为账快照/日志、全部原attempt、规则/schema版、票据身份、有效撤权/保留规则与源报表；输出为可重算恢复、逐批校对、票据各状态与未决差额。原交易/票据/账与银行查询各权威。

**必要机制与不变量：** 迁移前后历史确认金额/币种/归属不漂移；新旧解释器共存有退回条件。开票失败不改变支付已capture事实，票据更正保留关联。恢复不重新提交未知POST，不复活已撤支付/账户权限；必要账证保留与用户删除请求分开由实际权利决定。审计不保存不必要卡号或秘密。

**失败、并发、超时与恢复：** 恢复到旧时点后先查在途与渠道外部效果差异再开放写入；对账不明保持未决。回放在固定范围按source幂等，不全量重扣；迁移中断可继续或回到被验证组合，不仅回退程序忽略新数据。

**兼容：** 无开票要求路径可按有权适用决定排除；合成模型/沙箱/真实资金分别报告，不用单元测试宣称客户已到账。旧回调在支持窗内保持历史解释。

**验收与产物：** T-COM-LEDGER/RECON/HTTP从旧快照恢复并注入渠道已完成但本地未知、票据失败、规则迁移中断；核无重复付款/过账，金额守恒、票据独立、未决可查。保存准确构建/数据身份、原失败与恢复差异。

**正例 / 直接失败 / 合法邻例：** 正例为查清原渠道成功再补记来源分录；直接失败为开票失败触发再扣款或恢复全量POST；合法邻例为无需票据的免费履约不强制开票。

**来源：** 组织合成；财税/保留适用由真实权限与专业决定，不从技术通过推导法律、会计或支付认证。

## 真实入口与判据（全部 not-run）

T-COM-RECALC：以真实服务的固定规则版本对原报价/用量/分摊数据重算，独立Decimal/整数算例给预期；T-COM-LEDGER：在已批准隔离数据库中执行服务原生过账/冲正/重建入口，读取只读原日记账、source唯一键和余额，不运行通用删改SQL；T-COM-RECON：导入固定渠道/银行合成报表，运行实际对账入口并导出逐笔关系/差异；T-COM-HTTP继承订单专题curl合同。L5/L6必须给每一入口真实命令/API、工具/引擎版本、参数、权限、故障点与只读观察查询；没有入口不能称服务已验。

本地 `python3 -m unittest discover -s tests -p 'test_sec_edge_commerce_models.py' -v` 使用Python标准库合成金额/账本/状态数据，不能验证数据库耐久隔离、渠道结算或银行到账。[来源](../../../sources/commerce-billing.md)、[模型边界](../../../examples/security-edge-commerce/README.md)。
