# 字节分帧、协议协商与连接生命周期技术规范

**文档ID：** STD-L4-NETWORK-001　**版本：** 0.1.0　**状态：** adopted　**生效日期：** 2026-10-30

## 1 目标、适用与非目标

将不完整字节、协议协商、方向关闭与业务承诺准确分层，防止边界错认产生虚假完整消息或不安全回退。

**适用：** 流/报文协议端点、代理和安全传输profile；所选TCP/QUIC/HTTP/WS/DTLS能力按实际组合适用。

**非目标：** 不重写RFC算法、不强制全部协议；传输可靠性不提供业务事务或持久提交。

本文的“必须/不得”为采用相应条款时的必要条件，“应”为需说明偏离理由的建议，“可”为允许选项。外部标准的 MUST/SHOULD 依其原有强度与适用 profile 执行，项目参数不得降低其强制要求。能力不存在可据事实不适用；已承诺但未验的能力仍适用。

## 2 术语、主体与权威状态

read chunk、TLS record、QUIC packet、应用消息和业务操作是不同边界。连接方向/流可独立关闭；应用完整性证据与TLS正常关闭分别存在。协商结果只覆盖实际端点及中间链路。

**主体与所有权：** 解析器拥有有界增量状态；传输实现负责所选协议状态机；TLS端点验证预期对等身份；应用消费者给消息/业务完整条件；代理保留变换/终止点证据。

**前置输入：** wire版本/profile、长度/编码/字节序/扩展、最大合法消息/解压/重组预算、端点角色、身份信任和应用完整条件。

**输出与权威观察：** 精确消息交付、拒绝/截断原因、协商与方向终态、权威业务回执引用。传输ACK只能证明相应传输层事实。

**状态与终点：** 解析为空/头不足/载荷不足/完整/协议错误；连接建立/方向可用/半关闭/重置/关闭；业务未受理/已受理/已提交/未知独立建模。

条款 ID 在本文内稳定；全局身份为文档路径、版本与条款 ID 的组合。各条的前置输入、主体和状态继承本节，再叠加本条触发条件。诊断缺失不证明效果未发生；并发、超时、取消请求与真实业务终态分别记录。

## 3 机制、不变量及逐条验收

### NET-WIRE-01 有界增量解析

- **触发/前置：** 任意字节/报文输入、分片与粘连。
- **必要机制：** 必须按wire逐层累积完整头/载荷及终结，长度先检再分配，防整数溢出/符号转换；每连接和总体缓冲/片段/时间有界。压缩预算同时核解压后成本；UTF-8可跨read边界，不按块独立误解码。
- **不变量：** 相同合法字节序列的不同分段得到相同消息序与单次交付；不完整不冒充完成。
- **并发、超时、未知与恢复：** EOF在半帧明确截断；坏长度进入协议错误并释放所属解析状态，不能猜测补齐。合法大对象可走已声明分块。
- **产物与观察点：** 输入分段、消息边界、拒绝点和缓存峰值。
- **正例：** 两条粘连帧一次read交付两条，单帧逐字节送只交付一次。
- **直接失败：** read返回半个长度前缀即执行命令，或先按攻击者长度分配内存。
- **合法邻例：** 零长度若所选wire允许应合法通过，不因边界保护拒绝全部空消息。
- **可观察验收：** 对真实解析器穷举短消息全部切分，畸形长度/编码/压缩极值及最大合法对象；独立比较完整消息与副作用计数。
- **来源与限制：** RP31；RP34。来源只支持[逐命题表](../../../sources/runtime-protocol/SOURCE-CLAIMS.md)所列命题；其余必要机制是为保持本条不变量而提出的组织综合设计，不声称由单一外部标准规定。

### NET-WIRE-02 协商、代理与安全回退

- **触发/前置：** 版本、ALPN、子协议或扩展协商。
- **必要机制：** 必须记录双方和中间路径实际支持及协商结果；HTTP/2/3 WebSocket按扩展CONNECT与对应设置，不复用h1的101/Upgrade语义。未协商必需能力明确拒绝；可选回退必须保持安全/业务承诺。
- **不变量：** 链路一段支持不等于全链路支持；不启用未协商扩展。
- **并发、超时、未知与恢复：** 代理重启/协议转换重做适当协商；失败不静默改明文或更高权限端点。旧连接能力不移植至新实例。
- **产物与观察点：** 端点/代理版本、协议参数、握手结果/拒绝。
- **正例：** h2路径不支持扩展时，按明示安全等价h1回退或拒绝。
- **直接失败：** 启用HTTP/3便宣称所有客户端都能建立WebSocket。
- **合法邻例：** 纯HTTP轮询状态页无需新增WebRTC。
- **可观察验收：** 支持/不支持设置、错子协议和最终代理路径组合实测；比较实际协商而不只读配置。
- **来源与限制：** RP35；RP36。来源只支持[逐命题表](../../../sources/runtime-protocol/SOURCE-CLAIMS.md)所列命题；其余必要机制是为保持本条不变量而提出的组织综合设计，不声称由单一外部标准规定。

### NET-WIRE-03 方向关闭、EOF与完整性

- **触发/前置：** 半关闭、同时关闭、TLS异常EOF或流重置。
- **必要机制：** 必须按方向/流处理读写结束和共享资源；客户端完整上传后shutdown(write)仍可读取最终响应。TLS1.3写方向按profile发送close_notify，EOF前无close_notify不能证明发送数据收齐；独立应用长度/终结验证可以证明某消息完整，但仍记录TLS异常关闭。
- **不变量：** 单流关闭不误杀其他流；close_notify不是业务提交收据。
- **并发、超时、未知与恢复：** 迟到/重复关闭回调幂等释放所属资源；EOF未满足应用完整条件则不完整/未知。不得以应用完整豁免TLS发送关闭要求。
- **产物与观察点：** 双向时间线、流/连接资源、TLS关闭状态、应用完整证据与业务回执。
- **正例：** 上传方停写，服务器读EOF后仍写最终结果再释放。
- **直接失败：** 服务端读EOF即关整连接丢最终响应，或TLS边界截断被当完整对象。
- **合法邻例：** 此前独立验证完整应用对象可记消息完整，同时TLS异常事实保留。
- **可观察验收：** 真实端点测试半关闭/同时关闭、完整与不完整对象在记录边界断链、有/无close_notify，核三层结论分别准确。
- **来源与限制：** RP31；RP32。来源只支持[逐命题表](../../../sources/runtime-protocol/SOURCE-CLAIMS.md)所列命题；其余必要机制是为保持本条不变量而提出的组织综合设计，不声称由单一外部标准规定。

### NET-WIRE-04 认证profile与0-RTT重放

- **触发/前置：** TLS/DTLS认证、恢复或早期数据。
- **必要机制：** 必须锁认证模式：PKIX链和参考身份、受信指纹、或受权PSK作用域分别验证；合法无证书profile不强造证书。PSK不使用低熵口令。RFC9846每服务实例对同一0-RTT握手最多接受一次；部署仍须处理跨实例及客户端重试，应用副作用另有排重/拒绝早期执行。
- **不变量：** 通道认证不替代对象授权；单实例去重不声称集群业务恰好一次。
- **并发、超时、未知与恢复：** 票据/密钥轮换按真实profile失效，0-RTT拒绝后1-RTT重试保留业务意图；不能因业务幂等免除协议每实例重放约束。
- **产物与观察点：** 协商模式、对等身份(无秘密)、同/跨实例重放接受数及业务对象数。
- **正例：** 合法PSK路径无证书也能通过身份验证；副作用命令禁早期执行。
- **直接失败：** 错名证书忽略，或同实例重复0-RTT被再次接受。
- **合法邻例：** 无副作用幂等查询可在满足协议/资源约束下启早期数据。
- **可观察验收：** 真实库/服务分别回放同实例和跨实例0-RTT及拒绝后重试，核传输接受与业务效果，不用模型缓存冒充实测。
- **来源与限制：** RP32；RP33。来源只支持[逐命题表](../../../sources/runtime-protocol/SOURCE-CLAIMS.md)所列命题；其余必要机制是为保持本条不变量而提出的组织综合设计，不声称由单一外部标准规定。

### NET-WIRE-05 报文、可靠层与业务确认

- **触发/前置：** UDP/DTLS/QUIC DATAGRAM、跨流或业务成功主张。
- **必要机制：** 必须说明所选模式的可靠/顺序范围及丢失/新鲜度；DTLS不把报文变可靠有序，QUIC DATAGRAM不重传且无自身分片。TCP/QUIC ACK或bufferedAmount减少不证明应用处理；跨流无隐式因果顺序，关键依赖需应用条件。
- **不变量：** 可丢快照不套到必须确认命令；消息层与业务层成功有不同证据。
- **并发、超时、未知与恢复：** 丢响应保持未知并消费后端查询/幂等接口；路径超限有明确错误/分块替代，不能无限重发同大包。
- **产物与观察点：** 模式/尺寸、丢弃账、依赖身份及权威处理回执。
- **正例：** 位置样本按新鲜度丢弃，奖励命令走可靠业务确认。
- **直接失败：** 收到DATAGRAM ACK就标交易完成，或跨流“创建/使用”凭发送顺序依赖。
- **合法邻例：** 不可靠无序遥测合法，不强加无限可靠重传。
- **可观察验收：** 类型分层丢包/乱序/重复/MTU边界，核重要命令最终对象及样本缺口；独立观察传输与应用计数。
- **来源与限制：** RP37；RP38；RP34；RP53。来源只支持[逐命题表](../../../sources/runtime-protocol/SOURCE-CLAIMS.md)所列命题；其余必要机制是为保持本条不变量而提出的组织综合设计，不声称由单一外部标准规定。

## 4 兼容、迁移与退役

协议版本、扩展、代理与终端能力矩阵固定；安全降级只能在满足原承诺的已声明路径，不能为连通关闭验证。新profile不能沿用不同协商或不同终止链路回执。

## 5 跨域消费接口

消费网络基线M01–M07、M10–M11、M16–M20、M29–M30；后端负责方法/业务终态和去重，云负责入口部署，安全负责密钥/身份政策；本域给逐层可验证交付及拒绝边界。

接口只定位技术职责，不自动作出规范采用决定。通用状态、测试和制品义务消费 [L3 通用工程 v0.1.0](../../L3/001-通用工程规范--v0.1.0.md)；提供方版本与摘要、应用条款、实现入口和验收责任在项目契约中绑定。提供方保证须由相应实现证据支持，消费方按该保证的实际范围验收。

## 6 真实目标验收合同

真实目标绑定解析器/协议库版本，项目入口 `python -m unittest target_tests.test_wire -v` 或相应语言测试直接调用真实解析器；网络端点以 `openssl s_client -connect "$HOST:$PORT" -servername "$DNS" -verify_return_error -verify_hostname "$DNS"` 核已选证书profile，`curl --http2 -v "$URL"` 仅用于支持该协议的受控端点。TCP独立客户端按每字节分段、合并和shutdown(write)送数据，服务器必须返应用终态；HTTP/2/3扩展CONNECT须用支持的真实客户端读取协商而非凭curl版本号推断。

**判据：** 任意合法分段交付完全相同消息；截断/溢出/非法编码不执行半消息；半关闭后仍可取得最终响应；TLS缺close_notify不被误当完整流；实际协商拒绝未支持扩展且不放宽身份。

每次执行保存：正文/条款版本与摘要、目标制品/实现和工具版本、OS/设备/运行时/配置、输入及故障时间线、预期和实际、stdout/stderr/退出码或等价运行证据、权威状态回读、未覆盖范围。`not-run`、模型通过和真实目标通过是不同结果；实际无环境时保留命令和判据而不填写虚构回执。
