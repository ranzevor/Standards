# 实时媒体、路径维护与诊断技术规范

**文档ID：** STD-L4-NETWORK-002　**版本：** 0.1.0　**状态：** adopted　**生效日期：** 2026-10-30

## 1 目标、适用与非目标

使协商、可达、接收consent、媒体安全和实际呈现分别成立，不以单机连接或平均RTT代替真实实时能力。

**适用：** WebRTC、ICE/STUN/TURN、RTP/SRTP与DataChannel的实际采用profile。

**非目标：** 不要求所有网络产品部署TURN/媒体；不声称RTP保证QoS、硬实时或SFU链路天然端到端加密。

本文的“必须/不得”为采用相应条款时的必要条件，“应”为需说明偏离理由的建议，“可”为允许选项。外部标准的 MUST/SHOULD 依其原有强度与适用 profile 执行，项目参数不得降低其强制要求。能力不存在可据事实不适用；已承诺但未验的能力仍适用。

## 2 术语、主体与权威状态

信令stable、ICE选中对、DTLS身份、consent、设备许可、业务呼叫授权和实际音画分别是条件；DTLS-SRTP链路加密与平台不可解密的应用E2EE不同。

**主体与所有权：** 信令绑定会话世代/授权，ICE端点执行检查，TURN维护中继状态，媒体端点核consent/指纹/设备许可，消费者测真实音画/数据完整性。

**前置输入：** 具体浏览器/库、协议/编解码profile、信令身份、网络/NAT路径、中继与consent参数、媒体/数据模式及端到端预算。

**输出与权威观察：** 协商/候选/DTLS/consent状态、真实出站/接收/解码/呈现统计、时钟误差、数据完整/缺口及脱敏诊断。

**状态与终点：** 协商中/可达/安全关联/允许发送/可呈现分开；consent到期或撤销停止受限发送，旧响应不能使其复活；DataChannel open不是业务完成。

条款 ID 在本文内稳定；全局身份为文档路径、版本与条款 ID 的组合。各条的前置输入、主体和状态继承本节，再叠加本条触发条件。诊断缺失不证明效果未发生；并发、超时、取消请求与真实业务终态分别记录。

## 3 机制、不变量及逐条验收

### NET-MEDIA-01 信令世代与ICE可达

- **触发/前置：** offer/answer/candidate和网络变化。
- **必要机制：** 必须按会话/协商代际关联信令，处理同时offer、rollback与候选先后；STUN映射不证明对端可达，ICE检查/选对与应用可用分开。restart更新password与username fragment；适用RFC8863最低等待不能被无候选立即失败绕开。
- **不变量：** 旧answer/candidate不进入新会话；stable不等于通话已接通。
- **并发、超时、未知与恢复：** 检查失败走声明中继/替代或准确拒绝；无承诺中继无需新增服务。恢复只接受当前代路径和权限。
- **产物与观察点：** 信令状态、凭据代际(不含秘密)、候选对/检查和实际媒体。
- **正例：** 同时offer按受支持状态机处理，选对后真实接收合成媒体。
- **直接失败：** 拿到server-reflexive地址便显示直连，或旧answer接错会话。
- **合法邻例：** 局域网无需TURN也可按已承诺范围合格。
- **可观察验收：** 真实端点竞争/迟到/网络限制/最小等待及restart，核选中对和媒体，不只看候选列表。
- **来源与限制：** RP44；RP45；RP46；RP51。来源只支持[逐命题表](../../../sources/runtime-protocol/SOURCE-CLAIMS.md)所列命题；其余必要机制是为保持本条不变量而提出的组织综合设计，不声称由单一外部标准规定。

### NET-MEDIA-02 TURN独立状态与出口

- **触发/前置：** 采用中继。
- **必要机制：** 必须分别维护allocation、permission、channel的身份/寿命/刷新；发数据不刷新allocation，permission按IP且不是用户对象授权。遵守所选RFC规定寿命，项目预算不任意修改协议常量；凭据/出口/配额限制真实生效。
- **不变量：** 持续ChannelData不意味所有状态永不过期；中继不是开放转发器。
- **并发、超时、未知与恢复：** 各状态独立到期/刷新失败有可恢复终态，重建受根预算。中继恢复不恢复已撤销业务许可。
- **产物与观察点：** 各状态期限/刷新、目标地址、拒绝与合成媒体接收。
- **正例：** 按协议各自刷新，permission错误peer被拒。
- **直接失败：** ChannelData一直流动便不刷新allocation，断流后无限重建。
- **合法邻例：** 未使用TURN项目不强制中继费用或部署。
- **可观察验收：** 独立推进到期、错凭据、缺permission和配额，核真实转发/拒绝及恢复。
- **来源与限制：** RP47。来源只支持[逐命题表](../../../sources/runtime-protocol/SOURCE-CLAIMS.md)所列命题；其余必要机制是为保持本条不变量而提出的组织综合设计，不声称由单一外部标准规定。

### NET-MEDIA-03 consent、设备与业务许可

- **触发/前置：** 向对端发送媒体/应用数据。
- **必要机制：** 必须分别满足设备访问、呼叫/对象授权和所选consent协议。RFC7675按其30秒过期要求停止相应5-tuple发送；到期后迟到旧STUN成功响应不重建consent，同一ICE凭据不能再用于受影响5-tuple，须新session或restart新凭据重新取得有效consent。
- **不变量：** NAT保活/任意入站包/本地麦克风许可不能代替接收consent；协议常量不降格成可放宽项目阈值。
- **并发、超时、未知与恢复：** 后台节流/休眠恢复先核有效性；旧响应只审计不恢复发送；合法重建仍重验业务许可。
- **产物与观察点：** 独立许可状态、协议时钟、旧/新凭据代际及真实出站包。
- **正例：** 过期停发，新restart更新两凭据并重新检查后恢复。
- **直接失败：** 过期旧响应到来又发媒体，或用原凭据重建同5-tuple。
- **合法邻例：** 仅接收且不发应用数据的端点按协议无需同样维护发送consent，但恢复发送前须重获。
- **可观察验收：** 隔离端点抑制到期、迟到旧响应、显式撤销与新restart成对实测，断言出站报文及协议时间。
- **来源与限制：** RP48；RP45。来源只支持[逐命题表](../../../sources/runtime-protocol/SOURCE-CLAIMS.md)所列命题；其余必要机制是为保持本条不变量而提出的组织综合设计，不声称由单一外部标准规定。

### NET-MEDIA-04 媒体保护与DataChannel语义

- **触发/前置：** 音视频保护或数据通道。
- **必要机制：** 必须验证信令信任与DTLS指纹绑定，声明SFU/MCU解密主体；应用E2EE另绑密钥成员/撤销。DataChannel按ordered、maxPacketLifeTime/maxRetransmits、大小与缓冲合同选择，重传时限不是端到端deadline，不同channel无总顺序，bufferedAmount不证明对端处理。
- **不变量：** 保护范围不夸大；关键文件/命令不以部分块或队列归零宣告完整。
- **并发、超时、未知与恢复：** 通道/关联关闭保留已交付与未知，文件需要应用完整/恢复；指纹替换/不安全降级拒绝。
- **产物与观察点：** 指纹来源、实际解密主体、通道参数/队列和接收完整性。
- **正例：** 文件用满足契约模式及应用摘要确认；位置样本可无序零重传。
- **直接失败：** SFU能解密却称平台不可见E2EE；部分可靠通道丢块仍报文件完成。
- **合法邻例：** 逐跳加密合法，只要不声称额外E2EE。
- **可观察验收：** 错指纹、模式组合、消息尺寸、缓冲高水位和关联中止核真实接收；成员撤销若承诺E2EE须另验。
- **来源与限制：** RP49；RP50；RP51。来源只支持[逐命题表](../../../sources/runtime-protocol/SOURCE-CLAIMS.md)所列命题；其余必要机制是为保持本条不变量而提出的组织综合设计，不声称由单一外部标准规定。

### NET-MEDIA-05 端到端实时度量与隐私诊断

- **触发/前置：** 声称实时/低延迟或收集排障材料。
- **必要机制：** 必须把采集/生成、编码、排队、网络、抖动缓冲、解码和呈现计入预算，报告分位/尾部/丢失迟到与时钟误差。跨机单向延迟需同步误差，不能相减不同时钟；RTP无QoS保证。日志最小化关联阶段，不导出秘密/私人媒体。
- **不变量：** 均值/RTT不替代音画任务；高精度时钟不保证调度准时或硬实时。
- **并发、超时、未知与恢复：** 后台恢复/拥塞显示实际缺口；采样/日志失败不推断业务未发生，未知根因如实保留。
- **产物与观察点：** 真实阶段统计、音画标记、误差预算、丢失分母和脱敏诊断。
- **正例：** 合成音画从采集到播放测尾延迟，RTT另列。
- **直接失败：** 未同步墙钟相减负延迟就宣称硬实时达标。
- **合法邻例：** 没有单向同步条件可报告可解释RTT与端到端观测，不伪造单向精度。
- **可观察验收：** 目标设备/NAT/中继/负载和后台组合实测，独立复算分位与误差，核诊断材料不含秘密。
- **来源与限制：** RP52；RP43；RP54。来源只支持[逐命题表](../../../sources/runtime-protocol/SOURCE-CLAIMS.md)所列命题；其余必要机制是为保持本条不变量而提出的组织综合设计，不声称由单一外部标准规定。

## 4 兼容、迁移与退役

固定Recommendation/profile与候选修订的边界；各浏览器/设备/编解码组合单独验收。升级ICE/DTLS不自动升级应用身份/订阅，未支持路径如实说明。

## 5 跨域消费接口

消费基线M20–M28、M30–M33；安全提供授权/密钥/成员生命周期，云提供中继与预算，游戏/媒体应用定义可丢样本和关键数据；网络负责可达、保护、consent和真实传输/呈现证据。

接口只定位技术职责，不自动作出规范采用决定。通用状态、测试和制品义务消费 [L3 通用工程 v0.1.0](../../L3/001-通用工程规范--v0.1.0.md)；提供方版本与摘要、应用条款、实现入口和验收责任在项目契约中绑定。提供方保证须由相应实现证据支持，消费方按该保证的实际范围验收。

## 6 真实目标验收合同

受控双浏览器/端点使用固定测试页和合成媒体，采集 `RTCPeerConnection.getStats()`、状态事件、选中candidate pair、datachannel参数及真实收发；分别直连、受限NAT/UDP和已授权中继路径。consent测试由隔离协议端点抑制响应并注入旧响应，观察出站包，而非仅改JS布尔。DataChannel传合成文件核发送/接收摘要、大小、队列和关闭；目标播放用合成音画标记测采集至呈现时延。

**判据：** 错代信令/指纹拒绝；选对后真实媒体可达，TURN各状态正确刷新；RFC7675过期停止发送且旧响应/旧凭据不恢复，合法restart新凭据可恢复；媒体预算含编解码/缓冲/呈现并报告误差。

每次执行保存：正文/条款版本与摘要、目标制品/实现和工具版本、OS/设备/运行时/配置、输入及故障时间线、预期和实际、stdout/stderr/退出码或等价运行证据、权威状态回读、未覆盖范围。`not-run`、模型通过和真实目标通过是不同结果；实际无环境时保留命令和判据而不填写虚构回执。
