# L4 浏览器文档、DOM 与交互组件技术规范

**文档ID：** STD-L4-WEB-007　**版本：** 0.1.0　**状态：** adopted　**生效日期：** 2026-10-30

## 技术边界与依据

**技术对象**：浏览器 HTML 文档、DOM 树与事件系统、表单原生行为、焦点与键盘操作、Custom Elements、Shadow DOM、节点生命周期、动态内容与相关浏览器 API。适用所有使用这些机制的 Web 项目，不限定 React、Vue、Svelte 或原生 JavaScript。
引用标准原文，不复述其完整规范：
- [**WHATWG HTML Living Standard**](https://html.spec.whatwg.org/multipage/)：元素语义、表单、原生交互、自定义元素、Shadow DOM 相关机制。持续更新标准，适用行为须按项目支持的引擎和检查日期核实。
- [**WHATWG DOM Living Standard**](https://dom.spec.whatwg.org/)：节点、事件、监听、AbortSignal 与 DOM 结构。持续更新标准。
- [**W3C WAI-ARIA 1.2**](https://www.w3.org/TR/wai-aria-1.2/)：已发布的 ARIA 语义规范。是否使用特定角色应考虑原生语义优先。
- [**W3C ARIA APG**](https://www.w3.org/WAI/ARIA/apg/)：键盘交互和复杂控件的建议模式，属于实现指南，不可将指南中全部建议无条件定义成业务强制规则。
- [**W3C WCAG 2.2**](https://www.w3.org/TR/WCAG22/)：项目所选无障碍等级的正式要求。
- [**WPT 测试面板**](https://wpt.fyi/)：跨浏览器标准一致性证据；WPT 对浏览器实现的测试通过不等于具体业务页面完整验收。
本文件补充该技术体系的**工程决策、可检查边界和专项失败验证**，不重定义上述权威规范，也不替代对应的 [L4 Web 领域通用基线](002-Web-领域通用基线--v0.1.0.md)、L3、L2 或 L1。具体语言语法、框架组件生命周期、打包策略属于 L5；项目浏览器范围和测试目标由 L6 选定。

## 核验口径与消费接口

维护者负责落实本文机制，领域/API/存储提供者负责其权威保证，验收者从实际受支持入口观察结果。输入固定源码/构建、配置、数据/协议版本、角色/租户、目标平台、故障时序和预算；权威观察对象为**浏览器解析后的节点、事件序列、焦点与原生表单entry list**。真实执行入口为**真实浏览器事件日志、activeElement、Accessibility Tree、表单服务端回显**。逐章 P/F/N 分别为正常输入及判据、破坏该机制的直接失败变异、应继续成立的合法邻例；本章原有每项规则、原有验收与新增合同共同约束，不用单一通用案例替代具体子项。每个子项须在案例输入中保留其适用条件，并以自身原文规定的输出/不变量判定；复合章应拆记录各个观察量，不能以一个成功掩盖其他失败。

证据产物包括真实命令/用户动作、原始响应或事件、权威状态前后值、版本、时序、失败及恢复；尚无对应真实运行证据的场景状态为 `not-run`，标准库示例仅证明列明的局部边界。具体输入与命令见[执行入口](../../../examples/web-backend/RUNBOOK.md)，条款索引见[规范条款登记](../../../registry/requirements.json)，来源的有限支持命题见[逐命题来源映射](../../../sources/web-backend/claims.json)。

本文的跨组件约束与正例、失败反例、合法邻例由本规范综合定义；外部来源支持的机制及适用边界见来源表。项目架构、预算和业务规则由实际需求确定。L5 实现应映射到所选框架、SDK 或引擎；L6 按具体版本的提供者保证与受支持矩阵验收项目能力。

## 一、文档结构与原生语义的工程契约
1. HTML 文档必须由真实用途选择语言、标题、主要内容区域、导航和表单结构；不以带点击监听器的普通容器替代具有现成语义、键盘与失能行为的原生控件。
2. 动态生成 HTML 和 SSR 初始文档遵守 HTML 解析和元素内容模型；浏览器的自动纠错或隐式补全不应改变关键数据字段、表单结构及客户端 Hydration 的实际节点对应关系。
3. 每个交互的可见文本、图标标签、用户动作与原生角色一致。修改已有组件语义时检查下游键盘、焦点、自动填充、表单提交和屏幕阅读器的使用。
4. 对于 document、iframe、portal、top layer 等跨文档或特殊层叠对象，说明实际 DOM 所有者、关联标签及目标浏览器支持范围。
5. **验收**：检查真实渲染的 DOM、可访问名称与原生交互，不仅查看 JSX／模板源码和组件截图。

### WEB-001 核验合同

- **WEB-001-P · 输入/动作与合格判据：** 解析含label/button/表单的SSR文档并以键盘操作→实际DOM/名称/提交结构正确。
- **WEB-001-F · 直接失败变异：** 非法嵌套被解析器重排或div冒按钮却无键盘→失败。
- **WEB-001-N · 合法邻例：** 纯展示容器不添加交互role。

## 二、DOM 节点所有权与组件边界
1. 为受框架管理的 DOM 子树明确渲染所有者；第三方脚本、插件或 Web Components 直接修改同一子树之前，建立受控集成接口，避免框架下一次渲染将其状态覆盖。
2. 命令式 DOM 修改与声明式视图更新需要有明确职责分界。对外部库创建的节点规定挂载、更新、销毁的实际生命周期，不依赖页面刷新“清理”残留引用。
3. 动态组件卸载、切换项目或账号时释放 DOM 引用、事件监听、计时与观察器；对仍在进行的异步任务明确允许继续或取消的行为。
4. 插件与富文本渲染不得凭借持有 DOM 元素指针取得服务端授权或读写其他租户数据；Shadow DOM 的封装不构成安全隔离边界。
5. **验收**：反复挂载／卸载、切换页面和多次更新数据后，不出现幽灵节点、重复监听、重复提交、残留异步写入或失控占用。

### WEB-002 核验合同

- **WEB-002-P · 输入/动作与合格判据：** 框架与插件交替更新并反复卸载→唯一子树所有者及资源账稳定。
- **WEB-002-F · 直接失败变异：** 双写同一节点、旧账号回调写新树→失败。
- **WEB-002-N · 合法邻例：** 插件独占隔离子树可命令式维护。

## 三、事件传播与监听生命周期
1. 将事件传播分成捕获、目标、冒泡和跨 Shadow DOM 的 composed 行为，按平台实际事件定义做委派与阻断，不将 stopPropagation 作为全局修复。
2. 监听器应与组件或页面生命周期绑定；支持时使用 AbortSignal 或等价明确解除机制，注册与解除可核对。事件目标可能被动态替换时，不默认使用旧节点作为稳定身份。
3. 对输入、pointer、keyboard、composition、submit 和自定义事件，区分各事件发出阶段、真实用户动作和程序触发；不能将合成事件当作完整的真实可访问操作。
4. 高频事件在有明确性能证据时实施节流、合并或任务调度，并保证最终状态和取消条件正确；不能因去抖而吞掉必要的提交或用户输入。
5. **验收**：事件监听不重复，嵌套控件不触发额外副作用，动态移除节点后没有失效引用，跨 Shadow DOM 的必要事件能由预期调用方接收。

### WEB-003 核验合同

**必要机制补充：** stopPropagation不取消默认动作，preventDefault也不终止其他监听器；passive监听不能据此阻止默认动作。跨Shadow边界按composed与重定向后的target/composedPath核对。isTrusted不能充当身份或业务授权证明。

- **WEB-003-P · 输入/动作与合格判据：** 嵌套按钮/Shadow事件、动态替换和passive监听→传播、默认动作及解除分别正确。
- **WEB-003-F · 直接失败变异：** stopPropagation误当preventDefault或重复监听造成双提交→失败。
- **WEB-003-N · 合法邻例：** 确实不composed的内部事件无需外泄。

## 四、焦点、键盘和复杂控件
1. 优先使用具有原生焦点行为的控件；非原生可交互组件需明确 Tab 进入／退出、方向键、Enter／Space、Escape、禁用、焦点返回和状态播报的实际约定。
2. 对话框、组合框、菜单、树状控件、选项卡等在选定 APG 模式的基础上，根据具体交互与用户目标实现键盘行为；不能仅因设置 ARIA role 就视为实现了控件。
3. 开闭模态框、删除行、更新列表、客户端路由切换时必须有可预期的焦点去向；不得使用无条件 focus() 或无意义自动滚动反复打断输入。
4. 避免以正 tabindex 制造独立于视觉和 DOM 的混乱导航顺序；不可见、被禁用和加载中的控件遵循实际无障碍树与焦点规则。
5. **验收**：使用仅键盘导航、系统缩放以及至少一种适用辅助技术进行受控操作检查，记录控件、浏览器和辅助技术版本；静态扫描或单一截图不能代替。

### WEB-004 核验合同

- **WEB-004-P · 输入/动作与合格判据：** 键盘开关模态、删除触发器后返回→焦点落在有效后继且状态可读。
- **WEB-004-F · 直接失败变异：** role存在但Tab陷阱、正tabindex破坏任务顺序→失败。
- **WEB-004-N · 合法邻例：** 只读表格不必采用grid箭头模型。

## 五、原生表单与数据提交生命周期
1. 按 HTML 原生表单契约定义字段标签、name、type、合法值、required、disabled、readonly、自动填充、数据序列化、重置、提交按钮和错误反馈。不同状态在提交时的值与服务端契约保持一致。
2. 区分 input、change、beforeinput、composition、submit、formdata 等事件的真实阶段，不在多语言输入法组合期间任意篡改尚未确认的文本。
3. 使用 requestSubmit() 等 API 需要核实其是否实际触发原生校验和提交事件；不得通过绕过表单行为的事件模拟宣称完成原生校验。
4. 表单重复提交、迟到响应和网络未知结果由 UI 与权威服务端共同协调；客户端按钮锁定只是减少误操作，不能替代服务端幂等。
5. 对 form-associated custom elements（如实际使用）须检查目标浏览器是否支持 ElementInternals、提交值、重置、有效性和错误报告。未支持时有真实降级或明确限制。
6. **验收**：覆盖鼠标、Enter 键提交、多语言 IME、浏览器自动填充、无效输入、字段禁用、重置及服务端拒绝，确保用户可纠正错误且数据未丢失。

### WEB-005 核验合同

**必要机制补充：** form.submit()绕过交互约束验证和submit事件；requestSubmit(submitter)按实际submitter进入验证/提交算法。disabled、未选复选框、无name及非submitter按钮的entry构造不同于readonly字段。进入pending前先固定应提交快照，不能因禁用字段/提交按钮意外删掉其name/value。IME组合期间的Enter不得被错误转换为业务确认；beforeinput不在所有输入路径均可取消，实际事件顺序以目标浏览器/IME记录为准。

- **WEB-005-P · 输入/动作与合格判据：** 原生点击/Enter/requestSubmit、IME、autofill和重置→submitter/entry list与服务端一致。
- **WEB-005-F · 直接失败变异：** form.submit绕过校验却宣称requestSubmit等价，合成事件冒真实输入→失败。
- **WEB-005-N · 合法邻例：** disabled字段按HTML不提交，readonly的适用控件仍可提交。

## 六、自定义元素和 Shadow DOM 边界
1. 使用 Custom Elements 前明确与现有框架组件的关系、命名、实例属性同步、属性反射和 upgrade 时序，不把未知时序解释为随机 UI 故障。
2. connectedCallback、disconnectedCallback、attributeChangedCallback 等生命周期回调涉及异步任务或观察器时，必须可重复、可安全清理；多次连接不得重复订阅或丢失必要状态。
3. Shadow DOM 需明确 slot 分发、样式继承、焦点、事件重定向、可访问名称及外层调用方事件 API；closed shadowRoot 并非敏感数据保密或身份鉴权措施。
4. 组件资源加载失败或宿主元素在初始化前被移除时，必须恢复页面可用状态并释放资源；不要让浏览器内部状态被静默当成业务成功。
5. **验收**：在直接创建、移除、迁移 DOM 节点和异步升级等场景运行实际浏览器验证。

### WEB-006 核验合同

- **WEB-006-P · 输入/动作与合格判据：** 元素先设属性再upgrade，连接/移除/迁移→反射、slot、焦点和订阅可重复。
- **WEB-006-F · 直接失败变异：** closed shadowRoot被当鉴权或重连重复订阅→失败。
- **WEB-006-N · 合法邻例：** 组件未用表单关联无需ElementInternals。

## 七、MutationObserver、异步更新与性能
1. Observer 的订阅对象、监视选项、回调频率和取消条件应与真实数据流一致；DOM 写操作触发自身观察回调时应避免无限循环。
2. 与 resize、intersection、animation frame、microtask 和用户事件调度协作时，要控制读写交错、布局重复计算和滚动位置抖动。
3. 大规模节点更新必须按实际性能 Profile、输入规模和目标设备测量；避免以单次开发机快速响应替代目标用户设备的性能证据。
4. **验收**：动态批量更新与销毁之后，监听和观察器数量稳定，交互无错误重复，CPU／内存和帧间隔在项目已选预算内。

### WEB-007 核验合同

- **WEB-007-P · 输入/动作与合格判据：** Observer触发批量DOM写后卸载→无自激循环、读写有界且最终帧正确。
- **WEB-007-F · 直接失败变异：** 自身mutation无限回调或移除后继续观察→失败。
- **WEB-007-N · 合法邻例：** 小数据无需批处理优化。

## 八、动态 HTML 和 DOM 注入安全
1. 用户文本、第三方数据、模型输出、Markdown、富文本及 URL 一律按实际信任级别处理；普通文本优先安全文本 API，确需 HTML 时采用适用于目标上下文的可靠编码或净化。
2. 插入 DOM 的脚本、事件处理属性、URL Scheme、样式 URL、模板插值及跨窗口消息，需要分别按相关安全领域规范确认，不能依靠简单字符串替换或只禁止 script 标签保证安全。
3. CSP、Trusted Types、沙箱 iframe 和第三方脚本管理按项目威胁模型实施；安全策略兼容例外不得被默默放宽为不受限制的脚本执行。
4. **验收**：按实际富文本入口构造可证明的无害攻击测试样例，验证未授权 DOM 操作、脚本执行和敏感数据泄露不会发生；单一静态扫描不能宣称无漏洞。

### WEB-008 核验合同

- **WEB-008-P · 输入/动作与合格判据：** 富文本分别含属性/URL/HTML无害探针→上下文净化且合法内容保真。
- **WEB-008-F · 直接失败变异：** 仅删script、宽松Trusted Types policy直接返回输入→失败。
- **WEB-008-N · 合法邻例：** 纯文本用textContent保留尖括号原义。

## 九、与框架及第三方控件的集成
1. React、Vue、Svelte、原生 Web Components 或三方可视化工具共享同一页面时，必须明确谁拥有节点、状态和生命周期；事件和数据同步通过显式适配接口。
2. SSR/Hydration 后节点身份或事件附着改变时，需测试首屏、用户输入到初始化期间的状态保留和功能恢复。
3. 外部控件必须满足项目选定的焦点、键盘、语义、卸载和安全要求，不能因官方 Demo 可用就默认全部用户场景满足要求。
4. **验收**：目标框架升级、路由卸载、第三方组件重挂载和旧客户端缓存共存时，业务状态不丢失、控件不会重复触发事件。

### WEB-009 核验合同

**必要机制补充：** 接管前原生默认提交与框架事件重放必须协调为同一个逻辑意图；恢复不能重复消费同次用户动作。

- **WEB-009-P · 输入/动作与合格判据：** 慢JS期间输入并重挂三方控件→接管后草稿、节点和事件各一次。
- **WEB-009-F · 直接失败变异：** 初始化重放与原生默认动作双执行→失败。
- **WEB-009-N · 合法邻例：** 纯静态无脚本控件按原生路径完成。

## 十、专项测试矩阵
| 独立情形 | 验证对象 | 合格证据 |
| --- | --- | --- |
| 普通按钮和自定义按钮 | 键盘输入、焦点与禁用 | 原生与定制控件按适用语义完成相同用户动作，必要 ARIA 状态准确 |
| 嵌套点击区域 | 捕获／冒泡与重复写入 | 点击子控件只产生该动作实际允许的副作用 |
| 组件反复挂载与卸载 | 监听、观察器、资源 | 无重复触发，无废弃 DOM 回调及明显泄漏 |
| IME 输入及表单 Enter | composition／input／submit | 输入法候选处理、原生提交和服务端字段一致 |
| 自定义元素前后升级 | 连接／属性与回调顺序 | 节点动态插入、删除、升级后状态仍一致 |
| Shadow DOM 事件和焦点 | slot、composed、事件重定向 | 调用者可接收约定事件，焦点可预测，未伪造安全隔离 |
| 不可信富文本插入 | HTML／URL 注入边界 | 无越权脚本执行或敏感信息外泄，并遵守实际安全配置 |
| SSR 与客户端初始化 | 节点、事件、初始用户输入 | 初次渲染与可交互状态一致，未丢失操作或出现重复事件 |

## 十一、项目接入与生效限制
