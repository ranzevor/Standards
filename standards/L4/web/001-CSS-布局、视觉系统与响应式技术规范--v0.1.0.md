# L4 CSS 布局、视觉系统与响应式技术规范

**文档ID：** STD-L4-WEB-001　**版本：** 0.1.0　**状态：** adopted　**生效日期：** 2026-10-30

## 技术范围、权威来源与适用条件

本规范是 L4 Web 领域下的**具体技术专题**，适用于浏览器 CSS 层叠与继承、盒模型与尺寸计算、布局算法、响应式适配、文字排版、视觉主题、层叠定位、动态样式、样式性能及跨浏览器验证。不以 React、Vue、Tailwind 或特定构建工具为准入条件。
相应依据：[L4 Web 领域通用基线](002-Web-领域通用基线--v0.1.0.md)（Web 领域通用基线）、[L4 浏览器文档、DOM 与交互组件技术规范](007-浏览器文档、DOM-与交互组件技术规范--v0.1.0.md)（DOM 与交互）、[L3 通用工程规范](../../L3/001-通用工程规范--v0.1.0.md)（通用工程）、[L2 人类与 Agent 团队组织协作规范](../../L2/001-人类与-Agent-团队组织协作规范--v0.1.0.md)（团队协作）、[L1 全局治理补充规范](../../L1/001-全局治理补充规范--v0.1.0.md)（治理）。
行业已有规范**直接引用官方原文**，本文不重写 CSS 属性及算法定义：
- [**CSS Working Group Current Work**](https://www.w3.org/Style/CSS/current-work)：CSS 模块及各自发布状态总索引。
- [**CSS Cascading and Inheritance Level 5**](https://www.w3.org/TR/css-cascade-5/)：级联、继承、@layer；发布为 Candidate Recommendation Snapshot，引用所选版本时须核对页面状态。
- [**CSS Flexible Box Layout Level 1**](https://www.w3.org/TR/css-flexbox-1/)、[**CSS Grid Layout Level 2**](https://www.w3.org/TR/css-grid-2/)：一维与二维布局；相应版本属候选推荐阶段，不视为已发布最终 W3C Recommendation。
- [**CSS Box Sizing Level 3**](https://www.w3.org/TR/css-sizing-3/)、[**CSS Values and Units Level 4**](https://www.w3.org/TR/css-values-4/)、[**CSS Overflow Level 3**](https://www.w3.org/TR/css-overflow-3/)：内在尺寸、长度单位和溢出机制。
- [**CSS Conditional Rules Level 5**](https://www.w3.org/TR/css-conditional-5/)：容器查询及新条件规则；属于持续发展的草案，不将其中实验性特性默认视作浏览器已全面支持。
- [**Media Queries Level 5**](https://www.w3.org/TR/mediaqueries-5/)、[**CSS Logical Properties Level 1**](https://www.w3.org/TR/css-logical-1/)：设备／偏好条件与书写方向相对布局。
- [**CSS Color Level 4**](https://www.w3.org/TR/css-color-4/)、[**CSS Fonts Level 4**](https://www.w3.org/TR/css-fonts-4/)：色彩空间与字体。
- [**W3C WCAG 2.2**](https://www.w3.org/TR/WCAG22/)：需要满足的可访问性标准由项目确认；具体阅读器／交互契约另见 DOM 专项。
- [**Web Platform Tests**](https://wpt.fyi/)：用于识别跨浏览器实现差异，不能代替实际页面验收。
L5 负责具体 CSS 构建工具、预处理器、CSS-in-JS、Tailwind 及各框架的编译／组件样式实现；L6 负责选定浏览器、显示环境、支持语言、项目视觉要求和对应门禁。行业标准的发布级别、引用版本、审阅日期均需登记，不能把编辑草案当作无条件强制条文。

## 一、样式所有权、级联与可维护性
1. 每个样式来源须明确归属：浏览器默认、项目基础样式、设计 Token、组件样式、第三方库、用户偏好及状态覆盖。框架作用域、CSS Modules 或 Shadow DOM 不能替代实际的级联关系审查。
2. 项目确需 @layer 时先明确层顺序与作用范围。**普通声明与 !important 声明的层优先级方向不同**；引入或迁移第三方 CSS 时应验证，不能依赖不断增加的选择器特异性或全局 !important 覆盖修复。
3. 在重要控件上采用实际范围明确的类、属性或组件作用域；避免依赖深层 DOM 结构和动态生成类名作为公共 API。采用 @scope 或新选择器时先核对项目浏览器实际支持范围。
4. 基础 Reset 或 Normalize 不得悄悄移除原生焦点、列表语义、文字缩放、系统偏好和输入控件必要行为。样式重置后的可用性需要真实浏览器验证。
5. **验收**：第三方样式导入、组件组合、主题覆盖与更新后，视觉结果可预测，没有影响无关业务模块的全局覆盖；在开发者工具中能追踪声明来源和级联顺序。

### WEB-001 核验合同

- **WEB-001-P · 输入/动作与合格判据：** 导入第三方CSS并比较普通/important层序→Computed Style来源符合级联且焦点仍见。
- **WEB-001-F · 直接失败变异：** 用全局important掩盖反向层序、reset清除焦点→失败。
- **WEB-001-N · 合法邻例：** 无需layer的局部样式可保持简单。

## 二、设计 Token、主题与视觉状态契约
1. 有跨页面复用需求时，将间距、排版、颜色、表面、边框、阴影、层级、动效等稳定设计决定映射为清晰的可复用 Token；只有单个组件使用的局部值无需制造一套全局抽象。
2. 区分产品批准的视觉含义（危险、成功、注意、禁用）与纯装饰颜色，不能通过统一变量将不同业务状态意外混同。
3. CSS Custom Properties 的定义位置、继承范围、主题覆盖及必要回退值应明确；避免循环引用、意外继承和缺失 Token 导致关键控件不可见。
4. 主题切换时同步检验文字、图表、状态、交互焦点、滚动条、媒体资源和被嵌入子界面；暗色方案不能只更改背景和正文颜色。
5. **验收**：以实际设计 Token 使用点覆盖正常、悬停、聚焦、选中、禁用、错误及系统偏好；关键状态不只靠颜色区别。

### WEB-002 核验合同

- **WEB-002-P · 输入/动作与合格判据：** 切明暗主题及错误/禁用/聚焦→Token继承和状态含义一致。
- **WEB-002-F · 直接失败变异：** 缺变量使按钮透明或成功/危险同义→失败。
- **WEB-002-N · 合法邻例：** 仅一个组件用的局部值无需全局Token。

## 三、盒模型、内在尺寸与内容约束
1. 布局尺寸由内容约束与组件用途决定，明确 box-sizing、min/max-size、可替换元素、宽高比与内在尺寸，不以固定像素硬编码掩盖未定义的容器责任。
2. 对 Flex/Grid 的自动最小尺寸、min-content 和 max-content 等约束实施内容压力测试；存在长链接、国际化文本、代码、数据表格或媒体时，不得通过全局隐藏溢出来伪装“未超出”。
3. 图片、视频、Canvas 和可视化容器需要适当的 aspect-ratio、intrinsic fallback 与尺寸预留，避免加载引发明显布局跳动或错误裁切。
4. 尺寸算法在嵌套百分比、自动高度、绝对定位和容器查询结合时要实际测量，禁止依赖在单一固定分辨率上恰好成立的结果。
5. **验收**：含最长实际文本、空数据、最大合理数据量及异步资源的组件，按目标容器可正常伸缩，关键内容可见并可操作。

### WEB-003 核验合同

- **WEB-003-P · 输入/动作与合格判据：** 最长URL、空数据和晚到媒体放入嵌套百分比容器→可见且尺寸稳定。
- **WEB-003-F · 直接失败变异：** 根overflow:hidden藏掉必需字段→失败。
- **WEB-003-N · 合法邻例：** 允许横向滚动的代码区保留可达内容。

## 四、Flexbox 与 Grid 的布局职责
1. 一维分配优先按 Flex 布局模型理解主轴、交叉轴、换行、收缩与剩余空间；二维行列关系按 Grid 或其他适合的布局机制表达，不为了统一写法将所有页面强制改造为 Grid 或 Flex。
2. 布局顺序不能仅由 CSS 的 order、grid placement 或反向轴方向创造与 DOM 阅读和键盘焦点不一致的逻辑操作顺序。视觉重排需与真实交互顺序一并核验。
3. 使用 Grid track、minmax、auto-fit／auto-fill 或 subgrid 时核对最大／最小尺寸、内容溢出、子网格支持与浏览器差异；多级嵌套不应产生不可见或不可滚动区域。
4. Flex 子项的默认收缩、内在尺寸及未定义最小宽度可能引起布局溢出，应按实际组件和最小尺寸约束解决，不能直接删掉用户需要的字段。
5. **验收**：在混合宽度、长文案、动态条数、国际化和输入法下检查换行、对齐、操作顺序、焦点与数据完整性。

### WEB-004 核验合同

- **WEB-004-P · 输入/动作与合格判据：** Flex/Grid长文案及换行并用Tab走一遍→视觉与逻辑操作序一致。
- **WEB-004-F · 直接失败变异：** order把支付确认按钮读序移到错误位置→失败。
- **WEB-004-N · 合法邻例：** 一维普通布局无需改成Grid。

## 五、响应式媒体查询与容器查询
1. 根据实际内容失效点和用户操作设计布局断点，而不以某一款手机、显示器或框架默认断点作为唯一依据。
2. @media 处理设备／环境状态与用户偏好，@container 处理独立组件在容器内部的可用空间或其他实际支持的条件；使用容器查询前确认能够选取正确的查询容器，并了解尺寸 containment 对布局的影响。
3. 可能被嵌入侧栏、对话框、可调整网格或多窗口布局的组件，应以实际**容器宽度**而非仅视口宽度决定排版；支持不足时设计不损害基本任务的回退布局。
4. @supports 和渐进增强只证明某一 CSS 特性可解析或支持相应声明，不能直接证明完整组合布局符合所有浏览器的真实行为。
5. **验收**：同一个组件在等宽但不同视口、相同视口但不同容器等场景下，仍按实际可用空间适配；验证横竖屏及动态调整容器尺寸。

### WEB-005 核验合同

- **WEB-005-P · 输入/动作与合格判据：** 相同视口调侧栏宽及同宽容器换视口→按真实容器适配。
- **WEB-005-F · 直接失败变异：** 只测@supports解析就宣布组合布局可用→失败。
- **WEB-005-N · 合法邻例：** 无容器查询的流式布局可合法满足任务。

## 六、视口单位、缩放和安全区域
1. 使用 viewport-relative 单位时区分大、小、动态视口（如 lvh、svh、dvh）及浏览器 UI 对可见区域的变化；不得默认传统 vh 永远代表移动端可操作高度。
2. 在全屏、底部固定操作、沉浸式界面和有刘海或系统导航区域的设备上，适用时处理 safe-area 环境变量、软键盘遮挡以及滚动恢复。
3. 页面要接受用户浏览器缩放、操作系统文字放大、字体替换与实际可用内容宽度变化；不能通过禁止页面缩放来压制视觉问题。
4. 对移动端浏览器工具栏伸缩、横竖屏切换及软键盘弹出后是否能够滚动到必要输入与提交按钮进行真实设备或可信浏览器测试。
5. **验收**：触控可达、关键表单和操作按钮未被系统区域遮挡，放大后不丢失完成任务必需的信息。

### WEB-006 核验合同

**必要机制补充：** dvh随动态浏览器界面变化，不保证随覆盖式屏幕键盘缩小；必须在目标设备检查可视区、滚动和必要时VisualViewport相关行为，不能以改用dvh一项宣称解决全部遮挡。

- **WEB-006-P · 输入/动作与合格判据：** 移动工具栏/软键盘/旋转/200%缩放→提交区可滚动到达。
- **WEB-006-F · 直接失败变异：** 100vh固定裁切或禁止缩放→失败。
- **WEB-006-N · 合法邻例：** 不涉及安全区的普通桌面页不加空白占位。

## 七、定位、层叠上下文与浮层
1. 对 fixed、sticky、absolute、relative、transform 生成的 containing block 和 stacking context 进行真实布局设计，不将单一的 z-index 数值表当作完整层叠行为。
2. 对话框、Popover、Tooltip、菜单与非模态面板需要确认由谁管理浮层及焦点；浏览器 top layer 与普通 stacking context 不可简单互换，视觉覆盖不能代替实际交互隔离。
3. sticky 区域与祖先 overflow、滚动容器高度及导航栏相互影响时应有明确约束，不能只在无滚动的静态截图检查。
4. 需要视觉叠放时，提示和关键操作应有稳定可见位置；不得为提升 z-index 导致敏感内容遮挡、无法关闭或键盘焦点丢失。
5. **验收**：多重浮层、长页面滚动、动态定位目标移除、浏览器缩放与触控键盘打开后，前景对象可操作且不会遮挡必要业务任务。

### WEB-007 核验合同

- **WEB-007-P · 输入/动作与合格判据：** 嵌套模态/transform祖先/sticky长滚动→顶层可操作、焦点返回有效。
- **WEB-007-F · 直接失败变异：** 增z-index仍被祖先裁切或背景可提交→失败。
- **WEB-007-N · 合法邻例：** 非模态popover允许合同规定的外部交互。

## 八、溢出、滚动和动态内容
1. 为页面与局部容器明确负责滚动的层级、轴向、滚动位置保留与内容可达性；禁止仅因布局错位便在根容器一律使用 overflow: hidden。
2. 横向数据表、代码区、图形与长文本在滚动出现时，仍需保持标签、上下文、操作按钮和焦点可访问；滚动条存在与否不得改变核心业务信息。
3. 嵌套滚动、弹窗滚动锁、Scroll Snap、overscroll 行为和焦点自动滚动需要实际按设备交互测试，不使返回、键盘操作或关闭动作陷入不可恢复状态。
4. 虚拟滚动或 content-visibility 等优化与真实可访问性树、动态高度和项目截图／自动化测试发生冲突时，须评估并验证实际收益与可用性。
5. **验收**：短内容、超长内容、弹窗、多容器嵌套和实际输入聚焦后，不出现被裁掉且无法触达的必要内容。

### WEB-008 核验合同

- **WEB-008-P · 输入/动作与合格判据：** 打开长弹窗并嵌套滚动/虚拟列表→焦点与每项必要内容可达。
- **WEB-008-F · 直接失败变异：** 锁根滚动后关闭不恢复或虚拟项丢失语义→失败。
- **WEB-008-N · 合法邻例：** 大表格可合法横向滚动。

## 九、字体排版、多语言与书写方向
1. 字体家族、fallback、字重、行高、字距、字形变体与 Unicode 字符范围应服务于项目真实语言需求；不能以开发机器装有某字体作为用户端可用性证据。
2. 中文、英文、数字、标点、表格数字、RTL、竖排或多语混排（实际需要时）需核对断词、换行、字形宽度、可读性和文字选择行为。
3. 逻辑属性和 writing-mode 应表达随书写方向变化的布局意图；物理 left/right/top/bottom 若用于固定方向装饰，需明确其适用理由。
4. Web 字体的文件大小、字体子集、异步加载、字体回退、font-display 和文本度量差异需权衡真实性能与布局稳定性；不能以加载动画掩盖没有文本的首屏。
5. **验收**：按受支持语言、系统字体替代、文字放大及真实最长文本测量，无不可接受的行溢出、裁切、重叠或关键数字误读。

### WEB-009 核验合同

- **WEB-009-P · 输入/动作与合格判据：** 缺Web字体并切CJK/RTL/最长数字→断行、逻辑方向、数值可读。
- **WEB-009-F · 直接失败变异：** 本机字体掩盖缺字或裁掉负号→失败。
- **WEB-009-N · 合法邻例：** 固定方向装饰可用物理left/right。

## 十、色彩、主题及视觉可访问性
1. 将颜色、对比、状态和图像的关系根据用户可理解的视觉语义设计；不把外部标准规定的颜色计算算法重写为本项目私有算法。
2. 项目选择使用的 sRGB、广色域、OKLCH 或其他颜色空间，应依据显示设备、浏览器支持和既有设计资源确定，并验证色域外映射、回退和对比表现。
3. 正式交互产品的文字、UI 组件和信息图标按项目 L6 指定的 WCAG 标准及适用成功准则核验；以实际最终背景、状态和组件叠加条件检测，不能只凭 Token 名称表示“高对比”。
4. 支持 dark mode、forced-colors、prefers-contrast 等用户偏好时检查浏览器的真实系统模式，必要视觉边界不能仅靠背景图、阴影、半透明覆盖提供。
5. **验收**：切换主题、系统高对比、背景图片、禁用态和不同设备色彩条件时，关键业务内容可读且状态不会仅由颜色表达。

### WEB-010 核验合同

- **WEB-010-P · 输入/动作与合格判据：** 主题/forced-colors/透明背景组合→实际最终背景下达到所选准则。
- **WEB-010-F · 直接失败变异：** Token名叫高对比但实际对比不合格→失败。
- **WEB-010-N · 合法邻例：** 纯装饰色差无需等同业务失败。

## 十一、动效、过渡与运动偏好
1. 动效应具有明确反馈或界面引导价值；不得因视觉效果过度消耗资源、阻断输入或延迟重要业务操作。
2. 遵从实际系统与用户设置的 prefers-reduced-motion；对非必要位移、旋转、连续缩放和强烈过渡提供降低或替代行为，并检验变化后的信息仍然可理解。
3. 对滚动驱动动画、视图过渡、复杂 transform、滤镜与过度阴影等，在实际目标浏览器及设备中确认可用性与动画取消行为。
4. CSS 动画完成事件不能作为真实服务端事务已完成的证明；动画被跳过或用户减弱动效时业务流程仍必须正确。
5. **验收**：开启/关闭减弱动效、快速重复操作、页面离开及后台恢复时，无残留交互锁、隐藏内容或状态错乱。

### WEB-011 核验合同

- **WEB-011-P · 输入/动作与合格判据：** 减弱动效中重复激活并导航→流程不依赖animationend且无锁残留。
- **WEB-011-F · 直接失败变异：** 动画跳过即永不提交或取消后旧动画改状态→失败。
- **WEB-011-N · 合法邻例：** 必要状态反馈可用无位移替代。

## 十二、图像、媒体与视觉资源尺寸
1. 背景图、插图、图标、SVG 和视频容器的尺寸与裁剪策略要保留实际必要内容；使用 cover 等填充模式前验证关键主体不会被不同容器裁掉。
2. 对异步加载的媒体资源设置与布局意图相称的占位尺寸／宽高比，避免影响表单、操作定位和布局稳定性。
3. 引用 CSS 外部资源时核对来源、字体／图像许可、缓存、加载失败与隐私边界。包含凭据、私有参数和未经授权用户数据的 URL 不应经第三方样式资源传播。
4. 不把装饰性伪元素作为传达必须读取的完整业务内容的唯一途径；适用的文本替代和读屏内容须由 DOM 及无障碍契约保障。
5. **验收**：目标尺寸、DPR、图片加载失败与系统强制颜色时，用户仍能理解必要字段和完成操作。

### WEB-012 核验合同

- **WEB-012-P · 输入/动作与合格判据：** 不同DPR/容器/图片失败→主体、替代文本与占位完整。
- **WEB-012-F · 直接失败变异：** cover裁掉合同金额或伪元素唯一承载关键文本→失败。
- **WEB-012-N · 合法邻例：** 装饰背景无需逐图朗读。

## 十三、样式性能、渲染与资源管理
1. 依据实际页面测量 Style Recalculation、Layout、Paint、Composite、字体加载及长任务，而非以样式文件较短、类名较少或启用某个构建插件直接宣称性能提升。
2. 性能优化应优先基于真实瓶颈，谨慎采用 contain、content-visibility、will-change 等机制，明确其对布局尺寸、可访问性、内存及合成层的副作用。
3. 对高频动态组件、动画和拖拽的布局读写，需要避免无意义的同步布局测量与多次级联更新，并确认状态变化在正确帧呈现。
4. CSS 资源切分、关键样式内联、第三方样式加载及 font preloading 应按真实网络条件验证，不能为了合成性能分数而破坏加载顺序或安全策略。
5. **验收**：以目标设备与页面规模记录性能基线和候选数据，并同时复核视觉、交互和内容完整性。单次合成测试不代表真实用户分位数达标。

### WEB-013 核验合同

- **WEB-013-P · 输入/动作与合格判据：** 真实Trace比较批量更新前后→布局/绘制改善且焦点和内存不退化。
- **WEB-013-F · 直接失败变异：** 加will-change无收益却膨胀层内存→失败。
- **WEB-013-N · 合法邻例：** 无性能瓶颈不强制contain。

## 十四、第三方样式、设计系统与封装边界
1. 采用组件库、CSS reset、嵌入式第三方工具、白标主题或多租户定制时，需明确其层叠入口、变量覆写、样式隔离和兼容更新责任。
2. 外部 CSS 的选择器及导入顺序不得无控制地覆盖本项目业务状态和关键交互。样式包版本升级需在真实受影响页面进行视觉与行为回归。
3. 主题、品牌和业务数据为不同维度；租户视觉定制不应改变权限、金额、权益及其他服务器权威数据。
4. CSS-in-JS、CSS Modules、预处理器、Utility 类框架和构建优化的具体用法属于 L5；本领域只约束其产物的真实浏览器行为和回归质量。
5. **验收**：样式包版本切换、动态主题、嵌入式组件及第三方弹窗组合时，级联、字体、焦点和内容边界符合实际契约。

### WEB-014 核验合同

- **WEB-014-P · 输入/动作与合格判据：** 升级组件库并切白标主题→级联、字体和业务字段仍正确。
- **WEB-014-F · 直接失败变异：** 租户主题改变权限或三方样式覆盖禁用态→失败。
- **WEB-014-N · 合法邻例：** 框架具体类名组织可由L5选择。

## 十五、兼容性、渐进增强和失效回退
1. 新版 CSS 功能在项目受支持浏览器中必须有实际证据。CSS WG 正式标准、候选推荐、工作草案和 Editor’s Draft 是不同发布状态；规格先进不意味着实现已广泛兼容。
2. 对较新的 subgrid、容器查询、动态视口、新颜色函数、@scope 或其他特性，按目标浏览器可用性决定直接采用、声明条件回退或限定环境。此列举不表示所有特性都缺少支持。
3. @supports、降级样式和构建时转换应检测必要能力及真实视觉结果。无效规则被浏览器忽略后，关键内容不得消失或成为不受控的错误布局。
4. 需区分浏览器 BUG、标准行为、预处理器输出、用户样式与第三方覆盖，避免针对单一异常引入破坏其他环境的全局补丁。
5. **验收**：至少按项目浏览器矩阵验证关键页面，保留具体引擎及版本、视口、字体、语言、主题和回退效果；Web Platform Tests 只能辅助理解标准覆盖。

### WEB-015 核验合同

- **WEB-015-P · 输入/动作与合格判据：** 移除新CSS能力并跑目标引擎→基本任务有真实回退。
- **WEB-015-F · 直接失败变异：** 无效规则被忽略后内容消失→失败。
- **WEB-015-N · 合法邻例：** 装饰增强缺失不影响支持承诺。

## 十六、打印、导出与特殊输出（按需）
1. 只有实际包含打印、PDF、离线静态截屏、嵌入报告或高分辨率导出时，才启用对应 print/分页/色彩/字体规则。
2. 当某种输出承载合同、报价、报告或重要数据时，必须确保分页与裁切不丢失必要业务字段、签名、金额和条件；屏幕布局不能直接假定打印可用。
3. 纸张、字体及媒体色彩的特殊规则以实际目标渠道和受支持平台确认，必要时引用相应 CSS Paged Media 标准，不在此重复其算法正文。
4. **验收**：使用实际生成链路核对完整性、分页、真实资源、颜色和多语言布局；静态预览不代表最终 PDF/打印结果准确。

### WEB-016 核验合同

- **WEB-016-P · 输入/动作与合格判据：** 实际打印/PDF长表及多语言→所有金额、条件、分页完整。
- **WEB-016-F · 直接失败变异：** 屏幕预览好但最终PDF裁掉签名→失败。
- **WEB-016-N · 合法邻例：** 无打印/导出功能不承担分页门禁。

## 十七、CSS 专项静态质量门禁
1. 通过 CSS 解析、依赖／构建检查，确认无无效语法、无意覆盖、未使用的巨大样式包以及危险的第三方资源引入；具体 Lint 工具及其版本由 L5 配置。
2. 主要公共 UI 在设计与代码审查时检查内容尺寸、溢出、暗色／高对比、焦点、缩放、多语言和真实可访问性；不把“视觉像设计稿”作为唯一完成条件。
3. 回归用例必须对准实际版本、目标浏览器、正确字体、系统偏好、设备像素比、主题和资源加载条件。像素级截图可辅助发现差异，但需要区分抗锯齿和字体渲染的无害差异与真实内容损失。
4. 严重影响业务可用性、遮挡必要操作或造成越权内容可见的视觉故障应纳入阻断检查；纯装饰差异由项目确定风险级别，避免所有微小像素偏差都阻塞发布。
5. **验收**：规范文本、自动工具输出、视觉截图和真实浏览器交互分开记录；测试通过仅证明其覆盖的条件成立。

### WEB-017 核验合同

- **WEB-017-P · 输入/动作与合格判据：** 固定字体/DPR/主题比较候选并交互→重大内容损失阻断。
- **WEB-017-F · 直接失败变异：** 更新错误截图基线或遮罩掉焦点缺陷→失败。
- **WEB-017-N · 合法邻例：** 抗锯齿无害差异可有受控容差。

## 十八、技术验收场景矩阵
| 场景 | 重点检查对象 | 合格条件 |
| --- | --- | --- |
| 第三方样式覆盖 | @layer、特异性及 !important | 级联优先级符合预期，关键状态与用户样式不被意外覆盖 |
| 长文本和长链接 | min-content、Flex/Grid、换行 | 容器可用、关键字段不裁切，滚动及选择不失效 |
| 复杂二维表格 | Grid／Flex 伸缩及溢出 | 数值列与操作仍可辨认、可达 |
| 视觉重排 | order、阅读和焦点顺序 | 视觉与操作顺序不产生无法理解的矛盾 |
| 同视口不同容器 | @container 查询对象 | 组件按实际容器尺寸切换，非只依赖窗口宽度 |
| 小屏幕与软键盘 | 动态视口、安全区域、滚动 | 提交、关闭、错误定位等关键操作可达 |
| 多层弹窗及悬浮面板 | stacking context、top layer、sticky | 交互区域和焦点可恢复，无必要控件被永久遮挡 |
| 语言切换与字体加载 | CJK、RTL、fallback、line-height | 文本不重叠、不误读、不丢业务内容 |
| 系统深色与高对比 | Token、颜色空间、forced-colors | 必要状态可分辨，项目选择的对比目标成立 |
| 用户减弱动效 | prefers-reduced-motion | 动态反馈仍清楚，不发生业务状态遗漏或交互锁定 |
| 媒体加载延迟 | aspect-ratio、尺寸占位 | 无破坏关键操作的跳动或严重裁剪 |
| 高频动态列表 | Layout/Paint、contain、滚动 | 性能满足预算，内容与焦点未因优化丢失 |
| CSS 新特性不支持 | @supports、回退、目标浏览器 | 基本任务仍可完成，明确能力限制不被伪装为成功 |
| 打印或 PDF 导出 | 分页、裁切、字体和业务字段 | 实际导出含全部必要内容；无该需求的项目不启用 |
| 截图视觉回归 | 浏览器／字体／DPR／主题 | 差异可复核，不能用截图一致代替真实交互验收 |
## 十九、项目接入、证据与专项分工
项目 L6 选择目标屏幕、浏览器引擎与版本、语言、字体来源、用户偏好、可访问性等级、性能预算、是否支持离线／打印及其他真实契约。通过源代码检查、真实浏览器交互、截图、性能 Trace、视觉对比和自动化测试形成可复核证据，必要时记录已知差异及替代方案。项目不具有的功能无需做形式性验收。
本专题对应浏览器 CSS 模块的实际布局／呈现行为；HTML/DOM 事件、交互与表单结构以相邻 DOM 技术规范为准，SSR、状态与网络、安全系统另在各自 L4 专题中制定。Tailwind、Sass、PostCSS、CSS Modules、CSS-in-JS、UI 框架和具体构建工具的版本与使用约束由 L5 按实际技术栈另行制定。
本文技术条款及场景的文本覆盖不意味着任何真实站点、浏览器、辅助技术或生产环境已经完成测试。行业 CSS 标准继续以官方原文为准，项目实际适用和验收由 L6 独立实施。
