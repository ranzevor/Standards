## 核验口径与消费接口

维护者负责落实本文机制，领域/API/存储提供者负责其权威保证，验收者从实际受支持入口观察结果。输入固定源码/构建、配置、数据/协议版本、角色/租户、目标平台、故障时序和预算；权威观察对象为**最终role/name/state/relations、用户焦点与完整任务结果**。真实执行入口为**真实键盘、中文IME、选定屏幕阅读器的朗读/操作记录、Accessibility Tree**。逐章 P/F/N 分别为正常输入及判据、破坏该机制的直接失败变异、应继续成立的合法邻例；本章原有每项规则、原有验收与新增合同共同约束，不用单一通用案例替代具体子项。每个子项须在案例输入中保留其适用条件，并以自身原文规定的输出/不变量判定；复合章应拆记录各个观察量，不能以一个成功掩盖其他失败。

证据产物包括真实命令/用户动作、原始响应或事件、权威状态前后值、版本、时序、失败及恢复；尚无对应真实运行证据的场景状态为 `not-run`，标准库示例仅证明列明的局部边界。具体输入与命令见[执行入口](../../../examples/web-backend/RUNBOOK.md)，条款索引见[规范条款登记](../../../registry/requirements.json)，来源的有限支持命题见[逐命题来源映射](../../../sources/web-backend/claims.json)。

本文的跨组件约束与正例、失败反例、合法邻例由本规范综合定义；外部来源支持的机制及适用边界见来源表。项目架构、预算和业务规则由实际需求确定。L5 实现应映射到所选框架、SDK 或引擎；L6 按具体版本的提供者保证与受支持矩阵验收项目能力。

## 一、适用性与符合性目标
1. 在实际交付前明确受众、交互形态、目标平台、辅助技术需求、合同和适用法律，以及需达到的 WCAG 版本与等级。正式公共交互产品建议以 WCAG 2.2 AA 作为默认评估目标，只有在权利人确定适用范围后才成为对应项目的强制门禁。
2. 规范生效、链接可访问、组件库宣称“Accessible”与项目真实符合性是不同事实。网页、流程、文档、管理端、嵌入页面和第三方功能在实际使用范围内分别纳入评估，不能用首页得分代表整个产品。
3. 为关键任务按人群和输入条件组织测试：键盘、触控、缩放、高对比、屏幕阅读器、认知负担与暂时性限制等；实际范围基于项目用户条件，不能强制所有原型具有一整套生产审计流程。
4. **验收**：实际采用版本、等级、角色与任务、支持设备／浏览器、负责审查者和可复核证据均能对应项目范围。

### WEB-001 核验合同

- **WEB-001-P · 输入/动作与合格判据：** 按用户任务列页面/嵌入/完整流程和所选等级→范围可追溯。
- **WEB-001-F · 直接失败变异：** 组件自称accessible或首页均分冒全产品符合→失败。
- **WEB-001-N · 合法邻例：** 内部隔离原型不自动有公共认证义务。

## 二、文档语义与可访问性树
1. 优先利用原生 HTML 的语义、自动键盘支持和浏览器验证行为；页面的主要区域、标题、导航、列表、表格、标签及交互对象应表达其实际含义。
2. ARIA 属性不得作为任意改变角色、复制标题或掩盖错误 HTML 的捷径；使用与 HTML 默认语义冲突的 role 或属性时核对正式 ARIA in HTML 允许的规则。
3. 仅当原生控件无法满足真正需要的组件模式时，才采用自定义组合控件；自定义视觉元素一旦承担交互责任，必须补全可访问名称、状态、键盘与焦点契约。
4. 展示型 table 与可逐单元交互的 grid 有不同阅读和输入行为，不因布局像表格就自动创建复杂网格键盘模型。
5. **验收**：读取实际浏览器 Accessibility Tree 的 role/name/state/relations，并用至少一组适用的辅助技术核对用户理解，不以源码存在 aria-\* 作为完成证据。

### WEB-002 核验合同

- **WEB-002-P · 输入/动作与合格判据：** 读取最终AX树并操作原生/自定义控件→role/name/关系符合语义。
- **WEB-002-F · 直接失败变异：** 随意role覆盖禁止语义或只读table变交互grid→失败。
- **WEB-002-N · 合法邻例：** 原生足够时无需自定义组合控件。

## 三、可访问名称、描述及文本替代
1. 图标按钮、输入、链接、图片、图表控制点、复杂控件需有可被实际识别的名称。名称来源应与用户可见操作一致，不让控件只被读成图标文件名或技术字段。
2. 合法的 label、aria-labelledby、aria-label、aria-describedby 及描述关联根据对应标准选择，避免冗余、环状引用、隐藏空节点或重复描述。
3. 动态名称改变时考虑屏幕阅读器焦点和用户上下文，不能在关键操作中突然替换为无业务意义的技术状态。
4. 纯装饰图像可以从辅助技术中合理隐藏；包含重要业务条件的数据图像和复杂图表需要提供足够的文本或结构化等价内容。
5. **验收**：抽取非视觉路径，记录最终计算名称、描述和操作结果；对含图标、重复标签与条件性文本的控件进行差异核对。

### WEB-003 核验合同

- **WEB-003-P · 输入/动作与合格判据：** 重复图标/条件label/复杂图表非视觉任务→计算名称和描述准确。
- **WEB-003-F · 直接失败变异：** 名称只剩文件名或环状空引用→失败。
- **WEB-003-N · 合法邻例：** 纯装饰图片可从AT隐藏。

## 四、键盘导航与焦点入口
1. 所有用户可执行的核心任务应能在项目要求的键盘路径中完成，正确识别 Tab、Shift+Tab、Enter、Space、方向键、Escape 等与所选控件语义的对应关系。
2. 页面 DOM 顺序、视觉顺序、焦点顺序和阅读顺序应有合理一致性；CSS order、重排、绝对定位或门户挂载不能制造不可理解的跳跃。
3. 焦点状态在项目规定的主题、缩放、高对比和输入方式下保持可感知，不通过全局 outline:none 消除焦点指示；实际 WCAG 成功准则按采用等级判定。
4. 隐藏、禁用、加载中或已卸载的对象不能继续成为意外键盘陷阱；Tab 顺序和焦点离开必须可预测。
5. **验收**：仅使用键盘从入口至完成任务，记录所有焦点位置、聚焦样式、激活和取消的实际行为。

### WEB-004 核验合同

- **WEB-004-P · 输入/动作与合格判据：** Tab/ShiftTab/Enter/Space/Escape完整流程→焦点可感知且无陷阱。
- **WEB-004-F · 直接失败变异：** outline:none、隐藏节点仍截获焦点→失败。
- **WEB-004-N · 合法邻例：** 项目未用快捷键不强制新增。

## 五、组合控件焦点模式与 roving tabindex
1. Tabs、Toolbar、Tree、Listbox、Grid、Menu 等组合控件应选定与真实用户任务对应的焦点模型：roving tabindex、aria-activedescendant 或原生机制。并非所有组合控件都要使用相同的方向键模式。
2. 使用 roving tabindex 时明确单一 Tab 进入点、箭头移动、内容禁用、循环与边界行为；虚拟化或数据更新后要保持稳定的可聚焦对象。
3. 使用 aria-activedescendant 时，被引用的选项必须实际属于符合关系的可访问目标，焦点仍在宿主控件；视觉活动项、选中项和用户输入焦点须区分。
4. 焦点与选择是否联动必须按具体控件模式和实际业务风险确定。键盘移动不能未经确认就执行支付、删除或影响外部数据的动作。
5. **验收**：以键盘、屏幕阅读器和目标浏览器检查激活、移动、边界、选中、更新列表及卸载后的焦点一致性。

### WEB-005 核验合同

- **WEB-005-P · 输入/动作与合格判据：** 动态删除/虚拟选项下箭头移动→宿主焦点、活动项、选中分清。
- **WEB-005-F · 直接失败变异：** aria-activedescendant指不存在项或移动即付款→失败。
- **WEB-005-N · 合法邻例：** 组合控件可按模式选roving或原生机制。

## 六、Dialog、Popover 与模态行为
1. 区分模态与非模态弹层；模态需有清楚的可访问名称、正确焦点进入/返回以及适当的背景交互隔离，不能单靠 z-index 宣称背景已不可操作。
2. 使用原生 dialog 或浏览器 Popover API 时按其正式平台行为选择，分别处理取消、Escape、关闭按钮、确认以及焦点去向；不能将所有浮层实现为一个不具备语义的 div。
3. 弹层由不同组件动态打开、嵌套或在导航期间关闭时，不让已卸载的触发器成为焦点恢复目标，也不允许后台按钮被意外提交。
4. 错误提示、确认及警告弹层的标题与内容应保留必要业务条件及可修正动作；不把工程诊断展示给无关用户。
5. **验收**：键盘进入、循环/离开、打开嵌套弹窗、取消、提交失败、触发按钮消失和关闭后的焦点行为可重现。

### WEB-006 核验合同

- **WEB-006-P · 输入/动作与合格判据：** 嵌套模态/非模态及触发器删除后关闭→焦点和背景隔离正确。
- **WEB-006-F · 直接失败变异：** z-index代inert、关闭恢复到卸载节点→失败。
- **WEB-006-N · 合法邻例：** 非模态浮层不强制焦点陷阱。

## 七、Combobox、Listbox 与自动补全
1. 明确可输入／只选、单选／多选、是否异步查询、用户能否自由输入、选中与高亮的差异；不要因为外观是下拉列表就照搬所有 Listbox 模式。
2. 输入法 IME、远端搜索和键盘导航并行时，保留尚未确认的用户文本。迟到结果不能覆盖最新搜索词或已选值。
3. ARIA expanded、controls、active descendant、selected 等状态应反映真实 DOM 与控件行为；辅助技术获得的选项数量、分组和帮助提示在实际实现可理解。
4. 鼠标与触摸选择、Escape 关闭、Tab 离开及无结果／加载失败时，应按业务合同正确保留或取消草稿。
5. **验收**：键盘、读屏、中文 IME、空结果、异步迟到、跨组列表和服务端拒绝选择等场景的名称、焦点、输入及结果准确。

### WEB-007 核验合同

**必要机制补充：** composition尚未确认时的Enter、方向键和弹层选择须按实际IME路径区分；活动项不是选中值，候选确认不能无意触发不可逆业务动作。

- **WEB-007-P · 输入/动作与合格判据：** IME搜索A/B反序结果、Escape/Tab/触摸选择→草稿与选中值准确。
- **WEB-007-F · 直接失败变异：** 合成期间Enter选旧结果或expanded假状态→失败。
- **WEB-007-N · 合法邻例：** select-only与自由输入模式可有不同合法键盘规则。

## 八、Tabs、Menus、Toolbars 和快捷操作
1. Tabs 按实际采用的自动／手动激活模型处理焦点、选中态、关联面板和隐藏内容；键盘改变选中时，若有昂贵或不可逆的服务器副作用，应采用符合需求的确认机制。
2. Menu、Menu Button、Toolbar 与站点导航有不同语义，不应把普通网页链接导航不必要地改造成需要额外箭头键交互的 application menu。
3. 快捷键、上下文菜单及工具栏溢出动作要避免与浏览器、操作系统或辅助技术快捷键发生无提示冲突；应提供不依赖快捷键的可达操作。
4. **验收**：键盘/读屏完成切换、关闭、返回与点击面板内容，焦点、aria-selected、aria-controls 和可见页面一致。

### WEB-008 核验合同

- **WEB-008-P · 输入/动作与合格判据：** 手动/自动Tabs、菜单返回及快捷键冲突→选中/面板/焦点一致。
- **WEB-008-F · 直接失败变异：** 普通站点导航强套application menu或切Tab执行不可逆写→失败。
- **WEB-008-N · 合法邻例：** 普通链接导航保留原生Tab方式。

## 九、Tree、Grid 与复杂数据表
1. 真正具有树节点展开、层级移动或逐单元编辑的控件，需按照适用 APG 模式设计键盘、父子关系、位置状态和选择契约；普通树形信息与只读表格不强行添加完整应用控件交互模型。
2. 对有分页、虚拟化、排序和筛选的数据表，实际行列语义、表头关联、排序状态与数据范围应准确。视觉布局不能导致读屏错读列含义或总行数。
3. 虚拟列表与 Grid 中未加载项的表示方式需要与浏览器可访问性树和用户任务一致；焦点项从 DOM 消失时应维持可预期的活动节点。
4. **验收**：键盘跨行列、读屏读列名、排序筛选、动态删除、长表格滚动和编辑拒绝时，内容不丢失且操作可继续。

### WEB-009 核验合同

- **WEB-009-P · 输入/动作与合格判据：** 排序/筛选/虚拟滚动/删除行后读表头并编辑→行列和活动项正确。
- **WEB-009-F · 直接失败变异：** DOM消失后焦点悬空或总行数误报全量→失败。
- **WEB-009-N · 合法邻例：** 只读树形信息不强制应用键盘模型。

## 十、范围控件、拖放与替代输入
1. Slider、Spinbutton、进度、范围选择器及拖拽界面按照真实数值、单位、上限/下限和可执行动作选择原生或合适语义，数值显示与服务器业务精度一致。
2. 只有拖拽、捏合、多点触控或特定指针精度才能完成的重要任务，应提供符合采用可访问性目标的等效操作方式；不能以触屏动画成功代替所有用户可操作性。
3. 复杂画布、图形编辑、地图和时间轴的功能等价需基于项目实际用户任务和可用数据提供可操作结构、快捷键或替代界面，不默认每个视觉像素都需要成为独立控件。
4. **验收**：鼠标、触控、键盘、操作按钮替代、缩放与不同精度输入下，核心业务结果一致。

### WEB-010 核验合同

- **WEB-010-P · 输入/动作与合格判据：** 鼠标/触控/键盘及非拖拽入口改同一数值→单位精度和结果一致。
- **WEB-010-F · 直接失败变异：** 唯一精确拖拽入口阻断核心任务→失败。
- **WEB-010-N · 合法邻例：** 纯装饰画布无需逐像素变控件。

## 十一、表单、约束验证和错误反馈
1. 字段标签、必填、说明、字段组、单位、自动填充、输入格式及服务端错误，应保留有意义的可访问关联；原生提交细节继续由 DOM 专项负责。
2. 客户端格式错误和服务器业务拒绝需定位到可修正字段/关系及必要条件；状态变化在实际辅助技术中能获得，但不让重复播报打断用户正在输入。
3. 不应仅以红色边框、Toast 消失时间或顶部技术错误码表达失败。错误摘要、字段定位、正确焦点与恢复入口要按该产品所选标准实施。
4. IME、长文本、数字输入、错误恢复、重新认证和重复提交状态不能导致输入草稿被无条件清空。
5. **验收**：键盘/读屏完成一次合法提交、一次字段错误修复、一次服务器冲突恢复，字段含义和原输入保持正确。

### WEB-011 核验合同

- **WEB-011-P · 输入/动作与合格判据：** 字段错→读屏定位修正→服务端冲突恢复→输入/错误关联完整。
- **WEB-011-F · 直接失败变异：** 只红边/消失Toast或失败清空草稿→失败。
- **WEB-011-N · 合法邻例：** 不同错误呈现可用等价可访问模式。

## 十二、动态内容、状态消息与直播区域
1. 仅在用户需要获知后台变化时采用 live region、status 或 alert 等通知机制；不因发生每次重渲染就把整页设成高优先级播报。
2. 加载完成、列表筛选结果、保存成功、余额变化、用户权限失效和重要错误属于不同状态，不能简单合并为相同的 “done” 或无意义读屏提示。
3. 变化发生在未聚焦区域时，按重要性决定是否需要播报、何时播报、是否可以重复以及与焦点移动的关系；动态替换整个 live region 节点时要验证浏览器实际行为。
4. 对聊天、实时流、长任务和大量更新内容避免通知风暴，必要时提供暂停、查看变化或获取完整结果的可操作方式。
5. **验收**：不同屏幕阅读器与浏览器组合上，重要完成和错误能被获知、不会重复无界播报或遗漏影响决策的事实。

### WEB-012 核验合同

- **WEB-012-P · 输入/动作与合格判据：** 未聚焦状态更新/大量实时事件→必要消息可获知且无风暴。
- **WEB-012-F · 直接失败变异：** 整页assertive或重复重建live节点漏播完成→失败。
- **WEB-012-N · 合法邻例：** 无用户价值的背景变化无需逐条播报。

## 十三、客户端路由、Hydration 与焦点恢复
1. 客户端路由变更时，确保页面标题、主内容、可访问导航地标与焦点恢复保持用户上下文；详情按相邻渲染/路由专项。
2. Hydration 尚未完成时页面出现的控件不能无条件展示为“可操作”；输入保留、事件重放和用户结果只按实际框架支持与浏览器行为验收。
3. 切换账号、弹层关闭、列表删除和 bfcache 恢复时，不将焦点恢复到已删除、无权限或已隐藏元素。
4. **验收**：新旧标签、深链、前进/后退、未完成表单和网络失败下，键盘/读屏能够继续目标任务而不丢失核心上下文。

### WEB-013 核验合同

- **WEB-013-P · 输入/动作与合格判据：** 慢Hydration、Back及账号切换后AT继续→标题/焦点/上下文正确。
- **WEB-013-F · 直接失败变异：** 接管前按钮假可用或返回无权节点→失败。
- **WEB-013-N · 合法邻例：** 普通原生导航可由浏览器恢复合理状态。

## 十四、视觉对比、缩放、重排与强制颜色
1. 对比度、非文本 UI 对比、文字放大、内容重排、方向、间距、焦点可见和焦点遮挡等，直接采用项目选定的 WCAG 成功准则；不在组织文档复制阈值表。
2. 在受支持的浏览器和系统设置中检验缩放、用户样式、forced-colors、高对比与明暗主题；CSS 技术细节及 Token 映射由相邻 CSS 专项承担。
3. 固定工具栏、浮层、横向表格、软键盘与布局变化不应使必要交互被永久遮挡或无法滚动访问。
4. 不能用关闭页面缩放、强制固定字体或用纯颜色区分错误来通过静态布局检查。
5. **验收**：真实页面的长文案、系统字体变化、不同主题、放大和窄视口下，可读性及可操作性达到项目选定准则。

### WEB-014 核验合同

- **WEB-014-P · 输入/动作与合格判据：** 窄视口/文字放大/forced-colors/软键盘→所选WCAG准则实际成立。
- **WEB-014-F · 直接失败变异：** 禁缩放或固定栏遮掉焦点→失败。
- **WEB-014-N · 合法邻例：** 准则例外仅按标准实际适用条件判定。

## 十五、媒体、图像、图表和时间控制
1. 按功能类型检查图片文本等价、时间媒体字幕与描述、自动播放、暂停停止、动画运动敏感性；采用范围由项目实际媒体功能和 WCAG 等级决定。
2. 复杂图表、地图、数据可视化不一定能由一句 alt 说明全部操作；需要按真实业务目标提供数据表、结构化说明或可访问的筛选与导航入口。
3. 计时、自动切换、任务截止与长时间交互应根据真实安全及业务约束提供适当提示、延长、暂停或可恢复策略，不得为了符合某个形式要求错误承诺交易可以无限延时。
4. **验收**：在真实用户输入/观看条件下，非视觉、无声音或减少运动的替代路径包含完成任务需要的全部重要数据与控制。

### WEB-015 核验合同

- **WEB-015-P · 输入/动作与合格判据：** 无声/非视觉/减少运动完成媒体任务→等价信息和时间控制足够。
- **WEB-015-F · 直接失败变异：** 一句alt替代可操作图表全部功能→失败。
- **WEB-015-N · 合法邻例：** 真实业务到期不能承诺无限延期。

## 十六、语言、阅读顺序与认知可理解性
1. 页面语言、局部语言切换、标题层级、简明业务用词、目的可识别的链接及一致的导航方式，按项目受众和语言计划实现。
2. 可见标签、可访问名称、实际操作应保持一致，不能让同一动作在按钮、语音控制、快捷键和错误反馈中使用相互矛盾的名称。
3. 对密码填写、登录、重复录入和特殊认证路径应检查采用的 WCAG 可访问身份认证要求；任何替代路径必须经过身份安全规范的实际授权，不能削弱安全控制。
4. 帮助及恢复应提供必要业务原因与动作，不把实现细节、内部状态或面向 Agent 的诊断强加给用户。
5. **验收**：典型用户在语言切换、登录、表单错误和多步骤任务中，可以理解剩余操作与当前结果。

### WEB-016 核验合同

- **WEB-016-P · 输入/动作与合格判据：** 切语言/认证/错误恢复→可见标签与AT名称一致。
- **WEB-016-F · 直接失败变异：** 同一动作语音与按钮名矛盾或绕过安全认证→失败。
- **WEB-016-N · 合法邻例：** 安全允许的替代认证路径可成立。

## 十七、交互状态、权限与辅助技术同步
1. 对 expanded、selected、checked、pressed、invalid、disabled、busy 及当前页面状态，保证可见 UI、实际控件行为和暴露给辅助技术的语义一致。
2. 浏览器本地的“已禁用”不能代替服务端对无权限、账号撤销及租户数据的真正拒绝；可访问操作入口不自动产生业务授权。
3. 动态权限变更、服务端拒绝、会话过期及组件加载中断时，焦点与通知应如实反映状态，不将未知结果错误宣布为完成。
4. **验收**：账号与角色切换、成功/拒绝操作、禁用与恢复，视觉和辅助技术观察到的可执行状态一致，后端记录与实际交互一致。

### WEB-017 核验合同

- **WEB-017-P · 输入/动作与合格判据：** 撤权/忙碌/错误/恢复→UI、AX状态和后端可执行性同步。
- **WEB-017-F · 直接失败变异：** aria-disabled存在但点击仍越权写或未知播报成功→失败。
- **WEB-017-N · 合法邻例：** 只读可见与可写许可可不同。

## 十八、国际化与输入方式兼容
1. 将真实支持的中文、英文、RTL、复数、数字与时间格式对读屏名称、焦点、提示和键盘交互的影响纳入测试，不以纯机器翻译文本证明合规。
2. IME 组合输入、移动软键盘、触摸浏览、语音控制、外接键盘和放大辅助功能只按项目真实支持范围选取验收方式，但不能阻断已批准的核心任务。
3. 自定义键盘快捷键与辅助技术快捷键冲突时，需要有按采用规范允许的重映射、关闭或替代操作。
4. **验收**：目标语言/设备组合下输入不丢失、焦点不意外移动、重要提示不因布局溢出而不可读。

### WEB-018 核验合同

- **WEB-018-P · 输入/动作与合格判据：** CJK/RTL/软键盘/语音路径→输入和提示完整。
- **WEB-018-F · 直接失败变异：** 快捷键劫持AT或IME草稿丢失→失败。
- **WEB-018-N · 合法邻例：** 只对实际支持设备组合验收。

## 十九、复用组件库与第三方控件的准入
1. 引入第三方组件、设计系统、微前端或 AI 生成 UI 时，必须在最终产品组合中复核语义、键盘、状态、样式及版本；供应商宣传“WCAG compliant”不构成本项目符合性证据。
2. 组件库版本升级、重命名、Portal/Shadow DOM 集成和样式覆盖后，要重新检查其可访问名称、焦点、交互状态与回退路径，避免复用造成系统性故障。
3. 组件级检查可复用已有有效证据，但应用整合、业务接口和完整用户路径仍需相应端到端验收。文档不为相同实现重复制造多份测试流水。
4. **验收**：关键基础控件提供清楚的技术输入/输出契约、适用模式、已测环境和实际回归证明；声明不支持的模式有准确降级。

### WEB-019 核验合同

- **WEB-019-P · 输入/动作与合格判据：** 组件库升级/Portal/Shadow/主题覆盖→最终产品组合实测。
- **WEB-019-F · 直接失败变异：** 供应商WCAG声明代完整流程证据→失败。
- **WEB-019-N · 合法邻例：** 等价且仍适用组件证据可复用。

## 二十、测试策略、工具与真实辅助技术
1. 按实际项目范围选择 HTML 校验、Accessibility Tree 核对、自动化 a11y 扫描、键盘手工流程、屏幕阅读器、放大/高对比、触控与真实任务测试，各方法覆盖范围单独记录。
2. 自动测试工具对可机读属性有价值，无法单独证明正确的阅读体验、认知可理解性、复杂控件的全流程键盘行为或整个 WCAG 符合性。
3. 对存在多种可访问实现路径的组件，应按实际业务功能测量；不要用一个 APG 示例、一个 ARIA role 或某浏览器单次测试自动推断所有环境符合。
4. 独立审查可采用与实现过程独立的场景、测试数据和辅助技术；不能只让相同 Agent 复述自己的代码作为独立证明。
5. **验收**：测试对应产品版本、目标浏览器/OS/辅助技术版本、输入和预期、结果、未覆盖项与恢复动作，均可回查。

### WEB-020 核验合同

- **WEB-020-P · 输入/动作与合格判据：** 自动扫描/AX/键盘/真实AT分别运行→结果绑定各自范围。
- **WEB-020-F · 直接失败变异：** 扫描绿色冒读屏和完整WCAG通过→失败。
- **WEB-020-N · 合法邻例：** 不同合理交互模式按实际任务而非单APG例判断。

## 二十一、符合性判定与审计记录
1. 选定 WCAG 版本和等级后，按照对应规范的符合性要求评估相关网页、视图和完整流程；不能使用平均得分、局部自动检查通过比例或代表性页面结果宣称所有界面已通过。
2. 需要正式报告时可以参照 WCAG-EM 2.0 记录评估范围、取样策略、覆盖的核心功能、受支持技术、实际发现及限制。WCAG-EM 是辅助方法，不增加标准原文未规定的要求。
3. 可按 ACT Rules Format 1.1 或已有有效工具契约记录测试规则及结果；这并不表示所有测试都能被完全自动化。
4. 第三方嵌入、不可修改的外部业务流程和法律合同限制应按真实使用与对应责任进行评估和记录；不为满足报告外观而隐藏对用户实际重要的障碍。
5. **验收**：必须能从报告中的声明追溯到相应产品版本、完整任务、失败事项、浏览器组合和实际确认的权利范围。

### WEB-021 核验合同

- **WEB-021-P · 输入/动作与合格判据：** 从报告回查页面、全流程、失败与版本→符合性边界准确。
- **WEB-021-F · 直接失败变异：** 平均分或代表页面结果冒全产品声明→失败。
- **WEB-021-N · 合法邻例：** WCAG-EM辅助取样方法不新增成功准则。

| 外部组件库升级 | 角色/状态、键盘、第三方样式 | 真实组合环境回归通过，不凭库方声明 |
| 完整用户任务符合性 | 多个页面/角色、辅助技术、错误恢复 | 依据所选 WCAG 范围报告真实结果与未覆盖项 |
## 二十三、规范准入与实施边界
1. 本技术专题中的 WCAG、WAI-ARIA、ARIA in HTML、ACT Rules 等正式行业标准直接引用原发布物；APG、WCAG-EM、Working Draft 等按实际资料性质使用，不在本规范复制整套角色表、成功准则和计算算法。
2. 相邻 DOM 专项继续负责原生控件与事件，CSS 专项负责布局与呈现，路由专项负责导航恢复，浏览器身份安全专项负责服务器权限和认证；本规范独立维护**用户通过辅助技术与复杂控件完成任务的实际验收契约**。
行业标准、案例与静态审查不替代真实项目运行验收；L6 应保留实际版本、输入、结果与未覆盖边界。
