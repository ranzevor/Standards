# 命令进程、配置与标准流技术规范

**文档ID：** STD-L4-CLI-SDK-003　**版本：** 0.1.0　**状态：** adopted　**生效日期：** 2026-10-30

## 1 目标、适用与非目标

使命令从Shell分词、配置解析到流/退出状态成为可消费的稳定协议。

**适用：** 有命令入口、子进程、本地文件或终端交互的工具；库本身不被要求提供CLI。

**非目标：** 不强制POSIX、GNU选项、JSON、特定退出码或多Shell支持；不把独立argv当自动消除下游选项注入。

本文的“必须/不得”为采用相应条款时的必要条件，“应”为需说明偏离理由的建议，“可”为允许选项。外部标准的 MUST/SHOULD 依其原有强度与适用 profile 执行，项目参数不得降低其强制要求。能力不存在可据事实不适用；已承诺但未验的能力仍适用。

## 2 术语、主体与权威状态

argv是进程收到的参数序列，不是待再次解释的Shell源码；退出成功、业务否定、输入/权限/IO错误、取消和未知效果各有契约。流完整性描述结果是否全部交付，不由进程结束单独推导。

**主体与所有权：** Shell/直接启动器拥有分词；命令解析器拥有语法；配置解析器决定有效值但不授予权限；子进程管理器只清理所拥有资源；机器消费者按版本解释结果流。

**前置输入：** 命令树、支持Shell/OS、argv、配置来源及作用域、编码/locale、stdin/TTY能力、输出协议与文件目标。

**输出与权威观察：** 解析后意图、有效配置来源(脱敏)、stdout/stderr字节、退出码、文件差异与子进程/句柄终态。真正业务结果仍由实际目标确认。

**状态与终点：** 解析/验证→等待必要交互或执行→完整/部分/失败/未知；取消请求不是已取消，更不是外部动作回滚。

条款 ID 在本文内稳定；全局身份为文档路径、版本与条款 ID 的组合。各条的前置输入、主体和状态继承本节，再叠加本条触发条件。诊断缺失不证明效果未发生；并发、超时、取消请求与真实业务终态分别记录。

## 3 机制、不变量及逐条验收

### CLI-PROC-01 语法、分词与下游选项

- **触发/前置：** 解析命令或启动外部程序。
- **必要机制：** 必须固定子命令、位置/重复/未知选项、空参数和选项终止规则；保留已有argv边界。直接执行用参数序列和可信可执行路径；数据形--config仍可能成为下游选项，按被调程序协议使用终止符/等价数据入口或拒绝歧义。Shell解释仅用于已声明脚本产品。
- **不变量：** 普通数据不因拼接变代码，也不因独立argv变控制选项。
- **并发、超时、未知与恢复：** 解析失败前不触发默认写入；并发启动各自固定cwd/env，避免不可信目录抢占同名程序。
- **产物与观察点：** 实际argv、可执行文件身份、cwd/env白名单与目标副作用。
- **正例：** 含空格/分号的文件名保持单参数且无标记文件被创建。
- **直接失败：** 重新split/join造成参数断裂，或--config数据加载攻击者配置。
- **合法邻例：** 下游不支持--时可使用明确数据通道，不强制添加无效终止符。
- **可观察验收：** 以空值、空格、引号、Unicode、连字符名称和PATH同名替身核实际解析与副作用。
- **来源与限制：** RP10。来源只支持[逐命题表](../../../sources/runtime-protocol/SOURCE-CLAIMS.md)所列命题；其余必要机制是为保持本条不变量而提出的组织综合设计，不声称由单一外部标准规定。

### CLI-PROC-02 配置来源、空值与权限

- **触发/前置：** 多个配置来源或工作区自动发现。
- **必要机制：** 必须声明CLI/env/用户/项目/默认的优先级及相对路径基准，区分未指定、null、空值和显式禁用；有效配置诊断显示来源不泄密。不可信项目配置不能扩大动作范围、加载高权插件或自动切换生产目标。
- **不变量：** 实际目标和参数等于声明合并结果且不超有效权限。
- **并发、超时、未知与恢复：** 配置冲突/坏编码/递归引用有有界失败；检查与写之间目标变化需重验或原子绑定，不用一次路径检查当永久授权。
- **产物与观察点：** 脱敏有效配置、来源链、目标范围与文件差异。
- **正例：** 显式空值按合同禁用某功能而不是退回危险默认。
- **直接失败：** 仓库配置覆盖用户指定测试端点并发送生产写入。
- **合法邻例：** 产品可选配置文件高于env，只要公开且不越权。
- **可观察验收：** 穷举冲突/空值/作用域，变更cwd/父目录/链接，核实际选择集合与独立预期完全相等。
- **来源与限制：** RP08。来源只支持[逐命题表](../../../sources/runtime-protocol/SOURCE-CLAIMS.md)所列命题；其余必要机制是为保持本条不变量而提出的组织综合设计，不声称由单一外部标准规定。

### CLI-PROC-03 流边界、并发输出与完整性

- **触发/前置：** CLI输出供人或程序消费。
- **必要机制：** 必须分开结果、诊断和进度通道，定义编码、记录/结束边界和机器schema演进；并发生产者经单一序列化或等价原子记录策略输出，不能假定任意write均原子。大输出用有界流读取，两条pipe均持续排空，不能先wait再读造成死锁。
- **不变量：** 不完整结果不标完整；locale/TTY宽度不改变机器字段语义。
- **并发、超时、未知与恢复：** 下游提前关闭/磁盘满/编码错误按合同终止并清理；已输出部分有身份和不完整状态。外部文本控制字符在终端安全呈现。
- **产物与观察点：** stdout/stderr原字节、记录序号/终结、峰值缓冲及退出状态。
- **正例：** 诊断在stderr，JSON结果只有协议内容；JSONL中途失败明确无完整结束。
- **直接失败：** 进度污染JSON；多个线程拼坏同一记录；两个pipe满互等。
- **合法邻例：** 纯人读文本工具无机器格式承诺，不需改成JSON。
- **可观察验收：** 独立解析器消费双流大输出、Unicode和中断，核所有预期记录及完整性，不只看退出零。
- **来源与限制：** RP10；RP13。来源只支持[逐命题表](../../../sources/runtime-protocol/SOURCE-CLAIMS.md)所列命题；其余必要机制是为保持本条不变量而提出的组织综合设计，不声称由单一外部标准规定。

### CLI-PROC-04 交互、发现与终端可访问

- **触发/前置：** 帮助/版本、TTY和非TTY存在。
- **必要机制：** 必须提供生态合适的本地发现入口，无登录也能识别工具版本/前提；非交互缺确认/凭据按契约有界失败或显式等待协议。TTY只改变表现不静默改变业务目标；--yes不创造权限。关键状态不能仅靠颜色，外部控制序列不得被直接当可信终端动作。
- **不变量：** 机器执行不无界等密码；终端状态与真实动作一致。
- **并发、超时、未知与恢复：** 终端尺寸/编码改变保留必要语义；输入EOF、焦点/设备失效有明确结束；退出恢复所改终端模式。
- **产物与观察点：** 无网帮助输出、TTY/pipe行为、提示通道和终端恢复记录。
- **正例：** 无凭据help只输出本地说明；无色模式保留错误原因。
- **直接失败：** help先创建远端资源，或CI等待终端输入永不结束。
- **合法邻例：** 只支持TTY的全屏工具在非TTY快速解释不支持。
- **可观察验收：** 空stdin/pipe/pty与窄终端运行同意图，对比目标集合、延迟、提示和权限结果。
- **来源与限制：** RP10。来源只支持[逐命题表](../../../sources/runtime-protocol/SOURCE-CLAIMS.md)所列命题；其余必要机制是为保持本条不变量而提出的组织综合设计，不声称由单一外部标准规定。

### CLI-PROC-05 取消、文件写入与部分完成

- **触发/前置：** 长任务、子进程树或本地写操作。
- **必要机制：** 必须区分请求停止、停止新工作、在途收敛与最终结果；信号按平台传播并等待所拥有子进程回收。整体文件替换按真实同文件系统原子协议实施，保留需保护用户编辑；并发写用版本条件/锁或等价策略。
- **不变量：** 不杀宿主拥有资源，不以取消抹去已提交事实；失败不静默覆盖用户数据。
- **并发、超时、未知与恢复：** 保存检查点绑定输入/目标/版本和未知项；跨文件系统rename失败不能自动退化为可见半文件，除非合同明确流式提交。
- **产物与观察点：** 取消时间线、子进程/句柄、输出前后摘要、恢复与未知项。
- **正例：** 中断生成保留完整旧文件和可恢复新暂存；宿主共享连接仍活。
- **直接失败：** SDK遇错exit宿主，或取消已写远端动作却返回已回滚。
- **合法邻例：** 追加日志可以逐记录提交并报告最后完整记录，无需全文件事务。
- **可观察验收：** 在解析前、执行中、文件发布前后和外部提交后取消；核真实进程/文件/目标状态及所有权。
- **来源与限制：** RP10；RP08；RP11。来源只支持[逐命题表](../../../sources/runtime-protocol/SOURCE-CLAIMS.md)所列命题；其余必要机制是为保持本条不变量而提出的组织综合设计，不声称由单一外部标准规定。

## 4 兼容、迁移与退役

语法、输出字段/编码、错误码、默认配置和人机模式分别声明兼容性。不同Shell引用规则不互相冒充；不支持组合明确拒绝。帮助/版本能在无网络/凭据时说明本地工具身份。

## 5 跨域消费接口

消费基线M01–M11、M24、M28–M32、M34；后端/自动化负责远端效果核对，安全负责有效动作范围，桌面/平台负责实际信号/终端能力。CLI承担进程可观察合同。

接口只定位技术职责，不自动作出规范采用决定。通用状态、测试和制品义务消费 [L3 通用工程 v0.1.0](../../L3/001-通用工程规范--v0.1.0.md)；提供方版本与摘要、应用条款、实现入口和验收责任在项目契约中绑定。提供方保证须由相应实现证据支持，消费方按该保证的实际范围验收。

## 6 真实目标验收合同

消费者验收使用固定Python 3.12驱动直接 `subprocess.run([TOOL, ...], input=..., stdout=PIPE, stderr=PIPE, timeout=...)`；Shell画像分别固定 `bash --noprofile --norc -c` 和已承诺的 `pwsh -NoProfile -File tests/consumer.ps1`，不得把Bash通过记成PowerShell通过。TTY用目标平台pty/ConPTY；逐一测试closed stdin、双流大输出、下游关闭、SIGINT或平台取消。入口与TOOL摘要写入项目验收配置。

**判据：** 参数身份/有效目标符合独立预期；stdout机器结果可解析且无进度杂讯，截断不报完整成功；非交互缺必要输入有界失败；取消后子进程/句柄及外部事实正确。有限示例只证明该Python子进程，不替代产品或所有Shell。

每次执行保存：正文/条款版本与摘要、目标制品/实现和工具版本、OS/设备/运行时/配置、输入及故障时间线、预期和实际、stdout/stderr/退出码或等价运行证据、权威状态回读、未覆盖范围。`not-run`、模型通过和真实目标通过是不同结果；实际无环境时保留命令和判据而不填写虚构回执。
