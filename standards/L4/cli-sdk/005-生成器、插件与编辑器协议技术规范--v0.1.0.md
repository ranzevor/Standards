# 生成器、插件与编辑器协议技术规范

**文档ID：** STD-L4-CLI-SDK-005　**版本：** 0.1.0　**状态：** adopted　**生效日期：** 2026-10-30

## 1 目标、适用与非目标

保护用户源码并按真实协议生命周期提供生成、扩展和编辑器能力。

**适用：** 代码/配置生成、格式化/自动修复、插件加载、LSP或其他编辑器协议。

**非目标：** 不要求普通CLI实现生成器、沙箱或LSP；不把签名当动作许可，也不把建议型插件隔离当实际安全边界。

本文的“必须/不得”为采用相应条款时的必要条件，“应”为需说明偏离理由的建议，“可”为允许选项。外部标准的 MUST/SHOULD 依其原有强度与适用 profile 执行，项目参数不得降低其强制要求。能力不存在可据事实不适用；已承诺但未验的能力仍适用。

## 2 术语、主体与权威状态

生成区与手写区有不同所有权；诊断/预览/写入是不同模式。协议请求ID、文档版本、会话世代和字节长度不同；LSP字符位置编码与Content-Length字节数不可混用。

**主体与所有权：** 生成器只拥有约定输出区域；工作区维护者决定修改边界；插件宿主校验信任与实际能力；协议客户端/服务端各自按协商角色处理请求、文档和关闭。

**前置输入：** 输入规格/模板/工具版本、输出归属、用户修改基线、根目录、插件信任/能力与版本、LSP3.17客户端能力和文档版本。

**输出与权威观察：** 可审差异/冲突、输出来源、插件实际加载/拒绝、协议原始帧及文档版本/终态；用户原文与真实文件为写入权威。

**状态与终点：** 生成预览→验证→提交或冲突；插件发现不等于授权加载；LSP初始化前/协商中/运行/关闭已响应/退出分开。

条款 ID 在本文内稳定；全局身份为文档路径、版本与条款 ID 的组合。各条的前置输入、主体和状态继承本节，再叠加本条触发条件。诊断缺失不证明效果未发生；并发、超时、取消请求与真实业务终态分别记录。

## 3 机制、不变量及逐条验收

### CLI-EXT-01 生成身份、手写保护与冲突

- **触发/前置：** 首次/再次生成或模板升级。
- **必要机制：** 必须记录输入/模板/生成器身份和生成区域；提交前比较基线与当前用户修改，冲突显式处理。生成多个文件时定义可见性/部分结果，不能以自动生成名义任意覆盖。确定性承诺限定时间戳等可变字段。
- **不变量：** 用户拥有区域不静默丢失；输出来源可追溯。
- **并发、超时、未知与恢复：** 并发编辑以条件写/锁或等价方式防TOCTOU；中断保留旧完整集或明确部分/恢复，不把未生成文件标完成。
- **产物与观察点：** 输入清单、输出前后差异、冲突与生成manifest。
- **正例：** 固定规格再生无语义差异，修改手写区后提示冲突。
- **直接失败：** 模板升级无记录且覆盖用户实现。
- **合法邻例：** 一次性脚手架后用户全权维护，无需持续支持再生成。
- **可观察验收：** 固定输入两次生成，注入手写修改/并发编辑/写中断，核输出集合和用户内容。
- **来源与限制：** RP08。来源只支持[逐命题表](../../../sources/runtime-protocol/SOURCE-CLAIMS.md)所列命题；其余必要机制是为保持本条不变量而提出的组织综合设计，不声称由单一外部标准规定。

### CLI-EXT-02 诊断、预演与自动修复

- **触发/前置：** 格式化、Lint或源码迁移。
- **必要机制：** 必须区分只读诊断、预览与实际写入，限定根/忽略/链接/嵌套项目。格式幂等承诺用第二次执行验证；不能证明语义保持的修复明确需要选择并显示影响，不将解析成功当业务等价。
- **不变量：** check不写；目标集合等于选择与规则，不因“优化”漏文件。
- **并发、超时、未知与恢复：** 批量失败逐项报告，名称规范化碰撞拒绝静默覆盖；恢复仅处理实际未决项。
- **产物与观察点：** 前后hash、路径集合、修复diff及独立语义对照。
- **正例：** check前后摘要相同，写后第二次无新增变化。
- **直接失败：** 检查模式改文件，或修复将比较语义改掉仍称纯格式化。
- **合法邻例：** 明确语义迁移工具可有行为变化，但要按其迁移合同验收。
- **可观察验收：** 路径/Unicode/大小写/链接语料和语义负例分别运行，比较固定预期集合及差异。
- **来源与限制：** RP08。来源只支持[逐命题表](../../../sources/runtime-protocol/SOURCE-CLAIMS.md)所列命题；其余必要机制是为保持本条不变量而提出的组织综合设计，不声称由单一外部标准规定。

### CLI-EXT-03 插件发现、信任与能力

- **触发/前置：** 加载插件、模板脚本或项目扩展。
- **必要机制：** 必须声明发现顺序、身份/版本握手、工作区信任、实际进程边界及能力；项目配置不自动安装/执行任意代码。同进程插件拥有的宿主能力如实披露，未有沙箱不声称隔离。签名只帮助来源/完整性，不授予业务权限。
- **不变量：** 不可信发现不自动变执行；插件不能超有效动作/数据范围。
- **并发、超时、未知与恢复：** 错版/拒绝/失效有受控禁用路径；加载中断释放自有资源。撤权阻止新调用但不篡改已发生效果。
- **产物与观察点：** 发现/加载决定、真实进程/文件/网络调用和拒绝。
- **正例：** 未信任仓库插件未运行；显式受信同进程插件按实际能力使用。
- **直接失败：** 打开仓库自动运行postinstall并读取无关秘密。
- **合法邻例：** 封闭内建扩展不必提供公共市场或沙箱服务。
- **可观察验收：** 合成插件尝试写边界外标记文件/网络目标，核实际未调用；版本错误和合法受信插件成对测试。
- **来源与限制：** RP10。来源只支持[逐命题表](../../../sources/runtime-protocol/SOURCE-CLAIMS.md)所列命题；其余必要机制是为保持本条不变量而提出的组织综合设计，不声称由单一外部标准规定。

### CLI-EXT-04 LSP分帧、协商与文档版本

- **触发/前置：** 提供LSP3.17。
- **必要机制：** 必须以ASCII头和UTF-8内容字节长度增量分帧，遵循initialize先行及协商；保留强制基线能力，未知扩展按协议处理。文档更新按接收顺序及数组顺序应用，字符位置按协商编码；请求基于已同步文档版本。
- **不变量：** 中文/非BMP不破坏字节/字符边界；旧响应不错误覆盖新文档。
- **并发、超时、未知与恢复：** 请求乱序可并行但按ID关联；过期结果取消/忽略或合法变换，服务器不能仅因队列中状态变化一概取消仍有用结果。
- **产物与观察点：** 原帧字节、协商能力、文档版本与请求结果。
- **正例：** 包含中文的帧分多次送入仍仅交付一条，旧版本诊断不覆盖新版。
- **直接失败：** 按字符数填Content-Length；缺ClientCapabilities就免除所有强制同步。
- **合法邻例：** 只实现少量可选能力的服务端合法，只要准确声明并遵守基线。
- **可观察验收：** 独立驱动分片/粘连、缺省能力、Unicode及v5/v6交错请求，核解析与最终文档。
- **来源与限制：** RP14。来源只支持[逐命题表](../../../sources/runtime-protocol/SOURCE-CLAIMS.md)所列命题；其余必要机制是为保持本条不变量而提出的组织综合设计，不声称由单一外部标准规定。

### CLI-EXT-05 请求取消、关闭与重启

- **触发/前置：** 编辑器取消或关闭服务器。
- **必要机制：** 必须保持请求/通知区别；LSP取消不是撤销已发生编辑，已处理请求即使取消仍返回响应。shutdown请求先响应且不立即exit，客户端之后仅发协议允许消息并等待响应再exit；退出码按协议判断。崩溃重启受预算，重建工作区/文档不复用旧会话结果。
- **不变量：** 无丢失必要响应；旧会话结果不写入新文档。
- **并发、超时、未知与恢复：** 重复取消/关闭、stdout关闭和宿主崩溃有真实资源终点；不能无穷重启崩溃插件。未知已写编辑必须回读文件核对。
- **产物与观察点：** 请求/响应ID、shutdown响应、exit顺序/退出码及重启世代。
- **正例：** 收到shutdown后返回null响应，再exit正常退出。
- **直接失败：** shutdown立即杀进程丢回执，取消后假称文件写入已撤销。
- **合法邻例：** 未初始化直接exit按协议错误码退出是合法异常路径。
- **可观察验收：** 在请求开始/完成后取消，乱序关闭及重启后送旧响应，核真实文件、响应和进程码。
- **来源与限制：** RP14。来源只支持[逐命题表](../../../sources/runtime-protocol/SOURCE-CLAIMS.md)所列命题；其余必要机制是为保持本条不变量而提出的组织综合设计，不声称由单一外部标准规定。

## 4 兼容、迁移与退役

模板/插件API与输入Schema联合演进；一次性脚手架可交出全部所有权而不承诺永久再生成。LSP3.17是固定参考，不声称最新；可选能力缺省不能免除协议强制能力。

## 5 跨域消费接口

消费基线M23–M28、M30–M33；安全提供工作区信任/实际权限边界，桌面/文件规范提供原子文件行为，网络提供字节解析；生成器/编辑器拥有用户修改与文档世代一致性。

接口只定位技术职责，不自动作出规范采用决定。通用状态、测试和制品义务消费 [L3 通用工程 v0.1.0](../../L3/001-通用工程规范--v0.1.0.md)；提供方版本与摘要、应用条款、实现入口和验收责任在项目契约中绑定。提供方保证须由相应实现证据支持，消费方按该保证的实际范围验收。

## 6 真实目标验收合同

生成器由项目命令 `TOOL generate --spec fixtures/spec.json --output "$WORK" --check` 和真实写模式分别运行，先在临时副本修改手写区再再生成。LSP由独立驱动以stdio启动最终SERVER，逐字节/多帧写入原始Content-Length帧，发送initialize→initialized→didOpen/didChange→请求/取消→shutdown→exit，记录双方帧及进程码。驱动必须按UTF-8字节数分帧并校验文档版本；协议路径不是shell逐行JSON。

**判据：** check模式无文件变化，写模式不静默覆盖手写改动；插件加载真实受限且错版可拒；LSP正确关联请求/版本，过期结果不覆盖新文档，取消仍有响应，shutdown不提前退出导致丢响应。

每次执行保存：正文/条款版本与摘要、目标制品/实现和工具版本、OS/设备/运行时/配置、输入及故障时间线、预期和实际、stdout/stderr/退出码或等价运行证据、权威状态回读、未覆盖范围。`not-run`、模型通过和真实目标通过是不同结果；实际无环境时保留命令和判据而不填写虚构回执。
