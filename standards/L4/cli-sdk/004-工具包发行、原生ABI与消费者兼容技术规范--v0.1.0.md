# 工具包发行、原生ABI与消费者兼容技术规范

**文档ID：** STD-L4-CLI-SDK-004　**版本：** 0.1.0　**状态：** adopted　**生效日期：** 2026-10-30

## 1 目标、适用与非目标

使发行包能够在承诺的干净消费环境真正安装、链接/导入和运行，而不把源码构建或API相似当ABI兼容。

**适用：** 分发源码包、二进制、库、安装器或更新渠道；FFI仅在真实存在时适用。

**非目标：** 不强制所有工具跨平台、使用SemVer/签名服务或自更新；不新增发布许可。

本文的“必须/不得”为采用相应条款时的必要条件，“应”为需说明偏离理由的建议，“可”为允许选项。外部标准的 MUST/SHOULD 依其原有强度与适用 profile 执行，项目参数不得降低其强制要求。能力不存在可据事实不适用；已承诺但未验的能力仍适用。

## 2 术语、主体与权威状态

包坐标含名称/版本/平台/架构/渠道，坐标相同不得静默换字节。源码兼容、ABI、协议、输出与行为兼容分别判定；Python wheel tag只是特定生态的兼容声明示例。

**主体与所有权：** 构建者生成包与来源，发行者关联坐标/摘要，包管理器执行其安装职责，独立消费者只从发行包验证，宿主/FFI双方各按约定管理内存。

**前置输入：** 支持运行时/OS/架构、模块格式、包清单/锁定依赖、ABI/分配器、制品与渠道摘要、更新/卸载策略。

**输出与权威观察：** 实际包文件清单、干净消费结果、动态链接/FFI生命周期证据、安装副作用及更新恢复结果。

**状态与终点：** 已构建/已发布/已下载/已安装/可消费分开；更新为准备/切换/数据迁移/完成/恢复，程序回退不自动恢复数据。

条款 ID 在本文内稳定；全局身份为文档路径、版本与条款 ID 的组合。各条的前置输入、主体和状态继承本节，再叠加本条触发条件。诊断缺失不证明效果未发生；并发、超时、取消请求与真实业务终态分别记录。

## 3 机制、不变量及逐条验收

### CLI-PKG-01 公开兼容面与旧消费者

- **触发/前置：** 稳定API/命令/输出已承诺。
- **必要机制：** 必须登记实际公开行为和支持期限，分别评估源码、二进制、协议、输出、错误与默认值。新增枚举/字段也核消费者策略，不能单以编译通过证明行为兼容。实验入口可按明确实验合同演进。
- **不变量：** 同一兼容声明不隐藏破坏变化；已发布制品身份不可静默替换。
- **并发、超时、未知与恢复：** 废弃有可执行迁移和最后兼容版本；撤下渠道仍保留必要历史身份/诊断与用户资产，不自动删除。
- **产物与观察点：** API/行为差异、旧消费者固定语料和迁移结果。
- **正例：** 旧消费者在承诺补丁更新下解析相同稳定输出。
- **直接失败：** 补丁版把JSON改表格仍标兼容，或新枚举让旧代码误判成功。
- **合法邻例：** 内部实验可用日期版本且不承诺稳定，不强制SemVer。
- **可观察验收：** 旧消费工程对候选运行并核独立预期，故意改变输出/默认值必须使兼容门禁失败。
- **来源与限制：** RP12。来源只支持[逐命题表](../../../sources/runtime-protocol/SOURCE-CLAIMS.md)所列命题；其余必要机制是为保持本条不变量而提出的组织综合设计，不声称由单一外部标准规定。

### CLI-PKG-02 原生ABI、FFI与依赖组合

- **触发/前置：** 有编译扩展、动态库或跨语言边界。
- **必要机制：** 必须绑定架构/调用约定、类型布局/对齐、符号、分配与释放责任、异常/线程边界和下层库；宿主已有依赖不能被库任意覆盖。ABI承诺按实际编译器/运行库/选项组合验证。
- **不变量：** 分配器匹配，异常不越未定义边界；API相同不等于二进制相容。
- **并发、超时、未知与恢复：** 载入失败或不支持组合有清晰拒绝，部分构造不泄漏。升级先跑消费端生命周期和旧包兼容，不仅链接。
- **产物与观察点：** 包tag、真实加载库路径、布局/生命周期与错误证据。
- **正例：** 匹配平台扩展从发行wheel安装并跨FFI释放正确。
- **直接失败：** x86_64包发给arm64，或跨分配器free造成崩溃。
- **合法邻例：** 纯源码/纯解释库可无原生ABI承诺。
- **可观察验收：** 在支持矩阵从实际包导入/链接，分配/调用/释放多次，注入错架构/库版本，核拒绝与资源趋势。
- **来源与限制：** RP15；RP16。来源只支持[逐命题表](../../../sources/runtime-protocol/SOURCE-CLAIMS.md)所列命题；其余必要机制是为保持本条不变量而提出的组织综合设计，不声称由单一外部标准规定。

### CLI-PKG-03 包完整性与安装副作用

- **触发/前置：** 打包、安装或卸载。
- **必要机制：** 必须核包入口、数据/类型/头文件、依赖、可执行权限、许可/NOTICE及排除秘密；安装不能依赖仓库未打包文件。安装脚本、PATH/服务/全局配置改变明确，预演不写资源；卸载只删除自己拥有且合同允许的内容。
- **不变量：** 发行物具备全部承诺输入；安装权限不由工具便利性产生。
- **并发、超时、未知与恢复：** 安装中断与权限拒绝不自动改高权身份；部分安装可定位并恢复，用户数据和证据保留。
- **产物与观察点：** 包清单、安装前后文件/网络/配置差异与干净消费者结果。
- **正例：** 离开源码目录后发行包仍加载其必需数据。
- **直接失败：** install钩子上传cwd，或卸载把用户创建文件全部删掉。
- **合法邻例：** 免安装单文件直接从交付字节运行即可。
- **可观察验收：** 干净消费目录安装/运行/卸载，核文件、网络、全局环境和保留资产；删包内必需文件负例应失败。
- **来源与限制：** RP15。来源只支持[逐命题表](../../../sources/runtime-protocol/SOURCE-CLAIMS.md)所列命题；其余必要机制是为保持本条不变量而提出的组织综合设计，不声称由单一外部标准规定。

### CLI-PKG-04 更新、身份与恢复闭包

- **触发/前置：** 渠道下载/自动或手动更新。
- **必要机制：** 必须关联源码/构建/包坐标/平台/摘要与实际消费身份；校验/签名按生态和风险合同。更新切换与本地配置/持久数据迁移分别定义，旧程序遇新格式不静默覆盖。对最终渠道加工结果重验。
- **不变量：** 同版本不同平台可有独立坐标；同坐标不同字节不可沿用旧回执。
- **并发、超时、未知与恢复：** 失败保留可运行旧版或已验证恢复入口；不可逆数据迁移不能用复制旧二进制冒充回滚。迟到旧更新不得覆盖新候选。
- **产物与观察点：** 下载/消费摘要、更新世代、迁移/恢复演练和支持变化记录。
- **正例：** 更新被中断仍能启动旧版且配置完整，或明确走前向修复。
- **直接失败：** 更新失败新旧程序全丢，仍因渠道上传成功宣称可用。
- **合法邻例：** 包管理器负责已证原子切换时工具可消费该能力，不重复造更新器。
- **可观察验收：** 断点覆盖下载/校验/切换/迁移/首启，各阶段核实际可用版本与数据恢复；错摘要拒绝。
- **来源与限制：** RP12；RP08。来源只支持[逐命题表](../../../sources/runtime-protocol/SOURCE-CLAIMS.md)所列命题；其余必要机制是为保持本条不变量而提出的组织综合设计，不声称由单一外部标准规定。

## 4 兼容、迁移与退役

保持旧消费者语料及支持组合；破坏变化按所选版本政策迁移。SemVer仅在声明采用时约束版本；Stable ABI受编译器/下层库/平台条件约束，不是跨任意CPU/OS通用二进制。

## 5 跨域消费接口

消费基线M19–M22、M31–M36及云供应链制品身份/开源材料许可接口；平台安装信任与全局权限由安全/桌面提供，工具给实际包消费及兼容证据。

接口只定位技术职责，不自动作出规范采用决定。通用状态、测试和制品义务消费 [L3 通用工程 v0.1.0](../../L3/001-通用工程规范--v0.1.0.md)；提供方版本与摘要、应用条款、实现入口和验收责任在项目契约中绑定。提供方保证须由相应实现证据支持，消费方按该保证的实际范围验收。

## 6 真实目标验收合同

Python可选画像：`python -m venv "$CONSUMER"`；`"$CONSUMER/bin/python" -m pip install --no-index --find-links "$APPROVED_WHEELS" "$WHEEL"`；从非源码cwd执行 `"$CONSUMER/bin/python" -I consumer.py`。原生库按已承诺编译器运行 `cc consumer.c -I "$HEADERS" -L "$LIB" -ltool -o consumer && ./consumer`，记录链接库真实路径；只在项目已具材料/工具且获准环境执行。Windows固定等价命令而非复用POSIX路径。

**判据：** 从最终包而非仓库源码消费成功；包内必需入口/数据/声明齐全，架构/ABI不匹配被拒；安装/卸载不外发未授权材料、不删用户资产；升级故障可按真实数据合同恢复。

每次执行保存：正文/条款版本与摘要、目标制品/实现和工具版本、OS/设备/运行时/配置、输入及故障时间线、预期和实际、stdout/stderr/退出码或等价运行证据、权威状态回读、未覆盖范围。`not-run`、模型通过和真实目标通过是不同结果；实际无环境时保留命令和判据而不填写虚构回执。
