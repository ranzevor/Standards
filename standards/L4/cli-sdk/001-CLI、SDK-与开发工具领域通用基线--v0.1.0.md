## 适用分支与L5/L6边界

1. 每个产品先列实际形态及承诺。CLI、SDK、生成器、编辑器插件可组合，不以“开发工具”名义要求全部功能。36项机制中的条件是适用判据，不是新增功能清单；不存在该功能可标不适用并说明事实依据。
2. 内部隔离原型保留必要输入、版本、结果和风险边界；正式分发工具增加真实消费路径、兼容与发行证据；敏感数据、生产、收费、破坏性修改增加与影响相称的权限和恢复核验。不得以“原型”逃避已发生的真实副作用责任。
3. L5固定语言/运行时、Shell、OS、包生态、原生ABI和协议实现细节；L6固定具体产品支持矩阵、预算、超时、错误码、兼容承诺、保留策略及检查入口。本文不强制SemVer、POSIX、JSON、异步SDK、LSP、插件、遥测、自动更新、特定CI或签名厂商。
4. 具有对应系统组成时组合采用已生效后端、数据、云、AI、桌面等规范；本领域补充“工具到使用者”的契约，不替代服务端授权、数据库事务或操作系统能力。没有被采用的技术不得机械扩大为跨栈门禁。
5. 适用记录至少包含：机制ID、存在的功能/承诺、采用或不适用理由、L5实现映射、L6检查入口、完成标准、负责主体、当前证据身份与未验范围。可用既有测试/PR保存，不新增无意义台账。

## 领域机制与验收条款

下列每项独立声明适用条件、必须实现的技术语义和完成标准；失败输入、合法邻例及检查证据在后续矩阵用同号关联。本文中的“必须”表示项目选定采用且适用条件成立时的必要要求。

### M01 适用面与公开契约

- **适用条件：** 全部产品。
- **机制要求：** 区分终端程序、可导入库、远程服务SDK、生成器、插件及编辑器协议端点。逐项声明使用者、稳定入口、输入输出、副作用与支持边界；内部函数不因可见就自动成为公开API，已文档化行为也不能因未导出类型而忽略。
- **完成标准：** C01：每个承诺入口有负责人及兼容边界；实验面与稳定面可区分，旧承诺不被静默取消。
- **验证映射：** F01 / N01 / E01，见下表。

### M02 命令树与参数语法

- **适用条件：** 提供CLI时。
- **机制要求：** 声明子命令、位置参数、选项取值、重复选项、缩写与未知项处理；在具有选项终止符的语法中正确处理其后的连字符文件名。保留Shell已经完成的分词边界，不把argv无条件重新拼接解释；Shell命令语言产品另行声明解释边界。
- **完成标准：** C02：合法参数保持身份，歧义按已声明规则解析；非法项或透传验证失败不触发未授权默认操作。
- **验证映射：** F02 / N02 / E02，见下表。

### M03 配置优先级与作用域

- **适用条件：** 读取配置时。
- **机制要求：** 明确命令行、环境变量、用户配置、项目配置与默认值的优先级；区分未指定、空值及显式禁用。项目目录中的配置属于不可信输入，不得自动取得用户级执行权限；提供可诊断的有效配置来源但隐藏秘密。
- **完成标准：** C03：实际值、来源及作用域符合声明，拒绝跨权限覆盖，诊断不输出秘密。
- **验证映射：** F03 / N03 / E03，见下表。

### M04 帮助、版本与离线发现

- **适用条件：** CLI及可分发工具。
- **机制要求：** 提供适合其生态的帮助、版本和最小用法发现入口；帮助不得依赖登录成功或会产生业务写入的初始化。输出区分客户端版本、协议版本及远端服务版本；无法查询远端时保留本地身份。GNU风格CLI可采用--help/--version，不强迫所有入口同一拼写。
- **完成标准：** C04：可定位当前工具、合法入口和必要前提；查询本地帮助不产生业务副作用。
- **验证映射：** F04 / N04 / E04，见下表。

### M05 标准流与机器输出

- **适用条件：** CLI产生结果时。
- **机制要求：** 分别约定stdout、stderr、文件输出及退出状态；机器模式使用明确格式、编码、记录边界和版本策略，进度与诊断不混入结果流。JSON、JSON Lines或二进制均按所选协议验收，不把所有CLI强制改为JSON。串流中途失败须使消费者识别不完整结果。
- **完成标准：** C05：所承诺格式可解析且无杂讯；完成与部分输出可区分，消费者不会把残缺结果当完整集。
- **验证映射：** F05 / N05 / E05，见下表。

### M06 退出与错误语义

- **适用条件：** CLI或SDK。
- **机制要求：** 建立稳定可判别的成功、业务否定、输入错误、权限拒绝、临时故障、取消及未知结果表达；错误码取值按平台与产品定义，不强制统一数字。SDK不得擅自终止宿主进程；错误保留可操作上下文与原因链而不泄密。
- **完成标准：** C06：每种状态与契约一致，可区分正常否定和故障；库错误可由调用者接管，秘密不外泄。
- **验证映射：** F06 / N06 / E06，见下表。

### M07 交互与非交互执行

- **适用条件：** 支持CLI交互时。
- **机制要求：** 非交互运行不得无界等待终端输入；缺失必要确认或凭据时按契约失败或返回可继续动作。自动确认开关只确认已获授权的选择，不创造权限；TTY检测可改变表现而不静默改变业务含义，交互优先策略要可覆盖和测试。
- **完成标准：** C07：非交互路径有有界终态或明确外部等待契约；确认不扩权，同样输入的业务目标保持一致。
- **验证映射：** F07 / N07 / E07，见下表。

### M08 终端呈现与可访问性

- **适用条件：** 人读终端界面。
- **机制要求：** 声明颜色、宽度、控制字符与本地化策略；可在目标用户需要时关闭颜色/动画并保留完整错误语义。显示来自外部的文本时避免终端控制序列被当作可信操作；机器模式不受本地化或终端尺寸影响。
- **完成标准：** C08：目标用户能获得必要状态和恢复动作；不执行不可信终端控制效果，机器契约稳定。
- **验证映射：** F08 / N08 / E08，见下表。

### M09 子进程与参数注入

- **适用条件：** 启动外部程序时。
- **机制要求：** 区分直接argv调用与确有需要的Shell脚本执行；前者不通过字符串拼接引入解释，后者限定脚本来源和参数传递。独立argv仍可能被下游解析为选项：不可信数据须按被调程序协议与选项分离；支持时采用选项终止符，不支持时使用有证据的等价数据入口或拒绝歧义，不能强制所有工具支持--。明确可执行文件解析、工作目录、环境继承、退出传播与子进程清理；不得从不可信目录优先载入同名工具。
- **完成标准：** C09：普通数据不变成代码或下游控制选项，不因数据形文件名加载额外配置；实际执行身份、路径与环境符合承诺，退出与清理可追踪。
- **验证映射：** F09 / N09 / E09，见下表。

### M10 路径、文件与并发写入

- **适用条件：** 读写本地文件时。
- **机制要求：** 声明相对路径基准、符号链接处理、覆盖规则、权限与并发控制；临时文件位于获准位置且不泄漏敏感内容。需要整体替换时采用目标平台可验证的原子或等价一致性方案；不假定跨文件系统重命名原子，不将所有输出一律要求事务。
- **完成标准：** C10：无越界写入，覆盖满足明确策略；失败状态可识别并保留应保留的数据与恢复材料。
- **验证映射：** F10 / N10 / E10，见下表。

### M11 取消、信号与资源释放

- **适用条件：** 长任务或持资源操作。
- **机制要求：** 定义取消请求、停止接收新工作、在途处理、资源释放和终态的区别。采用目标平台支持的信号或取消接口，不强制Windows模拟Unix信号；取消不是已提交外部动作的撤销。宿主资源与库拥有资源分开释放。
- **完成标准：** C11：取消结果与真实提交一致，无不属于本组件的资源误释放；延迟及未停止工作明确可查。
- **验证映射：** F11 / N11 / E11，见下表。

### M12 超时、重试与未知提交

- **适用条件：** 发生远端或可能重复副作用时。
- **机制要求：** 区分连接、读写及总期限；重试受总预算、错误分类、服务契约和调用者策略约束。非幂等动作在提交结果未知时先查询或核对服务端幂等契约；查询未找到不证明原请求从未应用或已停止在途，最终一致索引的缺失不能触发新身份重发。依赖服务端去重时固定租户/目标/操作键作用域、载荷指纹和有效期限，只在契约覆盖目标接受/处理窗口且身份/参数一致时同键重试。本地派发时尚未过期不足以证明远端到达时安全；有限去重窗口须有目标强制接受截止、足够的已证处理窗口或等价机制，避免迟到请求被当新操作；过期、范围不明或无权威结论保持未知并提供核对入口。SDK重试不得与上层重试无界相乘；无副作用或已知幂等请求按真实契约处理。
- **完成标准：** C12：未知与未应用区分；查询缺失不放行新身份副作用，去重只在准确范围/参数/期限内使用；期限与次数满足声明，未知状态向调用者保真传播。
- **验证映射：** F12 / N12 / E12，见下表。

### M13 SDK公开类型与数据保真

- **适用条件：** 提供SDK时。
- **机制要求：** 明确可导入入口、类型、可空性、单位、枚举未知值、精度、时区及所有权；反序列化不得静默丢失契约必要字段。动态语言也需可执行的契约证据，不强迫静态类型；生成类型不替代真实服务行为校验。
- **完成标准：** C13：必要语义和精度不丢失；未知值按明确策略保留或拒绝，不伪造合法业务状态。
- **验证映射：** F13 / N13 / E13，见下表。

### M14 SDK初始化与宿主隔离

- **适用条件：** 可导入库或SDK。
- **机制要求：** 导入与构造的副作用须明确；不隐式发起计费请求、改全局日志/代理、注册不可撤销钩子或读取无关凭据。需要初始化的客户端区分配置验证、凭据取得与连接建立；可失败步骤向宿主返回错误，资源关闭路径可调用。
- **完成标准：** C14：未承诺副作用不存在，已声明副作用符合授权；失败与关闭不遗留未说明资源。
- **验证映射：** F14 / N14 / E14，见下表。

### M15 同步、异步与并发契约

- **适用条件：** SDK存在并发或异步入口时。
- **机制要求：** 说明线程安全、重入、事件循环、回调执行上下文、阻塞点及对象共享限制；非线程安全对象可以合法存在，但需明确隔离使用。不得由库私自接管或关闭宿主事件循环；异步取消和异常须沿调用链传播。
- **完成标准：** C15：承诺并发模型下无串扰或死锁；不支持用法被明确说明，宿主调度和生命周期不被夺取。
- **验证映射：** F15 / N15 / E15，见下表。

### M16 分页、迭代与流式资源

- **适用条件：** 暴露分页或数据流时。
- **机制要求：** 说明分页游标、排序、快照或变化语义、空页、结束条件和游标失效。游标续接绑定原租户、查询和排序语义，以及服务提供的快照身份；仅服务明确允许的参数可在页间改变，游标不是资源访问授权。失效时向调用者报告中断，不静默重头并伪称同一完整结果集；显式重新开始须区分新遍历及已交付部分。懒迭代器明确何时发请求及如何关闭。流式API提供与目标平台适配的反压或容量边界，不将无限数据全部缓存；断流保留已交付与未完成区别。
- **完成标准：** C16：终止符合服务协议，异常游标不无限循环；消费停止后资源按契约收敛，部分结果可识别。
- **验证映射：** F16 / N16 / E16，见下表。

### M17 凭据与身份上下文

- **适用条件：** 访问受保护资源时。
- **机制要求：** 明确凭据获取、作用域、刷新、撤销及存储边界；不把命令行参数作为唯一秘密输入途径。不同客户端身份和租户不可由共享缓存混淆；诊断及有效配置屏蔽秘密。认证成功不代替对象授权，失败后不得自动降级到权限更大的默认身份。
- **完成标准：** C17：身份绑定正确、拒绝不扩权，秘密不进入不受控输出，刷新和撤销行为可确认。
- **验证映射：** F17 / N17 / E17，见下表。

### M18 端点、代理与传输配置

- **适用条件：** 联网工具或SDK。
- **机制要求：** 明确信任的端点来源、代理、TLS验证、重定向、DNS及离线模式；配置错误不得静默关闭证书验证。令牌只发送给其被授权的目标，重定向或用户输入URL不得扩大传递范围；测试替身配置与生产默认分离。
- **完成标准：** C18：错误不弱化验证，凭据不跨授权端点，测试设置不成为不知情的默认生产配置。
- **验证映射：** F18 / N18 / E18，见下表。

### M19 公共API兼容与废弃

- **适用条件：** 有稳定公开契约时。
- **机制要求：** 将源码、二进制、协议、输出和行为兼容分别声明；新增枚举、异常、默认值或输出字段也按实际消费者评估。版本策略可选SemVer或其他可解释策略；若采用SemVer则按其公开API含义执行。废弃提供实际迁移条件，不以警告代替兼容验证。
- **完成标准：** C19：声明兼容范围内旧用法保持有效；不兼容变化明确批准、版本和迁移，未支持范围不伪装已覆盖。
- **验证映射：** F19 / N19 / E19，见下表。

### M20 运行时、ABI与依赖协同

- **适用条件：** 存在宿主运行时或原生边界时。
- **机制要求：** 声明最低与最高已验证环境、架构、模块格式、ABI及依赖约束；API源码兼容不意味着二进制兼容。依赖解析须考虑宿主已有版本，库不任意覆盖宿主依赖；跨语言FFI说明内存分配释放、布局和异常边界。
- **完成标准：** C20：受支持组合能消费实际包，原生边界资源正确；未验平台标为未验证而非自动支持。
- **验证映射：** F20 / N20 / E20，见下表。

### M21 打包内容与消费端安装

- **适用条件：** 分发软件包或二进制时。
- **机制要求：** 检查实际包入口、依赖、类型/头文件、许可证、数据文件、可执行权限及排除项；安装不依赖开发仓库偶然文件。安装/卸载脚本副作用明确且符合权限，不默认为修改全局环境。分发渠道与包名身份须可追溯。
- **完成标准：** C21：真实发行入口完整，未授权脚本副作用不存在；卸载边界清楚且不误删用户资产。

| M36 | F36：下架时无授权清空用户配置；删除历史发行身份使事故无法复核。 | N36：同一下架保留用户资产及应保留的历史发行证据，支持停止与删除动作分开授权。其他合法适用分支：内部实验已声明短期支持并在获准期限结束；停止新发行不等于删除既有用户文件。 | E36：核退役通知、迁移消费示例、历史版本/证据保留及卸载后用户资产清单。 | C36：支持变化真实传达，迁移与保留责任明确；无未经授权删除，历史可审计且不虚称持续支持。 |

## 官方参考资料、效力与核验边界

来源效力依实际采用的生态/协议区分。SemVer2.0.0、RFC8259、RFC9110、AIP158和LSP3.17的有限命题、固定源码身份及访问失败见[逐命题来源表](../../../sources/runtime-protocol/SOURCE-CLAIMS.md)。GNU/POSIX正文访问未成功，不以其目录或搜索摘要引入一致性义务。命令语法按实际L5合同，非GNU/POSIX工具不因此被误拒。

## 验收证据合同与实施方式

矩阵E01–E36是项目需落实的检查入口说明，不是已执行回执。L6为每个适用行绑定真实命令、脚本/测试名称、输入夹具、候选版本、消费环境、结果文件和C项断言。不能仅交一条“已检查”。涉及真实账户、服务、资金、数据或平台动作的验证，取得相应授权并在允许环境执行；技术引用或采用不产生外部动作许可。

每份实际证据至少记录：机制/场景ID、适用判据、准确工具/包版本或摘要、目标OS/Shell/运行时及服务版本、复现命令或操作步骤、合成/真实数据性质、stdout/stderr/错误与状态回读、预期和实得差异、通过/失败/未运行/不适用。结果含秘密时按既有制度保留受控原件并提供可核的脱敏引用，不把秘密放正文。

静态编制验收检查每个机制和失败行对应同号证据与完成条件，逐行核查失败与合法邻例仅在关键条件上变化。机器检查应识别缺行、重复ID、无效映射和故意交换证据；它只能证明文档结构及所编码的回归，不证明所有自然语言义务正确。独审另行检验适用性、执行性、上层一致性与未读来源边界。实际产品验收则必须从发行产物或真实入口到消费者结果，不把本规范结构自检冒称产品测试。

## 领域契约与完整专题接口

非目标：不强制所有工具提供CLI/异步/JSON/LSP/插件/多平台，或把源码兼容等同ABI；不由工具便利性授予全局安装或外部动作许可。
