# L4 后端与分布式系统领域通用基线

**文档ID：** STD-L4-BACKEND-007　**版本：** 0.1.0　**状态：** adopted　**生效日期：** 2026-10-30

## 定位与有效依据

本规范是 L4“后端与分布式系统”的**领域通用基线**，适用于单体、模块化单体、API 服务、异步 Worker、Serverless、多服务与分布式系统。以真实用户与运维目标决定技术复杂度，不强制微服务、队列或服务网格，也不把通用基线视作各具体技术专项已完成。
相应依据：[L1 全局治理补充规范](../../L1/001-全局治理补充规范--v0.1.0.md)、[L2 人类与 Agent 团队组织协作规范](../../L2/001-人类与-Agent-团队组织协作规范--v0.1.0.md)、[L3 通用工程规范](../../L3/001-通用工程规范--v0.1.0.md)。业务规则、数据和资金权利由有权主体决定，L5 负责具体语言及框架，L6 负责实际项目采用及运行验收。
官方规范直接引用：[RFC 9110 HTTP Semantics](https://www.rfc-editor.org/rfc/rfc9110.html)、[RFC 9111 HTTP Caching](https://www.rfc-editor.org/rfc/rfc9111.html)、[RFC 9457 Problem Details](https://www.rfc-editor.org/rfc/rfc9457.html)、[OpenAPI v3.2.1](https://spec.openapis.org/oas/v3.2.1.html)、[CloudEvents v1.0.2](https://github.com/cloudevents/spec/blob/v1.0.2/cloudevents/spec.md)、[W3C Trace Context 2021 Recommendation](https://www.w3.org/TR/trace-context/)、[OpenTelemetry Specification](https://opentelemetry.io/docs/specs/otel/)。[gRPC 官方核心概念](https://grpc.io/docs/what-is-grpc/core-concepts/)属于产品实施指南；[OWASP API Security Top 10 2023](https://api-security.owasp.org/editions/2023/en/0x03-introduction/)是安全风险参考。以上来源的权威类别不同，均不自动使项目启用该技术或合规。

## 核验口径与消费接口

维护者负责落实本文机制，领域/API/存储提供者负责其权威保证，验收者从实际受支持入口观察结果。输入固定源码/构建、配置、数据/协议版本、角色/租户、目标平台、故障时序和预算；权威观察对象为**领域权威持久状态、外部操作收据及各阶段独立身份**。真实执行入口为**真实接口客户端、数据库多连接查询、Broker/外部沙箱收据与阶段对账**。逐章 P/F/N 分别为正常输入及判据、破坏该机制的直接失败变异、应继续成立的合法邻例；本章原有每项规则、原有验收与新增合同共同约束，不用单一通用案例替代具体子项。每个子项须在案例输入中保留其适用条件，并以自身原文规定的输出/不变量判定；复合章应拆记录各个观察量，不能以一个成功掩盖其他失败。

证据产物包括真实命令/用户动作、原始响应或事件、权威状态前后值、版本、时序、失败及恢复；尚无对应真实运行证据的场景状态为 `not-run`，标准库示例仅证明列明的局部边界。具体输入与命令见[执行入口](../../../examples/web-backend/RUNBOOK.md)，条款索引见[规范条款登记](../../../registry/requirements.json)，来源的有限支持命题见[逐命题来源映射](../../../sources/web-backend/claims.json)。

本文的跨组件约束与正例、失败反例、合法邻例由本规范综合定义；外部来源支持的机制及适用边界见来源表。项目架构、预算和业务规则由实际需求确定。L5 实现应映射到所选框架、SDK 或引擎；L6 按具体版本的提供者保证与受支持矩阵验收项目能力。

## 一、架构形态与服务职责
按真实需求、独立部署价值、响应延迟、团队运维与费用选择单体、Worker 或多服务；每一组件明确业务职责、数据所有者、部署和故障边界。**验收**：实际入口到领域动作和用户结果可追踪，不为迎合架构删减功能。

### BE-001 核验合同

- **BE-001-P · 输入/动作与合格判据：** 从实际入口走到持久结果→组件职责/数据权威/故障域可查。
- **BE-001-F · 直接失败变异：** 为微服务形式拆分后丢原子约束→失败。
- **BE-001-N · 合法邻例：** 单体可满足全部需求。

## 二、领域模型与数据保真
定义领域身份、状态机、不变量及版本、数量、时间、来源、租户等合法差异。DTO、缓存、数据库设计和客户端不得擅定业务含义。**验收**：使用单变量对照验证读写、事件及跨角色交付保持实际差异。

### BE-002 核验合同

- **BE-002-P · 输入/动作与合格判据：** 改变金额/单位/租户/期限各一项→模型到事件导出保持差异。
- **BE-002-F · 直接失败变异：** DTO默认值吞掉合法空值或精度→失败。
- **BE-002-N · 合法邻例：** 只读模型可无状态机。

## 三、HTTP 方法与资源协议
遵守选定的 RFC 9110 方法、状态与缓存契约，区分安全读取和带副作用操作，不能在 GET 隐式扣费；分页、过滤、错误及条件请求有明确输入输出。**验收**：真实消费者验证权限、状态码、版本、业务结果和缓存隔离。

### BE-003 核验合同

- **BE-003-P · 输入/动作与合格判据：** 实际消费者重复安全读取及条件写→状态和授权符合HTTP。
- **BE-003-F · 直接失败变异：** GET查询参数触发删除命令→失败。
- **BE-003-N · 合法邻例：** 访问日志和既定流量计量不等于用户请求的破坏性动作。

## 四、RPC、流式与实时连接
对采用的 gRPC、WebSocket、SSE 等定义消息形态、认证上下文、deadline、背压、取消及断线重放；不将网络断开等同于已撤销持久副作用。**验收**：慢消费者、断线、旧客户端与服务重启可恢复或受控失败。

### BE-004 核验合同

- **BE-004-P · 输入/动作与合格判据：** 慢流/断线/重启/旧客户端→背压有界且外部结果可查。
- **BE-004-F · 直接失败变异：** 断连即显示已撤销持久副作用→失败。
- **BE-004-N · 合法邻例：** 低频查询不需长连接。

## 五、请求身份与跨服务上下文
身份、租户、委派授权、追踪标识和业务请求 ID 分别处理；网关转发的用户标头及外部消息按实际可信边界验证。**验收**：并发与权限变更时无跨租户串用或过期授权再执行。

### BE-005 核验合同

**必要机制补充：** 逻辑意图、执行尝试、数据库事务、业务事件、投递与Trace身份分别定义；重试保留意图而增加尝试，不以追踪采样决定是否已发生业务。

- **BE-005-P · 输入/动作与合格判据：** 伪造代理身份和跨租户并发→身份/意图/尝试/Trace不混用。
- **BE-005-F · 直接失败变异：** X-Tenant直接决定受信租户→失败。
- **BE-005-N · 合法邻例：** 同主体合法多组织切换。

## 六、API 合同与消费者演进
对 HTTP、RPC、事件、文件及回调定义字段、单位、默认值、版本和兼容窗口。采用 OpenAPI 等描述语言时锁定工具支持版本，Schema 静态检查不等于真实兼容。**验收**：已承诺支持的旧消费者和新服务交叉测试。

### BE-006 核验合同

- **BE-006-P · 输入/动作与合格判据：** 新服务与旧SDK/事件样本交叉→语义及字段保持。
- **BE-006-F · 直接失败变异：** Schema绿但单位改义→失败。
- **BE-006-N · 合法邻例：** 无历史消费者可简化兼容矩阵。

## 七、输入校验与错误语义
区分格式、领域拒绝、鉴权、冲突、速率限制、外部临时失败和内部缺陷；RFC 9457 仅在实际采用时使用，错误响应保留可操作条件而不暴露内部堆栈。**验收**：无效输入和外部失败均不损坏状态。

### BE-007 核验合同

- **BE-007-P · 输入/动作与合格判据：** 格式坏/无权/冲突/上游故障→分别拒绝且状态不损坏。
- **BE-007-F · 直接失败变异：** 全部200包success或公开SQL栈→失败。
- **BE-007-N · 合法邻例：** 合法自定义错误格式可不采Problem Details。

## 八、事务原子性与提交确认
识别每次写入的原子边界、隔离性、唯一约束及提交成功条件；事务外通知、支付和远端副作用不能因本地事务回滚自动撤销。**验收**：异常回滚及并发读写时保存业务不变量。

### BE-008 核验合同

- **BE-008-P · 输入/动作与合格判据：** 提交前/后退出进程→原子不变量和真实提交可回读。
- **BE-008-F · 直接失败变异：** 函数return当数据库已提交→失败。
- **BE-008-N · 合法邻例：** 无持久写入不强制事务。

## 九、锁、并发和业务幂等
按共享记录或业务操作范围选择版本条件更新、唯一性、锁、事务或队列协调。幂等身份及请求内容一致性需要独立定义，重试不等于恰好一次执行。**验收**：成功后超时、并发重复提交和幂等键冲突没有重复副作用。

### BE-009 核验合同

**必要机制补充：** 逻辑意图ID在安全重试间保持不变，每次发送另分配尝试ID；事务ID、事件ID、投递ID和Trace ID不得代替它。权威查询暂未发现记录、读副本落后、日志缺失、客户端超时均不证明原尝试不会随后提交。只有目标端对同意图实行覆盖所有在途/迟到尝试的原子唯一性，或有已安装的栅栏/终止与线性化屏障证明原尝试不再可生效，才可依合同重发；否则保持结果未知并继续有权核对，不新建意图绕过去重。有限去重保留窗须覆盖目标最后可能接受该意图的时刻、重放和恢复窗口；不能只比较本地派发时间。窗外仍可迟到时使用永久领域唯一性、目标拒旧期限/世代或有权人工核对。

- **BE-009-P · 输入/动作与合格判据：** 双进程同意图和冲突指纹→持久唯一结果。
- **BE-009-F · 直接失败变异：** 先查后执行再记键造成双扣→失败。
- **BE-009-N · 合法邻例：** 合法同键同参重传应返回原结果。

## 十、跨服务一致性与流程补偿
只有实际跨事务需求才引入 Saga、Outbox、Inbox 或补偿工作流；定义工作流身份、阶段、超时、下游确认及恢复责任。**验收**：消息迟到、两端局部故障、补偿失败后不会虚报资金或订单完成。

### BE-010 核验合同

- **BE-010-P · 输入/动作与合格判据：** 两域部分成功且补偿失败→欠履约可查。
- **BE-010-F · 直接失败变异：** Saga引擎Completed冒资金完成→失败。
- **BE-010-N · 合法邻例：** 单事务足够时不引入Saga。

## 十一、事件消息与消费者职责
定义发布者、消费者、事件身份、版本、顺序范围、ACK、重试及死信。CloudEvents 只是按项目选择的事件封装标准，不保证完整事务。**验收**：重复／乱序／毒消息与消费者重启后仍有可查询的处理结果。

### BE-011 核验合同

- **BE-011-P · 输入/动作与合格判据：** 重复/乱序/毒消息与消费者重启→各消费范围可恢复。
- **BE-011-F · 直接失败变异：** Broker ACK当所有订阅方业务成功→失败。
- **BE-011-N · 合法邻例：** 允许损失遥测可有不同交付等级。

## 十二、缓存与衍生查询状态
识别数据库和缓存、搜索索引、聚合视图的权威关系，明确键、租户、权限、时效和失效机制。**验收**：用户切换、权限撤销、写后读取及数据删除不会返回不应访问的旧结果。

### BE-012 核验合同

- **BE-012-P · 输入/动作与合格判据：** 撤权/写后读/换租户/删除重建→衍生结果不越权。
- **BE-012-F · 直接失败变异：** TTL未到继续返回已撤权敏感字段→失败。
- **BE-012-N · 合法邻例：** 公开搜索可有明确陈旧窗。

## 十三、数据存储访问契约
规定领域查询、读写职责、事务入口和数据访问预算；具体 Schema、索引、备份及恢复归 L4 数据库专项，ORM 约定归 L5。**验收**：生产等价数据形态的持久化和迁移保留关键业务字段及约束。

### BE-013 核验合同

- **BE-013-P · 输入/动作与合格判据：** 真实形态数据持久化并迁移→字段/约束/访问预算保留。
- **BE-013-F · 直接失败变异：** ORM注解当引擎原子保证→失败。
- **BE-013-N · 合法邻例：** 无数据库服务不强制引入存储。

## 十四、对象授权与服务身份
认证、对象级操作授权、字段／租户权限和内部服务授权独立核对；Gateway、JWT 校验或持有内部 Token 不自动满足目标资源权限。**验收**：直接调用内部接口、跨租户对象 ID 和过期身份均被正确拒绝。

### BE-014 核验合同

- **BE-014-P · 输入/动作与合格判据：** 内部直连/错aud/跨租户ID→逐对象动作拒绝。
- **BE-014-F · 直接失败变异：** JWT有效即可读任意对象→失败。
- **BE-014-N · 合法邻例：** 匿名公开对象可按契约读取。

## 十五、服务端密钥、配置与供应链
秘密按环境和服务权限注入，不能进入源码、公开响应、日志与无关 Agent 上下文。依赖、镜像和外部 SDK 的来源、版本与许可可查。**验收**：密钥轮换、依赖升级和配置缺失能受控恢复。

### BE-015 核验合同

- **BE-015-P · 输入/动作与合格判据：** 缺配置/轮换密钥/依赖升级→受控失败且无秘密外泄。
- **BE-015-F · 直接失败变异：** 生产密钥写日志或公开响应→失败。
- **BE-015-N · 合法邻例：** 公开非敏感配置可进入客户端。

## 十六、超时、取消与背压
明确客户端期限、网关超时、下游 deadline、队列限额和实际取消语义。重试、限流、背压、连接池和负载保护避免局部错误放大，不能绕过第三方配额。**验收**：慢请求和排队压力不会导致数据丢失或无边界资源消耗。

### BE-016 核验合同

- **BE-016-P · 输入/动作与合格判据：** 慢下游/排队/取消与提交竞争→期限和资源有界且未知保留。
- **BE-016-F · 直接失败变异：** 每跳重置总预算或取消即回滚→失败。
- **BE-016-N · 合法邻例：** 独立持久任务可在同步断开后继续。

## 十七、服务可用性及依赖退化
区分存活、就绪、领域能力和业务结果；定义故障域、隔离、健康检查与可安全降级范围，不强制所有项目有多副本。**验收**：依赖不可用和节点退出时，不通过虚构成功掩盖权限、金额及数据故障。

### BE-017 核验合同

- **BE-017-P · 输入/动作与合格判据：** 依赖不可用/节点退出→能力状态真实、不伪造成功。
- **BE-017-F · 直接失败变异：** 健康绿当订单履约→失败。
- **BE-017-N · 合法邻例：** 低风险单副本可明确可靠性范围。

## 十八、网关、服务发现与路由
明确入口、反向代理、TLS 终止、路径重写、负载分配及服务发现的真实信任边界。**验收**：正式域名至服务内部的完整路径、身份转发、长连接及发布切换有实测结果。

### BE-018 核验合同

- **BE-018-P · 输入/动作与合格判据：** 正式入口经代理到服务→路径/身份/长流/切换正确。
- **BE-018-F · 直接失败变异：** 本机直连通当CDN与TLS全链路通过→失败。
- **BE-018-N · 合法邻例：** 无网关的受控直接入口可合法。

## 十九、日志、指标与分布式追踪
按项目采用需要选择 W3C Trace Context／OpenTelemetry 版本，建立请求、业务状态、错误、队列和依赖的可核查关联，避免泄漏隐私与密钥。**验收**：故障的事实、推断和未知分开报告，进程存活不等于业务完成。

### BE-019 核验合同

- **BE-019-P · 输入/动作与合格判据：** 诊断缺失但查询权威业务键→事实/推断/未知分清。
- **BE-019-F · 直接失败变异：** 没有Trace就推断没发生提交→失败。
- **BE-019-N · 合法邻例：** 不采用OTel也可有可复核诊断。

## 二十、吞吐、尾延迟与资源预算
按真实峰值、存储量、连接数及第三方费用确定资源预算。优先实测 N+1 查询、连接池耗尽、队列积压、锁竞争和冷启动，避免以优化速度牺牲数据精度。**验收**：目标环境报告 P95／P99 或项目选定阈值及实际成本。

### BE-020 核验合同

- **BE-020-P · 输入/动作与合格判据：** 峰值/热键/连接池/冷启动负载→尾延迟/成本/正确性同时测。
- **BE-020-F · 直接失败变异：** 优化删条件写或丢金额精度→失败。
- **BE-020-N · 合法邻例：** 低负载无须昂贵集群。

## 二十一、滚动发布与跨版本兼容
版本关联服务包、配置、数据库、消息、外部 API 与旧客户端；按需要安排滚动、灰度和数据迁移。**验收**：新旧服务及客户端交错运行与回滚中，已承诺窗口内能正常或安全失败，不假定回滚已撤销外部事件。

### BE-021 核验合同

- **BE-021-P · 输入/动作与合格判据：** 旧新服务/客户端/消息/Schema混跑→支持窗内兼容或安全拒绝。
- **BE-021-F · 直接失败变异：** 回滚镜像即声称外部通知撤销→失败。
- **BE-021-N · 合法邻例：** 不可逆变更可合法前滚修复。

## 二十二、事故恢复和防复发
事故记录权威状态、已发生副作用、真实受影响用户、权限、证据、恢复和遗留问题。根因未知时不得推断；修复后验证实际请求与下游。**验收**：数据完整性、必要对账和针对性回归可复核。

### BE-022 核验合同

- **BE-022-P · 输入/动作与合格判据：** 恢复后按业务对象对账→实际影响和欠履约保留。
- **BE-022-F · 直接失败变异：** 告警恢复即关闭所有未知订单→失败。
- **BE-022-N · 合法邻例：** 根因未明可如实记录未知。

## 二十三、质量门禁与实际接线
按具体项目风险组合单元、合同、集成、事务、异步、权限、故障恢复和真实 E2E 测试。Web、API、Agent/MCP 及批处理入口须使用相同的权威业务规则，不重复高成本等价验证。**验收**：测试对应实际版本、环境、输入和结果。

### BE-023 核验合同

- **BE-023-P · 输入/动作与合格判据：** 真实入口到最终结果并注入故障→证据绑定版本和环境。
- **BE-023-F · 直接失败变异：** Mock支付或CI绿色冒真实收款→失败。
- **BE-023-N · 合法邻例：** 等价组件证据可复用而不重复高成本测试。

## 二十四、静态失效场景矩阵
| 情形 | 关键边界 | 预期业务结果 |
| --- | --- | --- |
| 单体满足全部需求 | 架构选型 | 无需强制拆成微服务 |
| 相同资源 ID 被不同租户访问 | 对象级权限 | 无越权读取和修改 |
| 权限撤销后旧任务运行 | 授权时效 | 按有权范围执行或停止 |
| 客户端超时但服务已提交 | 幂等和回读 | 无重复交易或消息 |
| 同时修改同一业务记录 | 版本、事务、锁 | 状态约束不被破坏 |
| 数据库提交但事件未发出 | 一致性补偿 | 下游可恢复，不静默丢失 |
| 消息重复或乱序 | 事件 ID、去重 | 处理结果有真实证据 |
| 第三方服务限流 | 配额、退避 | 遵守限流并保留受阻原因 |
| 旧程序遇新 Schema | 协议迁移 | 支持窗口内安全兼容 |
| 跨租户缓存命中 | 缓存作用域 | 无身份数据泄漏 |
| RPC 途中取消 | deadline、副作用 | 不虚报已撤销写入 |
| 补偿自身失败 | 工作流恢复 | 保留未完成证据和恢复动作 |
| 健康检查绿、业务故障 | 业务指标 | 准确区分可用与已完成 |
| 构建日志泄漏密钥 | 隐私、供应链 | 阻止传播并依权限处置 |
| 性能优化丢失金额精度 | 领域不变量 | 合法条件及数值保真 |
| 服务重启与网络分区 | 恢复与一致性 | 真实业务可恢复或安全失败 |
