本专项适用于真正发生跨版本切换的后端服务、客户端、数据库、配置、事件、任务及外部依赖。关注跨版本组合、迁移顺序、状态保护、恢复正确性和对最终用户的实际结果，不强制采用多集群、多 Agent 或特定中间件。

## 三、46 项跨版本机制及项目级验收

## 核验口径与消费接口

维护者负责落实本文机制，领域/API/存储提供者负责其权威保证，验收者从实际受支持入口观察结果。输入固定源码/构建、配置、数据/协议版本、角色/租户、目标平台、故障时序和预算；权威观察对象为**制品/配置/Schema/数据/消息/客户端版本与跨系统恢复水位**。真实执行入口为**实际部署只读查询、固定引擎DDL/回填、隔离恢复、旧新客户端与历史消息合同**。逐章 P/F/N 分别为正常输入及判据、破坏该机制的直接失败变异、应继续成立的合法邻例；本章原有每项规则、原有验收与新增合同共同约束，不用单一通用案例替代具体子项。每个子项须在案例输入中保留其适用条件，并以自身原文规定的输出/不变量判定；复合章应拆记录各个观察量，不能以一个成功掩盖其他失败。

证据产物包括真实命令/用户动作、原始响应或事件、权威状态前后值、版本、时序、失败及恢复；尚无对应真实运行证据的场景状态为 `not-run`，标准库示例仅证明列明的局部边界。具体输入与命令见[执行入口](../../../examples/web-backend/RUNBOOK.md)，条款索引见[规范条款登记](../../../registry/requirements.json)，来源的有限支持命题见[逐命题来源映射](../../../sources/web-backend/claims.json)。

本文的跨组件约束与正例、失败反例、合法邻例由本规范综合定义；外部来源支持的机制及适用边界见来源表。项目架构、预算和业务规则由实际需求确定。L5 实现应映射到所选框架、SDK 或引擎；L6 按具体版本的提供者保证与受支持矩阵验收项目能力。

### §01 适用边界与变更风险
**机制：** 根据真实业务、服务/存储/客户端版本风险与可恢复性选择必要迁移机制；区分普通、不可逆及资金/隐私高影响变更，不要求所有项目配置多集群。

**验收：** 项目明确真实业务不变量、影响范围、资金及数据授权，不虚构不需要的系统组件。

**§01 核验合同**

- **§01-P · 输入/动作与合格判据：** 列实际变更风险与恢复对象→机制相称。
- **§01-F · 直接失败变异：** 低风险改动强制买多集群→失败。
- **§01-N · 合法邻例：** 简单可逆变更可直接发布。

### §02 变更清单与目标状态
**机制：** 每轮列出源码、制品、配置、API/RPC、事件、Schema、缓存、任务、客户端及外部回调的旧新版本和写入主体；不要以单个 Git SHA 代表所有在线状态。

**验收：** 可对每个实际改变的对象反查目标版本、依赖和验收结果。

**§02 核验合同**

- **§02-P · 输入/动作与合格判据：** 逐制品/配置/API/Schema/客户端列旧新版→状态可反查。
- **§02-F · 直接失败变异：** 只Git SHA代表所有在线字节→失败。
- **§02-N · 合法邻例：** 未变组件保留其独立版本。

### §03 制品不可变性与构建链
**机制：** 源码提交、锁文件、构建环境、镜像/包的不可变摘要及部署记录贯通；不得以可漂移的 latest 标签或 CI 绿色代替生产制品身份。

**验收：** 实际在线版本和候选审查/构建产物完全关联。

**§03 核验合同**

- **§03-P · 输入/动作与合格判据：** 在线包回读摘要关联清洁构建→不可变身份贯通。
- **§03-F · 直接失败变异：** latest漂移或CI绿代制品→失败。
- **§03-N · 合法邻例：** 授权外部长期资源可独立记录。

### §04 隔离环境、租户与入口
**机制：** 开发、测试、预发布、生产隔离数据、凭据、通知、Webhook、支付和租户；恢复演练不连接无授权的真实外部写入目标。

**验收：** 正常、回退、异常分支都核对实际目标入口与执行权限。

**§04 核验合同**

- **§04-P · 输入/动作与合格判据：** 正常/异常/回退目标核环境→不触无权支付/通知。
- **§04-F · 直接失败变异：** 恢复脚本指向生产凭据→失败。
- **§04-N · 合法邻例：** 纯本地合成演练可完全离线。

### §05 职责、审批与部署权限
**机制：** 组织规范批准只确立技术条文，项目生产变更、数据删除、资金、客户承诺仍由真实权利主体授权；OPC 不制造额外虚构审批人。

**验收：** 审批记录、执行角色、生产写入权限、L6 验收可以独立核对。

**§05 核验合同**

- **§05-P · 输入/动作与合格判据：** 按操作核生产/删数/资金权限→技术采用与真实执行授权分开。
- **§05-F · 直接失败变异：** 草案批准冒生产变更许可→失败。
- **§05-N · 合法邻例：** 同真实人可兼必要角色。

### §06 服务、数据与消息依赖图
**机制：** 按调用链、数据库共享、旧新消费端、长任务和外部边界建立受影响拓扑及执行顺序；混跑风险应优先于发布脚本便利性。

**验收：** 新旧节点共存所需的协议/数据路径有明确先后及失败处理。

**§06 核验合同**

- **§06-P · 输入/动作与合格判据：** 旧新服务/消息/长任务依赖→顺序支持所有共存组合。
- **§06-F · 直接失败变异：** 发布便利顺序先删旧列→失败。
- **§06-N · 合法邻例：** 无跨组件变更无需全局编排。

### §07 现有运行基线与上线前门禁
**机制：** 保存上线前实际版本、负载、尾延迟、合法业务完成率、错误、容量和未知项；静态通过、旧环境绿灯不替代当前运行基线。

**验收：** 数据口径、样本、环境及业务结果能重复核验。

**§07 核验合同**

- **§07-P · 输入/动作与合格判据：** 保留上线前业务/尾延迟/容量基线→同口径可复算。
- **§07-F · 直接失败变异：** 旧环境绿灯冒当前运行基线→失败。
- **§07-N · 合法邻例：** 低样本准确标注限制。

### §08 跨版本兼容性矩阵
**机制：** 枚举旧客户端→新服务、新客户端→旧服务、新旧服务→数据库、新旧生产者→新旧消费者的真实可能组合；按长期任务/客户端保留决定兼容窗口。

**验收：** 所有实际共存组合都做有权输入、边界、异常和恢复对照。

**§08 核验合同**

- **§08-P · 输入/动作与合格判据：** 旧客户端新服务/反向及Schema组合→合法/错误/恢复都对照。
- **§08-F · 直接失败变异：** 只最新版本联调→失败。
- **§08-N · 合法邻例：** 不可能共存组合有技术证明可排除。

### §09 HTTP 资源与废弃协议
**机制：** 使用 HTTP 时保留 RFC 9110 和现行 API 规范的资源、方法、条件请求、缓存及错误合同；按 RFC 9745 Deprecation 和 RFC 8594 Sunset 区分不同通知效力。

**验收：** 解析成功不等于业务字段含义不变；废弃标记不直接停止服务。

**§09 核验合同**

- **§09-P · 输入/动作与合格判据：** HTTP方法/缓存/废弃通知真实消费者→语义保留。
- **§09-F · 直接失败变异：** Deprecation标记直接停服务→失败。
- **§09-N · 合法邻例：** 不采用HTTP的接口不硬套头部。

### §10 RPC 与 Protobuf wire 兼容
**机制：** 实际选用 Protobuf 时锁定 SDK/edition 的字段号、删除字段 reserved、枚举、默认值与 JSON 映射；RPC 流式取消、deadline 仍受原有契约。

**验收：** 真实新旧字节样本、方法结果及对象授权不变。

**§10 核验合同**

- **§10-P · 输入/动作与合格判据：** 新旧proto与JSON样本→字段号reserved/存在性/语义保持。
- **§10-F · 直接失败变异：** wire兼容冒枚举业务也兼容→失败。
- **§10-N · 合法邻例：** 其他IDL依自己的版本规范。

### §11 事件 Schema 与消费版本
**机制：** 区分 CloudEvents 1.0.2 封套与 data schema；评估字段类型/版本及消费者，Confluent BACKWARD/FORWARD/FULL/TRANSITIVE 等仅在选用时按产品定义生效。

**验收：** 新旧消息/消费者在实际保留周期内有可运行的合法读写组合。

**§11 核验合同**

- **§11-P · 输入/动作与合格判据：** 旧新事件/消费者/历史data→封套与业务Schema分别验证。
- **§11-F · 直接失败变异：** CloudEvents版本同就默认data同义→失败。
- **§11-N · 合法邻例：** 不用Schema Registry可有等价合同。

### §12 消息延迟、DLQ 与历史回放
**机制：** 最长滞后、Broker 积压、保留期、重放和已归档事件都可能含旧格式；读端退役必须评估未完成业务与历史数据。

**验收：** 重放不遗失旧事件、不误认为 Broker ACK 是客户完成。

**§12 核验合同**

- **§12-P · 输入/动作与合格判据：** DLQ/离线消费者重放最老支持事件→格式和欠处理可恢复。
- **§12-F · 直接失败变异：** 退役旧reader但留存队列仍含旧格式→失败。
- **§12-N · 合法邻例：** 支持窗已结束且义务处理完才可退役。

### §13 数据库 Schema 扩展与收缩
**机制：** 按兼容窗口选择先扩展结构、回填和验证、切换读写、再删除废弃字段的顺序；具体 DDL 属数据库 L4。

**验收：** 旧进程、备份恢复和异步任务不再依赖旧结构后才收缩。

**§13 核验合同**

**必要机制补充：** 收缩前的消费者清单包含旧Writer、长期任务、离线客户端、DLQ/历史事件及恢复备份所需程序；仅新服务已滚完不证明全部旧依赖结束。

- **§13-P · 输入/动作与合格判据：** 扩展/回填/切读写/收缩受控执行→旧writer退出后才删列。
- **§13-F · 直接失败变异：** 新程序就绪即删旧字段→失败。
- **§13-N · 合法邻例：** 无破坏性变化可不执行完整扩展收缩。

### §14 数据库锁、长事务和重写
**机制：** 依据实际数据库版本决定 ALTER/索引/约束的锁粒度、重写、复制延迟及超时；PostgreSQL 18 多种子操作锁要求不同。

**验收：** 真实数据量与并发负载下不把长锁操作误报无中断。

**§14 核验合同**

- **§14-P · 输入/动作与合格判据：** 真实数据量DDL锁/长事务→等待和重写边界可测。
- **§14-F · 直接失败变异：** 声明无锁而实际阻塞读写→失败。
- **§14-N · 合法邻例：** 不同DDL子操作可有不同锁合同。

### §15 数据回填与可恢复检查点
**机制：** 定义稳定游标、批次幂等、并发修改冲突、完成水位、暂停/续跑和限速；不能用会漂移的 OFFSET 导致遗漏。

**验收：** 任意失败点重试不双计、不漏数据，权威源完整。

**§15 核验合同**

- **§15-P · 输入/动作与合格判据：** 稳定游标回填中断/并发改→checkpoint与幂等不漏双计。
- **§15-F · 直接失败变异：** 漂移OFFSET漏行或重跑覆盖新数据→失败。
- **§15-N · 合法邻例：** 可证明静态快照可用对应游标。

### §16 双写、CDC 和投影对账
**机制：** 需要双写时明确权威源、事务/Outbox 边界、CDC 位点、重复与乱序处理、下游落后和切换条件；不能将两端 API 回执视为跨库原子性。

**验收：** 断链、消息重投和源读对照中可补齐并确认缺失记录。

**§16 核验合同**

- **§16-P · 输入/动作与合格判据：** 双写/CDC断链/重复与源对照→唯一权威和切换水位明确。
- **§16-F · 直接失败变异：** 两端ACK当跨库原子→失败。
- **§16-N · 合法邻例：** 单源事务Outbox可作接线。

### §17 约束、索引和兼容默认值
**机制：** 启用唯一、非空、FK、默认值前核对历史数据和当前写入者；数据库版本决定 NOT VALID/并发建索引等能否使用。

**验收：** 历史脏数据和旧版本客户端不会被提前启用的新约束意外中断。

**§17 核验合同**

- **§17-P · 输入/动作与合格判据：** 旧writer/脏历史启新约束→合法兼容或先修复。
- **§17-F · 直接失败变异：** 新NOT NULL提前阻断受支持旧写→失败。
- **§17-N · 合法邻例：** 引擎支持的延迟验证可按实际条件用。

### §18 不可逆变换及有损恢复
**机制：** 把删除、精度截断、不可逆编码和受密钥限制的数据与可无损逆迁移分开，标注最后可逆时点、损失对象与权利批准。

**验收：** 不声称代码回退会自动恢复被破坏的数据。

**§18 核验合同**

- **§18-P · 输入/动作与合格判据：** 删除/精度截断/密钥限制恢复→最后可逆点与损失明确。
- **§18-F · 直接失败变异：** 代码回退宣称恢复已删数据→失败。
- **§18-N · 合法邻例：** 无损可逆迁移可按测试逆转。

### §19 配置、Flag 与动态业务行为
**机制：** 配置协议、缺省行为、开关取值、灰度分组和各版本读写依赖受版本约束；关闭 Flag 不撤销既有持久写入。

**验收：** 旧新进程和切换/回退后使用正确的配置组合且可解释。

**§19 核验合同**

- **§19-P · 输入/动作与合格判据：** Flag/配置新旧混跑→默认值和业务行为一致。
- **§19-F · 直接失败变异：** 关Flag就声称持久数据撤回→失败。
- **§19-N · 合法邻例：** 发布代码但不开功能是合法不同状态。

### §20 凭据、证书和密钥轮换
**机制：** 保留必要的合法重叠窗口、撤销与历史密文恢复条件；不得因紧急回退扩大用户权限或让旧密钥泄露进入输出。

**验收：** 旧密文可在许可范围读取，失效凭据被拒。

**§20 核验合同**

- **§20-P · 输入/动作与合格判据：** 轮换/撤销/旧密文恢复→合法重叠与禁止新用分开。
- **§20-F · 直接失败变异：** 紧急回滚恢复已泄露密钥权限→失败。
- **§20-N · 合法邻例：** 允许历史解密不等于允许旧凭据发新写。

### §21 运行时及基础设施兼容
**机制：** 核对容器镜像、OS、驱动、数据库、网络代理、消息服务和调度器实际版本；不将单一云产品功能变成所有项目默认前提。

**验收：** 混合部署和重启时依赖协议、资源约束仍成立。

**§21 核验合同**

- **§21-P · 输入/动作与合格判据：** 实际OS/代理/Broker/驱动混跑→资源与协议约束不变。
- **§21-F · 直接失败变异：** 单云产品能力泛化全平台→失败。
- **§21-N · 合法邻例：** 单平台可按明确支持范围。

### §22 浏览器/移动和离线客户端
**机制：** PWA、Service Worker、缓存、移动安装包和排队离线请求可能跨越多次服务器升级；对不支持版本提供明确拒绝或迁移。

**验收：** 恢复联网必须重新验证身份、数据版本和幂等业务操作。

**§22 核验合同**

- **§22-P · 输入/动作与合格判据：** 离线旧客户端恢复→当前身份/数据版/原意图重核。
- **§22-F · 直接失败变异：** 服务已升级就假设客户端全升级→失败。
- **§22-N · 合法邻例：** 不支持旧版可安全拒绝并给有权迁移。

### §23 在途 HTTP/RPC/流连接
**机制：** 切换时考虑长上传、RPC stream、WebSocket/SSE、事务和外呼的排空、超时未知提交、取消及重新连接。

**验收：** 重连/重试不能重复收费、丢失在途合法任务。

**§23 核验合同**

- **§23-P · 输入/动作与合格判据：** 在途上传/流/外呼切换→排空或交接且结果可查。
- **§23-F · 直接失败变异：** 连接断开即重建新业务意图→失败。
- **§23-N · 合法邻例：** 可取消只读流可按合同重开。

### §24 后台作业与租约所有权
**机制：** 旧新 Worker 交接需明确 checkpoint、fencing、租约过期、终止和恢复条件；不能在同一业务副作用上存在两个获准写入者。

**验收：** 杀进程和并发恢复均不能造成双重处理。

**§24 核验合同**

**必要机制补充：** 执行世代只有在目标写入/效果边界被验证才构成栅栏：先原子安装新世代，再允许新执行者写入，旧世代检查与写入处于同一受控原子边界。本地租约到期、取消请求发出、Worker进程失联或代理断开都不证明旧在途操作已停止；已发外部操作仍按原意图查询。

- **§24-P · 输入/动作与合格判据：** kill旧Worker并新Worker接管→checkpoint及目标fence有效。
- **§24-F · 直接失败变异：** lease失效当旧远端写必停→失败。
- **§24-N · 合法邻例：** 不同业务对象当前Worker可并行。

### §25 渐进暴露策略
**机制：** 按风险使用小流量金丝雀、蓝绿、分批或直接替换，定义每阶段地域、租户、用户和成本；避免强制购买多套资源。

**验收：** 每阶段放量与停止可由项目批准标准和实际数据证实。

**§25 核验合同**

- **§25-P · 输入/动作与合格判据：** 小流量/蓝绿/直接替换的阶段门禁→风险和成本可证。
- **§25-F · 直接失败变异：** 盲目扩大样本或强制所有项目多套资源→失败。
- **§25-N · 合法邻例：** 可逆静态变更可简单直接发布。

### §26 路由粘性与共享权威
**机制：** DNS、网关、客户端缓存、租户粘性和同一数据库权威要协同；跨版本随机路由不能造成交易含义或身份授权混乱。

**验收：** 真实入口、处理实例与持久写入可按租户/版本关联。

**§26 核验合同**

- **§26-P · 输入/动作与合格判据：** DNS/网关/客户端混路由→同租户同权威语义一致。
- **§26-F · 直接失败变异：** 粘性代共享业务状态或旧区双写→失败。
- **§26-N · 合法邻例：** 无状态兼容版本可随机路由。

### §27 部署就绪与业务完成
**机制：** 区分进程存活、Readiness、Deployment Progressing、健康接口、客户业务入口及异步终态；Kubernetes ProgressDeadlineExceeded 并不自动回退代码/数据。

**验收：** 发布成功不能只凭 Pod Ready、HTTP 200 或绿色 CI 判定。

**§27 核验合同**

- **§27-P · 输入/动作与合格判据：** PodReady但异步业务失败→部署和履约分别判。
- **§27-F · 直接失败变异：** ProgressDeadlineExceeded冒自动代码数据回退→失败。
- **§27-N · 合法邻例：** 平台报告停滞后可由明确策略另行恢复。

### §28 SLI/SLO 与样本偏差
**机制：** 按相邻规范可观测性规范使用真实成功分母、尾延迟、低流量、失效数据与灰度群体；第三方操作的成功以其权威结果判断。

**验收：** 不同版本/地区的分母和采样条件可重算。

**§28 核验合同**

- **§28-P · 输入/动作与合格判据：** 灰度低流量/样本缺口→分母和版本准确。
- **§28-F · 直接失败变异：** 新版本只统计成功样本→失败。
- **§28-N · 合法邻例：** 不足样本可保持未定而不伪造显著性。

### §29 继续、停止与回退决定
**机制：** 为每阶段定义进度、重大失败、健康缺失、未知提交后的暂停和恢复门禁；未经授权不得自动删除生产数据或退款。

**验收：** 阻断时能准确保留已执行副作用及未完成任务。

**§29 核验合同**

- **§29-P · 输入/动作与合格判据：** 触发停止/未知提交→保留已发生效果和欠处理。
- **§29-F · 直接失败变异：** 自动退款/删数据超出真实授权→失败。
- **§29-N · 合法邻例：** 满足既定标准可继续可逆步骤。

### §30 遥测迁移与独立探测
**机制：** 发布可能同时改变指标名字、采样、日志和采集器，需保留关键路径的独立探测与监测新鲜度。

**验收：** 监测故障不能被解释为零错误。

**§30 核验合同**

- **§30-P · 输入/动作与合格判据：** 发布同时改监测名/Collector→独立探针发现盲区。
- **§30-F · 直接失败变异：** 没数据解释成零错误→失败。
- **§30-N · 合法邻例：** 保留兼容双报可短期迁移。

### §31 多流程并行写入隔离
**机制：** 同环境 Schema 迁移、回滚、Flag、切流及业务恢复必须具备唯一所有者、条件更新或有效互斥；不能依靠时间猜测顺序。

**验收：** 重复执行幂等，冲突操作安全拒绝并记录。

**§31 核验合同**

- **§31-P · 输入/动作与合格判据：** 并发Schema/Flag/回滚→条件互斥或唯一所有者。
- **§31-F · 直接失败变异：** 按固定等待猜顺序导致互覆→失败。
- **§31-N · 合法邻例：** 不同隔离资源可合法并行变更。

### §32 代码与配置回滚条件
**机制：** 旧制品与旧配置须真实存在且与新 Schema、新消息、新客户端仍兼容，故障新代码可通过受控方式恢复旧版。

**验收：** 制品回退与数据状态分别验收。

**§32 核验合同**

- **§32-P · 输入/动作与合格判据：** 旧包/旧配置配新数据→回退前兼容验证。
- **§32-F · 直接失败变异：** 仅镜像回退便宣布全部状态复原→失败。
- **§32-N · 合法邻例：** 安全只读兼容恢复可代全回滚。

### §33 数据与持久状态回退边界
**机制：** DDL、数据批次、任务状态和外部调用不能随镜像回滚；依据已发生变换选择保留兼容、逆迁移、前滚修复或受控 PITR。

**验收：** 回退后仍改变的状态和不可逆损失可列明。

**§33 核验合同**

- **§33-P · 输入/动作与合格判据：** 持久数据/任务/外呼独立核对→回退残留与损失可列。
- **§33-F · 直接失败变异：** DDL/消息/外部动作随代码自动撤回→失败。
- **§33-N · 合法邻例：** 不可逆情况可前滚修复。

### §34 前滚修复、Saga 与合法补偿
**机制：** 对业务已发生的副作用，只能由对应事务/工作流/商业领域定义补偿、撤销、退款或人工处理；不得无依据重试未知提交。

**验收：** 领域幂等键、外部确认、授权与退款账本可分开核对。

**§34 核验合同**

- **§34-P · 输入/动作与合格判据：** 补偿先查原意图与外部结果→自身幂等和授权成立。
- **§34-F · 直接失败变异：** 未知提交直接补发/退款→失败。
- **§34-N · 合法邻例：** 确认原动作未发生时可不补偿。

### §35 备份、日志链和 PITR 依赖
**机制：** 备份包含实际数据、配置及解密/恢复依赖；PostgreSQL 18 的 PITR 需要基础备份与连续 WAL，pg_dump 逻辑导出不能直接用于 WAL 回放。

**验收：** 备份介质可读取、校验并实际恢复到目标点；RPO 受实测限制。

**§35 核验合同**

- **§35-P · 输入/动作与合格判据：** 基础备份+连续WAL+密钥实际恢复→目标点可验。
- **§35-F · 直接失败变异：** pg_dump当可直接WAL回放的基础备份→失败。
- **§35-N · 合法邻例：** 逻辑导出可用于其实际支持的逻辑恢复。

### §36 跨系统恢复点与写入冻结
**机制：** DB 恢复点不自动包含 Broker 位点、对象存储、第三方支付、客户缓存和密钥变化；必须定义各权威系统一致性水位与恢复顺序。

**验收：** 恢复后核对业务对象、外部结果和未处理消息。

**§36 核验合同**

- **§36-P · 输入/动作与合格判据：** DB/Broker/对象/密钥跨系统恢复点→各水位和写入冻结明确。
- **§36-F · 直接失败变异：** 恢复DB就称第三方支付也回旧时刻→失败。
- **§36-N · 合法邻例：** 独立系统可不同截点但必须有补齐对账。

### §37 恢复重放、Inbox/Outbox 与补齐
**机制：** 恢复后消息位点可能超前或落后，依原 Inbox/Outbox、任务 checkpoint、业务键和第三方回执处理重复/遗漏。

**验收：** 重放不能重复实际已完成交易，遗漏任务有恢复路径。

**§37 核验合同**

**必要机制补充：** Outbox记录与产生它的领域修改在同一实际数据库事务中一起提交/回滚；后续发布确认与消费者提交不在该事务内，允许重复发布但不允许静默丢失。Inbox唯一键至少区分租户、业务消费范围和源事件身份；去重登记、目标本地业务修改及需要产生的下一步Outbox在同一实际事务完成。外部付款/发信不被该本地原子边界包围，须继续使用目标接受的意图键、收据与未知结果核对。

- **§37-P · 输入/动作与合格判据：** 恢复后offset前后偏移→Inbox/Outbox/业务键补漏去重。
- **§37-F · 直接失败变异：** 旧快照重放已发通知/扣费→失败。
- **§37-N · 合法邻例：** 纯投影可隔离副作用后重建。

### §38 外部不可逆履约
**机制：** 资金操作、发送邮件、Webhook、物理控制、第三方订单不能因本地快照恢复而消失；超时必须先查对方权威再行动。

**验收：** 重复扣款、重复通知与错误对外承诺被阻止。

**§38 核验合同**

- **§38-P · 输入/动作与合格判据：** 外部邮件/订单/物理效果存在→权威回读且欠义务不消失。
- **§38-F · 直接失败变异：** 本地还原快照就认为外部事实没发生→失败。
- **§38-N · 合法邻例：** 不可逆事实可经真实有权新动作补偿。

### §39 隔离恢复演练与 RTO/RPO
**机制：** 按风险和成本在独立环境验证制品、介质、WAL/日志链、密钥、租户隔离、业务断言和切流；恢复时间/损失目标由授权主体批准。

**验收：** 实际计时和数据校验结果支撑指标，不用模拟环境冒充生产恢复。

**§39 核验合同**

- **§39-P · 输入/动作与合格判据：** 隔离恢复演练计时/校验→实测RTO/RPO和边界。
- **§39-F · 直接失败变异：** 模拟进度条冒生产恢复能力→失败。
- **§39-N · 合法邻例：** 有限本地恢复只声称其真实覆盖。

### §40 事故处置与发布中断
**机制：** 记录确认的用户影响、时间线、故障及监测缺口、止损和未完成业务；安全事件可借鉴 NIST SP 800-61r3，非所有运维事故均适用安全合规要求。

**验收：** 事实与假设分开，恢复/剩余责任可追踪。

**§40 核验合同**

- **§40-P · 输入/动作与合格判据：** 事故中断发布→时间线/影响/未知/遗留保留。
- **§40-F · 直接失败变异：** 清空失败证据或泛称全部安全合规→失败。
- **§40-N · 合法邻例：** 非安全运维事故不强套NIST安全义务。

### §41 迁移期隐私、租户和最小权限
**机制：** 临时脚本、视图、备份、旧客户端、日志及导出仍需遵守原始数据权利和隔离；紧急恢复不得绕过安全控制。

**验收：** 旧链接、跨租户和回退数据导出均执行完整授权检查。

**§41 核验合同**

- **§41-P · 输入/动作与合格判据：** 旧链接/备份/临时脚本/导出→原租户数据权持续。
- **§41-F · 直接失败变异：** 紧急恢复绕过对象授权→失败。
- **§41-N · 合法邻例：** 有权匿名合成数据可用于隔离演练。

### §42 发布证据和追溯记录
**机制：** 记录真实执行者、目标环境、制品、配置、Schema、回填批次、门禁、受影响客户、外部回执和恢复选择；技术日志仅向授权角色开放。

**验收：** 可由单一业务对象追查实际版本与事件链。

**§42 核验合同**

- **§42-P · 输入/动作与合格判据：** 业务对象追到制品/配置/批次/回执→证据链匹配。
- **§42-F · 直接失败变异：** 一个可读版本号冒所有实际资源→失败。
- **§42-N · 合法邻例：** 最小必要技术证据可存原权威系统。

### §43 第三方弃用与迁移通知
**机制：** 实际存在客户/SDK/外部集成时按合同通知新旧语义及迁移期限；RFC 9745 为 Standards Track，RFC 8594 Sunset 为 Informational。

**验收：** 通知按有权受众发出，弃用标头不替代真实服务退出。

**§43 核验合同**

- **§43-P · 输入/动作与合格判据：** 旧客户/SDK迁移通知→受众和语义期限正确。
- **§43-F · 直接失败变异：** 标头当已实现替代或已发通知→失败。
- **§43-N · 合法邻例：** 无外部受众的内部变更可简化通知。

### §44 客户最终结果与遗留任务
**机制：** 滚动更新完成、故障告警解除不代表外部结算、异步履约和历史请求全部成功；应分开记录已完成、未知和待补偿。

**验收：** 真实最终结果与剩余工作可审计，客户不接收内部诊断。

**§44 核验合同**

- **§44-P · 输入/动作与合格判据：** rollout完成但欠结算→客户真实终态单列。
- **§44-F · 直接失败变异：** 解除告警便清全部未知订单→失败。
- **§44-N · 合法邻例：** 确认无遗留可按权威事实收尾。

### §45 旧版本退役与保留
**机制：** 删除旧字段、Flag、密钥、制品和迁移数据前确认长期客户端、旧队列、恢复备份及合法保留需求结束。

**验收：** 不清除仍支持恢复、审计或法律义务的证据。

**§45 核验合同**

- **§45-P · 输入/动作与合格判据：** 删旧列/密钥/制品前查旧队列/备份/客户端→保留闭包齐。
- **§45-F · 直接失败变异：** 只看在线进程就删恢复依赖→失败。
- **§45-N · 合法邻例：** 支持窗结束且义务已处理可正式退役。

### §46 峰值资源、成本与复盘
**机制：** 并行实例、双写、回填、备份、日志、外部 API 费用和故障余量各自预算；复盘将确认的根因对应到技术回归。

**验收：** 容量、性能、正确性与真实费用分别验收。

**§46 核验合同**

- **§46-P · 输入/动作与合格判据：** 双实例/回填/备份峰值→费用、性能、正确性各过门禁。
- **§46-F · 直接失败变异：** 优化只看吞吐而隐藏外部费用→失败。
- **§46-N · 合法邻例：** 无需双写的变更不制造额外成本。
