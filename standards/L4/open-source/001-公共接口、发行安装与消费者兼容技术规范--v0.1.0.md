# L4 公共接口、发行安装与消费者兼容技术规范

**文档ID：** STD-L4-OPEN-SOURCE-001　**版本：** 0.1.0　**状态：** adopted　**生效日期：** 2026-10-30

## 范围与身份

本专题深化[基线](002-开源项目与公共技术生态领域通用基线--v0.1.0.md)M01、M05—06、M09、M12—13、M16。公共接口包括库API/类型、CLI输出/退出码、配置、文件/数据格式、ABI、插件协议及文档承诺；仅有编译通过不能证明消费者兼容。不要求只发行源码的项目提供全平台二进制。[L3 v0.1.0](../../L3/001-通用工程规范--v0.1.0.md)用于一般交付接口。

必须/不得为必要条件，应为建议，可为选择。源码、标签、制品、索引条目、实际下载/安装和运行身份分别记录；同名称/版本不自动同字节。可复现性是声明输入/环境下可比较的性质，不证明来源可信、无漏洞或许可权利。

## 逐条合同

### OSS-R01 公共承诺、版本与支持矩阵

**对象与责任：** 维护者定义公共/实验/私有接口及支持版本，发行者核版本号与实际变更；消费者测试者按旧真实任务验证。

**输入/输出/权威：** 输入为API/CLI/配置/数据/ABI和运行时/平台矩阵、变更差异、弃用/迁移规则；输出为兼容判断、版本与支持声明。实际旧消费者行为和已发布承诺是权威，版本数字本身不证明兼容。

**必要机制与不变量：** 采用SemVer2.0.0时先声明公共API；已发布同版本内容不得改动，兼容修复/新增/破坏按原规则增patch/minor/major；0.y.z与预发行的性质按原文，不把build metadata当优先级。未采用SemVer可用另一明确规则，不静默误导支持范围。[O01]

**失败、并发、超时与恢复：** 发现仍承诺旧平台失败要保留，不从矩阵删项凑绿；撤销支持有生效版本/期限/迁移说明，不追改旧发行承诺。多分支并行修复各绑准确提交/制品，不把主干通过套旧分支。

**兼容：** 实验接口按明确先前规则可以变化；破坏升级可合法但必须正确版本/迁移。兼容不是要求所有历史用户永久无改动，范围由可核承诺限定。

**验收与产物：** T-OSS-CONSUMER以支持矩阵中的旧消费者/配置/数据与新制品运行正反任务，核实际行为和文档；破坏接口必须被差异审查识别。产物为矩阵分母、消费者身份、版本判据与未覆盖。

**正例 / 直接失败 / 合法邻例：** 正例为minor新增而旧任务仍成功；直接失败为patch删除公共函数；合法邻例为已明确不稳定私有接口变化不误判公共破坏。

**来源：** O01 SemVer2.0.0条款1、3—11；运行矩阵与兼容任务为组织合成。

### OSS-R02 不可变发行、渠道加工与消费身份

**对象与责任：** 发布者核命名空间/权限，渠道适配者核加工产物，消费者核实际下载/安装；文档维护者不得把上传受理当消费者可用。

**输入/输出/权威：** 输入为准确源码revision、构建输入、平台/架构、版本、制品摘要/证明、渠道条目和镜像关系；输出为上传/索引/下载/安装/运行各阶段结果。真实下载/运行字节是权威，可移动tag或网页徽章不是。

**必要机制与不变量：** 同版本更正发行新版本，不静默替换制品/重用旧签名或测试回执。渠道重签/重打包/安装加工时保存前后身份和对应消费信任验证；索引/缓存/镜像延迟可见。撤回说明风险和可获得替代，不声称已删所有消费者副本。

**失败、并发、超时与恢复：** 上传超时先查原渠道对象/摘要，不能盲重发制造同版本异字节；并发发行有命名空间准入。签后变化、错架构或缓存旧制品拒绝当前通过；保留失败与差异，不覆盖原制品。

**兼容：** 合法独立分支有独立身份/命名空间与承诺，不必须冒官方渠道；只源码发行明确安装责任/工具链，不伪列二进制覆盖。

**验收与产物：** T-OSS-INSTALL对精确制品做干净目录安装/运行，模拟同tag异commit、同version异digest、旧缓存与错架构；读取下载digest、安装文件/入口与运行版本。合法新版本单独验，旧证据不漂移。

**正例 / 直接失败 / 合法邻例：** 正例为消费端摘要与发行证明一致；直接失败为上传成功就宣称所有架构可用；合法邻例为第三方分支明确新身份独立发行。

**来源：** O01条款3仅支持SemVer采用时同版本不可变；制品加工/渠道阶段为组织合成，来源验证复用构建专题。

### OSS-R03 依赖安装、卸载与最小可用入口

**对象与责任：** 发行/平台适配负责人定义安装前置、权限、依赖/原生ABI和更新/卸载；测试者在真正干净消费者环境执行。

**输入/输出/权威：** 输入为制品摘要、支持系统/架构/运行时、依赖来源/锁、安装参数与已有版本/数据；输出为可用入口、失败状态、更新/卸载残余。实际安装日志/文件/进程行为为权威，不以包索引接受或import单项通过替代全部任务。

**必要机制与不变量：** 安装步骤以声明最小权限执行，外部脚本与下载范围明确；干净/已有版本/受限目录分别可判。更新保护用户数据并核程序/格式组合，卸载的保留/删除边界明确，不能广泛删除家目录。自动更新必须验证消费身份与信任策略，不因渠道相同绕过。

**失败、并发、超时与恢复：** 中断、空间不足、依赖缺失/ABI错和并发安装有可恢复路径；重复执行不破坏既有数据，不把残留半安装判成功。返回失败需有可用诊断，恢复沿原安装身份而非随机覆盖。

**兼容：** 单平台可只声明已支持平台；无安装步骤独立可执行文件仍核真实入口。离线安装可以使用获准同内容镜像，不强制账户/联网。

**验收与产物：** T-OSS-INSTALL执行干净安装、升级、缺依赖、非ASCII/空格路径、只读目录、中断/恢复和卸载；保存版本/入口、stdout/stderr/exit及前后文件清单。成功任务与拒绝侧用户数据保持并核。

**正例 / 直接失败 / 合法邻例：** 正例为精确制品在支持平台最小权限安装可运行；直接失败为半安装退出0或卸载误删用户文档；合法邻例为只提供源码的项目准确要求用户构建而不虚称二进制安装。

**来源：** 组织合成消费者工程合同，不将包管理器返回码推导全部支持平台成功。

### OSS-R04 可复现目标与差异解释

**对象与责任：** 构建负责人声明位级/规范化/功能等价的复现目标、允许变化和环境输入；独立重构者保留原件和比较算法。

**输入/输出/权威：** 输入为源码/依赖/工具/配置/环境、原始制品及允许变换；输出为原始diff、规范化diff与有限结论。未修改原件的字节比较和可解释差异是权威，不以删差异后哈希相同证明源到制品。

**必要机制与不变量：** 时间戳、路径、随机种子、签名等影响分别说明；允许变换必须先定义且不移除真实代码差异。两次相同只证明该输入/环境范围下相同，不证明可信构建或无后门；不同输出不能直接假称恶意，未知差异保留。

**失败、并发、超时与恢复：** 缺输入/工具版、重构失败或时间预算不足标未复现；不改原件/旧日志获得绿灯。并行重构环境各自记录，不把共享缓存同源输出当独立环境证据。

**兼容：** 明示未达位级复现但完整解释差异可交有限结论，不硬性拒绝所有签名时间变化；功能兼容须独立任务测试，不能由二进制diff反推。

**验收与产物：** T-OSS-REBUILD两干净环境按固定输入构建，`sha256sum "$A" "$B"`、`cmp "$A" "$B"`与固定版本二进制差异工具保留原差异；注入真实代码差异必须被识别，合法已定时间字段变化不能误称代码改变。

**正例 / 直接失败 / 合法邻例：** 正例为位级相同且仅声称该范围；直接失败为删所有变动区后宣称证明一致；合法邻例为明确解释签名时间差但不声称位级复现。

**来源：** 组织合成，不从SLSA证明存在推导可复现性或反之。

### OSS-R05 文档与示例的版本化可执行性

**对象与责任：** 文档维护者绑定相应发行/支持范围，示例作者限制数据/权限；发布者对生成页面与源码引用一致负责。

**输入/输出/权威：** 输入为安装/快速开始/API/迁移/支持文档、示例文件与准确依赖/环境；输出为可复现任务和失败/不适用说明。实际命令输出/链接目标与发行身份是权威，页面存在不是示例通过。

**必要机制与不变量：** 示例以合成数据和最小权限，危险/不可逆操作不得伪装快速开始默认；输出/错误/清理步骤与版本一致。生成文档改变后重新验实际产物，不能只测源码片段。说明外部服务/网络前提及离线行为，不隐含实际账号/费用权限。

**失败、并发、超时与恢复：** 安装/网络失败给可判终点与重试/清理，不让示例污染用户目录；外部输出作数据而非高权指令。旧版本文档保留范围，不静默指向不兼容新API。

**兼容：** 无凭据只读例可独立运行；明确需服务示例可保持not-run，不以伪输出冒成功。支持缩减按既有承诺/版本决议说明，不删失败以缩矩阵。

**验收与产物：** T-OSS-DOC在干净工作目录逐条运行准确版本示例和错误输入，核输出/exit、文件副作用与本地链接；生成站点对同发行复验。保留成功/原失败、工具版和未运行服务接口。

**正例 / 直接失败 / 合法邻例：** 正例为固定版本合成只读快速开始可复现；直接失败为旧示例无警告删除用户数据；合法邻例为准确声明外部服务前提且未运行的示例不被写成通过。

**来源：** 组织合成；实际包/API使用规则由L5固定官方文档，文字存在不证明运行。

## 真实执行入口（not-run）

T-OSS-CONSUMER：固定矩阵逐消费者运行其真实命令/测试入口，并保留旧制品/配置/数据。T-OSS-INSTALL：选定Python wheel的例子为 `python3 -m venv "$CLEAN_VENV"`、`"$CLEAN_VENV/bin/python" -m pip install --no-index --no-deps "$WHEEL"` 后调用真实入口；它只适用于已准备全部依赖/支持Python，不是所有生态通用验收。其他生态在L5给准确离线安装/卸载命令与原生ABI检查。T-OSS-REBUILD用项目原生构建入口与上述hash/cmp；T-OSS-DOC执行文档中真实命令但先绑定隔离目录/合成数据/最小权限，外部服务部分单列未执行。所有场景记录工具版、stdout/stderr/exit、精确制品摘要及前后文件/网络效果。

本包本地模型只检查合成元数据/图与有限兼容条件，不安装或发行真实包。[来源](../../../sources/open-source.md)、[模型边界](../../../examples/security-edge-commerce/README.md)。
