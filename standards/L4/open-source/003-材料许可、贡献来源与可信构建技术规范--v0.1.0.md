# L4 材料许可、贡献来源与可信构建技术规范

**文档ID：** STD-L4-OPEN-SOURCE-003　**版本：** 0.1.0　**状态：** adopted　**生效日期：** 2026-10-30

## 范围、非目标与术语

本专题深化[基线](002-开源项目与公共技术生态领域通用基线--v0.1.0.md)M02—03、M07—11。源码、文档、图像/字体、数据/模型、嵌入依赖、构建脚本、生成物分别是材料；公开可读不是许可。签名说明某材料的签发/完整性证据，不证明无漏洞或发行权。必须/不得为适用必要条件，应为建议，可为选择；不强制无依赖小工具建立包平台，不提供法律意见或SLSA/SPDX认证。[L3 v0.1.0](../../L3/001-通用工程规范--v0.1.0.md)规定一般材料/制品身份。

`material_id`绑定作用域与字节；`source_revision`不以可移动分支/标签替代；`artifact_digest`是实际消费制品的摘要。`NOASSERTION`是没有作断言，不等同`NONE`确认没有；源级、构建态、发行态和安装态清单范围分别声明。

## 逐条合同

### OSS-B01 材料作用域、许可文本与发行边界

**对象与责任：** 材料接收/发行负责人登记来源与声明，权利所有者/有权专业主体判断实际可用范围；扫描器不代替授权者。

**输入/输出/权威：** 输入为材料路径/字节、源入口/版本、作者/供应方声明、许可标识与准确文本、例外/NOTICE及用途；输出为逐材料可追溯清单、已决定范围与未决项。实际材料声明/许可文本及有权决定是权威，仓库根LICENSE不覆盖明确另授或未知材料。

**必要机制与不变量：** 对源码、文档、图片/字体、数据/模型及打包依赖分别核作用域；根许可只按其可证覆盖范围引用，不把可读、下载或被提交当再许可。缺文本、冲突或来源未知材料在发行边界隔离，保留调查事实；不为消除未知擅改第三方声明。生成物说明输入材料与工具条件，不能从生成者名字推导完整权利。

**失败、并发、超时与恢复：** 材料更新/移动/打包重跑作用域匹配，路径通配冲突显式拒绝；权利变更/撤回与历史副本另列。恢复旧版本不得重新带入已排除材料，不能用删历史证据“解决”冲突。

**兼容：** 合法混合许可可清楚分离，项目无需统一再许可；纯内部候选未获发行决定不因此公开。许可证标识扫描只证明标识匹配，不能证明法律兼容。

**验收与产物：** T-OSS-MATERIAL对根许可+异授图标、缺文本、重叠作用域、合法分离材料和重新打包输入核逐材料/发行文件映射；未知不被自动填根许可，合法混合材料保留。产物为原声明引用、文件摘要、范围决定及未决清单。

**正例 / 直接失败 / 合法邻例：** 正例为每材料有自己的可追许可范围；直接失败为根MIT覆盖另授字体；合法邻例为源码与文档不同许可但范围清楚且有权确认。

**来源：** 组织合成技术追溯要求；不声称SPDX标识或根许可存在本身给出法律权利。

### OSS-B02 贡献来源与变更接受

**对象与责任：** 贡献者说明来源/作者关系，接收者按项目已声明贡献条件审核实际变更；代提交者不能仅凭自己签名替原作者授予权利。

**输入/输出/权威：** 输入为差异、贡献身份/代提交关系、复制/生成来源、适用许可/贡献声明和条件版本；输出为接受、补证、隔离或拒绝及理由。原变更与有效声明是权威，Signed-off-by字符串或有效提交签名不独立证明全部权利。

**必要机制与不变量：** 接受绑定精确差异，后续修订重新核新增材料；复制片段/生成输出沿材料链追踪。项目选择DCO1.1时按原文声明条件处理来源与提交权，不改写该证书或把其当所有贡献自动合法。可以采用相称轻量声明，不强制所有项目签同一CLA。[O04]

**失败、并发、超时与恢复：** 审核后差异改变使旧决定失效于变化部分；来源争议保留原件/讨论而限制未决材料进入发行。机器人/报告文本不授予接受者运行高权限代码的权利。

**兼容：** 小型文案/修复可按已定轻量流程，不能因无企业CLA一律拒绝；同一作者合法新修订有新差异身份，不错误按提交者名去重。

**验收与产物：** T-OSS-MATERIAL/DIFF核未知复制片段、代提交链断裂、审核后加文件与合法小修；接受范围与实际发行字节一致。保留来源映射、贡献条件版和变更决定，不把自审写独审。

**正例 / 直接失败 / 合法邻例：** 正例为准确差异及可追来源按条件接受；直接失败为“提交签名有效”代替复制来源核对；合法邻例为满足项目轻量条件的小修不强制额外协议。

**来源：** O04 Developer Certificate of Origin1.1(a)—(d)仅支持该自述条件，技术材料链为组织合成，不作法律充足性判断。

### OSS-B03 依赖解析、隔离构建与输入身份

**对象与责任：** 依赖/构建负责人确定命名空间/源优先级、锁解析、工具链和执行权限；发行者不能把不可信贡献测试环境提升为发行环境。

**输入/输出/权威：** 输入为直接/传递及构建/测试/运行依赖、锁文件、实际解析记录/摘要、平台/特性、安装脚本、缓存和工具链；输出为完整范围的实际输入清单与隔离构建产物。实际下载/执行字节与环境能力为权威，不是锁文件存在。

**必要机制与不变量：** 防同名/优先级混淆，锁定精确来源/版本/摘要且核实际解析一致；不可信脚本/工作流、缓存、工件都作输入，不能得到签名/发行/生产秘密。构建隔离声明网络/文件/身份与持久状态，禁执行未获准安装脚本；每次产物记录输入/工具/配置。

**失败、并发、超时与恢复：** 下载不全/摘要错/锁不一致拒绝；重试不能自动切未批准公共源或复用不可信缓存。构建中断保留失败，不以残留工件当成功；缓存键包含相关平台/配置/输入并按信任域隔离。

**兼容：** 合法离线镜像在身份/内容策略允许时可使用；无依赖工具可给空依赖清单。不同架构/可选特性解析可不同但各自完整，不把一个平台清单冒充全部发行。

**验收与产物：** T-OSS-BUILD注入源优先级污染、锁漂移、安装脚本读取合成秘密标记、缓存/工件替换和合法离线镜像；核真实输入摘要/外部能力、构建失败/成功与无秘密外发。

**正例 / 直接失败 / 合法邻例：** 正例为已批准离线源固定内容构建；直接失败为私有同名包从公共源解析或外部贡献读发行秘密；合法邻例为无秘密隔离测试外部贡献仍可完成。

**来源：** 组织合成，SLSA框架只为来源证明字段背景，不以框架名证明构建已隔离。

### OSS-B04 制品、来源证明与消费策略

**对象与责任：** 构建者产生证明，发行者关联制品，消费者使用预设信任策略核签发者/builder、来源和参数；产物不能自行定义哪些根可信。

**输入/输出/权威：** 输入为真实制品digest、签名envelope、subject、predicateType、builder.id、buildType、externalParameters与resolvedDependencies、消费者期望策略；输出为该制品有限来源验证结论或拒绝。预配可信根/期望与真实消费字节为权威。

**必要机制与不变量：** 采用SLSA v1.2 Build Provenance时固定predicate主版本URI，核签名/subject摘要、builder和允许来源/构建类型/外参。区分框架级别所需证据和证明自报字段；依赖列表未必完整，不因有resolvedDependencies就宣称供应链闭包。通用未知字段按该格式规则忽略，externalParameters中未知/非预期字段按消费策略拒绝，不能二者混淆。[O02]

**失败、并发、超时与恢复：** 签后替换、错subject/签发者/来源、信任撤销或验证失败不得降级成仅哈希通过。验证和实际安装消费绑定同一字节，TOCTOU则重新验证；撤回传播不保证已缓存副本消失。

**兼容：** SLSA次版本扩展与主版本破坏按原解析规则；没有声明SLSA等级时不强造等级证明。合法第三方分支以独立预设策略/新身份消费，不冒官方源。

**验收与产物：** T-OSS-PROVENANCE送错digest/builder/source/外参、合法新未知扩展字段及合法分支；核验证器实际返回和安装摘要，保留策略版与证明。合成布尔signed不等于真签名验证。

**正例 / 直接失败 / 合法邻例：** 正例为可信builder与准确subject满足期望；直接失败为攻击者自签同名包被接受；合法邻例为未知非安全扩展字段按格式忽略而已知核心仍验证，未知外参仍按策略拒绝。

**来源：** O02 SLSA v1.2 build-provenance Model/Parsing rules、verifying-artifacts§How to verify/Check expectations；组织选择的期望值和实际信任批准另列。

### OSS-B05 SBOM范围、未知与引用完整性

**对象与责任：** 清单生产者声明源/构建/发行/安装范围，消费者按所选格式解析并对照实际内容；许可结论与组件枚举完整性独立。

**输入/输出/权威：** 输入为所描述制品摘要、包/文件/关系、工具/时间与格式版；输出为可解析清单、范围比对及未知/缺项。实际包内容/构建输入与清单关系共同权威，不以schema通过代替完整性。

**必要机制与不变量：** 采用SPDX2.3.1时语法版本仍按其规定使用SPDX-2.3，文档namespace随文档新版本唯一；元素ID唯一，关系两端存在或合法外部引用。NOASSERTION不转成NONE；未知许可/供应方不从根许可猜补。多版本同包用不同元素ID，源级清单不冒充二进制嵌入依赖全表。[O03]

**失败、并发、超时与恢复：** 断引用/重复ID/错制品摘要拒绝当前绑定；缺组件/扫描失败列缺口，不伪填完整。重新打包/平台加工重新核真实内容，不能只沿用源码SBOM。保持旧清单身份与新差异。

**兼容：** 格式允许的未知扩展字段按所选解析规则处理，核心未知值保留不确定；不能以“所有未知都拒绝”误拒合法NOASSERTION，也不能忽略必要结构错误。外部文档引用核命名空间/摘要和作用域。

**验收与产物：** T-OSS-SBOM用缺组件、重复ID、断引用、错digest、多版本、合法NOASSERTION/NONE及外部文档夹具运行真实格式验证器，再对实际制品清单；结构通过但缺嵌入依赖仍失败于完整性范围。

**正例 / 直接失败 / 合法邻例：** 正例为实际发行依赖与有效引用对应；直接失败为只列顶层却称完整或把未知改无依赖；合法邻例为明示源级范围且保留NOASSERTION，不假称安装态完整。

**来源：** O03 SPDX2.3.1§6.1/6.5、§7.2/7.5/7.7、§11.1；发行完整性比对为组织合成。

## 实际工具合同（not-run）

T-OSS-MATERIAL/DIFF：`sha256sum "$MATERIAL"`核字节，项目逐材料清单与实际路径集合比对，真实权利解释由有权主体确认。T-OSS-BUILD：固定工具链与锁，分别在无秘密隔离目录/已批准离线依赖源构建；例如Python采用 `python3 -m pip install --no-index --find-links "$WHEELHOUSE" --require-hashes -r "$LOCK"` 只适用于已固定符合pip hash格式的全量依赖，并另外约束构建脚本/可执行能力，不以此自动证明沙箱。T-OSS-PROVENANCE：使用L5固定版本的真实证明验证器，输入 `artifact+provenance+trusted-roots+expected-source/buildType/params`，完整命令/签名方案在L6绑定；仅 `sha256sum "$ARTIFACT"` 不足。T-OSS-SBOM：用所选SPDX官方schema/验证器准确版本校验并导出实际包内容比对；本包自制图检查不声称完整SPDX合规。

本地模型入口 `python3 -m unittest discover -s tests -p 'test_sec_edge_commerce_models.py' -v`；模型仅检查显式列出的合成材料和有限条件，包解析、隔离构建、签名/来源验证、SPDX完整格式及发行权分别按本节真实目标入口验收。[来源](../../../sources/open-source.md)、[模型边界](../../../examples/security-edge-commerce/README.md)。
