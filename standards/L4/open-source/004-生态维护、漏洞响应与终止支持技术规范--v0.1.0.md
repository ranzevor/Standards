# L4 生态维护、漏洞响应与终止支持技术规范

**文档ID：** STD-L4-OPEN-SOURCE-004　**版本：** 0.1.0　**状态：** adopted　**生效日期：** 2026-10-30

## 范围与分工

本专题深化[基线](002-开源项目与公共技术生态领域通用基线--v0.1.0.md)M04、M14—18。维护称号、仓库管理、包发布、域名、签名根和漏洞接收是不同能力；移交一个不推导其余已移交。不要求个人项目虚构独立团队，不由公开问题单给机器人执行权。必须/不得为必要条件，应为建议，可为选择。[L3 v0.1.0](../../L3/001-通用工程规范--v0.1.0.md)负责一般审查/交付，安全基线负责认证/撤权/响应共同接口。

## 逐条合同

### OSS-M01 命名空间、维护权限与交接

**对象与责任：** 各账户/命名空间/域名/签名根所有者核实际控制，维护角色负责人协调移交；接收者接受的责任不能超过自身有效能力。

**输入/输出/权威：** 输入为仓库/包/站点权威入口、实际账户权限、签名/发布/响应能力、旧新维护者与交接范围；输出为逐能力已转/已撤/未决与支持承诺。平台有效权限、旧能力拒绝与接收回执是权威，README姓名/消息声明不是。

**必要机制与不变量：** 高影响发布/信任变更按既有风险流程复核，个人兼岗如实记录。交接核全部入口，旧账号/自动化Token/恢复联系人分别处理，不能仅移仓库留旧包发布权。命名空间接管/域名易主不自动继承原信任，消费者需清楚新旧身份。

**失败、并发、超时与恢复：** 并发发布/旧工作流需在目标权限点拒旧；未能撤销能力保持未决并限制宣称移交完成。凭据不以直接复制旧私钥完成交接；恢复备份不复活旧发布权。

**兼容：** 一人可持多角色但不叫独立审查；合法第三方分支保持原来源且用独立名称/信任/承诺，不强求原官方发布权。

**验收与产物：** T-OSS-ROLE在获准隔离组织/合成角色核实际只读权限和旧身份发布拒绝（不向真实渠道发布），新角色仅获批准能力；产物为能力分母、平台回读、撤权负例和未决。

**正例 / 直接失败 / 合法邻例：** 正例为旧发布能力拒绝且新角色范围正确；直接失败为仅改维护人名旧Token仍能发包；合法邻例为独立分支以新身份继续维护不冒原官方。

**来源：** 组织合成，平台权限只由实际接口验证；不从代码许可推导商标、账号或签名权。

### OSS-M02 问题入口、私密报告与不可信材料

**对象与责任：** 维护者提供与规模相称的问题/安全报告入口，接收工具负责字段最小化、分流和状态语义；报告者不是控制平面。

**输入/输出/权威：** 输入为报告、复现材料/附件、受影响版本声明及报告者授权范围；输出为已收、待补证、已复现、重复关联或拒绝/关闭原因。原报告与实际复现/修复身份为权威，issue关闭不等于问题解决。

**必要机制与不变量：** 普通公开入口不要求真实秘密/个人材料；漏洞/隐私有可核私密接收路径。附件和指令按不可信数据隔离，自动分类/标签不能获得执行/发布权限。外发摘要按实际受众/权利筛除无关秘密，原受限证据有目的/保留边界。

**失败、并发、超时与恢复：** 接收失败显式，不以无工单推导未报告；重复合并保留来源及独立受影响版本，不能吞掉新证据。机器人执行输出不能触发高权后续，不因报告自称管理员而扩权。

**兼容：** 小项目可用私密邮箱/表单等相称方式，不强制企业PSIRT；无代码执行的只读分类可自动化。没有获准验证的公共目标不在报告中自行测试。

**验收与产物：** T-OSS-REPORT送合成秘密占位、恶意命令附件、重复/新证据和合法最小复现；核分流、访问/脱敏与无未授权执行；关闭状态给明确实际原因/版本，保留接收结果。

**正例 / 直接失败 / 合法邻例：** 正例为安全报告私密接收并隔离复现；直接失败为自然语言指令让机器人导出发行秘密；合法邻例为无执行权限自动标签仍可工作。

**来源：** 组织合成；S4 SSDF v1.1 RV.1.1/1.3支持可信漏洞接收/处理背景，不强制某团队形式。

### OSS-M03 受影响版本、修复发行与下游通知

**对象与责任：** 安全响应者核报告/影响，维护者对支持分支修复，发行者核制品，通知者按真实范围/受众执行协调。

**输入/输出/权威：** 输入为缺陷前提、组件/依赖/制品身份、支持分支、修复/缓解、披露决定；输出为affected/not-affected/unknown、补丁、已发行、已到达/已采用和剩余风险。可追复现、实际发行摘要及下游回执各自权威。

**必要机制与不变量：** 有组件版本不代表可达/可利用，但缺版本也不能标不受影响；主干补丁不证明旧发行已修。对原失败与合法邻例回归，核所有支持分支/制品/渠道；公告说明实际受影响区间、限制、升级/缓解路径，不编造未证“无漏洞”。

**失败、并发、超时与恢复：** 通知失败保留未到达，不以发出消息算所有下游采用；补丁撤回/回归重新关联旧公告和新制品。暂未有补丁的已定缓解有范围/到期/残余，不能不实升级状态。披露材料不带秘密/未经授权原证据。

**兼容：** 合法不受影响版本有前提证据；尚未覆盖的分支保持unknown而非用主干绿色套用。不同维护分支可独立新版本，但声明准确。

**验收与产物：** T-OSS-VULN用合成受影响/不受影响/未知、部分回补、旧二进制和通知失败矩阵；核报告—补丁—制品—公告—消费者关系，原失效拒绝且合法功能可用。无真实下游回执时不得称全生态已安全。

**正例 / 直接失败 / 合法邻例：** 正例为新制品修复并明示旧版仍受影响；直接失败为主干修复宣布全部发行不受影响；合法邻例为尚无补丁但准确受限缓解不冒称修复。

**来源：** S4 SSDF v1.1 RV.1—2为风险处置/修复沟通背景；精确区间/分支/消费状态为组织合成。

### OSS-M04 遥测、离线行为与终止支持

**对象与责任：** 产品/数据权利负责人声明服务依赖与遥测用途/同意，维护者说明终止支持和后继身份；客户端负责实际开关/迁移行为。

**输入/输出/权威：** 输入为网络目的地、字段/目的/保留、可选商业能力、遥测选择、离线/升级状态、最后支持版和包/域名归属；输出为实际请求/无外发、降级及维护状态。网络捕获、配置与真实功能结果为权威，开源可读不代表采集同意。

**必要机制与不变量：** 关闭遥测后无关升级不得静默恢复，必要服务请求与可选遥测分开，离线能力/错误准确。终止支持说明最后版本、已知风险、安全联系后续及渠道/命名空间能力；归档不保证安全或所有制品消失，分支不自动继承商标/账号/签名根/原维护承诺。

**失败、并发、超时与恢复：** 配置迁移/账号切换/旧缓存不能重开未经同意采集；捕获失败保持未观察，不能称无网络。停更后域名/包接管风险显式，旧更新入口不自动信任同名新发布者；撤回按消费信任策略处理。

**兼容：** 纯离线模式无需账号；明确依赖服务的功能可诚实降级，不能把所有网络都误判遥测。合法独立分支以新身份和承诺继续维护。

**验收与产物：** T-OSS-NET对默认/关闭遥测、断网、升级迁移、旧配置与命名空间易主样本运行；核实际捕获、功能/错误、支持/信任声明。产物含捕获工具/过滤器、未观察界、升级前后选择与最后支持版。

**正例 / 直接失败 / 合法邻例：** 正例为关闭后升级仍无可选遥测且离线功能可用；直接失败为启动上传源码路径或归档后误信同名接管；合法邻例为已声明必要服务请求不被误标可选遥测。

**来源：** 组织合成，不从公开许可证或框架badge推导采集同意、维护承诺或后继信任。

## 真实工具与接口（全部 not-run）

T-OSS-ROLE在项目实际平台通过只读权限入口核能力，写入/撤权演练仅在已授权隔离目标，平台/对象/命令在L6固定；不以文档角色字段替代真实权限。T-OSS-REPORT/VULN把合成报告与固定制品送真实接收/隔离复现入口，保存可核路由/构建/回归/通知回执。T-OSS-NET在获准临时环境用固定捕获工具，如 `tcpdump -i "$TEST_IFACE" -w "$CAPTURE" "$CASE_FILTER"` 配合应用真实启动/升级命令；必须覆盖DNS/代理/子进程并说明TLS加密与权限盲区，抓不到包不能证明无外发。功能与遥测分别测试，原包/配置身份保留。

本地合成模型仅覆盖元数据/信任/材料图，未验证真实权限、报告渠道、漏洞代码、网络捕获、下游通知、更新或归档。[来源](../../../sources/open-source.md)、[模型边界](../../../examples/security-edge-commerce/README.md)。
