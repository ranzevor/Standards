# L4 密码协议、认证材料与会话撤销技术规范

**文档ID：** STD-L4-SECURITY-002　**版本：** 0.1.0　**状态：** adopted　**生效日期：** 2026-10-30

## 范围、非目标与术语

本专题补充[安全基线](001-安全工程与身份系统领域通用基线--v0.1.0.md)§06—20、§24—30，管理实际采用的密码协议、认证材料、会话与撤销控制点；不强制匿名工具引入账户，不重新定义 OAuth、TLS、密码算法，不提供安全认证或操作授权。[L3 v0.1.0](../../L3/001-通用工程规范--v0.1.0.md)提供通用工程接口。必须/不得为适用后的必要条件；应为可说明理由的建议；可与例子不增加要求。

`principal=(issuer, stable_subject, tenant)`，显示名不是主键；`authentication_time`为实际完成相应认证的时点，不是令牌刷新时间。签发、验证、对象授权、业务批准是四种事实。`revocation_epoch`是控制点确认安装的撤销代际，不是日志里期望的数字。秘密只通过非秘密引用标识。未知表示证据不能确定；未执行表示尚无目标运行。

## 逐条合同

### SEC-P01 密码协议画像与验证失败

**对象与责任：** 使用 TLS/DTLS 或加密存储的实现负责人建立算法/库/协议画像，验证者以消费端行为核对；不适用的离线明文公开材料不强制加密。

**输入/输出/权威：** 输入是具体协议版本、库构建身份、用途、可信根、算法参数、随机源及寿命上限；输出是允许组合、拒绝组合与迁移条件。协商跟踪和实际验证器结果是权威，配置文本不是实际启用证明。

**必要机制与不变量：** 不自造算法、拼接签名或把编码当加密。声明采用 RFC9325 时执行其适用规范性要求：不协商 SSL2/3、TLS1.0/1.1；协议支持与例外按该文§3.1.1，不将本体建议降为任意 L6 数字。AES-GCM 同密钥的 nonce 必须满足所用算法唯一性要求，进程重启、多写入者和备份恢复不得重用；密文必须绑定无二义的用途/对象 AAD，认证失败不向业务释放明文。算法密钥/消息用量限额由选定标准和实现画像共同固定。[S8][S9]

**失败、并发、超时与恢复：** 随机源失败、计数耗尽或可信根未知必须停止受影响签发/加密，不能重置计数续用旧密钥；已输出密文与未提交计数的崩溃窗口要通过预分配持久区间、独立密钥代际等机制闭合。验证异常不能回退至跳过证书检查。

**兼容：** 旧合法数据的解密与禁止旧算法新写分开；迁移可有有界双读但不能以可用性复活已撤销签发权。没有声称未来协议版本继承本画像。

**验收与产物：** 目标入口 T-SEC-TLS、T-SEC-CRYPTO（文末）分别保存完整协商、错误证书拒绝、密文/AAD篡改拒绝及 nonce 跨重启账；逐组合匹配所选规范，合法组合可用且被禁组合无应用数据。模型只检查身份与计数条件，不验证密码强度。

**正例 / 直接失败 / 合法邻例：** 正例是可信根与正确主机匹配的允许协议；直接失败是证书错误后改成不验证仍成功，或同密钥重用 nonce；合法邻例是同一 nonce 数值用于独立新密钥代际且符合算法画像，不被错误全局去重。

**来源：** S8 RFC9325§3.1.1、§4.1、§7.1；S9 RFC5116§2.1—2.2、§3.1/3.3。持久区间与迁移状态机为组织合成，依据是跨恢复不能破坏算法前提。

### SEC-P02 密码、尝试限制与恢复材料

**对象与责任：** 采用口令认证的验证器管理者负责策略，客户端不得自行放宽。采用 NIST SP800-63B-4 时必须满足其适用要求，未完整核相应 AAL 不声明 AAL 符合。

**输入/输出/权威：** 输入为认证用途（单因素或只用于 MFA）、规范化规则、口令/恢复材料的受控测试引用；输出为绑定/验证决定、失败计数和材料失效状态。权威为服务端验证器与认证器生命周期记录。

**必要机制与不变量：** 采用该版§3.1.1时单因素口令最少15字符，只有仅作为 MFA 组成部分才可降至最少8字符；不得附加字符组成规则或无泄漏依据的周期改密；按原文执行阻止常见/泄漏候选、带盐抗离线攻击存储、受保护通道和速率限制，不截断后再比较。建议支持至少64字符，Unicode按代码点计长且规范化由画像固定。§3.2.2在该认证器类型要求限流时，单订阅账户使用特定认证器的连续失败上限不得超过100，其他更严限制从严；达到所选上限必须禁用相应认证器，按§4.1重新绑定后方可再用，涉及多个过量尝试认证器时按原文同时禁用；不能只清零计数或将组织阈值设得更宽。恢复码不明文入日志，采用该版保存恢复码方法时至少64位合格随机源并按原文绑定一次性消费与通知。[S2]

**失败、并发、超时与恢复：** 并发失败计数必须以账户/认证器实际作用域聚合；并发兑换同一恢复码只允许一个有效绑定事务。计数存储失败不得当零次；恢复证据不足保持待核，不以姓名/邮箱控制替代。合法限流解除遵循选定恢复方法而非永久锁号。

**兼容：** 已有较弱口令不能被悄然截断或当已迁移；采用时记录迁移与重新绑定决议。无口令系统不引入象征性口令，机器凭据不能套用人为口令长度证明强度。

**验收与产物：** T-SEC-HTTP 对注册/绑定/验证/恢复端点分别送边界长度、常见口令、正常长Unicode、并发失败与恢复重放；从计数/认证器记录与新会话查询判定，拒绝侧不得产生新绑定，合法恢复后旧失效材料拒绝。

**正例 / 直接失败 / 合法邻例：** 正例为满足所选画像的长口令和一次有效恢复；直接失败为单因素8字符被接受或第101次连续尝试仍不受限制；合法邻例为只作 MFA 成分的8字符口令，不能因单因素阈值一律误拒。例中长度不是完整 AAL 认证结论。

**来源：** S2§3.1.1.2、§3.2.2、§4.2、§4.6；并发账与观察合同为组织合成。

### SEC-P03 联合身份与令牌验证的事务绑定

**对象与责任：** OAuth/OIDC 客户端、令牌验证器和资源服务器分别负责自身检查；不把 IdP 信任表交给请求方改写。

**输入/输出/权威：** 输入为固定协议、预配 issuer、键来源、client/audience、用途、回调、当前挑战和时间窗口；输出为经过验证的主体声明，再进入对象授权。发行者元数据、验证器和当前事务账为权威，不以 JWT 解码文本、前端成功值或签名存在作为通过。

**必要机制与不变量：** 先按用途限定算法/密钥及发行者，再验证签名、有效期、受众、事务和防重放；ID Token不能替代访问令牌。采用 RFC9700 的授权码公有客户端必须使用 PKCE；公有客户端刷新令牌必须发送者约束或轮换，不能把两者都省略。联合断言按63C-4检查目标RP；同sub跨issuer不合并，账号链接另核双侧控制。[S3][S5]

**失败、并发、超时与恢复：** 当前事务一次消费；多标签并发各保留挑战，旧响应不能绑定新事务。键轮换取键失败不是跳过验证理由；未知kid不能无限触发网络取键，缓存按身份/期限隔离。刷新轮换的响应丢失按提供者协议核对原链，不能无条件重开旧refresh链。

**兼容：** 支持发行者/协议版本并存时分别有配置与验证入口；新增受众和信任根属于安全变更。没有采用 OAuth 的机器协议使用自身认证合同，不强加浏览器回调。

**验收与产物：** T-SEC-HTTP 对真实验证入口送错issuer/aud/purpose、过期、旧挑战、错误kid及合法当前事务，观察服务器会话和资源结果；保存经过脱敏的判定原因、事务消费记录及无副作用证据。

**正例 / 直接失败 / 合法邻例：** 正例是预配发行者的正确用途令牌再访问有权对象；直接失败是合法签名的另RP断言获得当前资源；合法邻例为同发行者另一个被明确支持受众走其独立正确入口，不把所有多受众协议误拒。

**来源：** S3 §3.13 Assertion Protection与§4.9断言验证；S5§2.1.1、§2.2.2。键缓存限界与账号链接为组织合成。

### SEC-P04 认证器、会话与新鲜度

**对象与责任：** 认证器绑定者、IdP和每个RP会话控制者声明各自生命期、再认证和退出保证；客户端可见缓存由对应客户端负责清理。

**输入/输出/权威：** 输入为账户代际、认证事件时点、认证器状态、会话绝对/不活动截止和敏感动作要求；输出为继续、再认证、结束、未知下游。每个RP的会话存储与旧凭据请求结果为权威。

**必要机制与不变量：** 绑定/替换/移除必须证明当前账户控制和绑定事务，按已选保证发通知。会话刷新不能抬高原认证保证或重置绝对新鲜度；成功认证后更换会话标识，服务器不得接受攻击者预置的固定会话。IdP退出与RP退出独立，宣称全端退出要收齐相应控制点的实效回执。[S2]

**失败、并发、超时与恢复：** 改密、丢失认证器、账户停用与风险升高按画像触发会话处理；长连、离线缓存和旧回包不能绕过。当前账户代际改变后旧异步结果不得建立新会话。下游超时只可记未知，不记已退出；合法重新认证开新会话，不复活旧绑定。

**兼容：** 多RP无需同厂商或相同超时值；采用某AAL时绝对/不活动阈值满足该等级原文，不能用任意组织配置替代规范上限。匿名无持续会话可排除此分支。

**验收与产物：** T-SEC-HTTP 在同一用户两个RP、长连接和账号切换后重复旧请求；以可控时钟跨绝对/不活动期限，核旧会话拒绝、当前新认证可用和敏感写计数。只清Cookie不足以通过。

**正例 / 直接失败 / 合法邻例：** 正例为到期后新鲜认证再执行；直接失败为IdP注销后未经核RP仍宣称全端退出；合法邻例是明确只注销当前RP时无关独立会话继续合法使用。

**来源：** S2§4.1/4.2/4.6、§5/5.2；防固定会话与跨账号回包为跨入口组织合成。

### SEC-P05 对象授权、撤权与目标栅栏

**对象与责任：** 资源控制者负责执行时授权，调度者不能仅凭发起时批准声称目标已拒旧权限；对已形成合法义务的事务由业务合同区分。

**输入/输出/权威：** 输入为完整主体命名空间、资源/租户/字段、动作、委派链、策略修订和目标已安装epoch；输出为允许/拒绝及实际效果。权威是资源端决定、资源变化与栅栏回读，目录写成功不是撤销完成。

**必要机制与不变量：** 每条受限读写/导出路径都检查对象与字段，权限属性由可信管理入口维护。撤权定义传播分母、最迟收敛、在途/已提交分界；旧epoch写入必须被目标拒绝，而不是只让调度者停止发送。安全关键未知不得无限依缓存放行；有界离线准入须预先规定对象和截止，不能事后扩大。

**失败、并发、超时与恢复：** 策略检查与副作用之间的竞争必须用同一事务、目标栅栏或可证等效边界收口；只在应用层查一次后排队不能抗撤权。撤销服务故障时按预定拒绝/限界降级；目标不能安装栅栏则不能声称即时撤销。恢复备份必须重应用有效撤权水位。

**兼容：** 合法已提交固定范围事务可按批准合同完成；撤权不抹除历史合法事实，也不把未提交新动作归入旧事务。多租户和单租户均按真实资源边界处理。

**验收与产物：** T-SEC-HTTP 将旧会话、签名链接、队列任务、长连分别在撤权前后交错执行；观察资源端旧代际拒绝、允许事务终点与传播水位。收敛前后结果逐点列，不用聚合绿灯替代。

**正例 / 直接失败 / 合法邻例：** 正例是当前策略允许的对象写入；直接失败为旧epoch任务在新栅栏后仍写；合法邻例为当前epoch对另一有权对象的并行写入，不应被全局锁或过宽撤销误拒。

**来源：** 组织合成，承接基线§13—17及后端实际授权/事务接口；NIST联合认证不被用来证明业务授权。

### SEC-P06 轮换、撤销与历史解密的分离

**对象与责任：** 材料所有者、发行者、目标端和全部消费者共同闭合轮换；登记认证凭据、签名、数据加密、包装密钥各自用途，不能混用一套完成标记。

**输入/输出/权威：** 输入为秘密引用、旧/新版本、消费者分母、目标接受集合、并存窗、备份和历史密文依赖；输出为准备/并存/切换/旧拒绝/已完成或未决。目标端负例和消费者实际使用版本为权威。

**必要机制与不变量：** 新材料先在获准环境生效并验证消费者，收齐切换结果后按合同撤旧并验证。泄漏材料不为回退重新获签发/认证权；合法历史解密可保留受限旧KEK或可信重包装，独立于旧签发拒绝。清单中的零消费者不能关闭未知消费者，离线实例须有重接入门禁。

**失败、并发、超时与恢复：** 同时轮换用版本比较或单一控制账防覆盖；延迟消费者/旧部署回滚须被目标拒旧或强制更新。部分失败保持未决集合，可延长并存只能经相应风险决定且不得违反已撤销事实。删除旧密钥前验证备份恢复闭包。

**兼容：** 不同材料可选择再加密、重包装、历史只读等不同路径；秘密库别名修改或重启成功均非所有消费者已切换。对硬件不可导出密钥只核对应引用与行为。

**验收与产物：** T-SEC-HTTP/CRYPTO 用两消费者和一个离线消费者，测试新值正例、旧值负例、旧部署重入、合法旧密文恢复；产物含不泄漏值的消费者版本账和未决项，全部分母核清方能完成。

**正例 / 直接失败 / 合法邻例：** 正例是所有在线消费者切新且旧认证拒绝；直接失败是别名更新就完成、离线实例仍能重入用旧值；合法邻例是受限保留旧KEK只解合法历史数据，不等同允许旧签名继续发行。

**来源：** 组织合成，承接安全基线§18—20与云秘密生命周期的目标/消费者接口；不声称某密码规范保证轮换部署。

### SEC-P07 审计、漏洞与可信恢复闭包

**对象与责任：** 审计接收者、安全响应者、制品/恢复负责人维护从线索到恢复的可核事实；记录兼岗事实，不伪造独立审查。

**输入/输出/权威：** 输入为受限原始事件、来源/时间质量、受影响组件与身份版本、恢复材料及当前撤权/删除水位；输出为已证/未知影响、遏制/修复/交付/恢复各自结果。实际资源/制品和拒绝回归为权威，告警安静不是根除。

**必要机制与不变量：** 记录决定、执行和效果不同阶段，保留原始失败及调查动作完整性/来源；收集只限必要字段。漏洞报告、可信复现、受影响版本、补丁、实际发行与下游采用分列。恢复资产用前检查完整性和失陷指标；重应用有效撤权、删除与密钥信任，不让备份复活旧入口。[S4][S6]

**失败、并发、超时与恢复：** 日志断流要显式告缺，关联ID不得由低信任输入伪造；乱序事件按事实时点与观察时点保留，不能凭时钟排序补造因果。恢复中发现未知制品或根因则限制结论并追踪，不覆盖原记录制造干净结果。

**兼容：** 小型离线项目可用相称的本地证据与私密报告入口，不强制企业PSIRT；没有扫描/运行触达的版本保持未核，不能按相近版本套通过。

**验收与产物：** T-SEC-AUDIT 注入事件缺口、改写副本、错误符号/制品和旧撤权备份；用日志读取、文件摘要与资源旧令牌请求交叉核对，输出时间线、证据指纹、缺口、原攻击路径拒绝及合法任务可用记录。

**正例 / 直接失败 / 合法邻例：** 正例是可信恢复资产与当前权限下业务恢复；直接失败为零告警证明无入侵或HTTP200证明根除；合法邻例是在观测缺口明确时仅对已证的有限入口给出局部恢复结论。

**来源：** S4 SSDF v1.1 PW.1、RV.1—2；S6 SP800-61r3 RS.AN-06/07、RC.RP-03/05。跨备份权利水位为组织合成。

## 真实目标执行合同（当前 not-run）

L6必须先绑定目标地址/精确构建、只用于获准测试的合成账号、请求路径、文件、可控时钟/故障接口和观察权限；缺绑定时不得将下列命令当已执行。响应、退出码、资源查询和拒绝侧无副作用同时保留，原始令牌不能出现在公开日志。

- **T-SEC-TLS：** `openssl version -a`记录版本；`openssl s_client -connect "$HOST:$PORT" -servername "$DNS" -verify_hostname "$DNS" -verify_return_error -CAfile "$TEST_CA" -tls1_3 < /dev/null`，再对允许TLS1.2与被禁旧版本、错DNS/不受信CA分别运行。协商失败须区分本地客户端不支持与目标实际拒绝，后者需目标握手日志；同一工具不能代表所有客户端。
- **T-SEC-HTTP：** 每个场景先将方法、相对路径和body绑定到 L6 case；`curl --config "$CASE_AUTH_CONFIG" --request "$METHOD" --header 'Content-Type: application/json' --data-binary @"$CASE_BODY" --dump-header "$CASE_HEADERS" --output "$CASE_REPLY" "$BASE$CASE_PATH"`。配置文件引用由测试设施提供的合成凭据，不把真实秘密写命令。紧随只读资源/会话/计数接口查询；HTTP状态不能单独证明无副作用。
- **T-SEC-CRYPTO：** 用实际库的固定版本测试入口送原文/密文/nonce/AAD夹具，记录库调用返回与明文释放次数；密钥/随机源故障须由库或测试设施注入。接口名、调用代码和用量上限进入L5，不用自制算法替代目标。
- **T-SEC-AUDIT：** `sha256sum "$RAW_EVIDENCE" "$RESTORE_ARTIFACT"`核材料身份；按T-SEC-HTTP查询原意图、实际结果和旧权限，按服务原生只读日志入口读取丢失计数/水位。摘要只能证明字节身份，不证明来源真实或权限有效。
