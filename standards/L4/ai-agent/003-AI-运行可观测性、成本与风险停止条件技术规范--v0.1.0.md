## 一、范围、现行依赖与控制边界

本专题规定已训练模型应用的运行信号、费用事实、预算准入、异常解释及有限风险保护。它回答“发生了什么、证据可信到哪里、还允许派发什么、怎样恢复”，不把记录数量、追踪成功或模型自评等同业务成功。不强制商业观测平台，不授权真实模型实验、付款、生产变更或扩大日志数据共享。

### 最小事实记录

| 类别 | 必须保留的适用语义 |
| --- | --- |
| 身份 | root_task_id、run_id、attempt_id、实际主体/租户的受控引用、provider_request_id（可未知）、父子/link关系 |
| 事实 | 来源系统、事件ID、发生与接收时间、模型/工具/配置版本、结果层级、证据引用、完整性/采样标记 |
| 费用 | 单位与类别、observed/estimated/unknown来源、币种与价表版本、settled/reserved/unresolved状态、原事件及修正引用 |
| 决策 | 规则版本、触发事实、动作scope、批准依据、未完任务、责任者、重查与恢复条件 |

以上为语义模型而非新互操作协议；不要求每个日志都复制全部字段。不把个人信息和完整内容塞入身份键。

### 不变量

- I1 同一任务的后代、重试、恢复共享原预算归属，准入计算覆盖已计费用和在途/未知预留。
- I2 未观测、未结算、取消请求已发出都不等于零费用、无副作用或已完成。
- I3 观测事实、因果假设、控制决定和业务验收分别可定位，相关性不冒充因果。
- I4 临时保护只阻断确有风险或违反有效授权的动作，不自动取消目标、改变权限或停止无关工作。
- I5 默认不采集内容；恢复和安全门禁不以过度日志采集作为必要条件。
- I6 原始失败和修正依据可追溯；导出器、采样器与模型输出不能改写权威任务状态。

## 三、32 项技术机制与验收

### 执行闭环与实现绑定

每条§适用时均由下表责任者在相应接受边界执行：输入须来自当前有效主体及权威状态；输出区分允许、拒绝、未知与已证实事实。模型提议、协议ACK、日志或摘要不能自签授权。并发接受使用预期版本/世代或等效条件；超时保留原逻辑操作、预算预留及核对责任。日志记录decision_id、输入/输出身份、原因和证据定位，不要求保存私有思维链。具体字段可复用既有系统。

| 组/条款 | 责任者及运行入口 | 权威输入 → 可观测输出 | 失败、并发、超时与恢复 | 兼容/合法边界 |
| --- | --- | --- | --- | --- |
| observability-G01 / §01—§04 | 观测契约维护者；`observe.bind` | 任务尝试、主体及实际版本 → 可定位且不授权的最小关联 | request_id缺失标未知，外部trace不夺权 | 小应用可不引分布式追踪 |
| observability-G02 / §05—§08 | 事件与计时维护者；`event.record/export` | 真实因果ID、事件时间和覆盖 → 分层状态与采样缺口 | 导出丢失不修改业务事实 | 采样trace不用作精确账本 |
| observability-G03 / §09—§12 | 隐私与出口维护者；`log.filter/read/delete` | 字段白名单、受众、保留和开关 → 有界最小诊断及清理状态 | 所有hook/错误出口各核，撤权禁用派生搜索 | 关闭内容不取消必要控制事实 |
| observability-G04 / §13—§16 | 用量与预算服务；`usage.ingest/budget.reserve` | 来源单位、价表及在途上界 → 未知/预留/已结算守恒账本 | 累计不重加，并发预留不双花 | 估算不冒账单 |
| observability-G05 / §17—§20 | 派发及结算控制器；`attempt.admit/cancel/settle` | SDK重试上界、预留ID与实际收据 → 受控调用和幂等结转 | 取消不释放未知费用，迟到收据补账 | 不可控费用不能保证原硬预算 |
| observability-G06 / §21—§24 | 异常与风险分析者；`cost.reconcile/risk.decide` | 账单窗口、独立事实与规则版本 → 可解释差额/原因及局部动作 | 137不独证OOM；相关性不写因果 | 阈值按风险不统一数字 |
| observability-G07 / §25—§28 | 保护与恢复责任者；`protect/alert/recover` | 真实授权、预算状态与受影响依赖 → 局部阻断、待决定及有限探测 | 冷却不复权；通知不当批准 | 无关已授权工作可继续 |
| observability-G08 / §29—§32 | 接续及观测验收方；`state.restore/telemetry.migrate` | 根账本、后代、schema和实际证据 → 未决责任与准确映射 | 字段缺失不归零，不靠Trace重放动作 | Development字段定向兼容 |

实现方将上述逻辑入口映射到[目标合同](../../../examples/ai-agent/target-contract.json)中的真实模块/命令，记录端点、准确版本、鉴权身份来源、输入输出与权威查询方式；无真实适配映射不声称目标已通过。有限参考模型及本地命令见[运行入口](../../../examples/ai-agent/README.md)，仅验证声明的控制不变量。

### §01 观察目标与最小实现
**机制：** 按模型调用、工具副作用和长期异步任务的实际风险定义需要回答的问题、信号及责任者。单调用可用结构化记录和本地账本，不强制部署分布式追踪、商业平台或全量内容采集。

**验收：** 简单生成任务能定位调用失败和费用上界，无多 Agent 时不要求虚构委派链。

**执行绑定：** `observability-G01`。**专用正例 P-observability-01：** 单调用用最小状态与账本。**直接失败 D-observability-01：** 单请求应用因未部署追踪平台被全局判停；预期：按适用目标验证最小记录，不制造平台采用门槛。**合法邻例 N-observability-01：** 不强制商业分布式追踪平台。

### §02 逻辑任务与尝试身份
**机制：** 由可信控制面生成 root_task_id、run_id、attempt_id；同一逻辑任务的重试、重连、恢复和后代共享预算归属。供应商 request_id 与应用身份分别保留，无法获得时显式未知，不能伪造。

**验收：** 首次请求加两次 SDK 重试共三次实际尝试、一个逻辑任务；模型输出的 request_id 不成为可信关联键。

**执行绑定：** `observability-G01`。**专用正例 P-observability-02：** 三次尝试仍属一个根任务。**直接失败 D-observability-02：** 重建 run 后费用归属到新空账本；预期：保留原根任务预算与新尝试身份。**合法邻例 N-observability-02：** 供应方ID缺失可记未知。

### §03 版本和部署关联
**机制：** 记录实际提供商、请求模型与返回模型（可得时）、工具/控制策略/价格表版本及部署身份；只保存不可逆摘要或版本引用而非秘密。模型别名不能证明固定权重版本。

**验收：** 别名切换后仍能分组定位请求配置，但报告不声称知道厂商未披露的模型快照。

**执行绑定：** `observability-G01`。**专用正例 P-observability-03：** 实际模型与价表版本可定位。**直接失败 D-observability-03：** 仅凭请求别名宣称行为可完全复现；预期：标注版本不确定性，保留实际可得配置。**合法邻例 N-observability-03：** 无法见权重摘要不伪造固定性。

### §04 跨边界追踪与信任
**机制：** trace/span 仅作关联，不作身份、授权或幂等凭据；跨不可信边界校验长度和格式、限制传播字段，必要时新建 trace 并以受控 link 关联。禁止通过 baggage 传播凭据、完整提示或个人标识。

**验收：** 伪造 traceparent 能关联诊断但不能切换租户、提升权限或覆盖他人记录。

**执行绑定：** `observability-G01`。**专用正例 P-observability-04：** trace仅关联不授租户权。**直接失败 D-observability-04：** 外部 Agent 的 trace_id 被用作租户授权；预期：拒绝授权推断并隔离外部上下文。**合法邻例 N-observability-04：** 跨不可信边界可新建trace并link。

### §05 异步因果关系
**机制：** 派发、接收、排队、执行和结果归档分别建事件；异步批次与多父任务使用明确 link/映射而非假设单一嵌套父 span。区分操作因果、时间相关与待证假设。

**验收：** 两个批次共用提供商账号时仍以 request/item 映射归属，不能把邻近时间事件自动认作同一原因。

**执行绑定：** `observability-G02`。**专用正例 P-observability-05：** 派发接收排队按真实ID关联。**直接失败 D-observability-05：** 按时间相近将另一任务的异常归因到本任务；预期：保留未关联状态，补查任务/尝试映射。**合法邻例 N-observability-05：** 时间相近不自动建立因果。

### §06 结果分层与真实性
**机制：** 分别记录传输、协议、模型响应、工具执行、外部副作用和业务验收结果；span OK、HTTP 200、无异常退出或模型自报完成均不证明业务成功。部分流、拒绝和未知外部结果有独立状态。

**验收：** 返回200但付款收据未知时业务保持待核对，而不是成功或可安全重放。

**执行绑定：** `observability-G02`。**专用正例 P-observability-06：** 200与付款unknown分层保留。**直接失败 D-observability-06：** SDK正常返回即写业务成功；预期：核对目标验收与系统收据，保留未知。**合法邻例 N-observability-06：** spanOK不代表用户业务完成。

### §07 时间、延迟与等待
**机制：** 区分端到端时延、排队、首 token、流式生成、工具/审批等待和重试退避；本进程时长用单调时钟，跨节点时间注明时钟偏差和事件时间/采集时间。

**验收：** 等待用户决定的时间不计成模型推理时间；迟到事件不倒置执行顺序。

**执行绑定：** `observability-G02`。**专用正例 P-observability-07：** 等待用户与模型时长分开。**直接失败 D-observability-07：** 审批等待被计入模型延迟并触发模型故障；预期：按分段指标与真实事件时间重算。**合法邻例 N-observability-07：** 跨节点时钟偏差可明确记录。

### §08 完整性与采样范围
**机制：** 记录采样、丢弃、导出失败、覆盖比例和口径；采样 trace 不承担精确计费账本。保留最小授权/预算/副作用状态所需事件，不将全量提示日志设为恢复前提。

**验收：** 关闭内容追踪后仍能做预算准入与副作用核对；采样统计不冒称总体失败率。

**执行绑定：** `observability-G02`。**专用正例 P-observability-08：** 采样覆盖缺口显式报告。**直接失败 D-observability-08：** 采样一成调用后直接将样本token作为总费用；预期：用独立用量账本并注明覆盖缺口。**合法邻例 N-observability-08：** 关闭内容追踪仍可做预算门禁。

### §09 基数与观测资源预算
**机制：** 用户输入、任务ID和完整工具参数不作无限基数指标标签；ID可置受控事件索引。规定事件大小、缓冲上界、导出速率和丢弃顺序，避免观测挤占核心执行和失控日志费用。

**验收：** 大量唯一 prompt 不生成同量指标时间序列，缓冲饱和可降级非关键诊断而保留控制事实。

**执行绑定：** `observability-G03`。**专用正例 P-observability-09：** 高基数ID放受控事件索引。**直接失败 D-observability-09：** 每条提示作为指标标签导致存储爆增；预期：拒绝高基数标签，按观测预算降级。**合法邻例 N-observability-09：** 必要业务指标可保持有限维度。

### §10 默认内容最小化
**机制：** 默认仅采集必要元数据、状态、计数和受控引用，不采集完整提示、响应、检索片段、工具参数/结果、截图或内部推理。确需内容调试时限定用途、数据类、范围、保留期和获准接收方，在采集前完成必要批准和脱敏。分别检查实际SDK的内容出口、正文属性、调试回调与采样开关；开关的覆盖范围必须通过所选实现验证，关闭一个不证明其他出口不发送。

**验收：** 含秘密的提示在应用、SDK、导出器和错误路径均不进入未获授权的观测/日志出口；调试开关不是数据分享授权。

**执行绑定：** `observability-G03`。**专用正例 P-observability-10：** 默认不采全文或密钥。**直接失败 D-observability-10：** 开启SDK调试后原始工具结果流入第三方日志；预期：阻止未获准采集/发送并核查已泄露范围。**合法邻例 N-observability-10：** 获准限定调试还需逐出口脱敏。

### §11 脱敏与不可信日志
**机制：** 在来源端按字段白名单与分类过滤，必要时二次导出过滤；散列可关联且不自动匿名。规范化控制字符并限制消息长度，不执行日志内容中的指令。仅采集摘要不能掩盖重要未知结果。

**验收：** 带换行伪造状态或秘密嵌套字段的异常被安全编码/过滤，原业务状态仍可定位。

**执行绑定：** `observability-G03`。**专用正例 P-observability-11：** 换行和ANSI作为数据编码。**直接失败 D-observability-11：** 攻击者把伪造成功事件和密钥塞进异常字符串；预期：结构化编码与字段过滤，可信状态来自控制面。**合法邻例 N-observability-11：** 必要未知状态不被摘要掩盖。

### §12 可见性与保留生命周期
**机制：** 日志读取/搜索/导出按租户、主体与用途隔离；保留、删除、备份及派生索引遵从现行数据规则。临时取证延长须明确范围和依据，不能以审计名义永久保留全部内容。

**验收：** 授权撤回后原主体不可继续检索内容；合法保留的最小凭据与删除范围可区分。

**执行绑定：** `observability-G03`。**专用正例 P-observability-12：** 撤权后搜索导出同样限权。**直接失败 D-observability-12：** 删除原日志后向量索引仍暴露敏感提示；预期：同步处置派生副本与访问权并验证。**合法邻例 N-observability-12：** 合法保留最小证据可隔离存在。

### §13 使用量事实与未知
**机制：** 区分供应商报告用量、客户端测量、tokenizer估算和缺失值；记录来源、单位、模型/计费类别、观测时间和结算状态。缺失不是零，流式中断或超时不证明未收费。

**验收：** 缺 usage 的已派发请求保持成本未知/预留，不记零成本完成。

**执行绑定：** `observability-G04`。**专用正例 P-observability-13：** 缺usage记unknown及预留。**直接失败 D-observability-13：** 流中断没有usage便将费用清零；预期：保留不确定费用并对账。**合法邻例 N-observability-13：** 供应商实报用量与估计可并列。

### §14 token计数与类别
**机制：** 输入、输出、缓存命中/写入、推理或音频/图像等类别按供应商当前口径拆分；包含关系须显式定义，避免总输出加推理子项重复计数。不同模型的token不能按相同单价或文本长度换算。

**验收：** 缓存输入若属于input总数则分项计价不再叠加总输入；不可得细项保持未知。

**执行绑定：** `observability-G04`。**专用正例 P-observability-14：** 累计token类别不重复相加。**直接失败 D-observability-14：** 输出总token再加包含在内的推理token；预期：按该版本计费口径去重类别。**合法邻例 N-observability-14：** 未知细项不默认为零。

### §15 价格估算与账单隔离
**机制：** 估算保存币种、价格生效时间、计价单位、服务层/批处理折扣和舍入口径；工具、存储、网络等适用项另列。估算不是发票，应列明税费、优惠、退款、组织分摊等未覆盖项。

**验收：** 同样token在不同服务层使用不同价表；报告区分预估、供应商成本记录与实际账单。

**执行绑定：** `observability-G04`。**专用正例 P-observability-15：** 费用估计附币种价表时间。**直接失败 D-observability-15：** 将公开单价乘token报告为最终发票金额；预期：标明估算依据与不含项，等待账单核对。**合法邻例 N-observability-15：** 聚合账单不伪造精确任务分摊。

### §16 根级预算与并发预留
**机制：** 每次可计费派发前原子校验同一预算域的已核算量、在途/未知预留与新请求保守上界；余额不能被并发读取分别花完。任务、租户与账户限额按实际适用层级组合，后代/重试不可重置。

**验收：** 两个子任务争用最后额度时至多获准可覆盖的派发；不会因日志采样而漏扣。

**执行绑定：** `observability-G04`。**专用正例 P-observability-16：** 最后预算原子准入单一派发。**直接失败 D-observability-16：** 两个并发调用各自认为剩余额度足够；预期：原子预留，只有满足所有适用限额的调用派发。**合法邻例 N-observability-16：** 并发日志采样不影响权威账本。

### §17 上界、估计误差与准入
**机制：** 对可计费操作按实际API限制、最大输出/工具调用及误差预留建立上界；软预算只报警，硬预算必须阻止不合规新派发。无法取得可信上界或实施硬限制时，不得以均值或风险接受代替硬预算准入。适用授权主体可另行批准明确的预算模式或额度变更，但不得将其表述为原硬限额保证，亦不得豁免不可放宽的约束；限流只约束速率，单独限流不保证总费用上界。

**验收：** 未知单价或无法限制的外部工具费用不能靠平均值冒充硬限额保证；仍可继续不耗该预算的工作。

**执行绑定：** `observability-G05`。**专用正例 P-observability-17：** 可信最大费用上界才承诺硬限额。**直接失败 D-observability-17：** 使用均值预测承诺严格不超支；预期：采用可验证上界或请求具体额度决策，不停无关工作。**合法邻例 N-observability-17：** 限流可用但不等于总费用封顶。

### §18 重试与隐藏调用
**机制：** 一个逻辑span可覆盖多次自动重试，不能按span数估计尝试数；结果轮询不等于新的推理计费。计入SDK内部重试、模型切换、工具轮询、补偿和委派开销；无法逐次拦截SDK内部派发时，先原子预留整个逻辑操作的最坏重试额度，或禁用自动重试并交由受控调度，事后合计不能替代硬预算准入，重试次数或费用无可控上界时不得按硬预算派发；设根级重试/时长/用量约束及退避，错误不一律重试。外部动作结果未知先核对，避免以节省延迟为由重复副作用。

**验收：** 超时后供应商已完成时不会再无条件派发；SDK自动重试也有尝试记录或可靠合计口径。

**执行绑定：** `observability-G05`。**专用正例 P-observability-18：** SDK内重试全部上界先预留。**直接失败 D-observability-18：** SDK内部重试无法逐次插入准入，上层只在结束后合计费用；预期：预留覆盖全部受限重试序列或禁用自动重试；无可控上界不得按硬预算派发。**合法邻例 N-observability-18：** 可禁自动重试改受控逐次调度。

### §19 异步取消与结算
**机制：** 取消请求、服务端确认取消、部分完成和费用最终结算分别记录；本地取消或父任务结束不释放远端仍在途预算。批次逐项确认完成、失败、未开始和未知，预留按证据结转/释放，以预留标识去重，将费用确认与对应预留释放原子结转，迟到费用可继续入账。

**验收：** cancel返回后仍执行的批次项保留预留与核对责任；不能把cancel当退款。

**执行绑定：** `observability-G05`。**专用正例 P-observability-19：** cancel_requested保留在途预留。**直接失败 D-observability-19：** 发出取消即释放全部预算供新批次使用；预期：保持在途/未知预留直到可核实终态和计费依据。**合法邻例 N-observability-19：** 最终证实未开始可释放。

### §20 幂等计量与对账修正
**机制：** 按稳定计费事件/请求/条目身份去重，区分重传同一用量和真实新尝试；对累计usage取差额或覆盖版本，不能逐帧累加累计值。保留原始事实引用与更正记录，迟到和退款不静默改历史。

**验收：** 重复webhook不重复记账；累计10再20只计20；负向调整有原事件引用。

**执行绑定：** `observability-G05`。**专用正例 P-observability-20：** 累计10再20只结算20。**直接失败 D-observability-20：** 重连重复usage与累计帧同时入账；预期：按事件语义去重并可追溯修正。**合法邻例 N-observability-20：** 真实新attempt另记不可误去重。

### §21 账单差异与归因边界
**机制：** 按账户/项目、时间窗、时区、模型/计费项和币种对齐供应商用量、成本与本地估算；保留未分摊余额、迟到项和差异原因。聚合账单无请求级证据时不得伪造精确个人或任务成本。

**验收：** 对账差额先排查窗口、折扣和未观测调用，不直接指控模型多收费或某用户滥用。

**执行绑定：** `observability-G06`。**专用正例 P-observability-21：** 账单差额保留未分摊。**直接失败 D-observability-21：** 聚合账单差额被全部归给最后一个任务；预期：保持未分摊并说明证据粒度。**合法邻例 N-observability-21：** 无请求粒度不强分给最后用户。

### §22 质量与漂移信号
**机制：** 将线上拒绝、结构错误、工具失败、投诉和业务验收与离线评测区分；按模型/配置/人群/时间窗口分层并报告分母、标签延迟、样本量和缺失。分布变化与质量下降是线索，不自动证明模型根因。

**验收：** 小样本单次拒绝不会被包装为全域质量崩溃；有业务风险的具体失败仍立即处理。

**执行绑定：** `observability-G06`。**专用正例 P-observability-22：** 分层拒绝率注明样本与缺失。**直接失败 D-observability-22：** 输入人群变化引起拒绝率升高便判模型退化；预期：分层核验并标注关联而非因果。**合法邻例 N-observability-22：** 具体严重失败无需等大样本处置。

### §23 异常解释与资源证据
**机制：** 保留观测事实、候选原因、支持/反证及置信范围；退出137只能表明常见shell约定下与SIGKILL一致，不单独证明OOM。需结合运行时终止原因、内存事件/限额和管理员取消/超时等证据；无证据保持原因未定。

**验收：** 显式kill与OOM样本即使相同退出码仍区别处理，不凭码自动扩内存或取消项目。

**执行绑定：** `observability-G06`。**专用正例 P-observability-23：** 相同137用独立证据区分原因。**直接失败 D-observability-23：** exit137被直接宣布为OOM并改资源配置；预期：核对独立证据，未证实时只报告终止事实。**合法邻例 N-observability-23：** 无证据时仅报终止原因未知。

### §24 风险规则与决策身份
**机制：** 每条保护规则定义风险、信号来源、适用作用域、触发窗口/阈值依据、动作上限、责任者、解释和恢复条件；模型自评或不可信工具文字不可独自触发扩大权限或永久终止。阈值由项目风险与实测设定，不统一数字。

**验收：** 同一超时对只读搜索与资金动作采用不同保护范围，规则版本与决定可追踪。

**执行绑定：** `observability-G06`。**专用正例 P-observability-24：** 保护规则含scope责任恢复条件。**直接失败 D-observability-24：** 所有项目统一三次失败即永久停工；预期：按风险和授权定义局部保护及恢复。**合法邻例 N-observability-24：** 不同业务可用不同合理阈值。

### §25 最小影响的临时保护
**机制：** 授权失效、确认越界、硬预算不足或必要安全控制不可用时，控制面拒绝相应不合规新动作；可对受影响能力/租户/尝试临时熔断、限流或转核对。保留原目标和未完状态，不把有限保护升级为自主取消、缩小任务或项目全局停工；目标/权限改变须适用批准。

**验收：** 单工具授权失效只阻断该工具相关派发，仍推进可独立完成的已授权工作。

**执行绑定：** `observability-G07`。**专用正例 P-observability-25：** 仅阻不合规新动作保留原目标。**直接失败 D-observability-25：** 一个工具诊断缺失导致撤销整个项目；预期：隔离实际风险范围；目标保持开放并请求必要决定。**合法邻例 N-observability-25：** 独立合法工作继续而非全局取消。

### §26 观测降级与安全底线
**机制：** 仅追踪导出或非必要诊断失效时标注观测降级、限制缓冲和补查，不自动停项目；若该信号确为执行授权、预算准入或副作用去重不可替代的控制依据，则只阻断依赖它的新动作。不得以日志完备为恢复条件强迫收集敏感内容。

**验收：** trace后端不可用且本地预算/授权完好时可继续；预算账本不可用则不能新增依赖额度的收费操作。

**执行绑定：** `observability-G07`。**专用正例 P-observability-26：** Trace导出故障不损本地授权预算。**直接失败 D-observability-26：** 导出器断线被当作全局安全控制失效；预期：区分诊断与强制控制，缩小技术隔离范围但不改变获批任务目标。**合法邻例 N-observability-26：** 预算账本不可用则阻相关收费派发。

### §27 告警与人工接手
**机制：** 告警含事实、受影响范围、已做保护、未决动作/费用、所需决定、负责人及重查条件；聚合重复告警但不吞掉新的高影响事实。人工可达性不足不自动授予Agent批准权。

**验收：** 通知发送成功不等于用户已读/批准；待决定状态可持续并继续无依赖工作。

**执行绑定：** `observability-G07`。**专用正例 P-observability-27：** 告警送达不当人已批准。**直接失败 D-observability-27：** 告警无人答复被当作同意增加预算；预期：保持待批准，保留恢复入口与责任。**合法邻例 N-observability-27：** 无人应答维持待决定状态。

### §28 熔断恢复与防振荡
**机制：** 恢复需风险原因已消除或授权主体在其权限内接受可豁免的具体风险（不得豁免不可放宽的安全边界或授权要求）、配置/授权/预算有效、未知副作用已核对及有限探测计划；恢复条件仅覆盖受影响动作及其依赖，不成为无关工作门槛；按适用窗口/退避/迟滞避免抖动。半开探测仍耗预算且受同一权限约束，不能作为绕过拒绝的重试。

**验收：** 重新登录或冷却到期不独自解除明确撤回；探测失败回到有限保护而不清空历史。

**执行绑定：** `observability-G07`。**专用正例 P-observability-28：** 冷却不覆盖明确撤回。**直接失败 D-observability-28：** 熔断冷却后自动重试已被明确拒绝的动作；预期：先确认有效新授权，禁止以探测绕过拒绝。**合法邻例 N-observability-28：** 半开探测仍按同一预算授权。

### §29 恢复账本与未决工作
**机制：** 重启、接手或更换模型前恢复任务/尝试、预算预留、在途后代、未决副作用、保护规则版本及责任者；日志不是执行事实库。缺失可补查的诊断不应阻止无风险独立工作，无法确认的外部动作不可盲目重放。

**验收：** 父进程退出后远端任务仍有人核对；保留工作目标而非将监控静默当完成。

**执行绑定：** `observability-G08`。**专用正例 P-observability-29：** 恢复查权威账本与远端未知。**直接失败 D-observability-29：** 重启只读最后一条trace便重放外部动作；预期：从权威控制状态恢复并核对未知结果。**合法邻例 N-observability-29：** 诊断缺失不阻独立无风险工作。

### §30 观测变更与迁移
**机制：** 对SDK、语义约定、采样/脱敏、价格类别或指标定义变更锁定版本和变更依据；验证字段重命名、单位、累计/增量与仪表盘分母兼容。允许双读短期对比但避免双计/双发内容。

**验收：** OTel Development字段变更后有映射和退出期限，不将缺字段解释为零用量。

**执行绑定：** `observability-G08`。**专用正例 P-observability-30：** schema变更验证单位累计语义。**直接失败 D-observability-30：** 升级后token字段变名导致费用突然归零；预期：契约回归发现缺失，保持未知并修正映射。**合法邻例 N-observability-30：** 短期双读不双计不双发正文。

### §31 验证分层与故障注入
**机制：** 结构与合成事件测试验证字段、账本不变量和保护决策；供应商计费、真实模型质量、实际跨系统追踪及生产保护需L5/L6实测与授权。使用脱敏/合成数据覆盖迟到、重传、并发、取消和导出失败，不为验证主动制造真实费用或外部副作用。

**验收：** 测试报告明确模拟账本与真实账单对账的边界，不以单元通过宣称线上不超支。

**执行绑定：** `observability-G08`。**专用正例 P-observability-31：** 合成账本与真实账单分列。**直接失败 D-observability-31：** 合成预算测试通过被宣传为真实模型零超支保证；预期：保留层级和未验证范围，要求适用环境证据。**合法邻例 N-observability-31：** 单元通过不宣传真实费用保证。

### §32 小型项目与责任闭环
**机制：** 允许不适用复杂指标或平台，但写明适用性、替代证据、负责人及何时重新评估。最小实现仍保留预算/授权/副作用边界和未知状态。规范批准、技术验证、实际部署与业务验收分别记录。

**验收：** 不使用外部工具的应用可省略工具链路；新增付费异步工具时必须重评预算及取消契约。

**执行绑定：** `observability-G08`。**专用正例 P-observability-32：** 简化平台仍留未知与责任。**直接失败 D-observability-32：** 小项目简化删除全部费用未知与恢复责任；预期：简化实现而不删除必要控制和责任。**合法邻例 N-observability-32：** 新增异步收费能力才重评对应契约。
