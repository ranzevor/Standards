# L4 模型及 Agent 应用版本演进与回退技术规范

**文档ID：** STD-L4-AI-AGENT-013　**版本：** 0.1.0　**状态：** adopted　**生效日期：** 2026-10-30

## 一、适用范围及继承关系

本专题规定已经训练好的模型在应用中的**联合行为版本、兼容迁移、灰度判断与可行回退**。适用于模型、提示、工具、知识、记忆、执行状态或配置发生实际变化的路径；无检索、无长期状态或无工具的应用不需虚构这些组件。不规定模型训练、不统一供应商或版本号方案、不要求多集群与全量付费评测。

前序技术规范：[AI/Agent 领域基线](001-AI-应用与-Agent-系统领域通用基线--v0.1.0.md)、[模型调用](014-模型接入、推理调用与响应契约技术规范--v0.1.0.md)、[检索](012-检索、知识接入与可验证溯源技术规范--v0.1.0.md)、[持久记忆](010-持久记忆、会话隔离与生命周期技术规范--v0.1.0.md)、[工具/MCP](009-工具能力契约与-MCP-互操作技术规范--v0.1.0.md)、[动作授权及副作用](004-Agent-授权、可变更动作与业务副作用技术规范--v0.1.0.md)、[后端跨版本](../backend/012-跨版本发布、迁移与恢复技术规范--v0.1.0.md)、[数据库Schema迁移](../database/003-Schema-迁移、回填与兼容收缩技术规范--v0.1.0.md)、[云发布与回退](../cloud/006-发布编排、渐进流量与回退技术规范--v0.1.0.md)。后端/数据库负责事务和物理数据迁移，云规范负责流量/控制器，本专题补充模型行为及语义状态联合兼容。项目分别记录各专题的采用范围与实现验收。

## 三、28 项机制与验收条件

### 执行闭环与实现绑定

每条§适用时均由下表责任者在相应接受边界执行：输入须来自当前有效主体及权威状态；输出区分允许、拒绝、未知与已证实事实。模型提议、协议ACK、日志或摘要不能自签授权。并发接受使用预期版本/世代或等效条件；超时保留原逻辑操作、预算预留及核对责任。日志记录decision_id、输入/输出身份、原因和证据定位，不要求保存私有思维链。具体字段可复用既有系统。

| 组/条款 | 责任者及运行入口 | 权威输入 → 可观测输出 | 失败、并发、超时与恢复 | 兼容/合法边界 |

### §01 联合发行身份与可变项清单
**机制：** 每次实际发布建立联合发行标识，关联应用/控制器制品、模型提供者/端点/实际模型标识、指令模板与变量规则、工具目录与实现、检索管线/知识水位、记忆及检查点结构、策略/配置/路由。无相关组件则注明不适用；不把一个 Git SHA 视为全部线上身份。

**验收：** 按一条实际任务记录可重建受控组件组合，区分声明版本与实际观测；秘密只保留受控引用，不进入清单正文。

**执行绑定：** `version-G01`。**专用正例 P-version-01：** 联合清单含模型提示工具知识状态。**直接失败 D-version-01：** 只记录代码SHA，后台已热更Prompt和工具Schema；预期：定位真实联合版本并识别未登记变更。**合法邻例 N-version-01：** 无相关组件明确不适用。

### §02 模型可固定性与不可复现边界
**机制：** 按供应商和托管平台实际合同区分固定模型ID、可漂移别名、部署名及无法观测的后端变更，不能仅靠是否含日期判断。可固定时选可定位版本；无法固定时记录限制、检测方法与获准备用路径。固定ID亦不保证逐Token确定性或永久供应。

**验收：** 对同名后端变化与模型下线分别演练识别和恢复决策；无法取得供应商内部摘要时不伪造该摘要或声称已冻结。

**执行绑定：** `version-G01`。**专用正例 P-version-02：** 固定ID与别名按实际合同区分。**直接失败 D-version-02：** 别名仍叫stable便把两周前测评视为当前模型证据；预期：记录无法冻结事实，复核受影响行为和可用恢复目标。**合法邻例 N-version-02：** 固定ID也不承诺逐token确定。

### §03 行为差异与变更影响分析
**机制：** 区分外部接口、业务语义、权限、副作用、成本和数据表示的变化；提示词标点、默认推理预算、工具描述也可能改变行为。由受影响调用链确定验证集合和需重审的批准范围，版本号或供应商宣称兼容不能替代分析。

**验收：** 同Schema但参数单位、拒绝/工具选择倾向改变的样本进入回归；有理由证明不受影响的路径可复用证据。

**执行绑定：** `version-G01`。**专用正例 P-version-03：** 金额元改分即使Schema同仍重验。**直接失败 D-version-03：** PATCH版本把金额默认单位从元改分，JSON仍合法；预期：判为语义不兼容，不以版本号或Schema通过放行。**合法邻例 N-version-03：** 有理由证明未受影响可复用。

### §04 比例适当的回归与证据复用
**机制：** 以变更差异、权限与后果选择静态、确定性契约、隔离集成、真实模型及必要业务验证；不要求每次文字或局部升级重跑全套大型评测。复用记录须绑定原组合、数据/判定器版本、时间、受影响范围和有效理由，未测范围明确。

**验收：** 低风险只读局部修改可使用针对性正反例；新写工具或记忆迁移必须补相应执行/恢复测试，不能拿旧纯聊天分数替代。

**执行绑定：** `version-G01`。**专用正例 P-version-04：** 新增写工具补执行恢复回归。**直接失败 D-version-04：** 新增写工具仅复用旧聊天基准，或改说明文字强制昂贵全量评测；预期：按真实差异补必要门禁并保留可复用证据，不以成本取消必要验证。**合法邻例 N-version-04：** 说明文字小改不强制昂贵全量评测。

### §05 确定的候选与实际上线关联
**机制：** 候选验证完成后锁定受控内容摘要和配置引用；任何影响已验收行为的变更形成新候选或明确增量复验。上线核对实际联合版本、环境、入口和批准范围，工件与运行状态分别取证。

**验收：** 模拟测试后热改系统指令，必须发现证据不再覆盖；CI绿色不替代当前执行环境验收。

**执行绑定：** `version-G02`。**专用正例 P-version-05：** 上线实际组合匹配受验候选。**直接失败 D-version-05：** 用已通过评测的release-7名义上线热改的工具指令；预期：阻止错配并将证据绑定真实发行内容。**合法邻例 N-version-05：** 热改提示形成新候选或增量复验。

### §06 指令与上下文表示迁移
**机制：** 变更系统/开发者指令、模板、变量渲染、摘要和上下文组装时保留来源等级、用户当前目标、有效限制及拒绝；旧会话摘要不自动套入新指令语义。需要转换时记录映射、前后语义核验和失败处置。

**验收：** 旧摘要中的未授权发送不能被新模板默认为已批准；合法输入仍能完成原有核心功能。

**执行绑定：** `version-G02`。**专用正例 P-version-06：** 摘要迁移保留待批与否决。**直接失败 D-version-06：** 新模板把旧摘要的“待批准”删成默认执行；预期：拒绝权限含义漂移并保留有效目标及否决。**合法邻例 N-version-06：** 合法同义模板变化可保持核心效用。

### §07 工具实现与协议组合兼容
**机制：** 同时记录工具提供者/端点、输入输出Schema、实际动作含义、错误、幂等及授权规则；即使工具名不变也核对实现差异。使用MCP等协议时依生效工具专题选定的实际版本测试，不从发现成功推定可调用。

**验收：** 旧模型产生旧参数交给新工具、新模型与旧工具及回退组合均在真实可能范围内验证；不兼容组合在调用前拒绝。

**执行绑定：** `version-G02`。**专用正例 P-version-07：** 同名工具改为永久删须重验。**直接失败 D-version-07：** 同名archive工具由移动到归档变为永久删除；预期：按真实副作用及授权重新验证，不能静默继承原批准。**合法邻例 N-version-07：** 新旧模型工具组合按真实可能范围测。

### §08 模型替代与能力保持
**机制：** 备用模型/供应商须满足受影响模态、上下文、结构化输出、工具调用与业务质量要求，并核对数据接收方、地域、费用及原授权。降级不能隐蔽取消产品承诺或核心动作；确实不能提供时明确受影响能力和恢复路径。

**验收：** 结构输出不支持、图片丢弃或工具参数失败时不可悄悄作为正常成功；不扩大外发与费用权限。

**执行绑定：** `version-G02`。**专用正例 P-version-08：** 备用图片能力不足不能假完成。**直接失败 D-version-08：** 回退模型不支持图片却把图像任务标记已完成；预期：保持核心契约或显式报告能力受限，取得必要变更授权。**合法邻例 N-version-08：** 无兼容目标可明确待恢复不擅降承诺。

### §09 检索与嵌入联合切换
**机制：** 记录语料源版本/增量水位、解析切片、嵌入/重排、索引、过滤器与引用定位；查询嵌入和索引空间匹配。重建期间旧新索引分离或采用可验证等效隔离，以完整性与权限对账后切换，不能让部分构建冒充完整。

**验收：** 测试向量维度相同但空间不同、回填缺片、引用坐标变化；查询结果可追到真实来源版本。

**执行绑定：** `version-G03`。**专用正例 P-version-09：** 查询与索引嵌入空间匹配。**直接失败 D-version-09：** 换嵌入模型但复用同维度旧索引导致相关性失真；预期：阻断不兼容空间，完成重建对账并验证引用。**合法邻例 N-version-09：** 同维度不作为空间相容证明。

### §10 知识回退与当前权利优先
**机制：** 回退知识/索引只恢复允许使用的内容版本，不倒退查询时ACL、撤销、删除、保留到期和现行权威状态；旧快照必须叠加当前失效信息，无法证明时隔离受影响数据而非重新公开。

**验收：** 恢复旧索引后已撤权文件不可检索，已替代规范不当作现行；保留必要历史溯源不等于允许重新用于当前决策。

**执行绑定：** `version-G03`。**专用正例 P-version-10：** 回退旧索引叠当前删除ACL。**直接失败 D-version-10：** 旧索引恢复后重新出现昨天删除的私有文件；预期：当前删除与访问权覆盖旧快照，验证派生缓存失效。**合法邻例 N-version-10：** 历史规范可留审计不当现行。

### §11 持久记忆语义迁移
**机制：** 对记忆主体/租户命名空间、来源、有效时间、纠错、撤销、冲突和表示方式定义迁移映射及幂等批次；保留可核验源与迁移水位。不能把新模型重写的总结当新用户事实或授予旧偏好执行权。

**验收：** 跨版本读写保持主体、否决与来源；有损压缩或无法解释的冲突需保留原始合法证据或明确人工处理路径。

**执行绑定：** `version-G03`。**专用正例 P-version-11：** 记忆迁移保主体来源撤回。**直接失败 D-version-11：** 记忆迁移把B用户的拒绝写入A命名空间且丢失来源；预期：阻断跨主体和语义污染，对账受影响批次。**合法邻例 N-version-11：** 有损总结不变新用户事实。

### §12 检查点与运行中任务绑定
**机制：** 检查点关联行为版本、图/节点、状态Schema、任务目标及外部动作身份；升级先确定旧任务在旧轨完成、显式迁移到兼容新轨或受控等待的路径。框架能反序列化不等于业务语义兼容，不强制所有项目采用特定框架。

**验收：** 测试中断节点改名、字段改义、新旧嵌套图及恢复映射；不兼容状态不直接运行，未完成目标仍可追踪。

**执行绑定：** `version-G03`。**专用正例 P-version-12：** 旧checkpoint只走相容轨或迁移。**直接失败 D-version-12：** 旧检查点停在confirm节点，新图改名后恢复跳过确认；预期：阻止错误恢复，采用验证过的映射或旧轨接续。**合法邻例 N-version-12：** 可解析JSON不等于可执行业务。

### §13 兼容矩阵与持续状态写入
**机制：** 枚举实际可能共存的新旧应用、工具、模型、索引、记忆/检查点读写者、异步消息和客户端组合，区分读兼容、写兼容与行为兼容；按保留期和恢复窗口确定边界，不要求穷举不存在的组合。

**验收：** 新写状态必须能由计划中的旧回退版本正确处理，或提前标记该回退不可行并给出受权替代；正反边界有证据。

**执行绑定：** `version-G04`。**专用正例 P-version-13：** 旧回退者能读新写状态。**直接失败 D-version-13：** 新版本写枚举approved-v2，旧版把未知值按批准处理；预期：阻断危险混跑并验证读写/行为兼容。**合法邻例 N-version-13：** 不可行回退提前标明并给受权替代。

### §14 扩展、回填、切换与收缩顺序
**机制：** 复用数据库现行迁移规则：先兼容扩展、幂等回填及对账，再切读写，最后在旧读写者/在途任务/恢复依赖已退出后收缩。Agent语义字段、工具调用格式及索引映射也遵循相应窗口，不强制双写。

**验收：** 部分回填、并发写入和旧Worker滞后可检测，收缩前有真实依赖清零证据及授权。

**执行绑定：** `version-G04`。**专用正例 P-version-14：** 旧消费者退出后才收缩字段。**直接失败 D-version-14：** 灰度10%时删除旧记忆字段，90%旧Worker读失败；预期：收缩前保留兼容结构并验证消费者退出。**合法邻例 N-version-14：** 无双写需要不强制双写。

### §15 不可逆迁移与前向修复
**机制：** 列出不可无损逆转的重写/删除、最后可逆点、新写数据及恢复依赖；不能把降级应用等同数据库倒退。发生不可逆迁移时选择保留新Schema配旧兼容程序、前向修复或经授权的数据恢复，并分别验证新写保留与损失。

**验收：** 有损记忆合并、列删除后不能虚称一键回滚；故障前后新增合法数据不被旧快照无条件覆盖。

**执行绑定：** `version-G04`。**专用正例 P-version-15：** 保留迁移后的合法新数据。**直接失败 D-version-15：** 回滚应用后用昨天快照覆盖今天有效客户修改；预期：拒绝未经授权数据损失，选择可验证前向修复/恢复路径。**合法邻例 N-version-15：** 不可逆状态可选受权前向修复。

### §16 业务副作用与操作身份跨版本保持
**机制：** 模型/代码/状态回退不撤销已经发送、发布、扣款、删除或下游执行的事实。持久业务操作ID、幂等记录及权威回执不随发行版本重置；未知结果先核对目标系统，不因切换模型重新生成动作身份。

**验收：** 在外部写成功而本地记录失败处切版，恢复不重复生效；补偿是独立有权业务动作而非技术版本倒转。

**执行绑定：** `version-G04`。**专用正例 P-version-16：** 跨版本沿原operation核已发事实。**直接失败 D-version-16：** 新模型接手已发送邮件任务后生成新ID再次发送；预期：先对账旧动作及收据，保留身份并阻止重复。**合法邻例 N-version-16：** 技术回滚不等于业务补偿。

### §17 当前授权与安全修复不得倒退
**机制：** 恢复时重验当前主体/对象/受众/费用/有效期限；撤权、审批撤回、已修安全漏洞和出站边界不能随旧配置复活。需要保留旧行为时可使用经验证的兼容适配，不以事故为由提升权限。

**验收：** 安全修复补丁与旧应用组合须有效；旧票据不覆盖新接收方、参数或真实影响，等价接续不制造重复同义确认。

**执行绑定：** `version-G05`。**专用正例 P-version-17：** 旧配置仍服从当前撤权安全补丁。**直接失败 D-version-17：** 旧配置回滚重新启用已封禁外发域和过期审批；预期：执行当前权限及安全约束，拒绝降级扩权。**合法邻例 N-version-17：** 等价原授权接续不重复确认。

### §18 会话粘性与新旧轨隔离
**机制：** 灰度分组按任务/会话/租户的实际一致性需要设置，避免同一长任务在不兼容行为版本间随机跳转。粘性不是安全隔离，仍验证共享状态；旧新轨的写入及后台消费者要有明确所有权。

**验收：** 连续轮次、子任务和队列均能反查所用行为轨；必须跨轨时通过兼容门禁而非仅重定向请求。

**执行绑定：** `version-G05`。**专用正例 P-version-18：** 任务保持相容行为轨。**直接失败 D-version-18：** 两轮对话交替走新旧模板，共享审批状态解释不一致；预期：保持有效行为轨或先验证迁移与共享状态兼容。**合法邻例 N-version-18：** 会话粘性不冒充安全隔离。

### §19 离线影子与真实动作隔离
**机制：** 影子流量或对照试验的候选不得重复生产写入、通知、计费工具及记忆污染；必要模型输入仍受数据发送和费用授权。只读/模拟输出与真正交付分开，不把影子工具结果伪装为真实收据。

**验收：** 复制一次有写能力任务时只有获准主轨能实际生效；影子调用和预算分别可观测。

**执行绑定：** `version-G05`。**专用正例 P-version-19：** 影子工具出口不产生真实写。**直接失败 D-version-19：** 镜像任务令稳定版和候选各创建一份真实订单；预期：隔离候选副作用出口并核对主轨唯一执行。**合法邻例 N-version-19：** 模型影子调用仍需数据费用许可。

### §20 灰度可比证据与信息不足
**机制：** 放量前定义合法任务成功、关键语义错误、越权/泄露、成本及延迟的口径、观察范围、采样/分组和判定方法；按项目风险选择小流量、只读试验或受控替换。低样本、分母缺失、遥测中断为证据不足，不是零失败。

**验收：** 候选与基线的任务分布/模型配置/数据版本差异可解释；必要质量、权限和业务结果不能被平均延迟改善抵消。

**执行绑定：** `version-G05`。**专用正例 P-version-20：** 低样本无遥测为证据不足。**直接失败 D-version-20：** 候选只接简单查询且没有失败遥测，被判优于旧版；预期：标注不可比/证据不足，不自动放量。**合法邻例 N-version-20：** 可比小流量试验可按风险设计。

### §21 明确触发与受权停止路径
**机制：** 为严重越权、数据泄漏、业务不变量破坏及预算失控定义独立硬闸；普通质量/成本退化设置与项目承诺匹配的阈值及观察条件。区分停止放量、停止新动作、隔离受影响路径、回退及继续调查；动作依既有授权执行。

**验收：** 把预设重大故障注入隔离测试后，自动或人工路径能实际阻断受影响执行并保留在途状态；未获操作权时及时上报，不暗自终止用户任务。

**执行绑定：** `version-G06`。**专用正例 P-version-21：** 泄漏硬闸独立于均分。**直接失败 D-version-21：** 泄露一条私有记录仍因总成功率99%继续扩大灰度；预期：硬闸覆盖平均分，按受权路径阻断并保留证据。**合法邻例 N-version-21：** 停止放量不自动取消用户目标。

### §22 回退目标实时可行性
**机制：** 在发布前及真正回退前核实旧联合组合存在、可访问/可运行、供应商仍服务、配置/依赖兼容、数据可读、当前安全约束和获准预算足够。旧模型已下线或只保留可漂移别名时不得承诺精确恢复；提前准备经验证可行的替代。

**验收：** 对旧模型拒绝服务、旧索引被清理、新状态不兼容逐项产生可解释结论，只有真实可行目标才能进入切换。

**执行绑定：** `version-G06`。**专用正例 P-version-22：** 真正回退前核旧模型仍可用。**直接失败 D-version-22：** 旧模型历史ID还在记录里但供应商已经停止服务；预期：判为目标不可用，走获准替代而非循环盲试。**合法邻例 N-version-22：** 不可精确恢复可用已验受权替代。

### §23 单一回退主权与在途收敛
**机制：** 同一目标的切流、配置、模型路由、后台Worker及恢复操作采用单一所有者或CAS/租约栅栏；旧放量作业不可覆盖已生效回退。停止新任务不代表已在途调用停止，需排空/隔离、对账未知外部结果及有效恢复。

**验收：** 旧Promotion延迟到达被拒；模型流式输出、子Agent与队列仍执行时状态如实保留，不能以控制面ACK宣称全退。

**执行绑定：** `version-G06`。**专用正例 P-version-23：** 旧Promotion不能覆盖新回退epoch。**直接失败 D-version-23：** 回退HTTP后新Worker继续消费，旧发布作业又自动升流量；预期：核对所有执行入口和控制器期望态，防止重入。**合法邻例 N-version-23：** 在途远端调用仍需排空或核对。

### §24 恢复后的受控配置冻结
**机制：** 恢复后冻结应用可控的模型选择、提示、工具、检索/状态映射与路由组合，记录冻结范围、负责人、退出条件和必要安全更新路径；自动配置刷新/GitOps不得立即推回故障组合。无法冻结供应商别名时明确残余漂移并监测，不声称冻结了外部服务内部实现。

**验收：** 热配置刷新不能静默改动恢复组合；当前撤权/删除不被冻结，修复后的解除冻结有新证据与授权。

**执行绑定：** `version-G06`。**专用正例 P-version-24：** 冻结可控组合不冻结ACL。**直接失败 D-version-24：** “冻结”恢复配置同时冻结ACL，使已撤权用户继续读取；预期：仅冻结受控行为配置，当前权利与安全更新持续生效。**合法邻例 N-version-24：** 供应商别名不可冻结如实监测。

### §25 回退后的实效验证与遗留责任
**机制：** 分别核对实际运行版本、合法关键任务恢复、当前授权、持久数据完整性、外部回执及预算；保留仍失败/未知/待补偿项和负责处理路径。恢复正常新请求不代表旧任务已经履约。

**验收：** 可定位到受影响任务的实际结局，明确完成、未完成与不可逆影响；观察窗口覆盖风险相关延迟任务。

**执行绑定：** `version-G07`。**专用正例 P-version-25：** 健康新请求与旧未决任务分列。**直接失败 D-version-25：** 旧版健康检查200但已扣款未交付的任务被关单；预期：业务对账及遗留任务单独跟踪，不以恢复健康掩盖。**合法邻例 N-version-25：** 不能以200抹未交付已扣款。

### §26 退役、弃用与保留窗口
**机制：** 按供应商下线通知、在途任务/客户端、备份、回退窗口及合法保留要求管理旧模型、工具、索引、状态转换器和制品退出。确认替代路径及未完成依赖后再按权限清理，不无限保留已删除数据来满足可复现。

**验收：** 仍依赖旧工具回执的任务不会被提前丢弃；外部模型到期前明确迁移选项，退出/删除操作另循项目权限。

**执行绑定：** `version-G07`。**专用正例 P-version-26：** 依赖退尽再退役转换器。**直接失败 D-version-26：** 清理旧工具转换器后历史未完成任务无法恢复；预期：先处理残留依赖及合法保留，再执行受权退役。**合法邻例 N-version-26：** 删除权优先不为复现无限保留秘密。

### §27 证据、隐私与可追踪限制
**机制：** 记录变更原因、联合版本差异、实际模型/环境、选择性验证理由、正反结果、灰度判定、授权/执行、恢复和未解决项。最小必要证据受控保存，脱敏或到期删除不得伪称完整逐字重现；失败证据不为美化结果被篡改。

**验收：** 审查者可在权限内定位一次选择/切换的依据，区分未测、失败和通过；只保留必要参数摘要而非秘密与全量个人正文。

**执行绑定：** `version-G07`。**专用正例 P-version-27：** 原失败及修正摘要可追溯。**直接失败 D-version-27：** 删掉失败样本只留绿色汇总，并把无法重现写成完全复现；预期：保留真实失败与限制，提供受控可追溯证据。**合法邻例 N-version-27：** 脱敏后不宣称完整逐字复现。

### §28 分层责任与项目采用边界
**机制：** 本专题规定应用联合版本和语义回退门禁，按实际采用关系组合模型/授权/知识/记忆、后端、数据库、云规范；各专题采用以准确版本的有效决定为准。L5实现实际供应商/框架机制，L6决定真实部署、费用、数据和客户承诺。本规范采用由有权决定适用范围的主体按 L1 登记，不能代替 L6 项目授权。

**验收：** 规范采用、静态 CI、模型实测与生产授权分别取得对应证据；依真实产品需求选最小实现，不用免责文字替代已承诺核心功能。

**执行绑定：** `version-G07`。**专用正例 P-version-28：** 规范采用与项目运行分别决议。**直接失败 D-version-28：** 仅凭 PR 检查通过便部署真实客户，并将无关条款用作强制依据；预期：只消费适用的现行义务，真实生产与业务分别授权验收。**合法邻例 N-version-28：** 技术CI不授费用生产或共享权。

## 五、最小项目应用记录及分层验证

项目可用一份受控发布记录而非复杂平台实现以下闭环：

1. 写明本次目标、旧新联合版本、改变与不改变项、实际受影响用户/任务/状态、授权及费用边界。
2. 列出真实兼容组合、在途任务接续路径、可逆时点、不可逆项和可用的回退/前向修复目标。
3. 逐路径决定需重测内容与可复用证据及理由。静态/模拟、真实模型行为、协议/存储/控制器集成和L6业务结果分别记录；不因本规范统一要求每次全量重测，不以模拟替代必要真实边界验证。
4. 放量前记录项目适用的成功/失败口径、硬闸、普通退化阈值、可比条件、证据不足处理、观察结束条件与执行权限。无灰度条件时可受控替换，但仍需必要基线和恢复路径。
5. 恢复后核对实际版本、持久状态、授权及外部事实，记录残余任务、合法补偿、受控冻结与退出条件。当前删除、撤权及安全修复不随历史状态倒退。

联合版本记录可以采用不可变标识加受控动态水位；不能要求将不允许长期保留的客户原文固化入库。对外部不可观察或已停服模型明确复现限制，提供已验证替代及剩余风险；不虚构恢复能力。L5决定具体实现与实际工具兼容，L6批准真实生产、数据、资金及客户承诺，L4不代替产品决策。

## 六、生命周期与采用

项目按 L1 登记所采用的准确版本、适用条款和依赖关系。L5 选择并验证实际实现，L6 按真实权利及目标验收业务结果；实现验收以相应项目的执行证据为准。
