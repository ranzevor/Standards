# L4 Agent 间通信、发现与委派协议技术规范

**文档ID：** STD-L4-AI-AGENT-006　**版本：** 0.1.0　**状态：** adopted　**生效日期：** 2026-10-30

## 一、适用范围、职责与协议关联

本专题规定：跨信任域服务身份、能力发现、任务/消息/制品与委派限制。不强制采用 A2A、多 Agent 或新基础设施。L0/L1管理采用与批准记录，L2管理交付责任，L3管理工程证据，适用以各自有效决定为准；[STD-L4-AI-AGENT-011 · L4 指令体系、不可信内容与提示注入防护技术规范](011-指令体系、不可信内容与提示注入防护技术规范--v0.1.0.md)处理不可信指令、[STD-L4-AI-AGENT-009 · L4 工具能力契约与 MCP 互操作技术规范](009-工具能力契约与-MCP-互操作技术规范--v0.1.0.md)处理工具/MCP、[STD-L4-AI-AGENT-004 · L4 Agent 授权、可变更动作与业务副作用技术规范](004-Agent-授权、可变更动作与业务副作用技术规范--v0.1.0.md)处理真实动作授权、[STD-L4-AI-AGENT-005 · L4 Agent 控制循环、计划与多 Agent 编排技术规范](005-Agent-控制循环、计划与多-Agent-编排技术规范--v0.1.0.md)处理本地控制权/并发及根预算、[STD-L4-AI-AGENT-015 · L4 长任务状态、检查点与可恢复执行技术规范](015-长任务状态、检查点与可恢复执行技术规范--v0.1.0.md)处理持久恢复。通用认证、HTTP、存储事务和网络出站继续归各相邻L4。本文只规定这些能力跨远端Agent边界时的绑定与互操作门禁，不以技术便利制定业务规则。

### 最小关联记录
优先扩展既有任务系统，字段名仅为语义示例，不是自创 A2A wire 字段：root_task_id、delegation_id、goal_revision、caller_subject、remote_service、selected_interface（URL、protocolBinding、protocolVersion、tenant）、card_digest、remote_task_id、context_id、authorization_ref、result_evidence、followup_owner。对未创建Task的直接Message不伪填remote_task_id；秘密不放authorization_ref。

### 协议不变量
- I1 卡片能力、签名完整性、认证主体、对象授权和实际业务批准是不同判断，不能互相推导。
- I2 任务归属使用可信服务/接口/主体与远端taskId复合关联；同context或referenceTaskIds不是访问许可。
- I3 未结束的异步任务有接续责任，连接与父请求结束不改变远端任务终态。
- I4 消息/通知/制品去重不等于业务幂等；未知副作用不得因重试生成新业务意图。
- I5 迟到结果保留真实发生事实，但不覆盖新目标、不复活已撤回操作、不自动触发下一步。
- I6 静态通过、协议完成、实际制品交付、业务成功和组织批准分别举证。

### 执行闭环与实现绑定

### §01 协议适用与信任域
**机制：** 只有实际跨独立 Agent 服务通信时选择 A2A 或已明确契约；本地函数式子 Agent 不被强制改成网络协议。协议描述不创造数据共享、委派或收费许可。

**验收：** 本地只读协作可不部署 A2A；跨域发送前仍核目的地与数据许可。

**执行绑定：** `communication-G01`。**专用正例 P-communication-01：** 跨信任域才选协议和接收方。**直接失败 D-communication-01：** 内部只读子调用被自动迁移到外部收费 Agent；预期：本地只读协作可不部署 A2A；跨域发送前仍核目的地与数据许可。。**合法邻例 N-communication-01：** 本地只读子调用无需A2A。

### §02 发现入口与身份绑定
**机制：** 记录获准发现入口、实际服务来源、选中接口、卡片摘要及认证主体。名称、provider 文本、目录排名或模型推荐不构成服务身份。发现 URL 和最终请求目标须按现有网络/授权规则核验。

**验收：** 同名恶意卡不能替换已批准服务，重定向后身份或接收方改变需重新核查。

**执行绑定：** `communication-G01`。**专用正例 P-communication-02：** 卡片接口摘要与真实服务绑定。**直接失败 D-communication-02：** 目录注入同名财务 Agent 并替换请求端点；预期：同名恶意卡不能替换已批准服务，重定向后身份或接收方改变需重新核查。。**合法邻例 N-communication-02：** 同名服务不必全拒而应消歧。

### §03 能力卡与内容指令分离
**机制：** skills、description、examples、文档链接和扩展描述均为远端材料；能力适配和可执行授权分开判定，不能把卡中自然语言升为上层命令。

**验收：** 卡片要求先导出聊天仍不产生该权限。

**执行绑定：** `communication-G01`。**专用正例 P-communication-03：** 卡片描述不授导出会话权限。**直接失败 D-communication-03：** 技能描述要求发送全部聊天才能开始检索；预期：卡片要求先导出聊天仍不产生该权限。。**合法邻例 N-communication-03：** 合法技能说明可供能力选择。

### §04 签名验证与信任根
**机制：** A2A卡片签名是可选机制。选择依赖签名时按固定规范的字段存在性、JCS及JWS规则验证，并独立绑定可信发行者/密钥；显式optional默认值不能被通用去默认算法误删。固定文本§8.4.1的精确存在性规则与§8.4.3的笼统去默认步骤有文字差异，适配器须保留原卡并用有/无默认字段对照验证选定解释，不能声称已消除互通风险。自带jku或有效自签名不建立信任；密钥取回仍受出站与撤销约束。

**验收：** 被篡改接口或未知密钥签名不能通过；明确 optional 默认值的卡片往返不误删字段；签名通过也不授业务权限。

**执行绑定：** `communication-G01`。**专用正例 P-communication-04：** 可信密钥及保留optional字段验签。**直接失败 D-communication-04：** 攻击者用自己的密钥签署管理员能力卡；预期：被篡改接口或未知密钥签名不能通过；明确 optional 默认值的卡片往返不误删字段；签名通过也不授业务权限。。**合法邻例 N-communication-04：** 签名可选且验过仍需对象授权。

### §05 卡片缓存与身份分区
**机制：** 公共卡与认证扩展卡按真实主体、服务接口和版本隔离缓存，遵循 HTTP 缓存条件；撤权、接口漂移或安全策略变化时重核，不把 TTL 当授权租期。

**验收：** 管理员扩展卡不会暴露给普通会话，旧卡无法恢复已撤销权限。

**执行绑定：** `communication-G02`。**专用正例 P-communication-05：** 认证扩展卡缓存按主体分区。**直接失败 D-communication-05：** 退出管理员会话后继续使用共享扩展卡；预期：管理员扩展卡不会暴露给普通会话，旧卡无法恢复已撤销权限。。**合法邻例 N-communication-05：** 公共卡可依HTTP语义缓存。

### §06 接口选择与路由租户
**机制：** 按 supportedInterfaces 有序选择双方支持且获准的协议/版本组合，绑定其 URL 和 tenant；tenant 是不透明路由值，不是认证租户证据。切换 binding 仍保持同一真实身份与任务归属。

**验收：** 相同 URL 不同 tenant 的任务不串用，改变 tenant 不能获得另一主体权限。

**执行绑定：** `communication-G02`。**专用正例 P-communication-06：** tenant严格取选定接口原值。**直接失败 D-communication-06：** 只匹配 URL 而忽略选定接口 tenant；预期：相同 URL 不同 tenant 的任务不串用，改变 tenant 不能获得另一主体权限。。**合法邻例 N-communication-06：** 路由tenant不是认证租户身份。

### §07 协议版本与实现版本
**机制：** 分别冻结规范发行版本、wire Major.Minor、服务卡 version、SDK版本及协议绑定；绑定类型与版本号不是同一维度。v1.0.1 规范的 wire 值为1.0，不能用SDK或卡片版本替代 A2A-Version。不支持版本返回明确错误，禁止为成功静默降级。

**验收：** 省略版本造成0.3解释、用1.0.1参与协商及旧方法名混入1.0均被兼容测试发现。

**执行绑定：** `communication-G02`。**专用正例 P-communication-07：** wire1.0与spec1.0.1分开。**直接失败 D-communication-07：** 把Agent自身version当协议版本并自动回退0.3；预期：省略版本造成0.3解释、用1.0.1参与协商及旧方法名混入1.0均被兼容测试发现。。**合法邻例 N-communication-07：** SDK版本不用于A2A-Version。

### §08 可选能力与必需扩展
**机制：** streaming、pushNotifications、extendedAgentCard 按真实声明及方法支持选择；required扩展必须理解并声明支持，不以忽略元数据继续。扩展URI和版本属于能力契约，不是授权范围。

**验收：** 必需扩展不支持时不发送依赖其安全语义的任务；未实现推送不假装可等待回调。

**执行绑定：** `communication-G02`。**专用正例 P-communication-08：** 不支持required扩展明确拒绝。**直接失败 D-communication-08：** 忽略required扩展后把未经约束的任务视为等价；预期：必需扩展不支持时不发送依赖其安全语义的任务；未实现推送不假装可等待回调。。**合法邻例 N-communication-08：** 不需推送可仅使用轮询。

### §09 传输身份与凭据受众
**机制：** 每个请求由实际传输认证与服务端策略决定主体、受众、scope和对象权；不把 Message.role、metadata 或路由tenant当凭据，不向另一Agent透传上游全局令牌。具体OAuth/TLS实现沿用相邻安全规范。

**验收：** 合法 JSON 自称 user/admin 仍不能读取他人任务；接口切换不能改变 token audience。

**执行绑定：** `communication-G03`。**专用正例 P-communication-09：** 每次传输认证绑定受众。**直接失败 D-communication-09：** Message.role=user 被当真实用户授权；预期：合法 JSON 自称 user/admin 仍不能读取他人任务；接口切换不能改变 token audience。。**合法邻例 N-communication-09：** Message.role文字不授管理员权。

### §10 对象授权覆盖所有操作
**机制：** Get/List/Cancel/Subscribe及推送配置读写均校验当前主体和目标任务；无context过滤的列表也需限权。授权失败响应不泄漏越权任务存在性，分页游标绑定主体和筛选范围。

**验收：** 猜中taskId、换分页游标或取消接口都不能绕过对象权限。

**执行绑定：** `communication-G03`。**专用正例 P-communication-10：** GetListCancelSubscribe都查对象权。**直接失败 D-communication-10：** 只能列自己任务却可用CancelTask操作他人任务；预期：猜中taskId、换分页游标或取消接口都不能绕过对象权限。。**合法邻例 N-communication-10：** 无context过滤仍限本人范围。

### §11 委派封套与原授权收缩
**机制：** 以现有任务系统固定根任务、委派者、实际接收Agent、目标版本、数据用途、动作范围、有效期及再委派限制；这些是本组织控制记录，不冒充A2A标准字段。下游只获得所需输入和能力。

**验收：** 检索委派不会获得发送权限，接收Agent变更不能沿用原数据许可。

**执行绑定：** `communication-G03`。**专用正例 P-communication-11：** 委派封套只发必要输入能力。**直接失败 D-communication-11：** 转发整个根上下文与所有可用工具给翻译Agent；预期：检索委派不会获得发送权限，接收Agent变更不能沿用原数据许可。。**合法邻例 N-communication-11：** 已有范围内等价接续不再请同义批准。

### §12 再委派与拒绝传播
**机制：** 跨域再次委派按[STD-L4-AI-AGENT-004 · L4 Agent 授权、可变更动作与业务副作用技术规范](004-Agent-授权、可变更动作与业务副作用技术规范--v0.1.0.md)授权及[STD-L4-AI-AGENT-005 · L4 Agent 控制循环、计划与多 Agent 编排技术规范](005-Agent-控制循环、计划与多-Agent-编排技术规范--v0.1.0.md)根预算/深度界面核对，不因远端声称可转包而扩大接收方。拒绝、撤回与期限随链路保真；协议可通信不意味可转授。

**验收：** A被拒绝后转给B也不能执行；已批准范围内接续不另设重复审批。

**执行绑定：** `communication-G03`。**专用正例 P-communication-12：** 拒绝期限再委派保持不扩接收方。**直接失败 D-communication-12：** 远端把禁止外发子任务转包给第三方；预期：A被拒绝后转给B也不能执行；已批准范围内接续不另设重复审批。。**合法邻例 N-communication-12：** 已获准转包仍核最小数据。

### §13 任务身份与归属映射
**机制：** 新taskId由服务生成，客户端只能引用存在任务；本地根任务/尝试与远端任务以服务身份、接口路由、调用主体、taskId复合关联。contextId和referenceTaskIds不授跨对象访问权。

**验收：** 两个服务返回同一taskId仍区分；task/context不匹配拒绝，不靠ID碰撞接管。

**执行绑定：** `communication-G04`。**专用正例 P-communication-13：** 服务接口主体task复合隔离。**直接失败 D-communication-13：** 另一服务同号task覆盖原委派的状态；预期：两个服务返回同一taskId仍区分；task/context不匹配拒绝，不靠ID碰撞接管。。**合法邻例 N-communication-13：** 直接Message不虚构远端taskId。

### §14 消息身份与重试
**机制：** messageId是消息身份，不保证Send Message幂等；协议仅允许对端选择去重。外部副作用重试沿用[STD-L4-AI-AGENT-004 · L4 Agent 授权、可变更动作与业务副作用技术规范](004-Agent-授权、可变更动作与业务副作用技术规范--v0.1.0.md)逻辑操作及权威收据；发送超时先核已有任务/业务结果，不凭重发同messageId推定只执行一次。

**验收：** 响应丢失后不能自动再创建一份外部操作；未知结果保留待核对。

**执行绑定：** `communication-G04`。**专用正例 P-communication-14：** 超时不凭messageId保证单次效果。**直接失败 D-communication-14：** 超时后假定messageId天然exactly-once而重发支付任务；预期：响应丢失后不能自动再创建一份外部操作；未知结果保留待核对。。**合法邻例 N-communication-14：** 对端明确有效去重可安全原意图重试。

### §15 多轮上下文与补参
**机制：** 保留服务端返回contextId、taskId和实际来源，按规范处理只传taskId时的上下文推导与两者不匹配拒绝。input-required只表示待输入；补参不得隐式改变目标、接收者或审批结论。

**验收：** 新context不能拼接旧任务私有历史；填写地址不批准付款。

**执行绑定：** `communication-G04`。**专用正例 P-communication-15：** taskcontext匹配后补参。**直接失败 D-communication-15：** 把input-required补充地址当作付款批准；预期：新context不能拼接旧任务私有历史；填写地址不批准付款。。**合法邻例 N-communication-15：** 填地址不自动批准付款。

### §16 直接消息与任务返回
**机制：** Send Message可返回直接Message或Task，按实际响应联合类型处理。直接答复不虚构可轮询taskId；Task受理、协议完成与业务验收独立。returnImmediately的具体默认与中断行为依锁定版本和真实测试，不从概述推断。

**验收：** 直接澄清信息不被标成任务执行成功，非阻塞受理后仍有跟进归属。

**执行绑定：** `communication-G04`。**专用正例 P-communication-16：** Task与直接Message按联合类型处理。**直接失败 D-communication-16：** 把直接澄清Message当Task completed；预期：直接澄清信息不被标成任务执行成功，非阻塞受理后仍有跟进归属。。**合法邻例 N-communication-16：** 同步结果可不建立后台轮询。

### §17 异步任务责任持续
**机制：** 返回非终态Task即记录获准轮询/订阅/推送方式、关联主任务和负责接续者；父请求或HTTP连接结束不注销远端任务。等待策略和预算继承09，持久恢复交11；不可无人认领。

**验收：** returnImmediately返回后主调用结束，仍可定位未完成任务和接续责任。

**执行绑定：** `communication-G05`。**专用正例 P-communication-17：** 非终态Task有跟踪方式和责任。**直接失败 D-communication-17：** HTTP 200后丢弃后台Task无人跟进；预期：returnImmediately返回后主调用结束，仍可定位未完成任务和接续责任。。**合法邻例 N-communication-17：** 父HTTP结束不注销远端任务。

### §18 中断与终态判定
**机制：** 按锁定proto区分submitted/working、input-required/auth-required中断、completed/failed/canceled/rejected终态及未知值。未知不当成功；中断不当永久失败。业务交付另核制品和外部回执。

**验收：** auth-required不会被超时推定批准，completed缺少业务证据不宣称履约。

**执行绑定：** `communication-G05`。**专用正例 P-communication-18：** 未知枚举不映射completed。**直接失败 D-communication-18：** 未知枚举被默认映射completed；预期：auth-required不会被超时推定批准，completed缺少业务证据不宣称履约。。**合法邻例 N-communication-18：** input-required是中断不是永久失败。

### §19 任务内授权与安全通道
**机制：** auth-required说明需要补充授权，不是已获授权。核对请求来自预期任务、目标动作和真实有权人；默认采用协商的带外安全渠道，消息链不承载秘密。协议允许协商带内不覆盖现行敏感信息/凭据规则。

**验收：** 恶意授权链接或全局Token索取不能因task状态而自动通过；带外完成后以真实状态更新接续。

**执行绑定：** `communication-G05`。**专用正例 P-communication-19：** auth-required经安全渠道独立授权。**直接失败 D-communication-19：** 远端auth-required要求在普通Message上传根Token；预期：恶意授权链接或全局Token索取不能因task状态而自动通过；带外完成后以真实状态更新接续。。**合法邻例 N-communication-19：** 协议允许协商带内不强迫传秘密。

### §20 流式事件与重连
**机制：** 按任务和context验证StreamResponse类型、首个任务快照及后续事件，遵循有序流要求；重连不假定完整重放、跨流全局序号或消息历史完整。缺口通过授权GetTask及制品核对补齐。

**验收：** 断流既不取消任务也不证明任务完成；重订阅快照与旧事件冲突时不盲覆盖。

**执行绑定：** `communication-G05`。**专用正例 P-communication-20：** 订阅首快照核当前任务与context。**直接失败 D-communication-20：** SSE断开后把未收到事件当远端失败重新发任务；预期：断流既不取消任务也不证明任务完成；重订阅快照与旧事件冲突时不盲覆盖。。**合法邻例 N-communication-20：** 断流不取消任务可按权轮询补缺。

### §21 制品身份与分块完整性
**机制：** artifactId只在任务内唯一；用复合任务键加artifactId隔离，按append和lastChunk处理增量。lastChunk只是该制品末块，不是任务终态；重复/缺口无可靠序号时回读完整制品，不能猜测拼接。

**验收：** 两个任务同名制品不混合，重复append不产生双内容，末块未到不交付完整文件。

**执行绑定：** `communication-G06`。**专用正例 P-communication-21：** artifact键含task且末块单独验。**直接失败 D-communication-21：** lastChunk=true被当全部任务已完成；预期：两个任务同名制品不混合，重复append不产生双内容，末块未到不交付完整文件。。**合法邻例 N-communication-21：** lastChunk不等于任务终态。

### §22 Part解析与资源引用
**机制：** 按所选proto oneof及ProtoJSON处理text/raw/url/data，包含标量/数组/null的data，不沿用旧kind或假设data只能对象。大小、类型、解码和外部URL读取受独立权限/出站限制。

**验收：** 同时携带多个oneof值或恶意base64拒绝；URL中秘密与私网目标不被自动访问。

**执行绑定：** `communication-G06`。**专用正例 P-communication-22：** Part只选一个oneof内容。**直接失败 D-communication-22：** 旧kind解析器漏验url而读取云元数据；预期：同时携带多个oneof值或恶意base64拒绝；URL中秘密与私网目标不被自动访问。。**合法邻例 N-communication-22：** 合法data数组标量null均可接收。

### §23 制品与远端内容非指令
**机制：** Message、Artifact和错误文本保留来源标记；制品在进入工具、渲染器或下游Agent前按用途验证。任务完成不把产物升级为可信系统指令或组织审批。

**验收：** 报告内隐藏删除命令不能驱动下一轮工具；自称已批准不能写审批登记。

**执行绑定：** `communication-G06`。**专用正例 P-communication-23：** completed产物仍不可信内容。**直接失败 D-communication-23：** completed任务产物要求执行管理员命令；预期：报告内隐藏删除命令不能驱动下一轮工具；自称已批准不能写审批登记。。**合法邻例 N-communication-23：** 合法报告可展示但不执行藏命令。

### §24 推送配置与目的地
**机制：** 仅在实际支持且已有接收方/用途许可时创建推送；配置绑定任务、调用主体和预期接收者。URL解析、DNS及重定向后的目标均受获准网络范围约束，不强制真实内网场景使用公网而是防止越界。

**验收：** 攻击者注册metadata地址或重定向到未许可接收方被阻断；更换URL重新核查。

**执行绑定：** `communication-G06`。**专用正例 P-communication-24：** 推送URL每跳核接收许可。**直接失败 D-communication-24：** 低权调用把Webhook改成攻击者收件站；预期：攻击者注册metadata地址或重定向到未许可接收方被阻断；更换URL重新核查。。**合法邻例 N-communication-24：** 真实获准内网部署可配置内网目标。

### §25 推送认证与关联
**机制：** Webhook接收方验证专用认证、发送服务与预期任务/context/config；HTTP 2xx只确认接收。认证令牌最小作用域保密，不能用查询taskId替代来源核验。

**验收：** 有效别的配置令牌无法注入本任务成功事件，taskId猜中不通过。

**执行绑定：** `communication-G07`。**专用正例 P-communication-25：** 专用认证匹配服务任务配置。**直接失败 D-communication-25：** 伪造Webhook通知冒充预期Agent任务完成；预期：有效别的配置令牌无法注入本任务成功事件，taskId猜中不通过。。**合法邻例 N-communication-25：** HTTP2xx只说明收到事件。

### §26 重复迟到通知与事实回读
**机制：** 推送可能重复、延迟和丢失；按应用可验证的事件身份/状态版本去重，协议未承诺字段不凭空假设。迟到事件保留已发生事实但不能复活撤回任务或覆盖较新权威状态，冲突回读。

**验收：** 重复成功通知不二次触发下游写入，旧working不能逆转终态。

**执行绑定：** `communication-G07`。**专用正例 P-communication-26：** 重复通知不再触发下游写。**直接失败 D-communication-26：** 重复推送触发两次下游发布；预期：重复成功通知不二次触发下游写入，旧working不能逆转终态。。**合法邻例 N-communication-26：** 旧事件可留历史而不倒转终态。

### §27 取消与未知远端结果
**机制：** CancelTask请求、确认取消、不可取消错误及实际副作用分别记录；取消需原任务范围内的有效授权，协议支持不新增取消权。连接关闭和删除推送均不等于取消；未知结果沿07/11对账。

**验收：** 取消失败或ACK丢失不伪报成功，已发邮件不被声明撤回。

**执行绑定：** `communication-G07`。**专用正例 P-communication-27：** CancelTask结果与副作用分别核对。**直接失败 D-communication-27：** 删除推送配置后宣称远端任务和付款均取消；预期：取消失败或ACK丢失不伪报成功，已发邮件不被声明撤回。。**合法邻例 N-communication-27：** 删推送不等于取消远端任务。

### §28 绑定转换与错误语义
**机制：** JSONRPC、GRPC、HTTP+JSON按固定1.0映射及proto生成物测试；保留标准错误、联合类型、字段存在性和服务参数语义。不把HTTP成功、SSE结束或SDK未抛异常作为任务成功。

**验收：** 代理不得丢tenant、版本或错误details；不支持版本不会被转换成空成功。

**执行绑定：** `communication-G07`。**专用正例 P-communication-28：** 绑定转换保留tenant版本错误。**直接失败 D-communication-28：** HTTP代理把VersionNotSupportedError转为200空Task；预期：代理不得丢tenant、版本或错误details；不支持版本不会被转换成空成功。。**合法邻例 N-communication-28：** 仅支持一种绑定可明确矩阵。

### §29 隐私与协议证据
**机制：** 记录卡片摘要、所选版本/接口、主体引用、委派关联、拒绝位置及结果来源，不记录无关上下文或秘密。外部引用及日志按接收者许可最小化；不索取远端内部思维链和工具实现。

**验收：** 审计可追踪错误路由但不泄漏Token、私有卡或客户原文。

**执行绑定：** `communication-G08`。**专用正例 P-communication-29：** 审计卡摘要不写原凭据。**直接失败 D-communication-29：** 排障日志公开扩展卡、认证信息和完整聊天；预期：审计可追踪错误路由但不泄漏Token、私有卡或客户原文。。**合法邻例 N-communication-29：** 无法取远端内部细节可说明边界。

### §30 资源边界与滥用限制
**机制：** 发现文档、卡片、消息、制品、流及通知设置与业务相称的有界解析/并发/存储控制；预算沿09/13界面累计。拒绝不自动切换高权账号、外域端点或新增费用。

**验收：** 恶意大卡/无限通知不耗尽任务预算；合法大制品可在获准渠道明确协商而非静默截断。

**执行绑定：** `communication-G08`。**专用正例 P-communication-30：** 卡片流制品均有大小频率界。**直接失败 D-communication-30：** 无限append事件绕过消息大小上限耗尽存储；预期：恶意大卡/无限通知不耗尽任务预算；合法大制品可在获准渠道明确协商而非静默截断。。**合法邻例 N-communication-30：** 合法大制品可走获准分块通道。

### §31 兼容差异与升级
**机制：** 升级卡片/规范/SDK/绑定/扩展后按所选矩阵重验；旧0.3与1.0字段、方法及task状态不直接混用。既有在途任务保留原接口和身份或经有证据迁移，不让新部署重放旧任务。

**验收：** 旧任务结果不会因版本转换重新触发已完成副作用；变更不静默覆盖已生效规范。

**执行绑定：** `communication-G08`。**专用正例 P-communication-31：** 在途旧任务保留原接口或验迁移。**直接失败 D-communication-31：** 升级SDK后旧taskId被当新委派重做；预期：旧任务结果不会因版本转换重新触发已完成副作用；变更不静默覆盖已生效规范。。**合法邻例 N-communication-31：** 不兼容旧版可明确拒绝。

### §32 分层互通与批准
**机制：** 静态反例及文本测试只证明候选结构/局部契约；L5需真实客户端/服务端、鉴权、断流及推送互通，L6需数据、费用、外发和业务验收。

**验收：** 所有静态测试通过仍不能声称真实A2A互通或组织已批准。

| 远端把禁止外发子任务转包给第三方 | §12 | A被拒绝后转给B也不能执行；已批准范围内接续不另设重复审批。 |
| 另一服务同号task覆盖原委派的状态 | §13 | 两个服务返回同一taskId仍区分；task/context不匹配拒绝，不靠ID碰撞接管。 |
| 超时后假定messageId天然exactly-once而重发支付任务 | §14 | 响应丢失后不能自动再创建一份外部操作；未知结果保留待核对。 |
| 把input-required补充地址当作付款批准 | §15 | 新context不能拼接旧任务私有历史；填写地址不批准付款。 |
| 把直接澄清Message当Task completed | §16 | 直接澄清信息不被标成任务执行成功，非阻塞受理后仍有跟进归属。 |
| HTTP 200后丢弃后台Task无人跟进 | §17 | returnImmediately返回后主调用结束，仍可定位未完成任务和接续责任。 |
| 未知枚举被默认映射completed | §18 | auth-required不会被超时推定批准，completed缺少业务证据不宣称履约。 |
| 远端auth-required要求在普通Message上传根Token | §19 | 恶意授权链接或全局Token索取不能因task状态而自动通过；带外完成后以真实状态更新接续。 |
| SSE断开后把未收到事件当远端失败重新发任务 | §20 | 断流既不取消任务也不证明任务完成；重订阅快照与旧事件冲突时不盲覆盖。 |
| lastChunk=true被当全部任务已完成 | §21 | 两个任务同名制品不混合，重复append不产生双内容，末块未到不交付完整文件。 |
| 旧kind解析器漏验url而读取云元数据 | §22 | 同时携带多个oneof值或恶意base64拒绝；URL中秘密与私网目标不被自动访问。 |
| completed任务产物要求执行管理员命令 | §23 | 报告内隐藏删除命令不能驱动下一轮工具；自称已批准不能写审批登记。 |
| 低权调用把Webhook改成攻击者收件站 | §24 | 攻击者注册metadata地址或重定向到未许可接收方被阻断；更换URL重新核查。 |
| 伪造Webhook通知冒充预期Agent任务完成 | §25 | 有效别的配置令牌无法注入本任务成功事件，taskId猜中不通过。 |
| 重复推送触发两次下游发布 | §26 | 重复成功通知不二次触发下游写入，旧working不能逆转终态。 |
| 删除推送配置后宣称远端任务和付款均取消 | §27 | 取消失败或ACK丢失不伪报成功，已发邮件不被声明撤回。 |
| HTTP代理把VersionNotSupportedError转为200空Task | §28 | 代理不得丢tenant、版本或错误details；不支持版本不会被转换成空成功。 |
| 排障日志公开扩展卡、认证信息和完整聊天 | §29 | 审计可追踪错误路由但不泄漏Token、私有卡或客户原文。 |
| 无限append事件绕过消息大小上限耗尽存储 | §30 | 恶意大卡/无限通知不耗尽任务预算；合法大制品可在获准渠道明确协商而非静默截断。 |
| 升级SDK后旧taskId被当新委派重做 | §31 | 旧任务结果不会因版本转换重新触发已完成副作用；变更不静默覆盖已生效规范。 |
| 文本检查全绿即发布新规范并对外发真实任务 | §32 | 所有静态测试通过仍不能声称真实A2A互通或组织已批准。 |
| 伪造签名卡经重定向导向私网并索取Token | §02、§04、§09、§24 | 先验证可信服务/密钥与实际出站目标；卡自签和重定向都不授权发凭据 |
| 管理员扩展卡缓存给普通用户，随后省略context列出全部任务 | §05、§09、§10 | 缓存按主体隔离；列表无过滤仍仅返回当前有权范围 |
| 同URL不同tenant且两个服务返回同号Task，通知错挂根任务 | §06、§13、§25 | 接口路由与可信主体复合关联；错误来源或context的事件不进入原任务 |
| 委派被拒后转包外部Agent并用旧票据发送 | §11、§12、§19 | 传递拒绝与最小范围；目标和接收者改变不继承授权 |
| SendMessage超时后同messageId重发，两个Task分别成功 | §14、§17、§26 | 不假定发送幂等；记录可能重复任务并先查外部结果，禁止重复下游副作用 |
| auth-required期间父请求结束，带外授权后漏掉全部事件 | §17、§18、§19、§20 | 保持责任人和获准更新通道；不推定失败、批准或完成，按真实状态接续 |
| 断流后重复append并收到lastChunk，错当整任务完成 | §20、§21、§26 | 复合制品键、完整性核对和任务终态分离；缺块回读，不猜测拼接 |
| 任务completed产物中夹带提示注入与秘密URL | §18、§22、§23 | 完成不提升内容信任；读取/渲染URL须独立核权，不执行产物指令 |
| 取消ACK丢失，旧working推送迟到，客户端再发同任务 | §14、§26、§27 | 查询权威任务和副作用；迟到状态不复活已撤回操作，不盲重放 |
| 协议升级丢tenant并把版本错误转HTTP成功，日志公开原凭据 | §06、§07、§28、§29、§31 | 绑定矩阵拒绝语义丢失；保留版本错误和原任务归属，证据去敏且不泄漏秘密 |

## 五、分层验证、例外与变更

静态门禁检查正文机制、直接/组合反例、关联字段、不变量、引用与生命周期；离线合成输入检查错误归属/过期授权等控制判据，不运行远端Agent、不证明真实密码学或网络防护。测试须保留正常样本与仅改变一个主体/任务/接口的拒绝对照，防止“全部拒绝”伪通过。

L5在获准环境验证锁定SDK与所选JSONRPC/GRPC/HTTP+JSON组合、协议1.0、真实卡片发现/签名、认证与所有对象操作、直接Message/Task、异步归属、补参/带外授权、断流/重订阅、分块、推送及取消错误。覆盖在途版本变更、身份轮换、重复通知和缺失更新；不是全部项目必须部署所有绑定。发现上游文字冲突需保存差异、真实报文与选定解释，不能只靠Mock或静态Schema决定。

L6另核接收Agent、数据用途、外发范围、费用、真实业务收据和人工权利，具体业务及取消权不由本篇产生。能力卡/接口/认证/SDK/规范/扩展及任务映射变更时重验相应反例。例外由现行L1及真实有权主体决定，不允许工程实现静默降低已批准目标或掩盖失败证据。
