## 一、范围、技术分工与最小控制契约

### 控制记录的最小语义

字段名是说明性命名，不是新互操作协议；同进程简单实现可内联，但不能省略适用语义。

| 控制记录 | 最少语义 |
| --- | --- |
| 根任务 | root_task_id、实际用户/租户、目标与验收谓词、有效授权引用、预算与截止、当前任务状态 |
| 计划/节点 | plan_revision、node_id、依赖及输入版本、必需/可选、输出契约、写入冲突域、完成证据 |
| 执行尝试 | attempt_id、真实执行者、control_epoch、活动/等待/结束原因、根级用量与在途预留 |
| 委派/交接 | 父子关联、路由目标、权限上界、交接 ID、来源与限制、接收确认及返回/失败责任 |
| 结果/事件 | 关联任务/节点/尝试/版本、事件 ID、证据位置、结果状态、未决副作用及收据引用 |

### 状态转换不变量

- I1 只有当前有效控制者能调度；共享资源接受写入前必须拒绝失效写者。
- I2 根任务已用额度加在途预留不得超过获准上限；重试、交接或重建 run 不重置账本。
- I3 模型提议、子 Agent 报告、SDK 正常返回与任务成功是不同事实；必需验收未满足不能写 succeeded。
- I4 旧计划/旧 epoch/旧尝试事件不能重新激活终态或覆盖新结果。
- I5 权限拒绝、撤回及输入信任级随委派保留；路由不产生新权限。
- I6 父运行结束时，所有仍在途后代和未知副作用有明确状态与接手者，不可遗失。

| 转换 | 必须满足的门禁 | 不能推断的事实 |
| --- | --- | --- |
| ready → running | 当前版本、有效控制者、依赖、权限、原子预算及并发准入均通过 | 模型说“开始”不代表已派发 |
| running → waiting | 等待对象、原因、责任者和重新检查条件明确 | 静默、超时不等于用户同意或外部失败 |
| running → handoff pending → running | 先准备目标，再由控制面提交新 epoch/所有者；查询可解决 ACK 丢失 | 双方收到文本不等于双方都可执行 |
| running → reconciling | 已发生或可能发生外部动作但结果不明 | 调度重试许可不等于可重放业务动作 |
| 非终态 → succeeded | 必需结果验收通过、交付满足目标、在途后代/副作用已处置 | max_turns 返回的兜底答案不是完成证据 |
| 非终态 → failed/cancelled/blocked | 真实原因、适用决定及未完成影响记录，禁止不合规新派发 | 停止一次运行不等于取消目标或回滚外部状态 |

## 三、36 项技术机制与验收

### 执行闭环与实现绑定

每条§适用时均由下表责任者在相应接受边界执行：输入须来自当前有效主体及权威状态；输出区分允许、拒绝、未知与已证实事实。模型提议、协议ACK、日志或摘要不能自签授权。并发接受使用预期版本/世代或等效条件；超时保留原逻辑操作、预算预留及核对责任。日志记录decision_id、输入/输出身份、原因和证据定位，不要求保存私有思维链。具体字段可复用既有系统。

| 组/条款 | 责任者及运行入口 | 权威输入 → 可观测输出 | 失败、并发、超时与恢复 | 兼容/合法边界 |
| --- | --- | --- | --- | --- |
| control-G01 / §01—§06 | 可信调度控制器；`plan.admit/schedule` | 当前目标、节点依赖和权威结果 → 受验计划或可恢复阻塞 | 旧plan结果不填新join，缺证据不猜完成 | 允许有退出条件的合法迭代 |
| control-G02 / §07—§12 | 根任务预算服务；`budget.reserve/progress.check` | 根身份、上界、多维限额与进展 → 原子预留及有限尝试 | 并发余量不双花；未知费用不释放 | SDKturn不是全任务预算 |
| control-G03 / §13—§18 | 委派及交接控制方；`delegate/handoff.commit` | 可信目标、权限和预期旧epoch → 唯一新控制者及限权输入 | CAS解双交接；ACK丢失查权威归属 | 子调用不等于转交总责任 |
| control-G04 / §19—§24 | 并发及结果协调者；`slot.acquire/resource.accept/join` | 活动槽、冲突域、fence及必需集合 → 受验结果集合与剩余任务 | 资源端拒旧写；等待避免同槽死锁 | 独立只读分支可并行 |
| control-G05 / §25—§30 | 故障及生命周期责任者；`event.admit/cancel/finalize` | 事件身份、当前attempt/epoch及后代 → 事实补充与真实终态原因 | 迟到旧事件不复活；取消非回滚 | 可选失败不全盘取消 |
| control-G06 / §31—§36 | 恢复与版本验收方；`resume/evaluate/release` | 当前待决、恢复闭包及联合版本 → 可执行接续与分层证据 | 沉默不授权；缺原操作收据先核对 | 静态调度测试与真实模型分开 |

实现方将上述逻辑入口映射到[目标合同](../../../examples/ai-agent/target-contract.json)中的真实模块/命令，记录端点、准确版本、鉴权身份来源、输入输出与权威查询方式；无真实适配映射不声称目标已通过。有限参考模型及本地命令见[运行入口](../../../examples/ai-agent/README.md)，仅验证声明的控制不变量。

### §01 最小编排与控制面分离
**机制：** 按任务不确定性选择固定工作流、单 Agent 循环、受控子任务或多 Agent；模型只能提出计划、路由和完成建议，可信控制器负责校验与状态转换。不强制多 Agent，也不以 Agent 数量作质量指标。

**验收：** 单次可验证查询可用固定流程完成；模型生成“切换为管理员”不能改变控制器身份。

**执行绑定：** `control-G01`。**专用正例 P-control-01：** 模型计划由可信控制器准入。**直接失败 D-control-01：** 固定查询被自动升级为多角色自治系统，模型文本直接成为控制器命令；预期：单次可验证查询可用固定流程完成；模型生成“切换为管理员”不能改变控制器身份。。**合法邻例 N-control-01：** 固定查询可用单流程不建多Agent。

### §02 任务身份与运行实例分离
**机制：** 为任务、执行尝试、计划版本、子任务和委派建立稳定关联；重试只新增 attempt_id，不能通过另建 root_task_id 逃避原任务限额、否决或未确认结果。任务完成与某次 SDK run 返回分别记录。

**验收：** 同一目标重开 run 后，原预算与未决动作仍属于同一根任务。

**执行绑定：** `control-G01`。**专用正例 P-control-02：** 重开attempt不清根预算未知项。**直接失败 D-control-02：** 达到循环上限后用新任务名继续，并清空先前使用量；预期：同一目标重开 run 后，原预算与未决动作仍属于同一根任务。。**合法邻例 N-control-02：** 新独立用户目标可有独立根任务。

### §03 计划节点的可验证契约
**机制：** 每个节点明确输入版本、期望输出、前置条件、工具/写入范围、验收谓词及责任主体；自然语言计划可作为界面，但调度依赖可验证契约。简单任务可内联表示，不强制持久图数据库。

**验收：** 只有代码生成完成而测试前置条件未满足时，发布节点保持不可调度。

**执行绑定：** `control-G01`。**专用正例 P-control-03：** 节点依赖验收满足才调度。**直接失败 D-control-03：** 计划只有“分析、完成”标签，生成文件后就触发发布；预期：只有代码生成完成而测试前置条件未满足时，发布节点保持不可调度。。**合法邻例 N-control-03：** 简单节点契约可内联不建图数据库。

### §04 依赖图与循环边界
**机制：** 调度前检查不存在的依赖、孤立必需节点及依赖环；需要迭代的有向循环须声明退出谓词、迭代预算和无进展检测，不能将所有环视为错误，也不能允许未声明回边无限执行。

**验收：** A 等 B、B 等 A 的任务图被诊断；合法修订循环有可检验退出边。

**执行绑定：** `control-G01`。**专用正例 P-control-04：** 未声明依赖环被诊断。**直接失败 D-control-04：** 生成的 DAG 互相等待，调度器持续重新入队；预期：A 等 B、B 等 A 的任务图被诊断；合法修订循环有可检验退出边。。**合法邻例 N-control-04：** 有退出谓词预算的迭代环合法。

### §05 计划修订与过期结果
**机制：** 计划发生实质修订时递增 plan_revision，记录原因、失效节点与在途任务；完成结果按输入和计划兼容性重验，不能把旧版本成功直接计入新计划。改计划不得扩大授权目标。

**验收：** v2 已改目标文件后，v1 对旧文件的完成报告不能满足 v2 验收。

**执行绑定：** `control-G01`。**专用正例 P-control-05：** 旧plan结果不满足新目标join。**直接失败 D-control-05：** 旧计划子任务迟到返回，覆盖新版产物并标记新版步骤完成；预期：v2 已改目标文件后，v1 对旧文件的完成报告不能满足 v2 验收。。**合法邻例 N-control-05：** 输入相容输出可经重验复用。

### §06 前置条件及权威反馈
**机制：** 在派发及实际执行边界核对任务状态、上游输出版本、真实权限和目标前置条件；模型对工具结果的摘要不是原始收据。必要依赖不足时记录可恢复阻塞而非猜测成功。

**验收：** 上游只报告“应该成功”但缺少结果版本时，下游写入不开始。

**执行绑定：** `control-G01`。**专用正例 P-control-06：** 上游权威收据满足前置条件。**直接失败 D-control-06：** Agent 伪造工具成功总结，协调器跳过前置证据；预期：上游只报告“应该成功”但缺少结果版本时，下游写入不开始。。**合法邻例 N-control-06：** 缺证据时阻塞相关写不猜成功。

### §07 计步口径与多维上限
**机制：** 明确一次模型调用、工具调用、图 super-step、重试、交接及子任务创建分别如何计数；配置有限的根任务调用/尝试总量、活动并发数、委派深度和时间边界。SDK max_turns 或 recursion_limit 不能代替其他维度。

**验收：** 一轮输出一百次工具调用不能按一轮预算绕过工具数量上限。

**执行绑定：** `control-G02`。**专用正例 P-control-07：** 一轮百工具按百调用计量。**直接失败 D-control-07：** 把图超级步数当成所有 Agent 与 Tool 的总调用数；预期：一轮输出一百次工具调用不能按一轮预算绕过工具数量上限。。**合法邻例 N-control-07：** 图step与模型turn可分别记数。

### §08 层级预算与原子预留
**机制：** 全体后代共享根任务预算账本；派发前原子预留该操作的有界额度，结算实际消耗后才释放未用部分。已用加在途预留不得超过获准限额；消费不明时保留预留，不能先退回再重试。预留必须覆盖可执行最大消耗而非乐观估算；无法取得可信上界或实施硬限制时，不得按该预留准入。结算/释放须按预留标识去重；预留成功但未启动、迟到消费回执均保留可核对状态。模型不得自行提高上限。

**验收：** 两个子任务同时争抢最后一份额度时只有满足预留条件者开始。

**执行绑定：** `control-G02`。**专用正例 P-control-08：** 最后额度并发原子预留。**直接失败 D-control-08：** 并发子 Agent 各自读取同一剩余额度，分别花完全部余额；预期：两个子任务同时争抢最后一份额度时只有满足预留条件者开始。。**合法邻例 N-control-08：** 未知费用保留而不先释放。

### §09 重试、改规划与深度的联合约束
**机制：** 每次自动修复、重新规划、回交、嵌套 Agent-as-tool 及递归委派纳入根预算；深度以委派链而非本地调用栈计算，交接次数另计。重建父节点不清零重试或深度。

**验收：** A→B→A 的交接与 A 派生子 A 均不能逃过根级计数。

**执行绑定：** `control-G02`。**专用正例 P-control-09：** 递归委派计根深度与总量。**直接失败 D-control-09：** 每个子 Agent 都限三轮，但无限递归生成新的三轮子 Agent；预期：A→B→A 的交接与 A 派生子 A 均不能逃过根级计数。。**合法邻例 N-control-09：** 非递归合法交接仍计handoff。

### §10 截止时间与等待语义
**机制：** 区分任务截止时间、活动执行超时、工具超时和等待用户/外部事件；由控制器时钟判断经过时间，在单进程内使用适当单调计时。一次等待无变化不是任务完成，超时也不证明远端动作未发生。

**验收：** 工具等待超时进入待核对状态，不因没有回包立即换一个写入请求。

**执行绑定：** `control-G02`。**专用正例 P-control-10：** 超时未知先核对而不换意图。**直接失败 D-control-10：** 等待接口超时后把未返回的外部写入当失败重新提交；预期：工具等待超时进入待核对状态，不因没有回包立即换一个写入请求。。**合法邻例 N-control-10：** 等待用户不当作同意或完成。

### §11 无进展与振荡检测
**机制：** 用目标、规范化动作参数、相关状态版本、证据增量和可验证进展判定重复或 A/B 振荡；不得只比较模型措辞。达到预设无进展阈值后禁止继续无界循环，保留未完成目标并报告诊断与获准恢复选择。

**验收：** 相同失败动作只换理由文字时仍被归并为无进展尝试。

**执行绑定：** `control-G02`。**专用正例 P-control-11：** 同动作换措辞仍判无进展。**直接失败 D-control-11：** 评审与实现循环互相要求重做相同内容，文本不同即被算进展；预期：相同失败动作只换理由文字时仍被归并为无进展尝试。。**合法邻例 N-control-11：** 真实新证据可推动下一轮。

### §12 评估回路与完成判据保护
**机制：** 执行者不能修改其完成谓词来宣称通过；评价器输出是证据建议，必须与冻结的任务要求、测试结果和独立性记录核对。需要独立审查时，不用同源多票或自我复述代替独立依据。

**验收：** 同源多票不能替代独立依据或冻结验收条件；删除失败测试也不能把未满足目标改判成功。

**执行绑定：** `control-G02`。**专用正例 P-control-12：** 冻结验收条件不由执行者修改。**直接失败 D-control-12：** 多个同模型评审一致通过即代替独立验收和负责人批准；预期：同源多票不能替代独立依据或冻结验收条件；删除失败测试也不能把未满足目标改判成功。。**合法邻例 N-control-12：** 合法等价解不必复制参考路径。

### §13 拆分边界与最小委派
**机制：** 子任务需有可独立验收输出、输入快照、权限上界、预算、依赖与交回方式；不为并发而拆开同一不可分业务动作。可共享只读研究，写入按资源冲突域协调。

**验收：** 拆出的两个研究任务可并行，但同一订单扣款不拆成独立竞争提交者。

**执行绑定：** `control-G03`。**专用正例 P-control-13：** 独立研究输出可并行委派。**直接失败 D-control-13：** 为了多 Agent 数量把一次外部交易拆成两个无归属写入者；预期：拆出的两个研究任务可并行，但同一订单扣款不拆成独立竞争提交者。。**合法邻例 N-control-13：** 不可分扣款不拆成两竞争写者。

### §14 控制权转移与子调用区分
**机制：** 明确 Agent-as-tool 的调用者保留汇总/最终响应责任，handoff 才转移指定执行段的控制权；每种边都定义返回、失败和输出归属。子任务的完成消息不得自行接管主会话或总任务。

**验收：** 资料检索子 Agent 返回证据，不因此成为最终交付负责人。

**执行绑定：** `control-G03`。**专用正例 P-control-14：** Agent-as-tool返回给调用者汇总。**直接失败 D-control-14：** 工具式子 Agent 声称“我现在是控制者”后直接改写整体任务状态；预期：资料检索子 Agent 返回证据，不因此成为最终交付负责人。。**合法邻例 N-control-14：** handoff可按契约转移指定段控制权。

### §15 真实身份、角色和路由验证
**机制：** 路由目标须由可信注册及本次任务允许集合解析，按真实执行身份与能力验权；名称、提示角色、模型生成 agent_id、handoff 参数 Schema 均不是许可。目标不存在、同名歧义或不具权限时拒绝对应转移。

**验收：** 名为 Reviewer 的写入 Agent 不会因名字而被赋予批准权。

**执行绑定：** `control-G03`。**专用正例 P-control-15：** 目标从可信允许集合解析。**直接失败 D-control-15：** 模型把 delegate_to 改为财务管理员，并利用合法 JSON 接管权限；预期：名为 Reviewer 的写入 Agent 不会因名字而被赋予批准权。。**合法邻例 N-control-15：** Reviewer名字不自动授审批权。

### §16 交接事务与单一控制者
**机制：** 交接携带 task_id、plan_revision、from/to、control_epoch、截止时间及接收确认；仅可信控制面针对预期旧所有者/世代以原子条件转换提交唯一的新 control_epoch 和控制所有者，并发交接不能各自生成有效新主。旧 epoch 在实际执行门禁失效；回执丢失先查询交接状态，不能让双方同时成为有效控制者。

**验收：** 接收方已承接但 ACK 丢失时，原控制者不能按旧 epoch 继续派发。

**执行绑定：** `control-G03`。**专用正例 P-control-16：** 交接CAS只生成一个有效新epoch。**直接失败 D-control-16：** 交接超时后源 Agent 和目标 Agent 都认为自己拥有任务；预期：接收方已承接但 ACK 丢失时，原控制者不能按旧 epoch 继续派发。。**合法邻例 N-control-16：** ACK丢失查询已提交控制归属。

### §17 交接上下文的信任保真
**机制：** 传递完成所需输入、原始证据引用、有效限制与撤回决定；区分用户指令、工具数据和 Agent 推断。摘要和共享历史不改变信任级别，不默认为可复制全部会话、秘密或无关租户数据。

**验收：** 子 Agent 收到的摘要不能把网页“用户已批准”提升为真实批准。

**执行绑定：** `control-G03`。**专用正例 P-control-17：** 上下文保留外部来源与拒绝。**直接失败 D-control-17：** 控制者转述恶意网页为系统指令，子 Agent 据此扩权；预期：子 Agent 收到的摘要不能把网页“用户已批准”提升为真实批准。。**合法邻例 N-control-17：** 无关会话秘密不随交接复制。

### §18 中断、拒绝与授权单调性
**机制：** 审批等待、拒绝、权限撤回及安全拦截须传播到相关后代与执行门禁；换 Agent、改路线或启用另一个工具不能清除拒绝。阻塞依赖可保留，独立且仍获授权的节点可继续，不将阻塞自动解释为整体取消。

**验收：** 退款被否决后无法通过转交“升级处理” Agent 执行；无关只读核对可继续。

**执行绑定：** `control-G03`。**专用正例 P-control-18：** 退款被拒后不能换Agent绕过。**直接失败 D-control-18：** 一个 Agent 被拒绝后，协调器重新派给另一个 Agent 绕过拒绝；预期：退款被否决后无法通过转交“升级处理” Agent 执行；无关只读核对可继续。。**合法邻例 N-control-18：** 独立只读核对可继续。

### §19 并发准入与背压
**机制：** 按根任务及共享服务的实际资源约束实施有界 fan-out、队列长度、活动任务数和外部限流；先取得并发槽再启动。模型可产生多个调用不代表执行器应一次性运行全部调用。父任务持有最后工作槽却等待需要同槽的子任务会产生资源死锁；采用等待不占工作槽、分级槽位或其他已验证方案避免此循环，不把图无环误当调度活性证明。

**验收：** 一轮生成一万子任务只会形成受限待处理队列，不会同时创建一万执行器。

**执行绑定：** `control-G04`。**专用正例 P-control-19：** fanout先取槽且父等待不占死锁槽。**直接失败 D-control-19：** 仅限制模型并行输出参数，执行器仍无限启动已排队 Tool；预期：一轮生成一万子任务只会形成受限待处理队列，不会同时创建一万执行器。。**合法邻例 N-control-19：** 独立服务槽可按分级策略并发。

### §20 写入冲突域与任务隔离
**机制：** 声明可变更对象、文件/分支、状态命名空间或业务记录键及其写者；互不冲突的独立分支不强制串行。共享浏览器、会话与持久子图须按实际可写状态隔离或串行，不因同一父任务而可无锁共享。

**验收：** 同一子图检查点命名空间不被两次并行调用覆盖，独立只读分支仍可并发。

**执行绑定：** `control-G04`。**专用正例 P-control-20：** 共享子图命名空间串行或隔离。**直接失败 D-control-20：** 两个 Tool 同时调用持久子 Agent，共写一个会话状态；预期：同一子图检查点命名空间不被两次并行调用覆盖，独立只读分支仍可并发。。**合法邻例 N-control-20：** 不同只读分支无需全局串行。

### §21 租约、栅栏与失效写者
**机制：** 可采用唯一写者、锁、版本条件更新或等效已验证机制；租约超时只意味着可重新协调，不证明旧写者停止。共享资源最终接受写入时核对 fencing token 或等效版本条件，拒绝旧 epoch；不能只在派发时查锁。

**验收：** Worker A 租约过期后晚到的写入，被资源端拒绝而非覆盖 Worker B 新结果。

**执行绑定：** `control-G04`。**专用正例 P-control-21：** 资源端拒旧epoch写入。**直接失败 D-control-21：** 锁过期后新 Agent 接班，旧 Agent 网络恢复仍可写同一对象；预期：Worker A 租约过期后晚到的写入，被资源端拒绝而非覆盖 Worker B 新结果。。**合法邻例 N-control-21：** 租约到期不声称旧进程已停止。

### §22 状态更新与合并函数
**机制：** 并行节点先提交各自结果及基线版本，由受控 reducer/合并器或串行责任主体合并；定义字段归属、重复输入与顺序语义。不把字符串拼接、最后写入获胜用于授权、状态终态或不可交换业务字段。

**验收：** 交换两个并行结果的到达顺序不会改变权限；冲突字段进入显式决议。

**执行绑定：** `control-G04`。**专用正例 P-control-22：** 合并字段有归属和冲突判据。**直接失败 D-control-22：** 两个子 Agent 分别写已取消和已成功，后到消息直接决定终态；预期：交换两个并行结果的到达顺序不会改变权限；冲突字段进入显式决议。。**合法邻例 N-control-22：** 可交换集合并可允许乱序。

### §23 重复分派与业务副作用
**机制：** 调度去重键绑定根任务、计划节点及同一逻辑操作，不把 attempt_id 当新业务意图；有副作用的节点沿用[STD-L4-AI-AGENT-004 · L4 Agent 授权、可变更动作与业务副作用技术规范](004-Agent-授权、可变更动作与业务副作用技术规范--v0.1.0.md)的操作 ID、幂等与收据。不确定结果先对账，不能靠多 Agent 投机重复执行。

**验收：** 同一付款节点双重投递仍绑定同一逻辑操作 ID，按[STD-L4-AI-AGENT-004 · L4 Agent 授权、可变更动作与业务副作用技术规范](004-Agent-授权、可变更动作与业务副作用技术规范--v0.1.0.md)幂等与收据核对使有效付款不重复；超时不得生成第二业务意图。

**执行绑定：** `control-G04`。**专用正例 P-control-23：** 重复节点沿原operation对账。**直接失败 D-control-23：** 相同节点被双重投递，两个 Agent 各产生一个新幂等键付款；预期：同一付款节点双重投递仍绑定同一逻辑操作 ID，按[STD-L4-AI-AGENT-004 · L4 Agent 授权、可变更动作与业务副作用技术规范](004-Agent-授权、可变更动作与业务副作用技术规范--v0.1.0.md)幂等与收据核对使有效付款不重复；超时不得生成第二业务意图。。**合法邻例 N-control-23：** 新attempt不等于新业务意图。

### §24 收敛、Join 与部分结果
**机制：** 在 fan-out 前声明必需/可选节点、all/any/阈值等 join 语义和截止策略；计入者必须是有效且通过验收的结果，不是仅收到消息。达到 any 条件时其余任务仍需按权限收尾/交接并核对在途副作用。

**验收：** 必需校验未通过或在途写入未处置时不得整体成功；首个失败或无证据结果不能触发 first-success join。

**执行绑定：** `control-G04`。**专用正例 P-control-24：** 必需节点通过且未决项有归属。**直接失败 D-control-24：** 任一子任务返回就整体成功，其他必需校验与在途写入被遗忘；预期：必需校验未通过或在途写入未处置时不得整体成功；首个失败或无证据结果不能触发 first-success join。。**合法邻例 N-control-24：** any join后其他任务仍需收尾。

### §25 冲突决议与证据优先
**机制：** 对互相冲突的结论按输入版本、来源权威性、适用范围和可复验结果处理；不能按回复时间、模型信心或多数票选择业务事实。无法技术消解的需求/权利冲突交有权主体，保留各版本。

**验收：** 三个同源 Agent 赞成不抵消目标系统的真实失败收据。

**执行绑定：** `control-G05`。**专用正例 P-control-25：** 实时权威收据胜同源多票。**直接失败 D-control-25：** 相互引用同一过期来源的三票结果压过实时权威数据；预期：三个同源 Agent 赞成不抵消目标系统的真实失败收据。。**合法邻例 N-control-25：** 无权利裁定时保留冲突待有权决定。

### §26 故障域与关联失败
**机制：** 预先规定单节点失败何时影响依赖、同组或根任务；框架 fail-fast/cancel-siblings 只是实现策略，不代替业务取消权限。保留已完成结果、失败证据和未决影响，能独立继续的工作不得被误报成失败。

**验收：** 可选图片检索失败不使已验证正文丢失，必需权限核对失败则阻止受影响写入。

**执行绑定：** `control-G05`。**专用正例 P-control-26：** 故障只影响真实依赖域。**直接失败 D-control-26：** 任意子 Agent 抛异常就把所有成功输出清空并取消独立任务；预期：可选图片检索失败不使已验证正文丢失，必需权限核对失败则阻止受影响写入。。**合法邻例 N-control-26：** 可选图片失败不抹已验正文。

### §27 结构化生命周期与后代归属
**机制：** 控制器持有所有后代任务的可追踪标识与状态，正常返回、异常或接替均不得遗失后台写入者；需脱离父生命周期运行时明确新责任主体、授权和预算，而非 fire-and-forget。

**验收：** 父 run 结束时，未完成后代均有可查状态和接手者，不会无主运行。

**执行绑定：** `control-G05`。**专用正例 P-control-27：** 父结束后代状态与接手者可查。**直接失败 D-control-27：** 父 Agent 返回后忘记未等待的异步任务，后台继续外发；预期：父 run 结束时，未完成后代均有可查状态和接手者，不会无主运行。。**合法邻例 N-control-27：** 获准长驻任务可明确转移归属。

### §28 取消传播与收尾核验
**机制：** 区分提出取消、取消被接受、禁止新派发、后代停止/交接及远端副作用核对；取消信号不等于已经停止，也不等于回滚。只在获准范围执行收尾，记录不可取消或结果不明的操作及负责核对者。

**验收：** 取消请求成功返回后，仍在远端执行的操作保持 reconciliation，不被报告为已撤销。

**执行绑定：** `control-G05`。**专用正例 P-control-28：** 取消受理不当停止或回滚证据。**直接失败 D-control-28：** 收到 cancel ACK 后立即宣称所有子任务和外部写入均已回滚；预期：取消请求成功返回后，仍在远端执行的操作保持 reconciliation，不被报告为已撤销。。**合法邻例 N-control-28：** 不可取消项保持核对责任。

### §29 正常完成与资源上限终止
**机制：** succeeded 须满足批准目标及全部必需节点验收，且无未处置的在途写入；预算耗尽、无进展、超时、拒绝或部分结果必须有不同原因。停止当前运行不等于取消用户目标，扩大预算或缩小目标不由模型自行决定。

**验收：** 最大轮数处理器返回一段答案时，未完成目标仍标为预算阻塞而非成功。

**执行绑定：** `control-G05`。**专用正例 P-control-29：** 轮数耗尽标阻塞非succeeded。**直接失败 D-control-29：** 捕获 MaxTurnsExceeded 后返回摘要，监控将它计作全任务成功；预期：最大轮数处理器返回一段答案时，未完成目标仍标为预算阻塞而非成功。。**合法邻例 N-control-29：** 符合目标的真实成功可正常结束。

### §30 事件接收及终态保护
**机制：** 只接收与任务、plan_revision、attempt_id、control_epoch 和当前状态相容的事件；事件重复、乱序和迟到需幂等处理。终态禁止被旧进度/完成消息重新激活；纠正必须为显式新决议并保留历史。

**验收：** 用户撤回后的迟到成功事件只能补充已发生事实，不能重新发起下一步。

**执行绑定：** `control-G05`。**专用正例 P-control-30：** 旧attempt回调不改新epoch状态。**直接失败 D-control-30：** 已取消任务被迟到的 RUNNING 消息重新加入队列；预期：用户撤回后的迟到成功事件只能补充已发生事实，不能重新发起下一步。。**合法邻例 N-control-30：** 旧费用收据仍可补充历史事实。

### §31 人工介入与接续入口
**机制：** 需人类输入时明确尚缺决定、受影响节点和仍可继续部分，绑定待决任务及计划版本；回答匹配当前待决对象后才恢复。人员接管与再次交回均重新核对所有权、有效权限和未决副作用。

**验收：** v1 的批准不能在 v2 已换目标后直接唤醒写入，沉默不视作同意。

**执行绑定：** `control-G06`。**专用正例 P-control-31：** 回答绑定当前interrupt及plan。**直接失败 D-control-31：** 人工等待被定时器视作批准，旧答案又恢复了改版任务；预期：v1 的批准不能在 v2 已换目标后直接唤醒写入，沉默不视作同意。。**合法邻例 N-control-31：** 沉默或旧版批准不唤醒新动作。

### §32 检查点与恢复专题界面
**机制：** 编排状态最少提供计划版本、活动控制者、后代清单、预算预留、结果引用和未决副作用的恢复接口；存储原子性、持久化协议与崩溃重放属于[STD-L4-AI-AGENT-015 · L4 长任务状态、检查点与可恢复执行技术规范](015-长任务状态、检查点与可恢复执行技术规范--v0.1.0.md)。仅本地内存或聊天摘要不能证明可持久恢复。

**验收：** 控制器重启后缺少在途操作收据时先核对，而非按摘要重新执行所有节点。

**执行绑定：** `control-G06`。**专用正例 P-control-32：** 恢复提供预算后代收据闭包。**直接失败 D-control-32：** 把最终聊天摘要当检查点，重启后重放整个 Agent 图；预期：控制器重启后缺少在途操作收据时先核对，而非按摘要重新执行所有节点。。**合法邻例 N-control-32：** 无持久需求可使用内存运行。

### §33 追踪关联与可审计决策
**机制：** 记录路由/交接/冲突决议的可解释摘要、版本、事件 ID、计量和证据引用，不要求保存模型私有思维链；追踪需最小化敏感内容。跨度成功只表示该观测段结束，不代替任务或业务成功。

**验收：** Trace OK 不足以证明付款成功，须关联权威收据；审计能定位计划/执行者及结果证据，不保存模型私有思维链或无关秘密。

**执行绑定：** `control-G06`。**专用正例 P-control-33：** Trace关联控制决策不存私有思维链。**直接失败 D-control-33：** Trace 标成 OK 就自动认定付款已成功且保存全部内部推理；预期：Trace OK 不足以证明付款成功，须关联权威收据；审计能定位计划/执行者及结果证据，不保存模型私有思维链或无关秘密。。**合法邻例 N-control-33：** spanOK只证明对应观测段。

### §34 确定性调度反例与模型评测分离
**机制：** 先用固定伪造模型/工具结果测试预算、错误角色、循环、乱序、重复、冲突和终止控制；再按获准 L5 环境测真实 SDK 与并发执行。模拟不证明真实模型稳定性、安全或外部原子性。

**验收：** 死循环脚本被控制器终止的测试与真实模型完成率分别报告。

**执行绑定：** `control-G06`。**专用正例 P-control-34：** 合成调度与真实模型结果分列。**直接失败 D-control-34：** 仅调用真实模型一次成功就声称并发栅栏、递归上限均已验证；预期：死循环脚本被控制器终止的测试与真实模型完成率分别报告。。**合法邻例 N-control-34：** 一次真实调用不证明并发栅栏。

### §35 版本差异与回归入口
**机制：** 冻结模型/指令、SDK、路由图、计数口径、reducer、并发及终态策略版本；升级后定向复验默认上限、取消、交接与子图语义。不能把滚动文档新能力当作旧部署已具备。

**验收：** 换 SDK 后若 recursion_limit 计数口径或取消行为改变，相关反例必须重验。

**执行绑定：** `control-G06`。**专用正例 P-control-35：** SDK变更定向复验计数取消。**直接失败 D-control-35：** 从新版本文档复制配置，旧执行器忽略字段仍被判已受限；预期：换 SDK 后若 recursion_limit 计数口径或取消行为改变，相关反例必须重验。。**合法邻例 N-control-35：** 未变且依赖相同证据可有理由复用。

### §36 分层验收和权利边界
**机制：** L4 约束控制循环与编排安全性；L5 落实具体框架、执行器与运行测试；L6 独立确认生产、费用、客户数据和真实业务验收。多 Agent 共识、技术审查、CI 绿灯均不能替代有权规范决策主体对新规范的批准。

**验收：** 本规范的静态回归通过仍不构成具体项目的生产部署授权。

**执行绑定：** `control-G06`。**专用正例 P-control-36：** 规范状态与真实项目授权分列。**直接失败 D-control-36：** Agent 投票通过候选后自动登记批准并执行生产部署；预期：本规范的静态回归通过仍不构成具体项目的生产部署授权。。**合法邻例 N-control-36：** 技术审查不自动批准生产部署。

## 五、分层验证、恢复界面与变更触发

1. **静态契约：** 审查任务/计划/身份、计量单位、完成谓词、交接、写域、join 与终态；逐条核对直接及组合反例。仓库内容回归只证明结构、覆盖和治理字段一致，不执行任何真实 Agent 编排。
2. **受控 L5：** 在获准环境用可重复的模型/工具桩先注入死循环、嵌套绕限、并发预留竞争、错误角色、ACK 丢失、过期租约、乱序/重复事件、子图命名空间冲突及父子取消；断言拒绝位置、实际写次数、在途状态和最终证据。补充重复结算/释放、预留后未启动、迟到消费、新旧控制者同时交接及父等待子同槽的交错排列，分别断言预算账本守恒、唯一有效世代与有界收敛。随后测选定 SDK/模型/进程的真实行为，单进程模拟不证明分布式栅栏或端到端副作用。
3. **L6 业务：** 对生产写入、对外通信、费用、客户数据或不可逆影响，独立确认真实主体许可、目标参数、业务收据及退出/恢复责任。
4. **恢复接口：** 在有效原授权内查明控制者、计划及未决操作再接续；结果不明不得盲目重放。持久原子边界、存储兼容与重放策略留给[STD-L4-AI-AGENT-015 · L4 长任务状态、检查点与可恢复执行技术规范](015-长任务状态、检查点与可恢复执行技术规范--v0.1.0.md)及现行后端规范，不能借本篇宣称已提供完整恢复引擎。
5. **复核触发：** 路由或模型/提示变化、SDK 升级、计数/并发默认值变化、reducer/完成条件变化、共享状态迁移、权限缩减和控制者接替均重新评估受影响反例。无进展诊断和预算阻塞不授权模型自行增加费用、缩小目标或销毁证据。

## 六、生命周期与采用

项目按 L1 登记所采用的准确版本、适用条款和依赖关系。L5 选择并验证实际实现，L6 按真实权利及目标验收业务结果；实现验收以相应项目的执行证据为准。
