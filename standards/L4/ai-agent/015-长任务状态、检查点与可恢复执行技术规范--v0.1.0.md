# L4 长任务状态、检查点与可恢复执行技术规范

**文档ID：** STD-L4-AI-AGENT-015　**版本：** 0.1.0　**状态：** adopted　**生效日期：** 2026-10-30

## 一、适用范围与恢复契约

本专题解决模型驱动执行跨进程、暂停、长期等待与崩溃之后，如何从可信状态接续且不重放已生效动作。继承[领域基线](001-AI-应用与-Agent-系统领域通用基线--v0.1.0.md)、[授权及副作用](004-Agent-授权、可变更动作与业务副作用技术规范--v0.1.0.md)和[控制循环及编排](005-Agent-控制循环、计划与多-Agent-编排技术规范--v0.1.0.md)；具体原子存储、Inbox/Outbox、栅栏与业务补偿复用[分布式工作流](../backend/004-分布式业务工作流与一致性技术规范--v0.1.0.md)。这里把这些基础机制接到模型决议、提示/工具语义、中断、流式响应和检查点上，不另造数据库备份或业务取消制度。

[STD-L4-AI-AGENT-010 · L4 持久记忆、会话隔离与生命周期技术规范](010-持久记忆、会话隔离与生命周期技术规范--v0.1.0.md)处理可跨会话使用的知识；本篇检查点保存执行闭包而非用户记忆。[STD-L4-AI-AGENT-005 · L4 Agent 控制循环、计划与多 Agent 编排技术规范](005-Agent-控制循环、计划与多-Agent-编排技术规范--v0.1.0.md)决定调度控制，本篇规定其持久提交与重建。[STD-L4-AI-AGENT-006 · L4 Agent 间通信、发现与委派协议技术规范](006-Agent-间通信、发现与委派协议技术规范--v0.1.0.md)处理跨域消息协议，[STD-L4-AI-AGENT-013 · L4 模型及 Agent 应用版本演进与回退技术规范](013-模型及-Agent-应用版本演进与回退技术规范--v0.1.0.md)处理联合版本发行；本篇只规定恢复入口所需的相关性与兼容门禁。不存在相应持久恢复需求时不强制工作流引擎；具体存储/SDK映射由L5实现，L6选择真实目标及验收窗口。

### 最小恢复记录

字段为说明性命名，可复用现有平台；不要求额外重复台账。

| 记录 | 必须能还原的语义 |
| --- | --- |
| 恢复身份 | tenant_id、root_task_id、branch_id、node_id、attempt_id、control_epoch |
| 提交身份 | checkpoint_id、parent_checkpoint_id、sequence、schema_version、commit_id、持久等级 |
| 决议输入 | input_cursor、plan_revision、模型/提示/工具/知识版本、accepted_response_id及结果引用 |
| 操作事实 | operation_id、参数摘要、授权引用、prepared/dispatched/unknown/confirmed 状态、权威回执 |
| 等待与限制 | interrupt_id、待决参数、deadline、not_before、取消世代、根预算及在途预留 |
| 恢复闭包 | 输出及制品内容身份、必需祖先/增量、已完成子项、未决后代与恢复责任 |

### 恢复不变量

- R1 发布为可恢复的检查点及必需引用均已达到其承诺持久等级，不能从部分快照派发。
- R2 同一逻辑外部动作跨重试、恢复、分叉和换运行仍可定位原 operation_id；至多一次效果取决于有效目标端契约，而不是本地提交成功。
- R3 已采纳模型决议不会因恢复重新采样而静默替换；变化只能形成显式受验的新修订。
- R4 当前授权、撤回和取消状态优先于旧快照；历史回放不复活被禁止的执行。
- R5 同一检查点仅有一个有效恢复世代，旧写者在实际接受边界失效。
- R6 未知外部结果、在途用量及未完成后代不会在压缩、终态或迁移时消失。
- R7 检查点迁移和历史分叉保留来源关系，不能变成新业务意图或跨租户能力。

### 崩溃窗口与允许恢复

| 最后可证事实 | 恢复处理 |
| --- | --- |
| 模型响应未完整准入 | 依[STD-L4-AI-AGENT-014 · L4 模型接入、推理调用与响应契约技术规范](014-模型接入、推理调用与响应契约技术规范--v0.1.0.md)重试模型调用并记新尝试，不补造工具参数 |
| 决议已持久、操作意图尚未派发 | 重验当前门禁后发同一逻辑操作 |
| 操作可能已送达、无可信收据 | reconciling；权威查询或有效去重契约，不推断未发生 |
| 外部效果已证实、检查点/会话未更新 | 回补该事实，禁止再执行已生效动作 |
| 最终输出/hook完成但终态保存失败 | 受控接续持久化与可去重交付，禁止重跑终态效果 |
| 最新检查点损坏/引用缺失 | 隔离该快照；从可证完整历史重建并对账跨窗口动作 |

## 三、30 项技术机制与验收

### 执行闭环与实现绑定

每条§适用时均由下表责任者在相应接受边界执行：输入须来自当前有效主体及权威状态；输出区分允许、拒绝、未知与已证实事实。模型提议、协议ACK、日志或摘要不能自签授权。并发接受使用预期版本/世代或等效条件；超时保留原逻辑操作、预算预留及核对责任。日志记录decision_id、输入/输出身份、原因和证据定位，不要求保存私有思维链。具体字段可复用既有系统。

| 组/条款 | 责任者及运行入口 | 权威输入 → 可观测输出 | 失败、并发、超时与恢复 | 兼容/合法边界 |
| --- | --- | --- | --- | --- |
| checkpoint-G01 / §01—§05 | 恢复状态维护者；`checkpoint.capture/load` | 租户任务、可信决议及类型版本 → 语义闭包与安全重绑资源 | 缺引用/篡改拒恢复，当前权利优先 | 短只读不强制checkpointer |
| checkpoint-G02 / §06—§10 | 持久提交及对账服务；`checkpoint.commit/effect.query` | 快照引用、commit_id和operation_id → 已持久指针与已证/未知效果 | ACK丢失查原提交；远端未知不盲重发 | 去重窗口真实有效才可重放 |
| checkpoint-G03 / §11—§15 | 恢复执行控制方；`resume.claim/replay` | 已采纳模型结果、子步完成集和epoch → 唯一有效恢复者及复用集合 | 前缀重执行去重，旧worker资源端拒绝 | 不完整模型调用可新尝试但不冒原决定 |
| checkpoint-G04 / §16—§20 | 输入与决策准入服务；`inbox.consume/resume.admit` | interrupt、用户新事件、撤回及联合版本 → 精确决定与相容下一动作 | 先到事件持久inbox，旧批准不匹配新目标 | 无法迁移可保留相容旧轨 |

### §01 恢复目标与状态分类
**机制：** 仅对跨进程、中断、长时间等待或需跨运行接续的 Agent 执行启用持久恢复。区分任务目标、一次运行、节点尝试、模型响应及外部操作；明确恢复点承诺覆盖哪些已确认输入和结果。纯只读短请求可重新计算，不强制引擎。

**验收：** 从权威执行状态辨认未决操作，不将摘要作为已完成游标。

**执行绑定：** `checkpoint-G01`。**专用正例 P-checkpoint-01：** 跨进程任务从权威状态恢复。**直接失败 D-checkpoint-01：** 聊天摘要写着完成，但未记录外部回执；预期：从权威执行状态辨认未决操作，不将摘要作为已完成游标。。**合法邻例 N-checkpoint-01：** 短只读无持久需求可重算。

### §02 检查点命名空间与逻辑身份
**机制：** 恢复键至少绑定租户、任务、分支、节点/子图及检查点世代；SDK thread_id 不作为对象访问凭证。重试换 attempt_id，但同一逻辑动作沿用 operation_id；另开会话不得清空原任务的拒绝、未决影响或预算。

**验收：** 鉴权后以完整作用域加载，跨租户恢复被拒绝。

**执行绑定：** `checkpoint-G01`。**专用正例 P-checkpoint-02：** 恢复键含租户任务分支世代。**直接失败 D-checkpoint-02：** 两个租户提供相同 thread_id 读取同一待执行调用；预期：鉴权后以完整作用域加载，跨租户恢复被拒绝。。**合法邻例 N-checkpoint-02：** thread_id不作为访问凭证。

### §03 语义快照最小闭包
**机制：** 记录已准入用户输入序号、目标/计划版本、模型输出或受控引用、工具参数规范化摘要、结果关联、待决审批、限制/撤回引用、下一节点、用量及未决操作。仅保存对话文本不能恢复控制面；快照须能解释每个待执行决定从何产生。

**验收：** 完整性检查拒绝自动接续，重取权威记录并重建待决集合。

**执行绑定：** `checkpoint-G01`。**专用正例 P-checkpoint-03：** 快照含决议授权预算未知操作。**直接失败 D-checkpoint-03：** 压缩快照只保留回答而丢弃工具调用 ID 和否决；预期：完整性检查拒绝自动接续，重取权威记录并重建待决集合。。**合法邻例 N-checkpoint-03：** 完整聊天文本不等于执行闭包。

### §04 可信来源与安全反序列化
**机制：** 加载前验证存储归属、完整性、schema_version、对象尺寸和允许类型。客户端可提交受限决议而不能替换服务端快照；签名须覆盖身份、版本及全体控制字段并防重放。JSON 合法或参数哈希一致不能证明快照可信；不得对不可信对象执行任意类型构造。

**验收：** 在反序列化/调度前拒绝篡改快照，加载服务端权威版本。

**执行绑定：** `checkpoint-G01`。**专用正例 P-checkpoint-04：** 可信存储完整性验证后反序列化。**直接失败 D-checkpoint-04：** 客户端改 serialized approvals 后通过 JSON 校验；预期：在反序列化/调度前拒绝篡改快照，加载服务端权威版本。。**合法邻例 N-checkpoint-04：** 客户端可交决定但不能换快照。

### §05 序列化往返与资源重建
**机制：** 显式定义枚举、空值、时间、二进制引用、结构化工具结果及版本的往返语义，不用字符串化兜底丢失类型。进程句柄、浏览器连接、临时路径及凭据不直接恢复为可用能力；重新绑定受权资源并核对内容身份。

**验收：** 往返验证发现语义变化，阻止依赖该结果的执行。

**执行绑定：** `checkpoint-G01`。**专用正例 P-checkpoint-05：** 精确JSON类型往返后重绑资源。**直接失败 D-checkpoint-05：** 自定义结果被序列化为字符串，恢复后误读成功状态；预期：往返验证发现语义变化，阻止依赖该结果的执行。。**合法邻例 N-checkpoint-05：** 旧进程句柄不恢复成可用能力。

### §06 检查点提交与恢复指针
**机制：** 先使快照及其全部必需引用达到所声明持久等级，再以条件更新发布当前 checkpoint_id/sequence。游标、输入消费位置、待发指令与完成集合须位于同一原子边界或有可恢复日志关联；提交 ACK 丢失按稳定提交 ID 查询，不新造矛盾快照。

**验收：** 该快照不可用于接续；定位最后完整提交并核对之后的外部动作。

**执行绑定：** `checkpoint-G02`。**专用正例 P-checkpoint-06：** 快照引用持久后CAS发布指针。**直接失败 D-checkpoint-06：** 恢复指针已经前进但工具结果 blob 尚未持久化；预期：该快照不可用于接续；定位最后完整提交并核对之后的外部动作。。**合法邻例 N-checkpoint-06：** 提交ACK丢失按commit_id查询。

### §07 持久等级与崩溃损失窗口
**机制：** 为每类执行边界声明同步、异步或退出时持久化及最坏丢失区间。会触发不可安全重算动作的模型决议须在派发前可靠登记；内存 checkpointer 不宣称支持进程崩溃恢复。异步窗口内的数据不得被上报成已持久确认。

**验收：** 承诺与配置不匹配被拒绝，采用满足边界的持久策略或明确未确认阶段。

**执行绑定：** `checkpoint-G02`。**专用正例 P-checkpoint-07：** 派发前决定达到承诺持久级。**直接失败 D-checkpoint-07：** 配置 exit 持久模式却承诺任意节点崩溃无损恢复；预期：承诺与配置不匹配被拒绝，采用满足边界的持久策略或明确未确认阶段。。**合法邻例 N-checkpoint-07：** 异步模式可明确未确认丢失窗口。

### §08 检查点与外部效果分离
**机制：** 在发送前持久登记 operation_id、同一性参数、授权引用及 expected target；发送后按[STD-L4-AI-AGENT-004 · L4 Agent 授权、可变更动作与业务副作用技术规范](004-Agent-授权、可变更动作与业务副作用技术规范--v0.1.0.md)的权威回执标记效果。检查点原子不意味着远端原子：外部成功本地未记、请求未发和发送未知分别处理，禁止靠 checkpoint 回滚重做所有工具。

**验收：** 恢复进入 reconciling，查询原操作，不产生第二逻辑外发。

**执行绑定：** `checkpoint-G02`。**专用正例 P-checkpoint-08：** 远端成功本地未记先查询原操作。**直接失败 D-checkpoint-08：** 工具外发成功后进程在保存收据前崩溃；预期：恢复进入 reconciling，查询原操作，不产生第二逻辑外发。。**合法邻例 N-checkpoint-08：** checkpoint原子不推远端原子。

### §09 未知结果的收敛路径
**机制：** 对每个未知操作设权威查询、有效幂等重试或受权人工核对入口；无查询且无有效去重保证时禁止盲目重放该动作，保留 unresolved 及责任者，独立安全节点可继续。查询暂无记录只有在提供方一致性/最终性契约支持时才可证明未执行。

**验收：** 保持未知，等待可确定证据或按有效原操作契约安全核对。

**执行绑定：** `checkpoint-G02`。**专用正例 P-checkpoint-09：** 最终一致暂空保持unknown。**直接失败 D-checkpoint-09：** 最终一致查询暂未找到订单便用新 ID 再创建；预期：保持未知，等待可确定证据或按有效原操作契约安全核对。。**合法邻例 N-checkpoint-09：** 提供方最终性证实未执行才可判未发。

### §10 幂等窗口与逻辑消费
**机制：** 恢复沿用原逻辑动作键及参数，检查供应方去重范围、有效期与结果语义；不能因新 Worker、重建 run 或历史压缩换键。同一事件的消费记录与其本地状态更新原子关联，外部动作仍须独立去重。

**验收：** 先查实际对象与权威收据；不凭过期键宣称至多一次。

**执行绑定：** `checkpoint-G02`。**专用正例 P-checkpoint-10：** 恢复沿原业务键核有效去重窗。**直接失败 D-checkpoint-10：** 暂停三十天后原幂等键已过期但自动重发；预期：先查实际对象与权威收据；不凭过期键宣称至多一次。。**合法邻例 N-checkpoint-10：** 过期幂等键不保证安全重放。

### §11 模型非确定输出的重放边界
**机制：** 已采纳的模型响应、工具选择及规范化参数以不可变结果记录回用；重放控制逻辑不得再次抽样并假装原决定。未取得完整可验证输出的模型调用可按[STD-L4-AI-AGENT-014 · L4 模型接入、推理调用与响应契约技术规范](014-模型接入、推理调用与响应契约技术规范--v0.1.0.md)重新尝试，但新增响应成为新候选，重验计划/授权并保留旧尝试及费用。

**验收：** 已提交决定不被替换；必要重规划有新修订并重新过门禁。

**执行绑定：** `checkpoint-G03`。**专用正例 P-checkpoint-11：** 已采纳响应不可变复用。**直接失败 D-checkpoint-11：** 恢复时重采样将原工具目标 A 改成 B；预期：已提交决定不被替换；必要重规划有新修订并重新过门禁。。**合法邻例 N-checkpoint-11：** 不完整模型调用可新尝试成新候选。

### §12 部分流与调用组完整性
**机制：** 流式 token、部分 JSON、已完成的工具调用和终止事件分别记录。只有完整、关联正确且通过契约的调用可进入待执行集合；记录同批每个调用的状态，恢复不能把已执行项视为未执行，也不能把最后可见 token 当整个 run 完成。

**验收：** 仅完整受验项可能执行，未完成项不得由摘要补全，已执行项先回执核对。

**执行绑定：** `checkpoint-G03`。**专用正例 P-checkpoint-12：** 完整受验调用才进待执行集合。**直接失败 D-checkpoint-12：** 流断在第二个工具参数中间，重启执行两个工具；预期：仅完整受验项可能执行，未完成项不得由摘要补全，已执行项先回执核对。。**合法邻例 N-checkpoint-12：** 已执行项先核收据不随部分流重做。

### §13 重执行单元与中断位置
**机制：** L5 列出框架从函数头、节点头还是已完成步骤后恢复；把模型采样、通知、hooks 和其他非幂等动作置于可记录重用的步骤边界。中断前代码及父图重新进入子图可能重跑，不能靠源码里 interrupt 的位置证明前缀只执行一次。

**验收：** 前缀副作用通过稳定操作身份去重或独立完成记录复用。

**执行绑定：** `checkpoint-G03`。**专用正例 P-checkpoint-13：** interrupt前缀重跑由稳定操作去重。**直接失败 D-checkpoint-13：** 节点先发通知后 interrupt，resume 再发通知；预期：前缀副作用通过稳定操作身份去重或独立完成记录复用。。**合法邻例 N-checkpoint-13：** 纯无副作用前缀可安全重算。

### §14 并行部分成功与检查点关联
**机制：** 保存每个子步骤完成写及其 task/node/input/checkpoint 关联；只复用已持久且与当前输入相容的结果。一个节点失败不清空兄弟成功集；恢复 pending writes 不得接入其他分支或旧输入的结果。

**验收：** 复用 A 的受验持久结果，仅按契约处理 B 和未知副作用。

**执行绑定：** `checkpoint-G03`。**专用正例 P-checkpoint-14：** 并行A成功B失败只复用受验A。**直接失败 D-checkpoint-14：** 并行 A 成功 B 失败，重启把 A 与 B 都重做；预期：复用 A 的受验持久结果，仅按契约处理 B 和未知副作用。。**合法邻例 N-checkpoint-14：** 不同输入分支不复用旧pendingwrite。

### §15 恢复领取与旧执行者隔离
**机制：** 针对预期检查点版本以原子条件取得唯一恢复所有者和 control_epoch；领取票据、状态迁移与后续命令关联可回查。领取后崩溃可由新世代接替；租约到期不证明旧 Worker 停止，实际写入门禁须拒绝旧世代。

**验收：** 一个恢复世代获准；重复请求返回同一状态，旧世代写入被拒绝。

**执行绑定：** `checkpoint-G03`。**专用正例 P-checkpoint-15：** 同checkpoint恢复CAS得唯一epoch。**直接失败 D-checkpoint-15：** 两个 Resume 请求同时从同一批准快照外发；预期：一个恢复世代获准；重复请求返回同一状态，旧世代写入被拒绝。。**合法邻例 N-checkpoint-15：** 租约失效旧worker仍需资源端栅栏。

### §16 持久唤醒与先到事件
**机制：** 等待记录绑定原因、对象、interrupt_id/nonce、版本、截止与唤醒责任。事件可能先于等待注册，采用持久 inbox 与状态条件匹配，不能只依靠内存回调；同一事件按身份消费，乱序/迟到事件只更新其适用事实。

**验收：** 恢复扫描持久未消费事件并准确匹配待决请求，不丢唤醒。

**执行绑定：** `checkpoint-G04`。**专用正例 P-checkpoint-16：** 持久inbox解决批准先到。**直接失败 D-checkpoint-16：** 批准事件先到但进程后注册监听而永久睡眠；预期：恢复扫描持久未消费事件并准确匹配待决请求，不丢唤醒。。**合法邻例 N-checkpoint-16：** 不匹配旧事件只留历史不唤醒。

### §17 人工决议绑定与并发消费
**机制：** 仅接受有权主体针对服务端待决项的决定；绑定任务/检查点/参数摘要/interrupt_id，按[STD-L4-AI-AGENT-004 · L4 Agent 授权、可变更动作与业务副作用技术规范](004-Agent-授权、可变更动作与业务副作用技术规范--v0.1.0.md)原子消费批准。输入 schema 只校验形状；一个布尔 true 不代表所有并行中断获批。重复决定可查询原结果，不能发起第二次执行。

**验收：** 按稳定待决 ID 匹配，未知、过期或缺失决定不恢复对应动作。

**执行绑定：** `checkpoint-G04`。**专用正例 P-checkpoint-17：** 决定绑定interrupt和参数摘要消费。**直接失败 D-checkpoint-17：** 两个并行审批以数组位置错配 true 答案；预期：按稳定待决 ID 匹配，未知、过期或缺失决定不恢复对应动作。。**合法邻例 N-checkpoint-17：** 未决并行项可继续等待。

### §18 恢复前当前限制重验
**机制：** 快照保留历史授权引用，但继续执行使用当前有效权限、撤回、对象版本与受众；旧 sticky approval 不覆盖后来的否决。撤权检查在恢复准入及动作接受边界适用，保持未受影响工作可执行。

**验收：** 旧批准不使动作可执行，记录受影响依赖与有效接续选项。

**执行绑定：** `checkpoint-G04`。**专用正例 P-checkpoint-18：** 恢复先核当前撤权及对象版本。**直接失败 D-checkpoint-18：** 旧 RunState 恢复缓存批准，忽略用户新撤回；预期：旧批准不使动作可执行，记录受影响依赖与有效接续选项。。**合法邻例 N-checkpoint-18：** 历史批准仍可作解释不授现行权。

### §19 新输入准入与消费位置
**机制：** 暂停期间新用户消息、修订和否决建立稳定事件身份及准入次序，在下次模型/工具执行前处理；消费位置与语义状态原子提交。新输入不覆盖正在核对的旧副作用；被拒输入及重复投递不能改变任务状态。

**验收：** 先准入当前变更并使旧计划动作失效，已发送事实仍独立核对。

**执行绑定：** `checkpoint-G04`。**专用正例 P-checkpoint-19：** 新输入在下一动作前准入。**直接失败 D-checkpoint-19：** 用户更换收件人在暂停期间到达，恢复先按旧参数发信；预期：先准入当前变更并使旧计划动作失效，已发送事实仍独立核对。。**合法邻例 N-checkpoint-19：** 重复输入事件不重复改变状态。

### §20 联合语义版本与恢复路由
**机制：** 快照绑定控制代码/SDK、模型标识、提示、工具 schema/语义、检索知识与序列化版本。恢复先计算受影响依赖；相容旧执行器可继续，无相容路径时隔离受影响节点并执行显式迁移/重规划，不能只靠 JSON schema 未变判语义兼容。

**验收：** 语义差异触发恢复门禁，不能用旧批准调用新行为。

**执行绑定：** `checkpoint-G04`。**专用正例 P-checkpoint-20：** 联合语义相容才接续。**直接失败 D-checkpoint-20：** 同名工具在新版由草稿变成真实发布但 schema 相同；预期：语义差异触发恢复门禁，不能用旧批准调用新行为。。**合法邻例 N-checkpoint-20：** Schema可解析不等于行为兼容。

### §21 证据新鲜度与模型重新推导
**机制：** 历史模型结论可用于解释旧决定，不自动满足当前价格、库存、文件内容或权限前置。为时效证据声明版本/有效区间与再验证条件，变化时使依赖输出失效并重新推导；重取数据不把网页新增指令升级为用户指令。

**验收：** 核对当前事实与对象版本，变化使受影响计划重新验证。

**执行绑定：** `checkpoint-G05`。**专用正例 P-checkpoint-21：** 旧库存证据过期要重取。**直接失败 D-checkpoint-21：** 三日前网页库存摘要被恢复后直接当可购买事实；预期：核对当前事实与对象版本，变化使受影响计划重新验证。。**合法邻例 N-checkpoint-21：** 历史结论可保留说明旧决定。

### §22 迁移、回放与分叉隔离
**机制：** 迁移保留源检查点、目标 schema、转换版本及验证结果，通过新指针发布，不原地抹除来源。历史回放/调试分叉默认使用不产生真实业务效果的工具边界；若要继续真实动作，先关联原 operation_id、当前权限和外部事实，不能把新分支视为新业务意图。

**验收：** 隔离副作用或沿用经核对的逻辑操作，不重复发送。

**执行绑定：** `checkpoint-G05`。**专用正例 P-checkpoint-22：** 迁移发布新指针保留源快照。**直接失败 D-checkpoint-22：** Time travel 分支重新执行原真实通知工具；预期：隔离副作用或沿用经核对的逻辑操作，不重复发送。。**合法邻例 N-checkpoint-22：** 历史调试分叉默认无真实副作用。

### §23 暂停屏障与在途执行
**机制：** 暂停指令先禁止新的受影响派发，再记录已发未决项和安全停靠点；paused 只在声明的执行范围达到屏障后成立。在途不可抢占调用可保持 reconciling，不虚报已停止；保存点失败不得丢弃已完成事实。

**验收：** 分开暂停受理、屏障达成与在途核对，给出真实残余集合。

**执行绑定：** `checkpoint-G05`。**专用正例 P-checkpoint-23：** 暂停屏障只对受影响派发生效。**直接失败 D-checkpoint-23：** 点击暂停后立刻显示所有远端操作已停止；预期：分开暂停受理、屏障达成与在途核对，给出真实残余集合。。**合法邻例 N-checkpoint-23：** 不可抢占调用仍可保持核对。

### §24 取消、终止与任务目标
**机制：** 记录取消/终止来源和适用授权，区别停止本次执行、撤销任务目标、远端撤销与补偿。取消屏障和终态 generation 持久化，重启及迟到事件不重新激活调度；已发生副作用保留并按既有权限核对，不让引擎终态吞掉遗留影响。

**验收：** 当前持久取消状态优先，旧快照不可复活，晚到收据仅补充事实。

**执行绑定：** `checkpoint-G05`。**专用正例 P-checkpoint-24：** 取消世代持久不被旧快照复活。**直接失败 D-checkpoint-24：** 终止进程后重启加载旧 running 快照继续外发；预期：当前持久取消状态优先，旧快照不可复活，晚到收据仅补充事实。。**合法邻例 N-checkpoint-24：** 晚到收据可补事实不重启任务。

### §25 时间、超时与恢复计时
**机制：** 持久保存任务 deadline、等待到期和重试 not_before；进程内单调计时不得直接序列化后跨主机比较。恢复按可信当前时刻重算剩余时间，区分工具超时、等待用户和目标截止；时间经过不构成批准或远端失败。

**验收：** 沿用原截止并处理停机越期，远端未知结果仍先核对。

**执行绑定：** `checkpoint-G05`。**专用正例 P-checkpoint-25：** 恢复沿原deadline重算余时。**直接失败 D-checkpoint-25：** 重启把剩余时间重新设为完整一小时；预期：沿用原截止并处理停机越期，远端未知结果仍先核对。。**合法邻例 N-checkpoint-25：** 进程单调时钟值不跨主机比较。

### §26 重试、预算与恢复风暴
**机制：** 恢复继承根级已用/在途预算、尝试次数与退避状态；多层引擎/SDK重试只在清晰责任层放大且受联合上限控制。未知费用保留预留，达到硬边界不再派发受影响调用，但目标保持未完成且提供有权接续入口。

**验收：** 根账本守恒且恢复有界；不通过新 run 绕过批准用量。

**执行绑定：** `checkpoint-G06`。**专用正例 P-checkpoint-26：** 根预算尝试退避跨重启保留。**直接失败 D-checkpoint-26：** 循环重启把 max_turns 和费用都清零；预期：根账本守恒且恢复有界；不通过新 run 绕过批准用量。。**合法邻例 N-checkpoint-26：** 不耗该预算的独立节点可继续。

### §27 终态持久化失败与结果交付
**机制：** 分别登记业务结果已证实、最终输出已接受、终态 hook 已执行、会话写入及用户交付回执。最终存储失败不允许重跑已完成工具或终态 hook；恢复须先核对各阶段，必要时新建受控接续记录引用原结果，只重试尚未完成且可去重阶段。

**验收：** 保留原终态效果，新接续只补持久化/可去重交付，不能重复原 hook。

### §28 会话写入与检查点分裂
**机制：** 明确 Session 历史与 RunState/checkpoint 的权威关系；恢复未提交批次时按相同 session/backend 与精确批次身份核对。全部已提交复用，未提交安全补写，部分提交或并发尾部变化隔离核对，不能按文本内容去重不同真实发生事件。

**验收：** 在原权威会话核对批次，不重复工具或静默建立失联历史。

### §29 保留、裁剪与恢复依赖闭包
**机制：** 裁剪历史前验证活跃检查点、delta祖先、待决审批、事件去重及外部操作收据的引用闭包；数据删除/撤回后保留不含被删内容的必要失效标记，旧快照不得恢复已禁用输入。恢复窗口与去重窗口协调，不能为减小大小丢失未决事实。

**验收：** 闭包校验阻止破坏性裁剪，重建或缩小可用恢复集需真实变更记录。

### §30 恢复证据与确定版本验收
**机制：** 每次恢复关联源/目标检查点、代码配置、原因、当前门禁、复用与重执行集合、外部收据和未决项。验证在崩溃点前后分别断言效果次数与状态，不以 SDK 返回或 trace OK 代替真实恢复；运行结果必须对应确定版本及故障注入位置。

**验收：** 记录实际故障矩阵与未测窗口，静态规范检查不能冒充运行证据。

**执行绑定：** `checkpoint-G06`。**专用正例 P-checkpoint-30：** 每崩溃窗口断言效果次数和未决。**直接失败 D-checkpoint-30：** 只跑一次正常流程便宣称所有恢复窗口可用；预期：记录实际故障矩阵与未测窗口，静态规范检查不能冒充运行证据。。**合法邻例 N-checkpoint-30：** 单次正常成功不宣称全恢复通过。

## 四、40 条静态失败输入及预期检查

## 五、L5 实施与L6验收界面

1. L5 给出实际 SDK/引擎/存储版本、持久模式、恢复起点、序列化映射及授权执行门禁。故障注入覆盖：意图提交前后、发送前后、回执前后、检查点指针发布前后、Session批次写入前后及终态hook前后。每点检查已提交输入、实际调用次数、目标效果次数、未决集合和恢复后下一条命令。
2. 在同一逻辑操作上排列两个恢复者、失效旧Worker、撤权、取消、迟到结果和事件先到等交错；断言 R1—R7。针对异步持久丢失窗口、部分子图成功、幂等到期、模型输出变化及旧提示/新工具组合分别建反例，不能只杀进程一次便推断全部恢复边界。
3. 对支持的每个历史schema和联合语义版本进行往返/迁移及历史回放；固定预期工具集合、目标参数和已生效操作集合。受控工具桩检验恢复逻辑，真实选定运行时与存储检验提交/栅栏；真实目标按L6权限检验收据与有效去重契约。三种证据分别报告。
4. 验收记录至少含候选提交、输入/配置身份、注入点、事件序列、预期与实际后继、实际效果计数和未决项。无查询或有效去重能力的外部端点必须展示未知结果的核对/人工处置路径，而不是承诺不存在的恰好一次效果。
5. 复验触发包括SDK/序列化/持久模式变化、模型/提示/工具语义变更、存储迁移、历史裁剪、去重窗口变化与新取消路径。恢复目标、可接受损失窗口和实际运行资源由相应项目确定，不以本篇统一制造新费用或缩小产品目标。

## 六、生命周期与采用

项目按 L1 登记所采用的准确版本、适用条款和依赖关系。L5 选择并验证实际实现，L6 按真实权利及目标验收业务结果；实现验收以相应项目的执行证据为准。
