# L4 代码、浏览器与环境执行隔离技术规范

**文档ID：** STD-L4-AI-AGENT-008　**版本：** 0.1.0　**状态：** adopted　**生效日期：** 2026-10-30

## 一、范围、执行边界与技术职责

本专题适用于 Agent 将模型输出、外部仓库/附件、脚本、Shell、笔记本、依赖构建、浏览器页面和下载内容置于真实可执行环境的情况。须明确宿主协调器、真实用户、浏览器控制端、不可信执行进程、文件、网络、凭据与持久工作区的隔离边界。系统不具备代码或浏览器执行能力时，不强制引入容器、Wasm、VM 或独立服务器；固定且真正只读的受信调用按实际风险裁剪。

相应[STD-L4-AI-AGENT-011 · L4 指令体系、不可信内容与提示注入防护技术规范](011-指令体系、不可信内容与提示注入防护技术规范--v0.1.0.md)负责低信任内容和提示注入识别、[STD-L4-AI-AGENT-009 · L4 工具能力契约与 MCP 互操作技术规范](009-工具能力契约与-MCP-互操作技术规范--v0.1.0.md)负责 Tool/MCP 协议、[STD-L4-AI-AGENT-004 · L4 Agent 授权、可变更动作与业务副作用技术规范](004-Agent-授权、可变更动作与业务副作用技术规范--v0.1.0.md)负责真实授权和业务副作用；本专题单独验证**即使模型被操纵或可执行代码受到攻击，真实 OS/浏览器/文件/网络边界仍限制其能力**。Linux、浏览器、容器和虚拟化的一般配置继承相邻 L4 云/后端安全规范，本专题只规定自主生成可执行输入、浏览器会话与 Agent 工作区带来的独立技术失效。[STD-L4-AI-AGENT-005 · L4 Agent 控制循环、计划与多 Agent 编排技术规范](005-Agent-控制循环、计划与多-Agent-编排技术规范--v0.1.0.md)、[STD-L4-AI-AGENT-015 · L4 长任务状态、检查点与可恢复执行技术规范](015-长任务状态、检查点与可恢复执行技术规范--v0.1.0.md)仍分别约束调度和恢复。L5 实际运行环境、SDK、权限与沙箱隔离测试及 L6 生产/客户数据/财务结果独立完成。

### 执行闭环与实现绑定

### 执行器信任边界与输入来源

### §01 执行面和真实边界识别
**机制：** 执行器在接受模型代码、命令、URL、脚本、笔记本及浏览器操作之前，按实际执行面、权限、输入可信级和可写外部资源分类；模型描述或工具名称不得将可执行操作标为只读。

**验收：** 只读查询伪装成 shell 写命令时，真实执行器按可写能力阻止。

**执行绑定：** `execution-G01`。**专用正例 P-execution-01：** 真实shell写操作按写权分类。**直接失败 D-execution-01：** 模型通过只读工具包装执行文件删除而获准；预期：只读查询伪装成 shell 写命令时，真实执行器按可写能力阻止。。**合法邻例 N-execution-01：** 固定纯计算可按低风险入口。

### §02 宿主协调器与不可信执行隔离
**机制：** 模型生成的代码和第三方项目依赖必须在与编排器、组织凭据及持久状态明确隔离的执行域运行；仅保留经核验的输入/输出通道。

**验收：** 脚本获得沙箱进程控制权后仍无法修改协调器配置或秘密。

**执行绑定：** `execution-G01`。**专用正例 P-execution-02：** 不可信代码与控制器秘密隔离。**直接失败 D-execution-02：** 不可信代码在与 Agent 控制器同进程加载并读取控制密钥；预期：脚本获得沙箱进程控制权后仍无法修改协调器配置或秘密。。**合法邻例 N-execution-02：** 仅有受验固定函数可简化边界。

### §03 执行环境身份和所有权
**机制：** 每次运行绑定任务、真实用户、租户、环境、源版本及有效期，执行域复用不得混淆工作区身份；沙箱标识不是授权凭据。

**验收：** 任务 B 不会读取任务 A 在回收后遗留的数据和进程。

**执行绑定：** `execution-G01`。**专用正例 P-execution-03：** 环境键绑定租户任务有效期。**直接失败 D-execution-03：** 跨租户共享环境将前次任务工作目录视为公共资料；预期：任务 B 不会读取任务 A 在回收后遗留的数据和进程。。**合法邻例 N-execution-03：** 同主体复用仍须清理前次状态。

### §04 能力授予和启动时快照
**机制：** 执行权限由有权服务端按真实动作和资源授予，冻结可审计的文件、网络、凭据、设备能力集；运行途中不能靠模型生成环境变量自行提权。

**验收：** 进程设置 FAKE_ADMIN=1 后仍无法调用生产写接口。

**执行绑定：** `execution-G01`。**专用正例 P-execution-04：** 能力快照由可信启动方签发。**直接失败 D-execution-04：** 代码自行设置管理员环境变量绕过授权限制；预期：进程设置 FAKE_ADMIN=1 后仍无法调用生产写接口。。**合法邻例 N-execution-04：** 环境变量文字不改变内核权限。

### §05 风险适配与最低实现复杂度
**机制：** 纯文本、固定无副作用计算、已签名工具及任意第三方代码按风险分别选原位调用、受限进程、Wasm、容器或更强隔离；不把某一种收费 VM 方案强制用于全部项目。

**验收：** 未执行不可信代码的流程不额外启动收费容器或暴露执行权限。

**执行绑定：** `execution-G01`。**专用正例 P-execution-05：** 按风险选受验隔离实现。**直接失败 D-execution-05：** 纯文本请求被无理由升级到有网络和主机挂载的代码沙箱；预期：未执行不可信代码的流程不额外启动收费容器或暴露执行权限。。**合法邻例 N-execution-05：** 无可执行输入无需强制容器。

### 命令、进程和操作系统权限

### §06 命令参数与解释器边界
**机制：** 明确区分固定命令加参数、shell 字符串、脚本解释及进程启动；对可控参数采用参数数组和数据验证，不把不可信文件名拼接进 shell。

**验收：** 文件名包含分号、换行、命令替换符号时只能被当成文件名。

**执行绑定：** `execution-G02`。**专用正例 P-execution-06：** 分号文件名作为单一argv。**直接失败 D-execution-06：** 用户提供的文件名经 shell 插值额外执行系统命令；预期：文件名包含分号、换行、命令替换符号时只能被当成文件名。。**合法邻例 N-execution-06：** 获准解释脚本仍运行受限域。

### §07 进程树继承及终止归属
**机制：** 为运行创建独立进程组和受控子进程树，明确可继承文件描述符、用户身份、工作目录、信号与终止处理；禁止逃逸为后台守护任务。

**验收：** 顶层命令退出后其子进程和持有资源的孙进程均受限并可回收。

**执行绑定：** `execution-G02`。**专用正例 P-execution-07：** 子孙进程有可查归属可回收。**直接失败 D-execution-07：** shell 派生脱离父进程的后台任务继续访问宿主资源；预期：顶层命令退出后其子进程和持有资源的孙进程均受限并可回收。。**合法邻例 N-execution-07：** 真正脱离父任务须明确新责任。

### §08 最小操作系统身份
**机制：** 进程使用无额外系统管理能力的身份与用户/组映射，不允许业务 Agent 以宿主 root、特权令牌或高权限默认账号执行外部代码。

**验收：** 不可信执行尝试写入宿主受限配置时得到内核级拒绝。

**执行绑定：** `execution-G02`。**专用正例 P-execution-08：** 非宿主root身份执行外部代码。**直接失败 D-execution-08：** 沙箱内进程使用宿主 root 写入系统配置；预期：不可信执行尝试写入宿主受限配置时得到内核级拒绝。。**合法邻例 N-execution-08：** 容器内UID0也需核实际宿主映射。

### §09 系统调用及额外权能过滤
**机制：** 按平台和版本验证 seccomp、能力限制、LSM 或等效操作系统控制的实际生效范围，不把容器名称或禁用某个 API 当成系统调用隔离。

**验收：** 禁用 syscall 过滤的反例不会在检验中被误认为已经沙箱化。

**执行绑定：** `execution-G02`。**专用正例 P-execution-09：** seccomp实际启用并验证拒绝。**直接失败 D-execution-09：** sandbox 标志为 true 但 seccomp 为 unconfined 仍被判已隔离；预期：禁用 syscall 过滤的反例不会在检验中被误认为已经沙箱化。。**合法邻例 N-execution-09：** 单独seccomp不声称完整沙箱。

### §10 文件描述符和 IPC 传递
**机制：** 启动执行前关闭或替换不必要的父进程文件描述符、UNIX Socket、管道和进程间通信入口；不得把特权 Docker/Agent 控制 Socket 挂入沙箱。

**验收：** 恶意任务无法通过继承的套接字控制宿主容器或其他任务。

**执行绑定：** `execution-G02`。**专用正例 P-execution-10：** 不继承Docker控制socket。**直接失败 D-execution-10：** 可执行代码利用继承的 Docker Socket 启动特权工作负载；预期：恶意任务无法通过继承的套接字控制宿主容器或其他任务。。**合法邻例 N-execution-10：** 必要受限IPC有明确授权契约。

### 文件、容器和资源硬边界

### §11 文件系统视图与最小挂载
**机制：** 每个执行域仅显露所需工作目录、只读输入和明确可写输出，敏感宿主路径、父目录与跨任务卷不应被透传；目录权限和挂载模式分别核验。

**验收：** 运行程序无法读取未授权的用户主目录、环境秘密文件或其他租户卷。

**执行绑定：** `execution-G03`。**专用正例 P-execution-11：** 只挂输入和指定输出目录。**直接失败 D-execution-11：** 沙箱虽限定输出目录却将宿主 HOME 整卷读写挂载；预期：运行程序无法读取未授权的用户主目录、环境秘密文件或其他租户卷。。**合法邻例 N-execution-11：** 只读卷也需核其中数据读取权。

### §12 路径解析与链接竞态
**机制：** 文件访问使用受根目录约束的规范化路径、文件描述符及适当内核原语防止 `..`、符号链接、硬链接、挂载别名及 TOCTOU 绕过。

**验收：** 竞争替换输出文件为指向宿主秘密的链接后，读写仍被拒绝。

**执行绑定：** `execution-G03`。**专用正例 P-execution-12：** 路径打开时约束根及链接竞态。**直接失败 D-execution-12：** 检查路径后攻击者替换符号链接读取沙箱外密钥；预期：竞争替换输出文件为指向宿主秘密的链接后，读写仍被拒绝。。**合法邻例 N-execution-12：** 合法内部符号链接按平台合同处理。

### §13 执行目录只读与持久化分离
**机制：** 代码、依赖、编译缓存、运行态和最终产物分区域管理；只允许经过验证的输出晋升为交付文件，不将沙箱可写目录当作可信执行入口。

**验收：** 修改临时依赖缓存不能覆盖下一次可信启动程序。

**执行绑定：** `execution-G03`。**专用正例 P-execution-13：** 临时产物不覆盖可信启动缓存。**直接失败 D-execution-13：** 运行脚本将恶意二进制写入下一任务共用 PATH 并被执行；预期：修改临时依赖缓存不能覆盖下一次可信启动程序。。**合法邻例 N-execution-13：** 经验证只读公共依赖可复用。

### §14 内核限制互补及版本探测
**机制：** namespaces、Landlock、LSM、seccomp、用户映射等保护具有不同覆盖和内核/OS 兼容条件；应检查实际功能与失败模式，不能由单一配置推断完整隔离。

**验收：** 内核不支持请求的隔离能力时执行器按安全策略拒绝或选等价已验方案。

**执行绑定：** `execution-G03`。**专用正例 P-execution-14：** 能力不支持则拒绝对应执行。**直接失败 D-execution-14：** 旧内核忽略某隔离特性，执行器依然报告全部保护生效；预期：内核不支持请求的隔离能力时执行器按安全策略拒绝或选等价已验方案。。**合法邻例 N-execution-14：** 可选等价已验方案而非全任务取消。

### §15 容器、Wasm 与虚拟机隔离级别
**机制：** 对来源不可控、可编译原生代码、浏览器和高危数据场景按实际攻击面选择隔离机制；Wasm 仅具显式导入能力，容器与宿主共享内核，VM 具有额外隔离边界。

**验收：** 可运行原生恶意二进制的高风险任务不会因使用普通容器就宣称具备 VM 边界。

### §16 容器运行权与宿主的控制面
**机制：** 禁止未授权 `--privileged`、host network/PID、设备直通、Docker Socket 和宿主根挂载；容器创建 API 及模板需由可信控制面约束而非执行代码自行决定。

### §17 CPU、内存与进程数硬预算
**机制：** 执行域应实施平台可验证的 CPU 时间、墙钟时限、内存及子进程数上限，并区分 OOM、超时、平台停止和业务取消状态。

### §18 磁盘、输出和日志容量
**机制：** 限制临时目录、写入大小、文件数量、解压体积、标准输出及日志速率；达到阈值时终止或拒绝，而非挤占宿主共享磁盘。

### §19 依赖安装、编译及供应链脚本

### §20 执行域生命周期与资源回收
**机制：** 运行、暂停、超时、失败和取消均须关闭进程树、临时网络端点、挂载、文件描述符与受权凭据；回收不代表外部已发生业务副作用被撤销。

### 浏览器会话和控制面隔离

**机制：** 每个受控浏览任务创建独立非持久 BrowserContext 或等价运行隔离，明确页面、弹窗、下载、Cookie、Storage 与身份的归属；复用浏览器进程不等于可复用登录态。

### §22 持久浏览器资料与登录凭据

### §23 浏览器自动化控制通道
**机制：** CDP、remote debugging、WebDriver、Playwright Browser Server 与控制端 Socket 均为高权入口；绑定受控地址与会话，禁止低信任页面或其他任务直接连接。

### §24 页面来源与导航链验证
**机制：** 模型选定链接、页面跳转、重定向与最终 Origin 应按真实网络位置和授权目标检查；新窗口、iframe、弹窗不得默认为原网站的可信延伸。

### §25 DOM、截图与网页内容信任边界
**机制：** 页面 DOM、可访问性树、HTML、截图 OCR 及 WebSocket 消息均视为网站提供的数据，不得变为执行器系统指令或权限批准；相关防护继承[STD-L4-AI-AGENT-011 · L4 指令体系、不可信内容与提示注入防护技术规范](011-指令体系、不可信内容与提示注入防护技术规范--v0.1.0.md)。

### §26 页面脚本与自动化评估权限

### §27 网页权限和设备能力
**机制：** 摄像头、麦克风、地理位置、通知、剪贴板、USB、文件系统及下载启动权限默认仅按任务需要与真实主体授权启用，撤权后关闭。

### §28 上传、下载与浏览器出站文件
**机制：** 文件选择、拖放、上传、下载与自动保存应经过真实目录白名单、数据出站策略和最终产物检查；下载文件不得自动作为可执行脚本或可信附件转发。

### 网络出口与秘密约束

### §29 执行网络出口与地址解析
**机制：** 按任务提供最小需要的外联能力；对 URL、DNS、IPv4/IPv6、私网、回环、链路本地与云元数据地址按真实解析结果检查，不把 DNS 名称白名单当成 IP 出口门禁。

### §30 重定向、代理和协议切换
**机制：** HTTP 重定向、代理、DNS 缓存、连接复用、WebSocket、FTP 与本地 UNIX Socket 的出站约束必须随实际目标重验；禁止借协议转换进入内网或特权服务。

### §31 凭据注入与生命周期最小化
**机制：** 仅由可信控制面按资源和任务提供必要短期凭据，不将组织长期密钥放入环境变量全集、命令行参数、浏览器 Profile 或持久镜像；执行域撤销必须独立有效。

### §32 标准输出、错误与终端控制字符
**机制：** stdout、stderr、PTY、ANSI 转义及执行日志只是来自不可信程序的结果；输出大小、控制字符、可执行命令片段和敏感内容按受众清洗，不可隐式执行。

### §33 任务间共享缓存与编译产物
**机制：** 依赖下载、浏览器缓存、编译输出及容器层在不同信任域复用前应核对来源、写权与内容身份；不允许低权租户污染后续可信任务入口。

### 输入输出、恢复和分层验收

### §39 突破验证与故障注入
**机制：** 静态配置审查、受控恶意样本、真实用户/租户隔离、逃逸和网络外发阻断须按隔离强度分级实测；对 CPU/PID/文件/权限、浏览器资料及跨任务状态保留反例和环境版本。

**验收：** 隔离验证包含真实拒绝响应和结果文件，不能用仅模型口头拒绝判通过。

**执行绑定：** `execution-G08`。**专用正例 P-execution-39：** 真实拒绝证据对应具体环境。**直接失败 D-execution-39：** 沙箱仅跑 echo hello 即宣称经受过逃逸与秘密访问测试；预期：隔离验证包含真实拒绝响应和结果文件，不能用仅模型口头拒绝判通过。。**合法邻例 N-execution-39：** echo成功不证明路径网络隔离。

### §40 L4 与 L5/L6 验收分层
**机制：** L4 规定执行域和技术能力边界；L5 要在真实 OS、容器/Wasm、浏览器、网络和运行权限下验证；L6 生产、资金、客户数据、出站发送及实际业务结果仍由有权主体审批验收。

**验收：** CI 通过不能被记为生产环境已阻断数据泄露或完成客户履约。

**执行绑定：** `execution-G08`。**专用正例 P-execution-40：** L5隔离与L6业务权利分列。**直接失败 D-execution-40：** 单元测试绿灯被宣传成已完成生产沙箱逃逸认证；预期：CI 通过不能被记为生产环境已阻断数据泄露或完成客户履约。。**合法邻例 N-execution-40：** 沙箱通过不授客户数据外发许可。

## 四、52 条静态失败输入及预期检查

前 40 条一一对应 §01—§40，后 12 条为跨文件、网络、浏览器与执行域的复合失效输入。以下是可复核静态反例及预期行为，并非已执行的沙箱逃逸、真实浏览器或生产环境测试。

| --- | --- | --- |
| 模型通过只读工具包装执行文件删除而获准 | §01 | 只读查询伪装成 shell 写命令时，真实执行器按可写能力阻止。 |
| 不可信代码在与 Agent 控制器同进程加载并读取控制密钥 | §02 | 脚本获得沙箱进程控制权后仍无法修改协调器配置或秘密。 |
| 跨租户共享环境将前次任务工作目录视为公共资料 | §03 | 任务 B 不会读取任务 A 在回收后遗留的数据和进程。 |
| 代码自行设置管理员环境变量绕过授权限制 | §04 | 进程设置 FAKE_ADMIN=1 后仍无法调用生产写接口。 |
| 纯文本请求被无理由升级到有网络和主机挂载的代码沙箱 | §05 | 未执行不可信代码的流程不额外启动收费容器或暴露执行权限。 |

## 五、分层验收与失效恢复

1. **静态与离线：** 固定 OS/browser/SDK 来源版本、任务信任级、权限模型、资源配额、路径与网络出站策略；对 52 个静态反例进行结构、权限与预期拒绝检查。静态文本或模拟结果不证明隔离实际生效。
2. **L5 真正运行：** 在获准的隔离环境实测用户/租户跨域、文件目录与符号链接、子进程、网络 DNS/重定向、浏览器 Cookie/Profile/CDP、资源限额、临时清理、沙箱禁用或不可用回退；保留执行器、kernel、浏览器、容器/Wasm 的真实版本和拒绝证据。不假装已有沙箱逃逸测试。
3. **L6 外部业务：** 生产写入、客户数据、对外传输、付费资源创建及实际外部副作用仍需有权人独立批准和真实业务回执。即使 L5 沙箱有效也不能据此自动取得商业或数据授权。
4. **变更/恢复：** OS、kernel、镜像、浏览器版本、SDK、挂载、凭据注入、网络策略、权限与工作区复用规则变化后执行受影响项定向回归；不支持关键隔离功能时拒绝或换已验证等价实现，不能退化为无约束宿主执行。

## 六、生命周期与采用

项目按 L1 登记所采用的准确版本、适用条款和依赖关系。L5 选择并验证实际实现，L6 按真实权利及目标验收业务结果；实现验收以相应项目的执行证据为准。
