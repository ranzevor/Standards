# L4 上下文组装、窗口管理与语义压缩技术规范

**文档ID：** STD-L4-AI-AGENT-007　**版本：** 0.1.0　**状态：** adopted　**生效日期：** 2026-10-30

## 一、适用条件、信息权利及跨专题分工

本专题适用于模型长对话、Agent 任务循环、多工具工作流和多模态输入的**暂态上下文选择、窗口预算、结构化压缩与恢复**。其控制对象是模型每次调用所读取的任务信息，不等于在外部索引中检索知识、经用户授权持久化记忆或执行器 Checkpoint。无需长上下文的简单应用可保留极简实现；不得因此强制采购向量数据库、付费压缩服务或采用某一云商。

[AI 应用与 Agent 领域通用基线](001-AI-应用与-Agent-系统领域通用基线--v0.1.0.md)确定真实权限与业务结果分界；[模型接入与响应契约](014-模型接入、推理调用与响应契约技术规范--v0.1.0.md)决定原生 API 能力和消息终态；[指令信任与提示注入防护](011-指令体系、不可信内容与提示注入防护技术规范--v0.1.0.md)决定低信任资料不得变成高权指令。[STD-L4-AI-AGENT-012 · L4 检索、知识接入与可验证溯源技术规范](012-检索、知识接入与可验证溯源技术规范--v0.1.0.md)、[STD-L4-AI-AGENT-010 · L4 持久记忆、会话隔离与生命周期技术规范](010-持久记忆、会话隔离与生命周期技术规范--v0.1.0.md)、[STD-L4-AI-AGENT-015 · L4 长任务状态、检查点与可恢复执行技术规范](015-长任务状态、检查点与可恢复执行技术规范--v0.1.0.md)、[STD-L4-AI-AGENT-002 · L4 AI 应用评测、回归与对抗验收技术规范](002-AI-应用评测、回归与对抗验收技术规范--v0.1.0.md)保留各自的独立机制。

本专题仅在构建请求上下文时提出事实、来源、权限、顺序、窗口与压缩保真的独立验收条件。L5 具体实现由实际模型/SDK/API 和会话存储完成；L6 由项目有权主体确认生产数据、费用、外部动作及真实业务结果。较大的窗口不提供准确性保证，更便宜的缓存不等于释放窗口容量，压缩之后的模型状态不自动成为新的授权凭据。

## 三、40 项独立机制与验收条件

### 执行闭环与实现绑定

| 组/条款 | 责任者及运行入口 | 权威输入 → 可观测输出 | 失败、并发、超时与恢复 | 兼容/合法边界 |

### 机制组：任务状态、上下文与权威边界

### §01 单次上下文的执行范围
**机制：** 上下文是一次模型请求可访问的输入、工具契约与必要状态，不等于全部组织知识或用户长期记忆；按具体任务、模型和执行主体确立窗口边界。

**验收：** 从一个用户临时任务切换到另一租户时不继承对方的历史信息或隐式能力。

**执行绑定：** `context-G01`。**专用正例 P-context-01：** 只装配当前租户任务窗口。**直接失败 D-context-01：** 用户 B 的新请求自动带入租户 A 的私有任务上下文；预期：清除无权读取的历史上下文并按当前主体构造请求。**合法邻例 N-context-01：** 同模型不同任务不共享隐式状态。

### §02 当前有效目标与否决
**机制：** 把用户当前目标、已明确拒绝的动作、授权时效和项目生效规范作为需要可定位来源的关键状态，不依赖概率摘要替代决策记录。

**验收：** 长会话压缩前后对资金、删除、外发等否决保持一致；冲突时按真正有权的最新决定处理。

**执行绑定：** `context-G01`。**专用正例 P-context-02：** 拒付决定保留源事件身份。**直接失败 D-context-02：** 用户拒绝付款后旧摘要只保留付款建议；预期：恢复后不得执行被撤回的付款动作。**合法邻例 N-context-02：** 过期建议可删但当前否决不可删。

### §03 事实、推断与未决项分类
**机制：** 将经权威验证的事实、第三方内容、模型推断、工作计划、未完成依赖、实际操作回执分别表达，避免压缩把推测转成已执行事实。

**验收：** 未执行 PR 合并的计划不能在摘要中转成“已合并”，无真实回执则仍待核验。

**执行绑定：** `context-G01`。**专用正例 P-context-03：** 计划与已执行回执分字段。**直接失败 D-context-03：** 模型计划运行 CI 被压缩成“CI 成功”；预期：保留执行证据和未完成状态差异。**合法邻例 N-context-03：** 无回执结论可标待核而不填成功。

### §04 暂态上下文与持久记忆分离
**机制：** 当前窗口内临时工作状态、检索证据、用户授权写入的跨会话记忆和可恢复执行检查点由不同来源与保留契约管理；本专题只定义窗口装配和丢失保护。

**验收：** 会话摘要不能自动成为可跨用户检索的长期记忆或具写入权限的检查点。

**执行绑定：** `context-G01`。**专用正例 P-context-04：** 窗口摘要不写跨会话记忆。**直接失败 D-context-04：** 将一次工具返回的敏感内容直接写入全局长期记忆；预期：须使用独立记忆写入授权与保留边界。**合法邻例 N-context-04：** 明确授权记忆可经独立入口写入。

### §05 上下文重建的输入契约
**机制：** 每次请求明确可复用原消息、服务端状态标识、压缩产物、检索引用和环境版本，并验证状态恢复后用户/项目/工具权限仍有效。

**验收：** 旧任务恢复时不会凭旧上下文恢复已撤销的外部工具或历史财务许可。

**执行绑定：** `context-G01`。**专用正例 P-context-05：** 重建前校验用户工具权限。**直接失败 D-context-05：** 用旧任务快照继续执行已经关闭的高权工具；预期：恢复前重新核验当前授权和版本。**合法邻例 N-context-05：** 旧上下文可用于解释历史。

### 机制组：窗口计量、资源预算与模型差异

### §06 实际窗口与模型限制
**机制：** 记录所选模型/端点实际输入、输出、推理及工具限制，采用供应商可用能力和实际请求计量，不把宣传最大窗口当作所有调用均可使用的固定值。

**验收：** 超出选用模型窗口的请求在产生错乱结果前受控裁剪/分批或拒绝。

**执行绑定：** `context-G02`。**专用正例 P-context-06：** 按实际端点窗口留输出额。**直接失败 D-context-06：** 将 1M 模型宣传值用于实际 200K 端点请求；预期：按真实端点窗口预算拒绝越界请求。**合法邻例 N-context-06：** 大窗口宣传不当作所有端点能力。

### §07 指令工具及多模态成本计数
**机制：** 按所选 tokenizer 或计数 API 纳入角色标记、系统提示、工具定义、图片音频/PDF、工具结果、缓存前缀与可能的推理 token；字符长度不是可靠 token 度量。

**验收：** 图片附件和长工具 Schema 消耗能计入预算，避免纯文本估算低报。

**执行绑定：** `context-G02`。**专用正例 P-context-07：** 图片和工具Schema计入输入。**直接失败 D-context-07：** 把图片 token 记为零导致请求超限；预期：按实际模态与工具成本估算并保留余量。**合法邻例 N-context-07：** 缓存费用折扣不减窗口占用。

### §08 输出与思考保留量
**机制：** 为目标输出、结构化响应、工具续写及可能的 reasoning/thinking 分配独立容量，避免输入占满窗口导致业务必填内容无法完成。

**验收：** 超长材料分析仍为合法完整响应保留足够空间，或进入清晰的不完整状态。

**执行绑定：** `context-G02`。**专用正例 P-context-08：** 推理输出工具续写各留容量。**直接失败 D-context-08：** 上下文占满所有 token 后强行要求长合同生成；预期：为输出留容量，不把截断标为完成。**合法邻例 N-context-08：** 不足可分批而非承诺完整。

### §09 成本、延迟和质量联合预算
**机制：** 窗口预算同时考量上下文长度、缓存折扣、服务端压缩费用、响应质量与请求耗时；便宜缓存命中不是扩大授权、无限上下文或已验证准确性的证据。

**验收：** 预算超额时有可解释的减载/停止策略而不牺牲关键业务事实。

**执行绑定：** `context-G02`。**专用正例 P-context-09：** 成本质量时延共同评估。**直接失败 D-context-09：** 缓存折扣让无关十万 token 被反复传入导致质量退化；预期：压缩无关数据并遵守任务费用上限。**合法邻例 N-context-09：** 便宜缓存可用但不扩授权。

### §10 溢出、估算误差与硬停条件
**机制：** 区分预估用量、供应商最终 token 计量、临界溢出与可执行裁剪；对重复失败设置次数/时间/费用停止门禁。

**验收：** 同一请求不断触发 context_length_exceeded 时不会无界重试扣费。

**执行绑定：** `context-G02`。**专用正例 P-context-10：** 连续溢出达到上限不再派发。**直接失败 D-context-10：** 窗口超限错误导致自动无穷减小 max_output_tokens；预期：按明确策略修复输入或停止。**合法邻例 N-context-10：** 可证明有效裁剪可有限重试。

### 机制组：资料选取、语义相关性与证据来源

### §11 任务依赖与信息选择
**机制：** 按当前任务实际必需的对象、用户决定、源规范、约束、工具状态与证据选取资料，而非机械追加所有历史内容。

**验收：** 检索到许多无关日志时能保留定位当前故障所需的必要事实。

**执行绑定：** `context-G03`。**专用正例 P-context-11：** 当前故障证据优先入窗口。**直接失败 D-context-11：** 把已否定的五种方案塞满上下文，挤掉当前目标；预期：保留有效需求、证据和约束并删除无关冗余。**合法邻例 N-context-11：** 无关旧日志可以归档。

### §12 来源权威、版本及有效性
**机制：** 对消息、检索片段、外部规范及工具输出保留来源、版本、生效与撤回状态、访问权限；检索排序和模型摘要均不自动赋权。

**验收：** 旧草案不会因为相关性高而覆盖当前已批准正式 main 的状态。

**执行绑定：** `context-G03`。**专用正例 P-context-12：** 现行来源及权限优先排名。**直接失败 D-context-12：** 检索旧版待审核文档用于覆盖新正式批准条款；预期：以实际版本权威和有效状态为准。**合法邻例 N-context-12：** 有权历史查询可用旧版。

### §13 冲突、纠错与替代关系
**机制：** 同一事实出现不同日期/来源时区分真实修改、否决、撤回和并行候选；摘要必须表达哪个决定仍有效，不能仅保留最近一句未经核实的主张。

**验收：** 任务历史存在已替换修复路线时不会把旧补丁当作最新正确做法。

**执行绑定：** `context-G03`。**专用正例 P-context-13：** 纠错显式替代旧值并留依据。**直接失败 D-context-13：** 用户否决的旧分支被后续助手摘要恢复为当前工作分支；预期：保留撤回原因与最新有效选择。**合法邻例 N-context-13：** 新近低权主张不自动胜出。

### §14 上下文片段的角色和信任隔离
**机制：** 将用户任务要求与网页、PDF、工具报错、第三方 Agent 消息等非可信资料以可检验结构分离，不因截断或压缩丢失角色来源。

**验收：** 压缩第三方网页后其中命令仍为引用内容，而非用户/系统指令。

**执行绑定：** `context-G03`。**专用正例 P-context-14：** 网页引用不变developer命令。**直接失败 D-context-14：** 网页中的 system: 命令在摘要里被提升为 developer 要求；预期：压缩不能升级低信任指令。**合法邻例 N-context-14：** 合法用户任务可要求分析网页。

### §15 长上下文顺序及位置偏差
**机制：** 对关键约束放置与检索顺序使用可重复的正反例，验证信息处于头、中、尾及分散位置时决策与引用准确性。

**验收：** 仅因否决信息位于中间而遗漏时，版本不能宣称长文本处理已达标。

**执行绑定：** `context-G03`。**专用正例 P-context-15：** 否决在头中尾均被保留。**直接失败 D-context-15：** 重要风险条件移到长文中部后模型不再识别；预期：对不同位置执行独立回归。**合法邻例 N-context-15：** 位置变化不强制逐字输出相同。

### 机制组：轮次、工具调用与并行因果关系

### §16 消息时序与有效阶段
**机制：** 区分用户轮次、助手中间进度、最终回答、工具调用和工具结果；拼接与回放应保留原始顺序、阶段与版本。

**验收：** 中间进度不会被压缩为最终用户已确认的业务输出。

**执行绑定：** `context-G04`。**专用正例 P-context-16：** 中间进度与final按phase区分。**直接失败 D-context-16：** 把辅助进度消息当作用户已接受的最终交付；预期：保留消息 phase/role 语义。**合法邻例 N-context-16：** 无phase接口可用受验适配映射。

### §17 工具调用与返回的原子关联
**机制：** 同一工具调用 ID、参数、实际返回及授权结果的因果关系不可被压缩拆分造成错配；清理时保留必要状态和外部回执。

**验收：** 工具返回属于另一个 call_id 时不能替换本次动作的真实收据。

**执行绑定：** `context-G04`。**专用正例 P-context-17：** call与result同身份成对保留。**直接失败 D-context-17：** 删除工具请求只保留“success”响应并错误绑定另一支付动作；预期：工具配对和业务回执不可混用。**合法邻例 N-context-17：** 可清理已无依赖的旧大结果。

### §18 未完成异步事件与取消
**机制：** 流中 Delta、后台等待、延迟通知和取消请求需保留进行中状态；模型摘要不能把 submitted、running 或 cancel_requested 当作 done。

**验收：** 恢复后能区分外部操作可能已发生与尚未确认完成，避免盲重试。

**执行绑定：** `context-G04`。**专用正例 P-context-18：** cancel_requested保持未决事实。**直接失败 D-context-18：** 后台工具写入仍 pending 却摘要成已完成；预期：继续查权威状态，不执行重复动作。**合法邻例 N-context-18：** 已证实完成收据可独立补账。

### §19 任务分叉、合并与并行所有权
**机制：** 多个 Agent/分支的上下文基于各自父版本、用户授权、文件/业务对象归属和任务 ID 合并；禁止用一个分支旧摘要覆盖另一个分支新事实。

**验收：** 并行作者的进度不能被简单合并成全部工作已验证。

**执行绑定：** `context-G04`。**专用正例 P-context-19：** 分支合并核父版本和写域。**直接失败 D-context-19：** 并行 Agent 各自写同一文件后仅保留旧分支摘要；预期：按版本与证据解决冲突。**合法邻例 N-context-19：** 无冲突只读分支可并行。

### §20 恢复检查点与外部真实状态
**机制：** 恢复中的窗口摘要属于模型输入，不是 checkpoint 已落盘或外部业务成功的证据；在途工具和已发动作须查实际系统状态并校验当前权限。

**验收：** 执行器崩溃后不会依据“预计成功”的摘要重复收费、通知或提交。

**执行绑定：** `context-G04`。**专用正例 P-context-20：** 预计支付成功不作重放依据。**直接失败 D-context-20：** 压缩记录‘付款应该成功’后恢复再次付款；预期：先核对支付回执与有效授权。**合法邻例 N-context-20：** 查询证实未发可沿原意图继续。

### 机制组：压缩、摘要与关键事实保真

### §21 可保留事实的结构化约束
**机制：** 以当前任务、必要约束、权利/否决、未决事项、客观证据与下一有效动作分开构造压缩保留集合；不能只要求“总结主要内容”。

**验收：** 恢复后保留关键日期、金额、租户、对象、否决与尚未完成项，且可核对原始来源。

**执行绑定：** `context-G05`。**专用正例 P-context-21：** 摘要显式列目标拒绝未知项。**直接失败 D-context-21：** 自动摘要把‘不允许合并’删除，仅留下‘准备合并’；预期：保留否决与实际状态。**合法邻例 N-context-21：** 已失效背景资料可不入活跃窗口。

### §22 可验证精度与数字类型
**机制：** 压缩前后对金额、日期、版本 SHA、精度单位、范围/上限、调用工具参数和条件保持语义；不允许按摘要风格省略影响决策的必要数字。

**验收：** 原输入中的不可逆删除对象与有效授权范围未被模糊概括。

**执行绑定：** `context-G05`。**专用正例 P-context-22：** 金额币种SHA类型保持精确。**直接失败 D-context-22：** 把 200 MiB 内存限制压缩成‘资源足够’；预期：保留可验证数值和单位。**合法邻例 N-context-22：** 可展示舍入值但执行用精确值。

### §23 出处、引文与可重取能力
**机制：** 压缩产生摘要时关联源片段位置、版本、访问权与重新获取路径；独立引用必须能区分模型推断和原始可核对事实。

**验收：** 权威文件发生变化时可以定位原版本和当前生效内容而非凭摘要替代。

**执行绑定：** `context-G05`。**专用正例 P-context-23：** 摘要引用可重取原源版本。**直接失败 D-context-23：** 摘要称某标准已批准但没有链接或版本回读；预期：引用原始权威或标记未核验。**合法邻例 N-context-23：** 源依法删除可记录不可回读。

### §24 分层压缩与重复压缩衰减
**机制：** 长任务可按阶段整理已完成结果、活跃约束、历史证据归档，但每次进一步压缩要防止关键内容在多轮摘要里渐进消失。

**验收：** 多次压缩后仍可恢复真正未批准事项、用户撤回与未完成外部动作。

**执行绑定：** `context-G05`。**专用正例 P-context-24：** 三次压缩仍保留当前否决。**直接失败 D-context-24：** 第一次保留审批限制，第三次压缩后彻底丢失；预期：做分层语义回归和必要源重取。**合法邻例 N-context-24：** 可将历史成功移到受控归档。

### §25 压缩失败的拒绝/恢复路径
**机制：** 对未知冲突、来源缺失、摘要不保真、令牌估算错误或模型拒绝压缩定义回退；不能为了腾出窗口而编造确定性结论。

**验收：** 关键用户决定不明确时请求真实状态或停止敏感外部动作，而非继续执行。

**执行绑定：** `context-G05`。**专用正例 P-context-25：** 压缩冲突时重取权威记录。**直接失败 D-context-25：** 摘要不确定付款是否完成时写成“完成”；预期：进入待核验状态并核对外部收据。**合法邻例 N-context-25：** 独立无风险子任务不必全停。

### 机制组：供应商上下文管理及缓存语义

### §26 OpenAI 透明与不透明压缩区别
**机制：** 选用 OpenAI Responses compaction 时识别服务端自动压缩和独立 /responses/compact 返回的加密不透明 item；不得篡改、解析或重排其内部语义作为人类可读审批记录。

**验收：** 显式 compact 输出以服务端返回窗口为后续输入， opaque item 仅作为协议状态继续传递。

**执行绑定：** `context-G06`。**专用正例 P-context-26：** opaque item按协议原样传递。**直接失败 D-context-26：** 取出 encrypted compaction item 自行写成‘批准付款’摘要；预期：不将不透明模型状态当授权或可人工审计事实。**合法邻例 N-context-26：** 可另存可审计决策但不解析opaque。

### §27 OpenAI 手动与服务端续接互斥条件
**机制：** 按所选 Responses 版本区分 previous_response_id 链接与完整 input-array 回放，保留工具/推理输出 item、phase 与关联；禁止两种方式混用时重复追加同一历史。

**验收：** 启用 previous_response_id 时不手动清理服务端链；手动方式按要求保留或使用完整 compact 输出。

**执行绑定：** `context-G06`。**专用正例 P-context-27：** previous_response_id只送新输入。**直接失败 D-context-27：** previous_response_id 加全量历史，导致同一工具请求重复出现在窗口；预期：选一种明确继承机制并核对因果。**合法邻例 N-context-27：** 手动全窗口回放是另一合法模式。

### §28 Claude Compaction Beta 的行为边界
**机制：** 选用 Claude API compaction 时记录 beta 版本、compact block 对旧上下文的替代规则、自动阈值或按需压缩差异及输入保留责任。

**验收：** 压缩触发后应用按该接口要求传递压缩块，不双重保留或遗漏重要后续轮次。

**执行绑定：** `context-G06`。**专用正例 P-context-28：** compact块按所选beta回放。**直接失败 D-context-28：** 把 Claude compact block 当普通文本删除，导致后续工具失去上下文；预期：按真实 beta 契约处理且执行语义核验。**合法邻例 N-context-28：** 未选Claude不需实现该格式。

### §29 Claude 上下文编辑与思考/工具清除
**机制：** 工具结果清除和 thinking block 清除分别遵守供应商版本限制及签名/缓存契约；清除低价值旧日志不能删除尚在途工具结果和真实批准。

**验收：** 旧工具结果可按条件清理，但当前轮工具 request/result 及签名不被破坏。

**执行绑定：** `context-G06`。**专用正例 P-context-29：** 清除旧工具结果保持当前调用配对。**直接失败 D-context-29：** 为节省 token 清除当前回合 thinking/call item，造成后续 API 拒绝或错位；预期：保持受支持的回放边界。**合法邻例 N-context-29：** 服务端编辑不要求手动同步改本地。

### §30 Gemini 缓存与窗口不能混同
**机制：** 区分所选Gemini API世代与模型：当前Interactions仅支持隐式缓存；显式cache对象只在仍支持它的旧generateContent模型组合中使用，Gemini4及以后不据旧接口假定支持。按实际TTL、接收权利和计量核验；缓存费用减免不等于释放窗口、允许超限或维持已撤回数据可用。

**验收：** 缓存复用大前缀仍纳入上下文预算，明确实际数据生命周期及权限。

**执行绑定：** `context-G06`。**专用正例 P-context-30：** 缓存前缀仍计入窗口。**直接失败 D-context-30：** 把 cached token 从窗口占用中全部扣除导致请求超限；预期：窗口容量和费用优化分开计量。**合法邻例 N-context-30：** 新版不支持显式缓存可仅用隐式。

### 机制组：数据权利、失效传播与可观测性

### §31 跨租户隔离与最小上下文披露
**机制：** 按当前主体与用途选择历史消息、缓存前缀、工具返回和外部资料；不得因为压缩减少体积就绕过原始数据权利、法域与接收者限制。

**验收：** 租户 A 历史被压缩后仍不能作为租户 B 的共享系统前缀。

**执行绑定：** `context-G07`。**专用正例 P-context-31：** A摘要不作为B公共前缀。**直接失败 D-context-31：** 把含 A 用户秘密的压缩摘要当公共提示模板给 B；预期：源数据的权限不因摘要消失。**合法邻例 N-context-31：** 获准匿名公共材料可共享。

### §32 不可信资料的摘要洗白防护
**机制：** 第三方工具/网页的注入指令在语义摘要、重写、翻译或压缩后仍保持低信任来源；引用摘要不能授予工具写入或财务权限。

**验收：** 恶意检索结果经摘要传给后续 Agent 时不能变成高权行动命令。

**执行绑定：** `context-G07`。**专用正例 P-context-32：** 网页经翻译仍保留低信任。**直接失败 D-context-32：** 网页的‘导出全部’指令经多轮压缩成为系统任务；预期：保持来源与权限边界。**合法邻例 N-context-32：** 有权用户可引用指令原文。

### §33 供应商存储、缓存与删除范围
**机制：** 区分本地暂态窗口、提供商状态链、加密 compaction item、显式 cache object、上传文件和长期记忆的保留/删除契约，分别按实际权利与版本处理。

**验收：** 用户请求删除后不因旧供应商缓存或对话链重新取回受撤销内容。

**执行绑定：** `context-G07`。**专用正例 P-context-33：** 删除覆盖供应商独立对象。**直接失败 D-context-33：** 本地历史清理后 provider-side conversation 仍可被重新接入；预期：根据数据权利覆盖所有独立副本。**合法邻例 N-context-33：** 法定保留副本不作当前推理。

### §34 纠错、撤销与下游传播
**机制：** 原始权限变更、规范失效或用户纠错后，定位上下文摘要、下一轮缓存、并行 Agent 分支和引文链，避免旧状态在下游任务恢复中再次生效。

**验收：** 用户撤回发信许可后，活跃上下文与后续分支均不允许继续发送。

**执行绑定：** `context-G07`。**专用正例 P-context-34：** 撤回传播至活跃分支与缓存。**直接失败 D-context-34：** 在新窗口纠错后旧分支继续按照已撤回订单自动付款；预期：撤销传播覆盖活跃副本。**合法邻例 N-context-34：** 已发生外部事实不从审计抹除。

### §35 链路证据及敏感内容最小化
**机制：** 记录摘要版本、压缩方法、token 估算/用量、失败原因、源记录定位、授权版本与工具结果关联；不能将完整原始提示、秘密或模型隐私块发布到低权日志。

**验收：** 日志能说明为何裁剪及失败，不泄漏用户原文或私有模型状态。

**执行绑定：** `context-G07`。**专用正例 P-context-35：** 记录源引用和用量不写秘密。**直接失败 D-context-35：** 调试日志直接公开了 compressed context 中的客户密钥；预期：只存必须的技术和业务证据。**合法邻例 N-context-35：** 内容日志关闭仍能核压缩版本。

### 机制组：验收模型、回归矩阵与项目适用

### §36 长位置与分散事实对照
**机制：** 设置关键事实在前、中、后、多个文档、不同长度及多步依赖条件的等价测试；测实际提取准确率与关键约束执行，而不是只测长窗口是否接受输入。

**验收：** 同一生效规范放在不同位置时产生一致结论，不能遗漏中部有效否决。

**执行绑定：** `context-G08`。**专用正例 P-context-36：** 等价事实跨位置对照。**直接失败 D-context-36：** 把权限边界放到 100K 文本中间后模型忽视它；预期：按位置等价反例验证。**合法邻例 N-context-36：** 合法同义改写不要求逐字一致。

### §37 截断、压缩和引用的失败注入
**机制：** 模拟 Token 超限、突发工具日志、压缩摘要漂移、缺失出处、类型转换丢失、后台任务未完成和撤权传播等边界，用独立保留样本判定。

**验收：** 每个风险事件都有可复现输入、预期失败/恢复和真实相关证据。

**执行绑定：** `context-G08`。**专用正例 P-context-37：** 缺出处摘要触发证据缺口。**直接失败 D-context-37：** 单测仅看压缩长度减少 60% 就宣称正确；预期：同时验证关键语义、授权和恢复。**合法邻例 N-context-37：** 无来源依赖的纯计算可继续。

### §38 模型/API/缓存版本迁移
**机制：** 模型或 tokenizer、prompt、工具 Schema、压缩策略、缓存 SDK、服务端会话版本变化，需检查原快照恢复后结构/状态及实际 token 计数兼容，必要时分批迁移或拒绝。

**验收：** 新模型不会将旧不可解析 compaction item 当可用恢复状态或产生越权调用。

**执行绑定：** `context-G08`。**专用正例 P-context-38：** 跨模型不兼容opaque被拒绝。**直接失败 D-context-38：** OpenAI compact 输出被原样送给不支持该格式的另一模型；预期：验证格式版本并安全停止或重建。**合法邻例 N-context-38：** 可重取合法原文构建新窗口。

### §39 精度、费用、时延及容错联合验收
**机制：** 控制测量关键事实保留率、合法任务成功率、错误恢复与 prompt cache/token 成本和时延；不以单一压缩比例、长窗口参数或缓存命中率判定质量。

**验收：** 压缩 80% 却丢失重要客户拒绝则不能通过，即使成本降低。

**执行绑定：** `context-G08`。**专用正例 P-context-39：** 压缩率高但丢拒绝判失败。**直接失败 D-context-39：** 压缩率优秀但漏掉支付否决仍标记质量提升；预期：业务正确性高于成本优化。**合法邻例 N-context-39：** 低压缩率但完整合法可通过。

### §40 L5 具体实现与 L6 权利业务验收
**机制：** L5 负责所选模型、SDK、token 计量器、压缩/编辑 API 和真实互通；L6 确认实际用户数据、有效授权、生产动作、费用、结果及长期保留条件；本标准不自动赋予项目写入权。

**验收：** 静态通过不意味着业务已安全恢复、生产部署已完成或用户请求已生效。

**执行绑定：** `context-G08`。**专用正例 P-context-40：** L5实测API与L6业务分列。**直接失败 D-context-40：** CI 仅验证摘要文档却宣称客户付款处理正确；预期：独立验收真实业务回执与数据权利。**合法邻例 N-context-40：** 没有相关能力可明确不适用。

## 五、验证方法、适用裁剪与项目交付边界

1. **静态设计及离线回放：** 保存明确的原始输入、压缩前后结构、约束/否决、来源版本、工具状态及预期判定；正例检验合法用户任务，反例包含窗口溢出、截断、错误摘要与跨租户。
2. **模型和 SDK 实际集成：** 按选用模型版本实测 token 计数、推理和多模态预算、压缩/编辑 API、工具项保留、缓存用量及其真实行为；模拟器测试只能证明特定代码路径。
3. **压缩保真及位置对照：** 测量关键事实保留、明确的权限和撤销、未完成任务判定、不同位置长文引用、时间/金额/版本保真；不能用单一压缩率或缓存命中率替代。
4. **L6 真实业务和费用：** 项目独立判断真实用户数据权利、模型提供者条款、付费限额、外部动作及业务完成状态，不因静态 CI、提供者自动 Compaction 或模型自述而认定项目已验收。

## 六、生命周期与采用

项目按 L1 登记所采用的准确版本、适用条款和依赖关系。L5 选择并验证实际实现，L6 按真实权利及目标验收业务结果；实现验收以相应项目的执行证据为准。
