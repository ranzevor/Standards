# L4 模型接入、推理调用与响应契约技术规范

**文档ID：** STD-L4-AI-AGENT-014　**版本：** 0.1.0　**状态：** adopted　**生效日期：** 2026-10-30

## 一、范围与实现归属

本 L4 专题规定模型接入与推理调用从请求输入、供应商/模型版本、输出状态、结构化契约、流式传输、错误与重试、数据保留、费用到版本迁移的技术边界，适用于本地模型、云端 API、模型网关和代理端点；不强制采用某供应商、多 Agent、MCP 或付费服务。AI/Agent 领域通用基线负责跨应用的权限与语义状态；工具实际执行、MCP、Agent 记忆、任务恢复与安全隔离另有独立专题。L5 负责具体 SDK/模型版本和真实协议集成；L6 负责数据权利、费用、客户履约和实际业务结果。

模型文本、工具提议、协议成功、异步任务结束与最终业务完成是独立状态。Schema 约束不能替代业务授权；商用模型服务的动态参数和数据保留默认值必须经实际项目许可与版本确认。

## 二、技术依据与有限命题

| 来源 | 性质 | 有限技术命题 |
| --- | --- | --- |
| [OPENAI-STATE](https://developers.openai.com/api/docs/guides/conversation-state) | 滚动厂商接口 | Response对象默认保存30天且store=false控制该行为；Conversation对象/条目不受该30天TTL；previous_response_id用于续接，不能推所有独立副本同时删除。 |
| [OPENAI-SO](https://developers.openai.com/api/docs/guides/structured-outputs) | 滚动厂商接口 | Structured Outputs仅支持Schema子集；拒绝可不匹配业务Schema，需独立处理；结构正确不证明业务值授权。 |
| [OPENAI-STREAM](https://developers.openai.com/api/docs/guides/streaming-responses) | 滚动厂商接口 | typed events区别output_text.delta、response.completed与error，不能以可见最后Token或网络FIN代替完整结果。 |
| [OPENAI-ERR](https://developers.openai.com/api/docs/guides/error-codes) | 滚动厂商接口 | 429包括rate_limit、credit_balance_exhausted及spend/usage限制；503过载独立；按code与Retry-After分类，不一律重试。 |
| [CLAUDE-STOP](https://platform.claude.com/docs/en/build-with-claude/handling-stop-reasons) | 滚动厂商接口 | end_turn、max_tokens、tool_use、pause_turn、refusal及context超限含义不同；empty end_turn也可能出现，仍需任务验收。 |
| [GEMINI-L](https://ai.google.dev/gemini-api/docs/generate-content/long-decode) | 特定模型/接口能力 | generateContent长输出按续写令牌多hop；CONTINUATION非终止；总max_output_tokens跨hop，SDK自动续写需相应版本。 |
| [GEMINI-I](https://ai.google.dev/gemini-api/docs/interactions-overview) | 滚动厂商接口 | Interactions默认存请求，可store=false转无状态；具体对象留存和其他副本须另核，不把API行为推广全域。 |
| [HTTP](https://www.rfc-editor.org/rfc/rfc9110.html) | IETF Standards Track | 非幂等请求不能凭连接失败盲自动重试；Retry-After可为HTTP日期或非负整数秒，仍受任务截止限制。 |

协议规则仅在选择相应版本与能力时适用；厂商SDK实现、开发中/弃用/Beta特性与自愿风险指南不相互替代。本文的主体权限、根预算、当前撤回优先与证据分层为组织工程设计，不冒充某产品的默认保证。数学界限依其明确假设成立，不证明模型在实际分布的稳定性。具体来源定位及有限支持范围见[命题登记](../../../sources/ai-agent-source-registry.json)。

## 三、35 项独立技术机制与验收条件

### 执行闭环与实现绑定

每条§适用时均由下表责任者在相应接受边界执行：输入须来自当前有效主体及权威状态；输出区分允许、拒绝、未知与已证实事实。模型提议、协议ACK、日志或摘要不能自签授权。并发接受使用预期版本/世代或等效条件；超时保留原逻辑操作、预算预留及核对责任。日志记录decision_id、输入/输出身份、原因和证据定位，不要求保存私有思维链。具体字段可复用既有系统。

| 组/条款 | 责任者及运行入口 | 权威输入 → 可观测输出 | 失败、并发、超时与恢复 | 兼容/合法边界 |
| --- | --- | --- | --- | --- |
| model-G01 / §01—§05 | 模型适配器维护者；`endpoint.resolve/request.build` | 端点模型SDK实际契约 → 带能力矩阵的调用身份 | 能力缺失拒相关路径，禁止偷偷换域 | 不同原生代际不强作同义 |
| model-G02 / §06—§10 | 请求准入控制器；`request.admit` | 当前主体、数据来源、窗口与预算 → 输入摘要、attempt/epoch/deadline | 过期及撤权拒派发；原预算跨重试 | 预处理保持单位与授权语义 |
| model-G03 / §11—§20 | 响应及流组装器；`response.ingest/finalize` | typed事件、item/call关联及终态 → 完整候选或明确部分结果 | 断流不提交参数；迟到旧尝试只留历史 | 未知事件按声明策略处理 |
| model-G04 / §21—§25 | 重试调度责任者；`request.retry/reconcile` | 原逻辑意图、错误code及时间界 → 受限新尝试或unknown核对项 | 不可恢复错误不盲重试，保留在途预留 | SDK隐藏重试有总上界 |
| model-G05 / §26—§30 | 数据与预算服务；`retention.delete/budget.reserve` | 对象类、接收方、价格和用量依据 → 删除状态及保守预留结算 | 缺用量不归零，取消不退款 | 各API默认值逐版本确认 |
| model-G06 / §31—§35 | 适配器发行维护者；`release.verify/rollback` | 联合版本、在途令牌、运行证据 → 能力差异表和项目验收记录 | 不兼容在途隔离，业务结果另核 | 所选组合定向验证 |

实现方将上述逻辑入口映射到[目标合同](../../../examples/ai-agent/target-contract.json)中的真实模块/命令，记录端点、准确版本、鉴权身份来源、输入输出与权威查询方式；无真实适配映射不声称目标已通过。有限参考模型及本地命令见[运行入口](../../../examples/ai-agent/README.md)，仅验证声明的控制不变量。

### 模型身份与能力矩阵

### §01 模型真实身份
**机制：** 每次调用关联提供商、区域、端点、实际模型版本与请求契约摘要；别名变化须触发受影响验证，不按同名假定二进制及行为兼容。

**验收：** 调用日志可恢复真实模型、部署及输入能力；别名变更不能静默跨越发布门禁。

**执行绑定：** `model-G01`。**专用正例 P-model-01：** 请求模型和返回模型分别登记。**直接失败 D-model-01：** 同名模型别名被替换而沿用旧结构化输出验收；预期：识别模型身份及能力漂移。**合法邻例 N-model-01：** 服务不披露指纹时记录未知。

### §02 实际能力与特性协商
**机制：** 为文本、多模态、工具提议、结构化输出、流式、后台、续写、并行调用等建立按模型/SDK 版本可核验矩阵，禁用不支持的参数和组合。

**验收：** 缺少指定能力时明确拒绝或进入经批准的降级流程，不伪造成功。

**执行绑定：** `model-G01`。**专用正例 P-model-02：** 图片能力存在才发送图像。**直接失败 D-model-02：** 纯文本模型收到图像请求后输出想象结果并标为已识别图片；预期：不支持能力不得伪装完成。**合法邻例 N-model-02：** 纯文本端点可显式拒绝图像分支。

### §03 供应商及区域回退
**机制：** 故障替代需同时满足数据权利、地域、能力、正确性、成本与权限；配置了候选提供商不意味着允许把所有输入外发。

**验收：** 敏感数据不会因为首选服务超时被转至未经许可的模型提供者。

**执行绑定：** `model-G01`。**专用正例 P-model-03：** 备用端点满足地域数据许可。**直接失败 D-model-03：** 首选模型超时，自动把客户记录发送未授权海外端点；预期：回退先核验数据权利。**合法邻例 N-model-03：** 首选超时可等待而不擅自换域。

### §04 兼容接口代际
**机制：** Responses、Messages、Gemini 等原生接口和兼容代理要分别声明支持的消息、事件、工具与状态子集；协议路径相似不构成同义保证。

**验收：** 未支持的 typed event、终态或工具字段应在适配器暴露明确错误。

**执行绑定：** `model-G01`。**专用正例 P-model-04：** 按原生代际解析typed event。**直接失败 D-model-04：** 兼容代理吞掉 response.incomplete 但上游认定完整；预期：契约差异不得被吞掉。**合法邻例 N-model-04：** 不支持事件可报告不兼容不伪造。

### §05 SDK 与端点版本
**机制：** 锁定实际 SDK、服务端 API 版本、适配器与默认重试/存储/参数行为；升级须比较变更影响而非只依赖构建通过。

**验收：** 一次 SDK 升级后能验证请求、响应、费用、保留与错误状态未静默漂移。

**执行绑定：** `model-G01`。**专用正例 P-model-05：** 升级SDK比较默认重试存储。**直接失败 D-model-05：** SDK 升级默认开启数据持久化而应用仍宣称不会留存；预期：检测默认行为和授权变化。**合法邻例 N-model-05：** 构建通过只保留构建结论。

### 输入与推理预算

### §06 输入模态及内容来源
**机制：** 请求对象明确消息角色、文本/图像/音频/附件/工具结果的来源、格式、长度和允许用途；不可信外部材料不转化为系统指令。

**验收：** 含错误 MIME、无授权文件或外部注入文本的输入在发送前被隔离。

**执行绑定：** `model-G02`。**专用正例 P-model-06：** 附件MIME与来源校验后准入。**直接失败 D-model-06：** 抓取 HTML 当系统消息拼接入模型请求；预期：保持来源及指令层级。**合法邻例 N-model-06：** 合法攻击语句作为数据可被分析。

### §07 上下文窗口与压缩
**机制：** 按真实计数器及模型限制配置输入、推理、工具与输出预算；裁剪不得删失撤回授权、金额单位、必要证据或当前目标。

**验收：** 超限后的语义保真、失败/重取条件可复现，不能以空缺自行填造授权。

**执行绑定：** `model-G02`。**专用正例 P-model-07：** 窗口为输出和工具结果留额。**直接失败 D-model-07：** 窗口裁剪抹去禁止支付的用户决定；预期：不得恢复已拒权限。**合法邻例 N-model-07：** 无需压缩的小输入直接发送。

### §08 推理及采样选项
**机制：** 依据模型能力选择 temperature、top_p、reasoning effort、max output、候选数及互斥设置，拒绝不支持或会使业务验收失效的组合。

**验收：** 参数验证失败不靠无限重试；总推理和输出使用量受已授权预算约束。

**执行绑定：** `model-G02`。**专用正例 P-model-08：** 受支持参数组合进入调用。**直接失败 D-model-08：** 推理模型不支持采样参数而客户端持续重放；预期：能力前置校验阻断。**合法邻例 N-model-08：** 不支持采样参数应本地拒绝。

### §09 请求身份与截止时间
**机制：** 区分根任务ID、逻辑调用ID、attempt_id、control_epoch、主体、Deadline、工具关联与取消。每次新尝试保留原任务和费用归属；响应接受边界验证当前尝试/世代及计划版本。迟到旧响应可补真实用量和已发生事实，不得覆盖新结果或触发下一动作。取消、流关闭和连接超时不能推定供应商已停止生成、已撤销工具效果或不再计费。

**验收：** 迟到片段、旧请求响应不覆盖较新的用户任务及业务状态。

**执行绑定：** `model-G02`。**专用正例 P-model-09：** attempt与epoch匹配才提交。**直接失败 D-model-09：** 请求取消后晚到的响应覆盖新的订单审核；预期：隔离过期请求响应。**合法邻例 N-model-09：** 旧响应可保留费用事实不覆盖新任务。

### §10 预处理的业务保真
**机制：** 输入正规化、摘要、媒体转换、批量组装时保留金额、单位、负号、身份、引用、原始来源和数据授权；结果与输入版本绑定。

**验收：** 预处理前后关键数值/权限等价，任何信息损失导致业务动作停闸。

**执行绑定：** `model-G02`。**专用正例 P-model-10：** 负号币种单位转换后相等。**直接失败 D-model-10：** 金额符号与币种转换时遗失却仍提交计费判断；预期：关键字段失真即拒绝。**合法邻例 N-model-10：** 无法无损转换可要求原格式。

### 输出完整性与语义

### §11 原生终止原因
**机制：** 将 OpenAI 响应状态与 typed events、Anthropic stop_reason、Gemini finish_reason 等按具体版本映射为完成、拒绝、工具请求、截断、暂停、延续和错误等，不单看 HTTP 状态。

**验收：** 服务端返回 200 但 max_tokens/refusal/incomplete 时不标记业务完成。

**执行绑定：** `model-G03`。**专用正例 P-model-11：** max_tokens保持截断状态。**直接失败 D-model-11：** Anthropic max_tokens 被当作自然结束；预期：区分截断与完成。**合法邻例 N-model-11：** end_turn还须业务验收才完成。

### §12 明确完成事件
**机制：** 仅在对应原生完整终止事件及所有必要数据校验满足后提交最终响应；单个 Delta 或网络 FIN 不代表完成。

**验收：** 中断流只能作为部分输出保留，不作为正式定稿或工具结果。

**执行绑定：** `model-G03`。**专用正例 P-model-12：** 完整终态后校验并交付。**直接失败 D-model-12：** 收到首个文字片段就保存为最终客户合同；预期：等待合法完整终态。**合法邻例 N-model-12：** 网络FIN仅能保存部分输出。

### §13 结构化 Schema 子集
**机制：** 选用供应商实际支持的 JSON Schema 子集、拒绝处理、必填/可选字段与版本；受控语法仍需应用校验对象归属、数量和业务不变量。

**验收：** 合法 JSON 中包含其他租户资源或非法业务金额时仍拒绝。

**执行绑定：** `model-G03`。**专用正例 P-model-13：** Schema与对象归属均通过。**直接失败 D-model-13：** Schema 合法的订单引用了未授权账户；预期：结构与业务双重校验。**合法邻例 N-model-13：** 合法数组按选择的Schema接受。

### §14 工具提议与调用收据
**机制：** 工具调用内容只视为参数提议；Call ID、方法、参数增量及因果关系必须与真正服务端执行结果分离，所有副作用受独立授权。

**验收：** 不凭模型生成的 JSON 或 tool_use 块声称写入已发生。

**执行绑定：** `model-G03`。**专用正例 P-model-14：** 工具参数仅成待授权提议。**直接失败 D-model-14：** 模型输出退款工具参数便直接回报退款完成；预期：待真实工具收据。**合法邻例 N-model-14：** 只生成草稿参数无需真实发送。

### §15 多块、引用和候选选择
**机制：** 识别候选、模态块、内容引用、工具响应与内部计算摘要，不将私有块直接拼接进用户文本；选中结果须有实际来源与顺序依据。

**验收：** 图文混合及多候选响应只输出必要业务字段，顺序可复现。

**执行绑定：** `model-G03`。**专用正例 P-model-15：** 只输出已选择可见内容块。**直接失败 D-model-15：** 将内部思考块混入对外文案；预期：按块类型和受众处理。**合法邻例 N-model-15：** 多个合法候选不必都对外展示。

### 流式、续写和异步作业

### §16 流事件契约
**机制：** 按原生 SSE、WebSocket 或其他版本化协议解析事件类型、序号、请求关联、结束事件和错误事件，不将网络关闭当成完成。

**验收：** 未知事件或缺失结束事件必须有兼容策略和明确不完整状态。

**执行绑定：** `model-G03`。**专用正例 P-model-16：** 原生结束事件与request关联。**直接失败 D-model-16：** FIN 到达但 response.completed 缺失仍登记成功；预期：结束事件单独验证。**合法邻例 N-model-16：** 可忽略已声明可选事件不误拒整流。

### §17 Delta 有序组装
**机制：** 文字、JSON 字段和工具参数的 Delta 按所属 Item/索引、序列和事件类型聚合；半成品 JSON/参数不可直接执行。

**验收：** 随机切分、交错内容和重复片段均只产生一个完整的有效结果。

**执行绑定：** `model-G03`。**专用正例 P-model-17：** 交错delta按item与序号组装。**直接失败 D-model-17：** 工具参数流未收束时即执行 DELETE；预期：完成前不执行工具。**合法邻例 N-model-17：** 无序号恢复不宣称可无损去重。

### §18 流量背压与断连
**机制：** 处理缓慢消费者、内存缓冲上限、断连、乱序、重复事件和取消；不支持恢复时明确标记不可无损恢复。

**验收：** 流缓冲保持有界，重连不自动重复提交业务对象。

**执行绑定：** `model-G03`。**专用正例 P-model-18：** 缓冲达到上限触发背压。**直接失败 D-model-18：** 重连后两次拼接同一片段导致订单重复；预期：去重并按协议恢复。**合法邻例 N-model-18：** 不支持重连可明确保留部分输出。

### §19 长生成续写契约
**机制：** 仅在所选模型及原生接口明确支持时启用长生成续写。记录单hop上限、原生CONTINUATION/continuation_token或等效状态、总输出/推理预算、令牌作用域、合并与最终完成条件；不得把某一generateContent模型/SDK的续写协议推广到全部Gemini或其他厂商。SDK自动续写的全部尝试亦受根级额度准入。

**验收：** Gemini CONTINUATION 不作为最终完成；续写失败时标记部分结果。

**执行绑定：** `model-G03`。**专用正例 P-model-19：** CONTINUATION沿令牌有界续写。**直接失败 D-model-19：** CONTINUATION 被忽略，截断答案自动发布；预期：正确延续或失败。**合法邻例 N-model-19：** 不支持续写模型可返回截断。

### §20 批量和背景请求
**机制：** 区分提交、运行、完成、取消、过期与结果领取；背景状态存储/保留、轮询和回调须与请求身份、数据权利及截止时间绑定。

**验收：** 异步入队成功或结果已过期不被归类为生成已完成。

**执行绑定：** `model-G03`。**专用正例 P-model-20：** queued任务有轮询责任。**直接失败 D-model-20：** 后台请求仅返回 queued 就完成客户交付；预期：异步终态和结果验收。**合法邻例 N-model-20：** 直接同步结果无需虚构后台task。

### 错误、重试及服务保护

### §21 错误可恢复性分类
**机制：** 区分认证/权限、参数不合法、内容拒绝、暂时限流、余额与费用上限、服务过载、网络超时和取消；永久拒绝不得无限重试。

**验收：** 不同 429 错误码能区别 credit_balance_exhausted 与临时 rate limit。

**执行绑定：** `model-G04`。**专用正例 P-model-21：** 余额耗尽不按瞬时限流重试。**直接失败 D-model-21：** 余额耗尽被误判为瞬时限流持续收费重试；预期：永久错误直接停止。**合法邻例 N-model-21：** 可恢复503按合同有界重试。

### §22 Retry-After 与退避
**机制：** 按 RFC 9110 处理 Retry-After 秒数/日期和供应商限流指示，缺失时有界指数退避与抖动，总重试次数和截止时间明确。

**验收：** 服务端给 120s 退避而任务只剩 20s 时正确延后或终止。

**执行绑定：** `model-G04`。**专用正例 P-model-22：** Retry-After120秒超过剩余截止不派发。**直接失败 D-model-22：** Retry-After 120 秒仍在 1 秒后重新请求；预期：遵守限界等待。**合法邻例 N-model-22：** 合法HTTP日期同样解析。

### §23 推理重试与业务幂等隔离
**机制：** 原模型调用失败后的重试不能直接重放已执行的外部工具动作；业务 Side Effect 的幂等键、回执与对账独立归工具专题。

**验收：** 历史工具结果不被当作重新执行动作的批准。

**执行绑定：** `model-G04`。**专用正例 P-model-23：** 重试推理不重放已完成付款。**直接失败 D-model-23：** 模型超时后重新运行已经扣款的工具调用；预期：不重复外部写入。**合法邻例 N-model-23：** 未产生工具副作用的推理可新尝试。

### §24 提供商熔断与受限降级
**机制：** 持续高错误率、过载与协议不兼容触发熔断、限流或停止；替换模型须受能力、数据许可和预算的共同门禁。

**验收：** 故障时不会无限尝试高价模型或越权地区。

**执行绑定：** `model-G04`。**专用正例 P-model-24：** 熔断仅隔离故障端点。**直接失败 D-model-24：** 所有备选大型模型依次被尝试直到预算耗尽；预期：预算和权限硬停。**合法邻例 N-model-24：** 已获权兼容备用端点可受控使用。

### §25 超时分层与孤儿任务
**机制：** 区分连接、首 Token、片段间隙、总 Deadline、后台作业及取消回执；本地超时后需核对服务器侧仍运行与费用情况。

**验收：** 孤儿生成可查询/取消或明确无法确认，不默认为服务端已停。

**执行绑定：** `model-G04`。**专用正例 P-model-25：** 本地超时保留远端未知与预留。**直接失败 D-model-25：** 客户端超时就停止本地计费但后台仍调用；预期：真实作业状态与费用回读。**合法邻例 N-model-25：** 查询证实未开始方可释放。

### 数据保留、使用量与可观测

### §26 供应商留存与状态默认
**机制：** 分别核查 provider 的请求日志、store 默认值、背景任务、文件上传和状态会话保留期限；使用与实际合同及模型端点相符的配置。

**验收：** 变更接口时能识别由无状态切换到服务器持久状态。

**执行绑定：** `model-G05`。**专用正例 P-model-26：** 按对象类核保留与store配置。**直接失败 D-model-26：** Gemini Interactions 默认 store=true 却被宣称零保留；预期：核对默认和配置。**合法邻例 N-model-26：** 不同API默认值不预设一致。

### §27 敏感数据与地域边界
**机制：** 按主体权限、用途和接收地域对输入、附件、工具响应及模型回传执行最小披露；不同租户历史不得混入同次模型调用。

**验收：** 真实请求入参不存在无权限的跨租户内容。

**执行绑定：** `model-G05`。**专用正例 P-model-27：** 同租户必要字段发给获准接收方。**直接失败 D-model-27：** 把两租户的聊天历史合并发送模型；预期：主体隔离生效。**合法邻例 N-model-27：** 脱敏仍需检查用途与可识别性。

### §28 状态缓存、文件与删除
**机制：** 隐式/显式缓存、上传文件、服务端会话及第三方异步对象分别管理保留、TTL 与删除；store=false 不代表所有派生资源已清除。

**验收：** 用户删除后外部缓存/文件无法继续重现失效信息。

**执行绑定：** `model-G05`。**专用正例 P-model-28：** 删除上传文件和独立缓存分别核对。**直接失败 D-model-28：** 关闭 store 但上传 File API 历史附件未清理；预期：分别清理每类对象。**合法邻例 N-model-28：** store关闭不声称所有副本擦除。

### §29 必要诊断与隐私化追踪
**机制：** 记录请求/模型版本、终态、错误、重试、Token 用量、业务关联和成本；日志不得默认复制原始提示、内部块或密钥到低权系统。

**验收：** 脱敏 Trace 可定位问题又不公开个人数据及 Token。

**执行绑定：** `model-G05`。**专用正例 P-model-29：** 脱敏Trace关联请求错误及成本。**直接失败 D-model-29：** 将用户完整原文和令牌发往公开观测系统；预期：限定日志内容和受众。**合法邻例 N-model-29：** 不采全文提示仍可诊断。

### §30 实际使用量和预算硬界
**机制：** 按供应商计费维度区分输入/输出/推理/缓存/Batch/续写与重试，并按任务、主体和租户累积消耗，实现费用阻断及事后对账。

**验收：** 总配额已触顶时续写与重试停止，不以图表告警替代停闸。

**执行绑定：** `model-G05`。**专用正例 P-model-30：** 续写重试计入原根预算。**直接失败 D-model-30：** 长输出自动续写未累计 Token 导致超支；预期：跨请求计量和限额。**合法邻例 N-model-30：** 成本未知不记零也不冒已结算。

### 兼容迁移与交付验收

### §31 端点兼容矩阵
**机制：** 对模型/SDK/接口世代与 Schema、模态、流、工具、状态和计费进行逐版本支持登记，不将兼容路径等同真实特性覆盖。

**验收：** 新端点返回新字段或新终态时可列出受影响行为。

**执行绑定：** `model-G06`。**专用正例 P-model-31：** 矩阵列真实支持终态和模态。**直接失败 D-model-31：** 代理更新后丢弃错误事件仍被标注全兼容；预期：矩阵真实反映。**合法邻例 N-model-31：** 兼容代理可只声明受验子集。

### §32 版本升级及灰度
**机制：** 模型别名、SDK、参数位置、返回结构变更需要适当离线对照、只读灰度、限权发布及自动停闸，不把生成语言流畅作为成功率。

**验收：** 事实/结构/成本回归下降时阻止进一步放量。

**执行绑定：** `model-G06`。**专用正例 P-model-32：** 灰度按语义质量权限成本判定。**直接失败 D-model-32：** 迁移到 Responses 但仍使用旧 delta 解析器；预期：迁移前后双路径验证。**合法邻例 N-model-32：** 低风险局部变更可定向回归。

### §33 回退与在途响应兼容
**机制：** 回滚模型或适配器要考虑旧请求事件、续写 Token、工具参数及后台任务；单独回滚源码不能撤销已发生的供应商存储或外部动作。

**验收：** 在途任务不兼容时可安全中止且不会混用历史结果。

**执行绑定：** `model-G06`。**专用正例 P-model-33：** 旧任务沿兼容适配器完成。**直接失败 D-model-33：** 旧续写令牌交给新版模型继续生成并声明成功；预期：联合版本控制。**合法邻例 N-model-33：** 不兼容令牌可隔离后重建候选。

### §34 真实供应商与故障注入
**机制：** 静态、模拟、真实模型/SDK 与所选服务器的集成验收分别报告；覆盖拒绝、截断、流断、错误码、429、Async、语义越界与取消。

**验收：** Mock 通过而真实 stop_reason 或 SSE 失败时不能报告生产兼容。

**执行绑定：** `model-G06`。**专用正例 P-model-34：** 真实拒绝截断断流分别测试。**直接失败 D-model-34：** 仅运行你好世界 Mock 便宣布所有模型兼容；预期：真实版本验收独立。**合法邻例 N-model-34：** Mock通过不推导模型稳定性。

### §35 L5/L6 结果边界
**机制：** L5 负责具体模型及 SDK/网络部署、真实协议版本；L6 确认客户数据、资金、许可证及用户业务结果，不以 HTTP 200 或 JSON 合法替代。

**验收：** 客户退款需真实执行与资金收据，不因模型生成结构正确而完成。

**执行绑定：** `model-G06`。**专用正例 P-model-35：** 退款按实际资金收据验收。**直接失败 D-model-35：** HTTP 200 与 schema 通过就宣称退款已生效；预期：业务授权和结果另验。**合法邻例 N-model-35：** 纯文本任务无须资金系统证据。

## 五、真实集成与变更控制

- **离线契约：** 使用声明的请求、模型/SDK/配置版本及正式响应样本测试 Schema、模态、停止原因、流式片段、异步状态、限流/取消、恢复及费用反例。对未覆盖的能力不以 Mock 通过代替。
- **L5 实际互通：** 在已授权运行环境与配额内，核验真实模型能力、请求返回、版本状态、数据留存、工具提议和异步/流式行为；供应商无法访问时记录实际阻断，不伪造成功。
- **L6 业务终验：** 用户数据权利、商业费用、生产环境、资金/通知等外部动作与真实客户结果归实际项目独立授权并提供收据。
- **演进与回退：** 模型/SDK/API 变更前检验矩阵、对照样本和费用边界；在途任务不可用新旧不兼容状态静默恢复。
