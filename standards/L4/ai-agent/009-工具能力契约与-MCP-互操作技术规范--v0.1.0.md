# L4 工具能力契约与 MCP 互操作技术规范

**文档ID：** STD-L4-AI-AGENT-009　**版本：** 0.1.0　**状态：** adopted　**生效日期：** 2026-10-30

## 一、适用范围与权责

本规范适用于 AI 应用调用模型工具，以及实际选用 Model Context Protocol（MCP）的 Host、Client 和 Server 之间的版本化互操作。未采用 MCP 的项目仅采纳适用的工具 Schema、权限、结果与生命周期约束；不得因为此技术规范强制安装 MCP、多 Agent、收费云服务或独立服务器。

AI/Agent 领域通用基线处理真实人类授权与业务结果分界；相应[STD-L4-AI-AGENT-014 · L4 模型接入、推理调用与响应契约技术规范](014-模型接入、推理调用与响应契约技术规范--v0.1.0.md)、[STD-L4-AI-AGENT-011 · L4 指令体系、不可信内容与提示注入防护技术规范](011-指令体系、不可信内容与提示注入防护技术规范--v0.1.0.md)、[STD-L4-AI-AGENT-007 · L4 上下文组装、窗口管理与语义压缩技术规范](007-上下文组装、窗口管理与语义压缩技术规范--v0.1.0.md)、[STD-L4-AI-AGENT-012 · L4 检索、知识接入与可验证溯源技术规范](012-检索、知识接入与可验证溯源技术规范--v0.1.0.md)、[STD-L4-AI-AGENT-010 · L4 持久记忆、会话隔离与生命周期技术规范](010-持久记忆、会话隔离与生命周期技术规范--v0.1.0.md)分别管理模型调用、指令污染、上下文、检索及持久记忆。本专题独立管理 Tool/Resource/Prompt 能力目录、JSON-RPC 消息、输入输出结构、Transport、逐请求元数据、MRTR、版本迁移和扩展。[STD-L4-AI-AGENT-004 · L4 Agent 授权、可变更动作与业务副作用技术规范](004-Agent-授权、可变更动作与业务副作用技术规范--v0.1.0.md)另行规定 Agent 业务授权、外部写入与幂等收据；[STD-L4-AI-AGENT-008 · L4 代码、浏览器与环境执行隔离技术规范](008-代码、浏览器与环境执行隔离技术规范--v0.1.0.md)和[STD-L4-AI-AGENT-015 · L4 长任务状态、检查点与可恢复执行技术规范](015-长任务状态、检查点与可恢复执行技术规范--v0.1.0.md)保持独立技术职责。

以选用协议版本为准：MCP 2026-07-28 核心无协议级 Session-ID 和旧式 initialize 握手，服务器不应从连接推断会话。业务自身的长期状态可以使用带有真实访问权的显式业务 Handle；工具描述、模型调用提议、JSON-RPC complete 及实际付款/发布完成不能相互推定。

## 二、技术依据与有限命题

| 来源 | 性质 | 有限技术命题 |
| --- | --- | --- |
| [MCP-V](https://modelcontextprotocol.io/specification/2026-07-28/basic/versioning) | 版本化协议 | 2026-07-28；请求自声明版本、无初始化握手；Server实现discover，Client可直接请求；新旧代际分别处理。 |
| [MCP-B](https://modelcontextprotocol.io/specification/2026-07-28/basic) | 版本化协议 | 请求ID非null字符串/整数且未完成集合不重号；未知resultType无效，缺失按complete向后兼容；协议完成非业务完成。 |
| [MCP-T](https://modelcontextprotocol.io/specification/2026-07-28/server/tools) | 版本化协议 | 目录随逐请求授权而非连接历史；注解不作权限；structuredContent允许任意合Schema的JSON值；非法HTTP参数头工具单独排除；工具业务错误有isError。 |
| [MCP-M](https://modelcontextprotocol.io/specification/2026-07-28/basic/patterns/mrtr) | 版本化协议 | MRTR重试新RPC ID；requestState原样回传且不能跨并行请求；服务端验证影响权限/业务状态的完整性、主体和有效期，单次消费另靠服务端。 |
| [MCP-C](https://modelcontextprotocol.io/specification/2026-07-28/basic/patterns/cancellation) | 版本化协议 | stdio发取消通知；StreamableHTTP断开请求流是取消信号；远端可已完成或不可取消，取消不是事务撤销。 |
| [MCP-H](https://modelcontextprotocol.io/specification/2026-07-28/basic/transports/streamable-http) | 版本化传输绑定 | 每请求POST、JSON或请求级SSE；头体版本一致；请求流断开按取消；不支持Last-Event-ID续流，不能将A2A断流语义套到MCP。 |
| [MCP-R](https://modelcontextprotocol.io/specification/2026-07-28/client/roots) | 弃用中的协议特性 | 2026-07-28起deprecated；新实现不应采用；roots是相关目录提示，不构成安全沙箱或访问控制。 |
| [MCP-S](https://modelcontextprotocol.io/specification/2026-07-28/client/sampling) | 弃用中的协议特性 | 2026-07-28起deprecated；能力声明及sampling.tools独立；人类可拒绝是SHOULD建议，不是全领域每次调用统一审批条款。 |
| [MCP-A](https://github.com/modelcontextprotocol/modelcontextprotocol/blob/main/docs/specification/2026-07-28/basic/authorization/security-considerations.mdx) | 条件适用协议安全 | 使用相应HTTP授权时核token受众；上游API使用独立token而非透传；OAuth2.1与CIMD所引仍有draft身份，非业务批准。 |
| [MCP-X](https://tasks.extensions.modelcontextprotocol.io/specification/draft/tasks) | 可选扩展草案 | Tasks扩展只在能力声明后使用，当前支持tools/call；resultType=task与普通结果并存；completed结果可含isError=true。 |
| [MCP-RES](https://modelcontextprotocol.io/specification/2026-07-28/server/resources) | 版本化协议 | URI资源、列举分页/缓存、独立read及可选变更订阅；逐请求授权，不因URI或目录缓存自动获得访问权。 |
| [MCP-P](https://github.com/modelcontextprotocol/modelcontextprotocol/blob/main/docs/specification/2026-07-28/server/prompts.mdx) | 版本化协议 | Prompt内容由Server定义，user-controlled指使用选择而非作者权威；声明能力并按请求授权列举，目录可分页缓存。 |

## 三、43 项独立技术机制与验收条件

### 执行闭环与实现绑定

每条§适用时均由下表责任者在相应接受边界执行：输入须来自当前有效主体及权威状态；输出区分允许、拒绝、未知与已证实事实。模型提议、协议ACK、日志或摘要不能自签授权。并发接受使用预期版本/世代或等效条件；超时保留原逻辑操作、预算预留及核对责任。日志记录decision_id、输入/输出身份、原因和证据定位，不要求保存私有思维链。具体字段可复用既有系统。

| 组/条款 | 责任者及运行入口 | 权威输入 → 可观测输出 | 失败、并发、超时与恢复 | 兼容/合法边界 |
| --- | --- | --- | --- | --- |
| mcp-G01 / §01—§05 | Host及工具服务；`catalog.resolve/action.accept` | Server来源、工具语义、当前主体 → 消歧目录、待执行提议与受理状态 | 撤权逐调用生效，目录不授执行权 | 非MCP工具仍适用授权边界 |
| mcp-G02 / §06—§10 | 协议及Schema适配器；`rpc.decode/result.validate` | 请求ID、dialect及原生结果 → 结构化候选或明确协议错误 | 未知值拒绝，超时未知不填成功 | 缺resultType旧响应合法按complete |
| mcp-G03 / §11—§15 | 传输适配器；`request.encode/validate` | 选定era、_meta、头体与handle → 自包含请求及受权业务状态 | 头体冲突拒绝；旧连接身份不继承 | 非法HTTP头工具单独排除；stdio可忽略注解 |

### 工具身份、能力描述和执行分界

### §01 Host、Client 与 Server 权责
**机制：** Host 控制对模型暴露的能力，MCP Client 与 Server 分别承担协议和实际工具执行；模型输出不自动具有业务授权。

**验收：** 未获授权的 Host 不会仅因工具可发现而执行高影响操作。

**执行绑定：** `mcp-G01`。**专用正例 P-mcp-01：** Host暴露与服务端授权各自校验。**直接失败 D-mcp-01：** 发现工具后 Host 未授权仍尝试删除生产记录；预期：模型与发现不能获得真实执行权。**合法邻例 N-mcp-01：** 模型可发现工具而未取得执行权。

### §02 跨 Server 工具名称消歧
**机制：** 工具身份组合 Server 来源、工具名称、Schema 版本和作用域；serverInfo.name 不应被当作全局唯一标识。

**验收：** 两个不同 Server 的同名工具不会被路由到错误租户。

**执行绑定：** `mcp-G01`。**专用正例 P-mcp-02：** 同名search带可信Server来源路由。**直接失败 D-mcp-02：** 两个 Server 的 search 工具被路由到错误租户；预期：工具身份需包含 Server 与版本。**合法邻例 N-mcp-02：** serverInfo.name相同不必全目录拒绝。

### §03 工具实际副作用分类
**机制：** 真实方法和后端权限决定读写、外发、破坏性及幂等性质；Tool Annotations 是风险提示，不是签发的权限凭据。

**验收：** readOnlyHint=true 的工具实际执行 DELETE 时，低权调用仍遭服务端拒绝。

**执行绑定：** `mcp-G01`。**专用正例 P-mcp-03：** 真实DELETE按写权限控制。**直接失败 D-mcp-03：** readOnlyHint=true 的工具执行真实 DELETE；预期：按后端副作用实施权限门禁。**合法邻例 N-mcp-03：** readOnlyHint可供展示不作许可。

### §04 工具目录随调用主体变化
**机制：** tools/list可按逐请求真实授权改变可见集合，但不能随连接历史或其他请求副作用改变。目录缓存按主体、Server及能力版本分区；列举可见性不构成当前可调用许可，实际调用仍由Server检查资源权限。

**验收：** 身份变更或撤权后旧管理员工具无法继续使用。

**执行绑定：** `mcp-G01`。**专用正例 P-mcp-04：** 逐请求授权变更后目录重新分区。**直接失败 D-mcp-04：** 普通用户继承旧管理员 tools/list 缓存；预期：当前身份决定工具可见与调用。**合法邻例 N-mcp-04：** 同权目录可稳定缓存。

### §05 工具发现与业务结果区分
**机制：** 区分 tools/list、工具调用提议、tools/call、服务器返回和外部实际业务收据，分别记录其状态。

**验收：** 仅发现 send_invoice 工具不会被报告为发票已送达。

**执行绑定：** `mcp-G01`。**专用正例 P-mcp-05：** list成功仍未产生发票。**直接失败 D-mcp-05：** 仅 tools/list 成功便宣称已经发送通知；预期：发现与实际业务结果分离。**合法邻例 N-mcp-05：** 已验调用结果仍另核送达。

### JSON-RPC、Schema 和结果

### §06 JSON-RPC ID 与 ResultType
**机制：** 请求ID为非null字符串或整数且不能与仍待响应的已发请求重复；响应ID匹配原请求，Notification无ID。未知resultType必须判无效；为兼容旧Server，缺失resultType必须按complete解释。complete只表示相应协议结果，工具isError、业务验收及外部效果仍独立判断。

**验收：** 返回未声明的结果类型时，客户端拒绝错误的完成认定。

**执行绑定：** `mcp-G02`。**专用正例 P-mcp-06：** 未知resultType拒绝解析。**直接失败 D-mcp-06：** resultType 为未知值仍被当作 complete；预期：未识别结果不能标记完成。**合法邻例 N-mcp-06：** 旧响应缺resultType按complete兼容。

### §07 inputSchema 和业务对象校验
**机制：** Tool 输入按实际 JSON Schema Dialect、类型、字段和范围验证，服务端另核资源对象和授权；2026-07-28未声明其他dialect时默认2020-12。

**验收：** Schema 合法但引用其他租户对象的参数仍被拒绝。

**执行绑定：** `mcp-G02`。**专用正例 P-mcp-07：** 2020-12结构与对象权分别核验。**直接失败 D-mcp-07：** Schema 合法但对象属于其他租户；预期：结构与资源 ACL 均必须通过。**合法邻例 N-mcp-07：** 声明支持的其他dialect可按合同用。

### §08 structuredContent 与 outputSchema
**机制：** 2026 Tool structuredContent 可以为 JSON 数组、标量或 null；声明 outputSchema 时双方按真实结构验证，不固定只能返回对象。

**验收：** 合法数组结果不会因错误对象解析而被标记业务成功。

**执行绑定：** `mcp-G02`。**专用正例 P-mcp-08：** outputSchema允许数组则接数组。**直接失败 D-mcp-08：** 数组 structuredContent 被当对象解析导致错误收据；预期：按真实输出 Schema 和 JSON 值类型校验。**合法邻例 N-mcp-08：** null或标量可在相应Schema合法。

### §09 Tool Content 与 Resource Link
**机制：** 文本、图片、音频、Resource Link、嵌入资源与 structuredContent 分类型处理，链接不自动授予 Resource 读取权限。

**验收：** 未经授权的 file URI 不会因工具结果包含链接而被自动读取。

**执行绑定：** `mcp-G02`。**专用正例 P-mcp-09：** resource_link只给定位不授读取。**直接失败 D-mcp-09：** Tool 返回未获授权的本地文件 URI；预期：Resource Link 不自动授予读取权限。**合法邻例 N-mcp-09：** 获准链接可经独立读取入口取回。

### §10 Schema 安全、外部引用与复杂度
**机制：** 对 JSON Schema 深度、递归、组合复杂度与校验时间设置有界控制，不自动解析恶意外部 $ref URI。

**验收：** 恶意递归 Schema 不会造成无限计算或访问攻击域。

**执行绑定：** `mcp-G02`。**专用正例 P-mcp-10：** 恶意ref不联网并有界校验。**直接失败 D-mcp-10：** 恶意递归 JSON Schema 触发外部 $ref 抓取；预期：限制 Schema 复杂度和外部引用。**合法邻例 N-mcp-10：** 本地受控Schema引用可按规则解析。

### 协议代际、逐请求元数据和传输

### §11 2025/2026 版本选择
**机制：** 明确客户端、Server、SDK 的实际协议版本，分别实现旧式 initialize/Session-ID 与 2026 自描述请求的兼容或受控拒绝。

**验收：** 新客户端遇到旧 Server 不会默默套用错误会话契约。

**执行绑定：** `mcp-G03`。**专用正例 P-mcp-11：** modern与legacy按检测分轨。**直接失败 D-mcp-11：** 新 Client 向旧 MCP Server 发送无 initialize 调用后伪装成功；预期：协议代际必须明确适配或拒绝。**合法邻例 N-mcp-11：** 明确双代实现可兼容旧初始化。

### §12 逐请求 _meta
**机制：** 2026 请求自带必要协议版本、客户端身份及能力元数据，Server 不从连接的上一个请求继承身份、任务和授权。

**验收：** 多任务复用同一 stdio/HTTP 连接不产生跨任务会话串用。

**执行绑定：** `mcp-G03`。**专用正例 P-mcp-12：** 请求各带版本身份能力。**直接失败 D-mcp-12：** 同一 stdio 连接的客户 B 继承客户 A 的 _meta；预期：每次请求应自包含且隔离。**合法邻例 N-mcp-12：** 同连接不同请求不继承认证。

### §13 路由 Header 与正文一致性
**机制：** Streamable HTTP 的版本、Mcp-Method、Mcp-Name 及必要参数 Header 与真实 JSON-RPC 正文核对，头体矛盾不执行。

**验收：** Header 指向 search、正文却请求 delete 的调用被拒绝。

**执行绑定：** `mcp-G03`。**专用正例 P-mcp-13：** 头体方法名称一致再执行。**直接失败 D-mcp-13：** Mcp-Name=search 但请求正文是 delete；预期：路由头和 RPC 正文须一致。**合法邻例 N-mcp-13：** 合法无name的方法不虚构工具名。

### §14 x-mcp-header 参数边界
**机制：** HTTP参数头映射按实际Schema静态可达路径及合法唯一字段名验证；仅支持合规string/integer/boolean等所选原始类型，number映射不许可，整数须在安全范围。StreamableHTTP客户端只从目录排除非法定义的单个工具并记录原因，不阻断其他合法工具；stdio等其他绑定可忽略此注解。协议关于敏感参数不应入头的建议与本应用数据出口禁止规则分别记录，不把建议强改成协议全局MUST。

**验收：** 含 CRLF 或把 api_key 映射 Header 的不可信定义不能通过。

**执行绑定：** `mcp-G03`。**专用正例 P-mcp-14：** 非法header工具被排除。**直接失败 D-mcp-14：** inputSchema 将 bearer_token 映射到 x-mcp-header；预期：禁止秘密入头及非法映射。**合法邻例 N-mcp-14：** 其他合法工具仍可列举调用。

### §15 协议无状态与业务 Handle
**机制：** 协议连接不等于用户会话，跨请求的浏览器、购物车和任务状态通过显式、授权且有期限的应用 Handle 传递。

**验收：** Server 横向调度及连接复用不会访问前一用户的购物车。

**执行绑定：** `mcp-G03`。**专用正例 P-mcp-15：** handle每次按当前主体鉴权。**直接失败 D-mcp-15：** 相同连接让两个不同租户共享购物车；预期：业务状态靠受权 Handle 关联。**合法邻例 N-mcp-15：** 无认证服务需声明受限bearer语义。

### 能力目录、分页和缓存

### §16 server/discover 的可选性
**机制：** 2026-07-28 Server必须实现server/discover；Client可预先调用，也可直接发带所需元数据的有效请求并处理UnsupportedProtocolVersion。识别modern错误后只在相容modern版本重试，不因任何错误一概退回legacy；双代实现按各传输明确的era检测接续。

**验收：** 不经 discover 的有效请求仍按版本和能力处理。

**执行绑定：** `mcp-G04`。**专用正例 P-mcp-16：** modern服务器实现discover。**直接失败 D-mcp-16：** Client 因没有旧 initialize 判断新版 Server 无工具；预期：可选发现不替代新版能力契约。**合法邻例 N-mcp-16：** client可不先discover直接有效请求。

### §17 目录分页与覆盖率
**机制：** tools/list、resources/list 和 prompts/list 按支持的 cursor/pagination 获取有权限的完整目录；仅有首批数据不等于全部目录。

**验收：** 分页未完成时不会断言某工具在 Server 上不存在。

**执行绑定：** `mcp-G04`。**专用正例 P-mcp-17：** 遍历cursor才声明目录完整。**直接失败 D-mcp-17：** Client 只读取 tools/list 第一页便认定全部工具已知；预期：分页与游标应正确遍历。**合法邻例 N-mcp-17：** 有权空目录是合法结果。

### §18 ttlMs、cacheScope 与撤权
**机制：** 可缓存目录和资源按真实主体、TTL、Cache Scope、数据权限和撤销事件确定有效性；缓存提示不代替服务端实时鉴权。

**验收：** tools/list 公共缓存不会泄漏管理员工具给普通用户。

**执行绑定：** `mcp-G04`。**专用正例 P-mcp-18：** private缓存按主体和版本隔离。**直接失败 D-mcp-18：** 目录 TTL 未到却仍允许被撤权用户写入；预期：缓存授权不得替代实时权限。**合法邻例 N-mcp-18：** public目录不自动授调用权。

### §19 列表稳定排序与目录变更
**机制：** 稳定排序有助于缓存，但须处理 Schema 更新、列表变更、通知丢失和必要重取；模型不能沿用不兼容工具目录。

**验收：** 工具签名变化后旧参数不会继续被自动调用。

**执行绑定：** `mcp-G04`。**专用正例 P-mcp-19：** 目录变更导致受影响Schema重验。**直接失败 D-mcp-19：** Schema 已更新但模型持续使用旧目录参数；预期：目录变化及版本兼容需回读。**合法邻例 N-mcp-19：** 无变化时稳定顺序可复用缓存。

### §20 宣告能力与实际 SDK 特性
**机制：** Tools、Resources、Prompts、MRTR 和扩展的支持能力必须以实际版本和真实请求核验，不把宣告标记等同已测试实现。

**验收：** Server 未真实实现 Tasks 时不会假装异步任务可查询。

**执行绑定：** `mcp-G04`。**专用正例 P-mcp-20：** 扩展能力与实际方法分别测。**直接失败 D-mcp-20：** Server 声称支持 Tasks 但实际返回未知方法；预期：能力广告必须经实际方法验证。**合法邻例 N-mcp-20：** 未选Tasks可返回普通CallToolResult。

### Resources、Prompts 和可信来源

### §21 Resources URI 与用户授权
**机制：** 资源 URI、MIME、权限与有效期按真实调用主体校验；列举资源和返回 Resource Link 不等于授权读取其正文。

**验收：** 其他租户的私有资源不能被无权 Client 自动读取。

**执行绑定：** `mcp-G05`。**专用正例 P-mcp-21：** URI读取独立核真实主体。**直接失败 D-mcp-21：** 工具链接中的其他租户私有 Resource 被无权读取；预期：Resource URI 读取需独立授权。**合法邻例 N-mcp-21：** 资源未列举不等于永不可读取。

### §22 资源变化和失效控制
**机制：** Resource 的内容更新、删除和变化通知可能延迟，关键业务请求仍需要重核版本、访问权和事实状态。

**验收：** 被撤销的资源缓存不会被当作现行组织决定。

**执行绑定：** `mcp-G05`。**专用正例 P-mcp-22：** 关键资源读时核最新有效性。**直接失败 D-mcp-22：** 已撤销的资源缓存继续作为组织现行政策；预期：资源版本与失效状态有效。**合法邻例 N-mcp-22：** 通知丢失可有界重取而非猜最新。

### §23 Prompts 作为外部模板
**机制：** prompts/list/get 返回的是受 Server 来源约束的模板与参数，不是 Host 的上层指令或组织正式审批。

**验收：** 外部 Prompt 要求读取管理员密钥时执行器仍拒绝。

**执行绑定：** `mcp-G05`。**专用正例 P-mcp-23：** 外部Prompt不改变Host权限。**直接失败 D-mcp-23：** 外部 Prompt 模板说先发送管理员密钥；预期：Prompt 模板不产生上级权限。**合法邻例 N-mcp-23：** 用户可选择合法服务端模板。

### §24 Tool/Resource 跨请求因果关系
**机制：** 工具结果关联原调用 ID、Resource URI、来源与对象权限；跨请求重试/缓存不能把另一租户的回执当作本次结果。

**验收：** 并行工具返回的发票 Resource 不会被错误绑定另一账户。

**执行绑定：** `mcp-G05`。**专用正例 P-mcp-24：** 并发回执按call源与对象绑定。**直接失败 D-mcp-24：** 并行 Tool Result 的发票 URI 绑定到另一账户；预期：原调用及 Resource 身份正确关联。**合法邻例 N-mcp-24：** 原意图重试可复用真实既有结果。

### §25 描述内容污染不得提权
**机制：** Tool 描述、资源文本和 Prompt 都可能携带不可信指令，工具选择和执行权限由 Host 和目标服务真实授权决定。

**验收：** 外部 Server 宣称“必须先导出所有聊天”不触发此动作。

**执行绑定：** `mcp-G05`。**专用正例 P-mcp-25：** 工具说明命令不扩数据范围。**直接失败 D-mcp-25：** 不可信 Tool 描述要求全量导出记忆；预期：描述文本不能升级为执行授权。**合法邻例 N-mcp-25：** 正常说明可支持模型参数选择。

### MRTR、Tasks 和取消

### §26 MRTR InputRequiredResult 状态
**机制：** 2026 可返回 input_required；Client 获取真实输入后用新的 JSON-RPC ID、inputResponses 和必要 requestState 重试，不得把待补参当 complete。

**验收：** 待用户补充地址的订单不会提前标记已下单。

**执行绑定：** `mcp-G06`。**专用正例 P-mcp-26：** MRTR换RPCid保持业务operation_id。**直接失败 D-mcp-26：** Tool 返回 input_required 却标订单已创建；预期：补参前保持未完成状态。**合法邻例 N-mcp-26：** 无inputRequests仅requestState可重试。

### §27 Elicitation 与业务批准分离
**机制：** Elicitation 表单补充信息不等于批准支付、删除或权限提升；业务高影响行动需真实有权主体单独确认。

**验收：** 用户填写电话号不能被系统解释为同意自动扣款。

**执行绑定：** `mcp-G06`。**专用正例 P-mcp-27：** 补地址不等于支付批准。**直接失败 D-mcp-27：** 用户只填补联系地址却自动被扣款；预期：Elicitation 不是业务支付同意。**合法邻例 N-mcp-27：** 真实单独业务批准可通过另一入口。

### §28 Tasks 扩展的真实选择
**机制：** Tasks是独立可选扩展，固定实际选定扩展版本/草案身份；当前tasks/get、tasks/update、tasks/cancel及resultType=task仅在相应请求能力声明后用于支持的tools/call。声明扩展不要求Server每次异步化；Client也须接受合法同步CallToolResult。task completed仍可带isError=true，不推业务成功。

**验收：** 未启用扩展的客户端不能假装已获得任务结果。

**执行绑定：** `mcp-G06`。**专用正例 P-mcp-28：** 只在tools/call按声明返回task。**直接失败 D-mcp-28：** 客户端未支持 Tasks 却调用 tasks/get；预期：扩展须按双方能力约束。**合法邻例 N-mcp-28：** 声明Tasks仍可合法同步返回complete。

### §29 Task 取消与外部副作用
**机制：** 取消/更新任务状态与实际已经发出的邮件、支付或删除分开记录；任务取消不能推定资金已撤销。

**验收：** 支付已完成后 Tasks cancel 成功仍保留真实外部事实。

**执行绑定：** `mcp-G06`。**专用正例 P-mcp-29：** 取消Task仍核实际邮件状态。**直接失败 D-mcp-29：** tasks/cancel 成功后声称银行付款已撤销；预期：任务取消与现实资金独立。**合法邻例 N-mcp-29：** completed内isError仍是工具业务失败。

### §30 旧 Server-to-Client 交互兼容
**机制：** 2025 依赖连接的 server-to-client 交互与 2026 MRTR 模式各按版本实现；不能无限等待旧持久流回调。

**验收：** 新 Server 与旧 Client 不因互等旧协议 Sampling/Elicitation 而死锁。

**执行绑定：** `mcp-G06`。**专用正例 P-mcp-30：** 旧交互按旧版新交互按MRTR。**直接失败 D-mcp-30：** 新版 Server 等待旧连接式 elicitation 形成死锁；预期：MRTR/旧协议互动不得混用。**合法邻例 N-mcp-30：** 未声明sampling可正确拒绝相关请求。

### 身份、数据出口和最小权限

### §31 OAuth Issuer、Token Audience
**机制：** HTTP 授权按所选版本检查真实发行者、受众、Scope 与令牌边界，不跨服务器转发无关 Bearer Token。

**验收：** Server A 无权利用授权给 Server B 的 Token 读取客户资料。

**执行绑定：** `mcp-G07`。**专用正例 P-mcp-31：** token受众只指向本服务。**直接失败 D-mcp-31：** 把 Server B 的 Bearer Token 透传给 Server A；预期：Issuer、Audience 与 Token 作用域保护。**合法邻例 N-mcp-31：** 上游API调用使用独立令牌。

### §32 真实服务端逐调用鉴权
**机制：** 每次调用基于用户、租户、资源、方法、环境、有效期鉴权，逐请求 _meta 自称 admin 不是合法身份。

**验收：** 撤权身份即使保留旧 tools/list 仍不能修改资源。

**执行绑定：** `mcp-G07`。**专用正例 P-mcp-32：** _meta自称admin不改变真实用户。**直接失败 D-mcp-32：** _meta 声称 role=admin 便获得生产写权限；预期：目标服务端独立鉴权。**合法邻例 N-mcp-32：** 已认证公开读取按实际权限通过。

### §33 Tool Annotations 非安全凭据
**机制：** readOnly/destructive/idempotent 等提示仅供风险理解，不授权商业、组织或真实生产操作。

**验收：** destructiveHint=false 不允许低权用户执行 delete_all。

**执行绑定：** `mcp-G07`。**专用正例 P-mcp-33：** 安全注解不授高影响权限。**直接失败 D-mcp-33：** destructiveHint=false 包装了 delete_all；预期：Annotations 不决定真实权限。**合法邻例 N-mcp-33：** 可信注解也不替代对象授权。

### §34 Header/Resource/Schema 注入边界
**机制：** 对恶意 Tool Schema、Header、Prompt、Resource URI、跳转和外部链接设置输入验证及网络出站限制。

**验收：** 含换行的 Header 与私网 Metadata URL 无法越权访问。

**执行绑定：** `mcp-G07`。**专用正例 P-mcp-34：** CRLF与私网目标分别校验。**直接失败 D-mcp-34：** 恶意 Header 换行覆盖身份字段并跳转内网；预期：Header、URL 和出站均需校验。**合法邻例 N-mcp-34：** 获准内网服务不被粗暴全拒绝。

### §35 租户隔离和隐私日志
**机制：** MRTR 用户输入、工具参数、资源内容和 Trace 日志按任务及数据权利最小披露，不泄漏原始秘密。

**验收：** 调试信息不会向所有用户公开客户表单与 Bearer Token。

**执行绑定：** `mcp-G07`。**专用正例 P-mcp-35：** MRTR表单不写公共Trace。**直接失败 D-mcp-35：** MRTR 客户表单被记录在公开 Trace；预期：个人数据和秘密最小化。**合法邻例 N-mcp-35：** 最小关联ID仍可用于诊断。

### 错误、迁移与分层验收

### §36 JSON-RPC 与工具业务错误
**机制：** 区分 JSON-RPC error、tools/call 的 isError、resultType 和 HTTP/网络故障；2026 资源缺失 -32602 与旧 -32002 按版本兼容。

**验收：** Tool isError=true 即使 HTTP 200 也不会被标记资金已到账。

**执行绑定：** `mcp-G08`。**专用正例 P-mcp-36：** isError与JSONRPC错误分别保留。**直接失败 D-mcp-36：** isError=true 但 HTTP 200 导致显示客户付款成功；预期：协议、工具与业务错误分层。**合法邻例 N-mcp-36：** 旧-32002可兼容但不发为新版码。

### §37 SDK 与协议版本矩阵
**机制：** 维护 SDK、HTTP/stdio Transport、旧新协议和扩展组合的实际支持矩阵；SDK 版本升级不等于协议自动升级。

**验收：** 2025 初始化响应不会被 2026 解码器当完整工具结果。

**执行绑定：** `mcp-G08`。**专用正例 P-mcp-37：** SDK与传输版本矩阵锁定。**直接失败 D-mcp-37：** 2025 初始化被 2026 解码器当作工具结果；预期：SDK/协议版本矩阵正确。**合法邻例 N-mcp-37：** 升级SDK不必同步升级协议。

### §38 真实 Client—Server 兼容
**机制：** 必须在 L5 实测发现、分页、tools/call、结果、错误、MRTR、真实鉴权和选用扩展；模拟器只说明静态/局部逻辑。

**验收：** 真实 Server 因缺少必需 _meta 拒绝时，项目不能声称协议已兼容。

**执行绑定：** `mcp-G08`。**专用正例 P-mcp-38：** 真实缺_meta拒绝则互通未通过。**直接失败 D-mcp-38：** Mock 通过但真实 Server 拒绝缺少的 _meta；预期：真实对端不通过不得宣称互通。**合法邻例 N-mcp-38：** 局部模型通过不当整协议通过。

### §39 版本迁移与在途操作
**机制：** 旧 Session-ID、Task ID 和业务 Handle 的迁移需按来源版本、真实动作状态与恢复门禁处理；回退不能重复产生外部副作用。

**验收：** 协议转换后旧付款任务不会被当作新 Tasks 再执行一次。

**执行绑定：** `mcp-G08`。**专用正例 P-mcp-39：** 旧任务保留原操作ID及权利。**直接失败 D-mcp-39：** 新 Tasks 状态机误重放旧扣款 Task ID；预期：跨版本状态迁移不重复写入。**合法邻例 N-mcp-39：** 无兼容迁移可明确隔离待核。

### §40 L5/L6 合同及业务结果
**机制：** L4 仅确定工具技术互通；L5 证实真实模型/SDK/Server，L6 确认数据权利、费用、对外操作与业务生效结果。

**验收：** Tool 返回字符串 success 但客户资金未入账，不得报告业务完成。

**执行绑定：** `mcp-G08`。**专用正例 P-mcp-40：** 工具success不证明银行到账。**直接失败 D-mcp-40：** Tool 返回 success 字符串即报告客户到账；预期：实际客户业务收据独立核验。**合法邻例 N-mcp-40：** 纯计算工具可按自身结果合同完成。

### §41 弃用特性的迁移与独立权限边界
**机制：** MCP 2026-07-28 的 roots 与 sampling 已标 deprecated，新实现 SHOULD NOT adopt。现有兼容实现仅在逐请求声明相关能力后受限处理；sampling.tools是单独能力，用户可拒绝采样的协议建议不能改写项目有效授权要求。roots只是相关目录提示，不是文件权限或安全沙箱；真实文件访问仍在服务端/OS约束。新路径按任务需要使用显式工具参数、资源URI、Server配置或直接模型API，并重新核数据接收、预算和行为兼容，不默认新增模型调用。

**验收：** 旧轨支持合法相关目录与受权采样时仍可工作；恶意根目录、未声明采样能力与越界工具均不能取得执行权。

**执行绑定：** `mcp-G08`。**专用正例 P-mcp-41：** 旧兼容轨声明能力且真实文件门禁拒绝越界。**直接失败 D-mcp-41：** 将roots列表当作内核沙箱且未声明能力就采样；预期：旧轨支持合法相关目录与受权采样时仍可工作；恶意根目录、未声明采样能力与越界工具均不能取得执行权。。**合法邻例 N-mcp-41：** 新实现直接获权工具调用不必实现已弃用sampling。

### §42 MRTR不透明状态的完整性与消费
**机制：** Client按原请求逐字回传requestState，不解析修改且不把它复用到并行请求。Server将其视为攻击者可控输入；若影响授权、资源访问或业务逻辑，验证完整性并绑定真实主体、有效期、方法和关键参数摘要；失败拒绝。签名/短TTL本身不保证单次消费；确有一次兑换语义时，在Server侧以原业务操作身份原子消费并可查询ACK丢失后的结果。MRTR更换RPCid不生成新业务意图或重置费用。

**验收：** 篡改、换主体、换参、过期和同状态兑换另一操作均拒绝；原操作ACK丢失可查询后安全接续而不二次生效。

**执行绑定：** `mcp-G08`。**专用正例 P-mcp-42：** 一次消费绑定原operation并拒绝重复新操作。**直接失败 D-mcp-42：** 有效签名requestState被两个并发请求兑换为两次扣费；预期：篡改、换主体、换参、过期和同状态兑换另一操作均拒绝；原操作ACK丢失可查询后安全接续而不二次生效。。**合法邻例 N-mcp-42：** 只影响请求失败的无权限状态可按规范省略完整性保护。

### §43 逐传输取消与不可推定效果
**机制：** 按所选协议代际和绑定实现取消：2026-07-28 stdio以notifications/cancelled指明在途请求；StreamableHTTP关闭该请求SSE流即为取消信号，不另要求该通知。Server应尽快停止且该HTTP请求不再发消息，但处理中已完成、不可取消、网络竞态及外部业务效果须另核。Client不以取消请求、本地迭代结束、流FIN或超时推定远端已停/已撤销/零费用。旧响应可存真实收据，不得覆盖新attempt/control_epoch或复活终态；订阅断流按能力重建订阅，不承诺Last-Event-ID续流。

**验收：** 在取消与完成的双向交错下，不增加第二逻辑操作；当前控制状态不被迟到响应改写，未知效果及费用仍有核对入口。

**执行绑定：** `mcp-G08`。**专用正例 P-mcp-43：** 按HTTP绑定取消并保留已发生或未知外部效果。**直接失败 D-mcp-43：** HTTP断流后宣称付款已回滚且释放全部费用预留；预期：在取消与完成的双向交错下，不增加第二逻辑操作；当前控制状态不被迟到响应改写，未知效果及费用仍有核对入口。。**合法邻例 N-mcp-43：** A2A断流按其Task契约跟踪，不能套MCP请求流取消语义。

## 五、分层互通与业务验收

1. **离线静态检查：** 明确所选协议/SDK、测试输入、能力列表、JSON-RPC 类型、Schema、Tool Result、Header、缓存、补参及扩展，保留正反例和可重放结果。静态通过不等于真实协议互通。
2. **L5 实际客户端—服务端测试：** 在已授权资源和隔离环境真实执行 Tool List/Call、资源/Prompt、MRTR、权限拒绝、无状态并发、错误和所选 Tasks 扩展；保留端点、SDK 版本与实际报文。不可用的能力不得伪装成功。
3. **L6 业务验收：** 数据访问、生产、客户发送、支付/退款、删除和用户同意由有权主体另行确认，并核对真实外部系统回执与费用；模型提议和协议完成不是业务成功。
4. **演进回退：** 协议与 SDK 变更核验新旧消息、工具 Schema、任务状态、业务 Handle 和令牌约束，失败时受控拒绝或回退，不因兼容代理说明就推定实际正确。

## 六、生命周期与采用
