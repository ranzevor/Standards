# L6 项目采用与实现验收接口规范

**文档ID：** STD-L6-001　**版本：** 0.1.0　**状态：** adopted　**生效日期：** 2026-10-30

## 目标、范围与术语

本规范定义将体系文档变成某个项目可执行约束的接口，适用于规范选用、草案试用、实现验收、兼容迁移及撤回。它不制定项目业务规则，不替项目选择技术栈，不证明真实项目已采用，不授予数据、费用、外部动作或生产操作权限。示例全部使用合成项目；不从其他真实项目导入材料。

“规范对象”是文档ID、版本、相对路径及 SHA-256 的组合；“局部条款ID”只在该文内唯一；跨文身份为 `document_id::clause_id`。“实施对象”是实际源/制品/配置/数据迁移等组件的固定身份及运行环境，不是项目名称。“适用”表示触发对象和承诺存在；“不适用”必须有事实性理由；“未确定”表示还不能作出判定。“通过”只属于准确对象、输入、观察点和证据层级。

“必须/不得”为选定采用后在触发条件成立时的必要要求；“应”为允许有理由偏离的建议；“可”和示例不产生功能或操作义务。本接口是组织合成契约，依赖[L1 GG-05四轴核验合同](../L1/001-全局治理补充规范--v0.1.0.md#gg-05-核验合同)及项目实际选定的L1治理条款、[L3工程](../L3/001-通用工程规范--v0.1.0.md)和具体 L4/L5 条款；来源解释见[共性来源](../../sources/common-governance.md)。

## ADP-01 固定采用对象与范围

- **主体与前提：** 具有项目规范选择决定权的主体；开始试用、采用或修改采用范围时。
- **输入与权威：** 项目真实需求、组件/环境、规范唯一登记及权利依据。文档目录不决定项目采用；采用记录不改变体系文档轴。
- **必要动作：** 必须锁定每文ID、版本、路径、SHA-256及条款范围；区分技术参考、草案试用和正式项目采用。待决定状态不得生成批准人或生效日期。
- **失败与恢复：** 摘要不符、同ID异版本或采用范围未知时核准确来源，不默认latest；并发改记录使用版本前提，保留旧决定及替代关系。
- **产物与验收：** 采用清单与准确正文一一对应。更新正文但不更新选择身份应被拒；记录不存在的真实采用不得通过真实性审查。
- **正确案例：** 合成离线工具仅将 Python 与 CLI 规范作为技术参考，尚未作出项目采用决定。
- **直接失败反例：** 只填“采用全部最新版”便宣布全体系正式生效。
- **合法邻例：** 已获权利主体决定试用草案，项目采用轴可记决定，但该规范仍为 draft。
- **检查入口：** `python checks/project_adoption.py` 核字段和本地对象，不认证真实决定权。

## ADP-02 逐条适用与依赖闭包

- **主体与前提：** 项目技术负责人和采用决定者；确定真实功能、承诺或技术组成时。
- **输入与权威：** 真实对象/用户任务、准确条款及提供/消费接口。技术参考不自动变成正式采用依赖。
- **必要动作：** 必须按条款记录适用、事实性不适用或未确定及理由；必要依赖须指定提供方文档/条款/版本/hash、保证、消费条件和验证责任。不能用规范名称代替逐条选择。
- **失败与恢复：** 缺必要提供方、同名条款错文或循环批准时不得登记范围闭合；可拆共同接口及双方职责，不以“可选”隐藏实际必要保证。
- **产物与验收：** 从每个适用条款追到必要依赖，闭包的对象均可解析；实际存在的支持承诺不能因未测试被改成不适用。
- **正确案例：** 离线无账号转换器不适用会话授权，但文件完整性与路径安全仍适用。
- **直接失败反例：** Web登录功能存在，却因没有测试账号把跨身份缓存标不适用。
- **合法邻例：** 不使用消息队列的单体不被强制引入 Outbox；已有数据库事务边界仍须明确。
- **检查入口：** 采用结构检查核ID和闭包边；技术审查核功能、必要性及理由。没有完整功能清单时保持未确定。

## ADP-03 实施身份、环境与参数

- **主体与前提：** 实现者和验收者；运行检查或声明结果前。
- **输入与权威：** 各组件源/制品摘要、实际运行版本、配置、数据形态、协议/ABI及支持端。
- **必要动作：** 必须明确目标平台、版本、运行入口、实际权限、数值参数来源、失败判据与允许副作用。L5提供API/工具约束；L6把相对预算转换为有来源的项目阈值，不修改协议不可变常量或弱化采用的安全最低要求。
- **失败与恢复：** 旧程序/新数据、配置缺失、目标与测试环境错绑时明确拒绝或按兼容合同运行；不能仅凭环境标签认定隔离，未知身份不得算通过。
- **产物与验收：** 重放者可定位同一实施对象及配置；变更任一影响行为组件触发相称复验。
- **正确案例：** 固定 SQLite 实际版本、journal/synchronous 设置、同一文件系统和掉电模拟边界。
- **直接失败反例：** 用内存模型通过推导真实数据库断电持久性通过。
- **合法邻例：** 无服务的离线库只需消费者导入/运行画像，不强制创建生产环境和回调。
- **检查入口：** 项目真实版本输出、制品清单、配置读回和目标工具；本仓示例不执行外部环境。

## ADP-04 可执行验收合同与独立期望

- **主体与前提：** 需求/技术验收者；定义或修订检查前。
- **输入与权威：** 需求与规范，而非当前实现输出；包括初始状态、输入夹具、时钟/随机性及错误注入点。
- **必要动作：** 每个检查必须给出可执行命令或真实工具步骤、前置条件、预期状态/输出/副作用次数、观察点和失败终点。重要规则包含正常、直接失败、合法邻例和必要复合情形；涉及不确定性时声明比较方法与容差来源。
- **失败与恢复：** 命令缺依赖、设备不可用或期望未定时记 not-run/blocked，不算失败行为已经验证。测试自身缺陷修订保留原失败及独立依据。
- **产物与验收：** 另一受权执行者可按固定合同得到可判断结果；日志或截图的存在本身不是业务成功判据。
- **正确案例：** COMMIT后丢响应，观察权威订单按原意图最多一个且查询到明确/未知状态。
- **直接失败反例：** 把实现实际返回值复制成期望，再宣称所有输入符合。
- **合法邻例：** 等价编码输入应得到相同规范化结果，不强求不同输入产生不同输出。
- **检查入口：** 按目标 L4/L5 所列命令实跑；本仓只执行已明确的离线/合成合同。

## ADP-05 证据分层、结果与独审

- **主体与前提：** 执行者、审查者及结果登记者；写任何验收结论时。
- **输入与权威：** 原始输出、起止/退出码、精确对象、实际检查过程及受权保存位置。
- **必要动作：** 必须分别登记文档结构、语义实审、有限模型、隔离实现与真实业务层；结果为 not-run/partial/fail/pass/unknown/not-applicable，后者有适用依据。独审记录冻结对象、独立依据与实际方法，不由不同名称自证。
- **失败与恢复：** 截断日志、缺观察、旧版本或独立性不足时结论不扩大。修改对象后重验受影响项，旧证据保留历史且不被当前生成器改写。
- **产物与验收：** 证据指向实际可访问且有权保存的对象，预期/实际/判定可相互核对；结构通过不能使 semantic_review 或 implementation 自动变pass。
- **正确案例：** Python合成账本测试通过，真实支付与税务判断均未执行。
- **直接失败反例：** 把字段中 `independent=true` 当作独立审查过程已经发生。
- **合法邻例：** 真实负研究结果符合预先协议，可是研究交付通过而非模型效果达标。
- **检查入口：** 采用检查器核证据记录必需字段和层级一致；人工核真实性、语义与权限。

## ADP-06 未知效果、并发与恢复

- **主体与前提：** 调用外部系统或写共享状态的实现者；超时、崩溃、重放、换主体或控制世代变化时。
- **输入与权威：** 逻辑意图、尝试、目标资源、有效权限/世代与原权威状态。
- **必要动作：** 必须区分未执行、已执行、执行中和未知；按领域幂等/事务/目标栅栏/核对协议恢复。同一意图安全重传不等于可创建新意图。较新尝试失败不消除旧尝试未知，客户端取消不撤回已生效副作用。
- **失败与恢复：** 没有权威核对能力时保持未知并给风险处置责任；有限去重窗需覆盖目标实际接受/处理边界，不能凭本地派发时间推安全。
- **产物与验收：** 重复、乱序、旧世代和并发各有输入；权威最终状态、副作用次数、预算和权限一致。
- **正确案例：** 连接断开后查询原支付操作，不盲目重复扣款。
- **直接失败反例：** 将任务标取消后认定在途旧命令不可能再写入。
- **合法邻例：** 无外部副作用的只读查询可按预算安全重复；不要求所有查询建立耐久操作账。
- **检查入口：** 对应后端、自动化、安全、网络和交易契约；合成模型必须列耐久性/时钟/并发假设。

## ADP-07 例外、兼容、迁移与退出

- **主体与前提：** 具有所涉范围决定权的采用者；变更版本、支持窗口、例外或撤回时。
- **输入与权威：** 旧新精确规范和实施对象、条款映射、支持承诺、第三方约束与真实决定。
- **必要动作：** 必须列保留/新增/修改/移除义务、兼容消费者、数据/配置/协议迁移、可逆和不可逆边界、例外起止/补偿/恢复；不擅自改变他人权利。停止支持、撤回和删除分别决定。
- **失败与恢复：** 例外过期、迁移中断或旧消费者不兼容时按预先路径恢复/前向修复；不能只回退二进制就宣称新数据和外部效果均回滚。
- **产物与验收：** 旧新组合交叉验，关键数据/权利/输出保持；失败原件与决定历史可回溯。
- **正确案例：** 有损格式升级不允许旧程序写，先验证恢复点并给前向修复方案。
- **直接失败反例：** 删除旧失败条款后把符合率改100%。
- **合法邻例：** 无已存数据的新库接口仍可有消费者兼容检查，不虚造数据迁移作业。
- **检查入口：** [兼容与迁移指南](../../guides/COMPATIBILITY.md)及采用/例外/兼容/退役模板；实际操作按目标权限执行。

## ADP-08 合成示例与下游消费

- **主体与前提：** 文档使用者和工具维护者；复制模板、实现采用检查或消费示例时。
- **输入与权威：** [合成采用示例](../../examples/adoption-contracts/README.md)、[schema](../../registry/schemas/project-adoption.schema.json)和检查器代码。
- **必要动作：** 示例必须带 example_only=true、operation_authorized=false、decision.status=not-decided；条款选择仅演示接口，不冒充完整真实项目符合性。下游填写真实记录时重新确认身份、适用、决定和实际证据，不能沿用合成名字作为真实角色。
- **失败与恢复：** 示例正文或规范hash变化须重新生成并复验，不能手改期望掩盖版本漂移；未知字段与重复对象应报告。
- **产物与验收：** 六类场景可解析到实际候选；空采用、逐条不适用、草案技术引用可合法表达，伪造已采用/已实施被拒。
- **正确案例：** Web+后端+数据库记录分别锁文，全部真实实现保持not-run。
- **直接失败反例：** 示例的“合成交易”名称被写入正式客户采用清单并标付款已成功。
- **合法邻例：** 空采用决定记录用于尚未选规范的探索阶段，不能被误判为完整符合性证明。
- **检查入口：** `python checks/project_adoption.py` 和 `python -m unittest discover -s tests -p test_project_adoption.py -v`。检查只判记录一致性，不认证法律或业务事实。
