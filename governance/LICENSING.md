# 权属、许可与第三方材料

## 当前许可决定

项目所有者确认其有权许可的 Standards 自有材料，并决定以材料类型而非单一全仓许可证授权。根 [LICENSE](../LICENSE) 是当前权威分配入口：

- **CC BY 4.0：** 规范正文、文档、译文、模板、发行文档、视觉资源、规范/治理机器数据、Agent Skill 说明以及项目编制的来源元数据和有限释义；
- **Apache-2.0：** 校验器、生成器、工具、测试、仓库自动化/配置、可执行示例/夹具和软件型 Schema；
- 文件存在更具体的许可或第三方通知时，以更具体条件为准。

标准许可证全文位于 `LICENSES/CC-BY-4.0.txt` 与 `LICENSES/Apache-2.0.txt`。本决定授权上述自有范围按对应许可证公开复制、修改、商业使用与再分发，并覆盖正式 Source 与 Agent Skill 消费包中的相同材料。

规范采用信息见[采用决定](ADOPTION.md)，项目许可适用范围见根 [LICENSE](../LICENSE)。

## 自有内容的权利事实

项目所有者对所指明自有材料的权利确认按准确对象范围有效，不覆盖明确第三方材料、第三方许可或商标权。文件摘要用于识别对象，不自行证明或否定法律权利；新加入而不在确认范围内的对象、存在具体权利冲突的对象以及第三方材料分别登记和核对。

CC BY 4.0 要求再分发时保留适当署名、许可证信息并标明修改；不得暗示许可方为修改版或第三方使用背书。Apache-2.0 的版权、专利、NOTICE、修改标记及商标边界按其正式条文执行。项目不通过摘要或二次说明改写标准许可证条款。

## 第三方材料与来源记录

根 [LICENSE](../LICENSE) 按路径和材料类型分配自有材料的许可；实际第三方材料及不同许可条件在对应文件或 [NOTICE](../NOTICE.md) 中注明。发行构建按实际文件集合生成完整性清单，并核对这些规则和通知。[来源目录](../sources/README.md)与来源登记记录外部材料的发布者、版本、章节、URL 和具体支持命题。

`sources/` 中由项目编制的元数据、哈希、有限释义与出处说明属于 CC BY 4.0 的项目自有范围；其中实际属于第三方的标准文本、代码、论文、商标、引文或其他内容仍由原权利条件控制，不因进入同一文件而被本项目重新授权。仅链接、有限释义、复制摘录、代码改编和随包依赖必须按实际形态分别处理。

当前来源记录以引用信息和具体支持命题为主，不把整份上游标准声明为本项目自有内容。需要复制第三方原文、许可文本、字体、图像或代码时，应登记具体版本、原许可、必要署名/NOTICE、修改要求和制品范围；不能用来源 URL 代替这些义务。

封面为项目自有本地图像，按根 `LICENSE` 的 CC BY 4.0 范围授权。README 徽章由 Shields.io 服务生成，其展示对象与来源见[徽章说明](../guides/README-BADGES.md)。未来嵌入第三方字体、标识或素材时单独核其条件。

## 贡献授权

贡献者提交材料前必须确认其有权按目标路径的出站许可证贡献：落入 CC BY 4.0 范围的贡献按 CC BY 4.0 提供，落入 Apache-2.0 范围的贡献按 Apache-2.0 提供，除非贡献与维护者在合并前明确记录另一项兼容决定。第三方材料必须同时保留其来源和适用条件。

贡献按上述出站许可证处理，无额外 CLA 或 DCO 要求。Pull Request 的提交行为仅在本仓已经公开展示的贡献与许可条件范围内作为贡献意图，不覆盖贡献者明确标记为“Not a Contribution”的材料，也不替代第三方权利核验。

## 官方身份、名称与商标

内容许可证不授予 Ranzevor 名称、Logo、服务标识或其他商标权，也不允许暗示 Ranzevor 对修改版、派生版或第三方分发进行了认可。允许为说明来源而进行合理、惯常的名称使用。

“官方 Standards 发行”应对应 Ranzevor 实际发布的准确 Git/Tag/Release 身份和制品摘要；改编版必须标明修改，不得仅因许可证兼容而沿用官方发布身份。

## 异议与恢复

权利异议应指明对象、主张、依据及所需处理，并按[维护入口](MAINTENANCE.md)进入实际接收渠道。保留对象摘要、原通知、异议和处置记录，避免扩散无关个人或机密材料。

出现具体冲突时只冻结或替换受影响范围，不自动推翻无争议材料的既有许可决定。更换材料、补充许可或撤回分发后，应重新核受影响的仓库、Source/Skill 制品、NOTICE 与清单；已合法取得的不可撤销许可证权利按对应许可证本身处理。
