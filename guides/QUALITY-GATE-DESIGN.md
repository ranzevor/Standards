# 质量门禁设计与验收

本指南面向检查器作者和审查者，将 [L3 CE-02、CE-11、CE-19](../standards/L3/001-通用工程规范--v0.1.0.md)、[PGT](../standards/project-governance/003-需求设计与验收追溯规范--v0.1.0.md)及 [PGQ-01、02、06](../standards/project-governance/011-测试质量门禁与证据规范--v0.1.0.md)用于软件仓库门禁。采用范围仍由项目选定的准确条款决定。

## 1. 先固定检查合同

为每项检查明确对象、真实不变量、独立预期来源、允许变化、观察点及失败后的处理。优先复用需求、包配置、接口定义和现有测试；同一事实保留一个权威位置。

| 对象 | 独立预期 | 应拒绝的输入 | 应继续接受的变化 |
| --- | --- | --- | --- |
| 包成员 | 准确候选的源码、打包配置及承诺分发的类型/数据/许可文件 | 删除承诺成员后重算包内自述清单；混入另一候选的字节 | 新版按自己的配置合法增删、改名；无顺序合同的成员重排 |
| 配置身份 | 本次实际读取并完成语义校验的同一份字节 | 校验旧字节，却返回后一次读取的新字节摘要 | 等价 JSON 排版均合法，各自保留不同字节摘要 |
| 依赖入口 | 项目声明的独立依赖组与实际解析语义 | 漏组、多组、重复项或未经允许的来源 | 已确认互不依赖的 include 顺序调整 |
| 文档 | 可解析的链接、稳定锚点、准确命令和技术含义 | 命令失效、义务改变或必要信息丢失 | 人类可读标签的同义改写及不影响合同的排版 |
| 来源引用 | 对象用途、来源类型和准确版本 | 浮动引用冒充固定版本；错误来源 | 官方依赖或材料引用中的完整提交身份 |
| 路径 | 授权物理根、成员类型及实际打开对象 | `..`、大小写冲突、文件/目录冲突、链接导向根外 | 根内普通文件、Unicode 与空格路径 |

摘要匹配证明所比较字节一致；所需成员是否齐全、来源是否可信及行为是否正确分别有自己的判据。对文档中的摘要应按用途审查，避免用全局禁长字符串规则误拒准确来源。

## 2. 独立推导制品预期

先从受审源码和打包声明得到预期成员及映射，再读取实际制品，分别比较成员集合、映射字节、许可/类型文件及来源身份字段。将制品清单与制品自身比较，只能检出二者不一致；攻击者同时删除成员并重算清单时，独立预期仍需发现缺失。

[合成实现](../examples/repository_engineering/contracts.py)中的 `expected_package` 从源码和候选版本生成预期，`verify_package` 另核实际成员、自述清单和 `source_manifest_sha256` 与源码文件集合的关系。这个文件映射示例不包含 wheel 元数据、依赖解析或平台 ABI 检查；实际包按 [CLI/SDK 发行规范](../standards/L4/cli-sdk/004-工具包发行、原生ABI与消费者兼容技术规范--v0.1.0.md)接入对应消费者入口。

版本一致性从当前候选版本推导。软件版本、数据格式版本、冻结科研协议和输入工件身份各按自己的兼容合同演进；贡献指南不把某次发行号写成以后永远不得改变的常量。

## 3. 用反例和合法邻例检验检查器

1. 正例满足已定义合同。
2. 直接反例只破坏目标不变量，并确认拒绝发生在目标判据。
3. 合法邻例改变排布、文案或合法版本，保留相同技术合同。
4. 新发现修复后，保留原反例并检查相关合法路径。

例如删除 `py.typed` 后同步重算自述清单，应在独立成员比较失败。若仅因清单未重算而失败，尚未触及“清单与包同时遗漏”的机制。源码身份字段矛盾也应直接落到对应判据。

有限解析器写明支持的语法，对未支持形式给出明确结果；输入范围扩展时增加相应反例和合法邻例。Git 忽略规则通过实际匹配结果核验，YAML 引用通过支持的结构核验，避免只搜索固定文本排布。

## 4. 读取与物理路径边界

语义校验和摘要计算消费同一次读取的字节。`read_config` 的示例允许路径在读取后变化，但返回身份只对应已经校验的快照；需要后续文件仍为同对象时，调用者另行固定该对象或在提交边界核对。

Windows junction 和 POSIX 目录链接都可能改变实际寻址。`resolve_member` 演示在受控、无并发改写的目录中解析物理路径并按路径组件判定根归属，不能用字符串前缀或 `is_symlink()` 代替。存在不可信并发写入时，采用目标平台的句柄、根身份和最终打开对象核验，或先建立受控不可变快照；一次路径检查不锁定之后的打开动作。

## 5. 选择检查与保存结果

按受影响的不变量选择检查。纯文字排版核内容、链接和必要渲染；命令变化执行该命令；路径、身份、并发及恢复逻辑变化增加对应直接反例和合法邻例。原实验的对象、环境与证明命题未变时，可按 PGQ-06 复用有效结果。

从仓库根使用 Python 3.12 运行本指南的合成场景：

```sh
python -X utf8 -B -m unittest tests.test_repository_engineering -v
```

场景清单、各平台条件和结果边界见[示例说明](../examples/repository_engineering/README.md)。原始输出保存在源码目录外或 CI 制品中；正式测试源码保留合成输入及判据。
