## 类型与术语

规范定义可采用要求；指南说明任务步骤；参考说明字段或接口；教程提供可重复学习路径；记录描述具体对象发生过的事实。译文保持原类型，不将教程例子升格为要求。

| 中文 | English | 具体含义 |
| --- | --- | --- |
| 必须／不得 | MUST／MUST NOT | 适用且选定采用时的必要要求 |
| 建议 | SHOULD | 可有理由偏离并保留相应保障 |
| 可 | MAY | 可选机制，不要求所有产品新增能力 |
| 采用 | adoption | 选择准确规范对象及适用范围 |
| 实现验收 | implementation acceptance | 对目标实现的实际证据和判定 |
| 未执行 | not-run | 没有运行，不等于失败 |
| 不适用 | not-applicable | 有范围依据，不等于未知 |
| 内容摘要 | digest | 字节身份，不是内容概述summary |
| 完整译文 | full translation | 覆盖正文/例子/恢复，不代表独立审查通过 |

缺词保留中文并加临时说明，由领域作者解决；代码名称、路径、协议字面量不随意翻译。语言标签识别语言，不证明地区法律适配。

## 更新流程

1. 固定中文文档ID、版本、路径、摘要及全部条款ID；列出增删改和受影响例子。
2. 逐条翻译范围、条件、强度、例子、失败恢复、依赖和来源边界；不只翻标题。缺段为partial，源已改为outdated，只有概述为summary。
3. 重算相对链接；真实英文目标存在才改指英文，否则标明Chinese only。命令、数据单位和预期错误保持同义。
4. 固定译文摘要和同序条款映射，重读源确认没有并发变化。任何字节变化都需核身份，即使版本号不变。
5. 运行 `python checks/translations.py` 核20份源译身份和链接；`python checks/project_readme.py` 核README合同和徽章；运行专项回归。自动输出仅为identity-verified。
6. 作者逐条实读中文和英文，记录歧义/差异及处置；接收维护者确认是否接收。独立审查另记，不把作者自读或机器通过当成独立审阅。

机器合同及来源记录在[translations.json](../registry/translations.json)，包括路径、源版本、双摘要、同序ID、覆盖状态及人工审阅状态。哈希只能证明读的是哪份文件，不能证明译得对。

## 回退与界面边界

关键要求有争议时使用权威中文并请领域负责人澄清，不靠机器翻译默认放行。源改变而译文未同步时标outdated；修复后重核身份并实读。界面语言选择不等于文档全文已本地化；本指南不要求无UI项目新增语言设置，也不代替真实UI、格式、地区合规测试。
