# 从规范到项目采用合同

本指南说明如何选择规范、填写项目采用记录并执行验收。项目记录包含适用条款、实施配置、责任人、必要操作权限和实际结果。完整接口见[L6规范](../standards/L6/001-项目采用与实现验收接口规范--v0.1.0.md)，决定与结果按[L1 GG-05四轴](../standards/L1/001-全局治理补充规范--v0.1.0.md#gg-05-核验合同)分别记录。

## 1. 描述真实对象，不从技术栈反推业务

先列用户任务、组件、部署/分发环境、持久数据、外部副作用、接口消费者及已有兼容承诺。无账号离线工具不必引入会话系统；已有登录、交易或同步的产品不能为了缺少测试而把它们标成不适用。未知事实保留“未确定”。

从[目录](../INDEX.md)选择L0–L3、必要L4专题与实际L5适配。基线不自动覆盖独立专题，语言适配也不替代领域合同。固定每文ID、版本、路径和SHA-256；不可变快照可保留旧版，不用`latest`替换已决定对象。

## 2. 写出逐条选择和必要依赖

使用[采用模板](../templates/ADOPTION.md)，逐条记录触发事实、适用/不适用/未确定、理由与验证责任。引用关系分两类：

- 必要消费：没有提供方保证，当前实现无法成立。例如客户端的未知提交展示消费服务的原意图查询/防重合同。
- 技术参考：用于解释或比较，不构成执行或批准前提。两个参考互相链接不等于必要依赖环。

必要接口至少有准确两端条款、提供保证、消费条件、提供方版本/hash与验证责任。批准互相等待不能证明依赖闭包；可提取共同接口和分别可完成的职责，不能通过改成“可选”隐藏真实依赖。

## 3. 将条款落到可执行检查

对每个选定适用条款固定：实施源/制品/配置/数据身份、实际工具与目标版本、初始状态、输入、故障点、命令或工具步骤、独立期望、观察点、终止/超时和恢复条件。数字阈值来自业务/协议/目标测量依据，不随实现结果临时放宽。

同一重要机制至少验证正常路径、直接破坏不变量的失败路径和相邻合法路径。HTTP提交后断响应、旧attempt迟到、账号切换、重复事件、版本并存等复合情形按实际风险增加。模型、替身、隔离真实组件与真实业务结果分别登记；文件存在、日志含`pass`或测试总数都不是业务证明。

## 4. 先核记录，再执行被授权目标

本仓提供[六份合成接口示例](../examples/adoption-contracts/README.md)。示例选择演示所需的条款，决定和运行状态均未设置。项目应按实际范围建立自己的适用条款清单。以下命令检查记录、身份与有限状态规则：

```bash
python checks/project_adoption.py
```

记录中的命令和工具步骤在获准环境执行。命令不可用时记录受阻，未运行时保留 `actual=null` 和空证据。产品验收关联准确对象、起止时间、原始输出、退出码及可复核观察。

## 5. 决定、试用与维护

实际决定由具备相应项目权利的主体记录，不由JSON字段认证。已有有效决定覆盖该项目范围时，直接复用原主体、授权范围、生效时间及依据，记录项目的适用条款和配置，不为相同采用意图另造确认门槛。项目采用规则见[采用政策](../governance/ADOPTION.md#项目采用)，具体符合性以项目实际结果为准。草案试用不改变体系文档状态；作者自审不成为独审；正式选择也不证明实现达标。记录例外的准确范围、风险、补偿控制、复查触发及结束条件，不能靠例外掩盖永久缺失的核心义务。

正文、依赖、目标平台、权限或需求变化触发影响分析。保留旧决定与旧证据，按[迁移指南](MIGRATION.md)比较义务和接口，重验受影响对象。撤回采用、结束试用或退役时仍处理残留数据、凭据、消费者及不可逆外部效果。
