# 产物用途、内容边界与完整性

本页消费 `STD-PG-004 / PGR-04` 和 `STD-PG-019 / PGX-01、PGX-02`。采用范围及正文定位见[行为指南入口](../AI-BEHAVIOR.md)。

## 先识别交付对象

| 对象 | 读者需要什么 | 交付时核对 |
| --- | --- | --- |
| 文章、报告 | 观点、事实、依据、结论及必要条件 | 核心内容完整，无要求读者自行补齐的占位 |
| 产品界面 | 功能、操作、反馈及影响使用的条件 | 使用者无需理解内部调度或生成过程 |
| README | 项目定位、使用路径、支持范围、许可和维护入口 | 命令和链接可用，信息面向项目使用者 |
| PR | 问题、实际变化、影响及相关验证 | 审查者能定位差异，不必阅读完整聊天流水 |
| JSON、SQL、配置 | 消费者契约要求的精确结构 | 能直接解析或在约定环境使用 |
| 交付说明 | 成果入口、重要变化、验证范围和实际遗留 | 结果与真实状态对应，没有用汇报替代产物 |

## 三种边界

**内容边界。** 正文包含读者完成任务所需内容。协作中的自我解释、工具限制和下一步安排放在适当说明中；没有用途的信息可以省去。影响产品使用的限制、研究局限和接口条件仍属于相关正文。

**文件边界。** 源码、正式成果、生成物、不可替代证据和临时文件按实际用途分类。一个当前源码入口即可；历史由准确 Git 或发行身份取得。执行原始结果放在授权运行目录，以必要索引关联，不为展示完成度反复复制全仓。

**完整性。** 文案纯净和交付完整分别验收。JSON 可以没有多余文字却缺字段；报告可以排版完整却没有回答问题；代码可以有函数名却只有占位。按照任务完成条件逐项检查。

## 适当说明的位置

“Linux 尚未验证”如果描述本次执行覆盖，可以放入交付说明；如果决定产品承诺的支持平台，应在使用文档中明确。研究的样本限制影响结论，本身就是研究成果的一部分。同一句话不因含有“未验证”就应被自动删除。

## 验收

[产物场景](../../examples/ai-agent/behavior/cases/artifacts.json)覆盖报告、产品页、JSON、README、研究摘要和完整代码。

- 正例：`output.json` 直接保存所需数据，键顺序可自由变化。
- 直接失败：给 JSON 文件添加 Markdown 围栏或自然语言前言；给完整实现留下核心 TODO。
- 合法邻例：报告在正文中保留与结论直接相关的研究限制。

自动检查负责确切格式和存在性，内容归属由审查者按完整上下文判断。不得仅按“我”“不得”“未验证”等词执行全局删除。
