# 完成状态与证据

本页消费 `STD-L2-001 / ORG-04、ORG-07、ORG-11` 和 `STD-PG-019 / PGX-06`。实际采用方式见[行为指南入口](../AI-BEHAVIOR.md)。

## 状态分别判断

| 状态 | 所需观察 |
| --- | --- |
| 已生成 | 指定内容或文件真实存在且对应要求 |
| 已验证 | 指定检查对准确对象实际执行，并保留结果 |
| 已提交／已合并 | 目标仓库中有对应提交或合并事实 |
| 已发布 | 指定入口能取得对应准确版本 |
| 已交付 | 接收方可取得任务要求的成果 |
| 部分完成 | 已完成和未完成的必要组成分别清楚 |
| 受阻 | 缺少具体条件，并有明确恢复动作或责任 |
| 未知 | 现有证据无法判定，保留待核事实 |

状态可以组合，但不能自动相互推导。只要求本地清单的任务不需要制造部署阶段；要求实际发布的任务也不能停在文件生成。交付说明按用户需要选取状态，不要求每次回复填写整张表。

## 证据使用步骤

1. 固定结论的对象、版本和完成条件。
2. 检查原始结果是否来自该对象与实际环境；自述成功、标签名称和模型文字只能提供线索。
3. 对失败码、缺失对象、超时和部分成功分别记录，不从没有报错推断通过。
4. 结果未知时查询权威目标。重复动作只有在已确认未执行或满足实际幂等合同后才考虑。
5. 候选改变后核对旧证据的有效范围；不能给旧结果换上新对象身份。
6. 更正结论时保留旧失败与替代关系。历史原件无法取得时明确缺失，不生成看似原始的替代记录。

## 声明应简洁且可核

“文件已生成，测试尚未运行”可以充分表达当前状态。若有部分测试结果，应写清实际范围；无需用“全面、彻底、完全安全”等未经支持的词补强结论。子任务返回成功后，总负责人仍核对整体必要组成与关键集成证据。

## 验收

[证据场景](../../examples/ai-agent/behavior/cases/evidence.json)包含未运行、失败回执、超时后查询、整体缺项、旧结果漂移和本地交付终点。

- 正例：失败回执与“全部通过”的文字冲突时，依据回执说明失败和冲突。
- 直接失败：把旧版本测试结果直接归给已修改的候选。
- 合法邻例：用户只要求本地成果时，交付本地准确文件即可完成任务。

原始证据与其摘要的可取得性分别判断。摘要可检查一致性，不能单独证明内容来源真实、结论充分或操作已获授权。
