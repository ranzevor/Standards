# 行为配置的采用、升级与反馈

本页帮助项目把[行为专题](../AI-BEHAVIOR.md)接入既有采用和维护记录。它是可选实施指南；正式义务仍由项目选定的规范、条款及准确版本确定，不因下载新版消费包自动增加。

## 从一个具体任务开始

先描述实际任务、交付对象、已有授权和完成条件，再选择相关专题。简单文案编辑可以只采用表达和产物边界；有工具副作用的任务再选择自主执行与证据要求。已有项目记录、PR 或任务系统足以承载这些内容时，直接复用。

| 实际问题 | 优先选用 | 首次验收观察 |
| --- | --- | --- |
| 反复宣告能力、重复边界或无据声称通过 | [声明与表达](EXPRESSION.md) | 成稿是否完整；说明是否影响使用；真实限制是否仍保留 |
| 授权内工作停在计划或重复请求确认 | [授权内执行](AUTONOMY.md) | 是否执行到已授权完成条件；缺少具体决定时是否准确询问 |
| 产品文案混入过程说明、文件与交付说明混淆 | [产物边界](DELIVERABLES.md) | 实际文件能否直接使用；必要使用条件是否在正确位置 |
| 把生成、测试、合并或发布混为完成 | [完成与证据](EVIDENCE.md) | 每项状态是否有相应对象、观察和限制 |
| 模型补丁越积越多或任务上下文过载 | [按需加载与适配](PROFILES.md) | 是否只加载适用内容；适配项是否仍有复现依据 |

通过[规范登记](../../registry/standards.json)固定文档 ID、版本、路径和 SHA-256，再选择条款。记录适用事实、责任、例外和验收目标，沿用[项目采用指南](../ADOPTION.md)的已有授权与四轴结果区分。

## 把选择放进实际宿主

先确认宿主真正读取的指令位置、工具权限和输出通道。把项目选择写成短而明确的任务规则，链接到本次固定的专题与正式条款。仅放置文件或安装 Skill 不证明宿主已加载；用一个获准的实际任务观察加载与执行结果。

需要特定模型或宿主适配时，使用[适配模板](../../examples/ai-agent/behavior/adapter.template.json)记录具体偏差、范围和移除条件。没有实际证据时保持禁用、待验证，不为整个型号系列预填“兼容”。不要复制或索取宿主不可披露的提示内容。

## 先固定试验，再看结果

按[评测指南](EVALUATION.md)预先选择案例、重复次数和判据。保留全部计划试验，包括失败、中断和缺失证据；由未执行该任务的审查者核实原始可见记录及文件。小规模试运行支持当前任务与配置的判断，不能扩张为整个模型系列的结论。

自动检查通过表示其覆盖的有限文件条件成立；语义判据、真实授权和来源仍须结合观察判断。接受一个有效的新工具路径时，应先核任务合同，不因它不同于参考答案而拒绝。

## 升级时比较准确对象

记录旧新发行集合版本，以及真正采用的文档、条款和适配配置。集合版本增加但所选规范的 ID、版本与摘要未变时，不伪造正文升级。文档路径变化时使用稳定 ID 解析新登记，保留旧版不可变快照；不要用当前路径替换历史证据。

按[迁移指南](../MIGRATION.md)核对要求含义、路径、必要依赖、工具格式和目标环境。对变化的部分补验；无变化的证据只在对象和条件仍成立的范围内复用。只有旧新任务、规范绑定和评分器一致时，才直接比较行为试验结果；否则分别报告，并说明发生了什么变化。

完成切换前保留旧包、旧配置与恢复方式。一次工具失败先判断是否产生副作用或部分结果，再决定查询、重试或回退。已产生的外部效果不能用代码回退代替补偿。

## 让反馈变成可复现修订

可以直接在现有 Issue 中填写[反馈模板](../../examples/ai-agent/behavior/FEEDBACK.template.md)的必要字段：准确对象、预期、实际、授权范围、复现输入和原始观察。敏感材料按项目既有渠道处理，普通报告只保留必要且可分享的最小案例。

维护者先复现并区分规范歧义、宿主限制、适配问题或评分器误判，再补直接失败例与相邻合法例。修复通过准确提交的独立 PR 审查后，更新受影响指南、案例、索引和发行说明。没有复现的报告保留具体缺失，不以流畅的解释关闭。

模型、宿主、指令或工具权限变化会触发适配复核。对已无法复现的问题比较启用和停用适配的结果；确认不再需要后禁用该适配并保留历史。模板默认禁用，当前没有证据支持的模型专属补丁也不预先启用。
