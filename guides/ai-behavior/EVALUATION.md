# 行为评测的准备、记录与判定

本配置复用 `STD-L4-AI-AGENT-002 / §01、§03、§13、§14、§17、§18、§27、§29`，通过[规范登记](../../registry/standards.json)固定真实条款身份。案例集是安全合成任务，真实模型可以运行这些任务；案例文本和评分器单元测试均不自动成为模型运行结果。

## 评测对象

评测一个明确的模型、宿主、指令、工具和选定任务组合。`tools/behavior_eval.py` 提供冻结计划、捕获文件、绑定证据和汇总判定的有限入口。它不连接模型服务，不提供操作系统沙箱，也不从操作者填写的名称认证模型身份。模型及其工具在项目批准的隔离环境中运行，身份来源和不可冻结部分保存在执行配置与可见运行记录中。

## 运行顺序

1. 从[执行配置模板](../../examples/ai-agent/behavior/execution.template.json)建立实际配置。填写模型标识来源、宿主版本、执行者、本次可控制且可披露的项目指令、工具配置和推理参数。未知的实际模型标识使用 `null`，明确其限制。宿主未公开的指令记为不可固定的限制，不复制特权提示或私有推理。
2. 在看见输出前选择案例、重复次数和预算，准备源码目录外的新运行目录。准备命令固定案例正文、来源文件、规范版本与摘要、执行配置、评分器文件以及每次试验身份。把返回的 `batch_sha256` 保存到项目既有执行记录；后续汇总必须使用这个预先记录的值。
3. 将每次试验的 `prompt.txt` 与配置中的实际指令交给被测 Agent。它只在该试验的 `workspace/` 和真实授权范围内工作。宿主没有适当隔离时，不运行涉及不可信工具或真实外部动作的任务。
4. 保存实际最终回复与可见执行记录。记录可以包含输入、工具调用、返回、错误和动作结果，不要求披露模型私有思维链。先完成本次写入，再冻结现场并捕获。
5. 独立审查者阅读原始任务、实际文件、回复和运行记录，填写每个语义判据与来源真实性判据，给出理由及行级证据。审查者标识与执行者不同并不能单独证明独立性，需说明实际独立工作。
6. 对冻结的观察运行判定与汇总。修复或重跑创建新的试验记录，保留原失败；不得重写第一次观察。

### 命令示例

以下路径由操作者换成已授权的位置；输出目录必须在源码树之外且此前不存在。

```sh
python tools/behavior_eval.py prepare --config ../execution.json --out ../behavior-run --case AUTO-001 --case ART-003 --repetitions 2
```

Agent 完成某次试验后，用本次原始回复和可见记录捕获。例如：

```sh
python tools/behavior_eval.py capture --run ../behavior-run/AUTO-001/1 --response ../raw/response.txt --trace ../raw/trace.txt --origin operator-captured-agent
python tools/behavior_eval.py review-template --run ../behavior-run/AUTO-001/1
```

将审查模板另存为该试验的 `review.json` 并由独立审查者填写。每个非未知判定至少引用一个实际捕获文件的有效行段，例如 `trace.txt`、`response.txt`、`observation.json` 或该次 `workspace/` 中的实际产物文件。随后执行：

```sh
python tools/behavior_eval.py evaluate --run ../behavior-run/AUTO-001/1 --review ../behavior-run/AUTO-001/1/review.json
python tools/behavior_eval.py aggregate --directory ../behavior-run --batch-sha256 '准备时记录的64位SHA256'
```

命令返回码：`0` 表示该操作完成或所选运行通过，`1` 表示已判定失败，`2` 表示证据不足或输入无效。应读取 JSON 中的具体状态；不能只看命令是否产生输出。

## 自动判据与语义判据

自动检查从实际文件读取存在性、完整文本、明确片段或 JSON 值，不接受案例执行者填写的 `pass` 字段。JSON 对象键顺序可以不同；布尔值不会与数字混同。摘要固定准确字节；文件或记录改变后，旧捕获和审查失效。

重放旧运行时，从当时冻结的源码版本调用工具。即使指定 `--root`，目标目录中的评分器也必须与实际执行的实现一致，不能用新版逻辑冒充旧版身份。

语义审查判断任务是否实质完成、说明是否必要、内容是否归属正确以及声明是否有据。来源审查判断记录是否真的来自声明的执行，包含哪些可独立取得的依据。工具检查审查覆盖、引用范围与身份绑定，不能自动认证理由真实或语义判断正确。报告会明确这些结论由审查者作出。

## 结果与分母

每个预定试验保留在分母。已有实际产物失败或独立审查确认的必要判据失败时，结果为 `FAIL`，超时、错误或其他未知判据不能抹掉这项已知失败。没有已知失败，但缺少捕获、执行未完成、必要审查缺失或判据仍未知时为 `INSUFFICIENT`。所选试验全部满足文件检查与独立审查才能为 `PASS`。这是本可选配置的保守全通过策略；修改策略应形成新的配置和预先冻结的计划。

`synthetic-fixture` 表示用手写输出测试评分器。它可以产生 `fixture_result`，但不会计入模型成功数；即使夹具全通过，行为评测仍为证据不足。真正运行 Agent 时可以使用安全合成案例，关键区别是输出的实际来源与完整观察。

汇总给出完整分母、各案例族的计数和选定试验的成功比例。不同案例族、首次执行、重试、不同模型或宿主分别解释，不据少量通过宣称整个系列稳定合规。发生重大越权时保留独立失败，不用平均分抵消。

可以为基线与候选分别准备相同案例和次数，再使用 `compare --baseline <目录> --candidate <目录> --baseline-sha256 <预先记录值> --candidate-sha256 <预先记录值>`。比较会核对任务、规范绑定及评分器一致，报告成对状态变化；存在未执行或证据不足时明确为 `INCOMPLETE`，不推断统计显著性或因果关系。非必要确认次数、语义声明密度和成本等指标仍需按项目预先定义的观察口径另行记录，不从通过率反推。

## 边界与恢复

每份证据文件上限为 2 MiB；任务目录最多 256 个文件或目录条目、总文件字节最多 16 MiB。捕获会登记额外出现的文件，便于审查意外副作用。路径不能越出运行目录或经过符号链接。更大的合法证据需在采用项目中选择有明确权限与保留条件的证据接口，不能删掉关键部分再称完整验证。执行配置只记录必要信息，密钥和私有业务材料不要进入模板或规范源码。

运行期间保持任务文件的唯一写入责任；捕获和审查期间不再修改现场。捕获失败时保留已生成内容和错误，查明具体原因。不要直接覆盖旧观察、替换旧审查摘要或删除原始失败。

## 验收与外部实践

[评分场景](../../examples/ai-agent/behavior/cases/evaluation.json)覆盖缺失产物、未执行、完整分母、合法不同路径、重大失败和合成夹具边界。正例是实际文件与完整审查共同支持通过；直接失败是成功自述覆盖缺失文件；合法邻例是满足相同合同的另一条工具路径。

[Anthropic：Demystifying evals for AI agents](https://www.anthropic.com/research/demystifying-evals-for-ai-agents)区分对话轨迹与环境结果，并讨论重复试验和规则、模型、人工裁判。本配置采用这些有限实践组织观察；当前输出仍只支持实际执行的任务和环境。
