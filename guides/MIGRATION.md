# 规范与项目升级

升级以文档内容、条款义务和消费接口为对象。先固定旧版本和新版本的 ID、路径、SHA-256、适用范围及变更理由。

## 逐项比较

| 对象 | 比较内容 | 验收 |
| --- | --- | --- |
| 条款 | 触发条件、主体、必要动作、不变量、失败恢复和验收方式 | 新旧义务有明确映射，删除或合并有具体理由 |
| 路径与引用 | 目录、相对链接、锚点、模板和消费端引用 | 唯一当前入口与引用均指向准确对象 |
| 来源 | 版本、章节、支持命题与适用条件 | 新要求由对应来源或明确的组织设计理由支持 |
| 依赖 | 提供与消费接口、版本、摘要及必要条件 | 受影响的必要依赖闭合 |
| 检查 | 正例、反例、合法邻例及目标环境 | 原判据保持或按实际要求说明变化 |
| 项目采用 | 条款选择、参数、例外、支持窗口及现有消费者 | 项目采用记录与真实实施一致 |

文档更名通常保留稳定 ID；拆分或合并列出替代关系。文件的新增、修改、删除和路径差异使用 Git 比较准确旧新对象；面向消费者的迁移说明记录受影响入口、条款义务、兼容条件和必要操作。跨版本证据复用说明对象、条件和有效范围，发生变化的部分执行补验。

```sh
python checks/generate_registry.py --check

python checks/validate_all.py
python -m unittest discover -s tests -v
```

## 项目切换与恢复

采用项目固定消费者、数据格式、兼容窗口、切换条件和恢复目标，验证旧新版本的实际输入输出。代码回退、数据恢复和外部操作补偿分别处理；已发生的支付、通知、设备安装或授权变化使用对应业务的恢复合同。

升级完成后核对完整性、核心行为、权限和消费者。保留当前采用版本、必要变更说明及可恢复材料。

## AI 行为配置升级

行为配置按[采用与升级流程](ai-behavior/ADOPTION.md)比较场景、规范绑定、指令、模型或宿主及评分器身份。旧运行使用其冻结版本重放，受影响的配置补做真实试验；反馈与适配退役保留原始失败和明确的生效范围。
